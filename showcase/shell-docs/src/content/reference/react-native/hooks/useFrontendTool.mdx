## 概览

`useFrontendTool` 在组件作用域内向 CopilotKit 注册一个客户端工具。当智能体决定调用该工具时，所提供的 `handler` 函数会在设备上执行。你还可以选择提供一个 `render` 组件，在聊天界面中显示自定义 UI，以展示工具的执行进度与结果。

<Callout type="info">
  该钩子从 `@copilotkit/react-core/v2` 重新导出。它与 [React (V2) 的 `useFrontendTool`](/reference/v2/hooks/useFrontendTool) 完全相同，仅导入路径不同。
</Callout>

该钩子管理完整的注册生命周期：如果同名工具已存在则发出警告，在挂载时注册工具及其渲染组件，并在卸载时清理这两项注册。在 v2 中，参数模式使用 [Zod](https://zod.dev) 定义，而非普通的参数数组。

## 签名

```tsx
import { useFrontendTool } from "@copilotkit/react-native";

function useFrontendTool<T extends Record<string, unknown>>(
  tool: ReactFrontendTool<T>,
  deps?: ReadonlyArray<unknown>,
): void;
```

## 参数

<PropertyReference name="tool" type="ReactFrontendTool<T>" required>
  工具定义对象。

<PropertyReference name="name" type="string" required>
  工具的唯一名称。智能体在决定调用工具时会引用该名称。如果已注册同名工具，会记录一条警告。
</PropertyReference>

<PropertyReference name="description" type="string" required>
  用自然语言描述工具的用途与使用时机，供智能体理解。
</PropertyReference>

<PropertyReference name="parameters" type="z.ZodSchema" required>
  定义工具输入参数的 Zod 模式。该模式决定对外发布的工具模式与类型推断。运行时参数会经过 JSON 解析，但不会依据该模式进行校验。
</PropertyReference>

<PropertyReference
  name="handler"
  type="(args: T, context?: { toolCall, agent, signal?, isReplay? }) => Promise<string>"
  required
>
  当智能体调用工具时执行的异步函数。它接收解析后的参数（类型来自 `parameters`，但不依据其校验），以及一个可选的上下文对象，其中包含 `toolCall`（原始工具调用元数据）、`agent`（调用该工具的智能体实例）、`signal`（一个 `AbortSignal`，当用户通过 `stopAgent()` 或 `agent.abortRun()` 停止智能体时会被中止）和 `isReplay`（在线程历史恢复期间执行该调用时为 `true`；参见 `reconnectBehavior`）。长时间运行的处理函数可以检查 `signal.aborted` 以提前退出。
</PropertyReference>

<PropertyReference
  name="render"
  type="React.ComponentType<{ name: string; args: Partial<T>; status: ToolCallStatus; result: string | undefined }>"
>
  在聊天界面中渲染的可选组件，用于可视化工具的执行过程。在 React Native 中，渲染组件返回 React Native 元素（如 `<View>` / `<Text>`）。该组件接收 `name`（工具名称）、`args`（参数，流式传输期间为部分值，执行开始后为完整值）、`status`（`ToolCallStatus.InProgress`、`ToolCallStatus.Executing` 或 `ToolCallStatus.Complete` 之一）以及 `result`（处理函数返回的字符串结果，仅在状态为 `Complete` 时可用）。

  **声明的返回类型是 `ReactNode`，比 React Native 实际能绘制的范围更宽**。`render` 是一个 `React.ComponentType`，因此返回裸字符串的 `render` 能通过类型检查，但在设备上会抛出异常。参见 [React Native 需要的 render 类型](#react-native-需要的-render-类型)。
</PropertyReference>

  <PropertyReference name="available" type='"enabled" | "disabled" | "remote"' default='"enabled"'>
    控制工具可用性。设为 `"disabled"` 可暂时阻止智能体调用该工具；设为 `"remote"` 表示该工具在服务端处理。
  </PropertyReference>

  <PropertyReference name="reconnectBehavior" type='"passive" | "resume-pending"' default='"passive"'>
    当线程历史恢复（例如页面重新加载之后）时，对该工具仍未应答的调用如何处理。使用 `"passive"` 时，调用会显示但处理函数不会运行。使用 `"resume-pending"` 时，处理函数会为该调用运行（其上下文中 `isReplay: true`），随后运行照常继续。只对可以安全重复运行的处理函数启用此选项。在同一页面上，一个调用不会同时启动两次；但如果其结果从未到达智能体，它可能在停止或切换线程后再次运行，并且恢复同一线程的两个标签页可能各自运行一次。如果智能体在调用此工具的同时还调用了一个保持 `"passive"` 行为的工具，后续运行会发送没有结果的 passive 调用，某些模型提供方会拒绝这种情况。
  </PropertyReference>
</PropertyReference>

<PropertyReference name="deps" type="ReadonlyArray<unknown>">
  可选的依赖数组。当其变化时，工具会被注销并重新注册，使新的 `handler` 与 `render` 闭包生效。把 `handler` 或 `render` 捕获的、且会随时间变化的每个值都传进来——两者都是在注册时捕获的，不会在每次渲染时重新读取。

  `deps` 对普通数据（字符串、数字、布尔值、`null`、日期，以及由它们构成的普通对象和数组）按值进行比较，因此诸如 `[{ status }]` 这样的内联字面量只在其内容变化时才重新注册。函数与之前一样永远不算变化，所以要把会变化的回调保存在 ref 中。类实例和其他对象按引用（同一性）比较，因此传入来自 `useAgent` 的 `agent` 这类循环引用的值是安全的。增加或移除条目都算变化。参见 [依赖比较](#依赖比较)。
</PropertyReference>

## 用法

### 使用 Zod 参数的基础工具

```tsx
import { useState } from "react";
import { Text, View } from "react-native";
import { useFrontendTool } from "@copilotkit/react-native";
import { z } from "zod";

function TodoManager() {
  const [todos, setTodos] = useState<string[]>([]);

  useFrontendTool(
    {
      name: "addTodo",
      description: "Add a new item to the user's todo list",
      parameters: z.object({
        text: z.string().describe("The todo item text"),
        priority: z.enum(["low", "medium", "high"]).describe("Priority level"),
      }),
      handler: async ({ text, priority }) => {
        setTodos((prev) => [...prev, text]);
        return `Added "${text}" with ${priority} priority`;
      },
    },
    [],
  );

  return (
    <View>
      {todos.map((t, i) => (
        <Text key={i}>{t}</Text>
      ))}
    </View>
  );
}
```

### 带自定义渲染组件的工具

```tsx
import { Text, View } from "react-native";
import { useFrontendTool, ToolCallStatus } from "@copilotkit/react-native";
import { z } from "zod";

function WeatherWidget() {
  useFrontendTool(
    {
      name: "getWeather",
      description: "Fetch and display weather information for a city",
      parameters: z.object({
        city: z.string().describe("City name"),
        units: z.enum(["celsius", "fahrenheit"]).default("celsius"),
      }),
      handler: async ({ city, units }, { signal }) => {
        const response = await fetch(
          `https://your-server/api/weather?city=${city}&units=${units}`,
          { signal },
        );
        const data = await response.json();
        return JSON.stringify(data);
      },
      render: ({ args, status, result }) => {
        if (status === ToolCallStatus.InProgress) {
          return (
            <View>
              <Text>Fetching weather for {args.city}...</Text>
            </View>
          );
        }
        if (status === ToolCallStatus.Complete && result) {
          const data = JSON.parse(result);
          return (
            <View>
              <Text>{data.city}</Text>
              <Text>
                {data.temperature}&deg; {data.units}
              </Text>
              <Text>{data.conditions}</Text>
            </View>
          );
        }
        return null;
      },
    },
    [],
  );

  return null;
}
```

### 条件可用的工具

```tsx
import { View } from "react-native";
import { useFrontendTool } from "@copilotkit/react-native";
import { z } from "zod";

function AdminPanel({ isAdmin }: { isAdmin: boolean }) {
  useFrontendTool(
    {
      name: "deleteUser",
      description: "Delete a user account by ID (admin only)",
      parameters: z.object({
        userId: z.string().describe("The ID of the user to delete"),
      }),
      handler: async ({ userId }) => {
        await fetch(`https://your-server/api/users/${userId}`, {
          method: "DELETE",
        });
        return `User ${userId} deleted`;
      },
      available: isAdmin ? "enabled" : "disabled",
    },
    [isAdmin],
  );

  return <View>{/* admin UI */}</View>;
}
```

## React Native 需要的 render 类型

`render` 的类型是 `ReactToolCallRenderer<T>["render"]`，即一个 `React.ComponentType`。函数组件的返回类型是 `ReactNode`，因此**以下代码能通过编译**：

```tsx
useFrontendTool({
  name: "showWeather",
  description: "Show the weather",
  parameters: z.object({ city: z.string() }),
  handler: async ({ city }) => city,
  // Compiles. `ReactNode` includes `string`.
  render: ({ args }) => `Weather in ${args.city}`,
});
```

但随后会在设备上失败。该字符串会作为宿主视图的裸文本子节点进入预构建聊天的 `FlatList`，React Native 会抛出 *Text strings must be rendered within a `<Text>` component*。数字、元素数组或 `undefined` 也一样——它们都是 `ReactNode`，而没有一个能被 React Native 的列表渲染器绘制。

`@copilotkit/react-native` 导出一个**可选启用**的类型，它把返回类型收窄为 `ReactElement | null`，让编译器直接拒绝：

```tsx
import { useFrontendTool } from "@copilotkit/react-native";
import type { FrontendToolRenderFunction } from "@copilotkit/react-native";
import { Text } from "react-native";
import { z } from "zod";

const renderWeather: FrontendToolRenderFunction<{ city: string }> = ({
  args,
}) => <Text>{args.city}</Text>;

// `TS2322: Type 'string' is not assignable to type 'ReactElement…'`
const broken: FrontendToolRenderFunction<{ city: string }> = ({ args }) =>
  `Weather in ${args.city}`;

useFrontendTool({
  name: "showWeather",
  description: "Show the weather",
  parameters: z.object({ city: z.string() }),
  handler: async ({ city }) => city,
  render: renderWeather,
});
```

<PropertyReference name="FrontendToolRenderFunction<T>" type="(props: React.ComponentProps<ReactToolCallRenderer<T>['render']>) => React.ReactElement | null">
  一种工具调用渲染函数，其返回类型被收窄为 React Native 的 `ReactElement | null`。它的 props 直接取自 react-core 的权威契约 `ReactToolCallRenderer`，未做任何改动，因此不会与已注册渲染器实际被调用时的 props 产生偏差；只有返回类型是 React Native 特有的。

  `T` 是解析后的工具参数——与 `useFrontendTool` 的 `T` 相同——默认为 `Record<string, unknown>`，因此裸写也是合法的。
</PropertyReference>

<Callout type="warn" title="需要显式启用，且仅显式启用有效">
  该类型不改变任何钩子签名。在 `useFrontendTool` 调用中**内联**编写的渲染器仍按 react-core 返回 `ReactNode` 的契约进行检查，裸字符串在那里仍能通过编译。只有用它标注渲染器时才能获得收窄——将 `render` 声明为独立的 `FrontendToolRenderFunction<T>` 并传入，如上例所示。它本身并不能让这个包变得安全。
</Callout>

[`useRenderTool`](/reference/react-native/hooks/useRenderTool) 则完全不需要这些：它把自己的 `render` 声明为 `(props) => ReactElement | null`，因此在那里裸字符串无需任何标注就会被拒绝。

## 行为

- **重复检测**：如果已注册同名（`name`）工具，钩子会记录一条警告。同一时间每个名称只有一个工具处于活动状态。
- **挂载/卸载生命周期**：工具及其可选的渲染组件在挂载时注册，在卸载时移除。
- **依赖追踪**：提供 `deps` 时，任何依赖变化都会刷新注册。普通数据按值比较；函数和其他对象按引用比较。参见下文 [依赖比较](#依赖比较)。
- **handler 与 render 在注册时捕获**：两个闭包都不会在每次渲染时重新读取。`handler` 或 `render` 从组件状态或 props 读取的值，会冻结在工具最后一次注册时的值上，因此必须在 `deps` 中声明。
- **渲染组件生命周期**：如果提供了 `render` 函数，它会被加入内部的渲染工具调用注册表。它会接收流式传输中的 `args`（`InProgress` 期间为部分值，`Executing` 和 `Complete` 期间为完整值）。
- **`render` 的返回类型是 `ReactNode`，而非 `ReactElement | null`**：裸字符串能通过类型检查，随后会在聊天的 `FlatList` 中抛出异常。用 [`FrontendToolRenderFunction<T>`](#react-native-需要的-render-类型) 标注渲染器，让编译器拒绝它。
- **无返回值**：该钩子返回 `void`。

## 依赖比较

钩子将 `deps` 归约为一个版本号，并只把该版本号放入注册 effect（`packages/react-core/src/v2/hooks/tool-registration.ts`）。`deps` 从不被序列化。每个条目都与上一次渲染的对应条目进行比较：

- 普通数据按值比较：字符串、数字、布尔值、`null`、`undefined`、日期，以及由它们构成的普通对象和数组。诸如 `[{ status }]` 或 `[items.filter(isOpen)]` 这样的内联字面量只在其内容变化时才重新注册。键顺序无关紧要。
- 函数与之前一样永远不算变化：`deps` 中的新回调不会触发工具重新注册。通过 ref 读取会变化的回调（见下文）。
- 类实例、`Map`、`Set` 及其他非普通对象按引用（同一性）比较。
- 循环引用的值（例如 `useAgent` 返回的 `agent`）可以安全列出。普通数据内部的循环引用同样安全。
- 增加或移除条目都算变化。

为了在注册保持稳定的同时让闭包始终读到最新值，可以把该值排除在 `deps` 之外，并通过一个最新值 ref 来读取：

```tsx
import { useEffect, useRef } from "react";
import { useFrontendTool } from "@copilotkit/react-native";
import { z } from "zod";

function DraftTool({ onSubmit }: { onSubmit: () => Promise<string> }) {
  const latestOnSubmit = useRef(onSubmit);
  useEffect(() => {
    latestOnSubmit.current = onSubmit;
  });

  useFrontendTool(
    {
      name: "submitDraft",
      description: "Submit the current draft",
      parameters: z.object({}),
      handler: async () => latestOnSubmit.current(),
    },
    [],
  );

  return null;
}
```

同样的 ref 模式也适用于需要实时状态的 `render` 组件。
