## 概览

`useInterrupt` 处理智能体中断，并携带用户输入恢复执行。它支持 **AG-UI 标准中断流**——`RUN_FINISHED` 且 `outcome.type === "interrupt"`，携带一个 `interrupts` 数组——以及旧版自定义事件流（`on_interrupt`）。对于标准中断，你的 `render`/`handler` 会收到 `interrupt`（主要中断）和 `interrupts`（全部未决集合）；调用 `resolve(payload)` 恢复执行，或调用 `cancel()` 取消。

<Callout type="info">
  该钩子从 `@copilotkit/react-core/v2` 重新导出。它与 [React (V2) 的 `useInterrupt`](/reference/v2/hooks/useInterrupt) 完全相同，仅导入路径不同。
</Callout>

默认情况下，中断 UI 会自动渲染在 [`CopilotChat`](/reference/react-native/components/CopilotChat) 内部。如果你设置 `renderInChat: false`，该钩子会返回元素，由你手动放置。`render` 返回的元素是一个 React Native 元素。

`event.value` 的类型是 `any`，因为中断负载的结构取决于你的智能体。可根据需要在回调（如 `handler`、`enabled`、`render`）中做类型收窄。

## 签名

```tsx
import { useInterrupt } from "@copilotkit/react-native";

function useInterrupt<
  TResult = never,
  TRenderInChat extends boolean | undefined = undefined,
>(
  config: UseInterruptConfig<any, TResult, TRenderInChat>,
): TRenderInChat extends false
  ? React.ReactElement | null
  : TRenderInChat extends true | undefined
    ? void
    : React.ReactElement | null | void;
```

## 参数

<PropertyReference name="config" type="UseInterruptConfig<any, TResult, TRenderInChat>" required>
  中断配置。

  <PropertyReference name="render" type="(props: InterruptRenderProps<any, TResult | null>) => React.ReactElement" required>
    中断 UI 的渲染回调。当有中断可用时调用。该回调接收：
    - `event`：中断事件（`{ name, value }`）。`value` 为 `any`；可根据需要在回调中做类型收窄。
    - `interrupt`：主要的标准 `Interrupt`（`{ id, reason, message?, toolCallId?, responseSchema?, expiresAt?, metadata? }`），旧版中断时为 `null`。
    - `interrupts`：所有未决的标准中断（旧版中断为空数组）。
    - `result`：从 `handler` 返回类型推断，或为 `null`
    - `resolve(payload?, interruptId?)`：对于标准中断，为目标中断（默认为主要中断）记录 `{ status: "resolved", payload }`，并在所有未决中断都处理完毕后统一提交。对于旧版中断，通过 `command.resume = payload` 立即恢复。
    - `cancel(interruptId?)`：对于标准中断，为目标中断记录 `{ status: "cancelled" }`，并在全部处理完毕后恢复。旧版中断不支持（直接关闭且不恢复）。
  </PropertyReference>

<PropertyReference
  name="handler"
  type="(props: InterruptHandlerProps) => TResult | PromiseLike<TResult>"
>
  可选的预处理回调。在渲染之前运行，可以返回同步或异步数据，这些数据会在 `render` 中以 `result` 暴露。`TResult` 会根据处理函数的返回类型自动推断。如果处理函数抛出异常或被拒绝，`result` 为 `null`。
</PropertyReference>

<PropertyReference name="enabled" type="(event: InterruptEvent) => boolean">
  可选的过滤器。返回 `false` 可让该钩子实例忽略匹配的中断。
</PropertyReference>

<PropertyReference name="agentId" type="string">
  可选的智能体 id。默认为当前配置的聊天智能体。
</PropertyReference>

  <PropertyReference name="renderInChat" type="boolean" default="true">
    控制 UI 渲染的位置：
    - `true`（默认）：把中断 UI 发布到 [`CopilotChat`](/reference/react-native/components/CopilotChat)
    - `false`：从钩子返回中断元素，由你手动放置
  </PropertyReference>
</PropertyReference>

## 返回值

<PropertyReference name="element" type="Conditional by renderInChat">
  返回类型由 `renderInChat` 推断：
  - `renderInChat: false` -> `React.ReactElement | null`
  - `renderInChat: true` 或省略 -> `void`
  - 动态布尔值 -> `React.ReactElement | null | void`
</PropertyReference>

## 用法

### 聊天内中断 UI（默认）

```tsx
import { Text, TouchableOpacity, View } from "react-native";
import { useInterrupt } from "@copilotkit/react-native";

function ApprovalInterrupt() {
  useInterrupt({
    render: ({ event, resolve }) => (
      <View style={{ padding: 12, borderWidth: 1, borderRadius: 8 }}>
        <Text>{event.value.question}</Text>
        <View style={{ marginTop: 8, flexDirection: "row", gap: 8 }}>
          <TouchableOpacity onPress={() => resolve({ approved: true })}>
            <Text>Approve</Text>
          </TouchableOpacity>
          <TouchableOpacity onPress={() => resolve({ approved: false })}>
            <Text>Reject</Text>
          </TouchableOpacity>
        </View>
      </View>
    ),
  });

  return null;
}
```

### AG-UI 标准中断（批准 / 取消）

```tsx
import { Text, TouchableOpacity, View } from "react-native";
import { useInterrupt } from "@copilotkit/react-native";

function ApprovalInterrupt() {
  useInterrupt({
    render: ({ interrupt, resolve, cancel }) => (
      <View style={{ padding: 12, borderWidth: 1, borderRadius: 8 }}>
        <Text>{interrupt?.message ?? "Approve this action?"}</Text>
        <View style={{ marginTop: 8, flexDirection: "row", gap: 8 }}>
          <TouchableOpacity onPress={() => resolve({ approved: true })}>
            <Text>Approve</Text>
          </TouchableOpacity>
          <TouchableOpacity onPress={() => cancel()}>
            <Text>Cancel</Text>
          </TouchableOpacity>
        </View>
      </View>
    ),
  });

  return null;
}
```

### 手动放置与异步预处理

```tsx
import { Text, TouchableOpacity, View } from "react-native";
import { useInterrupt } from "@copilotkit/react-native";

function SidePanelInterrupt() {
  const element = useInterrupt({
    renderInChat: false,
    enabled: (event) => event.value.startsWith("approval:"),
    handler: async ({ event }) => ({ label: event.value.toUpperCase() }),
    render: ({ event, result, resolve }) => (
      <View style={{ borderWidth: 1, borderRadius: 8, padding: 12 }}>
        <Text style={{ fontWeight: "500" }}>{result?.label ?? ""}</Text>
        <Text style={{ marginTop: 8 }}>{event.value}</Text>
        <TouchableOpacity style={{ marginTop: 8 }} onPress={() => resolve({ accepted: true })}>
          <Text>Continue</Text>
        </TouchableOpacity>
      </View>
    ),
  });

  return <>{element}</>;
}
```

## 行为

- 标准中断从 `RUN_FINISHED`（`outcome.type === "interrupt"`）检测；旧版中断从 `on_interrupt` 自定义事件检测。
- `resolve`/`cancel` 会为每个未决中断累积一条响应；当所有未决中断都处理完毕后，恢复运行才会启动。
- 已过期（超过 `expiresAt`）的中断不会被恢复。
- 中断 UI 在运行收尾时呈现。
- 启动新的运行会清除待处理的中断状态。
- `event.value` 为 `any`；可根据需要在回调中做类型收窄。对于标准中断，`event.value` 就是主要的 `Interrupt`。
- `render.result` 从 `handler` 的返回类型推断，始终为 `TResult | null`。
- 如果 `handler` 抛出异常或被拒绝，`result` 会被设为 `null`。
