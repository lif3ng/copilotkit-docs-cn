## 概览

`useAgent` 是一个 React hook，返回 [AG-UI AbstractAgent](https://docs.ag-ui.com/sdk/js/client/abstract-agent) 实例。该 hook 会订阅智能体状态变化，并在智能体的状态、消息或执行状态发生变化时触发重新渲染。

<Callout type="info">
  从 `@copilotkit/react-core/v2` 重新导出。与 [React (V2) 的 `useAgent`](/reference/v2/hooks/useAgent) 完全相同，只是导入路径不同。
</Callout>

默认情况下，它绑定到 CopilotKit 注册表中的共享智能体。它也可以为单个线程注册私有的代理智能体，这在使用自定义线程切换器和多会话 UI 时非常有用。

如果未配置具有指定 `agentId` 的智能体，或仅提供了线程作用域选项集的一部分，则会**抛出错误**。

## 签名

```tsx
import { useAgent } from "@copilotkit/react-native";

function useAgent(options?: UseAgentProps): {
  agent: AbstractAgent;
  isReady: boolean;
};
```

对于不导入内置聊天渲染栈的完全无头 UI，请从无头入口导入该 hook：

```tsx
import { useAgent } from "@copilotkit/react-native/headless";
```

## 参数

<PropertyReference name="options" type="UseAgentProps">
  该 hook 的配置对象。

<PropertyReference name="agentId" type="string" default='"default"'>
  要获取的智能体的 ID。解析顺序为：显式指定的 `agentId`、外围聊天配置的 `agentId`、提供方级别的 `agentId`，最后是 `"default"`。
</PropertyReference>

  <PropertyReference name="threadId" type="string">
    私有代理智能体的线程 ID。必须与 `agentId` 和 `runtimeAgentId` 一起传入。
  </PropertyReference>

  <PropertyReference name="runtimeAgentId" type="string">
    注册私有代理智能体时，请求要路由到的 runtime 侧智能体 ID。必须与 `agentId` 和 `threadId` 一起传入。
  </PropertyReference>

  <PropertyReference name="updates" type="UseAgentUpdate[]" default="[OnMessagesChanged, OnStateChanged, OnRunStatusChanged]">
    控制哪些智能体变化会触发组件重新渲染。可选值：
    - `UseAgentUpdate.OnMessagesChanged` - 消息变化时重新渲染
    - `UseAgentUpdate.OnStateChanged` - 状态变化时重新渲染
    - `UseAgentUpdate.OnRunStatusChanged` - 执行状态变化时重新渲染

    传入空数组 `[]` 可阻止自动重新渲染。

  </PropertyReference>

  <PropertyReference name="throttleMs" type="number">
    由消息与状态变化触发的重新渲染的节流间隔（毫秒）。运行生命周期更新仍会立即触发。省略时，该 hook 继承提供方的 `defaultThrottleMs`；若两个值都未设置，则更新不节流。传入 `0` 可为该 hook 禁用提供方节流。
  </PropertyReference>
</PropertyReference>

有两种合法的选项形态：

- `useAgent()` 或 `useAgent({ agentId })`：绑定到共享智能体。线程来自聊天配置或智能体本身。
- `useAgent({ agentId, runtimeAgentId, threadId })`：在 `agentId` 下注册一个私有本地智能体，将其路由到 `runtimeAgentId` 所指的 runtime 智能体，并固定到 `threadId`。

## 返回值

<PropertyReference name="object" type="{ agent: AbstractAgent; isReady: boolean }">
  包含智能体实例及其就绪信号的对象。

  <PropertyReference name="agent" type="AbstractAgent">
    AG-UI 智能体实例。完整接口细节参见 [AbstractAgent 文档](https://docs.ag-ui.com/sdk/js/client/abstract-agent)。

    ### 核心属性

    <PropertyReference name="agentId" type="string | undefined">
      智能体实例的唯一标识符。
    </PropertyReference>

    <PropertyReference name="description" type="string">
      对智能体用途的人类可读描述。
    </PropertyReference>

    <PropertyReference name="threadId" type="string">
      当前会话线程的唯一标识符。
    </PropertyReference>

    <PropertyReference name="messages" type="Message[]">
      会话消息数组。每条消息包含：
      - `id: string` - 消息的唯一标识符
      - `role: "user" | "assistant" | "system"` - 消息角色
      - `content: string` - 消息内容
    </PropertyReference>

    <PropertyReference name="state" type="any">
      在应用与智能体之间同步的共享状态对象。双方都可以读取和修改该状态。
    </PropertyReference>

    <PropertyReference name="isRunning" type="boolean">
      表示智能体当前是否正在执行。
    </PropertyReference>

    ### 方法

    <PropertyReference name="runAgent" type="(parameters?: RunAgentParameters, subscriber?: AgentSubscriber) => Promise<RunAgentResult>">
      底层方法：向智能体发送一次运行，并在运行结束后以 `RunAgentResult`（`{ result, newMessages }`）兑现。`result` 是该运行的最终值，`newMessages` 是运行期间产生的消息。

      它不会发送你已注册的前端工具或上下文，不会执行前端工具调用，也不会链式发起后续运行。普通运行请改用 [`useCopilotKit`](/reference/react-native/hooks/useCopilotKit) 中的 `copilotkit.runAgent({ agent })`。它接受相同的 `forwardedProps`，并以相同的 `RunAgentResult` 兑现。与 `agent.runAgent()` 不同，当运行本身失败时它不会 reject，核心会把该错误（错误码 `AGENT_RUN_FAILED`）上报给错误订阅者，并以 `{ result: undefined, newMessages: [] }` 兑现。

      **参数**：
      - `parameters.forwardedProps?: any` - 传递给智能体执行上下文的数据

      要响应中断，请使用 [`useInterrupt`](/reference/react-native/hooks/useInterrupt)，它会替你恢复运行。若要手动恢复，请传入标准 `resume` 数组，其中包含被暂停运行所报告的中断 id：`copilotkit.runAgent({ agent, resume: [{ interruptId: interrupt.id, status: "resolved", payload }] })`。较旧的 `forwardedProps: { command: { resume } }` 形式是 `on_interrupt` 自定义事件的旧版路径。

      **示例**：
      ```tsx
      const { copilotkit } = useCopilotKit();

      const { result, newMessages } = await copilotkit.runAgent({
        agent,
        // Any data your agent reads from the run input.
        forwardedProps: { source: "refresh-button" },
      });
      ```
    </PropertyReference>

    <PropertyReference name="setState" type="(newState: any) => void">
      更新共享状态。更改对应用与智能体双方立即可见。

      **示例**：
      ```tsx
      agent.setState({
        ...agent.state,
        theme: "dark"
      });
      ```
    </PropertyReference>

    <PropertyReference name="subscribe" type="(subscriber: AgentSubscriber) => { unsubscribe: () => void }">
      订阅智能体事件。返回清理函数。

      **订阅者事件**：
      - `onCustomEvent?: ({ event: { name: string, value: any } }) => void` - 自定义事件
      - `onRunStartedEvent?: () => void` - 智能体执行开始
      - `onRunFinalized?: () => void` - 智能体执行完成
      - `onStateChanged?: (state: any) => void` - 状态变化
      - `onMessagesChanged?: (messages: Message[]) => void` - 消息新增或修改
    </PropertyReference>

    <PropertyReference name="addMessage" type="(message: Message) => void">
      向会话添加单条消息，并通知订阅者。
    </PropertyReference>

    <PropertyReference name="addMessages" type="(messages: Message[]) => void">
      向会话添加多条消息，并一次性通知订阅者。
    </PropertyReference>

    <PropertyReference name="setMessages" type="(messages: Message[]) => void">
      用一个新的消息数组替换整个消息历史。
    </PropertyReference>

    <PropertyReference name="abortRun" type="() => void">
      中止当前正在执行的智能体运行。
    </PropertyReference>

    <PropertyReference name="clone" type="() => AbstractAgent">
      创建智能体的深拷贝，包括克隆的消息、状态与配置。
    </PropertyReference>

  </PropertyReference>

  <PropertyReference name="isReady" type="boolean">
    表示 `agent` 是真实的、已与 runtime 同步的智能体，而非 runtime 仍在连接或连接失败时返回的临时替身。

    `agent` 始终是一个完整构造的实例，因此调用其方法总是安全的。当 `isReady` 为 `false` 时，该实例只是一个占位符，待 runtime 完成同步后会被替换为真实智能体——届时 `agent` 的引用会发生变化，依赖它的副作用会重新执行。当你只想针对真实智能体执行操作时（例如订阅不希望在临时窗口期间错过的运行生命周期事件），请以 `isReady` 作为守卫条件。
  </PropertyReference>
</PropertyReference>

## 用法

### 基本用法

```tsx
import { Text, View } from "react-native";
import { useAgent } from "@copilotkit/react-native";

function AgentStatus() {
  const { agent } = useAgent();

  return (
    <View>
      <Text>Agent: {agent.agentId}</Text>
      <Text>Messages: {agent.messages.length}</Text>
      <Text>Running: {agent.isRunning ? "Yes" : "No"}</Text>
    </View>
  );
}
```

### 访问与更新状态

```tsx
import { Text, TouchableOpacity, View } from "react-native";
import { useAgent } from "@copilotkit/react-native";

function StateController() {
  const { agent } = useAgent();

  return (
    <View>
      <Text>{JSON.stringify(agent.state, null, 2)}</Text>
      <TouchableOpacity
        onPress={() => agent.setState({ ...agent.state, count: 1 })}
      >
        <Text>Update State</Text>
      </TouchableOpacity>
    </View>
  );
}
```

### 事件订阅

```tsx
import { useEffect } from "react";
import { useAgent } from "@copilotkit/react-native";

function EventListener() {
  const { agent } = useAgent();

  useEffect(() => {
    const { unsubscribe } = agent.subscribe({
      onRunStartedEvent: () => console.log("Started"),
      onRunFinalized: () => console.log("Finished"),
    });

    return unsubscribe;
  }, []);

  return null;
}
```

### 多个智能体

```tsx
import { Text, View } from "react-native";
import { useAgent } from "@copilotkit/react-native";

function MultiAgentView() {
  const { agent: primary } = useAgent({ agentId: "primary" });
  const { agent: support } = useAgent({ agentId: "support" });

  return (
    <View>
      <Text>Primary: {primary.messages.length} messages</Text>
      <Text>Support: {support.messages.length} messages</Text>
    </View>
  );
}
```

### 线程作用域的智能体

当一个 runtime 智能体需要多个独立的前端实例时（例如每个打开的会话一个），请使用线程作用域形式。本地 `agentId` 在当前提供方内必须唯一。

```tsx
import { Text } from "react-native";
import { useAgent } from "@copilotkit/react-native";

function ThreadPreview({ threadId }: { threadId: string }) {
  const { agent, isReady } = useAgent({
    agentId: `preview-${threadId}`,
    runtimeAgentId: "support",
    threadId,
    throttleMs: 100,
  });

  if (!isReady) return <Text>Loading...</Text>;

  return <Text>{agent.messages.length} messages</Text>;
}
```

### 优化重渲染

```tsx
import { Text } from "react-native";
import { useAgent, UseAgentUpdate } from "@copilotkit/react-native";

// Only re-render when messages change
function MessageCount() {
  const { agent } = useAgent({
    updates: [UseAgentUpdate.OnMessagesChanged],
  });

  return <Text>Messages: {agent.messages.length}</Text>;
}
```

## 行为

- **自动重新渲染**：当智能体状态、消息或执行状态变化时组件重新渲染（可通过 `updates` 参数配置）
- **可选节流**：消息与状态更新触发的重新渲染可通过 `throttleMs` 或提供方的 `defaultThrottleMs` 进行节流。
- **就绪状态**：runtime 连接期间，`agent` 是一个完整构造的临时替身，`isReady` 为 `false`；runtime 同步完成后，`agent` 会切换为真实实例，`isReady` 变为 `true`。必须以真实智能体为目标的操作（例如一次性订阅）请以 `isReady` 作为守卫条件
- **错误处理**：如果不存在具有指定 `agentId` 的智能体，则抛出错误
- **线程作用域**：`threadId` 与 `runtimeAgentId` 必须与显式的本地 `agentId` 一起传入；不完整的组合会在运行时抛错，且无法通过 TypeScript 类型检查。
- **状态同步**：通过 `setState()` 进行的状态更新对应用与智能体双方立即可见
- **事件订阅**：针对生命周期事件与自定义事件的订阅/取消订阅模式
