## 概览

`CopilotKitProvider` 是 CopilotKit 的 React Native 提供方。用它包裹你的应用（或需要 copilot 的子树），即可配置运行时连接。其下的每个 hook 与组件都会从上下文读取配置好的客户端。

导入该包会自动安装 CopilotKit 在 Hermes 上所需的 [polyfills](/reference/react-native#polyfills)，因此使用提供方之前无需手动导入它们。

<Callout type="info">
  React Native 尚不支持云功能（`publicLicenseKey` / 受许可密钥控制的功能）。请将 `runtimeUrl` 指向自托管的运行时。
</Callout>

<Callout type="info">
  原生 iOS 与 Android 应用暂无内置 Inspector。浏览器版 Inspector 依赖 DOM，已被有意排除在 React Native 依赖图之外，因此该提供方不暴露 inspector prop。
</Callout>

## 导入

```tsx
import { CopilotKitProvider } from "@copilotkit/react-native";
```

## 属性

<PropertyReference name="children" type="ReactNode" required>
  在提供方内渲染的组件。
</PropertyReference>

<PropertyReference name="runtimeUrl" type="string" required>
  CopilotKit 运行时端点的 URL，例如
  `https://your-server/api/copilotkit`。在物理设备上测试时，请使用你机器的局域网 IP（而非 `localhost`）。
</PropertyReference>

<PropertyReference name="headers" type="Record<string, string> | (() => Record<string, string>)" default="{}">
  随每个运行时请求一起发送的自定义请求头。传函数可惰性计算请求头（例如附加最新的授权令牌）。该函数在提供方渲染时调用，而非每个请求调用——参见[前端：React Native](/frontends/react-native#provider-options)了解轮换令牌模式。

  web 版提供方的构建函数现在在发送时执行，且接受异步函数。这两者此处均暂不支持：React Native 上仅支持在渲染时求值的同步函数。
</PropertyReference>

<PropertyReference name="credentials" type="RequestCredentials">
  fetch 请求的凭据模式（例如跨域请求中为 HTTP-only cookie 使用 `"include"`）。
</PropertyReference>

<PropertyReference name="messageFilter" type="(messages: Message[], context: { agentId: string }) => Message[]">
  在每次运行时重写发送给智能体的消息列表。

CopilotKit 会在每次请求时发送整个线程。当你的智能体已经存储了会话——LangGraph checkpointer、Mastra memory store、Strands `SessionManager`——这些负载大部分都是浪费，而且将传入列表与自己存储合并的智能体可能会把每一轮对话向模型展示两次。在移动网络下，这种负载代价会更早显现。

返回要发送的消息：

```tsx
<CopilotKitProvider
  runtimeUrl="https://your-server/api/copilotkit"
  messageFilter={(messages) => messages.slice(-1)}
>
  <App />
</CopilotKitProvider>
```

该过滤器只改变请求体。UI 渲染的会话记录不受影响，因此聊天仍显示完整对话。损坏的工具调用对会在请求发出前被修复，因此如此粗放的过滤器也不会让某个工具结果卡在审批中途。

通过你的 CopilotRuntime 访问的智能体会遵守此设置。你的应用自行构建并直接传入的智能体则不会。CopilotKit Intelligence 运行与建议运行永远不会被过滤。

</PropertyReference>

<PropertyReference name="useSingleEndpoint" type="boolean">
  运行时是否使用单一路由端点。不设置则自动检测。
</PropertyReference>

<PropertyReference name="properties" type="Record<string, unknown>" default="{}">
  每次运行时转发给智能体的自定义属性（例如用户元数据或 LangGraph Platform 的 `authorization`）。
</PropertyReference>

<PropertyReference name="onError" type="(event: { error: Error; code: CopilotKitCoreErrorCode; context: Record<string, any> }) => void | Promise<void>">
  当 CopilotKit 遇到错误时调用的错误处理器。对所有错误类型都会触发：运行时连接失败、智能体错误与工具错误。若未提供，错误将记录到 `console.error`。

```tsx
<CopilotKitProvider
  runtimeUrl="https://your-server/api/copilotkit"
  onError={(event) => {
    console.error(`[${event.code}]`, event.error.message, event.context);
  }}
>
  <App />
</CopilotKitProvider>
```

</PropertyReference>

<PropertyReference name="debug" type="DebugConfig">
  启用客户端事件管线的调试日志。为 `true` 时，核心实例会输出详细日志。
</PropertyReference>

<PropertyReference name="defaultThrottleMs" type="number">
  `onMessagesChanged` / `onStateChanged` 订阅的默认节流间隔（毫秒）。各个 hook 与组件可通过各自的 `throttleMs` 覆盖。
</PropertyReference>

## 用法

```tsx
import { CopilotKitProvider } from "@copilotkit/react-native";
import { SafeAreaProvider } from "react-native-safe-area-context";
import { ChatScreen } from "./ChatScreen";

export default function App() {
  return (
    <SafeAreaProvider>
      <CopilotKitProvider runtimeUrl="https://your-server/api/copilotkit">
        <ChatScreen />
      </CopilotKitProvider>
    </SafeAreaProvider>
  );
}
```

## 行为

- **自动安装 polyfill**：导入该包会在任何 CopilotKit 代码运行前，安装 CopilotKit 所依赖的 Web API polyfill（`ReadableStream`、`TextEncoder`、`crypto.getRandomValues`、`DOMException`、`location`）。
- **共享的渲染工具注册表**：该提供方会实例化 CopilotKit 客户端，其渲染器注册表与其余 CopilotKit 共享。由 [`useRenderTool`](/reference/react-native/hooks/useRenderTool)、[`useFrontendTool`](/reference/react-native/hooks/useFrontendTool) 或 [`useComponent`](/reference/react-native/hooks/useComponent) 注册的渲染函数都写入同一个注册表，因此它们与 [`useRenderToolCall`](/reference/react-native/hooks/useRenderTool#rendering-a-tool-call-outside-the-chat) 可以在提供方下任何位置工作。无需第二个注册表，也无需为渲染额外挂载提供方。
- **稳定的引用**：请求头函数与 `properties` 会在内部做记忆化，以避免重新渲染时的 effect 抖动。
