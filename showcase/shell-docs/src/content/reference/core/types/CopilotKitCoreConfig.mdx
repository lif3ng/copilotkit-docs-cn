## 概览

`CopilotKitCoreConfig` 是 [`CopilotKitCore`](/reference/core/classes/CopilotKitCore) 构造函数接受的配置对象。它将核心连接到 CopilotRuntime 端点，并为它预置前端工具、建议、请求头和转发的属性。

## 导入

```ts
import type { CopilotKitCoreConfig } from "@copilotkit/core";
```

## 定义

```ts
interface CopilotKitCoreConfig {
  runtimeUrl?: string;
  runtimeTransport?: CopilotRuntimeTransport;
  agents__unsafe_dev_only?: Record<string, AbstractAgent>;
  headers?:
    | Record<string, string>
    | (() => Record<string, string>)
    | (() => Promise<Record<string, string>>);
  credentials?: RequestCredentials;
  messageFilter?: CopilotKitMessageFilter;
  properties?: Record<string, unknown>;
  tools?: FrontendTool<any>[];
  suggestionsConfig?: SuggestionsConfig[];
  debug?: DebugConfig;
}
```

## 属性

<PropertyReference name="runtimeUrl" type="string">
  CopilotRuntime 的端点。
</PropertyReference>

<PropertyReference name="runtimeTransport" type='"rest" | "single" | "auto"' default="auto">
  CopilotRuntime 端点的传输方式。`"auto"` 会先探测 REST，失败时回退到单路由模式。
</PropertyReference>

<PropertyReference name="agents__unsafe_dev_only" type="Record<string, AbstractAgent>">
  智能体名称到其 `AbstractAgent` 实例的映射。仅供开发使用——生产环境需要 CopilotRuntime。
</PropertyReference>

<PropertyReference name="headers" type="Record<string, string> | (() => Record<string, string>) | (() => Promise<Record<string, string>>)" default="{}">
  附加到 `CopilotKitCore` 发出的每个 HTTP 请求上的请求头。传入一个 record 表示静态请求头，或传入一个函数（同步或异步）来即时构建它们。构建器会在每次请求发送时运行，因此总能用到刷新后的 token。请在构建器内部做缓存——每次都发起网络调用的构建器会给每个请求额外增加一次调用。

  如果构建器抛出异常或返回 rejected，请求将不会被发送，`onError` 会收到 [`HEADER_RESOLUTION_FAILED`](/reference/core/enums/CopilotKitCoreErrorCode)。

  参见 [`CopilotKitCore`](/reference/core/classes/CopilotKitCore) 上的 `setHeaders` 与 `resolveHeaders`。
</PropertyReference>

<PropertyReference name="credentials" type="RequestCredentials">
  fetch 请求的凭据模式（例如设为 `"include"` 以发送 HTTP-only cookie）。
</PropertyReference>

<PropertyReference name="messageFilter" type="CopilotKitMessageFilter">
  在每次运行时重写发送给运行时智能体的消息列表。当智能体已经自行保存了会话、重新发送只会造成浪费或重复时，可以使用它。该过滤器只改变请求体——UI 渲染的会话记录不受影响——并且在请求发出前会修复损坏的工具调用配对。智能推理运行与建议运行永远不会被过滤。之后可通过 `setMessageFilter` 修改。
</PropertyReference>

<PropertyReference name="properties" type="Record<string, unknown>" default="{}">
  以 `forwardedProps` 形式发送给 AG-UI 智能体的属性。
</PropertyReference>

<PropertyReference name="tools" type="FrontendTool<any>[]" default="[]">
  核心可用的[前端工具](/reference/core/types/FrontendTool)的有序集合。
</PropertyReference>

<PropertyReference name="suggestionsConfig" type="SuggestionsConfig[]" default="[]">
  核心的[建议配置](/reference/core/types/SuggestionsConfig)。
</PropertyReference>

<PropertyReference name="debug" type="DebugConfig">
  为客户端事件管线启用调试日志。
</PropertyReference>

## 用法

```ts
import { CopilotKitCore } from "@copilotkit/core";
import { z } from "zod";

const copilotkit = new CopilotKitCore({
  runtimeUrl: "/api/copilotkit",
  headers: { Authorization: "Bearer token" },
  properties: { userId: "user_123" },
  tools: [
    {
      name: "sayHello",
      description: "Greet the user",
      parameters: z.object({ name: z.string() }),
      handler: async ({ name }) => `Hello, ${name}!`,
    },
  ],
});
```
