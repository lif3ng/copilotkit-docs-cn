## 概览

`CopilotKitCore` 是 `@copilotkit/core` 的主入口。它通过 AG-UI 协议连接到 CopilotRuntime，暴露可用的智能体，持有前端工具、共享上下文和建议的注册表，并在这些状态发生任何变化时通知订阅者。React、Angular 和原生（vanilla）绑定都包装了该类的一个单一实例——当你需要在这些框架之外使用智能体客户端时，可以直接使用它。

## 导入

```ts
import { CopilotKitCore } from "@copilotkit/core";
```

## 构造函数

```ts
new CopilotKitCore(config: CopilotKitCoreConfig)
```

<PropertyReference name="config" type="CopilotKitCoreConfig" required>

  <PropertyReference name="runtimeUrl" type="string">

  <PropertyReference name="runtimeTransport" type='"rest" | "single" | "auto"' default="auto">
    运行时端点的传输方式。`"auto"` 会先探测 REST，失败时回退到单路由。
  </PropertyReference>

  <PropertyReference name="headers" type="Record<string, string> | (() => Record<string, string>) | (() => Promise<Record<string, string>>)" default="{}">
    附加到核心发出的每个 HTTP 请求的请求头。传记录（record）表示静态请求头，或传一个（同步或异步）函数来实时构建。构建函数在每次请求发送时运行，因此始终使用刷新后的令牌。请在构建函数内部做好缓存——每次都发起网络调用的构建函数会给每个请求增加一次额外调用。如果构建函数抛出异常或 Promise 被拒绝，该请求将不会发送，并且 `onError` 会收到 `HEADER_RESOLUTION_FAILED`。
  </PropertyReference>

  <PropertyReference name="credentials" type="RequestCredentials">

  </PropertyReference>

  </PropertyReference>

  <PropertyReference name="agents__unsafe_dev_only" type="Record<string, AbstractAgent>" default="{}">
    以名称为键的本地智能体实例。仅限开发——生产环境需要 CopilotRuntime。
  </PropertyReference>

  <PropertyReference name="debug" type="DebugConfig">
    为客户端事件管线启用调试日志。
  </PropertyReference>
</PropertyReference>

## 方法

### 智能体

<PropertyReference name="getAgent(id: string): AbstractAgent | undefined" type="method">
  返回以 `id` 注册的智能体，不存在时返回 `undefined`。
</PropertyReference>

<PropertyReference name="runAgent(params: CopilotKitCoreRunAgentParams): Promise<RunAgentResult>" type="method">
  针对运行时运行一个智能体，流式接收事件并执行其产生的所有前端工具调用。
</PropertyReference>

<PropertyReference name="connectAgent(params: CopilotKitCoreConnectAgentParams): Promise<RunAgentResult>" type="method">
  连接到一个智能体以接收其当前状态和消息流，而不开启新的运行。
</PropertyReference>

<PropertyReference name="stopAgent(params: CopilotKitCoreStopAgentParams): void" type="method">
  中止给定智能体当前的运行。
</PropertyReference>

<PropertyReference name="registerProxiedAgent(params): { agent; unregister }" type="method">
  在本地的 `agentId` 下注册一个 [ProxiedCopilotRuntimeAgent](/reference/core/classes/ProxiedCopilotRuntimeAgent)，把出站请求路由到 `runtimeAgentId`。返回该代理和一个 `unregister` 清理句柄。若 `agentId` 已被占用则抛出异常。
</PropertyReference>

<PropertyReference name="addAgent__unsafe_dev_only(params: CopilotKitCoreAddAgentParams): void" type="method">
  添加一个本地智能体实例。仅限开发。
</PropertyReference>

<PropertyReference name="removeAgent__unsafe_dev_only(id: string): void" type="method">
  按 id 移除一个本地智能体。仅限开发。
</PropertyReference>

<PropertyReference name="setAgents__unsafe_dev_only(agents: Record<string, AbstractAgent>): void" type="method">
  替换整个本地智能体集合。仅限开发。
</PropertyReference>

### 工具

<PropertyReference name="addTool(tool: FrontendTool): void" type="method">
  注册一个智能体可调用的前端工具。如果同名且 `agentId` 相同的工具已注册，该调用为空操作（会记录一条警告）。参见 [FrontendTool](/reference/core/types/FrontendTool)。
</PropertyReference>

<PropertyReference name="removeTool(id: string, agentId?: string): void" type="method">
  按名称移除已注册的工具。不传 `agentId` 时，只移除该名称的全局（未限定作用域）工具；传入 `agentId` 时，只移除限定到该智能体的工具。
</PropertyReference>

<PropertyReference name="getTool(params: CopilotKitCoreGetToolParams): FrontendTool<any> | undefined" type="method">
  返回一个已注册的工具，找不到时返回 `undefined`。
</PropertyReference>

<PropertyReference name="setTools(tools: FrontendTool<any>[]): void" type="method">
  替换整个工具注册表。
</PropertyReference>

<PropertyReference name="runTool(params: CopilotKitCoreRunToolParams): Promise<CopilotKitCoreRunToolResult>" type="method">
  直接执行一个已注册的前端工具，无需 LLM 轮次。处理函数会运行，渲染组件会出现，并且工具调用与结果消息都会追加到 `agent.messages`。
</PropertyReference>

### 上下文

<PropertyReference name="addContext(context: Context): string" type="method">
  添加一个与智能体共享的上下文条目，并返回其生成的 id。
</PropertyReference>

<PropertyReference name="removeContext(id: string): void" type="method">
  按 id 移除一个上下文条目。
</PropertyReference>

### 建议

<PropertyReference name="addSuggestionsConfig(config: SuggestionsConfig): string" type="method">
  注册一个建议配置并返回其生成的 id。
</PropertyReference>

<PropertyReference name="removeSuggestionsConfig(id: string): void" type="method">
  按 id 移除一个建议配置。
</PropertyReference>

<PropertyReference name="getSuggestions(agentId: string): CopilotKitCoreGetSuggestionsResult" type="method">
  返回某个智能体当前的建议和加载状态。
</PropertyReference>

<PropertyReference name="reloadSuggestions(agentId: string): void" type="method">
  为某个智能体重新生成建议。
</PropertyReference>

<PropertyReference name="clearSuggestions(agentId: string): void" type="method">
  清空某个智能体当前的建议。
</PropertyReference>

### 订阅

<PropertyReference name="subscribe(subscriber: CopilotKitCoreSubscriber): CopilotKitCoreSubscription" type="method">
  订阅核心生命周期事件（智能体变更、上下文变更、错误、运行时连接状态等）。返回一个带 `unsubscribe()` 方法的订阅对象。参见 [CopilotKitCoreSubscriber](/reference/core/types/CopilotKitCoreSubscriber)。
</PropertyReference>

<PropertyReference name="subscribeToAgentWithOptions(agent, subscriber, options?): CopilotKitCoreSubscription" type="method">
  订阅单个智能体的消息、状态和运行生命周期回调，支持可选节流。每个回调都带有错误保护。当你需要 AG-UI 事件处理函数或逐条通知时，请直接使用 `agent.subscribe()`。
</PropertyReference>

### Inspector 元数据

<PropertyReference name="refreshInspectorMetadata(): Promise<void>" type="method">
  在不重连运行时智能体的情况下刷新可选的可信 Inspector 元数据。核心只会在已连接到 runtime-info 响应中报告 `inspectorMetadata: true` 的运行时时才发起请求。每次刷新有五秒的截止时限。路由、超时和解析失败都会以“无元数据”告终，不会改变运行时连接状态。
</PropertyReference>

### 配置

<PropertyReference name="setRuntimeUrl(runtimeUrl: string | undefined): void" type="method">
  更新运行时端点。
</PropertyReference>

<PropertyReference name="setRuntimeTransport(runtimeTransport: CopilotRuntimeTransport): void" type="method">
  更新传输方式。
</PropertyReference>

<PropertyReference name="setHeaders(headers: CopilotKitHeadersSource): void" type="method">
  替换请求头并重新应用到现有智能体。可传记录、同步构建函数或异步构建函数——见 [`headers`](/reference/core/types/CopilotKitCoreConfig) 配置项。对于记录，值为 `null` 或 `undefined` 的键会从存储的请求头中删除，这是清除某个请求头的受支持方式（例如登出时清除 `Authorization`）。空字符串仍是有效的请求头值，会被保留。核心会用新请求头刷新之前先清空可信 Inspector 元数据，并通知 `onHeadersChanged` 订阅者。

  当当前来源也是一条规范化后取值相同的记录时，此调用是空操作——不刷新 Inspector、也不触发 `onHeadersChanged`。新的构建函数、取值不同的记录、或记录与构建函数之间的切换，都算作变更。构建函数自行解析出新令牌（例如轮换的鉴权令牌）永远不会触发 `onHeadersChanged`，也不会自行重新应用请求头——它会在下次发送请求时被采用。请把响应式逻辑建立在“请求头发生变更”上，而不要依赖请求头的值或对象同一性。
</PropertyReference>

<PropertyReference name="resolveHeaders(): Record<string, string> | Promise<Record<string, string>>" type="method">
  解析当前请求头：记录或同步构建函数时同步返回，异步构建函数时返回 Promise。并发调用会共享同一次进行中的构建函数调用。用它获取构建函数当下会产生的值——下面的 `headers` getter 只反映上次解析出的值。
</PropertyReference>

<PropertyReference name="setCredentials(credentials: RequestCredentials | undefined): void" type="method">
  替换 fetch 凭据模式并重新应用到现有智能体。核心会用新模式刷新之前先清空可信 Inspector 元数据。
</PropertyReference>

<PropertyReference name="setMessageFilter(messageFilter: CopilotKitMessageFilter | undefined): void" type="method">
  替换应用于出站消息列表的过滤器并重新应用到现有智能体。之后发现的智能体也会采用它，因此在 `/info` 返回之前设置的过滤器不会丢失。传 `undefined` 可恢复发送完整线程。
</PropertyReference>

<PropertyReference name="setProperties(properties: Record<string, unknown>): void" type="method">
  替换发送给智能体的转发属性。
</PropertyReference>

<PropertyReference name="setDebug(debug: DebugConfig | undefined): void" type="method">
  切换客户端事件管线的调试日志。
</PropertyReference>

<PropertyReference name="setDefaultThrottleMs(value: number | undefined): void" type="method">
  设置 `subscribeToAgentWithOptions` 使用的默认节流间隔（毫秒）。无效值会被忽略。
</PropertyReference>

## 用法

```ts
import { CopilotKitCore } from "@copilotkit/core";

const copilotkit = new CopilotKitCore({
  runtimeUrl: "/api/copilotkit",
  tools: [
    {
      name: "showAlert",
      handler: ({ message }: { message: string }) => window.alert(message),
    },
  ],
});

const subscription = copilotkit.subscribe({
  onRuntimeConnectionStatusChanged: ({ status }) => console.log(status),
});

// `agents` populates after the runtime responds — `onAgentsChanged` (above)
// fires when they're ready; this guarded lookup is for illustration.
const agent = copilotkit.getAgent("default");
if (agent) {
  await copilotkit.runAgent({ agent });
}

subscription.unsubscribe();
```

## 行为

- **智能体异步填充** —— `agents` 在运行时响应后才会填充，因此刚构造完成时可能为空。请用 `subscribe({ onAgentsChanged })` 在智能体可用时作出响应。
- **错误呈现** —— 失败（运行时 fetch、智能体运行、工具执行、订阅者回调）会通过 `onError` 订阅者回调并附带 [CopilotKitCoreErrorCode](/reference/core/enums/CopilotKitCoreErrorCode) 送达；它们不会从发起调用的方法中抛出——唯一例外是 `runTool()`，当找不到指定工具或其解析到的智能体时，它也会抛出异常。
- **订阅者隔离** —— 某个订阅者回调中抛出的异常会被捕获并记录，不会阻塞向其他订阅者的通知。
- **Inspector 元数据隔离** —— 元数据在已连接通知和智能体通知完成之后加载。改变解析结果的 `setHeaders` 调用或凭据变更都会刷新它——但不会重新拉取 `/info`。运行时 URL、传输方式、鉴权、连接和 capability 检查会防止过期的请求覆盖更新的值。
- **`__unsafe_dev_only` API** —— `*Agent__unsafe_dev_only` 方法用于在开发时注册本地内存智能体。生产环境必须通过 CopilotRuntime。
