## 概览

`ProxiedCopilotRuntimeAgent` 是 AG-UI [`AbstractAgent`](https://docs.ag-ui.com/sdk/js/client/abstract-agent) 的实现（扩展自 `HttpAgent`），`CopilotKitCore` 用它与 CopilotRuntime 通信。它会构建正确的运行时 URL，选择传输方式（`rest`、`single` 或自动探测），并在运行时处于 Intelligence 模式时透明地委托给一个 Intelligence 智能体。你很少直接构造它——`CopilotKitCore` 会为每个运行时智能体创建一个——但当你想在单个运行时智能体上挂载多个前端智能体时，会用到它（通过 [`registerProxiedAgent`](/reference/core/classes/CopilotKitCore)）。

## 导入

```ts
import { ProxiedCopilotRuntimeAgent } from "@copilotkit/core";
```

## 构造函数

```ts
new ProxiedCopilotRuntimeAgent(config: ProxiedCopilotRuntimeAgentConfig)
```

<PropertyReference name="config" type="ProxiedCopilotRuntimeAgentConfig" required>
  配置对象。扩展自 AG-UI 的 `HttpAgentConfig`（去掉 `url`）。参见 [ProxiedCopilotRuntimeAgentConfig](/reference/core/types/ProxiedCopilotRuntimeAgentConfig)。

  <PropertyReference name="runtimeUrl" type="string">
    CopilotRuntime 的基础 URL。末尾斜杠会被去掉。`transport` 为 `"single"` 时必填。
  </PropertyReference>

  <PropertyReference name="transport" type="CopilotRuntimeTransport" default="auto">
    传输方式：`"rest"`、`"single"` 或 `"auto"`（先探测 REST，失败时回退到单路由）。
  </PropertyReference>

  <PropertyReference name="runtimeAgentId" type="string">
    出站请求路由到的运行时侧智能体 id。设置后，本地 `agentId` 仍作为注册表键，而流量会路由到 `runtimeAgentId`。
  </PropertyReference>

  <PropertyReference name="credentials" type="RequestCredentials">
    应用于运行时 fetch 请求的凭据模式。
  </PropertyReference>

  <PropertyReference name="runtimeMode" type='"sse" | "intelligence" | "pending"' default="sse">
    运行时模式。`"pending"` 表示模式尚未解析；当智能体进入 Intelligence 委托路径时，会通过 runtime-info 请求来解析它。
  </PropertyReference>

  <PropertyReference name="intelligence" type="IntelligenceRuntimeInfo">
    Intelligence 运行时元数据（例如 websocket URL），用于构建 Intelligence 委托。
  </PropertyReference>

  <PropertyReference name="capabilities" type="AgentCapabilities">
    对外宣告的智能体能力，由 `capabilities` / `getCapabilities()` 返回。
  </PropertyReference>

  <PropertyReference name="debug" type="ResolvedDebugConfig">
    应用于该智能体的调试配置。
  </PropertyReference>
</PropertyReference>

## 方法

<PropertyReference name="run(input: RunAgentInput): Observable<BaseEvent>" type="method">
  针对运行时运行该智能体，返回 AG-UI 事件流。根据解析出的运行时模式，经由 HTTP、单路由或 Intelligence 委托路由。
</PropertyReference>

<PropertyReference name="connect(input: RunAgentInput): Observable<BaseEvent>" type="method">
  连接到运行时智能体以接收其事件流，而不开启新的运行。
</PropertyReference>

<PropertyReference name="connectAgent(parameters?, subscriber?): Promise<RunAgentResult>" type="method">
  更高层的连接，会解析出结果；在 Intelligence 模式下，还会把委托的消息、状态和运行生命周期桥接回该代理。
</PropertyReference>

<PropertyReference name="abortRun(): void" type="method">
  中止当前的运行。在 Intelligence 模式下，中止委托并分离本地运行管线；在 HTTP（`rest`/`single`）模式下，向运行时发送停止请求。当智能体没有 `agentId`/`threadId` 或 `fetch` 不可用时为空操作。
</PropertyReference>

<PropertyReference name="detachActiveRun(): Promise<void>" type="method">
  分离当前已挂载的运行管线（以及委托的管线，如存在），而不中止底层运行。
</PropertyReference>

<PropertyReference name="getCapabilities(): Promise<AgentCapabilities>" type="method">
  解析该智能体对外宣告的能力（未配置时返回空对象）。
</PropertyReference>

<PropertyReference name="clearReplayCursor(threadId: string): void" type="method">
  在 Intelligence 模式下，丢弃委托为某个线程缓存的事件游标，使下一次连接时回放完整历史。其他运行时模式下为空操作。
</PropertyReference>

<PropertyReference name="clone(): ProxiedCopilotRuntimeAgent" type="method">
  返回一个新的独立实例，沿用运行时 URL、id、传输方式、模式、能力、请求头、消息和状态。`state` 和 `messages` 是深拷贝，因此修改副本不会影响原始实例；委托（如存在）通过其自身的 `clone()` 克隆。
</PropertyReference>

<PropertyReference name="capabilities: AgentCapabilities | undefined" type="getter">
  已配置的能力，或 `undefined`。
</PropertyReference>

<PropertyReference name="runtimeAgentId: string | undefined" type="property">
  只读。出站请求所路由到的运行时侧智能体 id（在已配置时）。
</PropertyReference>

## 用法

```ts
import { CopilotKitCore } from "@copilotkit/core";

const copilotkit = new CopilotKitCore({ runtimeUrl: "/api/copilotkit" });

// Mount a second frontend agent against the same runtime agent.
const { agent, unregister } = copilotkit.registerProxiedAgent({
  agentId: "chat-1",
  runtimeAgentId: "default",
});

await copilotkit.runAgent({ agent });

// On cleanup:
unregister();
```

## 行为

- **传输方式自动探测** —— 当 `transport: "auto"` 时，智能体会发起 `GET /info`；2xx 响应选择 REST，否则回退到单路由（`POST { method: "info" }`）。
- **模式惰性解析** —— 只有当智能体进入 Intelligence 委托路径时，才会通过 runtime-info 请求解析 `"pending"` 的运行时模式；普通 HTTP 的 `run`/`connect` 会在不解析它的情况下继续。
- **Intelligence 委托** —— 在 Intelligence 模式下，代理会创建一个内部的 `IntelligenceAgent` 委托（websocket），并把它的消息、状态和 `isRunning` 镜像回自身。
- **不可变的路由 id** —— `runtimeAgentId` 是 `readonly` 的；REST 运行 URL 在构造时即已固化，修改它会导致路由失步。
- **中止/Zod 错误被吞掉** —— `AbortError` 和 Zod 校验错误会静默地结束流而不是向外传播，因此取消一次运行不会表现为错误。
