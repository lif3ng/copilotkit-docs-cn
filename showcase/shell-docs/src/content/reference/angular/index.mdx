`@copilotkit/angular` 为 Angular 应用提供[提供方](/reference/angular/functions/provideCopilotKit)、预构建聊天组件、一个 `CopilotKit`
服务以及独立函数。一切均构建于 [AG-UI](https://docs.ag-ui.com)
智能体协议之上。

<Callout type="info">
  该包面向 Angular 22，以 standalone 组件与提供方的形式发布。主 API 从
  `@copilotkit/angular` 导入。MCP Apps 使用 `@copilotkit/angular/mcp-apps`
  入口。不存在 `/v2` 子路径。
</Callout>

## 安装

```sh
npm install @copilotkit/angular @angular/cdk
```

`@angular/cdk` 与 `rxjs` 是 peer 依赖。如果你的智能体通过 AG-UI
直连，还需安装 `@ag-ui/client`。

## 样式

使用预构建 UI 组件时，请在全局样式中引入一次样式表。它是自包含的，因此聊天无需任何其他 CSS 即可渲染。

```css title="src/styles.css"
@import "@copilotkit/angular/styles.css";
```

## 提供方配置

将 [`provideCopilotKit`](/reference/angular/functions/provideCopilotKit)
添加到你的应用提供方列表，并在此处配置运行时连接。根级 `CopilotKit`
服务会读取这份应用级配置。

```ts title="src/app/app.config.ts"
import { ApplicationConfig } from "@angular/core";
import { provideCopilotKit } from "@copilotkit/angular";

export const appConfig: ApplicationConfig = {
  providers: [
    provideCopilotKit({
      runtimeUrl: "/api/copilotkit",
    }),
  ],
};
```

要在没有运行时的情况下直连 AG-UI 智能体，请传入 `selfManagedAgents` 而不是 `runtimeUrl`：

```ts title="src/app/app.config.ts"
import { ApplicationConfig } from "@angular/core";
import { provideCopilotKit } from "@copilotkit/angular";
import { HttpAgent } from "@ag-ui/client";

export const appConfig: ApplicationConfig = {
  providers: [
    provideCopilotKit({
      selfManagedAgents: {
        default: new HttpAgent({ url: "http://localhost:8000/" }),
      },
    }),
  ],
};
```

然后把聊天组件放入一个 standalone 组件的模板中：

```ts title="src/app/app.component.ts"
import { Component } from "@angular/core";
import { CopilotChat } from "@copilotkit/angular";

@Component({
  selector: "app-root",
  standalone: true,
  imports: [CopilotChat],
  template: `<copilot-chat />`,
})
export class AppComponent {}
```

## Angular 约定

CopilotKit 遵循 Angular 的依赖注入与 signal 模式：

- 在应用提供方列表中注册 [`provideCopilotKit`](/reference/angular/functions/provideCopilotKit)。
- 通过调用 signal 读取响应式状态，例如 `agentStore().messages()`。
- 从构造函数、字段初始化器或其他注入上下文中调用可注入的辅助函数。
- 在组件的 `imports` 数组中导入 standalone 组件。
- 通过组件输入、模板、指令与内容投影自定义 UI。

## 生命周期与渲染环境

可注入的辅助函数会把自己的 effects、订阅、运行时注册、定时器与观察者绑定到所属 Angular 的
`DestroyRef` 上。请从字段初始化器、构造函数或显式注入上下文中调用它们。不要让被注入的控制器存活得比该
injector 的生命周期更久。在工具 handler 内启动的应用自有工作（例如一次
fetch）仍由应用自己负责取消。

CopilotKit 的主要聊天组件基于 signal，并支持 zoneless
变更检测。仅限浏览器的行为在服务端渲染期间保持惰性，在 hydration
之后激活。请保证服务端与客户端首次渲染使用完全相同的配置与初始模型/输入值，避免在服务端运行智能体或工具，并把应用自有的 DOM
操作置于 Angular 平台守卫或 `afterNextRender` 之后。

A2UI、Open Generative UI、音频采集与 MCP Apps 可以出现在 SSR
树中，但它们的自定义元素、媒体 API、沙箱与 iframe 只有在浏览器中才会变为可交互。完整的配置、清理、错误处理、SSR、hydration 与
zoneless 契约见 [Angular 生产与生命周期](/reference/angular/production-lifecycle)。
