---

## 概览

`injectAgentStore` 订阅一个 [AG-UI agent](https://docs.ag-ui.com/sdk/js/client/abstract-agent)，并返回 Angular 的 `Signal<AgentStore>`。`AgentStore` 把智能体实例及其响应式状态（消息、共享状态和运行状态）以 Angular signals 的形式暴露出来，因此当智能体变化时，你的组件会自动重新渲染。

调用外层 signal 即可读取 store，再调用各成员自身的 signal 读取成员：`store().messages()`、`store().isRunning()`、`store().state()`。`agent` 成员是普通的 AG-UI 实例（不是 signal），可直接读取：`store().agent`。

请在注入上下文中调用它，例如构造函数或字段初始化器。当所属组件或服务销毁时，订阅会自动拆除。

<Callout type="warn">
  智能体的解析是惰性且响应式的。如果运行时同步完成后仍无法为给定的 `agentId` 解析出智能体（例如该 id 与运行时 `/info` 报告的任何智能体都不匹配，也未通过 `agents` 或 `selfManagedAgents` 配置），读取 store signal 会抛出一个错误，其中列出已知的智能体。
</Callout>

## 签名

```ts
import { injectAgentStore } from "@copilotkit/angular";
import type { Signal } from "@angular/core";

function injectAgentStore(
  agentId: string | Signal<string | undefined>,
): Signal<AgentStore>;
```

## 参数

<PropertyReference name="agentId" type="string | Signal<string | undefined>" required>
  要订阅的智能体的 ID。固定智能体传普通字符串；需要响应式切换智能体时传 `Signal<string | undefined>`。当解析出的 id 为空或 `undefined` 时，使用默认智能体 id。只要该 id、可用智能体集合或运行时连接状态发生变化，返回的 signal 就会重新解析。
</PropertyReference>

## 返回值

<PropertyReference name="store" type="Signal<AgentStore>">
  一个持有当前 `AgentStore` 的 Angular signal。调用它（`store()`）会返回最新的 `AgentStore` 实例，并在智能体重新解析时重新计算。如果无法解析智能体，读取它同样会抛错（见上方提示块）。

  `AgentStore` 暴露以下成员：

  <PropertyReference name="agent" type="AbstractAgent">
    底层的 AG-UI 智能体实例。这是一个普通引用，不是 signal，因此可直接以 `store().agent` 读取。用它调用智能体方法，例如 `runAgent`、`setState`、`addMessage` 和 `abortRun`。完整接口见 [AbstractAgent 文档](https://docs.ag-ui.com/sdk/js/client/abstract-agent)。
  </PropertyReference>

  <PropertyReference name="messages" type="Signal<Message[]>">
    智能体会话消息的只读 signal。用 `store().messages()` 读取。每一项都是一个 AG-UI `Message`，包含 `id`、`role`（`"user" | "assistant" | "system" | "tool" | "developer"`）和 `content` 等字段。智能体消息变化时随之更新。
  </PropertyReference>

  <PropertyReference name="state" type="Signal<unknown>">
    智能体共享状态对象的只读 signal，在你的应用与智能体之间保持同步。用 `store().state()` 读取。store 会从智能体当前的 `state` 同步初始化该 signal，包括订阅之前恢复的状态。可按你智能体的状态形态按需进行类型转换或标注。
  </PropertyReference>

  <PropertyReference name="isRunning" type="Signal<boolean>">
    指示智能体当前是否正在执行的只读 signal。用 `store().isRunning()` 读取。运行初始化时变为 `true`，运行结束、失败或报告协议级运行错误时变为 `false`。
  </PropertyReference>

  <PropertyReference name="interruptController" type="InterruptController">
    此会话的待处理中断——与其他成员描述的是同一智能体和线程。直接读取它（`store().interruptController`），然后绑定它的 signals：`hasInterrupt()`、`view()`、`interrupt()`、`interrupts()`、`error()`，并用 `resolve(payload?, interruptId?)` 或 `cancel(interruptId?)` 来处理。

    该控制器随 store 一起创建并连接。智能体保留的标准 AG-UI 中断会立即呈现，旧版 `on_interrupt` 事件则在 store 的整个生命周期内被监听。store 被拆除或智能体被替换时，控制器随之销毁。

    这是不带过滤的默认版本，且无类型（`InterruptController<unknown, never>`）。需要带类型的值、`enabled` 过滤器或 `handler` 时，请对同一智能体 id 使用 [`injectInterrupt`](/reference/angular/functions/injectInterrupt)。
  </PropertyReference>
</PropertyReference>

## 用法

### 基本用法

```ts title="src/app/agent-status.component.ts"
import { Component } from "@angular/core";
import { injectAgentStore } from "@copilotkit/angular";

@Component({
  selector: "app-agent-status",
  standalone: true,
  template: `
    <div>Messages: {{ store().messages().length }}</div>
    <div>Running: {{ store().isRunning() ? "Yes" : "No" }}</div>
  `,
})
export class AgentStatusComponent {
  readonly store = injectAgentStore("default");
}
```

### 读取与更新共享状态

通过 signal 读取状态，通过智能体实例写入状态。

```ts title="src/app/theme-panel.component.ts"
import { Component } from "@angular/core";
import { injectAgentStore } from "@copilotkit/angular";

@Component({
  selector: "app-theme-panel",
  standalone: true,
  template: `
    <pre>{{ store().state() | json }}</pre>
    <button (click)="setDark()">Dark theme</button>
  `,
})
export class ThemePanelComponent {
  readonly store = injectAgentStore("default");

  setDark() {
    const agent = this.store().agent;
    agent.setState({ ...(agent.state as object), theme: "dark" });
  }
}
```

### 响应式切换智能体

传入一个 signal，这样当选中的智能体 id 变化时，store 会重新解析。

```ts title="src/app/multi-agent.component.ts"
import { Component, signal } from "@angular/core";
import { injectAgentStore } from "@copilotkit/angular";

@Component({
  selector: "app-multi-agent",
  standalone: true,
  template: `
    <button (click)="agentId.set('support')">Support</button>
    <button (click)="agentId.set('sales')">Sales</button>
    <div>Active: {{ store().agent.agentId }}</div>
    <div>Messages: {{ store().messages().length }}</div>
  `,
})
export class MultiAgentComponent {
  readonly agentId = signal<string | undefined>("support");
  readonly store = injectAgentStore(this.agentId);
}
```

## 行为

- **响应式解析**。当 `agentId`、可用智能体集合、运行时连接状态、运行时 URL 或传输方式、请求头发生变化时，返回的 signal 会重新计算。
- **临时智能体**。当已配置运行时但尚未连接时，会创建并缓存一个临时代理运行时智能体，让 store 在运行时同步之前也有内容可渲染。
- **自动清理**。所属组件或服务销毁时，智能体订阅会被退订。切换到新智能体时，会先拆除上一个 store 的订阅，包括其中断控制器。
- **缺少智能体时报错**。如果运行时同步完成后仍无法解析出智能体，读取 store signal 会抛出一个错误，其中列出已知的智能体 id。
