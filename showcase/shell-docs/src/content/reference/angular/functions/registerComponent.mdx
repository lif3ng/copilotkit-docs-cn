description: "Angular 函数，用于注册一个智能体可作为工具调用的独立组件以在聊天中显示它，无需 handler，智能体侧也无需任何添加"
---

## 概览

`registerComponent` 将一个独立的 Angular 组件注册为智能体可调用的工具，用以显示该组件。当智能体调用这个工具时，CopilotKit 会使用工具调用的参数在聊天中渲染你的组件。没有 handler、没有用户交互，也没有服务端执行：由智能体决定何时显示组件并填充其数据。

这是最简单的生成式 UI 形式，也是唯一一种智能体侧无需任何配合的形式。该工具由前端声明并通过 AG-UI 转发给智能体，因此无论背后是 Python 智能体还是 TypeScript 智能体，行为都一致。对比 [`registerRenderToolCall`](/reference/angular/functions/registerRenderToolCall)，后者绘制的是智能体已有的工具，因此要求该工具必须存在于智能体中。

你在 Angular 注入上下文（组件或服务构造函数，或字段初始化器）中调用 `registerComponent`。注册会立即生效，并在所属注入器销毁时被移除。

`registerComponent` 是 `@copilotkit/react-core/v2` 和 `@copilotkit/vue/v2` 中 `useComponent` 的 Angular 对应版本。它构建的面向模型的工具描述完全相同，因此无论组件由哪个前端注册，模型看到的工具都是一样的。

<Callout type="info">
  请从包根路径 `@copilotkit/angular` 导入。不存在 `/v2` 子路径。`registerComponent` 必须在作用域内包含 [`provideCopilotKit`](/reference/angular/functions/provideCopilotKit) 的注入上下文中运行。
</Callout>

## 签名

```ts
import { registerComponent } from "@copilotkit/angular";

function registerComponent<Args extends Record<string, unknown>>(
  config: RegisterComponentConfig<Args>,
): void;
```

## 参数

<PropertyReference name="config" type="RegisterComponentConfig<Args>" required>
  组件注册对象。

  <PropertyReference name="name" type="string" required>
    智能体看到的工具名称。请使用一个动词，让模型在用户要求该可视化时会选用它，例如 `show_incident` 或 `render_bar_chart`。
  </PropertyReference>

  <PropertyReference name="parameters" type="StandardSchemaV1<unknown, Args>" required>
    描述参数的 [Standard Schema](https://standardschema.dev)（例如 Zod 对象）。它会作为工具的参数向模型宣告，并为组件读取的 `args` 提供类型。请描述每个字段——模型在填充载荷时会读取这些描述。
  </PropertyReference>

  <PropertyReference name="component" type="Type<ToolRenderer<Args>>" required>
    要渲染的独立 Angular 组件类。CopilotKit 会实例化它并绑定 `toolCall` signal 输入，与 [`registerRenderToolCall`](/reference/angular/functions/registerRenderToolCall) 的做法完全一致。
  </PropertyReference>

  <PropertyReference name="description" type="string">
    面向模型说明组件显示什么内容。CopilotKit 会先加上自己的一句话，说明该工具渲染一个可视化组件，然后再附上你的描述。
  </PropertyReference>

  <PropertyReference name="agentId" type="string">
    可选的智能体作用域。设置后，只有具有此 id 的智能体会获得该工具。省略时，该工具对所有智能体可用。
  </PropertyReference>

  <PropertyReference name="followUp" type="boolean">
    组件渲染后智能体是否再进行一轮对话。对于结束该轮对话的组件，保持不设置即可。
  </PropertyReference>
</PropertyReference>

没有 `handler` 字段。纯展示组件不运行任何应用代码，CopilotKit 会以空工具结果（而不是编造的结果）结束智能体的这一轮。如果你想在渲染之外还运行浏览器代码，请使用同时带 `handler` 和 `component` 的 [`registerFrontendTool`](/reference/angular/functions/registerFrontendTool)。

## 返回值

`registerComponent` 返回 `void`。它以副作用的方式注册工具及其渲染器，并在所属注入器销毁时将两者一并移除。

## 组件

你的 `component` 实现 `ToolRenderer<Args>` 接口——与所有其他 Angular 渲染器使用的是同一份契约。使用 Angular 的 `input.required()` 声明 `toolCall` 输入，并读取 `toolCall().args`：

```ts
import { Signal } from "@angular/core";

interface ToolRenderer<Args extends Record<string, unknown>> {
  toolCall: Signal<AngularToolCall<Args>>;
}
```

`toolCall()` 是以 `status` 为键的可辨识联合类型。当模型仍在流式传输载荷时，状态为 `in-progress`，`args` 为 `Partial<Args>`，因此在读取你所需的字段前，请先依据 `status` 收窄类型。完整联合类型见 [`registerRenderToolCall`](/reference/angular/functions/registerRenderToolCall#angulartoolcall)。

## 用法

### 展示一个由智能体填充的卡片

```ts title="src/app/incident-card.component.ts"
import { Component, input } from "@angular/core";
import { AngularToolCall, ToolRenderer } from "@copilotkit/angular";

type IncidentArgs = { id: string; severity: string; summary: string };

@Component({
  selector: "app-incident-card",
  standalone: true,
  template: `
    @let call = toolCall();
    @if (call.status === "in-progress") {
      <div class="text-sm opacity-70">Loading incident…</div>
    } @else {
      <article class="rounded-lg border p-4">
        <header class="flex items-baseline justify-between">
          <strong>{{ call.args.id }}</strong>
          <span class="text-xs uppercase">{{ call.args.severity }}</span>
        </header>
        <p class="text-sm">{{ call.args.summary }}</p>
      </article>
    }
  `,
})
export class IncidentCardComponent implements ToolRenderer<IncidentArgs> {
  readonly toolCall = input.required<AngularToolCall<IncidentArgs>>();
}
```

在 `provideCopilotKit` 作用域内的任意位置注册一次即可：

```ts title="src/app/chat.component.ts"
import { Component } from "@angular/core";
import { z } from "zod";
import { registerComponent } from "@copilotkit/angular";
import { IncidentCardComponent } from "./incident-card.component";

@Component({
  selector: "app-chat",
  standalone: true,
  template: ``,
})
export class ChatComponent {
  constructor() {
    registerComponent({
      name: "show_incident",
      description: "Show one incident from the incident table.",
      parameters: z.object({
        id: z.string().describe("The incident id, such as INC-4711"),
        severity: z.string().describe("One of sev1, sev2, sev3"),
        summary: z.string().describe("One sentence on what happened"),
      }),
      component: IncidentCardComponent,
    });
  }
}
```

智能体侧无需添加任何东西。该工具会随运行的工具列表到达智能体，智能体按名称调用它。

### 限定于单个智能体

```ts
registerComponent({
  name: "show_incident",
  parameters: incidentSchema,
  component: IncidentCardComponent,
  agentId: "support-agent",
});
```

## 用你自己的数据为组件提供事实依据

一个基于应用并不持有的记录而“正确”渲染的组件，与真正正确的组件在浏览器里、在截图里看起来毫无二致。模型会根据它所知道的内容填充这些 props，因此数据从未到达智能体的组件，其内容出自智能体的凭空编造。

注册组件只是渲染这一半。请通过 [`CopilotKitAgentContext`](/reference/angular/directives/CopilotKitAgentContext) 或 [`connectAgentContext`](/reference/angular/functions/connectAgentContext) 把智能体应描述的数据交给它，然后将渲染出的字段与你应用持有的记录进行核对。
