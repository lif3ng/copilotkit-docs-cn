---
title: "provideMCPApps"
description: "为 Angular 配置可选启用的 MCP Apps 活动渲染器。"
---

MCP Apps 需从二级入口点导入，这样不使用它的应用就不会加载其宿主与沙箱代码。

```ts
import { ApplicationConfig } from "@angular/core";
import { provideCopilotKit } from "@copilotkit/angular";
import { provideMCPApps } from "@copilotkit/angular/mcp-apps";

export const appConfig: ApplicationConfig = {
  providers: [
    provideCopilotKit({ runtimeUrl: "/api/copilotkit" }),
    provideMCPApps({
      idleTimeoutMs: 30_000,
      initializationTimeoutMs: 30_000,
      hostInfo: { name: "Acme Copilot", version: "1.0.0" },
    }),
  ],
};
```

```ts
interface MCPAppsConfig {
  idleTimeoutMs?: number;
  initializationTimeoutMs?: number;
  hostInfo?: { name: string; version: string };
  hostCapabilities?: Record<string, unknown>;
  hostContext?: Record<string, unknown>;
  allowSameOriginFallback?: boolean;
}
```

`provideMCPApps` 为 `activityType: "mcp-apps"` 贡献一个优先级较低的内置渲染器；应用显式提供的活动渲染器仍然优先生效。它有意不接受 MCP 服务器 URL。资源加载、工具调用和后续消息都经由所选的 AG-UI 智能体传输。

小组件（widget）运行在不透明来源（opaque origin）的沙箱中，因此无法访问你页面的 cookie、存储或 DOM。`allowSameOriginFallback: true` 会为需要 `localStorage`、`IndexedDB` 或 cookie 的受信任小组件恢复 `allow-same-origin`。这并不安全：此后每个小组件都会以你页面的来源运行。参见 [沙箱与小组件存储](/generative-ui/mcp-apps#sandbox-and-widget-storage)。

每个小组件都拥有自己的可中止 FIFO 队列和 iframe 监听器。销毁某个小组件只会取消它自己的工作；切换线程会丢弃队列中过时的工作。忙碌的智能体与初始化握手使用配置的超时时间。快照内容、JSON-RPC 消息和精确的 iframe 事件来源在使用前都会经过校验。宿主上下文对浏览器可见，不得包含机密信息。

在 SSR 期间小组件处于静止状态。它的沙箱和消息监听器会在浏览器端水合（hydration）之后初始化。`CopilotMCPAppsWidget`、模式、令牌以及现成的活动配置也都从二级入口点公开，供高级自定义宿主使用；参见[公开 API 清单](/reference/angular/public-api)。
