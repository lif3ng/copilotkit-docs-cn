## 概览

`provideCopilotKit` 是 `@copilotkit/angular` 的主要配置入口。它返回一个 Angular [`Provider`](https://angular.dev/guide/di/dependency-injection-providers)，由你添加到应用提供器中。该提供器把你的 [`CopilotKitConfig`](#参数) 存储在 `COPILOT_KIT_CONFIG` 注入令牌之后，根 [`CopilotKit`](/reference/angular/services/CopilotKit) 服务会从这里读取它。

在 `app.config.ts` 中注册一次即可。仅靠组件级配置提供器无法配置根 `CopilotKit` 服务。

你通常以两种方式之一配置连接：用 `runtimeUrl` 指向一个 CopilotKit 运行时，或用 `selfManagedAgents` 直连一个或多个 AG-UI 智能体。

## 签名

```ts
import { provideCopilotKit } from "@copilotkit/angular";
import type { Provider } from "@angular/core";

function provideCopilotKit(config: CopilotKitConfig): Provider;
```

## 参数

<PropertyReference name="config" type="CopilotKitConfig" required>
  CopilotKit 配置对象。

<PropertyReference name="runtimeUrl" type="string">
  CopilotKit 运行时端点的 URL。设置此项可让智能体流量经由运行时路由（例如 Next.js、Express 或 Hono 后端）。
</PropertyReference>

<PropertyReference name="headers" type="Record<string, string> | (() => Record<string, string>) | (() => Promise<Record<string, string>>)">
  随每个运行时请求一起发送的额外 HTTP 请求头，例如 `Authorization` 请求头。传对象表示静态请求头，或传函数（同步或异步）来即时构建。构建函数会在每次请求发送时执行，因此始终使用刷新后的令牌。

  请在构建函数内部做缓存——每次都调用网络的构建函数会让每个请求多出一次调用。如果构建函数抛出异常或被拒绝，该请求不会发送，`onError` 会收到 `header_resolution_failed`。

  重复传入同一个构建函数不会产生任何效果。切换用户时，请向 `copilotKit.updateRuntime({ headers })` 传入新函数（或一个记录对象）（参见 [`CopilotKit`](/reference/angular/services/CopilotKit) 服务），或重新挂载组件，以便为新用户重新加载 Inspector 元数据和线程列表。这不会重新拉取运行时的 `/info`。

  核心请求头也会发送到任何 `selfManagedAgents` / `agents__unsafe_dev_only` 智能体，包括位于其他来源（origin）的智能体。如果这些智能体指向第三方，请不要在核心请求头中放入 bearer 令牌。

  如果你传入格式有效的 `licenseKey`，会自动合并进一个 `X-CopilotCloud-Public-Api-Key` 请求头，除非你已在此处设置。
</PropertyReference>

<PropertyReference name="credentials" type="RequestCredentials">
  运行时 fetch 请求的凭据模式。跨域请求中携带 HTTP-only cookie 时使用 `"include"`。省略时采用浏览器 Fetch 的默认行为。
</PropertyReference>

<PropertyReference name="messageFilter" type="(messages: Message[], context: { agentId: string }) => Message[]">
  改写每次运行时发送给智能体的消息列表。

CopilotKit 会在每次请求中发送整个线程。当你的智能体已经自己存储对话时——例如 LangGraph checkpointer、Mastra memory store 或 Strands `SessionManager`——这些负载大部分是浪费，而且会把入站列表与自己存储合并的智能体可能让模型把每一轮对话看到两次。

返回要发送的消息：

```ts
provideCopilotKit({
  runtimeUrl: "/api/copilotkit",
  messageFilter: (messages) => messages.slice(-1),
});
```

该过滤器只改变请求体。UI 渲染的会话记录不受影响，因此聊天中仍显示完整对话。不完整的工具调用对会在请求发出前被修复，因此再粗暴的过滤器也不会把工具结果卡在审批中间。

经由你的 CopilotRuntime 访问的智能体会遵守此设置。应用自行构造并直接传入的智能体则不会。CopilotKit Intelligence 运行和建议运行永远不会被过滤。

之后可用 `updateRuntime({ messageFilter })` 更改它，并通过显式传入 `undefined` 作为该键的值来关闭它。

</PropertyReference>

<PropertyReference name="licenseKey" type="string">
  你的 CopilotCloud 公钥。形如 `ck_pub_` 后接 32 个十六进制字符的值会作为 `X-CopilotCloud-Public-Api-Key` 请求头发送，除非该请求头已设置。当前包中水印渲染和缺少密钥警告均已被禁用。
</PropertyReference>

<PropertyReference name="properties" type="Record<string, unknown>">
  随每个请求转发给运行时的任意键值属性。用于请求范围的元数据，例如用户 id 或租户。
</PropertyReference>

<PropertyReference name="enableInspector" type="boolean">
  控制开发浏览器构建中的 CopilotKit Inspector。默认显示，除非设为 `false`；在生产环境或服务端渲染期间从不加载，即使显式设为 `true` 也是如此。
</PropertyReference>

<PropertyReference name="agents" type="Record<string, AbstractAgent>">
  智能体 id 到 AG-UI 智能体实例的映射。用于在客户端直接注册智能体。在底层核心构建时，它们会与 `selfManagedAgents` 合并。
</PropertyReference>

<PropertyReference
  name="selfManagedAgents"
  type="Record<string, AbstractAgent>"
>
  智能体 id 到 AG-UI 智能体实例的映射，这些实例不经过 CopilotKit 运行时、直接连接智能体端点。在此提供 `@ag-ui/client` 智能体（例如 `HttpAgent`）即可直接与智能体服务器通信。
</PropertyReference>

<PropertyReference name="tools" type="ClientTool[]">
  启动时注册的客户端工具。每个 `ClientTool` 是一个不带 `handler` 的前端工具定义，外加一个可选的 `renderer` 组件。当工具同时提供 `renderer` 和 `parameters` 时，其渲染器会自动注册为工具调用渲染器。
</PropertyReference>

<PropertyReference name="renderToolCalls" type="RenderToolCallConfig[]">
  工具调用的渲染器。每个条目将工具 `name` 和 `args` 的 [Standard Schema](https://standardschema.dev) 映射到可视化该调用的 `component`。可选的 `agentId` 将渲染器限定于单个智能体，`passAgent` 则把智能体暴露给渲染器。
</PropertyReference>

<PropertyReference
  name="renderActivityMessages"
  type="RenderActivityMessageConfig[]"
>
  智能体活动消息的渲染器。每个条目将 `activityType` 和 `content` 模式映射到一个 `component`。可选的 `agentId` 将渲染器限定于单个智能体。
</PropertyReference>

<PropertyReference name="suggestionsConfig" type="SuggestionsConfig[]">
  建议配置。每个条目要么是动态配置（`instructions` 加可选的 `minSuggestions`、`maxSuggestions`、`available`、`providerAgentId`、`consumerAgentId`），要么是静态配置（显式的 `suggestions` 数组加可选的 `available` 和 `consumerAgentId`）。
</PropertyReference>

<PropertyReference name="frontendTools" type="FrontendToolConfig[]">
  启动时注册的客户端工具，每个都包含 `name`、`description`、`parameters` 模式、异步 `handler`，以及可选的 `component` 渲染器、`followUp` 和 `agentId`。处理器在根注入上下文中运行，因此可以使用 `inject()`。限定于组件的工具请优先使用 [`registerFrontendTool`](/reference/angular/functions/registerFrontendTool)。
</PropertyReference>

<PropertyReference name="humanInTheLoop" type="HumanInTheLoopConfig[]">
  启动时注册的人机协同（human-in-the-loop）工具。每个条目包含 `name`、`description`、`parameters` 模式、一个收集用户响应的 `component` 渲染器，以及可选的 `agentId`。限定于组件的工具请优先使用 [`registerHumanInTheLoop`](/reference/angular/functions/registerHumanInTheLoop)。
</PropertyReference>

<PropertyReference name="defaultToolRendering" type="boolean" default="false">
  为其他情况下未知的工具调用启用纯文本回退渲染器。省略或设为 `false` 时，未知工具将被隐藏。
</PropertyReference>

  <PropertyReference name="a2ui" type="A2UIConfig">
    A2UI（agent 到 UI 的声明式界面）的配置。运行时可通过 `/info` 宣告支持 A2UI；提供 catalog 也能在没有该运行时能力的情况下启用前端渲染器与智能体上下文。

    <PropertyReference name="theme" type="Record<string, unknown>">
      用于为渲染界面设置样式的 A2UI 主题。
    </PropertyReference>
    <PropertyReference name="catalog" type="A2UICatalog">
      界面渲染所用的 catalog：`basicCatalog` 或来自 `createAngularCatalog` 的 catalog，两者都位于 `@copilotkit/angular/a2ui`。提供它后，即使运行时未通过 `/info` 宣告支持 A2UI，也能启用 A2UI。没有 catalog 时，即使运行时启用了 A2UI，它也会保持关闭，并且 CopilotKit 会记录一条警告。
    </PropertyReference>
    <PropertyReference name="loadingComponent" type="Type<unknown>">
      界面加载期间显示的 Angular 组件。
    </PropertyReference>
    <PropertyReference name="includeSchema" type="boolean" default="true">
      是否将 catalog 组件模式作为上下文发送给智能体。设为 `false` 可省略模式上下文：智能体仍会收到 catalog ID 和 catalog 自定义组件的名称，但不会收到它们的 JSON 模式以及 A2UI 生成与设计指南。使用 CopilotKit 中间件注入的 A2UI 工具的 LangGraph 智能体此时只会向其 A2UI 子智能体提供组件名称。要给子智能体更多细节，请通过中间件的 A2UI 指南传入组合指南：TypeScript 中为 `a2uiParams.guidelines.compositionGuide`，Python 中为 `a2ui_params["guidelines"]["composition_guide"]`。
    </PropertyReference>
    <PropertyReference name="recovery" type="A2UIRecoveryOptions">
      控制 A2UI 重试与诊断状态何时可见。

      <PropertyReference name="showAfterMs" type="number" default="2000">
        显示瞬时重试状态前的延迟。
      </PropertyReference>
      <PropertyReference name="showAfterAttempts" type="number" default="2">
        从此尝试次数起立即显示重试状态。
      </PropertyReference>
      <PropertyReference name="debugExposure" type='"hidden" | "collapsed" | "verbose"'>
        客户端诊断可见性。权威的服务端生命周期内容可能会覆盖它。
      </PropertyReference>
    </PropertyReference>

  </PropertyReference>

  <PropertyReference name="openGenerativeUI" type="OpenGenerativeUIConfig">
    开放式生成式 UI（`generateSandboxedUi` 工具）的配置。提供此对象即启用该特性。

    <PropertyReference name="sandboxFunctions" type="SandboxFunction[]">
      沙箱 UI 可通过 `Websandbox.connection.remote.<functionName>(args)` 回调宿主应用的函数。每个都包含 `name`、`description`、`parameters` 模式和 `handler`。
    </PropertyReference>
    <PropertyReference name="designSkill" type="string">
      传递给智能体的生成式 UI 设计指南。默认为内置的 shadcn 风格设计技能。
    </PropertyReference>

  </PropertyReference>
</PropertyReference>

## 返回值

返回一个 Angular `Provider`，它把你的（已补充请求头的）配置绑定到 `COPILOT_KIT_CONFIG` 注入令牌。请将其添加到应用提供器中。

## 用法

### 通过运行时连接

把 `runtimeUrl` 指向你的 CopilotKit 运行时端点，并在应用配置中注册该提供器。

```ts title="src/app/app.config.ts"
import { ApplicationConfig } from "@angular/core";
import { provideCopilotKit } from "@copilotkit/angular";

export const appConfig: ApplicationConfig = {
  providers: [
    provideCopilotKit({
      runtimeUrl: "/api/copilotkit",
      headers: {
        Authorization: "Bearer <token>",
      },
      properties: {
        userId: "user_123",
      },
    }),
  ],
};
```

### 直接连接 AG-UI 智能体

要在没有 CopilotKit 运行时的情况下与智能体服务器通信，请传入 `selfManagedAgents`，其中放置 `@ag-ui/client` 智能体（例如 `HttpAgent`）。

```ts title="src/app/app.config.ts"
import { ApplicationConfig } from "@angular/core";
import { provideCopilotKit } from "@copilotkit/angular";
import { HttpAgent } from "@ag-ui/client";

export const appConfig: ApplicationConfig = {
  providers: [
    provideCopilotKit({
      selfManagedAgents: {
        default: new HttpAgent({ url: "http://localhost:8000/" }),
      },
    }),
  ],
};
```

### 注册启动工具

传入 `frontendTools` 即可在应用启动时注册客户端工具。它们的处理器在根注入上下文中运行，因此可以使用 `inject()`。

```ts title="src/app/app.config.ts"
import { ApplicationConfig } from "@angular/core";
import { provideCopilotKit } from "@copilotkit/angular";
import { z } from "zod";

export const appConfig: ApplicationConfig = {
  providers: [
    provideCopilotKit({
      runtimeUrl: "/api/copilotkit",
      frontendTools: [
        {
          name: "sayHello",
          description: "Greet the user by name",
          parameters: z.object({ name: z.string() }),
          handler: async ({ name }) => `Hello, ${name}!`,
        },
      ],
    }),
  ],
};
```

## 行为

- 提供的配置会绑定到 `COPILOT_KIT_CONFIG` 注入令牌。可用 [`injectCopilotKitConfig`](/reference/angular/functions/injectCopilotKitConfig) 读取它。
- 格式有效的 `licenseKey` 会合并进 `X-CopilotCloud-Public-Api-Key` 请求头，除非该请求头已存在。当前包不会渲染水印，也不会记录缺少密钥的警告。
- 创建底层核心时，`agents` 与 `selfManagedAgents` 会合并在一起，因此同时出现在两者中的 id 会解析为 `selfManagedAgents` 条目。
- Inspector 接收同一个核心实例。Angular 会复用已存在的 `cpk-web-inspector` 元素，并且在根服务销毁时只移除自己创建的元素。
