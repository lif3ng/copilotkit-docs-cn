description: "Angular 函数，用于向 CopilotKit 注册一个客户端前端工具，可附带可选的 Angular 渲染组件，在智能体调用时于浏览器中运行"
---

## 概览

`registerFrontendTool` 向 CopilotKit 注册一个客户端工具。当智能体决定调用该工具时，传入的 `handler` 函数会在浏览器中执行，其解析出的值会作为工具结果返回给智能体。你还可以选择提供一个 `component`（一个独立的 Angular 组件），在聊天中渲染自定义 UI，展示该工具调用的进度与结果。

你需要在一个 Angular 注入上下文（组件或服务的构造函数，或字段初始化器）中调用 `registerFrontendTool`。工具会立即注册。当所属的 injector 被销毁时，CopilotKit 会移除同名（以及可选 agent id）的工具与渲染器注册。参数 schema 采用 [Standard Schema](https://standardschema.dev)，例如 [Zod](https://zod.dev) 对象，用于对外宣告的工具 schema 与 TypeScript 类型推断。运行时参数会被 JSON 解析，但不会依据该 schema 进行校验。

handler 在注册该工具的同一个 injector 内运行，因此可以调用 `inject()` 来访问你的其他 Angular 服务。

如果浏览器端没有任何逻辑需要执行，只是想让智能体展示一个组件并带上它提供的参数，请使用 [`registerComponent`](/reference/angular/functions/registerComponent)，而不要写一个空壳 handler。

<Callout type="info">
  从包根路径 `@copilotkit/angular` 导入，不存在 `/v2`
  子路径。`registerFrontendTool` 必须在作用域内包含
  [`provideCopilotKit`](/reference/angular/functions/provideCopilotKit) 的注入上下文中运行。
</Callout>

## 签名

```ts
import { registerFrontendTool } from "@copilotkit/angular";

function registerFrontendTool<Args extends Record<string, unknown>>(
  frontendTool: FrontendToolConfig<Args>,
): void;
```

## 参数

<PropertyReference name="frontendTool" type="FrontendToolConfig<Args>" required>
  工具定义对象。

  <PropertyReference name="name" type="string" required>
    工具的唯一名称。智能体在决定调用工具时会引用该名称。核心层会跳过第二个同名且
    `agentId` 相同的工具，但 Angular 仍会追加其前端工具渲染配置。请避免重复的键。
  </PropertyReference>

  <PropertyReference name="description" type="string" required>
    一段自然语言描述，告诉智能体这个工具做什么、何时使用。
  </PropertyReference>

  <PropertyReference name="parameters" type="StandardSchemaV1<unknown, Args>" required>
    一个 [Standard Schema](https://standardschema.dev)（例如 Zod 对象），定义对外宣告的
    工具输入 schema，并为 `handler` 参数提供类型推断。运行时参数会被 JSON 解析并断言为
    `Args`；此辅助函数不会依据 schema 校验它们。对于不接受参数的工具，传入空对象
    schema，例如 `z.object({})`。
  </PropertyReference>

  <PropertyReference
    name="handler"
    type="(args: Args, context: FrontendToolHandlerContext) => Promise<unknown>"
    required
  >
    一个异步函数，在智能体调用工具时运行。它接收解析后并断言为推断类型的 `args` 以及一个
    `context` 对象；它运行在注册该工具的注入上下文内，因此可以在其中调用 `inject()`。其解析值会作为工具结果返回给智能体。

    <PropertyReference name="context.toolCall" type="ToolCall">
      原始的 AG-UI 工具调用元数据，包括工具调用的 `id`。
    </PropertyReference>

    <PropertyReference name="context.agent" type="AbstractAgent | undefined">
      调用该工具的智能体实例。通过 WebMCP 调用工具时无此值。
    </PropertyReference>

    <PropertyReference name="context.signal" type="AbortSignal | undefined">
      当前运行的可选 `AbortSignal`。存在时，用户停止智能体会中止它。读取
      `signal.aborted` 前请先确认其存在，或将其作为可选的 `fetch` signal 传入。
    </PropertyReference>

    <PropertyReference name="context.isReplay" type="boolean | undefined">
      当该调用在线程历史恢复期间执行时为 `true`（见
      `reconnectBehavior`）。来自实时运行的调用无此值。
    </PropertyReference>
  </PropertyReference>

  <PropertyReference name="component" type="Type<ToolRenderer<Args>>">
    可选的独立 Angular 组件类，用于在聊天中可视化该工具调用。CopilotKit
    会实例化它并绑定一个 `toolCall` signal 输入，暴露流式的 `args`、`status` 与
    `result`。完整的 `ToolRenderer` 与 `AngularToolCall` 结构见
    [`registerRenderToolCall`](/reference/angular/functions/registerRenderToolCall)。
  </PropertyReference>

  <PropertyReference name="followUp" type="boolean">
    工具结果返回后，智能体是否自动继续本次运行。
  </PropertyReference>

  <PropertyReference name="reconnectBehavior" type='"passive" | "resume-pending"' default='"passive"'>
    当线程历史恢复（例如页面重新加载）时，对该工具仍未应答的调用会如何处理。设为
    `"passive"` 时，调用仅显示，handler 不会运行。设为 `"resume-pending"`
    时，handler 会以 `isReplay: true` 的上下文为该调用运行，随后运行照常继续。仅当
    handler 可以安全地多次运行时才应启用此项。同一页面上一个调用不会同时启动两次，但如果其结果从未到达智能体，它可能在停止或切换线程后再次运行，且恢复同一线程的两个标签页可能各自运行一次。如果智能体在调用该工具的同时还调用了一个保持
    passive 的工具，后续运行会发送不带结果的 passive 调用，某些模型提供方会拒绝这种情况。
  </PropertyReference>

  <PropertyReference name="agentId" type="string">
    可选的智能体作用域。设置后，该工具只提供给具有此 id 的智能体。销毁时的清理也限定在同一
    `agentId`。
  </PropertyReference>

  <PropertyReference name="webmcp" type="boolean | { annotations?: { readOnlyHint?: boolean; untrustedContentHint?: boolean } }">
    同时通过 WebMCP API（`document.modelContext`）将该工具暴露给浏览器智能体。传
    `true` 以默认 annotations 注册，或传一个对象以指定的 WebMCP annotations
    注册。浏览器智能体调用该工具时运行的是同一个 `handler`；此时上下文中没有
    `agent`。在 WebMCP 不可用（浏览器未启用该 API）的环境下这是空操作。
  </PropertyReference>
</PropertyReference>

## 返回值

`registerFrontendTool` 返回 `void`。它以副作用的方式完成注册，并为所属 injector 建立按名称与 agent id 的清理逻辑。

## 行为

- **立即注册**。函数一运行，工具就会被添加到 CopilotKit，因此请在构造或字段初始化时调用，而不要在事件处理器中调用。
- **在注入上下文中运行**。`handler` 通过 `runInInjectionContext` 使用注册该工具的 injector 调用，因此 `inject()` 在其中可用。
- **按键清理**。当所属组件或服务被销毁时，CopilotKit
  会移除具有相同 `name` 和可选 `agentId` 的前端工具、人机协同（human-in-the-loop）工具与工具调用渲染器。共享该键的注册会被一并移除。
- **可选渲染器**。传入 `component` 时，它会随工具一同注册，聊天便能渲染工具调用的进度与结果。
- **WebMCP 注册**。设置 `webmcp` 后，只要所属 injector 仍然存活，工具还会注册到
  `document.modelContext` 上。为此工具需要一个 `description`（WebMCP 会拒绝没有描述的工具）。

## 用法

### 带 Zod schema 与异步 handler 的基础工具

在组件构造函数中注册工具。handler 读写一个本地 signal，然后为智能体返回一个字符串结果。

```ts title="src/app/todo.component.ts"
import { Component, signal } from "@angular/core";
import { z } from "zod";
import { registerFrontendTool } from "@copilotkit/angular";

@Component({
  selector: "app-todo",
  standalone: true,
  template: `
    <ul>
      @for (todo of todos(); track todo) {
        <li>{{ todo }}</li>
      }
    </ul>
  `,
})
export class TodoComponent {
  readonly todos = signal<string[]>([]);

  constructor() {
    registerFrontendTool({
      name: "addTodo",
      description: "Add a new item to the user's todo list",
      parameters: z.object({
        text: z.string().describe("The todo item text"),
        priority: z.enum(["low", "medium", "high"]).describe("Priority level"),
      }),
      handler: async ({ text, priority }) => {
        this.todos.update((current) => [...current, text]);
        return `Added "${text}" with ${priority} priority`;
      },
    });
  }
}
```

由于 handler 运行在注入上下文中，你可以通过 `inject()` 获取服务，而不必从组件中捕获它：

```ts title="src/app/weather.component.ts"
import { Component, inject } from "@angular/core";
import { z } from "zod";
import { registerFrontendTool } from "@copilotkit/angular";
import { WeatherService } from "./weather.service";

@Component({
  selector: "app-weather",
  standalone: true,
  template: ``,
})
export class WeatherComponent {
  constructor() {
    registerFrontendTool({
      name: "getWeather",
      description: "Fetch weather information for a city",
      parameters: z.object({
        city: z.string().describe("City name"),
        units: z.enum(["celsius", "fahrenheit"]).default("celsius"),
      }),
      handler: async ({ city, units }, { signal }) => {
        const weather = inject(WeatherService);
        const result = await weather.fetch(city, units, { signal });
        return JSON.stringify(result);
      },
    });
  }
}
```

### 带自定义 Angular 渲染组件的工具

将一个独立组件作为 `component` 传入，即可在聊天中可视化该工具调用。渲染器实现
`ToolRenderer<Args>`，因此暴露一个 `toolCall` signal 输入，携带 `status`、（可能不完整的）
`args` 与 `result`。

```ts title="src/app/weather-tool-view.component.ts"
import { Component, input } from "@angular/core";
import { AngularToolCall, ToolRenderer } from "@copilotkit/angular";

type WeatherArgs = { city: string; units: "celsius" | "fahrenheit" };

@Component({
  selector: "app-weather-tool-view",
  standalone: true,
  template: `
    @let call = toolCall();
    @if (call.status === "in-progress") {
      <div class="animate-pulse">Fetching weather for {{ call.args.city }}...</div>
    } @else if (call.status === "complete") {
      @let data = parse(call.result);
      <div class="rounded border p-4">
        <h3>{{ data.city }}</h3>
        <p>{{ data.temperature }} {{ data.units }}</p>
        <p>{{ data.conditions }}</p>
      </div>
    }
  `,
})
export class WeatherToolViewComponent implements ToolRenderer<WeatherArgs> {
  readonly toolCall = input.required<AngularToolCall<WeatherArgs>>();

  protected parse(result: string) {
    return JSON.parse(result);
  }
}
```

连同该组件一起注册工具：

```ts title="src/app/weather.component.ts"
import { Component, inject } from "@angular/core";
import { z } from "zod";
import { registerFrontendTool } from "@copilotkit/angular";
import { WeatherService } from "./weather.service";
import { WeatherToolViewComponent } from "./weather-tool-view.component";

@Component({
  selector: "app-weather",
  standalone: true,
  template: ``,
})
export class WeatherComponent {
  constructor() {
    registerFrontendTool({
      name: "getWeather",
      description: "Fetch and display weather information for a city",
      parameters: z.object({
        city: z.string().describe("City name"),
        units: z.enum(["celsius", "fahrenheit"]).default("celsius"),
      }),
      handler: async ({ city, units }, { signal }) => {
        const result = await inject(WeatherService).fetch(city, units, { signal });
        return JSON.stringify(result);
      },
      component: WeatherToolViewComponent,
    });
  }
}
```
