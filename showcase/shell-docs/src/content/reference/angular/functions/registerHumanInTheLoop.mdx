---

## 概览

`registerHumanInTheLoop` 注册一个会暂停智能体、等待人类输入的工具。当智能体调用该工具时，CopilotKit 会渲染你提供的 `component` 并挂起智能体运行。该组件从用户那里收集决策（例如确认或拒绝的选择），然后调用 `respond(result)`。这个调用会以你传给 `respond` 的值（按后文所述方式序列化）完成该工具，并让运行继续进行。

你需要在一个 Angular 注入上下文（组件或服务的构造函数，或字段初始化器）中调用 `registerHumanInTheLoop`。工具会立即注册。当所属的 injector 被销毁时，CopilotKit 会移除同名（以及可选 agent id）的工具与渲染器注册。

与 [`registerFrontendTool`](/reference/angular/functions/registerFrontendTool) 不同，你无需编写 `handler`。CopilotKit 会提供一个等待用户调用 `respond` 的 handler，因此由渲染出来的组件决定智能体何时恢复。

<Callout type="info">
  从包根路径 `@copilotkit/angular` 导入，不存在 `/v2`
  子路径。`registerHumanInTheLoop` 必须在作用域内包含
  [`provideCopilotKit`](/reference/angular/functions/provideCopilotKit) 的注入上下文中运行。
</Callout>

## 签名

```ts
import { registerHumanInTheLoop } from "@copilotkit/angular";

function registerHumanInTheLoop<Args extends Record<string, unknown>>(
  humanInTheLoop: HumanInTheLoopConfig<Args>,
): void;
```

## 参数

<PropertyReference name="humanInTheLoop" type="HumanInTheLoopConfig<Args>" required>
  工具定义对象。

  <PropertyReference name="name" type="string" required>
    工具的唯一名称。智能体在决定调用工具时会引用该名称。
  </PropertyReference>

  <PropertyReference name="description" type="string" required>
    一段自然语言描述，告诉智能体这个工具做什么、何时使用。
  </PropertyReference>

  <PropertyReference name="parameters" type="StandardSchemaV1<unknown, Args>" required>
    一个 [Standard Schema](https://standardschema.dev)（例如 Zod 对象），定义对外宣告的
    工具输入 schema，并为暴露给你组件的 `args` 提供类型推断。运行时参数会被 JSON
    解析并断言为 `Args`；此辅助函数不会依据 schema 校验它们。对于不接受参数的工具，传入空对象
    schema，例如 `z.object({})`。
  </PropertyReference>

  <PropertyReference name="component" type="Type<HumanInTheLoopToolRenderer<Args>>" required>
    智能体等待期间渲染的独立 Angular 组件类。CopilotKit
    会实例化它并绑定一个 `toolCall` signal 输入，其值携带 `args`、`status`、`result` 与
    `respond` 回调。
  </PropertyReference>

  <PropertyReference name="agentId" type="string">
    可选的智能体作用域。设置后，该工具只提供给具有此 id 的智能体。销毁时的清理也限定在同一
    `agentId`。
  </PropertyReference>
</PropertyReference>

## 返回值

`registerHumanInTheLoop` 返回 `void`。它以副作用的方式注册工具，并为所属 injector 建立按名称与 agent id 的清理逻辑。

## 渲染器组件

你的 `component` 实现 `HumanInTheLoopToolRenderer<Args>` 接口。它暴露一个 `toolCall` signal 输入，请使用 Angular 的 `input()` 声明：

```ts
import { Signal } from "@angular/core";

interface HumanInTheLoopToolRenderer<Args extends Record<string, unknown>> {
  toolCall: Signal<HumanInTheLoopToolCall<Args>>;
}
```

### HumanInTheLoopToolCall

`toolCall()` 返回一个以 `status` 为判别键的可辨识联合类型。每个变体都携带一个 `respond` 回调：

```ts
type HumanInTheLoopToolCall<Args extends Record<string, unknown>> =
  | {
      name?: string;
      args: Partial<Args>; // streaming, may be incomplete
      status: "in-progress";
      result: undefined;
      respond: (result: unknown) => void;
    }
  | {
      name?: string;
      args: Args; // fully parsed
      status: "executing";
      result: undefined;
      respond: (result: unknown) => void;
    }
  | {
      name?: string;
      args: Args; // fully parsed
      status: "complete";
      result: string; // stored tool-message content
      respond: (result: unknown) => void;
    };
```

`respond(result)` 回调是你的组件恢复智能体运行的方式。你传给 `respond`
的值会直接成为工具结果：字符串按原样存储，其他值由核心层序列化为 JSON。它不会被包在信封结构里，因此智能体看到的形状与 React 和 Vue
适配器下的完全相同。智能体等待期间，`status` 为 `executing`（参数仍在流式传输时为
`in-progress`）。一旦工具消息到达，`status` 变为 `complete`，`result` 中包含存储的工具消息字符串。

## 用法

### 确认对话框

该组件渲染一个确认按钮和一个拒绝按钮。每个按钮记录不同的决策并恢复智能体运行。

```ts title="src/app/confirm-dialog.component.ts"
import { Component, computed, input } from "@angular/core";
import { HumanInTheLoopToolCall, HumanInTheLoopToolRenderer } from "@copilotkit/angular";

type ConfirmArgs = { message: string };

@Component({
  selector: "app-confirm-dialog",
  standalone: true,
  template: `
    @let call = toolCall();
    @if (call.status === "complete") {
      <pre class="text-sm opacity-70">{{ call.result }}</pre>
    } @else {
      <div class="rounded border p-4">
        <p>{{ message() }}</p>
        <div class="mt-3 flex gap-2">
          <button type="button" (click)="call.respond('confirmed')">Confirm</button>
          <button type="button" (click)="call.respond('rejected')">Reject</button>
        </div>
      </div>
    }
  `,
})
export class ConfirmDialogComponent implements HumanInTheLoopToolRenderer<ConfirmArgs> {
  readonly toolCall = input.required<HumanInTheLoopToolCall<ConfirmArgs>>();
  readonly message = computed(() => this.toolCall().args.message ?? "Are you sure?");
}
```

连同该组件一起注册工具：

```ts title="src/app/chat.component.ts"
import { Component } from "@angular/core";
import { z } from "zod";
import { registerHumanInTheLoop } from "@copilotkit/angular";
import { ConfirmDialogComponent } from "./confirm-dialog.component";

@Component({
  selector: "app-chat",
  standalone: true,
  template: ``,
})
export class ChatComponent {
  constructor() {
    registerHumanInTheLoop({
      name: "confirmAction",
      description: "Ask the user to confirm before performing a sensitive action",
      parameters: z.object({
        message: z.string().describe("The confirmation question to show the user"),
      }),
      component: ConfirmDialogComponent,
    });
  }
}
```

当智能体调用 `confirmAction` 时，对话框会出现在聊天中，运行随之暂停。点击按钮会以 `"confirmed"` 或 `"rejected"` 作为工具结果发送。已完成的工具调用会暴露这个存储下来的字符串。

清理与其他工具注册辅助函数使用同一条共享的按名称与 agent id
移除路径。共享该键的前端工具、人机协同工具与工具调用渲染器会被一并移除。
