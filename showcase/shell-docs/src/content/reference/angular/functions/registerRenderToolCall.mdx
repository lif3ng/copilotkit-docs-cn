---
title: "registerRenderToolCall"

---

## 概览

`registerRenderToolCall` 为工具调用注册一个渲染器。它不会运行 handler，而是告诉
CopilotKit：当会话中出现 `name` 匹配的工具调用时，应渲染哪个独立的 Angular
组件。用它来可视化那些不在浏览器中执行的工具调用，例如服务端工具或智能体化（长时间运行）工具，此时你只需要在聊天中展示进度与结果。

你需要在一个 Angular 注入上下文（组件或服务的构造函数，或字段初始化器）中调用
`registerRenderToolCall`。渲染器会立即注册。当所属的 injector 被销毁时，CopilotKit
会移除同名（以及可选 agent id）的工具与渲染器注册。

如果你想既运行浏览器 handler 又渲染 UI，请改用 [`registerFrontendTool`](/reference/angular/functions/registerFrontendTool)
及其 `component` 字段。如果智能体还没有这个工具，而你只想让它展示你的某个组件，请使用
[`registerComponent`](/reference/angular/functions/registerComponent)，它会从前端声明该工具，智能体侧无需任何改动。

<Callout type="info">
  从包根路径 `@copilotkit/angular` 导入，不存在 `/v2`
  子路径。`registerRenderToolCall` 必须在作用域内包含
  [`provideCopilotKit`](/reference/angular/functions/provideCopilotKit) 的注入上下文中运行。
</Callout>

## 签名

```ts
import { registerRenderToolCall } from "@copilotkit/angular";

function registerRenderToolCall<Args extends Record<string, unknown>>(
  renderToolCall: RenderToolCallConfig<Args>,
): void;
```

## 参数

<PropertyReference name="renderToolCall" type="RenderToolCallConfig<Args>" required>
  渲染器定义对象。

  <PropertyReference name="name" type="string" required>
    要渲染的工具调用的名称。使用字面量 `"*"`
    可注册一个兜底渲染器，处理所有没有注册更具体渲染器的工具调用。
  </PropertyReference>

  <PropertyReference name="args" type="StandardSchemaV1<unknown, Args>" required>
    一个 [Standard Schema](https://standardschema.dev)（例如 Zod
    对象），描述工具调用的参数。它用于为暴露给你组件的 `args` 提供类型。
  </PropertyReference>

  <PropertyReference name="component" type="Type<ToolRenderer<Args>>" required>
    为该工具调用渲染的独立 Angular 组件类。CopilotKit
    会实例化它并绑定一个 `toolCall` signal 输入。
  </PropertyReference>

  <PropertyReference name="agentId" type="string">
    可选的智能体作用域。设置后，渲染器只作用于具有此 id
    的智能体发出的工具调用。省略时，渲染器作用于所有智能体。
  </PropertyReference>

  <PropertyReference name="passAgent" type="boolean" default="false">
    设为 `true` 时，CopilotKit 还会在组件上绑定一个 `agent` signal
    输入，值为发出该工具调用的智能体实例。如果你的渲染器不需要智能体实例，请保持 `false`（默认值）。
  </PropertyReference>
</PropertyReference>

## 返回值

`registerRenderToolCall` 返回 `void`。它以副作用的方式注册渲染器，并为所属 injector
建立按名称与 agent id 的清理逻辑。共享该键的前端工具、人机协同工具与渲染器注册会被一并移除。

## 渲染器组件

你的 `component` 实现 `ToolRenderer<Args>` 接口。CopilotKit
按名称绑定输入，因此请使用 Angular 的 `input()` 声明它们：

```ts
import { Signal } from "@angular/core";
import { AbstractAgent } from "@ag-ui/client";

interface ToolRenderer<Args extends Record<string, unknown>> {
  // Required: the current state of the tool call.
  toolCall: Signal<AngularToolCall<Args>>;
  // Bound only when the config sets passAgent: true.
  agent?: Signal<AbstractAgent | undefined>;
}
```

### AngularToolCall

`toolCall()` 返回一个以 `status` 为判别键的可辨识联合类型。`args` 与 `result`
的形状取决于状态：

```ts
type AngularToolCall<Args extends Record<string, unknown>> =
  | {
      name?: string;
      args: Partial<Args>; // streaming, may be incomplete
      status: "in-progress";
      result: undefined;
    }
  | {
      name?: string;
      args: Args; // fully parsed
      status: "executing";
      result: undefined;
    }
  | {
      name?: string;
      args: Args; // fully parsed
      status: "complete";
      result: string; // the tool result, as a string
    };
```

- **`in-progress`** 表示参数仍在流式传入，因此 `args` 为 `Partial<Args>`，`result` 为 `undefined`。
- **`executing`** 表示参数已完整到达且工具正在运行，因此 `args` 为完整的 `Args`，`result` 仍为 `undefined`。
- **`complete`** 表示工具已执行完毕，因此 `args` 为完整值，`result` 中保存字符串结果。

## 用法

### 服务端工具的渲染器组件

该渲染器在工具运行期间显示加载指示，然后渲染结果。它按 `status`
进行收窄，因此模板只有在 `result` 可用之后才会读取它。

```ts title="src/app/search-tool-view.component.ts"
import { Component, input } from "@angular/core";
import { AngularToolCall, ToolRenderer } from "@copilotkit/angular";

type SearchArgs = { query: string };

@Component({
  selector: "app-search-tool-view",
  standalone: true,
  template: `
    @let call = toolCall();
    @switch (call.status) {
      @case ("in-progress") {
        <div class="text-sm opacity-70">Preparing search...</div>
      }
      @case ("executing") {
        <div class="text-sm opacity-70">Searching for "{{ call.args.query }}"...</div>
      }
      @case ("complete") {
        <pre class="rounded border p-3 text-sm">{{ call.result }}</pre>
      }
    }
  `,
})
export class SearchToolViewComponent implements ToolRenderer<SearchArgs> {
  readonly toolCall = input.required<AngularToolCall<SearchArgs>>();
}
```

为你的智能体发出的工具名称注册它：

```ts title="src/app/chat.component.ts"
import { Component } from "@angular/core";
import { z } from "zod";
import { registerRenderToolCall } from "@copilotkit/angular";
import { SearchToolViewComponent } from "./search-tool-view.component";

@Component({
  selector: "app-chat",
  standalone: true,
  template: ``,
})
export class ChatComponent {
  constructor() {
    registerRenderToolCall({
      name: "searchDocuments",
      args: z.object({ query: z.string() }),
      component: SearchToolViewComponent,
    });
  }
}
```

### 接收智能体实例

设置 `passAgent: true` 后，CopilotKit 还会绑定 `agent` signal 输入。请在组件上将其声明为可选的
`input()`。

```ts title="src/app/handoff-tool-view.component.ts"
import { Component, input } from "@angular/core";
import { AbstractAgent } from "@ag-ui/client";
import { AngularToolCall, ToolRenderer } from "@copilotkit/angular";

type HandoffArgs = { target: string };

@Component({
  selector: "app-handoff-tool-view",
  standalone: true,
  template: `<div>Handing off to {{ toolCall().args.target }}</div>`,
})
export class HandoffToolViewComponent implements ToolRenderer<HandoffArgs> {
  readonly toolCall = input.required<AngularToolCall<HandoffArgs>>();
  readonly agent = input<AbstractAgent | undefined>();
}
```

```ts title="src/app/chat.component.ts"
registerRenderToolCall({
  name: "handoff",
  args: z.object({ target: z.string() }),
  component: HandoffToolViewComponent,
  passAgent: true,
});
```
