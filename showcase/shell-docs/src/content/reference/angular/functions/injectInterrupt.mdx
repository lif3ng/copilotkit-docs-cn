---
title: "injectInterrupt"
description: "Angular 中基于 signal 的标准与旧版 AG-UI 中断处理。"
---

`injectInterrupt` 会创建一个注入器作用域的控制器，用于处理 AG-UI 中断。
它同时支持标准中断数组与旧版的 `on_interrupt` 自定义事件，并可处理多个并发决策。

```ts
function injectInterrupt<TValue = unknown, TResult = never>(
  agentId?: string | Signal<string | undefined>,
  options?: Omit<InjectInterruptOptions<TValue, TResult>, "agentId">,
): InterruptController<TValue, TResult>;
```

```ts
import { Component } from "@angular/core";
import { injectInterrupt } from "@copilotkit/angular";

@Component({
  template: `
    @if (interrupt.view(); as decision) {
      <p>{{ decision.event.name }}</p>
      <button type="button" (click)="decision.cancel()">Cancel</button>
      <button type="button" (click)="decision.resolve({ approved: true })">
        Approve
      </button>
    }
  `,
})
export class ApprovalView {
  readonly interrupt = injectInterrupt<{ reason: string }>();
}
```

## 参数

- `agentId`：字符串或 signal；默认为当前上下文中的聊天智能体。
- `enabled(event)`：同步或异步过滤器。返回 `false` 时，该事件仍可供其他控制器使用。
- `handler(props)`：同步或异步预处理，其结果通过控制器的 `result` signal 暴露。

先前的 `injectInterrupt({ agentId, enabled, handler })` 调用形式仍然受支持。

该控制器暴露 `event`、`interrupt`、`interrupts`、`result`、`error`、`hasInterrupt` 和 `view` 这些 signal，以及 `resolve(payload?, interruptId?)` 与 `cancel(interruptId?)` 方法。当有多个标准中断同时挂起时，必须先对每个 ID 执行 resolve 或 cancel，智能体才能恢复运行。由工具支撑的决策会在恢复前持久化一条工具结果消息。

每个 store 都已经通过 [`AgentStore.interruptController`](/reference/angular/functions/injectAgentStore) 暴露了一个未过滤的控制器。当决策需要类型化的值、`enabled` 过滤器或 `handler` 时，再使用 `injectInterrupt`。

<Callout type="warn">
  各控制器之间不会互相认领中断。同一个智能体的 store 控制器与过滤控制器可能同时暴露同一个决策。如果两个 UI 都在下一轮运行开始前调用 `resolve`，二者都可能尝试恢复它。同一个决策只应渲染一个控制器。
</Callout>

例如，在这个组件中，匹配的退款中断会同时通过两个属性可见：

```ts
type RefundRequest = { type: "refund"; amount: number };

export class RefundPage {
  readonly store = injectAgentStore("ticketing");
  readonly refunds = injectInterrupt<RefundRequest>("ticketing", {
    enabled: event => event.value.type === "refund",
  });

  // For a matching interrupt, both expressions are true:
  // this.store().interruptController.hasInterrupt()
  // this.refunds.hasInterrupt()
}
```

针对该决策应渲染 `refunds`，不要再渲染 `store().interruptController`。未渲染的 store 控制器只会观察该中断；除非应用代码调用它的 `resolve` 或 `cancel` 方法，否则它无法恢复任何内容。

当所属注入器被销毁时，智能体订阅会随之断开。线程变更以及新的或失败的运行会清除过期的决策。谓词与处理器的失败会被 `error` 捕获；已过期的决策使用 `InterruptExpiredError`。恢复失败会清除挂起状态并触发拒绝（reject）——绝不会自动重试。该控制器不执行任何 DOM 操作且对 SSR 安全，但应用不应在服务端渲染期间恢复智能体。
