v2 React API（`@copilotkit/react-core/v2`）是构建 copilot 应用的下一代接口。它提供了一套精简的 hook 与组件，构建于 [AG-UI](https://docs.ag-ui.com) 智能体协议之上。

## 提供方配置

用 `<CopilotKitProvider>` 包裹你的应用，以配置 v2 运行时连接：

```tsx
import { CopilotKitProvider } from "@copilotkit/react-core/v2";

function App() {
  return (
    <CopilotKitProvider runtimeUrl="/api/copilotkit" agentId="default">
      <YourApp />
    </CopilotKitProvider>
  );
}
```

[`<CopilotKit>`](/reference/components/CopilotKit) 导出是 v1 兼容包装器，并非 `<CopilotKitProvider>` 的别名。请在 v2 提供方上使用 `agentId`；兼容包装器使用的是 `agent`，并保留 v1 的错误处理约定。

<Accordion title="CopilotKitProvider 属性">

### 属性

<PropertyReference name="agentId" type="string" default='"default"'>
  此提供方下聊天与 hook 使用的默认智能体。显式指定的 hook 或聊天 `agentId`，或外层的聊天配置，优先级更高。
</PropertyReference>

<PropertyReference name="licenseToken" type="string">
  用于离线验证 CopilotKit Intelligence 功能的签名许可令牌。
</PropertyReference>

<PropertyReference name="selfManagedAgents" type="Record<string, AbstractAgent>">
  由你的应用管理并直接注册到 CopilotKit 的 AG-UI 智能体。当你连接智能体而不经过 Copilot Runtime 路由时使用此项。
</PropertyReference>

<PropertyReference name="openGenerativeUI" type="{ sandboxFunctions?: SandboxFunction[]; designSkill?: string }">
  Open Generative UI 的配置。使用 `sandboxFunctions` 将宿主函数暴露给生成的沙箱 iframe，使用 `designSkill` 覆盖为 `generateSandboxedUi` 注入作为智能体上下文的设计指引。
</PropertyReference>

<PropertyReference name="defaultThrottleMs" type="number">
  由消息与状态更新引发的 `useAgent` 重新渲染的默认节流间隔（毫秒）。单个 `useAgent` 调用与预构建聊天组件可通过各自的 `throttleMs` 覆盖它。
</PropertyReference>

<PropertyReference name="debug" type="DebugConfig">
  启用针对 AG-UI 传输层与事件管线的客户端调试日志。传 `true` 获取事件与生命周期摘要，或传入含 `verbose: true` 的配置对象以包含完整事件负载。
</PropertyReference>

<PropertyReference name="runtimeUrl" type="string">
  CopilotKit 运行时端点的 URL。挂载后惰性转发给核心层。
</PropertyReference>

<PropertyReference name="headers" type="Record<string, string> | (() => Record<string, string>) | (() => Promise<Record<string, string>>)" default="{}">
  随运行时调用一起转发的请求头。传对象表示静态请求头，或传函数（同步或异步）以动态构建。构建函数会在每个请求发送时执行，因此总能使用刷新后的令牌。直接内联箭头函数即可。

  请在构建函数内部做缓存。Clerk 与 Auth0 的 `getToken()` 已自带缓存。每次都发起网络请求的构建函数会为每个请求额外增加一次调用。

  若构建函数抛出异常或 reject，该请求将不会发送，且 `onError` 会收到 `header_resolution_failed`。

  重复传入同一个构建函数不会产生任何效果。切换用户时，请重新挂载提供方（例如 `key={userId}`），以便 Inspector 元数据与线程列表为新用户重新加载。这不会重新获取运行时的 `/info`。

  `copilotkit.headers` 是最后解析出的值。对你自己的请求，请使用 `await copilotkit.resolveHeaders()`。

  核心请求头也会发送给任何 `selfManagedAgents` / `agents__unsafe_dev_only` 智能体，包括位于其他源的智能体。如果这些智能体指向第三方，请不要将 bearer 令牌放入核心请求头。

  ```tsx
  const { getToken } = useAuth();

  <CopilotKitProvider
    runtimeUrl="/api/copilotkit"
    headers={async () => ({ Authorization: `Bearer ${await getToken()}` })}
  >
  ```
</PropertyReference>

<PropertyReference name="credentials" type="RequestCredentials">
  fetch 请求的凭据模式（例如跨域请求中为 HTTP-only cookie 使用 `"include"`）。
</PropertyReference>

<PropertyReference name="publicApiKey" type="string">
  Copilot Cloud 公共 API 密钥。
</PropertyReference>

<PropertyReference name="publicLicenseKey" type="string">
  `publicApiKey` 的别名。
</PropertyReference>

<PropertyReference
  name="properties"
  type="Record<string, unknown>"
  default="{}"
>
  运行时元数据负载。
</PropertyReference>

<PropertyReference name="useSingleEndpoint" type="boolean">
  省略时，传输方式会根据运行时 info 响应协商确定。设为 `true` 使用单一端点，设为 `false` 使用独立路由。
</PropertyReference>

<PropertyReference
  name="agents__unsafe_dev_only"
  type="Record<string, AbstractAgent>"
>
  用于开发/测试的预实例化智能体。**不适用于生产环境。**
</PropertyReference>

<PropertyReference name="renderToolCalls" type="ReactToolCallRenderer[]">
  静态的工具调用渲染器集合。该数组在渲染间应保持稳定。
</PropertyReference>

<PropertyReference
  name="renderActivityMessages"
  type="ReactActivityMessageRenderer[]"
>
  静态的活动消息渲染器集合。
</PropertyReference>

<PropertyReference
  name="renderCustomMessages"
  type="ReactCustomMessageRenderer[]"
>
  静态的自定义消息渲染器集合。
</PropertyReference>

<PropertyReference name="frontendTools" type="ReactFrontendTool[]">
  在提供方层级定义的静态工具处理器。该数组在渲染间应保持稳定。
</PropertyReference>

<PropertyReference name="humanInTheLoop" type="ReactHumanInTheLoop[]">
  声明式的人机协同（human-in-the-loop）工具定义。每个定义同时成为工具处理器与工具调用渲染器。
</PropertyReference>

<PropertyReference name="enableInspector" type="boolean">
  控制 localhost 或回环主机上开发浏览器构建中的 CopilotKit Inspector。除非设为 `false`，否则默认显示；而在远程主机、生产环境或 SSR 期间绝不会加载，即使显式设为 `true`。
</PropertyReference>

<PropertyReference name="showDevConsole" type='boolean | "auto"'>
  **在 Inspector 控制方面已弃用**：该 prop 不再改变 Inspector 的可见性。请改用 `enableInspector`。
</PropertyReference>

<PropertyReference name="onError" type="(event: { error: Error; code: CopilotKitCoreErrorCode; context: Record<string, any> }) => void | Promise<void>">
  当 CopilotKit 遇到错误时调用的错误处理器。对所有错误类型都会触发：运行时连接失败、智能体错误与工具错误。

与 v1 的 `onError` 不同，它**不**要求 `publicApiKey`；任何配置下错误处理均可正常工作。

```tsx
<CopilotKitProvider
  runtimeUrl="/api/copilotkit"
  onError={(event) => {
    console.error(`[${event.code}]`, event.error.message, event.context);
  }}
>
  <App />
</CopilotKitProvider>
```

</PropertyReference>

</Accordion>
</Accordions>

## 导入入口

当你的应用渲染 CopilotKit 的 web UI 组件或 A2UI 界面时，使用主 v2 入口：

```tsx
import {
  CopilotKitProvider,
  CopilotChat,
  useAgent,
} from "@copilotkit/react-core/v2";
```

当你构建完全自定义的聊天界面、只需要与平台无关的 hook 时，使用无头（headless）入口。这样可以避免内置的聊天渲染栈及其 CSS：

```tsx
import {
  useAgent,
  useCopilotKit,
  useFrontendTool,
  useRenderToolCall,
} from "@copilotkit/react-core/v2/headless";
```

无头入口导出提供方上下文、聊天配置提供方、`useAgent`、工具 hook、建议、线程、能力与共享类型。它不导出 `CopilotKitProvider`、`CopilotKit`、`CopilotChat`、`CopilotPopup`、`CopilotSidebar`、`useDefaultRenderTool` 或 A2UI 渲染辅助函数。

## 样式

使用 v2 UI 组件时，在应用边界处一次性导入样式表：

```tsx
import "@copilotkit/react-core/v2/styles.css";
```
