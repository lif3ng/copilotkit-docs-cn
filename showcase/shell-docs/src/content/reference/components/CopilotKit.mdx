<Callout type="info" title="这是 v1 Provider，为向后兼容而重新导出">
  `<CopilotKit>` 是 v1 Provider。它从 `@copilotkit/react-core/v2` 重新导出，以便 v1 应用在导入路径变化后仍能正常工作，并且它在内部渲染 `<CopilotKitProvider>`。**v2 的 Provider 是 `<CopilotKitProvider>`**——新的 v2 代码请使用后者。
</Callout>

两者并不是别名：它们用不同的 prop 指定智能体。

|                | v1 `<CopilotKit>`  | v2 `<CopilotKitProvider>` |
| -------------- | ------------------ | ------------------------- |
| 指定智能体     | `agent="my_agent"` | `agentId="my_agent"`      |

你也可以用 `<CopilotChat agentId="my_agent">` 为单个聊天指定智能体，或用 `<CopilotChatConfigurationProvider agentId="my_agent">` 为某个子树指定。这两者都会覆盖 Provider 层级的默认值。参见 [Provider 与 handler 配对](/backend/runtime-endpoints#provider-and-handler-pairs)。

两个 Provider 对省略 `useSingleEndpoint` 的处理方式相同：传输方式会根据 Runtime info 响应协商确定。1.70.2 之前的版本会把 `<CopilotKit>` 固定为单路由传输。

该组件通常会包裹你的整个应用（或应用中你希望加入 copilot 的某个子树）。它为所有其他组件和 hooks 提供 copilot 上下文。

## 示例

关于自托管 CopilotKit 的更多信息请见[这里](/direct-to-llm/guides/self-hosting)。

```tsx
import { CopilotKit } from "@copilotkit/react-core/v2";

<CopilotKit runtimeUrl="<your-runtime-url>">// ... your app ...</CopilotKit>;
```

<PropertyReference name="headers" type="Record<string, string> | (() => Record<string, string>) | (() => Promise<Record<string, string>>)"  >
随运行时请求一起发送的额外请求头。传对象表示静态请求头，或传一个（同步或异步）函数来实时构建请求头。该函数会在每次请求发送时运行，因此始终使用刷新后的令牌。

在构建函数内部做好缓存。Clerk 和 Auth0 的 `getToken()` 本身已带缓存。每次都发起网络调用的构建函数会给每个请求增加一次额外调用。

如果构建函数抛出异常或 Promise 被拒绝，该请求将不会发送，并且 `onError` 会收到 `header_resolution_failed`。

旧版 v1 的 `CopilotTask` / GraphQL 路径不会等待异步构建函数：它会在不带该构建函数请求头的情况下发送请求，并记录一次性的开发警告。同步构建函数和普通对象都会按预期到达 `CopilotTask`。

核心请求头也会发送给任何 `selfManagedAgents` / `agents__unsafe_dev_only` 智能体，包括位于其他源（origin）上的智能体。如果这些智能体指向第三方，请不要在核心请求头中放入 bearer 令牌。

例如：

```tsx
const { getToken } = useAuth();

<CopilotKit
  runtimeUrl="/api/copilotkit"
  headers={async () => ({ Authorization: `Bearer ${await getToken()}` })}
>
  {children}
</CopilotKit>
```

</PropertyReference>

<PropertyReference name="children" type="ReactNode" required>
  要在 CopilotKit 内渲染的子元素。
</PropertyReference>

<PropertyReference name="properties" type="Record<string, any>"  >
随请求一起发送的自定义属性。
  可包含用于创建线程的 threadMetadata，以及用于 LangGraph Platform 身份验证的 authorization。
  例如：
  ```js
  {
    'user_id': 'users_id',
    'authorization': 'your-auth-token', // For LangGraph Platform authentication
    threadMetadata: {
      'account_id': '123',
      'user_type': 'premium'
    }
  }
  ```

注意：`authorization` 属性会自动转发给 LangGraph 智能体。详情请参阅 LangGraph 智能体身份验证指南（见上方代码示例）。

</PropertyReference>

<PropertyReference name="credentials" type="RequestCredentials"  >
指示在跨源请求的情况下，用户代理是否应向另一个域发送或从其接收 cookie。

要启用 HTTP-only cookie 身份验证，请设置 `credentials="include"`，并在运行时端点上配置 CORS：

```tsx
// Frontend (https://myapp.com)
<CopilotKit runtimeUrl="https://api.myapp.com/copilotkit" credentials="include">
  {children}
</CopilotKit>;

// Backend (https://api.myapp.com)
import { createCopilotRuntimeHandler } from "@copilotkit/runtime/v2";

const handler = createCopilotRuntimeHandler({
  runtime,
  basePath: "/copilotkit",
  cors: {
    origin: "https://myapp.com",
    credentials: true,
  },
});
```

</PropertyReference>

<PropertyReference name="showDevConsole" type="boolean"  >
是否显示开发者控制台。

设为 `true` 显示错误横幅和 toast，设为 `false` 隐藏所有错误 UI。出于生产环境安全考虑，默认为 `false`。

</PropertyReference>

<PropertyReference name="showIntelligenceIndicator" type="boolean">

</PropertyReference>

<PropertyReference name="selfManagedAgents" type="Record<string, AbstractAgent>">

</PropertyReference>

<PropertyReference name="agents__unsafe_dev_only" type="Record<string, AbstractAgent>">

<PropertyReference name="a2ui" type="{ theme?: Theme; catalog?: any; loadingComponent?: React.ComponentType; includeSchema?: boolean; recovery?: A2UIRecoveryRendererOptions }">
A2UI（Agent-to-UI）渲染器的配置。

当运行时报告 `CopilotRuntime` 中已配置 `a2ui` 时，内置的 A2UI 渲染器会自动激活。该 prop 是可选的，仅在需要覆盖主题、提供自定义组件 `catalog`、设置 `loadingComponent`、切换是否包含 schema（`includeSchema`）或调整错误恢复状态 UI（`recovery`）时才需要。

`includeSchema` 默认为 `true`，会把目录（catalog）的组件 schema 以及 A2UI 生成与设计指南作为上下文发送给智能体。设为 `includeSchema: false` 时，智能体仍会收到目录 ID 和目录中自定义组件的名称，但不会收到它们的 JSON schema 和指南。此时，使用 CopilotKit 中间件注入的 A2UI 工具的 LangGraph 智能体只会把组件名称交给它的 A2UI 子智能体。若要给子智能体更多细节，可通过中间件的 A2UI 指南传入组合指南：TypeScript 中为 `a2uiParams.guidelines.compositionGuide`，Python 中为 `a2ui_params["guidelines"]["composition_guide"]`。

```tsx
<CopilotKit runtimeUrl="/api/copilotkit" a2ui={{ theme: myCustomTheme }}>
  {children}
</CopilotKit>
```

</PropertyReference>

<PropertyReference name="mcpApps" type="{ allowSameOriginFallback?: boolean }">
内置 MCP Apps 渲染器的配置。

`allowSameOriginFallback` 会在 MCP App 沙箱上恢复 `allow-same-origin`。默认情况下，小部件（widget）使用不透明的源。**不安全**：设置后，小部件将以你页面的源运行，可以读取你的 cookie、存储和 DOM。只对你信任的、确实需要 `localStorage`、`IndexedDB` 或 cookie 的小部件使用它。参见 [沙箱与小部件存储](/generative-ui/mcp-apps#sandbox-and-widget-storage)。

</PropertyReference>

<PropertyReference name="openGenerativeUI" type="{ sandboxFunctions?: SandboxFunction[]; designSkill?: string }">
  Open Generative UI 的配置。用 `sandboxFunctions` 将宿主函数暴露给生成的沙箱化 iframe，用 `designSkill` 覆盖注入给 `generateSandboxedUi` 的、作为智能体上下文的设计指南。
</PropertyReference>

<PropertyReference name="defaultThrottleMs" type="number">
  由消息和状态更新触发的 `useAgent` 重渲染的默认节流间隔（毫秒）。单个 `useAgent` 调用和预构建聊天组件可以用各自的 `throttleMs` 覆盖它。
</PropertyReference>

<PropertyReference name="agent" type="string">

</PropertyReference>

<PropertyReference name="onError" type="CopilotErrorHandler"  >
可选的错误处理函数，用于全面的调试与可观测性。

需要 publicApiKey：只有提供了 publicApiKey，错误处理才会生效。这是一项 CopilotKit Intelligence 功能。

@param errorEvent - 带有丰富调试上下文的结构化错误事件

@example

```tsx
<CopilotKit
  publicApiKey="ck_pub_your_key"
  onError={(errorEvent) => {
    debugDashboard.capture(errorEvent);
  }}
>
  {children}
</CopilotKit>
```

</PropertyReference>

<PropertyReference name="enableInspector" type="boolean">
  启用或禁用 CopilotKit Inspector，可用于检查 AG-UI 事件、查看智能体消息、检查智能体状态以及可视化智能体上下文。在 localhost 或回环地址上的开发浏览器构建中默认启用；在远程主机、生产环境以及服务器端渲染时始终禁用。
</PropertyReference>

<PropertyReference name="debug" type="DebugConfig">
  为 AG-UI 传输层和事件管线启用客户端调试日志。传 `true` 可获得事件与生命周期摘要；传带有 `verbose: true` 的配置对象则包含完整的事件载荷。
</PropertyReference>
