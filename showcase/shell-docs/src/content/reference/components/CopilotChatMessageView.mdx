## 概览

`CopilotChatMessageView` 渲染聊天消息列表，并可在智能体运行时渲染一个输入中的光标。它把单条消息的渲染委托给插槽组件（`assistantMessage` 与 `userMessage`），并支持 render-prop 形式的 `children` 函数，以便完全掌控布局。

## 导入

```tsx
import { CopilotChatMessageView } from "@copilotkit/react-core/v2";
import "@copilotkit/react-core/v2/styles.css";
```

## Props

<PropertyReference name="isRunning" type="boolean" default="false">
  智能体当前是否正在执行。为 `true` 时，光标插槽会渲染在最后一条消息之后，表示仍有活动在进行。
</PropertyReference>

<PropertyReference name="messages" type="Message[]" default="[]">
  要渲染的聊天消息数组。每个消息对象至少包含 `id`、`role`（`"user"` 或 `"assistant"`）与 `content`。
</PropertyReference>

<PropertyReference name="transformMessages" type="(messages: Message[]) => Message[]">
  在渲染前重塑列表：可以基于完整列表丢弃、替换或重排消息。它接收已合并重复 id 后的消息，并返回要渲染的列表。虚拟化、行键、滚动到底部与“最新消息”都以返回的列表为准，因此被丢弃的消息不会占据任何行。工具调用卡片仍会在完整的 `messages` 中查找其结果，因此隐藏工具结果消息不会使卡片变空。每个 id 最多返回一次，并且你自行构造的消息要使用在线程流式输出期间保持不变的 id。当 `messages` 或该函数变化时，transform 会重新运行，因此请传入稳定的函数（例如用 `useCallback`）。参见[重塑消息列表](/custom-look-and-feel/slots#reshaping-the-message-list)。
</PropertyReference>

<PropertyReference name="groupMessages" type="(messages: Message[]) => MessageRow[]">
  把列表拆分成行。对单独渲染的消息返回 `messageRow(message)`；对一起渲染在 `wrapper` 内的消息返回 `messageGroup({ key, messages, wrapper })`，`wrapper` 会收到 `groupKey`、`messages`、`children`（这些消息的默认渲染）以及 `state` / `setState`。每一行就是一个虚拟化行。聊天会把组的状态保存在其 `key` 之下，因此该行离开窗口后状态仍然保留；当 key 不再出现时状态被丢弃，线程变化时被清除。它接收 `transformMessages` 之后的列表。每条消息至多放入一行，在线程流式输出期间保持 key 稳定，在模块层级定义 wrapper，并传入稳定的函数。参见[把消息分组到一行](/custom-look-and-feel/slots#grouping-messages-into-one-row)。
</PropertyReference>

<PropertyReference name="messageFeedback" type="boolean" default="true">
  Trajectory 启动后，回复的拇指按钮是否为 Automatic Learning 记录评分。设为 `false` 可让拇指按钮只使用你自己的 `onThumbsUp` / `onThumbsDown` 处理器与插槽。参见[收集回复评分](/intelligence/capture-interactions#collect-reply-ratings)。
</PropertyReference>

<PropertyReference name="toolCallDisplay" type='"grouped" | "line" | "stacked" | "turn" | "separate"' default='"grouped"'>
  工具调用在列表中的展示方式。

- `"grouped"`（默认）：智能体连续发起的调用共用一张卡片，折叠为一条摘要（"Used 3 tools · run_command ×2, read_file"）。当某个调用正在运行时，摘要会点名它。展开卡片可以看到每个调用一行，每行再展开可查看其参数与结果。
- `"line"`：同样的分组，呈现为一行安静的文本，类似推理消息的"Thought for 4 seconds"。展开后是一个行列表。
- `"stacked"`：最新的调用叠在先前调用堆栈的顶部。点击堆栈会把它们展开为每个调用一张卡片。
- `"turn"`：智能体公开工作。回复顶部有一行"Working"，当其后跟有调用时，叙述文字会淡化为弱化样式，调用以行的形式出现。回复完成后，之前的一切折叠为"Worked for 9s"，只留下回复正文。该行就是 [`workSummary`](#worksummary) 插槽。
- `"separate"`：每个调用都有自己的卡片。这是引入分组之前的行为。

分组仅适用于其渲染器选择加入分组的调用，[`useDefaultRenderTool()`](/reference/hooks/useDefaultRenderTool) 的内置卡片即属此类。自定义的兜底渲染器用 `group: true` 加入分组；在此之前，它的调用会单独显示，因为聊天无法判断它绘制了什么（也可能什么都没画）。任何未分组的调用都会把组从它所在处切开，文本、推理与活动消息也是如此。完全没有渲染器的调用依旧什么都不渲染。要重新设计样式或替换分组本身，请使用 [`CopilotChatToolCallsView`](/reference/components/CopilotChatAssistantMessage#copilotchattoolcallsview) 的 `group` 插槽。参见[工具调用分组](/generative-ui/tool-rendering#grouping-tool-calls)。
</PropertyReference>

<PropertyReference name="children" type="(props: { isRunning: boolean; messages: Message[]; messageElements: React.ReactElement[] }) => React.ReactElement">
可选的 render-prop 函数，接收解析后的状态与预构建的消息元素。提供该函数时，组件会调用它而不是渲染默认的消息列表布局。回调接收 `isRunning`（当前运行状态）、`messages`（原始消息数组）与 `messageElements`（由 `assistantMessage` 与 `userMessage` 插槽构建的 React 元素数组）。提供 `children` 会关闭虚拟化，因此每条消息都会被挂载；对于列表层面的调整，优先使用 `transformMessages`。
</PropertyReference>

## 插槽

所有插槽 props 都遵循 CopilotKit 插槽系统：每个插槽都接受一个替换用的 React 组件、一个合并进默认组件 class 的 `className` 字符串，或一个用于扩展默认组件的局部 props 对象。

<PropertyReference name="assistantMessage" type="SlotProp<typeof CopilotChatAssistantMessage>">
  渲染助手消息的插槽。默认为 [`CopilotChatAssistantMessage`](/reference/components/CopilotChatAssistantMessage)，提供 Markdown 渲染、工具调用展示与操作工具栏。

**作为替换组件**：

```tsx
<CopilotChatMessageView
  assistantMessage={({ message }) => (
    <div className="my-assistant-msg">{message.content}</div>
  )}
/>
```

**作为 className**：

```tsx
<CopilotChatMessageView assistantMessage="bg-blue-50 rounded-lg" />
```

**作为局部 props**：

```tsx
<CopilotChatMessageView assistantMessage={{ toolbarVisible: false }} />
```

</PropertyReference>

<PropertyReference name="userMessage" type="SlotProp<typeof CopilotChatUserMessage>">
  渲染用户消息的插槽。默认为 [`CopilotChatUserMessage`](/reference/components/CopilotChatUserMessage)，提供右对齐的消息展示与可选的分支导航。

**作为替换组件**：

```tsx
<CopilotChatMessageView
  userMessage={({ message }) => (
    <div className="my-user-msg">{message.content}</div>
  )}
/>
```

**作为 className**：

```tsx
<CopilotChatMessageView userMessage="bg-gray-100 rounded-lg" />
```

</PropertyReference>

<PropertyReference name="cursor" type="SlotProp<typeof CopilotChatMessageView.Cursor>">
  `isRunning` 为 `true` 时显示的输入中指示器插槽。默认为 `CopilotChatMessageView.Cursor`，渲染一个脉动圆点动画。

**作为替换组件**：

```tsx
<CopilotChatMessageView
  cursor={() => <span className="animate-bounce">...</span>}
/>
```

**作为 className**：

```tsx
<CopilotChatMessageView cursor="text-blue-500" />
```

</PropertyReference>

<PropertyReference name="workSummary" type="SlotProp<typeof CopilotChatWorkSummary>">
  `"turn"` 工具调用展示方式下每条回复顶部那一行的插槽。默认为 [`CopilotChatWorkSummary`](/reference/components/CopilotChatToolCallGroup#copilotchatworksummary)。智能体工作时它显示"Working"并伴随计时，回复完成后变为"Worked for 9s"，并可切换展开/收起已折叠的工作内容。仅在 `toolCallDisplay` 为 `"turn"` 时渲染。

**作为 className**：

```tsx
<CopilotChatMessageView toolCallDisplay="turn" workSummary="text-xs" />
```

**作为替换组件**：

```tsx
<CopilotChatMessageView
  toolCallDisplay="turn"
  workSummary={({ isWorking, isOpen, calls, onClick }) => (
    <button onClick={onClick} aria-expanded={isOpen}>
      {isWorking ? "Thinking it through…" : `Checked ${calls.length} sources`}
    </button>
  )}
/>
```

</PropertyReference>

## 用法

### 基本消息列表

```tsx
function MessageList() {
  const { agent } = useAgent();

  return (
    <CopilotChatMessageView
      messages={agent.messages}
      isRunning={agent.isRunning}
    />
  );
}
```

### 自定义消息插槽

```tsx
function CustomMessages() {
  const { agent } = useAgent();

  return (
    <CopilotChatMessageView
      messages={agent.messages}
      isRunning={agent.isRunning}
      assistantMessage="bg-blue-50 p-4 rounded-xl"
      userMessage="bg-gray-100 p-4 rounded-xl"
      cursor={() => (
        <div className="animate-pulse text-gray-400">Thinking...</div>
      )}
    />
  );
}
```

### 用 Render-Prop Children 自定义布局

```tsx
function CustomLayout() {
  const { agent } = useAgent();

  return (
    <CopilotChatMessageView
      messages={agent.messages}
      isRunning={agent.isRunning}
    >
      {({ isRunning, messages, messageElements }) => (
        <div className="flex flex-col gap-4 p-6">
          <div className="text-sm text-gray-500">
            {messages.length} message{messages.length !== 1 ? "s" : ""}
          </div>
          {messageElements}
          {isRunning && (
            <div className="text-sm text-blue-500 animate-pulse">
              Agent is responding...
            </div>
          )}
        </div>
      )}
    </CopilotChatMessageView>
  );
}
```

### 选择工具调用的展示方式

```tsx
function AgentChat() {
  const { agent } = useAgent();

  return (
    <CopilotChatMessageView
      messages={agent.messages}
      isRunning={agent.isRunning}
      toolCallDisplay="turn"
    />
  );
}
```

在 `CopilotChat`、`CopilotSidebar` 或 `CopilotPopup` 中，通过 `messageView` 插槽设置：

```tsx
<CopilotChat messageView={{ toolCallDisplay: "line" }} />
```

要让每个调用重新拥有自己的卡片：

```tsx
<CopilotChat messageView={{ toolCallDisplay: "separate" }} />
```

### 隐藏助手消息上的工具栏

```tsx
function MinimalChat() {
  const { agent } = useAgent();

  return (
    <CopilotChatMessageView
      messages={agent.messages}
      isRunning={agent.isRunning}
      assistantMessage={{ toolbarVisible: false }}
    />
  );
}
```

## 行为

- **消息渲染**：`messages` 数组中的每条消息都会根据其 `role` 用对应的插槽组件渲染。助手消息使用 `assistantMessage` 插槽；用户消息使用 `userMessage` 插槽。
- **光标显示**：仅当 `isRunning` 为 `true` 时才渲染 `cursor` 插槽。它出现在列表最后一条消息之后；当最后渲染的消息是推理消息时它会隐藏，因为推理消息会显示自己的指示器。
- **虚拟化**：在聊天滚动容器内，一旦渲染的消息超过 50 条，就只挂载屏幕上的行。统计的是实际渲染的消息数：即 `transformMessages` 返回的消息，或使用 `groupMessages` 时其返回行中的消息。窗口本身按行移动，每个组就是一行。提供 `children` 会关闭虚拟化；在开发环境下，如果正是这一点导致长线程被完整挂载，组件会警告一次。
- **最新消息**：最后渲染的消息会以 `isLatest` 传给其插槽。当 `isRunning` 为 `true` 时，最新的助手消息会隐藏工具栏，最新的推理消息则以流式方式显示。
- **工具调用分组**：分组可以跨越消息，因为智能体常常把每个调用作为独立的助手消息发送。组归属于它开始的那条消息，而调用并入了该组的后续消息则不再渲染自己的工具调用。当智能体正在运行且组后面没有别的内容时，其摘要会点名正在进行的调用。
- **工作摘要**：在 `"turn"` 展示方式下，回复进行期间摘要会取代光标。"Worked for 9s" 累计的是智能体在该回复上的运行时间，因此中间的等待（比如等待批准）不计入。它需要本组件亲眼看到该回复启动，因此恢复的线程会改为显示工具数量（"Used 7 tools"）。结束回复的文本在折叠后仍然可见，即使其所在消息还调用了工具。回复工作的展开/收起状态会被记住，即使后续运行更新了它。
- **Render-Prop 覆盖**：当 `children` 以函数形式提供时，组件把所有布局委托给该函数。`messageElements` 数组由插槽组件预构建，因此自定义布局仍能受益于插槽定制。
- **插槽系统**：每个插槽 prop 接受三种形式——替换组件、合并进默认组件的 className 字符串，或扩展默认组件 props 的局部 props 对象。
