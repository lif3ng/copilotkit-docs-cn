---
title: IncomingMessage
description: 传递给 Channels 处理器的规范化提供方消息，包括用户、多模态内容部分与托管关联 id。
---

`IncomingMessage` 是传递给 `onMessage`、`onMention`、工具与交互上下文的规范化入站回合。

## 结构

```ts
interface IncomingMessage {
  text: string;
  user: ApplicationUser | null;
  actor: ProviderActor;
  ref: MessageRef;
  platform: string;
  contentParts?: AgentContentPart[];
  eventId?: string;
  turnId?: string;
  deliveryId?: string;
}
```

| 字段 | 托管 Slack 与 Teams 下的行为                                                                        |
| -------------- | ------------------------------------------------------------------------------------------------------- |
| `text`         | 经过入站规范化处理后的提供方文本。                                                              |
| `user`         | 由 Channel 的 `identifyUser` 策略返回、可为 null 的应用用户。                              |
| `actor`        | 触发该事件的提供方账户，其中包含必需的 actor 种类。                              |
| `ref`          | 在普通消息处理器中，它的 id 可能为空；不要假设每个入站回合都可以编辑。 |
| `platform`     | 原生来源：消息投递为 `"slack"` 或 `"teams"`。                                           |
| `contentParts` | 已检索到附件时填充好的文件/媒体部分。                                                              |
| `eventId`      | 用于应用幂等的稳定提供方事件 id。                                                   |
| `turnId`       | 托管回合的关联 id。                                                                            |
| `deliveryId`   | 托管租约/投递的关联 id。                                                                  |

## 多模态提示

```ts
const prompt = message.contentParts?.length
  ? [
      ...(message.text ? [{ type: "text" as const, text: message.text }] : []),
      ...message.contentParts,
    ]
  : message.text;

await thread.runAgent({ prompt });
```

托管历史不包含当前入站回合。省略 `prompt` 时，`runAgent()` 会自动注入该消息；当回合可能同时包含文本与附件时，请使用上面的显式组合提示。参见[文件与多模态输入](/slack/files-and-multimodality)。
