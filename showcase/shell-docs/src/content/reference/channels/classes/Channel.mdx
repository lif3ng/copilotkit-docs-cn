`createChannel(options)` 会返回你在 `CopilotRuntime({ channels })` 上声明的 Channel。

```ts title="channel.ts"
import { createChannel } from "@copilotkit/channels";
import { makeAgent } from "./agent.js";

const channel = createChannel({
  name: "support",
  identifyUser: "platform",
  agent: makeAgent,
});
```

使用项目内唯一的 Intelligence Channel Code。托管运行时会为该渠道同时声明 Slack 和 Microsoft Teams，并确保每路投递都按提供方隔离。

## createChannel 选项

| 选项                | 类型                                                   | 说明                                                                                                                        |
| ------------------- | ------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| `name`              | `string`                                               | 项目内唯一的 Intelligence Code。托管渠道必填；小写 kebab-case，3–64 个字符，且不能是 `channels`。                            |
| `identifyUser`      | `"platform" \| ChannelIdentifyUser`                    | 必填的身份策略。针对每个提供方事件返回一个应用用户或 `null`。                                                                |
| `showToolStatus`    | `boolean`                                              | 控制托管 Slack 的工具调用进度展示。默认隐藏；设为 `true` 可显示。                                                            |
| `replyContinuation` | `ReplyContinuationOptions`                             | 托管 Slack 的长回复限制：`messageByteLimit`、`maxMessages` 与 `truncationMarker`。                                           |
| `agent`             | `AbstractAgent \| (threadId: string) => AbstractAgent` | 智能体实例或工厂。优先使用工厂；每一轮都会克隆配置的结果。                                                                   |
| `sanitizeAgentEvents` | `boolean`                                            | 默认为 `true`；修复 HTTP 事件流中一个已知格式错误的 AG-UI 父消息字段。                                                       |
| `tools`             | `ChannelTool[]`                                        | 转发给智能体的带类型工具。                                                                                                   |
| `context`           | `ContextEntry[]`                                       | 每次运行都会发送的稳定 `{ description, value }` 上下文。                                                                      |
| `components`        | `ChannelComponent[]`                                   | 具名 JSX 组件，其回调可从存储的快照中重建。                                                                                   |
| `commands`          | `ChannelCommand[]`                                     | 为支持命令的提供方声明的命令。                                                                                                |
| `store`             | `StoreConfig`                                          | 状态 schema、持久化、轮次并发（默认 `parallel`）、去重，以及可选的会话记录桥接。                                              |
| `adapters`          | `PlatformAdapter[]`                                    | 底层直连传输。它们可与该渠道上的云托管 Intelligence 适配器共存。                                                              |

一个渠道可以接收托管的 Slack 和 Teams 投递。名称在同一个 `CopilotRuntime` 内必须唯一。

关于长回复默认值、事件清理与智能体克隆要求的更多细节，参见详细的 [`createChannel` 选项](/reference/channels/functions/createChannel)。

## StoreConfig

| 选项                | 类型                               | 说明                                                                                                                                           |
| ------------------- | ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `state`             | `StandardSchema`                   | 为 `thread.state()` 提供类型，并校验每一次 `setState(value)`。                                                                                  |
| `adapter`           | `StateStore`                       | SDK 状态的持久化实现。缺省时，当前的托管实时路径会回退到进程内存。                                                                              |
| `transcripts`       | `TranscriptsConfig`                | 由 SDK 管理的跨平台会话记录配置，以顶层 `identifyUser` 得出的应用用户为键。                                                                     |
| `actionRetentionMs` | `number`                           | 持久化回调与一次性人机协同（human-in-the-loop）续接的保留期。默认：七天。                                                                       |
| `concurrency`       | `"parallel" \| "serial" \| "drop"` | 同一会话上重叠轮次的处理方式。默认：`"parallel"`。参见 [`StoreConfig`](/reference/channels/types/StoreConfig)。                                 |
| `onLockConflict`    | `"drop" \| "force" \| callback`    | **已弃用**。请改用 `concurrency`。取静态值时映射为 drop/parallel。                                                                              |
| `lockTtl`           | `number`                           | 会话锁 TTL，单位毫秒（drop / 旧版路径）。默认：`60_000`。                                                                                      |
| `dedupTtl`          | `number`                           | 入站事件去重窗口，单位毫秒。默认：`300_000`。                                                                                                  |

`StateStore` 包含 `kv`、`list`、`lock`、`dedup` 与 `queue` 五个部分。远程实现必须保持值可经 JSON 序列化。

### StateStore 契约

生产级适配器需要实现这一异步契约。当多个 runner 实例共享同一后端时，锁、去重与队列操作必须保持原子性。

```ts title="state-store.ts"
interface StateStore {
  kv: {
    get<T>(key: string): Promise<T | undefined>;
    set<T>(key: string, value: T, ttlMs?: number): Promise<void>;
    consume<T>(key: string): Promise<T | undefined>;
    delete(key: string): Promise<void>;
  };
  list: {
    append<T>(
      key: string,
      value: T,
      options?: { maxLen?: number; ttlMs?: number },
    ): Promise<number>;
    range<T>(key: string, start?: number, stop?: number): Promise<T[]>;
    trim(key: string, maxLen: number): Promise<void>;
    delete(key: string): Promise<void>;
  };
  lock: {
    acquire(
      key: string,
      options?: { ttlMs?: number },
    ): Promise<{ token: string } | null>;
    release(key: string, token: string): Promise<void>;
  };
  dedup: {
    // true means the key was already recorded inside the TTL.
    seen(key: string, ttlMs: number): Promise<boolean>;
  };
  queue: {
    enqueue<T>(
      key: string,
      value: T,
      options?: {
        maxSize?: number;
        onFull?: "drop-oldest" | "drop-newest";
      },
    ): Promise<number>;
    dequeue<T>(key: string): Promise<T | undefined>;
    depth(key: string): Promise<number>;
  };
}
```

所有值都必须能经 JSON 往返不失真。分布式实现只有在传入的 token 仍持有该锁时才允许释放锁。

## 属性

| 属性                | 类型                         | 说明                                                                                                          |
| ------------------- | ---------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `name`              | `string \| undefined`        | 声明的 Intelligence Code。                                                                                    |
| `showToolStatus`    | `boolean \| undefined`       | 来自 `createChannel()` 的托管 Slack 工具调用可见性偏好。                                                       |
| `replyContinuation` | `ReplyContinuationOptions \| undefined` | 来自 `createChannel()` 的托管 Slack 续接偏好。                                                      |
| `adapters`          | `readonly PlatformAdapter[]` | 已挂载传输的快照。托管渠道初始为空，在激活时获得 Intelligence 适配器。                                         |
| `commandNames`      | `string[]`                   | 通过 `commands` 或 `onCommand` 声明的规范化名称。                                                              |
| `transcripts`       | `Transcripts`                | 可选的 SDK 会话记录 API。它不是托管提供方的历史存储。                                                          |

`transcripts` getter 只有在渠道激活之后才可用；若在运行时监听器启动渠道之前读取，它会抛出异常。

## 消息处理函数

```ts title="channel.ts"
channel.onMessage(async ({ thread, message }) => {
  await thread.runAgent({
    prompt: message.contentParts?.length
      ? [
          ...(message.text
            ? [{ type: "text" as const, text: message.text }]
            : []),
          ...message.contentParts,
        ]
      : message.text,
  });
});
```

| 方法                       | 处理函数入参                        | 说明                                                                                                                           |
| -------------------------- | ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `onMessage(handler)`       | `{ thread, message }`               | 托管 Slack 与 Teams 轮次使用此处理函数。                                                                                       |
| `onMention(handler)`       | `{ thread, message }`               | 注册后，机器人提及（mention）会路由到此处理函数；否则回退到 `onMessage`。其余内容一律由 `onMessage` 处理。                      |
| `onWelcome(handler)`       | `{ thread, user, actor, platform }` | 对于受支持的提供方安装或会话激活，运行一次。未注册处理函数即不输出欢迎语。                                                      |
| `onThreadStarted(handler)` | `{ thread, user, actor }`           | 在会上报会话开启事件的提供方入口上触发。                                                                                       |

`message.platform` 是原生提供方（`"slack"` 或 `"teams"`）。在托管渠道上，`thread.platform` 携带相同的原生提供方。

## 交互与中断处理函数

| 方法                                 | 用途                                                               | 托管 Slack/Teams                                                    |
| ------------------------------------ | ------------------------------------------------------------------ | ------------------------------------------------------------------- |
| `onInteraction(id, handler)`         | 处理某个特定的不透明操作 id。                                       | 已投递的操作支持此方式。JSX 回调通常更简单。                        |
| `onInterrupt(eventName, handler)`    | 为智能体中断发布 UI；稍后调用 `thread.resume(value)`。             | 当前托管渲染器使用 `eventName: "on_interrupt"`。                    |
| `onReaction(emoji?, handler)`        | 处理已投递的表情回应事件。                                         | 入站支持取决于提供方。                                              |
| `onCommand(command)`                 | 注册带类型或自由文本的命令。                                       | 取决于提供方。                                                      |
| `onModalSubmit(callbackId, handler)` | 处理模态框表单提交。                                               | 托管实时路径不会投递。                                              |
| `onModalClose(callbackId, handler)`  | 处理模态框关闭。                                                   | 托管实时路径不会投递。                                              |

参见 [Slack 交互式消息指南](/slack/interactive)、[Teams 交互式消息指南](/teams/interactive)与 [JSX 回调参考](/reference/channels/types/JSXCallbacks)。

## 运行时生命周期

Channel 没有公开的 `start()` 方法。Node 与 Express 监听器拥有长期运行的进程生命周期，因此创建任一监听器都会自动启动托管渠道。在这类挂载上，`ready()` 是可选的：当启动过程必须在其余逻辑继续之前观察到初始托管状态时，再 await 它。

Hono 与通用 Fetch 挂载面向请求，保持惰性。在预期接收托管流量之前，请在显式的长期运行启动路径中调用并 await `ready()`；仅创建这类处理函数并不会打开 Realtime Gateway 连接。

| 运行时挂载      | 启动行为                   | `ready()` 的作用                     |
| --------------- | -------------------------- | ------------------------------------ |
| Node 监听器     | 创建监听器时即启动         | 可选的就绪等待与初始状态检查         |
| Express 监听器  | 创建监听器时即启动         | 可选的就绪等待与初始状态检查         |
| Hono 挂载       | 惰性                       | 在预期托管流量之前显式 await         |
| 通用 Fetch 挂载 | 惰性                       | 在预期托管流量之前显式 await         |

在等待就绪之前先安装关闭处理函数，这样缓慢或不完整的提供方配置也不会阻碍优雅关闭：

```ts title="channel.ts"
const listener = createCopilotNodeListener({ runtime });

const channels = listener.channels;
if (!channels) throw new Error("Channels were not configured.");

const shutdown = async () => {
  await channels.stop();
  process.exit(0);
};

process.once("SIGTERM", shutdown);
process.once("SIGINT", shutdown);

await channels.ready({ timeoutMs: 30_000 });
const status = channels.status();
if (status.overall !== "online") {
  throw new Error(`Channel not online: ${JSON.stringify(status)}`);
}
```

`ready()` 会观察第一个 `online` 或 `setup_required` 结果；它不会主动发起 Node 或 Express 的激活。在接收托管流量之前请先检查 `status()`。即使托管配置不完整，已配置的直连适配器仍会启动，但渠道会保持 `setup_required`，直到其托管提供方配置完成。后续的掉线与重连可通过 `status()` 观察。

| 状态             | 含义                                                                       |
| ---------------- | -------------------------------------------------------------------------- |
| `connecting`     | 激活正在进行，或惰性挂载尚未启动渠道。                                     |
| `online`         | 托管会话健康，可以接收投递邀请。                                           |
| `setup_required` | 运行时声明已存在，但提供方配置未完成。                                     |
| `reconnecting`   | 网关连接已断开，正在重试。                                                 |
| `error`          | 激活或有界重连失败。                                                       |
| `stopped`        | 监听器已被拆除。                                                           |
