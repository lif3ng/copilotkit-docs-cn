---
title: "Transcripts"
description: "以稳定的用户身份为键，追加、查询、保留与删除应用自有的会话记录。"
---

`Transcripts` 在渠道的 `StateStore` 上存储一条可选的、由 SDK 管理的记录。需配置顶层的 `identifyUser` 与 `store.transcripts`。

## 配置

```ts
const channel = createChannel({
  name: "support-slack",
  identifyUser: ({ actor }) => accounts.resolveApplicationUser(actor.id),
  agent: makeAgent,
  store: {
    adapter: durableStateStore,
    transcripts: {
      retention: "30d",
      maxPerUser: 500,
    },
  },
});
```

`retention` 接受毫秒数或时长字符串。条目存储在 `list` 部分上，因此该部分必须持久化才能支撑生产环境的会话记录。

## append

```ts
await channel.transcripts.append(
  thread,
  {
    role: "assistant",
    text: "The incident owner is Payments.",
  },
  { userId: "usr_123" },
);
```

当 `userId` 为 `null` 时，追加会静默地不执行任何操作。

## list

```ts
const entries = await channel.transcripts.list({
  userId: "usr_123",
  limit: 20,
  roles: ["user", "assistant"],
});
```

条目按最旧在前排列，可按平台、`threadId` 或角色过滤。在托管渠道上，`platform` 是原生提供方（`"slack"` 或 `"teams"`）。请使用稳定的应用 `userId` 在提供方之间携带上下文，只有当你只想要某一个提供方的条目时才按平台过滤。

## delete

```ts
const { deleted } = await channel.transcripts.delete({
  userId: "usr_123",
});
```

这只会删除由 SDK 管理的会话记录。它不会删除提供方历史或单独的 Intelligence 记录。

## 自动桥接

`thread.runAgent({ transcript: true })` 会注入既有条目、追加当前用户轮次、运行智能体，并追加其响应。不要手动追加这些相同的轮次。

`channel.transcripts` 在运行时启动渠道之后可用。参见[历史与会话记录](/slack/history-and-transcripts)。
