`@copilotkit/channels` 支持两种提供方连接模型：

| 模型 | Channel 声明 | 提供方连接 | 可用提供方 |
| -------------------- | -------------------------------------------------------- | ----------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| 云托管 Intelligence | `createChannel({ name, identifyUser, agent })`           | CopilotKit Intelligence 存储提供方凭据，并掌管入站与出站流量 | Slack 与 Microsoft Teams                               |
| 直连适配器 | `createChannel({ name, adapters, identifyUser, agent })` | 你的 Channels 进程存储提供方凭据，并掌管提供方套接字或 webhook | Slack、Microsoft Teams、Discord 与 WhatsApp           |

对 Discord 与 WhatsApp 的云托管 Intelligence 支持即将推出。它们的直连适配器已随 `@copilotkit/channels` 发布。

<Callout type="info" title="直连不等于独立运行">
  直连适配器将提供方连接移入你的进程。`CopilotRuntime` 仍掌管 Channel 生命周期，并通过 Intelligence 连接工作。直连的提供方流量不会经过托管 Realtime 网关及其规范的投递、重试与持久化层，因此传输可靠性由你的进程负责。不存在公开的 `channel.start()` 方法。
</Callout>

## 声明直连适配器

安装该总包（umbrella package）及其经过测试的运行时版本：

<ChannelsInstall />

该包与所有提供方子路径均为仅 ESM 的公开导出。请使用 `import`；不支持 CommonJS 的 `require()`。

从该包的提供方子路径导入适配器：

```ts title="channel.ts"
import { createChannel } from "@copilotkit/channels";
import { slack } from "@copilotkit/channels/slack";
import { makeAgent } from "./agent.js";

function required(name: string): string {
  const value = process.env[name];
  if (!value) throw new Error(`Missing required environment variable: ${name}`);
  return value;
}

export const channel = createChannel({
  name: "support-direct",
  identifyUser: "platform",
  adapters: [
    slack({
      botToken: required("SLACK_BOT_TOKEN"),
      appToken: required("SLACK_APP_TOKEN"),
      replyContinuation: {
        maxMessages: 8,
      },
    }),
  ],
  agent: makeAgent,
});

channel.onMessage(async ({ thread }) => {
  await thread.runAgent();
});
```

将此 Channel 传给 `new CopilotRuntime({ channels: [channel], ... })`，并通过运行时的 Channels 控制启动它，与托管快速开始中的做法一致。挂接到 Intelligence 的 Slack 与 Teams 连接会选择托管提供方；`createChannel` 上没有 `provider` 选项。多个直连适配器可以共存于同一个 Channel，并各自保留自己的提供方流量。

一个直连 Channel 可以包含多个直连适配器。其 `name` 仍必须存在，且在该 `CopilotRuntime` 声明的各 Channel 中保持唯一。

## 提供方入口

### Slack

```ts
import {
  slack,
  SlackAdapter,
  type SlackAdapterOptions,
} from "@copilotkit/channels/slack";
```

`SlackAdapterOptions` 要求提供 `botToken` 与 `appToken`。Socket Mode 默认开启。HTTP 模式需要设置 `socketMode: false` 并提供 `signingSecret`。对于长回复，`replyContinuation` 接受 `messageByteLimit`、`maxMessages` 与 `truncationMarker`；默认值为 11,000 个 UTF-8 字节和 20 条消息，并在截断时显示可见的截断提示。

Slack 入口还导出其监听器、渲染器、编解码器、流式辅助工具、会话存储、内置上下文与工具、文件辅助工具以及 `SLACK_LIMITS`。更底层的渲染与编解码入口可从 `@copilotkit/channels/slack/render` 与 `@copilotkit/channels/slack/codec` 获取。

### Microsoft Teams

```ts
import {
  teams,
  TeamsAdapter,
  type TeamsAdapterOptions,
} from "@copilotkit/channels/teams";
```

`TeamsAdapterOptions` 接受 `clientId`、`clientSecret`、`tenantId`、`port`、`host` 与 `allowedServiceUrls`。对接真实 Teams 时必须提供 `clientId` 与 `clientSecret`；多租户部署可以省略 `tenantId`。这些值会回退到小写的 `clientId`、`clientSecret` 与 `tenantId` 环境变量。只有在使用 Microsoft 365 Agents Playground 进行匿名本地开发时，才可以同时省略这三者。适配器默认在端口 `3978` 上服务 `POST /api/messages`。

配置了 `clientId` 后，发往 `POST /api/messages` 的每个请求都必须携带该应用的有效 Bot Framework 或 Azure AD 令牌，且来自为其配置的签发方，否则将以 `401` 拒绝。activity 的 `serviceUrl` 必须是 Microsoft 连接器主机（Teams 商业版、GCC、GCC High、DoD 与 21Vianet 世纪互联，`*.botframework.com`、`*.botframework.azure.us`），并且当令牌带有 `serviceurl` 声明时与之匹配，否则将以 `403` 拒绝；机器人会向该 URL 发送其应用令牌。可使用 `allowedServiceUrls` 添加其他连接器来源，例如供 Bot Framework Emulator 使用的 `http://localhost:<port>`。仅环回主机接受纯 `http`。Bot Framework 令牌的签名密钥还必须已为该 activity 的 `channelId` 背书。

未配置 `clientId` 时，该端点不做身份验证，因此只监听 `127.0.0.1`。若把 `host` 设为 `0.0.0.0` 之类的非环回地址，就会把这个未经验证的端点暴露到网络中。当配置的 `clientId` 与 `Connections__*` 环境设置冲突，或仅设置了 Bot Framework SDK 的 `MicrosoftAppId` / `MicrosoftAppPassword` 变量时，启动会失败；请改用 `clientId` / `clientSecret` / `tenantId` 或 `Connections__<id>__Settings__*`。

Teams 入口还导出其服务器、Adaptive Card 渲染器、会话存储、消息流、交互辅助工具、文件辅助工具以及 `TEAMS_LIMITS`。渲染器导出也可从 `@copilotkit/channels/teams/render` 获取。

### Discord

```ts
import {
  discord,
  DiscordAdapter,
  type DiscordAdapterOptions,
} from "@copilotkit/channels/discord";
```

`DiscordAdapterOptions` 要求提供 `botToken` 与 `appId`；设置 `guildId` 可立即在某个开发服务器（guild）中注册斜杠命令。该入口还导出其监听器、渲染器、命令注册、会话存储、流式辅助工具、内置上下文与工具、文件辅助工具以及 `DISCORD_LIMITS`。

在 Discord Developer Portal 中为机器人启用特权 **Message Content Intent** 与 **Server Members Intent**。适配器会在每次连接时请求 `MessageContent` 与 `GuildMembers`。

### WhatsApp

```ts
import {
  whatsapp,
  WhatsAppAdapter,
  type WhatsAppAdapterOptions,
} from "@copilotkit/channels/whatsapp";
```

`WhatsAppAdapterOptions` 要求提供 `accessToken`、`phoneNumberId`、`appSecret` 与 `verifyToken`。webhook 服务器默认使用端口 `3000` 与路径 `/webhook`。该入口还导出其客户端、渲染器、会话与历史存储、内置上下文与工具、文件辅助工具以及 `WA_LIMITS`。

## 能力边界

直连与托管适配器的能力并不完全相同。例如，直连 Slack 适配器支持模态框（modal）、表情回应、增量流式与临时消息。托管 Slack 接受流式 API，但会先缓冲整个流再一次性发布，而不是增量更新；其余三项能力它均不支持。当你自己持有适配器实例时，可查看该直连适配器实例的只读 `capabilities` 属性。返回能力结果的 Thread 方法也可能返回 `{ ok: false }`；请处理该结果，不要以为提供方名称就必然保证某种行为。

提供方指南记录了托管契约与各提供方的发布状态。当你的部署有意自行掌管提供方凭据、套接字、webhook 与提供方专属操作时，请使用本页。
