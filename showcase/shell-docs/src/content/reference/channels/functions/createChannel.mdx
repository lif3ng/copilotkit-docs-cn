---
title: createChannel
description: 声明一个托管 Slack 或 Teams Channel，及其智能体、处理器、工具、组件与 SDK 持久化配置。
---

`createChannel(options)` 会创建与提供方无关的 Channel，并注册到 `CopilotRuntime({ channels })` 中。

## 签名

```ts
function createChannel<TStateSchema>(
  options: CreateChannelOptions<TStateSchema>,
): Channel<ThreadStateOf<TStateSchema>>;
```

从聚合包中导入它：

```ts
import { createChannel } from "@copilotkit/channels";
```

## 托管示例

```ts title="channel.ts"
const channel = createChannel({
  name: "support",
  identifyUser: "platform",
  agent: makeAgent,
  tools: [getIncident],
  context: [
    {
      description: "Response style",
      value: "Put the next action first.",
    },
  ],
});

channel.onMessage(async ({ thread, message }) => {
  await thread.runAgent({ prompt: message.text });
});
```

Channel 名称即项目内唯一的 Intelligence Code。一个托管运行时可以为该 Channel 同时声明 Slack 和 Teams；Intelligence 会把每条准备投递的消息只路由回其来源提供方。

不通过 `runAgent()` 而直接回复的处理器可以省略 `agent`。

## 选项

| 选项             | 类型                                           | 说明                                                                                                                                    |
| ---------------- | ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `name`           | `string`                                       | 托管投递必填。必须与项目内唯一的 Intelligence Code 一致。                                                      |
| `identifyUser`   | `"platform" \| ChannelIdentifyUser`            | 必填。将每个提供方 actor 映射到应用用户或 `null`。参见身份与内存指南中的 [Slack](/slack/identity-and-memory) 或 [Teams](/teams/identity-and-memory)。 |
| `showToolStatus` | `boolean`                                      | 托管 Slack 默认隐藏工具调用进度。设为 `true` 可显示进度；无论哪种设置，工具历史在 Intelligence 中始终可见。 |
| `replyContinuation` | `ReplyContinuationOptions`                  | 托管 Slack 的续写限制。直连 Slack 则在 `slack()` 上配置同一选项。                                             |
| `agent`          | `AbstractAgent \| (threadId) => AbstractAgent` | 调用 `thread.runAgent()` 时必填。不会从 `runtime.agents` 继承。建议使用工厂函数。                                 |
| `sanitizeAgentEvents` | `boolean`                                  | 默认为 `true`。在严格的 HTTP 流校验之前，修复 AG-UI 已知的可空 parent-message 字段。                       |
| `tools`          | `ChannelTool[]`                                | Channel 级别的类型化工具。                                                                                                           |
| `context`        | `ContextEntry[]`                               | 添加到每次智能体运行中的稳定上下文。                                                                                             |
| `components`     | `ChannelComponent[]`                           | 用于重建回调的具名 JSX 组件。                                                                                  |
| `commands`       | `ChannelCommand[]`                             | 从提供方入口路由过来的已声明命令。                                                                                      |
| `store`          | `StoreConfig`                                  | 状态、持久化、回合并发（默认 `parallel`）、会话记录与去重。                                                   |
| `adapters`       | `PlatformAdapter[]`                            | 开发者自有的直连传输层，可与云端托管的 Intelligence 适配器共存。                                            |

托管运行时会校验 `name`：必须为小写 kebab-case，长度 3–64 个字符，不等于 `channels`，且在 Runtime 内唯一。

处理器会同时收到必填的提供方 `actor` 和可为空的应用 `user`。SDK 会为每个传入事件解析一次这一对对象。两者都是不可变的快照。SDK 不会通过邮箱、姓名或句柄关联账号。

回调输出格式不当时会以 `channel_identity_invalid` 拒绝。回调抛出异常时会以 `channel_identity_failed` 拒绝，且绝不会回退到标准平台策略。

### 调优较长的 Slack 回复

当 Slack 回复超过单条消息的软字节上限时，会续写为多条消息。默认值为每条消息 11,000 个 UTF-8 字节、每条回复最多 20 条消息，超出后会附加一条可见的英文截断提示。大多数 Channel 应保留这些默认值；当产品需要更紧的上限或本地化的提示时再自定义：

| 字段 | 行为 |
| ----- | -------- |
| `messageByteLimit` | 续写为下一条 Slack 消息之前的软 UTF-8 字节上限。 |
| `maxMessages` | 一条回复在被截断前最多占用的消息数。 |
| `truncationMarker` | 达到消息上限时附加的可见提示。 |

```ts
const channel = createChannel({
  name: "support",
  identifyUser: "platform",
  agent: makeAgent,
  replyContinuation: {
    maxMessages: 8,
    truncationMarker: "\n\n_This reply was shortened for Slack._",
  },
});
```

### 清理 HTTP 智能体事件

`sanitizeAgentEvents` 默认为 `true`。它会修复某些 LangGraph 工具调用流与中断流中发出的可空 `parentMessageId`，从而避免严格的客户端校验中止整个运行。该清理器只作用于通过 HTTP 流式传输的智能体，且只针对这个已知的畸形字段。设为 `false` 则原样转发事件，让畸形事件在校验时失败。

每次运行都会使用 `agent.clone()` 的一个独立结果，包括 `agent` 是工厂函数的情况。如果自定义智能体的子类字段中保存了配置，应重写 `clone()` 以保留这些配置，同时不共享可变的单次运行状态。Channels 0.6.1 会在可枚举字段被丢弃时发出警告；仅该警告不会再拒绝这一回合。

## 注册方法

返回的 Channel 支持：

- `onMessage` 和 `onMention`
- `onWelcome`
- `onInterrupt`
- `onInteraction`
- `onCommand`
- `onReaction`
- `onThreadStarted`
- `onModalSubmit` 和 `onModalClose`，用于支持模态框的适配器
- `tool`，用于在 Channel 启动前添加工具

处理器签名参见 [`Channel`](/reference/channels/classes/Channel)，持久化配置参见 [`StoreConfig`](/reference/channels/types/StoreConfig)。
