## 概览

`useInterrupt` 处理智能体中断，并以用户输入恢复执行。它支持 **AG-UI 标准中断流**——`RUN_FINISHED` 携带 `outcome.type === "interrupt"` 与一个 `interrupts` 数组——以及旧版的自定义事件流（`on_interrupt`）。对于标准中断，你的 `render`/`handler` 会收到 `interrupt`（主中断）与 `interrupts`（全部未决中断的集合）；调用 `resolve(payload)` 即可恢复，调用 `cancel()` 则取消。

默认情况下，中断 UI 会自动渲染在 `<CopilotChat>` 内部。如果你设置了 `renderInChat: false`，该 Hook 会返回元素，由你手动放置。

`event.value` 的类型是 `any`，因为中断负载的结构取决于你的智能体。请按需在你的回调（如 `handler`、`enabled`、`render`）中做类型收窄。

## 签名

```tsx
import { useInterrupt } from "@copilotkit/react-core/v2";

function useInterrupt<
  TResult = never,
  TRenderInChat extends boolean | undefined = undefined,
>(
  config: UseInterruptConfig<any, TResult, TRenderInChat>,
): TRenderInChat extends false
  ? React.ReactElement | null
  : TRenderInChat extends true | undefined
    ? void
    : React.ReactElement | null | void;
```

## 参数

<PropertyReference name="config" type="UseInterruptConfig<any, TResult, TRenderInChat>" required>
  中断配置。

  <PropertyReference name="render" type="(props: InterruptRenderProps<any, TResult | null>) => React.ReactElement" required>
    中断 UI 的渲染回调。当有中断可用时被调用。该回调接收：
    - `event` —— 中断事件（`{ name, value }`）。`value` 为 `any`；请按需在回调中做类型收窄。
    - `interrupt` —— 主标准 `Interrupt`（`{ id, reason, message?, toolCallId?, responseSchema?, expiresAt?, metadata? }`），旧版中断时为 `null`。
    - `interrupts` —— 全部未决的标准中断（旧版中断时为空数组）。
    - `result` —— 由 `handler` 返回类型推断而来，或为 `null`
    - `resolve(payload?, interruptId?)` —— 对于标准中断，为目标中断（默认为主中断）记录 `{ status: "resolved", payload }`，并在所有未决中断都被处理后提交恢复。对于旧版中断，映射为 `command.resume = payload`。
    - `cancel(interruptId?)` —— 对于标准中断，为目标中断记录 `{ status: "cancelled" }`，并在所有未决中断都被处理后提交。对于旧版中断，直接搁置该待处理中断而不恢复。
  </PropertyReference>

<PropertyReference
  name="handler"
  type="(props: InterruptHandlerProps) => TResult | PromiseLike<TResult>"
>
  可选的预处理回调。在渲染之前运行，可以返回同步或异步数据，并在 `render` 中以 `result` 暴露。`TResult` 会从处理器的返回类型自动推断。如果处理器抛出异常或被拒绝，`result` 为 `null`。
</PropertyReference>

<PropertyReference name="enabled" type="(event: InterruptEvent) => boolean">
  可选的过滤器。返回 `false` 可让该 Hook 实例忽略匹配的中断。
</PropertyReference>

<PropertyReference name="agentId" type="string">
  可选的智能体 id。默认为当前配置的聊天智能体。
</PropertyReference>

  <PropertyReference name="renderInChat" type="boolean" default="true">
    控制 UI 渲染的位置：
    - `true`（默认）：把中断 UI 发布到 `<CopilotChat>` 中
    - `false`：由该 Hook 返回中断元素，供你手动放置
  </PropertyReference>
</PropertyReference>

## 返回值

<PropertyReference name="element" type="Conditional by renderInChat">
  返回类型由 `renderInChat` 推断：
  - `renderInChat: false` -> `React.ReactElement | null`
  - `renderInChat: true` 或省略 -> `void`
  - 动态布尔值 -> `React.ReactElement | null | void`
</PropertyReference>

## 用法

### 聊天内中断 UI（默认）

```tsx
function ApprovalInterrupt() {
  useInterrupt({
    render: ({ event, resolve }) => (
      <div className="p-3 border rounded">
        <p>{event.value.question}</p>
        <div className="mt-2 flex gap-2">
          <button onClick={() => resolve({ approved: true })}>Approve</button>
          <button onClick={() => resolve({ approved: false })}>Reject</button>
        </div>
      </div>
    ),
  });

  return null;
}
```

### 手动放置与异步预处理

```tsx
function SidePanelInterrupt() {
  const element = useInterrupt({
    renderInChat: false,
    enabled: (event) => event.value.startsWith("approval:"),
    handler: async ({ event }) => ({ label: event.value.toUpperCase() }),
    render: ({ event, result, resolve }) => (
      <aside className="rounded border p-3">
        <div className="font-medium">{result?.label ?? ""}</div>
        <div className="mt-2">{event.value}</div>
        <button className="mt-2" onClick={() => resolve({ accepted: true })}>
          Continue
        </button>
      </aside>
    ),
  });

  return <>{element}</>;
}
```

### AG-UI 标准中断（批准/取消）

```tsx
function ApprovalInterrupt() {
  useInterrupt({
    render: ({ interrupt, resolve, cancel }) => (
      <div className="p-3 border rounded">
        <p>{interrupt?.message ?? "Approve this action?"}</p>
        <div className="mt-2 flex gap-2">
          <button onClick={() => resolve({ approved: true })}>Approve</button>
          <button onClick={() => cancel()}>Cancel</button>
        </div>
      </div>
    ),
  });
  return null;
}
```

## 行为

- 标准中断从 `RUN_FINISHED`（`outcome.type === "interrupt"`）检测；旧版中断从 `on_interrupt` 自定义事件检测。如果同一次运行中两者同时出现，标准中断优先。
- `resolve`/`cancel` 会为每个未决中断累积一个响应；待所有未决中断都被处理后，恢复运行才会开始。标准恢复在同一线程上使用新的 `runId`，并通过 `resume[].interruptId` 标识待处理的中断。
- 已过期的中断（超过 `expiresAt`）不会被恢复——该 Hook 会记录一条错误并清除待处理状态。
- 中断 UI 在运行收尾时呈现。
- 开始新的运行会清除待处理的中断状态。
- `event.value` 为 `any`——请按需在你的回调中做类型收窄。
- `render.result` 由 `handler` 的返回类型推断而来，类型始终为 `TResult | null`。
- 如果 `handler` 抛出异常或被拒绝，`result` 会被置为 `null`。
