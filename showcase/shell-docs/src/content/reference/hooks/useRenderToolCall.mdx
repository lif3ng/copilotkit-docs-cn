## 概览

<Callout type="warn" title="同名，但与 v1 的 API 不同">
  v2 的 `useRenderToolCall`（即本页，来自 `@copilotkit/react-core/v2`）是一个**无参数 Hook**，它*返回*一个用于消费工具调用的渲染器函数。它**不是** v1 的 [`useRenderToolCall`](/reference/v1/hooks/useRenderToolCall)——后者接收 `{ name, parameters, render }` 配置对象来*注册*渲染器。在 v2 中为既有后端工具注册渲染器请使用 [`useRenderTool`](/reference/hooks/useRenderTool)。
</Callout>

`useRenderToolCall` 返回一个把工具调用映射为 React 元素的渲染器函数。返回的函数按工具名称查找匹配的渲染配置（优先选择作用于当前 `agentId` 的渲染器，其次是不限定智能体的渲染器，最后在找不到精确匹配时使用通配 `"*"` 渲染器），对 JSON 参数做部分解析，判定当前的 `ToolCallStatus`，并返回相应的 React 元素。当既没有针对具体工具的渲染器、也没有通配渲染器时，它会回退到框架内置的 `DefaultToolCallRenderer`，因此返回的元素实际上始终不为 `null`（签名保留 `ReactElement | null` 只是为了类型兼容）。

该 Hook 主要由聊天 UI 组件使用，为工具调用展示可视化反馈。在大多数应用中你不会直接调用它；你只需通过 `useRenderTool` 为既有后端工具注册渲染组件，聊天组件会在内部使用 `useRenderToolCall` 来解析它们。

## 签名

```tsx
import { useRenderToolCall } from "@copilotkit/react-core/v2";

function useRenderToolCall(): (
  props: UseRenderToolCallProps,
) => React.ReactElement | null;
```

## 返回值

<PropertyReference name="renderer" type="(props: UseRenderToolCallProps) => React.ReactElement | null">
  一个接收工具调用 props 并返回 React 元素或 `null` 的函数。

  <PropertyReference name="props" type="UseRenderToolCallProps" required>
    描述要渲染的工具调用的输入对象。

    <PropertyReference name="toolCall" type="ToolCall" required>
      工具调用对象。工具名称从 `toolCall.function.name` 读取，JSON 编码的参数从 `toolCall.function.arguments` 读取。
    </PropertyReference>

    <PropertyReference name="toolMessage" type="ToolMessage">
      工具结果消息（如果可用）。它存在即表示工具调用已完成，并包含结果字符串。
    </PropertyReference>

  </PropertyReference>
</PropertyReference>

## 状态判定

渲染器根据输入确定 `ToolCallStatus`：

| 条件                                                                | 状态                        | `result`                                |
| ------------------------------------------------------------------- | --------------------------- | --------------------------------------- |
| 没有 `toolMessage`，且工具调用 id **不在**执行集合中                 | `ToolCallStatus.InProgress` | `undefined`                             |
| 没有 `toolMessage`，但工具调用 id **在**提供方执行集合中             | `ToolCallStatus.Executing`  | `undefined`                             |
| 存在 `toolMessage`                                                  | `ToolCallStatus.Complete`   | 工具消息中的结果字符串                   |

## ToolCallStatus

`ToolCallStatus` 枚举从 `@copilotkit/react-core/v2` 导出：

| 值                          | 说明                                                 |
| --------------------------- | ---------------------------------------------------- |
| `ToolCallStatus.InProgress` | 工具调用的参数仍在流式传输中。                        |
| `ToolCallStatus.Executing`  | 参数已完全解析；工具正在执行。                        |
| `ToolCallStatus.Complete`   | 执行已结束，结果可用。                                |

## 用法

### 在自定义聊天组件中使用渲染器

```tsx
function CustomChatMessage({ message }) {
  const renderToolCall = useRenderToolCall();

  if (message.type === "tool_call") {
    // Always returns an element: your registered renderer, the wildcard
    // ("*") renderer, or the framework's built-in DefaultToolCallRenderer.
    const element = renderToolCall({
      toolCall: message.toolCall,
      toolMessage: message.toolMessage,
    });

    return <div className="tool-call-container">{element}</div>;
  }

  return <div>{message.content}</div>;
}
```

### 通过 useRenderTool 注册渲染器

既有后端工具的工具调用渲染器通过 `useRenderTool` 或直接通过提供方的 `renderToolCalls` prop 注册。`useRenderToolCall` Hook 会在渲染时解析这些注册。

```tsx
import { useRenderTool } from "@copilotkit/react-core/v2";
import { z } from "zod";

function App() {
  useRenderTool(
    {
      name: "searchDatabase",
      parameters: z.object({
        query: z.string().describe("Search query"),
      }),
      render: ({ parameters, status, result }) => {
        if (status === "inProgress") {
          return <div>Preparing search...</div>;
        }
        if (status === "executing") {
          return <div>Searching for "{parameters.query}"...</div>;
        }
        if (status === "complete" && result) {
          return <div>Search complete: {result}</div>;
        }
        return null;
      },
    },
    [],
  );

  return <ChatInterface />;
}
```

### 通配渲染器

如果找不到精确的名称匹配，该 Hook 会回退到通配 `"*"` 渲染器。这适合为所有未处理的工具调用提供一套通用 UI。

```tsx
function App() {
  return (
    <CopilotKit
      runtimeUrl="/api/copilotkit"
      renderToolCalls={[
        {
          name: "*",
          render: ({ name, args, status, result }) => {
            if (status === ToolCallStatus.InProgress) {
              return (
                <div className="text-gray-500 text-sm">Running {name}...</div>
              );
            }
            if (status === ToolCallStatus.Complete) {
              return (
                <div className="text-green-600 text-sm">{name} completed.</div>
              );
            }
            return null;
          },
        },
      ]}
    >
      <YourApp />
    </CopilotKit>
  );
}
```

## 行为

- **按名称查找并按智能体限定作用域**：渲染器会先在已注册的渲染配置中查找工具名称的精确匹配。当多个配置匹配同一名称时，优先选择作用于当前 `agentId` 的渲染器，其次是不限定智能体的渲染器，再是第一个匹配项。如果不存在精确匹配，则回退到通配（`"*"`）渲染器，最后回退到框架内置的 `DefaultToolCallRenderer`。
- **部分 JSON 解析**：工具调用的 `arguments` 字符串在传给渲染组件之前会先经过 `partialJSONParse` 解析，因此工具调用仍处于 `InProgress` 时，部分流式传入的参数也能增量渲染。
- **状态推断**：状态由 `toolMessage` prop 是否存在以及工具调用 id 是否在提供方的执行集合中来判定。渲染组件始终收到结构一致的 `name`、`toolCallId`、`args`、`status` 与 `result`。
- **未匹配工具的默认渲染器**：如果没有为该工具名称注册渲染器，也不存在通配渲染器，该函数会回退到内置的 `DefaultToolCallRenderer` 而不是返回 `null`，因此未处理的工具调用依然开箱即用地绘制 UI。
- **由聊天组件在内部使用**：内置的 `CopilotChat`、`CopilotPopup` 与 `CopilotSidebar` 组件都使用该 Hook 渲染工具调用。只有构建自定义聊天 UI 时才需要直接调用它。

### 禁用默认工具渲染

由于该 Hook 在没有渲染器匹配时会回退到内置的 `DefaultToolCallRenderer`，工具调用会开箱即用地绘制 UI。要关闭它，请注册一个不产生 UI 的渲染器（空片段，`() => <></>`）。已注册的渲染器优先于默认渲染器，因此不会显示回退 UI。

注册一个通配（`"*"`）渲染器（通过 [`useRenderTool`](/reference/hooks/useRenderTool)）即可为**所有**工具调用禁用默认渲染。通配重载不需要 `parameters` schema，因此无需 Zod。拥有自己具名渲染器的工具仍会正常绘制。

```tsx
function App() {
  // Suppress the built-in DefaultToolCallRenderer for every tool call
  // without its own named renderer.
  useRenderTool({ name: "*", render: () => <></> }, []);

  return <YourApp />;
}
```

#### 针对特定工具

要禁用单个工具的渲染，请以该工具的名称注册一个渲染器。具名渲染器需要 `parameters` schema；如果只想隐藏 UI，传入直通 schema（`z.any()`）即可：

```tsx
import { z } from "zod";

function App() {
  useRenderTool(
    { name: "specificTool", parameters: z.any(), render: () => <></> },
    [],
  );

  return <YourApp />;
}
```

你也可以按条件退出——对某些状态不渲染任何内容，对另一些状态渲染真实 UI（例如在 `InProgress` 时隐藏、在 `Complete` 时显示结果），因为 `render` 函数会收到当前的 `status`。
