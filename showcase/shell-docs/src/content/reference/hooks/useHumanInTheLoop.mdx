## 概览

`useHumanInTheLoop` 注册一个交互式工具，它会暂停智能体的执行，直到用户通过你的自定义 UI 做出响应。与 `useFrontendTool` 不同，它没有 `handler` 函数。该 Hook 提供一个内部状态机（`InProgress` -> `Executing` -> `Complete`），并在工具处于 `Executing` 状态时向渲染组件提供 `respond` 回调。在 `respond` 被传入用户输入调用之前，智能体保持暂停。

该 Hook 构建在 `useFrontendTool` 之上，由内部管理的处理器在 `respond` 被调用时兑现工具调用的 promise。确认对话框、审批流程、表单收集，或任何需要人先提供输入智能体才能继续的场景，都适合使用它。

## 签名

```tsx
import { useHumanInTheLoop } from "@copilotkit/react-core/v2";

function useHumanInTheLoop<T extends Record<string, unknown>>(
  tool: ReactHumanInTheLoop<T>,
  deps?: ReadonlyArray<unknown>,
): void;
```

## 参数

<PropertyReference name="tool" type="ReactHumanInTheLoop<T>" required>
  交互式工具的定义。

<PropertyReference name="name" type="string" required>
  工具的唯一名称。智能体在需要人工输入时会引用这个名称。
</PropertyReference>

<PropertyReference name="description" type="string" required>
  一段自然语言描述，告诉智能体该工具做什么、何时调用（例如“要求用户在删除记录前进行确认”）。
</PropertyReference>

<PropertyReference name="parameters" type="z.ZodSchema" required>
  定义智能体传给工具的参数的 Zod schema。这些参数会被转发给渲染组件，便于你构建感知上下文的 UI。
</PropertyReference>

  <PropertyReference name="render" type="React.ComponentType<RenderProps>" required>
    驱动人机交互的 React 组件。组件接收的 props 随当前状态而不同：

    **当 `status` 为 `ToolCallStatus.InProgress` 时：**
    - `args: Partial<T>` —— 流式传输中的部分参数
    - `respond: undefined` —— 尚不可用
    - `result: undefined`

    **当 `status` 为 `ToolCallStatus.Executing` 时：**
    - `args: T` —— 已完全解析的参数
    - `respond: (result: unknown) => Promise<void>` —— 调用它把用户的响应发回给智能体并恢复执行
    - `result: undefined`

    **当 `status` 为 `ToolCallStatus.Complete` 时：**
    - `args: T` —— 原始参数
    - `respond: undefined` —— 已不可用
    - `result: string` —— 序列化后的结果

  </PropertyReference>

  <PropertyReference name="available" type='"enabled" | "disabled" | "remote"' default='"enabled"'>
    控制工具的可用性。设为 `"disabled"` 可临时阻止智能体通过该工具请求人工输入。
  </PropertyReference>
</PropertyReference>

<PropertyReference name="deps" type="ReadonlyArray<unknown>">
  可选的依赖数组。提供后，只要数组中的值发生变化，工具注册就会刷新。

  `deps` 对普通数据（字符串、数字、布尔值、`null`、日期以及由它们组成的普通对象和数组）按值比较，因此 `[{ status }]` 这样的内联字面量只在其内容变化时才会重新注册。与之前一样，函数永远不会被视为已变化，所以请把会变化的回调保存在 ref 中。类实例和其他对象按引用（identity）比较，因此传入来自 `useAgent` 的 `agent` 这类循环引用的值是安全的。增删数组条目也算变化。
</PropertyReference>

## 用法

### 确认对话框

智能体请用户确认某个破坏性操作的常见模式。

```tsx
function DeleteConfirmation() {
  useHumanInTheLoop(
    {
      name: "confirmDeletion",
      description: "Ask the user to confirm before deleting items",
      parameters: z.object({
        itemName: z.string().describe("Name of the item to delete"),
        itemCount: z.number().describe("Number of items to delete"),
      }),
      render: ({ args, status, respond, result }) => {
        if (status === ToolCallStatus.InProgress) {
          return (
            <div className="p-4 text-gray-500">Preparing confirmation...</div>
          );
        }

        if (status === ToolCallStatus.Executing && respond) {
          return (
            <div className="p-4 border rounded">
              <p>
                Are you sure you want to delete {args.itemCount} {args.itemName}
                (s)?
              </p>
              <div className="flex gap-2 mt-4">
                <button
                  onClick={() => respond({ confirmed: true })}
                  className="bg-red-500 text-white px-4 py-2 rounded"
                >
                  Delete
                </button>
                <button
                  onClick={() => respond({ confirmed: false })}
                  className="bg-gray-300 px-4 py-2 rounded"
                >
                  Cancel
                </button>
              </div>
            </div>
          );
        }

        if (status === ToolCallStatus.Complete && result) {
          const parsed = JSON.parse(result);
          return (
            <div className="p-2 text-sm text-gray-600">
              {parsed.confirmed ? "Items deleted." : "Deletion cancelled."}
            </div>
          );
        }

        return null;
      },
    },
    [],
  );

  return null;
}
```

### 表单输入收集

在智能体继续之前，从用户处收集结构化输入。

```tsx
function ShippingAddressForm() {
  useHumanInTheLoop(
    {
      name: "collectShippingAddress",
      description:
        "Collect shipping address from the user before placing an order",
      parameters: z.object({
        orderSummary: z
          .string()
          .describe("A summary of the order being placed"),
      }),
      render: ({ args, status, respond }) => {
        const [address, setAddress] = useState({
          street: "",
          city: "",
          zip: "",
        });

        if (status === ToolCallStatus.Executing && respond) {
          return (
            <div className="p-4 border rounded space-y-3">
              <p className="font-medium">Order: {args.orderSummary}</p>
              <p>Please enter your shipping address:</p>
              <input
                placeholder="Street address"
                value={address.street}
                onChange={(e) =>
                  setAddress({ ...address, street: e.target.value })
                }
                className="w-full border p-2 rounded"
              />
              <input
                placeholder="City"
                value={address.city}
                onChange={(e) =>
                  setAddress({ ...address, city: e.target.value })
                }
                className="w-full border p-2 rounded"
              />
              <input
                placeholder="ZIP code"
                value={address.zip}
                onChange={(e) =>
                  setAddress({ ...address, zip: e.target.value })
                }
                className="w-full border p-2 rounded"
              />
              <button
                onClick={() => respond(address)}
                className="bg-blue-500 text-white px-4 py-2 rounded"
              >
                Submit Address
              </button>
            </div>
          );
        }

        if (status === ToolCallStatus.Complete) {
          return (
            <div className="p-2 text-green-600">
              Shipping address submitted.
            </div>
          );
        }

        return null;
      },
    },
    [],
  );

  return null;
}
```

### 带上下文的审批工作流

```tsx
function ExpenseApproval() {
  useHumanInTheLoop(
    {
      name: "approveExpense",
      description: "Request manager approval for an expense report",
      parameters: z.object({
        employeeName: z.string().describe("Name of the employee"),
        amount: z.number().describe("Expense amount in dollars"),
        category: z.string().describe("Expense category"),
        description: z.string().describe("Description of the expense"),
      }),
      render: ({ args, status, respond, result }) => {
        if (status === ToolCallStatus.Executing && respond) {
          return (
            <div className="p-4 border rounded">
              <h3 className="font-bold">Expense Approval Required</h3>
              <div className="mt-2 space-y-1 text-sm">
                <p>Employee: {args.employeeName}</p>
                <p>Amount: ${args.amount.toFixed(2)}</p>
                <p>Category: {args.category}</p>
                <p>Description: {args.description}</p>
              </div>
              <div className="flex gap-2 mt-4">
                <button
                  onClick={() => respond({ approved: true })}
                  className="bg-green-500 text-white px-4 py-2 rounded"
                >
                  Approve
                </button>
                <button
                  onClick={() =>
                    respond({ approved: false, reason: "Needs more detail" })
                  }
                  className="bg-red-500 text-white px-4 py-2 rounded"
                >
                  Reject
                </button>
              </div>
            </div>
          );
        }

        if (status === ToolCallStatus.Complete && result) {
          const parsed = JSON.parse(result);
          return (
            <div
              className={`p-2 text-sm ${parsed.approved ? "text-green-600" : "text-red-600"}`}
            >
              {parsed.approved
                ? "Expense approved."
                : `Expense rejected: ${parsed.reason}`}
            </div>
          );
        }

        return null;
      },
    },
    [],
  );

  return null;
}
```

## 行为

- **阻塞智能体执行**：该工具被调用时智能体会暂停，等待 `respond` 回调被调用后才继续。
- **内部状态机**：该 Hook 管理三个状态——`InProgress`（参数流式传入中）、`Executing`（等待用户响应）与 `Complete`（用户已响应）。你的渲染组件会收到与各状态相匹配的 props。
- **单次响应**：每次工具调用中 `respond` 回调只应调用一次。调用它会以提供的值兑现工具调用的 promise。
- **构建于 `useFrontendTool` 之上**：在底层，该 Hook 用内部生成的处理器包装 `useFrontendTool`，因此相同的生命周期行为（挂载/卸载注册、重名警告）全部适用。
- **挂载/卸载生命周期**：工具及其渲染组件在挂载时注册，在卸载时移除。
- **无返回值**：该 Hook 返回 `void`。

## ToolCallStatus

`ToolCallStatus` 枚举从 `@copilotkit/react-core` 导出，定义了工具执行的三个阶段：

| 值                          | 说明                                                                                        |
| --------------------------- | ------------------------------------------------------------------------------------------- |
| `ToolCallStatus.InProgress` | 参数正从智能体流式传输而来。工具尚未开始执行。                                              |
| `ToolCallStatus.Executing`  | 参数已完全解析。对 `useHumanInTheLoop` 而言，此时 `respond` 回调可用。                       |
| `ToolCallStatus.Complete`   | 执行已结束。`result` 字符串可用。                                                            |
