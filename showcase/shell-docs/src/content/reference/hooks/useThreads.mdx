## 概览

Intelligence 的 [AG-UI 流](/AG-UI-Streams)提供了这些对话背后的事件历史与送达机制。使用 `useThreads` 管理对话列表，然后将选定的 `threadId` 传给你的聊天界面。你的框架仍保留自己的对话与模型上下文管理。

`useThreads` 是一个 React hook，用于管理 CopilotKit Intelligence 中的会话线程。它会获取指定智能体的线程列表，通过 WebSocket 保持实时同步，并暴露用于重命名、归档和删除线程的变更方法。

线程按最近更新时间倒序排列。提供 `limit` 时，该 hook 支持基于游标的分页。

只有当所连接的运行时声明了兼容的 REST 线程端点时，`useThreads` 才会激活。云托管的 Intelligence 提供用于线程元数据与实时更新的这些端点。自托管的 runner 持久化（如 `AgentRunner`、`SqliteAgentRunner` 或自定义 runner）仍可持久化并回放聊天历史，但不会自动提供受管的 `useThreads` 列表/变更/实时契约。

## 签名

```tsx
import { useThreads } from "@copilotkit/react-core/v2";

function useThreads(input: UseThreadsInput): UseThreadsResult
```

## 参数

<PropertyReference name="input" type="UseThreadsInput">
  该 hook 的配置对象。

  <PropertyReference name="agentId" type="string">
    要列出其线程的智能体 ID。必须与运行时中配置的某个智能体匹配。
  </PropertyReference>

  <PropertyReference name="includeArchived" type="boolean" default="false">
    是否在列表中包含已归档的线程。
  </PropertyReference>

  <PropertyReference name="limit" type="number" default="undefined">
    每页最多获取的线程数。设置后会通过 `fetchMoreThreads()` 与 `hasMoreThreads` 启用基于游标的分页。
  </PropertyReference>
</PropertyReference>

## 返回值

<PropertyReference name="result" type="UseThreadsResult">

  ### 状态

  <PropertyReference name="threads" type="Thread[]">
    当前用户与智能体的线程数组，按最近更新时间倒序排列。每个 `Thread` 包含：
    - `id: string` ——线程唯一标识符
    - `agentId: string` ——该线程所属的智能体
    - `name: string | null` ——线程名称（首次运行时由 LLM 自动生成，或通过 `renameThread` 手动设置）
    - `archived: boolean` ——该线程是否已归档
    - `createdAt: string` ——ISO 8601 时间戳
    - `updatedAt: string` ——ISO 8601 时间戳
    - `lastRunAt?: string` ——该线程最近一次运行的 ISO 8601 时间戳。仅当线程至少运行过一次时才存在。适合用来展示与 `updatedAt` 区分开的“最后活动”时间（`updatedAt` 在重命名/归档等元数据变更时也会更新）。
  </PropertyReference>

  <PropertyReference name="isLoading" type="boolean">
    正在获取初始线程列表时为 `true`。
  </PropertyReference>

  <PropertyReference name="error" type="Error | null">
    获取或变更线程时产生的最近一次错误；若尚未发生错误则为 `null`。
  </PropertyReference>

  <PropertyReference name="hasMoreThreads" type="boolean">
    当前页之外还有更多线程时为 `true`。仅在设置了 `limit` 时有意义。
  </PropertyReference>

  <PropertyReference name="isFetchingMoreThreads" type="boolean">
    正在获取更多线程时为 `true`。
  </PropertyReference>

  ### 方法

  <PropertyReference name="fetchMoreThreads" type="() => void">
    获取下一页线程。若 `hasMoreThreads` 为 `false` 或已有获取正在进行，则为空操作。
  </PropertyReference>

  <PropertyReference name="renameThread" type="(threadId: string, name: string) => Promise<void>">
    重命名线程。服务器确认操作后该 Promise 即 resolve，失败时 reject 并抛出 `Error`。
  </PropertyReference>

  <PropertyReference name="archiveThread" type="(threadId: string) => Promise<void>">
    软删除线程。线程仍保留在数据库中且 `archived: true`，但除非 `includeArchived` 为 `true`，否则不会出现在列表中。已归档线程可通过 `unarchived` 平台事件恢复。服务器确认后 Promise resolve，失败时 reject 并抛出 `Error`。没有内置确认对话框——如有需要请自行实现。
  </PropertyReference>

  <PropertyReference name="deleteThread" type="(threadId: string) => Promise<void>">
    永久且不可逆地删除线程。线程记录将从数据库中彻底移除。服务器确认后 Promise resolve，失败时 reject 并抛出 `Error`。没有内置确认对话框——如有需要请自行实现。
  </PropertyReference>
</PropertyReference>

## 用法

```tsx title="ThreadList.tsx"
import { useThreads } from "@copilotkit/react-core/v2"; // [!code highlight]

function ThreadList() {
  const {
    threads,
    isLoading,
    renameThread,
    archiveThread,
    deleteThread,
  } = useThreads({ agentId: "my-agent" }); // [!code highlight]

  if (isLoading) return <div>Loading threads...</div>;

  return (
    <ul>
      {threads.map((thread) => (
        <li key={thread.id}>
          <span>{thread.name ?? "Untitled"}</span>
          <button onClick={() => renameThread(thread.id, "New name")}>
            Rename
          </button>
          <button onClick={() => archiveThread(thread.id)}>Archive</button>
          <button onClick={() => deleteThread(thread.id)}>Delete</button>
        </li>
      ))}
    </ul>
  );
}
```

## 行为

- 挂载时会获取线程列表并建立实时 WebSocket 订阅。
- 若运行时未声明线程端点，则不会发出 `/threads` 请求，且 `error` 会说明线程端点不可用。
- 来自任何客户端的线程创建、重命名、归档与删除都会立即反映出来，无需轮询。
- 所有变更方法均采用**悲观更新**——UI 只在服务器通过 WebSocket 确认操作后才更新，而不是在发出请求时立即更新。Promise 在确认后 resolve（15 秒超时），失败时 reject。
- `error` 状态会更新为任意操作产生的最近一次错误。
- `threads` 数组始终按 `updatedAt` 降序排列（最近的在前）。
- 新线程会在首次运行后由 LLM **自动命名**（2–5 个词的标题）。可通过运行时上的 `generateThreadNames` 进行配置。
