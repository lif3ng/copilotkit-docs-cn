## 概览

`useThreads` 是一个 Vue 3 组合式函数，用于读取智能体当前的活动线程列表，并从客户端变更该列表。它接受响应式输入：必填的智能体 id、归档过滤、页面大小，以及 `enabled` 标志。当 `enabled` 为 `false` 时，该 hook 会清空其线程存储上下文并完全跳过 `/threads`；未获授权时线程抽屉保持空闲，靠的正是这一机制。

当所连接的运行时提供它所需的线程端点时，`useThreads` 会激活；当运行时明确报告线程列表功能不可用时，它保持空闲。

该 hook 返回规范化后的线程记录，只包含 Vue UI 会用到的字段：`id`、`agentId`、`name`、`archived`、`createdAt`、`updatedAt`，以及可选的 `lastRunAt`。线程按 `lastRunAt`、`updatedAt`、`createdAt` 的顺序排序。

<Callout type="info">
  `error` 包含运行时与配置问题，例如缺少运行时 URL 或线程端点不受支持。`listError` 只报告线程存储中真正的列表与变更失败。
</Callout>

## 签名

```ts
import { useThreads } from "@copilotkit/vue/v2";

function useThreads(input: UseThreadsInput): UseThreadsResult;
```

## 参数

<PropertyReference name="input" type="UseThreadsInput">
  组合式函数的配置对象。

  <PropertyReference name="agentId" type="MaybeRefOrGetter<string>">
    要列出其线程的智能体 ID。必填。
  </PropertyReference>

  <PropertyReference name="includeArchived" type="MaybeRefOrGetter<boolean | undefined>">
    列表中是否包含已归档线程。省略或传入 `false` 可只显示活动线程。
  </PropertyReference>

  <PropertyReference name="limit" type="MaybeRefOrGetter<number | undefined>">
    可选的页面大小。提供后，该 hook 会对线程列表分页，并暴露 `hasMoreThreads` 与 `fetchMoreThreads`。
  </PropertyReference>

  <PropertyReference name="enabled" type="MaybeRefOrGetter<boolean | undefined>" default="true">
    控制该 hook 是否参与线程获取。为 `false` 时，它会清空存储上下文，不发出任何 `/threads` 请求。
  </PropertyReference>
</PropertyReference>

## 返回值

<PropertyReference name="object" type="UseThreadsResult">
  响应式线程状态与线程变更方法。

  <PropertyReference name="threads" type="Ref<Thread[]>">
    当前线程列表，已规范化为 Vue 组件所用的字段。
  </PropertyReference>

  <PropertyReference name="isLoading" type="Ref<boolean>">
    当 hook 正在等待首个可用的线程上下文或加载当前页时为 `true`。
  </PropertyReference>

  <PropertyReference name="error" type="Ref<Error | null>">
    当前错误，包括运行时与配置错误。
  </PropertyReference>

  <PropertyReference name="listError" type="Ref<Error | null>">
    线程存储中最近一次列表或变更错误，不包括运行时与配置错误。
  </PropertyReference>

  <PropertyReference name="fetchMoreError" type="Ref<Error | null>">
    最近一次失败的分页请求的错误，没有则为 `null`。
  </PropertyReference>

  <PropertyReference name="hasMoreThreads" type="Ref<boolean>">
    是否还有更多页。
  </PropertyReference>

  <PropertyReference name="isFetchingMoreThreads" type="Ref<boolean>">
    当前是否有分页请求正在进行。
  </PropertyReference>

  <PropertyReference name="isMutating" type="Ref<boolean>">
    当前是否有重命名、归档、取消归档或删除变更正在进行。
  </PropertyReference>

  <PropertyReference name="fetchMoreThreads" type="() => void">
    请求下一页。没有下一页或已有请求正在进行时为空操作。
  </PropertyReference>

  <PropertyReference name="refetchThreads" type="() => void">
    从服务器重新读取当前页。
  </PropertyReference>

  <PropertyReference name="startNewThread" type="() => void">
    通知线程存储新线程已开始，并清除过期的线程列表错误状态。它本身不会创建或切换当前聊天线程。如需这样做，请使用 `useCopilotChatConfiguration().startNewThread()`。
  </PropertyReference>

  <PropertyReference name="renameThread" type="(threadId: string, name: string) => Promise<void>">
    以乐观更新方式重命名线程。
  </PropertyReference>

  <PropertyReference name="archiveThread" type="(threadId: string) => Promise<void>">
    以乐观更新方式归档线程。
  </PropertyReference>

  <PropertyReference name="unarchiveThread" type="(threadId: string) => Promise<void>">
    以乐观更新方式恢复已归档线程。
  </PropertyReference>

  <PropertyReference name="deleteThread" type="(threadId: string) => Promise<void>">
    以乐观更新方式删除线程，若服务器拒绝则回滚。
  </PropertyReference>
</PropertyReference>

## 用法

### 列出线程

```vue
<script setup lang="ts">
import { computed } from "vue";
import { useThreads } from "@copilotkit/vue/v2";

const { threads, isLoading, listError, refetchThreads } = useThreads({
  agentId: "support-agent",
  includeArchived: true,
  limit: 20,
});

const activeThreads = computed(() =>
  threads.value.filter((thread) => !thread.archived),
);
</script>
```

### 手动分页

```vue
<script setup lang="ts">
import { useThreads } from "@copilotkit/vue/v2";

const { hasMoreThreads, fetchMoreThreads, fetchMoreError } = useThreads({
  agentId: "support-agent",
  limit: 20,
});
</script>
```

## 行为

- 该 hook 对 `agentId`、`includeArchived`、`limit` 与 `enabled` 保持响应式。
- 当缺少运行时 URL 或运行时报告线程端点不受支持时，会设置 `error`，而 `listError` 仍专注于存储自身的失败。
- `enabled: false` 会清空线程存储上下文并跳过 `/threads`；未授权的线程抽屉因此不会发起获取。
- 变更在 core 存储中是乐观更新的。删除请求失败时会回滚。
- `fetchMoreError` 单独跟踪，因此“加载更多”请求失败时可以就地展示错误，而不会丢失已加载的列表。
- 线程按 `lastRunAt`、`updatedAt`、`createdAt` 排序。
