## 概览

`useAgentContext` 用于注册随智能体运行一起发送的响应式上下文数据。该上下文条目会在组合式函数活跃期间持续存在，并在作用域清理时自动移除，因此智能体始终能看到应用状态的最新快照，无需手动清理。

由于参数接受 `MaybeRefOrGetter`，你可以传入普通值、ref、计算属性或 getter 函数。任何响应式源发生变化时，已注册的上下文都会自动更新。这让你能把任何可序列化的应用状态（用户偏好、选中项、计算值等）作为上下文暴露出来，供智能体在生成响应或做决策时引用。

<Callout type="info">
  `useAgentContext` 必须在能访问 `CopilotKitProvider` 所提供 CopilotKit 实例的组件中调用。与所有 Vue 组合式函数一样，应在 `<script setup>` 或 `setup()` 函数内同步调用，使其响应式作用域绑定到组件生命周期。
</Callout>

## 签名

```ts
import { useAgentContext } from "@copilotkit/vue/v2";

function useAgentContext(context: AgentContextInput): void;
```

## 参数

<PropertyReference name="context" type="AgentContextInput" required>
  一个对象，描述要暴露给智能体的上下文。

  <PropertyReference name="description" type="MaybeRefOrGetter<string>" required>
    上下文的人类可读描述。智能体借助它理解该值代表什么、何时引用它。接受普通字符串、ref、计算属性或 getter 函数。
  </PropertyReference>

  <PropertyReference name="value" type="MaybeRefOrGetter<JsonSerializable>" required>
    要提供的上下文值。必须能解析为 JSON 可序列化的值：`string`、`number`、`boolean`、`null`、数组，或键为字符串且值可序列化的普通对象。非字符串值在发送前会经 `JSON.stringify` 序列化，因此智能体收到的是 JSON 字符串，而不是你传入的值。
    参见[智能体接收到的内容](#智能体接收到的内容)。
    接受普通值、ref、计算属性或 getter 函数。
  </PropertyReference>
</PropertyReference>

## 用法

### 基本用法

将简单的静态应用状态作为上下文提供给智能体。

```vue
<script setup lang="ts">
import { useAgentContext } from "@copilotkit/vue/v2";

useAgentContext({
  description: "Current workspace",
  value: "copilotkit-vue",
});
</script>

<template>
  <div>Workspace ready</div>
</template>
```

### 来自组件状态的响应式上下文

传入 ref 或 getter，底层状态变化时上下文便会自动更新，无需重新注册。

```vue
<script setup lang="ts">
import { ref } from "vue";
import { useAgentContext } from "@copilotkit/vue/v2";

const selectedCategory = ref("electronics");
const priceRange = ref({ min: 0, max: 500 });

useAgentContext({
  description: "The user's current product filter settings",
  value: () => ({
    category: selectedCategory.value,
    priceRange: priceRange.value,
  }),
});
</script>

<template>
  <select v-model="selectedCategory">
    <option value="electronics">Electronics</option>
    <option value="books">Books</option>
    <option value="clothing">Clothing</option>
  </select>
  <!-- ... price range controls ... -->
</template>
```

### 使用计算属性

凡是接受 `MaybeRefOrGetter` 的地方都可以使用 `computed` ref，包括 `description`。

```vue
<script setup lang="ts">
import { computed, ref } from "vue";
import { useAgentContext } from "@copilotkit/vue/v2";

const props = defineProps<{
  user: { name: string; role: string };
}>();

const userContext = computed(() => ({
  name: props.user.name,
  role: props.user.role,
}));

useAgentContext({
  description: computed(() => `Profile for ${props.user.name}`),
  value: userContext,
});
</script>

<template>
  <div>Welcome, {{ user.name }}</div>
</template>
```

### 多个上下文

每个组件都可以注册自己的上下文。所有已注册的上下文会同时对智能体可见。

```vue
<script setup lang="ts">
import { ref } from "vue";
import { useAgentContext } from "@copilotkit/vue/v2";

const collapsed = ref(false);

useAgentContext({
  description: "Current dashboard view and layout",
  value: { view: "analytics", columns: 3 },
});

useAgentContext({
  description: "Sidebar navigation state",
  value: () => ({ collapsed: collapsed.value, activeSection: "reports" }),
});
</script>

<template>
  <div>
    <!-- dashboard layout -->
  </div>
</template>
```

## 智能体接收到的内容

每个已注册的条目都会以 `{ description, value }` 的形式送达智能体，且 `value` 是一个 **JSON 字符串**——而不是你传入的对象或数组。AG-UI 协议将其类型定义为字符串，因此在编写智能体时，这不是一个可以忽略的实现细节。

注册以下内容：

```vue
<script setup lang="ts">
import { useAgentContext } from "@copilotkit/vue/v2";

useAgentContext({
  description: "Incident dashboard records",
  value: [{ id: "INC-1041", severity: "sev1" }],
});
</script>
```

智能体实际收到的是：

```json
{
  "description": "Incident dashboard records",
  "value": "[{\"id\":\"INC-1041\",\"severity\":\"sev1\"}]"
}
```

读取任何字段之前先解析它。在 Python 智能体中：

```python
import json

def dashboard_records(context):
    entry = next(
        (item for item in context if item["description"] == "Incident dashboard records"),
        None,
    )
    return None if entry is None else json.loads(entry["value"])
```

在 TypeScript 智能体中：

```ts
const entry = context.find(
  (item) => item.description === "Incident dashboard records",
);
const records = entry ? JSON.parse(entry.value) : undefined;
```

这份上下文列表在智能体中的出现位置取决于所用框架的 AG-UI 适配器——具体填充到哪个字段，请查阅对应集成的指南。

<Callout type="warn">
  不要按你注册时的结构对 `value` 做类型检查。
  Python 中的 `isinstance(entry["value"], list)` 或 TypeScript 中的 `Array.isArray(entry.value)` 永远不会为真，因为 `value` 在传输层始终是字符串。如果智能体把这种失败的检查解读为“未发送任何上下文”，就会在应用其实已正确注册上下文的情况下拒绝所有请求，而且这两种情况从 UI 上无法区分。
</Callout>

## 行为

- **作用域生命周期**：上下文在组合式函数的响应式作用域活跃期间持续注册，并在作用域清理（组件卸载）时自动移除，无需手动清理。
- **响应式更新**：`description` 和 `value` 通过 `toValue` 解析，因此 ref、计算属性和 getter 都会被追踪。解析后的值变化时，先前的上下文条目会被移除并重新注册新值，使智能体保持同步。
- **序列化**：字符串值原样传递。其他任何值都会经 `JSON.stringify` 序列化，因此必须符合 `JsonSerializable`（`string | number | boolean | null | JsonSerializable[] | { [key: string]: JsonSerializable }`）。函数、类实例或符号等不可序列化的值无法正确序列化。因此智能体读到的始终是字符串——参见[智能体接收到的内容](#智能体接收到的内容)。
- **多个上下文**：组件树中多处调用 `useAgentContext` 注册的上下文会同时全部对智能体可见。每个条目内部由 `addContext` 返回的 ID 标识，并在清理时移除。
- **无返回值**：该组合式函数返回 `void`。
