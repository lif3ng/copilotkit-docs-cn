## 概览

`useCopilotChatConfiguration` 是一个 Vue 3 组合式函数，读取由最近的 `CopilotChatConfigurationProvider` 注入的聊天配置上下文。该提供方组件由 CopilotKit 聊天组件（`CopilotChat`、`CopilotPopup` 和 `CopilotSidebar`）自动挂载——`CopilotKitProvider` **不会**挂载它——你也可以直接挂载。它返回一个 `ComputedRef`，解析为当前的 `CopilotChatConfigurationValue`；组件树中不存在提供方时为 `null`。

由于该组合式函数返回 `ComputedRef`，值始终保持响应式：标签、活跃智能体或线程、弹窗状态或抽屉状态变化时，解析出的值会自动更新。它为本地化标签、智能体/线程绑定、弹窗状态以及聊天 UI 组件共用的抽屉控件提供了一个轻量的响应式上下文。

<Callout type="info">
  与所有 Vue 组合式函数一样，应在 `<script setup>` 或 `setup()` 函数内同步调用 `useCopilotChatConfiguration`，使注入能针对外围组件树正确解析。当祖先链上没有 `CopilotChatConfigurationProvider`（或会挂载它的 CopilotKit 聊天组件）时，返回的 ref 解析为 `null`，因此要对该情况做防护，而不要默认一定有值。
</Callout>

## CopilotChatConfigurationProvider

一个提供方组件，向所有后代聊天组件注入本地化标签、智能体与线程 ID 以及可选的弹窗状态。CopilotKit 聊天组件（`CopilotChat`、`CopilotPopup`、`CopilotSidebar`）会自动挂载一个，因此只有在聊天组件之外读取配置，或想为某个子树限定/覆盖配置时，才需要直接挂载它。

### 用法

```vue
<script setup lang="ts">
import { CopilotChatConfigurationProvider } from "@copilotkit/vue/v2";
</script>

<template>
  <CopilotChatConfigurationProvider
    :labels="{ chatInputPlaceholder: 'Ask me anything...' }"
    agent-id="my-agent"
    thread-id="thread-123"
    :is-modal-default-open="true"
  >
    <slot />
  </CopilotChatConfigurationProvider>
</template>
```

### 属性（Props）

<PropertyReference name="labels" type="Partial<CopilotChatLabels>">
  标签覆盖项的子集。未提供的标签会回退到内置默认值，再回退到父级提供方的标签。所有可用键见下文 [CopilotChatLabels](#copilotchatlabels)。
</PropertyReference>

<PropertyReference name="agentId" type="string" default='"default"'>
  与此聊天上下文关联的智能体 ID。回退到父级提供方的 `agentId`，再回退到默认智能体 ID（`"default"`）。
</PropertyReference>

<PropertyReference name="threadId" type="string">
  用于保持会话连续性的线程 ID。省略时回退到父级提供方的 `threadId`，否则会生成一个随机 UUID，并在提供方生命周期内保持不变。
</PropertyReference>

<PropertyReference name="hasExplicitThreadId" type="boolean">
  标记所提供的 `threadId` 是调用方的真实选择，而非内部生成的 UUID。省略时，提供方根据 `threadId` 本身是否被提供来推断。这主要供内部包装器使用；大多数应用可以不设置。
</PropertyReference>

<PropertyReference name="isModalDefaultOpen" type="boolean">
  提供时，该提供方将拥有弹窗开/关状态，并以此值作为初始状态。省略时，弹窗状态继承自父级提供方（如有）。
</PropertyReference>

注入的配置值还携带共享的抽屉状态与线程控制辅助函数，详见下文组合式函数的返回值说明。

提供方渲染其默认 `<slot />`，放在其内部的后代组件因此能收到注入的配置。

## useCopilotChatConfiguration

### 签名

```ts
import { useCopilotChatConfiguration } from "@copilotkit/vue/v2";
import type { ComputedRef } from "vue";
import type { CopilotChatConfigurationValue } from "@copilotkit/vue/v2";

function useCopilotChatConfiguration(): ComputedRef<CopilotChatConfigurationValue | null>;
```

### 参数

该组合式函数不接受任何参数。

### 返回值

返回一个 `ComputedRef`。在任何 `CopilotChatConfigurationProvider` 之外使用时，其 `.value` 为 `null`，否则为一个 `CopilotChatConfigurationValue` 对象：

<PropertyReference name="labels" type="CopilotChatLabels">
  完整解析后的标签对象，由内置默认值、父级提供方和最近提供方的覆盖项合并而成。所有键见 [CopilotChatLabels](#copilotchatlabels)。
</PropertyReference>

<PropertyReference name="agentId" type="string">
  此聊天上下文解析出的智能体 ID。
</PropertyReference>

<PropertyReference name="threadId" type="string">
  此聊天上下文解析出的线程 ID。
</PropertyReference>

<PropertyReference name="hasExplicitThreadId" type="boolean">
  当解析出的 `threadId` 由调用方（或父级提供方）选择、而非在提供方链内部悄悄生成时为 `true`。只在真实后端线程上才有意义的消费方应以它而非 `!!threadId` 作为判断条件。
</PropertyReference>

<PropertyReference name="isModalOpen" type="boolean | undefined">
  当前弹窗打开状态。树中没有提供方通过 `isModalDefaultOpen` 拥有弹窗状态时为 `undefined`。
</PropertyReference>

<PropertyReference name="setModalOpen" type="((open: boolean) => void) | undefined">
  控制弹窗打开状态的函数。树中没有提供方拥有弹窗状态时为 `undefined`。
</PropertyReference>

<PropertyReference name="drawerOpen" type="boolean">
  当前线程抽屉状态。只要存在提供方就始终可用。
</PropertyReference>

<PropertyReference name="setDrawerOpen" type="(open: boolean) => void">
  控制线程抽屉状态的函数。
</PropertyReference>

<PropertyReference name="drawerRegistered" type="boolean">
  当前提供方链中挂载了线程抽屉时为 `true`。
</PropertyReference>

<PropertyReference name="registerDrawer" type="() => () => void">
  注册一个线程抽屉，返回用于注销它的清理函数。
</PropertyReference>

<PropertyReference name="setActiveThreadId" type="(threadId: string, options?: { explicit?: boolean }) => void">
  从代码切换活跃线程。`options.explicit` 为 `true` 时，新线程被视为调用方的显式选择。
</PropertyReference>

<PropertyReference name="startNewThread" type="() => void">
  将当前聊天重置为一个全新的、非显式的线程。
</PropertyReference>

## 用法

### 在组件中读取配置

调用一次组合式函数，然后从返回的 ref 读取。对不存在提供方的情况要对 `null` 做防护。

```vue
<script setup lang="ts">
import { useCopilotChatConfiguration } from "@copilotkit/vue/v2";

const config = useCopilotChatConfiguration();
</script>

<template>
  <h2 v-if="config">{{ config.labels.modalHeaderTitle }}</h2>
  <h2 v-else>Chat</h2>
</template>
```

### 基本标签自定义

在聊天 UI 外围挂载一个提供方来限定标签覆盖的作用范围。

```vue
<script setup lang="ts">
import { CopilotChatConfigurationProvider } from "@copilotkit/vue/v2";
import ChatUI from "./ChatUI.vue";

const labels = {
  chatInputPlaceholder: "Ask me anything...",
  modalHeaderTitle: "AI Assistant",
  welcomeMessageText: "Hello! What can I do for you?",
  chatDisclaimerText: "Responses are AI-generated.",
};
</script>

<template>
  <CopilotChatConfigurationProvider :labels="labels">
    <ChatUI />
  </CopilotChatConfigurationProvider>
</template>
```

### 绑定到特定智能体与线程

```vue
<script setup lang="ts">
import { CopilotChatConfigurationProvider } from "@copilotkit/vue/v2";
import ChatWindow from "./ChatWindow.vue";
</script>

<template>
  <CopilotChatConfigurationProvider
    agent-id="support-agent"
    thread-id="ticket-456"
    :labels="{
      chatInputPlaceholder: 'Describe your issue...',
      modalHeaderTitle: 'Support Chat',
    }"
  >
    <ChatWindow />
  </CopilotChatConfigurationProvider>
</template>
```

### 弹窗状态管理

提供方设置 `is-modal-default-open` 后，后代组件可以读取 `isModalOpen` 并调用 `setModalOpen`。由于组合式函数返回 `ComputedRef`，切换状态会自动保持同步。

```vue
<!-- App.vue -->
<script setup lang="ts">
import { CopilotChatConfigurationProvider } from "@copilotkit/vue/v2";
import ToggleButton from "./ToggleButton.vue";
import ChatModal from "./ChatModal.vue";
</script>

<template>
  <CopilotChatConfigurationProvider :is-modal-default-open="false">
    <ToggleButton />
    <ChatModal />
  </CopilotChatConfigurationProvider>
</template>
```

### 抽屉状态管理

需要从另一个组件打开或关闭线程抽屉时，使用共享的抽屉状态。

```vue
<!-- ToggleDrawer.vue -->
<script setup lang="ts">
import { useCopilotChatConfiguration } from "@copilotkit/vue/v2";

const config = useCopilotChatConfiguration();

function toggleDrawer() {
  const value = config.value;
  if (!value?.setDrawerOpen) return;
  value.setDrawerOpen(!value.drawerOpen);
}
</script>

<template>
  <button v-if="config" @click="toggleDrawer">
    {{ config.drawerOpen ? "Close drawer" : "Open drawer" }}
  </button>
</template>
```

```vue
<!-- ToggleButton.vue -->
<script setup lang="ts">
import { useCopilotChatConfiguration } from "@copilotkit/vue/v2";

const config = useCopilotChatConfiguration();

function toggle() {
  const value = config.value;
  if (!value?.setModalOpen) return;
  value.setModalOpen(!value.isModalOpen);
}
</script>

<template>
  <button v-if="config?.setModalOpen" @click="toggle">
    {{
      config.isModalOpen
        ? config.labels.chatToggleCloseLabel
        : config.labels.chatToggleOpenLabel
    }}
  </button>
</template>
```

### 嵌套提供方

提供方可以嵌套。子级提供方继承并合并父级的标签，子级覆盖优先。

```vue
<script setup lang="ts">
import { CopilotChatConfigurationProvider } from "@copilotkit/vue/v2";
import SalesChat from "./SalesChat.vue";
</script>

<template>
  <CopilotChatConfigurationProvider
    :labels="{ chatDisclaimerText: 'Company-wide disclaimer.' }"
  >
    <CopilotChatConfigurationProvider
      agent-id="sales"
      :labels="{ modalHeaderTitle: 'Sales Assistant' }"
    >
      <!-- This context has both the company disclaimer and the sales title -->
      <SalesChat />
    </CopilotChatConfigurationProvider>
  </CopilotChatConfigurationProvider>
</template>
```

## 行为

- **响应式 ref**：该组合式函数返回 `ComputedRef<CopilotChatConfigurationValue | null>`。在脚本中通过 `config.value` 读取，在模板中通过 `config`（自动解包）读取。注入的配置变化时值会重新计算。
- **标签合并**：标签按顺序合并：内置默认值（`CopilotChatDefaultLabels`），然后是父级提供方的标签，最后是当前提供方的标签。因此任意层级都可以做部分覆盖。
- **智能体 ID 解析**：`agentId` 从最近的提供方解析，回退到父级提供方，再回退到默认智能体 ID（`"default"`）。
- **线程 ID 生成**：任何层级都未提供 `threadId` 时，会生成一个随机 UUID，并在提供方生命周期内保持不变。`hasExplicitThreadId` 报告解析出的线程 ID 是调用方的选择还是内部生成的 UUID。
- **弹窗状态归属**：只有提供方设置了 `isModalDefaultOpen` 时才会创建弹窗状态（`isModalOpen` / `setModalOpen`）。未设置该 prop 的提供方透传父级的弹窗状态；没有任何提供方拥有弹窗状态时，这两个字段均为 `undefined`。
- **抽屉状态归属**：抽屉状态（`drawerOpen` / `setDrawerOpen`）通过提供方链共享，`drawerRegistered` / `registerDrawer` 追踪是否挂载了抽屉，以便移动端入口得以显示。
- **线程覆盖**：`setActiveThreadId` 和 `startNewThread` 是命令式辅助函数，供线程抽屉和其他宿主 UI 使用。解析出的线程是否被视为调用方控制，仍由 `hasExplicitThreadId` 决定。
- **空值解析**：在任何 `CopilotChatConfigurationProvider` 之外使用时，返回的 ref 解析为 `null` 而不是抛错。组件应优雅处理这种情况。
