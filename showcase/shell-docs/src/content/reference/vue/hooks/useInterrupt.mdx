## 概览

`useInterrupt` 是一个用于处理智能体中断的 Vue 3 组合式函数。它同时支持 AG-UI 标准中断流与旧版 `on_interrupt` 自定义事件流，并把活动中断暴露为响应式状态，同时提供用于恢复执行的 `resolve` 与 `cancel` 方法。

默认情况下，该组合式函数会把状态发布到 [`CopilotChat`](/reference/vue/components/CopilotChat) 中，你可以通过聊天组件的 `#interrupt` 插槽渲染中断 UI。如果你想自行放置 UI，请设置 `renderInChat: false`。

`event.value` 的类型由 `TValue` 类型参数决定，默认为 `unknown`。可以在 `handler` 与 `enabled` 回调中自行收窄类型，或在调用组合式函数时显式传入 `TValue`。

<Callout type="info">
  `resolve` 与 `cancel` 是主要方法。`resolveInterrupt` 与 `cancelInterrupt` 作为向后兼容的别名保留。
</Callout>

## 签名

```ts
import { useInterrupt } from "@copilotkit/vue/v2";

function useInterrupt<TValue = unknown, TResult = never>(
  config?: UseInterruptConfig<TValue, TResult>,
): UseInterruptResult<TValue, TResult>;
```

## 参数

<PropertyReference name="config" type="UseInterruptConfig<TValue, TResult>">
  可选的中断配置。

  <PropertyReference name="handler" type="(props: InterruptHandlerProps<TValue>) => TResult | PromiseLike<TResult>">
    可选的预处理回调。当中断进入待处理状态时执行，可返回同步或异步数据并暴露为 `result`。`TResult` 根据该回调的返回类型推断，Promise 会被自动解包。若回调返回已拒绝的 Promise，`result` 将变为 `null`。同步 `throw` 不会被捕获，`result` 保持不变。

    该回调接收以下参数：

    - `event` —— 中断事件（`{ name, value }`）。`value` 的类型为 `TValue`。
    - `interrupt` —— 标准 AG-UI 流生效时的主中断对象，否则为 `null`。
    - `interrupts` —— 完整的标准中断集合，旧版流为 `[]`。
    - `resolve(response)` —— 恢复智能体执行。
    - `cancel()` —— 标准流生效时取消当前中断。
  </PropertyReference>

  <PropertyReference name="enabled" type="(event: InterruptEvent<TValue>) => boolean">
    可选的过滤器。返回 `false` 可让该组合式函数实例忽略匹配的中断。当其返回 `false` 时，`result` 与 `slotProps` 保持 `null`，也不会向聊天发布任何内容。
  </PropertyReference>

  <PropertyReference name="agentId" type="string">
    可选的智能体 id。默认为当前配置的聊天智能体。
  </PropertyReference>

  <PropertyReference name="renderInChat" type="boolean" default="true">
    控制中断状态是否发布到 `<CopilotChat>`：
    - `true`（默认）：把 `slotProps` 发布到 `<CopilotChat>`，以便通过 `#interrupt` 插槽渲染。
    - `false`：跳过发布；由你使用返回的 ref 自行渲染中断。
  </PropertyReference>
</PropertyReference>

## 返回值

<PropertyReference name="object" type="UseInterruptResult<TValue, TResult>">
  响应式的中断状态以及恢复/取消辅助方法。

  <PropertyReference name="interrupt" type="Ref<InterruptEvent<TValue> | null>">
    最新一个待处理的中断事件（`{ name, value }`），没有则为 `null`。新运行开始或中断被处理后会清空。
  </PropertyReference>

  <PropertyReference name="result" type="Ref<TResult | null>">
    `handler` 返回的值；在未提供 handler、handler 返回已拒绝的 Promise，或 `enabled` 过滤掉了该中断时为 `null`。
  </PropertyReference>

  <PropertyReference name="hasInterrupt" type="ComputedRef<boolean>">
    当有待处理中断且通过了可选的 `enabled` 过滤时为 `true`，否则为 `false`。
  </PropertyReference>

  <PropertyReference name="resolve" type="InterruptResolveFn">
    主要的恢复方法。

    - 旧版流：以 `command.resume = payload` 恢复执行，并转发原始中断事件。
    - 标准流：记录对目标中断的响应。当有多个中断待处理时，响应会累积，只有在全部处理完毕后智能体才会恢复执行。若在多个中断同时打开时省略 `interruptId`，该 hook 会发出警告并默认指向第一个。
    - 已过期的标准中断不会被恢复。
  </PropertyReference>

  <PropertyReference name="resolveInterrupt" type="InterruptResolveFn">
    `resolve` 的向后兼容别名。
  </PropertyReference>

  <PropertyReference name="cancel" type="InterruptCancelFn">
    取消待处理的中断。

    - 标准流：记录对目标中断的取消。多个打开的中断会累积响应，直到全部处理完毕。若在多个中断同时打开时省略 `interruptId`，该 hook 会发出警告并默认指向第一个。
    - 旧版流：仅关闭中断，不恢复执行。
  </PropertyReference>

  <PropertyReference name="cancelInterrupt" type="InterruptCancelFn">
    `cancel` 的向后兼容别名。
  </PropertyReference>

  <PropertyReference name="slotProps" type="ComputedRef<InterruptRenderProps<TValue, TResult | null> | null>">
    发布到 `<CopilotChat>` `#interrupt` 插槽的 props，没有活动中断时为 `null`。形态为 `{ event, interrupt, interrupts,
    result, resolve, cancel }`。
  </PropertyReference>
</PropertyReference>

## 用法

### 聊天内中断 UI

```vue
<script setup lang="ts">
import { CopilotChat, useInterrupt } from "@copilotkit/vue/v2";

interface Approval {
  question: string;
}

useInterrupt<Approval>();
</script>

<template>
  <CopilotChat>
    <template #interrupt="{ event, resolve }">
      <div class="rounded border p-3">
        <p>{{ (event.value as Approval).question }}</p>
        <div class="mt-2 flex gap-2">
          <button @click="resolve({ approved: true })">Approve</button>
          <button @click="resolve({ approved: false })">Reject</button>
        </div>
      </div>
    </template>
  </CopilotChat>
</template>
```

### 手动放置与异步预处理

```vue
<script setup lang="ts">
import { useInterrupt } from "@copilotkit/vue/v2";

const { interrupt, result, hasInterrupt, resolve } = useInterrupt<
  string,
  { label: string }
>({
  renderInChat: false,
  enabled: (event) => event.value.startsWith("approval:"),
  handler: async ({ event }) => ({ label: event.value.toUpperCase() }),
});
</script>

<template>
  <aside v-if="hasInterrupt" class="rounded border p-3">
    <div class="font-medium">{{ result?.label ?? "" }}</div>
    <div class="mt-2">{{ interrupt?.value }}</div>
    <button class="mt-2" @click="resolve({ accepted: true })">Continue</button>
  </aside>
</template>
```

### 在脚本中读取响应式状态

```ts
import { useInterrupt } from "@copilotkit/vue/v2";

const { interrupt, hasInterrupt, result, cancel, resolve } = useInterrupt({
  handler: ({ event }) => ({ label: String(event.value) }),
});

// `interrupt` and `result` are reactive refs; `hasInterrupt` is a computed.
// Call `resolve(response)` or `cancel()` to address the interrupt.
```

## 行为

- 中断同时从 AG-UI 标准中断事件与旧版 `on_interrupt` 自定义事件中收集。
- 若同一次运行中两种流同时出现，标准中断优先。
- 待处理的中断会在运行收尾时浮出。
- 开始新运行会清空待处理的中断状态，运行失败则丢弃进行中的中断。
- 当多个标准中断同时打开时，`resolve(payload, interruptId)` 与 `cancel(interruptId)` 会累积响应，直到每个中断都被处理，然后一次性恢复执行。
- 在多个标准中断同时打开时省略 `interruptId`，会默认指向第一个中断并记录一条警告。
- 已过期的标准中断不会被恢复。
- `result` 从 `handler` 的返回类型推断，类型始终为 `TResult | null`。
- 当 `enabled` 返回 `false` 时，该中断被忽略：`result` 与 `slotProps` 保持 `null`，也不会向聊天发布任何内容。
- 省略 `renderInChat` 或设为 `true` 时，`slotProps` 会发布到 `<CopilotChat>` 的 `#interrupt` 插槽。设为 `renderInChat: false` 时，不会向聊天发布，需使用返回的 ref 自行渲染。
- 对旧版中断调用 `cancel()` 仅关闭中断，不恢复执行。
