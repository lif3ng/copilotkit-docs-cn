## 概览

`useCopilotKit` 是一个底层 Vue 3 组合式函数，注入 CopilotKit 提供方上下文，可直接访问核心实例与提供方级别的响应式状态。由于它返回的是 Vue ref，在 `computed`、`watch` 或模板中读取它们能让代码对连接状态、执行中的工具调用等运行时变化保持响应。

<Callout type="info">
  `useCopilotKit` 是一个底层组合式函数。大多数应用应改用 `useAgent` 或 `useFrontendTool` 等更高层的组合式函数。
</Callout>

在 `CopilotKitProvider` 之外调用时**会抛出错误**。该组合式函数注入的是提供方上下文，因此必须运行在以 `CopilotKitProvider` 为祖先的组件树中。

## 签名

```ts
import { useCopilotKit } from "@copilotkit/vue/v2";

function useCopilotKit(): CopilotKitContextValue;
```

## 参数

该组合式函数不接受任何参数。

## 返回值

该组合式函数返回 `CopilotKitContextValue` 对象。每个成员都是 Vue ref（或计算属性 ref），因此要通过 `.value` 访问底层值（或让模板自动解包）。

<PropertyReference name="copilotkit" type="ShallowRef<CopilotKitCoreVue>">
  一个持有活跃 CopilotKit 核心实例的 `shallowRef`。`CopilotKitCoreVue` 扩展自框架无关的 `CopilotKitCore`，因此 `copilotkit.value` 是管理智能体、工具、建议与运行时通信的中央协调器。它提供：
  - 智能体管理（`agents`、`getAgent`）
  - 工具注册与执行（`runTool`）
  - 建议配置与获取
  - 运行时连接管理
  - 通过 `subscribe()` 订阅事件

  核心实例在每个 `CopilotKitProvider` 中只创建一次，并在提供方生命周期内保持稳定。
</PropertyReference>

<PropertyReference name="executingToolCallIds" type="Ref<ReadonlySet<string>>">
  一个 ref，指向当前正在执行的工具调用 ID 集合。它在提供方级别追踪，因此即使子组件尚未挂载，工具执行事件也能被捕获——这对人机协同（human-in-the-loop）重连等场景很重要：组件树挂载时可能已有待处理的工具调用存在。
</PropertyReference>

<PropertyReference name="a2uiTheme" type="ComputedRef<A2UITheme | undefined>">
  一个计算属性 ref，指向提供方上配置的 A2UI 主题；未提供主题时为 `undefined`。
</PropertyReference>

<PropertyReference name="a2uiCatalog" type="ComputedRef<unknown>">
  一个计算属性 ref，指向提供方上配置的 A2UI 组件目录。
</PropertyReference>

<PropertyReference name="a2uiLoadingComponent" type="ComputedRef<unknown>">
  一个计算属性 ref，指向 A2UI 界面加载期间渲染的组件。
</PropertyReference>

<PropertyReference name="a2uiIncludeSchema" type="ComputedRef<boolean>">
  一个计算属性 ref，指示是否包含 A2UI schema。
</PropertyReference>

## 用法

### 访问核心实例

```vue
<script setup lang="ts">
import { computed } from "vue";
import { useCopilotKit } from "@copilotkit/vue/v2";

const { copilotkit } = useCopilotKit();

const agentIds = computed(() => Object.keys(copilotkit.value.agents ?? {}));
</script>

<template>
  <div>
    <h3>Registered Agents</h3>
    <ul>
      <li v-for="id in agentIds" :key="id">{{ id }}</li>
    </ul>
  </div>
</template>
```

### 订阅核心事件

在 `onMounted` 中订阅，并在 `onUnmounted` 中清理订阅。

```vue
<script setup lang="ts">
import { onMounted, onUnmounted } from "vue";
import { useCopilotKit } from "@copilotkit/vue/v2";

const { copilotkit } = useCopilotKit();

let subscription: { unsubscribe: () => void } | undefined;

onMounted(() => {
  subscription = copilotkit.value.subscribe({
    onRuntimeConnectionStatusChanged: () => {
      console.log("Runtime connection status changed");
    },
  });
});

onUnmounted(() => {
  subscription?.unsubscribe();
});
</script>
```

### 以编程方式运行工具

`copilotkit.value.runTool()` 让你可以直接从代码执行已注册的前端工具，无需 LLM 轮次。工具的处理器会运行，渲染组件会出现在 UI 中，工具调用及其结果都会加入智能体的消息历史。

```vue
<script setup lang="ts">
import { z } from "zod";
import { useCopilotKit, useFrontendTool } from "@copilotkit/vue/v2";

const { copilotkit } = useCopilotKit();

// Register the tool
useFrontendTool({
  name: "exportData",
  description: "Export data as CSV",
  parameters: z.object({ format: z.string() }),
  handler: async ({ format }) => {
    const csv = await generateCsv(format);
    downloadFile(csv);
    return `Exported as ${format}`;
  },
});

// Trigger it from a button, no LLM needed
async function handleExport() {
  try {
    const { result, error } = await copilotkit.value.runTool({
      name: "exportData",
      parameters: { format: "csv" },
    });
    // `error` is set when the handler itself throws.
    if (error) console.error(error);
  } catch (err) {
    // `runTool` rejects if the tool (or its agent) cannot be found.
    console.error(err);
  }
}
</script>

<template>
  <button @click="handleExport">Export CSV</button>
</template>
```

#### `runTool` 参数

<PropertyReference name="params" type="CopilotKitCoreRunToolParams">
  <PropertyReference name="name" type="string" required>
    要执行的已注册前端工具名称。
  </PropertyReference>

<PropertyReference name="agentId" type="string">
  用于工具与消息作用域限定的智能体 ID。默认为 `"default"`。
</PropertyReference>

<PropertyReference
  name="parameters"
  type="Record<string, unknown>"
  default="{}"
>
  传给工具处理器的参数。
</PropertyReference>

  <PropertyReference name="followUp" type="string | false" default="false">
    控制执行后是否触发 LLM 后续处理：
    - `false`，执行工具后停止（默认）
    - `"generate"`，触发一次智能体运行，让 LLM 响应工具结果
    - 其他任意字符串，以此文本添加一条用户消息，然后触发智能体运行
  </PropertyReference>
</PropertyReference>

#### `runTool` 返回值

<PropertyReference name="result" type="CopilotKitCoreRunToolResult">
  <PropertyReference name="toolCallId" type="string">
    工具调用的唯一 ID，与加入历史的消息一致。
  </PropertyReference>

<PropertyReference name="result" type="string">
  工具处理器返回值的字符串化结果（纯渲染工具为空字符串）。
</PropertyReference>

  <PropertyReference name="error" type="string | undefined">
    处理器抛错时的错误消息。工具结果消息会包含 `"Error: ..."`。注意，找不到工具或其智能体时 `runTool` 本身会 **reject**（抛出）——这类查找失败以 rejected promise 的形式出现，而不是通过该字段——因此除了检查 `error`，还要把调用包在 `try`/`catch` 中。
  </PropertyReference>
</PropertyReference>

### 检查工具执行状态

由于 `executingToolCallIds` 是 ref，可以用 `computed` 基于它驱动 UI，或在模板中直接读取。

```vue
<script setup lang="ts">
import { computed } from "vue";
import { useCopilotKit } from "@copilotkit/vue/v2";

const { executingToolCallIds } = useCopilotKit();

const executingCount = computed(() => executingToolCallIds.value.size);
</script>

<template>
  <div v-if="executingCount > 0">
    Executing {{ executingCount }} tool call(s)...
  </div>
</template>
```

## 行为

- **缺少提供方时报错**：在 `CopilotKitProvider` 之外调用时抛出 `useCopilotKit must be used within CopilotKitProvider`。
- **是 ref 而非普通值**：每个返回成员都是 Vue ref 或计算属性 ref。通过 `copilotkit.value` 访问核心实例，通过 `executingToolCallIds.value` 访问实时集合。用 `computed`、`watch` 或模板绑定保持响应式用法。
- **核心引用稳定**：`copilotkit` ref 是每个提供方创建一次的 `shallowRef`，在提供方生命周期内保持稳定。只有 `executingToolCallIds` 会随工具调用的开始与结束而变化。
- **提供方级别的工具追踪**：`executingToolCallIds` 在提供方级别而非单个组件中追踪，因此子组件挂载前发出的工具执行开始事件不会丢失。
