---
title: "CopilotKitProvider"
description: "包裹你的应用并提供 CopilotKit 上下文的 Vue 3 提供方组件。"
---

<Callout type="info">
  这是 Vue 3 提供方组件，请从 `@copilotkit/vue/v2` 导入。
</Callout>

`CopilotKitProvider` 通常包裹你的整个应用（或你希望放置 copilot 的子树）。它会创建 CopilotKit 核心实例，并向所有后代组件与组合式函数（例如 [`useCopilotKit`](/reference/vue/hooks/useCopilotKit) 和 [`useAgent`](/reference/vue/hooks/useAgent)）提供 copilot 上下文。

被包裹的应用通过组件的[默认插槽](#插槽slots)渲染，因为 Vue 使用插槽而非 `children` prop。

## 示例

```vue
<script setup lang="ts">
import { CopilotKitProvider } from "@copilotkit/vue/v2";
</script>

<template>
  <CopilotKitProvider runtime-url="/api/copilotkit">
    <!-- ... your app ... -->
  </CopilotKitProvider>
</template>
```

使用公开 API 密钥连接 Copilot Cloud，而非自托管运行时：

```vue
<script setup lang="ts">
import { CopilotKitProvider } from "@copilotkit/vue/v2";
</script>

<template>
  <CopilotKitProvider public-api-key="ck_pub_your_key">
    <!-- ... your app ... -->
  </CopilotKitProvider>
</template>
```

## 属性（Properties）

你必须至少提供 `runtimeUrl`、`publicApiKey` 或 `publicLicenseKey` 之一（或一组本地智能体），否则该提供方会在开发环境下告警、在生产环境下抛错。

<PropertyReference name="runtimeUrl" type="string">
  Copilot Runtime 实例的端点。省略但设置了公开密钥时，
  请求会回退到 Copilot Cloud 聊天端点。
</PropertyReference>

<PropertyReference name="headers" type="Record<string, string> | (() => Record<string, string>) | (() => Promise<Record<string, string>>)">
  随每个请求一起发送的额外请求头。静态请求头传普通对象，
  或传返回请求头的函数（同步或异步）。构建器会在每个请求发送时执行，
  因此始终使用刷新后的令牌。

请在构建器内部做缓存。Clerk 和 Auth0 的 `getToken()` 已自带缓存。
每次都访问网络的构建器会为每个请求增加一次额外调用。

若构建器抛出异常或 Promise 被拒绝，该请求不会发送，
`onError` 会收到 `header_resolution_failed`。

重复传入同一个构建器函数是空操作；通过 `headers` prop 传入新函数同样如此：
提供方会为任何构建器保留一个稳定的包装器。切换用户时，
请重新挂载提供方（例如借助 `key`），或用新函数或普通对象调用
`copilotkit.value.setHeaders(...)`，以便为新用户重新加载 Inspector 元数据和线程列表。
此操作不会重新获取运行时的 `/info`。

`copilotkit.value.headers` 是最近一次解析的值。
发起自己的请求时可用 `await copilotkit.value.resolveHeaders()`。

核心请求头也会发送给任何 `selfManagedAgents` / `agents__unsafe_dev_only` 智能体，
包括位于其他源（origin）的智能体。如果这些智能体指向第三方，
请不要在核心请求头中放入 bearer 令牌。

```json
{
  "Authorization": "Bearer X"
}
```

</PropertyReference>

<PropertyReference name="credentials" type="RequestCredentials">
  指示用户代理是否应为跨源请求发送或接收 cookie。设为 `"include"`
  可启用 HTTP-only cookie 身份验证（需在运行时端点上配置带凭据的 CORS 以保持一致）。
</PropertyReference>

<PropertyReference name="messageFilter" type="(messages: Message[], context: { agentId: string }) => Message[]">
  重写每次运行时发送给智能体的消息列表。

CopilotKit 会随每个请求发送整个线程。当你的智能体已自行存储会话
（如 LangGraph checkpointer、Mastra memory store、Strands `SessionManager`）时，
这些负载大多是浪费，而将传入列表与其自身存储合并的智能体
可能让模型把每一轮对话看两遍。

返回要发送的消息：

```vue
<CopilotKitProvider
  runtime-url="/api/copilotkit"
  :message-filter="(messages) => messages.slice(-1)"
>
  <YourApp />
</CopilotKitProvider>
```

该过滤器只改变请求体。UI 渲染的会话记录不受影响，因此聊天中仍显示完整对话。
损坏的工具调用配对会在请求发出前修复，所以如此粗糙的过滤器
也不会把工具结果卡在审批中间。

经由你的 CopilotRuntime 访问的智能体会遵守此过滤器。
你的应用自行构造并直接传入的智能体则不会。
CopilotKit Intelligence 运行和建议运行永不过滤。

</PropertyReference>

<PropertyReference name="defaultThrottleMs" type="number">
  应用于未指定自身 `throttleMs` 的 `useAgent` 组合式函数的默认节流间隔（毫秒）。
  必须是非负有限数字；无效值会记录错误并回退为不限流。
</PropertyReference>

<PropertyReference name="publicApiKey" type="string">
  你的 Copilot Cloud API 密钥。

还没有？前往 https://dashboard.operations.copilotkit.ai 免费获取一个。

</PropertyReference>

<PropertyReference name="publicLicenseKey" type="string">
  访问 CopilotKit Intelligence 特性的公开许可密钥。

还没有？前往 https://dashboard.operations.copilotkit.ai 免费获取一个。

</PropertyReference>

<PropertyReference name="licenseToken" type="string">
  用于离线验证 CopilotKit Intelligence 特性的签名许可令牌。
  可从 https://dashboard.operations.copilotkit.ai 获取。
</PropertyReference>

<PropertyReference name="properties" type="Record<string, unknown>" default="{}">
  随每个请求发送的自定义属性。可包含用于线程创建的 `threadMetadata`，
  以及用于 LangGraph Platform 身份验证的 `authorization`。

```js
{
  user_id: "users_id",
  authorization: "your-auth-token", // For LangGraph Platform authentication
  threadMetadata: {
    account_id: "123",
    user_type: "premium",
  },
}
```

</PropertyReference>

<PropertyReference name="useSingleEndpoint" type="boolean">
  控制运行时传输方式。`true` 使用单一端点，`false` 使用 REST 传输，
  省略时自动检测传输方式。
</PropertyReference>

<PropertyReference name="agents__unsafe_dev_only" type="Record<string, AbstractAgent>" default="{}">
  以智能体 ID 为键的浏览器内本地智能体，仅供开发使用。
  它们在客户端运行而非经由运行时，因此不要在生产环境中依赖它们。
</PropertyReference>

<PropertyReference name="selfManagedAgents" type="Record<string, AbstractAgent>" default="{}">
  以智能体 ID 为键的自管理智能体。与 `agents__unsafe_dev_only` 合并
  （键冲突时以这些为准）。
</PropertyReference>

<PropertyReference name="renderToolCalls" type="VueToolCallRenderer<any>[]">
  工具调用的渲染器，将工具名与参数模式映射为用于在 UI 中渲染该工具调用的 Vue 组件。
</PropertyReference>

<PropertyReference name="renderActivityMessages" type="VueActivityMessageRenderer<unknown>[]" default="[]">
  活动消息的渲染器，将活动类型与内容模式映射为 Vue 组件。
  内置 MCP Apps 渲染器始终自动合并进来；A2UI 与 Open Generative UI 渲染器
  则在这些特性激活时合并进来。
</PropertyReference>

<PropertyReference name="renderCustomMessages" type="VueCustomMessageRenderer[]" default="[]">
  自定义消息类型的渲染器。
</PropertyReference>

<PropertyReference name="frontendTools" type="VueFrontendTool[]" default="[]">
  可供智能体使用的前端工具。必须为稳定数组；要动态增删工具，
  请改用 [`useFrontendTool`](/reference/vue/hooks/useFrontendTool) 组合式函数。
</PropertyReference>

<PropertyReference name="humanInTheLoop" type="VueHumanInTheLoop[]" default="[]">
  在解析前暂停等待用户输入的人机协同（human-in-the-loop）工具。必须为稳定数组；
  要动态增删，请改用 [`useHumanInTheLoop`](/reference/vue/hooks/useHumanInTheLoop) 组合式函数。
</PropertyReference>

<PropertyReference name="openGenerativeUI" type="{ sandboxFunctions?: SandboxFunction[]; designSkill?: string }">
  Open Generative UI 的配置。`sandboxFunctions` 将宿主函数暴露给生成的沙箱 UI
  （可通过 `Websandbox.connection.remote` 调用），`designSkill` 覆盖提供给生成工具的
  默认设计指南。`sandboxFunctions` 必须为稳定数组。
</PropertyReference>

<PropertyReference name="enableInspector" type="boolean">
  控制开发期间的 CopilotKit Inspector。它在浏览器开发构建中默认启用，
  且在生产环境或 SSR 期间从不加载。在 Vue 模板中，
  传入 `:enable-inspector="false"` 可将其禁用。
</PropertyReference>

<PropertyReference name="showDevConsole" type="boolean | &quot;auto&quot;">
  **已弃用**：请使用 `enableInspector`。此 prop 不再控制 Inspector。
</PropertyReference>

<PropertyReference name="onError" type="(event: { error: Error; code: CopilotKitCoreErrorCode; context: Record<string, any> }) => void | Promise<void>">
  可选的错误处理器，用于调试与可观测性。接收一个结构化错误事件，
  包含错误对象、错误代码和上下文调试信息。

```vue
<script setup lang="ts">
import { CopilotKitProvider } from "@copilotkit/vue/v2";

function handleError(event: {
  error: Error;
  code: string;
  context: Record<string, any>;
}) {
  debugDashboard.capture(event);
}
</script>

<template>
  <CopilotKitProvider public-api-key="ck_pub_your_key" :on-error="handleError">
    <!-- ... your app ... -->
  </CopilotKitProvider>
</template>
```

</PropertyReference>

<PropertyReference name="a2ui" type="{ theme?: A2UITheme; catalog?: any; loadingComponent?: Component; includeSchema?: boolean }">
  A2UI（Agent-to-UI）渲染器的配置。当运行时报告 `CopilotRuntime` 中配置了
  `a2ui` 时，内置 A2UI 渲染器会自动激活，因此此 prop 是可选的，
  仅在需要覆盖主题、提供自定义组件 `catalog`、设置 `loadingComponent`
  或切换是否包含模式（`includeSchema`）时才需要。

  `includeSchema` 默认为 `true`，会把目录的组件模式以及 A2UI 生成与设计指南
  作为上下文发送给智能体。设为 `includeSchema: false` 时，智能体仍会收到目录 ID
  和目录自定义组件的名称，但不含它们的 JSON 模式或指南。此时，
  使用 CopilotKit 中间件注入的 A2UI 工具的 LangGraph 智能体只会把组件名交给
  它的 A2UI 子智能体。若要给子智能体更多细节，请通过中间件的 A2UI 指南传入组合指南：
  TypeScript 中为 `a2uiParams.guidelines.compositionGuide`，
  Python 中为 `a2ui_params["guidelines"]["composition_guide"]`。

```vue
<template>
  <CopilotKitProvider
    runtime-url="/api/copilotkit"
    :a2ui="{ theme: myCustomTheme }"
  >
    <!-- ... your app ... -->
  </CopilotKitProvider>
</template>
```

</PropertyReference>

<PropertyReference name="mcpApps" type="{ allowSameOriginFallback?: boolean }">
  内置 MCP Apps 渲染器的配置。`allowSameOriginFallback` 会在 MCP App 沙箱上恢复
  `allow-same-origin`；默认情况下组件获得不透明源。**不安全**：设置后，
  组件将以你页面的源运行，可以读取你的 cookie、存储和 DOM。
  仅对你信任且需要 `localStorage`、`IndexedDB` 或 cookie 的组件使用。
  参见 [Sandbox and widget storage](/vue/generative-ui/mcp-apps#sandbox-and-widget-storage)。
</PropertyReference>

<PropertyReference name="debug" type="DebugConfig">
  为客户端事件管线启用调试日志。接受 `true` / `false` 来切换事件与生命周期日志
  （关闭详细输出），或传入 `{ events?: boolean; lifecycle?: boolean; verbose?: boolean }`
  进行细粒度控制。
</PropertyReference>

## 插槽（Slots）

<PropertyReference name="default" type="slot" required>
  默认插槽渲染被包裹的应用。Vue 使用插槽而非 `children` prop，
  因此放在 `<CopilotKitProvider>` 开闭标签之间的所有内容都会接收 copilot 上下文。

```vue
<template>
  <CopilotKitProvider runtime-url="/api/copilotkit">
    <!-- This content is the default slot -->
    <App />
  </CopilotKitProvider>
</template>
```

</PropertyReference>
