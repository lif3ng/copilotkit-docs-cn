## 这是什么？

Microsoft Agent Framework 可以把一个后端工具标记为需要审批（approval-gated）。当智能体决定调用该工具时，它不会直接运行，而是以一个 AG-UI 中断（interrupt）结束本轮运行，把这个待处理的工具调用带到你的前端。你的 UI 向用户询问，你的答复则让智能体继续运行。

决策由后端掌控，因此前端不会注册一个与后端工具同名的工具。任何会发起 AG-UI 中断的智能体都走这条相同的路径。

## 什么时候应该使用它？

当操作发生在服务端、且审批本身就是该操作的一种属性时，使用本方案：

- 破坏性或不可逆的操作，例如删除一条记录
- 花费金钱、发送邮件，或调用第三方 API
- 任何无论接入哪个前端、审批规则都必须生效的场景

如果工作本身在浏览器中运行，请改用[基于工具的人机协同](/microsoft-agent-framework/human-in-the-loop/tool-based)。

## 实现

<Steps>
  <Step>
    ### 运行并连接你的智能体

    <RunAndConnect />
  </Step>

  <Step>
    ### 把后端工具标记为需要审批

    该工具的其他方面都不变。框架会替你暂存这次调用并发起审批。

    <Tabs groupId="language_microsoft-agent-framework_agent" items={['.NET', 'Python']} persist>
      <Tab value="Python">
        ```python title="agent/src/agent.py"
        from agent_framework import tool

        @tool(
            name="delete_file",
            description="Delete a file",
            approval_mode="always_require", # [!code highlight]
        )
        def delete_file(filename: str) -> str:
            return f"Deleted {filename}."
        ```
      </Tab>
      <Tab value=".NET">
        ```csharp title="Program.cs"
        // Wrap the function so the framework requests approval before it runs.
        var deleteFileTool = new ApprovalRequiredAIFunction( // [!code highlight]
            AIFunctionFactory.Create(DeleteFile, "delete_file", "Deletes a file"));

        builder.Services.AddChatClient(/* ... */)
            .ConfigureOptions(options =>
            {
                options.Tools ??= [];
                options.Tools.Add(deleteFileTool);
            })
            .UseFunctionInvocation();
        ```
      </Tab>
    </Tabs>
  </Step>

  <Step>
    ### 使用 `useInterrupt` 渲染审批

    `useInterrupt` 会接收智能体发起的每一个 AG-UI 中断。调用 `resolve` 表示批准并继续运行，调用 `cancel` 表示拒绝。

    ```tsx title="page.tsx"
    import { useInterrupt } from "@copilotkit/react-core/v2"; // [!code highlight]

    export function ApprovalPanel() {
      // renderInChat: false makes useInterrupt return the element, so render it yourself.
      const approval = useInterrupt({
        renderInChat: false,
        render: ({ interrupt, resolve, cancel }) => {
          if (!interrupt) return <></>;
          return (
            <div>
              <p>{interrupt.message}</p>
              {/* [!code highlight:2] */}
              <button onClick={() => resolve({ approved: true })}>Approve</button>
              <button onClick={() => cancel()}>Deny</button>
            </div>
          );
        },
      });

      return <div>{approval}</div>;
    }
    ```

    <Callout type="info">
      `renderInChat` 默认为 `true`，会把你的 UI 绘制在聊天内部。如果没有挂载 `<CopilotChat />`，则什么都不会出现，也不会有任何警告。像上面那样传入 `renderInChat: false`，并自行放置返回的元素。
    </Callout>
  </Step>

  <Step>
    ### 试一试吧！

    让智能体删除一个文件。运行会停下，你的审批 UI 会出现，且只有在你批准之后工具才会执行。
  </Step>
</Steps>

## 中断包含哪些内容

需要审批的调用到达时，`reason` 会被设为 `"tool_call"`。以下字段在两种后端中都是一致的：

| 字段 | 描述 |
| --- | --- |
| `id` | 该中断的标识。当同时有多个中断打开时，把它传给 `resolve` 或 `cancel`。 |
| `reason` | 需要审批的调用为 `"tool_call"`。 |
| `message` | 人类可读的摘要，例如 `Approve running delete_file?` |
| `toolCallId` | 待处理调用的 id。它与两种后端都会发出的 `TOOL_CALL_START` 事件相匹配，因此可以把两者关联起来。 |
| `responseSchema` | 智能体所期望载荷的 JSON Schema。两种后端都要求一个布尔值 `approved`。 |

Python 适配器还会把整个请求放在 `interrupt.metadata.agent_framework.function_call` 下，从中可以拿到工具的 `name` 及其 `arguments`。.NET 服务端不会发送该字段，因此如果你要同时支持两者，请从 `message` 中读取工具名称。

## 批准、拒绝与取消

`cancel()` 和 `resolve({ approved: false })` 都不会运行该工具，但它们结束本轮的方式不同：

- `resolve({ approved: true })` 让智能体继续运行，工具随之执行。
- `resolve({ approved: false })` 把拒绝结果交给智能体，它会继续运行并可以回复用户。
- `cancel()` 立即结束运行。

<Callout type="warn">
  不要注册一个与后端工具同名的前端工具。工具名称在两者之间必须唯一，一旦冲突，运行会以 `Duplicate tool name` 错误失败。
</Callout>
