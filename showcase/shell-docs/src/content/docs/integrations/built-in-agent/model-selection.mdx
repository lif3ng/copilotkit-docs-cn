内置智能体基于 [Vercel AI SDK](https://sdk.vercel.ai) 构建，因此你既可以使用内置的模型字符串，也可以传入任意自定义的 AI SDK 模型。

## 支持的模型

使用 `"provider:model"` 格式指定模型，`"provider/model"` 格式同样有效。

下表列出这些文档所使用的模型。快速开始使用 `openai:gpt-5.4-mini`。
内置智能体会将模型 id 原样发送给提供方，因此同一提供方的其他模型 id 也可以使用。

| ------------ | --------------------- |
| GPT-5.5      | `openai:gpt-5.5`      |
| GPT-5.4      | `openai:gpt-5.4`      |
| GPT-5.4 Mini | `openai:gpt-5.4-mini` |
| GPT-5        | `openai:gpt-5`        |

## 环境变量

为你所选的提供方设置 API 密钥：

```bash
# OpenAI
OPENAI_API_KEY=sk-...

# Anthropic
ANTHROPIC_API_KEY=sk-ant-...

# Google
GOOGLE_API_KEY=...

# MiniMax
MINIMAX_API_KEY=...

# 可选：使用中国端点
MINIMAX_BASE_URL=https://api.minimaxi.com/v1
```

### OpenAI 兼容端点

要将 `openai:` 模型字符串发送到其他 OpenAI 兼容端点，请设置 `OPENAI_BASE_URL`：

```bash
OPENAI_BASE_URL=https://api.groq.com/openai/v1
OPENAI_API_KEY=gsk_...
```

内置智能体会根据该主机选择要使用的 OpenAI API：

- OpenAI（`api.openai.com`、`*.api.openai.com`）与 Azure OpenAI 主机使用 Responses API。
- 其他任何主机都会使用 Chat Completions API，因为大多数 OpenAI 兼容服务器只提供 `/chat/completions`。运行时会在首次运行时把这一选择记录到日志。

如果你想自行选择 API，可将 `COPILOTKIT_OPENAI_API` 设置为 `responses` 或 `chat`。例如，位于 OpenAI 之前的代理（如 LiteLLM 或 Portkey）需要 `responses` 才能保留仅 Responses API 支持的特性，例如推理摘要（reasoning summaries）：

```bash
OPENAI_BASE_URL=https://my-gateway.example.com/v1
COPILOTKIT_OPENAI_API=responses
```

你也可以直接在配置中传入 API 密钥：

```typescript
const agent = new BuiltInAgent({
  model: "openai:gpt-5.4-mini",
  apiKey: process.env.MY_OPENAI_KEY, // [!code highlight]
});
```

## 自定义模型（AI SDK）

如果模型字符串未覆盖你要用的提供方，或者你想自行配置提供方（例如自定义 base URL），可以直接传入任意 Vercel AI SDK 的 `LanguageModel` 实例。
首先，从提供方软件包的 `ai-v6` 发布线安装：

```npm
npm install @ai-sdk/openai@ai-v6
```

<Callout type="warn" title="为每个 @ai-sdk 提供方安装 ai-v6 版本">
  内置智能体运行在 AI SDK 6（`ai@6`）上，需要 3.x 系列的 `@ai-sdk/*` 提供方软件包。为你安装的每个提供方都加上 `@ai-v6`，例如
  `npm install @ai-sdk/azure@ai-v6`。
</Callout>

```typescript
import { BuiltInAgent } from "@copilotkit/runtime/v2";
import { createOpenAI } from "@ai-sdk/openai"; // [!code highlight]

const openai = createOpenAI({
  // [!code highlight]
  apiKey: process.env.OPENAI_API_KEY, // [!code highlight]
}); // [!code highlight]

const agent = new BuiltInAgent({
  model: openai("my-fine-tuned-model"), // [!code highlight]
});
```

这适用于任何 AI SDK 提供方，包括 Azure OpenAI、AWS Bedrock 和 Ollama。如果面向的是 OpenAI 兼容端点，请先阅读下一节。

```typescript
import { createAzure } from "@ai-sdk/azure";

const azure = createAzure({
  resourceName: "my-resource",
  apiKey: process.env.AZURE_API_KEY,
});

const agent = new BuiltInAgent({
  model: azure("my-deployment"),
});
```

### OpenAI 兼容提供方：使用 `provider.chat(model)`

`@ai-sdk/openai` 3.x 在直接调用 `provider(model)` 时，会把请求发送到 OpenAI 的 **Responses** API（`POST {baseURL}/responses`）。许多 OpenAI 兼容提供方并不提供该端点，只提供 Chat Completions API（`POST {baseURL}/chat/completions`）。当你把 `createOpenAI` 指向这类提供方并调用 `provider(model)` 时，智能体运行会因提供方返回的错误而失败，例如 404。

请改用 `provider.chat(model)`，它会把请求发送到 Chat Completions API：

```typescript
import { BuiltInAgent } from "@copilotkit/runtime/v2";
import { createOpenAI } from "@ai-sdk/openai";

const provider = createOpenAI({
  apiKey: process.env.PROVIDER_API_KEY,
  baseURL: "https://api.example-provider.com/v1",
});

const agent = new BuiltInAgent({
  model: provider.chat("provider-model-id"), // [!code highlight]
});
```

只有当主机支持 Responses API 时（例如 OpenAI 本身或转发到 OpenAI 的代理），才使用直接调用 `provider(model)` 的形式。`"openai:..."` 模型字符串不存在这个问题：当 `OPENAI_BASE_URL` 指向的主机既不是 OpenAI 也不是 Azure 时，内置智能体会自动为你选用 Chat Completions API（参见 [OpenAI 兼容端点](#openai-兼容端点)）。

## OpenRouter、代理与自带 LLM

任何暴露 **OpenAI 兼容** API 的服务——包括 [OpenRouter](https://openrouter.ai)、自托管网关、内部 LLM 代理、[Ollama](https://ollama.com)、[Together](https://together.ai)、[Groq](https://groq.com)、[Novita](https://novita.ai)，或你自己的微调端点——都可以通过上文[自定义模型](#自定义模型ai-sdk)中展示的同一 `createOpenAI({ baseURL })` 模式来使用。把 `baseURL` 指向该提供方的 OpenAI 兼容路由，并传入你的密钥：

<Callout type="warn" title="调用 provider.chat(model)">
  如果端点只提供 Chat Completions API——上述大多数提供方都是如此——请调用 `provider.chat("model")` 而不是
  `provider("model")`。直接调用会把请求发送到 Responses API。只有对转发 Responses API 到 OpenAI
  的代理，才保留直接调用的写法。参见 [OpenAI 兼容提供方](#openai-兼容提供方使用-providerchatmodel)。
</Callout>

```typescript
import { BuiltInAgent } from "@copilotkit/runtime/v2";
import { createOpenAI } from "@ai-sdk/openai"; // [!code highlight]

// OpenRouter: one key, hundreds of models behind an OpenAI-compatible API
const openrouter = createOpenAI({
  // [!code highlight]
  apiKey: process.env.OPENROUTER_API_KEY, // [!code highlight]
  baseURL: "https://openrouter.ai/api/v1", // [!code highlight]
}); // [!code highlight]

const agent = new BuiltInAgent({
  model: openrouter.chat("anthropic/claude-sonnet-4-6"), // [!code highlight]
});
```

同样的写法适用于任何 OpenAI 兼容代理，只需替换 `baseURL` 和密钥。
无需安装 CopilotKit 专用的提供方，按[自定义模型](#自定义模型ai-sdk)所示安装
`@ai-sdk/openai@ai-v6` 即可。只要 AI SDK 能与之通信，内置智能体就能使用它。

<Callout type="warn" title="模型在智能体上设置">
  CopilotKit **没有**提供用于在请求时选择或切换模型的云端托管端点。模型是在**智能体上**配置的，
  形式为 `"provider:model"` 字符串或 AI SDK 的 `LanguageModel` 实例：

```typescript
new BuiltInAgent({ model: "openai:gpt-5.4-mini" }); // built-in string
new BuiltInAgent({ model: openrouter.chat("...") }); // any LanguageModel
```

若要按用户、请求或特性开关切换模型，请在你自己的后端以所需的 `model` 构建智能体。若要完全掌控运行时，还可以使用[自定义智能体](/backend/custom-agent)。

</Callout>

## 工作原理

内置智能体会将模型字符串解析为 AI SDK 提供方实例：

| 模型字符串                      | AI SDK 提供方       | 解析后的调用                     |
| ------------------------------- | ------------------- | -------------------------------- |
| `"openai:gpt-5.4-mini"`         | `@ai-sdk/openai`    | `openai("gpt-5.4-mini")`         |
| `"anthropic:claude-sonnet-4-6"` | `@ai-sdk/anthropic` | `anthropic("claude-sonnet-4-6")` |
| `"google:gemini-3.8-flash"`     | `@ai-sdk/google`    | `google("gemini-3.8-flash")`     |

`"provider:model"` 与 `"provider/model"` 两种分隔符都受支持，效果完全相同。

<Callout type="info" title="需要其他 AI SDK 或完全掌控？">
  [自定义智能体](/backend/custom-agent)让你接入自己的 AI SDK、TanStack AI
  或任意自定义 LLM 后端，其余交给 CopilotKit 处理。
</Callout>
