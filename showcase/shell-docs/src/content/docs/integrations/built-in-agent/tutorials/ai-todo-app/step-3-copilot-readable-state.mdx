现在，应用中已经有了聊天弹窗，我们可以直接与 copilot 对话。这很棒，但我们的 copilot 对应用还一无所知。在这一步中，我们将向 copilot 提供待办事项的状态。

在这一步中，你将学到如何向 copilot 提供知识。就本例而言，我们希望 copilot 了解应用中的任务。

## 应用的状态

我们先快速回顾一下应用状态的工作方式。打开 [`lib/hooks/use-tasks.tsx`](https://github.com/CopilotKit/CopilotKit/tree/main/examples/starters/todos-app/start/lib/hooks/use-tasks.tsx) 文件。

一眼望去就能发现，该文件暴露了一个 provider（`TasksProvider`），它定义了以下实用的内容：

- 任务状态（`tasks`）
- 添加任务的函数（`addTask`）
- 更新任务的函数（`updateTask`）
- 删除任务的函数（`deleteTask`）

这些内容都可以通过 `useTasks` 钩子消费，应用的其余部分正是使用它（欢迎查看 `TasksList`、`AddTask` 和 `Task` 组件）。

这与大多数 React 应用类似：无论是单个功能还是整个应用的前端状态，都由 context 或状态管理库来管理。

## `useAgentContext` 钩子

我们的目标是让 copilot 感知到这份状态，从而提供更准确、更有用的回复。借助 [`useAgentContext`](/reference/hooks/useAgentContext) 钩子即可轻松实现。

```tsx title="lib/hooks/use-tasks.tsx" {3,8-11}
// ... the rest of the file

import { useAgentContext } from "@copilotkit/react-core/v2"; // [!code highlight]

export const TasksProvider = ({ children }: { children: ReactNode }) => {
  const [tasks, setTasks] = useState<Task[]>(defaultTasks);

  // [!code highlight:4]
  useAgentContext({
    description: "The state of the todo list",
    value: JSON.stringify(tasks),
  });

  // ... the rest of the file
};
```

在这个示例中，我们使用 `useAgentContext` 钩子向 copilot 提供任务的状态。

- 对于 `description` 属性，我们提供一段简洁的描述，告诉 copilot 这份可读数据的含义。
- 对于 `value` 属性，我们将整个状态以 JSON 字符串的形式传入。
