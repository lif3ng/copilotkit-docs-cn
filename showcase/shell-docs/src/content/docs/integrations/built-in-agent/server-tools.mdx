## 什么是服务器工具？

服务器工具是运行在你的后端、可被内置智能体调用的函数。它们通过 `defineTool()` 定义，并使用 Zod schema 保证参数的类型安全。

## 什么时候应该使用它？

- 你的智能体需要访问数据库、API 或其他后端服务
- 你希望工具参数具备带校验的类型安全
- 工具逻辑需要用到服务器端的密钥或资源

<Callout type="warn" title="工具运行在服务器上，而 UI 依然运行在浏览器中">
`execute` 运行在你的服务器上，因此它能访问密钥、数据库或内部服务——但它无法触及 DOM、组件状态或页面中的任何其他内容。当*操作*本身属于浏览器时，请改将它注册为[前端工具](/frontend-tools)。

渲染与执行是相互独立的。服务器工具的调用依然会流式传输到浏览器，因此你可以在 `execute` 继续运行于服务器的同时，用同名工具的仅渲染注册为它提供 UI。

<FrontendOnly frontend="react">
使用 [`useFrontendTool`](/frontend-tools) 处理浏览器端的操作，并用 `useRenderTool` 进行仅渲染注册。
</FrontendOnly>
<FrontendOnly frontend="angular">
使用 [`registerFrontendTool`](/reference/angular/functions/registerFrontendTool) 处理浏览器端的操作，并用 [`registerRenderToolCall`](/reference/angular/functions/registerRenderToolCall) 进行仅渲染注册。
</FrontendOnly>
</Callout>

## 定义工具

```typescript title="src/copilotkit.ts"
import { BuiltInAgent, defineTool } from "@copilotkit/runtime/v2";
import { z } from "zod";

const getWeather = defineTool({
  name: "getWeather",
  description: "Get the current weather for a location",
  parameters: z.object({
    location: z.string().describe("The location's name"),
  }),
  execute: async ({ location }) => {
    // Your implementation here
    return { temperature: 72, condition: "sunny", location };
  },
});

const builtInAgent = new BuiltInAgent({
  model: "openai:gpt-5.4-mini",
  tools: [getWeather],
  maxSteps: 2                   //Important for tool calls
});
```

<Callout type="warn" title="`parameters` 接受的是 schema 校验器，而非 JSON Schema">
`parameters` 必须是 Standard Schema v1 校验器——Zod、Valibot、ArkType 等均可。传入普通的 JSON Schema 对象会在工具 schema 转换过程中抛出错误。校验器同时还是 `execute` 推断参数类型的依据，因此手写的 JSON Schema 也会失去这一能力。
</Callout>

## 工具响应

工具可以返回任何可 JSON 序列化的值。智能体会利用该响应继续对话。

## 多个工具

传入一个工具数组——智能体会根据用户的请求选择调用哪一个：

<Callout type="warn" title="需要避开的两个名称">
`AGUISendStateSnapshot` 和 `AGUISendStateDelta` 会在内置智能体自行发起模型调用时自动注入。如果你用这两个名称之一去定义自己的工具，就会替换掉内置工具并破坏共享状态。

服务器工具在与前端工具重名时也总是胜出：如果在两侧都定义 `getWeather`，模型只会看到服务器端的那个，前端处理器永远不会触发。当两侧都需要各自的工具时，请给它们取不同的名称。
</Callout>

```typescript title="src/copilotkit.ts"
const searchDocs = defineTool({
  name: "searchDocs",
  description: "Search the documentation for relevant articles",
  parameters: z.object({
    query: z.string().describe("The search query"),
  }),
  execute: async ({ query }) => {
    const results = await search(query);
    return { results, count: results.length };
  },
});

const createTicket = defineTool({
  name: "createTicket",
  description: "Create a support ticket",
  parameters: z.object({
    title: z.string().describe("Ticket title"),
    priority: z.enum(["low", "medium", "high"]).describe("Ticket priority"),
    description: z.string().describe("Detailed description of the issue"),
  }),
  execute: async ({ title, priority, description }) => {
    const ticket = await db.tickets.create({ title, priority, description });
    return { ticketId: ticket.id, status: "created" };
  },
});

const builtInAgent = new BuiltInAgent({
  model: "openai:gpt-5.4-mini",
  tools: [searchDocs, createTicket], // [!code highlight]
  maxSteps: 2                        
});
```

## 复杂的 Zod schema

使用嵌套对象、数组、枚举和可选字段来构建复杂的工具参数：

```typescript
const bookFlight = defineTool({
  name: "bookFlight",
  description: "Search for and book flights",
  parameters: z.object({
    trip: z.object({
      origin: z.string().describe("Origin airport code (e.g., SFO)"),
      destination: z.string().describe("Destination airport code (e.g., JFK)"),
      date: z.string().describe("Departure date in YYYY-MM-DD format"),
    }),
    passengers: z.array(
      z.object({
        name: z.string(),
        seatPreference: z.enum(["window", "middle", "aisle"]).optional(),
      })
    ).describe("List of passengers"),
    class: z.enum(["economy", "business", "first"]).default("economy"),
  }),
  execute: async ({ trip, passengers, class: seatClass }) => {
    const flights = await searchFlights(trip, seatClass);
    return { flights, passengerCount: passengers.length };
  },
});
```

## 错误处理

在工具中抛出错误或返回错误对象——智能体会看到该错误，并能告知用户或尝试其他方案：

```typescript
const getUser = defineTool({
  name: "getUser",
  description: "Look up a user by email",
  parameters: z.object({
    email: z.string().email().describe("The user's email address"),
  }),
  execute: async ({ email }) => {
    const user = await db.users.findByEmail(email);
    if (!user) {
      throw new Error(`No user found with email: ${email}`); // [!code highlight]
    }
    return { id: user.id, name: user.name, role: user.role };
  },
});
```

<Callout type="warn" title="返回纯数据">
工具返回的任何内容在模型看到之前都会被序列化。类实例、循环引用，或任何 `JSON.stringify` 无法处理的内容，都会被替换为一个指明工具名称的占位字符串，模型会基于该字符串而非你的数据进行推理。请返回纯对象、数组和原始值——错误结构也不例外。
</Callout>

## 多步骤工具调用

默认情况下，智能体只执行单个步骤。如果你的智能体需要串联多个工具调用（例如先搜索、再创建工单），请设置 `maxSteps`：

```typescript
const builtInAgent = new BuiltInAgent({
  model: "openai:gpt-5.4-mini",
  maxSteps: 5, // [!code highlight]
  tools: [searchDocs, createTicket, getUser],
});
```

设置 `maxSteps: 5` 后，智能体可以：
1. 调用 `searchDocs` 查找相关信息
2. 处理结果
3. 使用搜索得到的详情调用 `createTicket`
4. 持续执行直至完成（最多 5 次迭代）

<Callout type="info">
更多选项（如 `toolChoice`、`temperature` 和 `providerOptions`）请参阅[高级配置](/advanced-configuration)。
</Callout>

<Callout type="warn" title="工厂会忽略 `tools` 数组">
本页所有内容描述的都是通过 `model` 和 `tools` 构建的内置智能体。如果你改用 `factory` 来构建，`tools` 数组将不会被读取——模型调用由工厂负责，因此工具必须由工厂自行传入。请先用 `convertToolDefinitionsToVercelAITools`（针对 AI SDK 工厂）或你所选运行时的等价转换器完成转换，再把结果传给工厂发起的调用。
</Callout>

<Callout type="info" title="使用自定义后端？">
  如果你使用的是[自定义智能体](/backend/custom-agent)而非 `BuiltInAgent`，请参阅 “With Tools” 示例，了解如何在 AI SDK、TanStack AI 或自定义后端中接入工具。
</Callout>
