## 简介

AG2（1.0+）通过把一个智能体变成工具来实现委托。`Agent.as_tool()` 返回一个普通工具，当协调者的模型调用它时，会在对方自己隔离的流中、以其自己的历史记录运行该智能体。协调者的上下文保持精简，而是否委托的决定权仍留在模型手中。

CopilotKit 会以两种形式看到每一次委托：既是一次普通工具调用，也是一次 AG-UI 1.0 **子智能体调用**（`SUBAGENT_STARTED`、`SUBAGENT_FINISHED`、`SUBAGENT_ERROR`），因此无需在后端做任何额外接线，你就能渲染 “正在研究……” / “正在撰写……” 这类进度。

<Callout type="info">
  CopilotKit 消费 AG2 通过 <code>/chat</code> 流式传输的 AG-UI 协议事件。参见 <a href="https://docs.ag2.ai/docs/user-guide/ag-ui/" target="_blank">AG2 AG-UI 集成文档</a> 与上游的 <a href="https://docs.ag2.ai/docs/user-guide/subagents/" target="_blank">AG2 子智能体指南</a>。
</Callout>

## 后端

安装带 AG-UI 与 OpenAI 附加依赖的 AG2：

```bash
pip install "ag2[ag-ui,openai]>=1.1.2"
```

把每个专家智能体构建成普通的 `Agent`，再作为工具交给协调者。只有协调者被包在 `AGUIStream` 中——专家智能体通过它被访问：

```python title="agent.py"
from typing import Annotated

from fastapi import FastAPI, Header
from fastapi.responses import StreamingResponse
from pydantic import Field

from ag2 import Agent, tool
from ag2.ag_ui import AGUIStream, RunAgentInput
from ag2.config import OpenAIResponsesConfig

@tool
def search_docs(
    query: Annotated[str, Field(description="What to look up")],
) -> str:
    """Look a topic up in the product documentation."""
    return f"Docs say: {query} is supported since v1.0."

researcher = Agent(
    name="researcher",
    prompt="You research topics using the documentation tool and report findings plainly.",
    config=OpenAIResponsesConfig(model="gpt-5.5"),
    tools=[search_docs],
)

writer = Agent(
    name="writer",
    prompt="You turn research notes into a single tight paragraph.",
    config=OpenAIResponsesConfig(model="gpt-5.5"),
)

coordinator = Agent(
    name="coordinator",
    prompt=(
        "You coordinate specialists. Delegate research to `task_researcher`, "
        "then hand the findings to `task_writer`. Do not answer from memory."
    ),
    config=OpenAIResponsesConfig(model="gpt-5.5"),
    tools=[
        researcher.as_tool(description="Research a topic in the product docs."),
        writer.as_tool(description="Turn research notes into one paragraph."),
    ],
)

stream = AGUIStream(coordinator)
app = FastAPI()

@app.post("/chat")
async def run_agent(
    message: RunAgentInput,
    accept: str | None = Header(None),
) -> StreamingResponse:
    return StreamingResponse(
        stream.dispatch(message, accept=accept),
        media_type=accept or "text/event-stream",
    )
```

`as_tool()` 默认把工具命名为 `task_<agent name>`——即上面的 `task_researcher` 和 `task_writer`。传入 `name=` 可以覆盖默认命名；`description=` 则是必填的：它是协调者的模型在决定是否委托时唯一会阅读的内容。

## 前端能收到什么

每次委托都会产生一次工具调用和一次子智能体调用，后者带有自己的 `subagentRunId`，因此并行的两次对同一智能体的委托也能区分开：

```text
RUN_STARTED
TOOL_CALL_START      toolCallName: "task_researcher"
TOOL_CALL_ARGS
SUBAGENT_STARTED     subagentRunId: "4f1c…", name: "researcher", description: "<the objective>"
SUBAGENT_FINISHED    subagentRunId: "4f1c…", result: "<what it returned>"
TOOL_CALL_RESULT
TOOL_CALL_END
…
TEXT_MESSAGE_CHUNK
RUN_FINISHED
```

- 失败的委托以携带消息的 `SUBAGENT_ERROR` 结束，而运行会继续进行：协调者的模型会被告知该委托已失败，并可能自行恢复。被取消或超时的委托同样以 `SUBAGENT_ERROR` 结束（`cancelled` 或 `expired`）。
- 这些事件不携带用量信息；运行自身的用量已经包含了委托消耗的部分。
- 委托不再以 `STEP_STARTED` / `STEP_FINISHED` 的形式上报。如果你之前基于 `task:<agent name>` 步骤做了过滤，请改为订阅 `SUBAGENT_*` 事件。
- 如果专家智能体向人类提问，它会像其他任何[中断](/ag2/human-in-the-loop#approve-a-tool-call-with-interrupts)一样到达客户端，并附上该调用的 `subagentRunId` 标记。

在基于它构建 UI 之前，有两个值得了解的后果：

- **委托就是普通的工具调用**。凡是能对工具调用做的事，对子智能体同样适用——用 `useRenderTool` 渲染它，或交给默认的工具渲染器展示。参见[工具渲染](/ag2/generative-ui/tool-rendering)。
- **专家智能体自己的工具调用留在它自己的流里。** 上面的 `search_docs` 运行在 `researcher` 的隔离流中，因此它不会作为单独的 `TOOL_CALL_*` 对出现在协调者的 AG-UI 输出里。如果你需要这种可见性，请为专家智能体提供自己的端点，而不是委托给它。
- **共享状态不会从专家智能体流回。** 委托会拿到协调者会话变量的一个*副本*，而专家智能体对 `context.variables` 的写入被有意地不合并回去——否则并发委托会互相覆盖。写状态的专家智能体既不会改变 UI 所见的任何东西，也不会报错。请从委托中返回该值，改由协调者写入。依赖项也以同样方式复制，因此 `Inject(...)` 在专家智能体内部依然有效。

## 用 `agent.subscribe` 跟踪委托

对于侧边面板或进度列表，通过 `useAgent` 拿到的 agent 订阅调用事件。在携带其 `subagentRunId` 的 finished 或 error 事件到达之前，该运行都视为仍在进行，因此不需要单独的运行记录：

```tsx title="components/agent-panel.tsx"
import type {
  SubagentErrorEvent,
  SubagentFinishedEvent,
  SubagentStartedEvent,
} from "@ag-ui/client";
import { useAgent } from "@copilotkit/react-core/v2";
import { useEffect, useState } from "react";

export function SubagentPanel() {
  const { agent } = useAgent({ agentId: "my_agent" });
  const [started, setStarted] = useState<SubagentStartedEvent[]>([]);
  const [finished, setFinished] = useState<Record<string, SubagentFinishedEvent>>({});
  const [failed, setFailed] = useState<Record<string, SubagentErrorEvent>>({});

  useEffect(() => {
    const subscription = agent.subscribe({
      onRunStartedEvent: () => {
        setStarted([]);
        setFinished({});
        setFailed({});
      },
      onSubagentStartedEvent: ({ event }) => setStarted((all) => [...all, event]),
      onSubagentFinishedEvent: ({ event }) =>
        setFinished((all) => ({ ...all, [event.subagentRunId]: event })),
      onSubagentErrorEvent: ({ event }) =>
        setFailed((all) => ({ ...all, [event.subagentRunId]: event })),
    });
    return () => subscription.unsubscribe();
  }, [agent]);

  return (
    <ul>
      {started.map((run) => (
        <li key={run.subagentRunId}>
          {run.name}:{" "}
          {failed[run.subagentRunId] ? "failed" : finished[run.subagentRunId] ? "done" : "running…"}
        </li>
      ))}
    </ul>
  );
}
```

## 在聊天中渲染委托

由于委托就是一次工具调用，渲染它走的是普通的工具渲染路径：

```tsx title="app/page.tsx"
import { z } from "zod";
import { useRenderTool } from "@copilotkit/react-core/v2";
// ...

const YourMainContent = () => {
  // ...
  useRenderTool({
    name: "task_researcher",
    parameters: z.object({
      objective: z.string(),
      context: z.string().optional(),
    }),
    render: ({ status }) => (
      <p className="text-gray-500 mt-2">
        {status !== "complete" && "Researching..."}
        {status === "complete" && "Research done."}
      </p>
    ),
  });
  // ...
};
```

具名的 `useRenderTool` 注册需要 `parameters` 模式——只有通配（`name: "*"`）重载可以省略它。每次 `as_tool()` 委托都接受相同的两个参数：`objective` 和可选的 `context`，因此上面的模式适用于任何子智能体。

## 在委托与单智能体之间抉择

当某个步骤需要自己的指令、自己的工具或自己的历史时，就使用 `as_tool()`——一个可能要发起十几次工具调用的 `researcher` 不应污染协调者的上下文。当工作只是带少量工具的单个提示时，保持单智能体即可：每一次交接，委托都要多付出一次模型往返。
