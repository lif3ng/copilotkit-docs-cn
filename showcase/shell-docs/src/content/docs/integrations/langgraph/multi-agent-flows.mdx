## 什么是多智能体流？

在构建智能体化应用时，你常常需要编排需要多个智能体协同配合的复杂流。这在传统上称为多智能体编排（multi-agent orchestration）。

## 何时使用？

当你需要编排需要多个智能体协同配合的复杂流时，多智能体流就能派上用场。随着智能体化应用规模的增长，将子任务委托给其他智能体可以帮助你扩展应用的关键部分。

- 将上下文切分为更小的块
- 将子任务委托给其他智能体
- 用单个智能体来编排整个流

## CopilotKit 如何支持？

CopilotKit 可以在两种不同的模式下使用：**路由模式**（Router Mode）或 **Agent Lock**。默认情况下，CopilotKit 使用路由模式，利用你配置的 LLM 在智能体之间路由请求。

### 路由模式（默认）

使用 CoAgents 时默认启用路由模式。要使用它，请在 `CopilotKit` provider 组件中指定 runtime URL prop，并省略 `agent` prop，如下所示：

```tsx
<CopilotKit runtimeUrl="<copilot-runtime-url>">
  {/* Your application components */}
</CopilotKit>
```

在路由模式下，CopilotKit 充当中央枢纽，根据用户的输入在不同智能体或操作之间动态选择并 _路由_ 请求。这种模式适合以聊天为先的体验：LLM 聊天机器人是各种交互的入口，交互既可以留在聊天 UI 中，也可以扩展为原生 React UI 组件。

在此模式下，CopilotKit 会根据上下文和用户输入，将请求智能地路由到最合适的智能体或操作。

请注意，使用此模式时，你需要在智能体代码中显式地“退出工作流”。
更多信息请参阅[“退出智能体循环”一节](/integrations/langgraph/advanced/exit-agent)。

<Callout type="warn">
  路由模式要求你先配置 LLM 适配器。配置方法请参阅文档中的[“配置 Copilot
  Runtime”](/quickstart?copilot-hosting=self-hosted#set-up-a-copilot-runtime-endpoint)一节。
</Callout>

### Agent Lock 模式

要使用 Agent Lock 模式，请在 `CopilotKit` 组件中通过 `agent` prop 指定智能体名称：

```tsx
// [!code word:agent]
<CopilotKit runtimeUrl="<copilot-runtime-url>" agent="<the-name-of-the-agent>">
  {/* Your application components */}
</CopilotKit>
```

在此模式下，CopilotKit 被配置为只与特定智能体协作。当你想专注于某个特定任务或领域时，这种模式非常有用。路由模式下，LLM 和 CopilotKit 的路由器可以在各智能体之间自由切换以处理用户请求；而 Agent Lock 模式下，所有请求都会留在单个工作流图中，从而确保对工作流的精确控制。

哪种模式最适合你的应用体验就用哪种！另外请注意，虽然 `CopilotKit` provider 不能嵌套，但你可以在应用的不同区域使用不同的智能体或模式——例如，你可以让一个处于路由模式的聊天机器人调用任意智能体或工具，同时在其他位置集成某个特定智能体，以获得更聚焦的工作流。
