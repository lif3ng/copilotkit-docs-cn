## 在现有应用中添加 Intelligence

围绕你的 LangGraph 智能体，为用户提供跨设备的重连、进度补看与消息送达能力。按照 [Intelligence 快速开始](/intelligence/quickstart)连接你现有的 CopilotKit 应用与 Runtime，然后确认新对话能够被保存。这会为经由 CopilotKit 的运行启用 AG-UI 流，无需任何历史导入。

保持你的 LangGraph 智能体及其持久化存储处于连接状态，以便在导入对话之后能够继续这些对话。参见[流如何与框架存储协同工作](/intelligence/threads-explained#how-threads-work-with-framework-storage)。

## 纳入更早的对话（可选）

要让用户能够重新打开在接入 Intelligence 之前记录的对话，可使用下方的导入器复制受支持的历史内容。导入不会启用实时送达，也不会建立持续的数据库复制，并且无法恢复源端已不再暴露的历史。

LangGraph 导入器会从 LangGraph Server / LangSmith 部署（Python 或 TypeScript）以及带持久化的 Python FastAPI 应用中读取已保存的对话。它会迁移已保存的消息、富工具结果、附件以及可用的智能体状态。某些交互内容（例如 MCP 应用视图）可能未在原始历史中保存。

以下前置条件与命令仅适用于该历史导入。可使用 Threads Drawer（线程抽屉）或[无头线程（Headless Threads）](/headless-threads)通过同一套 UI 打开导入的对话和新对话。

## 前置条件

- 一个已接入 Intelligence 的现有 CopilotKit 应用。
- 保存在持久化存储中的 LangGraph 对话。进程退出后，内存中的对话无法再导入。
- 对于 **LangSmith**，需要你的 LangGraph Server / LangSmith 部署 URL 与 API 密钥。
- 对于 **FastAPI**，需要能访问你的 Python 应用编译后的图及其持久化 checkpointer（保存对话状态的存储）。

## 确认目标项目

选择将接收这些历史的 Intelligence 项目。其 app-api URL 与项目级 runtime 密钥共同确定目标位置。导入前你需要先导出这些值。

对于 CLI 创建的应用，你可以选择一个云端托管的项目：

```bash title="Terminal"
npx copilotkit@latest project select
```

该命令会更新当前目录所选的项目，并把该项目级 runtime 密钥写入应用生成的 `.env`。

## 配置来源

选择你在 [LangGraph 快速开始](/quickstart)中使用的同一套配置：使用 LangGraph Server 的 Python 或 TypeScript 智能体选 **LangSmith**；运行在你自己 FastAPI 应用中的 Python 智能体选 **FastAPI**。

<Tabs groupId="deployment_method" items={['LangSmith', 'FastAPI']}>
  <Tab value="LangSmith">
    在你的 shell 中设置 LangGraph 部署 URL 与 API 密钥。导入器从框架原生的环境变量读取来源凭据，而不是从原始 CLI 标志读取。

    ```bash title="Terminal"
    export LANGGRAPH_API_URL="https://your-langgraph-deployment"
    export LANGGRAPH_API_KEY="..."
    ```

    如果你的部署采用这种认证方式，也可以改用 `LANGSMITH_API_KEY` 或 `LANGCHAIN_API_KEY`。如果你的 LangGraph Cloud 工作区要求租户请求头，请设置 `LANGGRAPH_TENANT_ID` 或 `LANGSMITH_TENANT_ID`。

    下面的示例假设每个线程在 LangGraph 元数据中都有顶层 `user_id` 字段。其值必须与你的 runtime 通过 `identifyUser` 返回的应用用户 ID 一致。使用 `--user-source metadata.user_id` 读取该字段。如果所有来源线程都属于同一个用户，则使用 `--user-source literal:user-123` 并填入该用户的实际 ID。

    每个选中的线程应只属于一个图。横跨多个图 ID 的线程会被跳过。
  </Tab>
  <Tab value="FastAPI">
    在导入之前，先从你现有的图中导出对话。FastAPI 智能体端点并不提供 LangGraph Server 的历史 API。

    把导出辅助脚本下载到你的 Python 应用的工具目录：

    ```bash title="Terminal"
    curl -fsSL https://unpkg.com/copilotkit@4.22.0/exporters/langgraph/export_checkpointer.py \
      -o export_checkpointer.py
    ```

    在该辅助脚本旁添加这个函数：

    ```python title="export_history.py"
    import json
    from export_checkpointer import export_thread

    async def export_history(graph, thread_ids):
        with open("history.jsonl", "w", encoding="utf-8") as output:
            for thread_id in thread_ids:
                record = await export_thread(
                    graph,
                    {"configurable": {"thread_id": thread_id}},
                    source_id="my-fastapi-app",
                    graph_id="support_graph",
                )
                output.write(json.dumps(record, allow_nan=False) + "\n")
    ```

    在你的应用的异步工具中，于现有图与 checkpointer 处于打开状态时调用 `await export_history(graph, thread_ids)`。使用你的应用为同一个用户保留的线程 ID，并在这些对话空闲时导出。这一步只读取已保存的历史，不会运行智能体。

    为 `source_id` 选定一个名称，并在之后从该存储导出时保持不变。将 `graph_id` 设置为你稍后在下方智能体映射中使用的图名称。导出会生成 `history.jsonl`；该文件包含对话数据，请妥善保管。
  </Tab>
</Tabs>


## 执行试运行

先从预览开始。这一步会读取来源、发现图 ID、统计对话数量、报告跳过项，并估算上传体积，而不会写入 CopilotKit Intelligence。它不需要 CopilotKit Intelligence 的 URL 或 API 密钥。

<Tabs groupId="deployment_method" items={['LangSmith', 'FastAPI']}>
  <Tab value="LangSmith">
    ```bash title="Terminal"
    npx copilotkit@latest import --source langgraph --user-source metadata.user_id --dry-run
    ```
  </Tab>
  <Tab value="FastAPI">
    ```bash title="Terminal"
    npx copilotkit@latest import --source langgraph \
      --langgraph-snapshot ./history.jsonl --user-source literal:user-123 --dry-run
    ```
  </Tab>
</Tabs>

## 将图 ID 映射到 CopilotKit 智能体 ID

把每个来源图 ID 映射到你线上 CopilotKit runtime 使用的 `agentId`。LangSmith 场景使用发现的 `graph_id`；FastAPI 场景使用你导出时提供的 `graph_id`。

```json title="agent-map.json"
{
  "support": "support"
}
```

本示例把 LangGraph 图 `support` 映射到 runtime 智能体 `support`。请将这两个值替换为你应用的 ID。导入与后续运行应使用同一个 runtime 智能体 ID。

## 准备 CopilotKit Intelligence 目标

真正的导入需要目标 app-api URL 与项目级 runtime 密钥。CLI 创建的起步模板会把它们写入 `.env`，但导入器读取的是当前进程环境，不会自动加载 `.env` 或 `.copilotkit/project.json`。

导入前，把这些生成的值复制到你的 shell 中：

```bash title="Terminal"
export INTELLIGENCE_API_URL="https://..."
export CPK_INTELLIGENCE_API_KEY="cpk-..."
```

你也可以改用 `--api-url` 与 `--api-key` 直接传入目标信息。

## 导入线程

在试运行与智能体映射都确认无误后再执行导入。对这些线程而言，要在第一次接入式运行之前导入更早的历史。如果实时记录或其他导入已占用了原生线程 ID，导入器会报告 `IMPORT_NATIVE_ID_CONFLICT`，且不会覆盖该记录。

<Tabs groupId="deployment_method" items={['LangSmith', 'FastAPI']}>
  <Tab value="LangSmith">
    ```bash title="Terminal"
    npx copilotkit@latest import \
      --source langgraph \
      --agent-map ./agent-map.json \
      --user-source metadata.user_id
    ```

    使用 `--user-source` 告诉导入器从哪里查找每个线程的终端用户 ID。如果所有选中的线程都属于同一个用户，也可以改用 `--user-source literal:user-123`。
  </Tab>
  <Tab value="FastAPI">
    ```bash title="Terminal"
    npx copilotkit@latest import \
      --source langgraph \
      --langgraph-snapshot ./history.jsonl \
      --agent-map ./agent-map.json \
      --user-source literal:user-123
    ```

    把 `user-123` 替换为你的 Runtime 通过 `identifyUser` 返回的应用用户 ID。这会把该导出中的每个对话都归属到该用户；每个用户的导出需分别导入。
  </Tab>
</Tabs>

对于自托管的 CopilotKit Intelligence，在命令中添加 `--api-url "$INTELLIGENCE_API_URL"` 与 `--api-key "$CPK_INTELLIGENCE_API_KEY"`。添加 `--yes` 可跳过确认提示。

## 验证导入的线程

以你导入其 ID 的那个应用用户身份登录。从 Threads Drawer 打开该对话，确认更早的消息能够显示。发送一条消息，确认 LangGraph 更新的是同一个原生线程。Intelligence 会把这次新的交互连同已导入的历史一起记录。

## 重新运行或替换

默认情况下，已导入过的对话会被跳过。

使用 `--replace` 刷新它们；正在运行或已继续的对话保持不变。将该标志加到上面同一条导入命令中，保留其来源、智能体映射与用户选择。

## 继续使用 LangGraph 持久化

导入只是复制受支持的历史，不会建立持续的数据库复制。Intelligence 的重命名、归档与删除操作只影响 Intelligence 记录，原生 LangGraph 线程记录保持不变。

你的应用会把之后的对话经由 CopilotKit 发送到 CopilotKit Intelligence。保持原有的 LangGraph 智能体及其持久化存储处于连接状态，并从 Threads Drawer 重新打开已导入的对话，即可从中断处继续，包括受支持的待审批项与输入请求。

- **Threads Drawer**：CLI 创建的起步模板已内置。使用 [Threads Drawer 指南](/prebuilt-components/copilot-threads-drawer)自定义其现成的线程 UI。
- **无头线程**（Headless Threads）：仅当你需要自定义 UI 时才使用[无头线程指南](/headless-threads)。用 `useThreads` 选中一个线程，保存其 `thread.id`，并把该值作为 `threadId` 传给你的聊天组件。

如果你的后端会把 CopilotKit 线程 ID 映射到 LangGraph 线程 ID，请保持该映射稳定，这样恢复的 CopilotKit 线程才能到达预期的 LangGraph 线程。LangGraph Platform 的线程 ID 必须是 UUID，因此必要时请持久化保存映射，而不要直接复用 CopilotKit 的 `threadId`。

打开一个已导入的对话并发送后续消息，即可继续它。

如果想要自动记录而不做历史导入，请参考[保留现有 LangGraph 对话示例](/threads-lifecycle#example-keep-an-existing-langgraph-conversation)。
