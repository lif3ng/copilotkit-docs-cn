## 我的工具调用没有流式输出

这可能由多种原因导致。

首先，我们强烈建议阅读[人机协同（human-in-the-loop）](/langgraph/human-in-the-loop)指南，其中有更深入的示例，讲解如何在 LangGraph 智能体中流式输出工具调用。
你也可以查看我们的[旅行教程](/langgraph/tutorials/ai-travel-app/step-6-human-in-the-loop)，了解如何在更复杂的示例中流式输出工具调用。

如果已经看过上述内容，可以继续检查以下几点：

<Accordions>
    <Accordion title="你使用的是 llm.invoke() 而不是 llm.ainvoke()">
        <p>
            调用 LangGraph 智能体时，可以选择同步或异步方式。如果同步调用，
            工具调用不会逐步流式输出，只会流式输出最终结果；如果异步调用，
            工具调用则会逐步流式输出。

            ```python
            config = copilotkit_customize_config(config, emit_tool_calls=["say_hello_to"])
            response = await llm_with_tools.ainvoke(
                [ SystemMessage(content=system_message), *state["messages"] ],
                config=config
            )
            ```
        </p>
    </Accordion>

</Accordions>

## 报错：`'AzureOpenAI' object has no attribute 'bind_tools'`

此报错通常是由于从 LangGraph 导入了错误的类。把 `AzureOpenAI` 换成 `AzureChatOpenAI` 来导入，问题即可解决。

```python
from langchain_openai import AzureOpenAI # [!code --]
from langchain_openai import AzureChatOpenAI # [!code ++]
```

## 我遇到了 “agent not found” 报错

如果看到此报错，说明 CopilotKit 找不到你想使用的 LangGraph 智能体。排查方法如下：

<Accordions>
    <Accordion title="检查 agent lock mode 配置">
        如果你在使用 agent lock mode，
        请检查 `langgraph.json` 中定义的 agent 与 CopilotKit provider 中定义的是否一致：

        ```json title="langgraph.json"
        {
            "python_version": "3.12",
            "dockerfile_lines": [],
            "dependencies": ["."],
            "graphs": {
                "my_agent": "./src/agent.py:graph"// In this case, "my_agent" is the agent you're using // [!code highlight]
            },
            "env": ".env"
        }
        ```

        ```tsx title="layout.tsx"
        {/* [!code highlight:1] */}
        <CopilotKit agent="my_agent">
            {/* Your application components */}
        </CopilotKit>
        ```

        常见问题：
        - agent 名称拼写错误
        - 大小写不一致
        - `langgraph.json` 中缺少条目
    </Accordion>
    <Accordion title="检查智能体在 LangGraph Platform 端点上的注册">
        使用 LangGraph Platform 端点时，请确保智能体已正确声明，且与 `langgraph.json` 中的定义一致：

        ```json title="langgraph.json"
        {
            "python_version": "3.12",
            "dockerfile_lines": [],
            "dependencies": ["."],
            "graphs": {
                "my_agent": "./src/agent.py:graph"// In this case, "my_agent" is the agent you're using // [!code highlight]
            },
            "env": ".env"
        }
        ```

        ```typescript title="/copilotkit/api/route.ts"
        const runtime = new CopilotRuntime({
          // ... The rest of your CopilotRuntime definition
          // [!code highlight:7]
          agents: {
            'my_agent': new LangGraphAgent({
              deploymentUrl: '<your-api-url>',
              graphId: 'my_agent',
              langsmithApiKey: '<your-langsmith-api-key>' // Optional
            }),
          },
        });
        ```
    </Accordion>
    <Accordion title="检查 useAgent 中的智能体名称">
        确保 `langgraph.json` 中定义的 agent 与传给 `useAgent` hook 的 `agentId` 一致：

        ```json title="langgraph.json"
        {
            "python_version": "3.12",
            "dockerfile_lines": [],
            "dependencies": ["."],
            "graphs": {
                "my_agent": "./src/agent.py:graph"// In this case, "my_agent" is the agent you're using // [!code highlight]
            },
            "env": ".env"
        }
        ```

        ```tsx title="MyComponent.tsx"
        // Your React component
        useAgent({
            agentId: "my_agent", // [!code focus]
        });
        ```
    </Accordion>
    <Accordion title="检查 useCoAgentStateRender 中的智能体名称">
        确保 `langgraph.json` 中定义的 agent 与传给 `useCoAgentStateRender` hook 的 `name` 一致：

        ```json title="langgraph.json"
        {
            "python_version": "3.12",
            "dockerfile_lines": [],
            "dependencies": ["."],
            "graphs": {
                "my_agent": "./src/agent.py:graph"// In this case, "my_agent" is the agent you're using // [!code highlight]
            },
            "env": ".env"
        }
        ```

        ```tsx title="MyComponent.tsx"
        // Your React component
        useCoAgentStateRender({
            name: "my_agent", // [!code focus] This must match exactly
        });
        ```
    </Accordion>

</Accordions>

## 创建隧道时的连接问题

如果隧道创建过程一直在转圈，可能是你的路由器或 ISP 阻断了与 CopilotKit 隧道服务的连接。

<Accordions>
    <Accordion title="路由器或 ISP 阻断了隧道连接">
        要验证与隧道服务的连通性，可以尝试以下命令：

        ```bash
        ping tunnels.devcopilotkit.com
        curl -I https://tunnels.devcopilotkit.com
        telnet tunnels.devcopilotkit.com 443
        ```

        如果这些命令都失败，可能是路由器的安全功能或 ISP 阻断了连接。常见解决办法：
        - 检查路由器安全设置
        - 向你的 ISP 确认是否存在连接限制
        - 尝试使用手机热点
    </Accordion>

</Accordions>

## 我遇到了 “Failed to find or contact remote endpoint at url, Make sure the API is running and that it's indeed a LangGraph platform url” 报错

如果看到此报错，说明 LangGraph platform 客户端无法连接到你的端点。

<Accordions>
    <Accordion title="确认端点可达">
        查看运行在远程端点 URL 上的后端 API 日志，确保它已启动并可以接收请求。
    </Accordion>
    <Accordion title="确认通过 LangGraph 部署工具运行 LangGraph platform 端点">
        使用 `langgraph dev`、`langgraph up`、LangGraph cloud URL 或 LangGraph 提供的同等方式，确认后端 API 正在运行。
    </Accordion>
    <Accordion title="确认远程端点与端点定义类型匹配">
        如果你的远程端点是使用 FastAPI 运行的，即使智能体用的是 LangGraph，它也不会被视为 LangGraph platform 端点。
        你可能需要调整该端点的 `remoteEndpoints` 定义，使其符合预期的格式。

        将端点定义从：
        ```
        new CopilotRuntime({
          remoteEndpoints: [
            langGraphPlatformEndpoint({
            deploymentUrl: "https://your-fastapi-endpoint:port",
            langsmithApiKey: '<langsmith API key>' // optional
            agents: [], // Your previous agents definition
          ],
        });

        // or

        new CopilotRuntime({
          agents: {
            'agent-name': new LangGraphAgent({
              deploymentUrl: "https://your-fastapi-endpoint:port",
              langsmithApiKey: '<langsmith API key>', // optional
              graphId: 'langgraph.json graph id', // Your previous graphId definition
            }),
          }
        });
        ```

        改为：
        ```
        import { HttpAgent } from "@ag-ui/client";

        new CopilotRuntime({
            agents: {
                'agent-name': new HttpAgent({
                    url: 'https://your-fastapi-endpoint:port/your-agent-uri'
                }),
            }
        });
        ```
    </Accordion>

</Accordions>

## 在 LangGraph 与 FastAPI 一起使用时遇到 “No checkpointer set” 报错

如果遇到此报错，说明编译 graph 时缺少 checkpointer。
你可以访问 [LangGraph 持久化指南](https://docs.langchain.com/oss/python/langgraph/persistence#checkpoints)，了解什么是 checkpointer 以及如何添加它。

## 我看到消息流式输出后又消失了

LangGraph 智能体是有状态的。在遍历 graph 的过程中，状态会在每个节点结束时保存。CopilotKit 将智能体状态作为前端聊天显示内容的
唯一事实来源。但由于状态只在节点结束时发出，CopilotKit 允许你_在节点执行过程中_流式输出预测性的状态更新。默认情况下，CopilotKit 会把正在生成的
消息和工具调用流式输出到发起交互的前端聊天中。**如果这些预测状态在节点结束时没有被持久化，它们就会从前端聊天中消失**。

在这种情况下，最可能的原因是状态中的 `messages` 属性在节点执行过程中被更新，但这些修改没有在节点结束时被持久化。

<img src="https://cdn.copilotkit.ai/docs/copilotkit/images/coagents/message-state-diagram.png" />

<Accordions>
    <Accordion title="我希望这些消息被持久化">
        要解决这个问题，只需在节点结束时返回新消息，从而持久化这些消息即可。

         <Tabs groupId="language_langgraph_agent" items={["Python", "TypeScript"]} persist>
            <Tab value="Python">
                ```python
                from langchain_core.runnables import RunnableConfig
                from copilotkit.langgraph import copilotkit_customize_config

                async def chat_node(state: AgentState, config: RunnableConfig):
                    # 1) Call the model with CopilotKit's modified config
                    model = ChatOpenAI(model="gpt-5.4")
                    response = await model.ainvoke(state["messages"], modifiedConfig)

                    # 2) Make sure to return the new messages
                    return {
                        messages: response,
                    }
                ```
            </Tab>
            <Tab value="TypeScript">
                ```typescript

                async function chatNode(state: AgentState, config: RunnableConfig): Promise<AgentState> {
                    // 1) Call the model with CopilotKit's modified config
                    const model = new ChatOpenAI({ temperature: 0, model: "gpt-5.4" });
                    const response = await model.invoke(state.messages, modifiedConfig);

                    // 2) Make sure to return the new messages
                    return {
                        messages: response,
                    }
                }
                ```
            </Tab>
        </Tabs>
    </Accordion>
    <Accordion title="我根本不想让这些消息流式输出">
        这时可以参考我们关于[禁用流式传输](/langgraph/advanced/disabling-state-streaming)的文档。更具体地说，
        你可以在任何不希望消息被流式输出的地方，使用 copilotkit config 来禁用消息发出。

        <Tabs groupId="language_langgraph_agent" items={["Python", "TypeScript"]} persist>
            <Tab value="Python">
                ```python
                from langchain_core.runnables import RunnableConfig
                from copilotkit.langgraph import copilotkit_customize_config

                async def chat_node(state: AgentState, config: RunnableConfig):
                    # 1) Configure CopilotKit not to emit messages
                    modifiedConfig = copilotkit_customize_config(
                        config,
                        emit_messages=False, # if you want to disable message streaming
                    )

                    # 2) Call the model with CopilotKit's modified config
                    model = ChatOpenAI(model="gpt-5.4")
                    response = await model.ainvoke(state["messages"], modifiedConfig)

                    # 3) Don't return the new response to hide it from the user
                    return state
                ```
            </Tab>
            <Tab value="TypeScript">
                ```typescript

                async function chatNode(state: AgentState, config: RunnableConfig): Promise<AgentState> {
                    // 1) Configure CopilotKit not to emit messages
                    const modifiedConfig = copilotkitCustomizeConfig(config, {
                        emitMessages: false, // if you want to disable message streaming
                    });

                    // 2) Call the model with CopilotKit's modified config
                    const model = new ChatOpenAI({ temperature: 0, model: "gpt-5.4" });
                    const response = await model.invoke(state.messages, modifiedConfig);

                    // 3) Don't return the new response to hide it from the user
                    return state;
                }
                ```
            </Tab>
        </Tabs>

        <Callout title="运行的是 subgraph 或 langchain？">
            只需确保将上文定义的 modified config 作为 subgraph 或 langchain 的 `RunnableConfig` 传入即可！
        </Callout>
    </Accordion>

</Accordions>
