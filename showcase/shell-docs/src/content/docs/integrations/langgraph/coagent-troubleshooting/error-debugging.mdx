CopilotKit 提供全面的错误处理能力，帮助你调试问题并监控应用行为。无论你是在本地开发还是在生产环境运行，CopilotKit 都提供工具来高效地捕获、理解和解决报错。

## 快速开始

<Steps>

<Step>
### 使用 dev console 进行本地开发

在本地开发时，启用 dev console 即可在 UI 中直接看到报错：

```tsx
export default function App() {
  return (
    <CopilotKit
      runtimeUrl="<your-runtime-url>"
      showDevConsole={true} // [!code highlight]
    >
      {/* Your app */}
    </CopilotKit>
  );
}
```

<Callout type="tip">
  dev console 会直接在你的 UI 中显示错误横幅，方便你在开发过程中发现问题。此功能**无需 API 密钥**。
</Callout>

</Step>

<Step>
### 生产环境错误可观测性

对于生产应用，使用错误可观测性 hook 将报错发送到监控服务（需要 `publicApiKey`）：

```tsx
export default function App() {
  return (
    <CopilotKit
      runtimeUrl="<your-runtime-url>"
      publicApiKey="ck_pub_your_key" // [!code highlight]
      onError={(errorEvent) => {
        // [!code highlight]
        // Send to your monitoring service
        console.error("CopilotKit Error:", errorEvent);

        // Example: Send to analytics
        analytics.track("copilotkit_error", {
          type: errorEvent.type,
          source: errorEvent.context.source,
          timestamp: errorEvent.timestamp,
        });
      }} // [!code highlight]
      showDevConsole={false} // Hide dev console in production
    >
      {/* Your app */}
    </CopilotKit>
  );
}
```

<Callout type="info">
  **需要 publicApiKey**？前往
  [https://dashboard.operations.copilotkit.ai](https://dashboard.operations.copilotkit.ai) 免费
  获取一个！
</Callout>

</Step>

</Steps>

## 错误处理选项

### Dev Console（`showDevConsole`）

dev console 在开发过程中提供即时的可视化反馈：

```tsx
<CopilotKit runtimeUrl="<your-runtime-url>" showDevConsole={true}>
  {/* Your app */}
</CopilotKit>
```

**特性：**

- ✅ **无需 API 密钥**——适用于任何配置
- ✅ **可视化错误横幅**——报错以横幅形式显示在你的 UI 中
- ✅ **实时反馈**——报错一出现就能立即看到
- ✅ **面向开发**——提供用于调试的详细报错信息

**最适用于：**

- 本地开发
- 测试与调试
- 理解报错流程

<Callout type="warn">
  在生产环境中请设置 `showDevConsole={false}`，以避免向最终用户展示报错详情。
</Callout>

### 错误可观测性（`onError`）

错误可观测性 hook 提供对详细报错信息的编程式访问，用于监控与分析：

```tsx
<CopilotKit
  publicApiKey="ck_pub_your_key"
  onError={(errorEvent: CopilotErrorEvent) => {
    // Send error data to monitoring services
    switch (errorEvent.type) {
      case "error":
        logToService("Critical error", errorEvent);
        break;
      case "request":
        logToService("Request started", errorEvent);
        break;
      case "response":
        logToService("Response received", errorEvent);
        break;
      case "agent_state":
        logToService("Agent state change", errorEvent);
        break;
    }
  }}
>
  {/* Your app */}
</CopilotKit>
```

**特性：**

- ✅ **丰富的报错上下文**——关于出错原因的详细信息
- ✅ **请求/响应追踪**——监控完整的对话流程
- ✅ **智能体状态监控**——追踪智能体交互与状态变化
- ✅ **生产可用**——结构化数据非常适合监控服务

**前提条件：**

- 需要来自 [Copilot Cloud](https://dashboard.operations.copilotkit.ai) 的 `publicApiKey`
- 属于 CopilotKit 企业级可观测性服务的一部分

<Callout type="info">
  **注意**：基础错误处理无需 Cloud 即可使用。`onError` hook 专门用于
  **错误可观测性**——将报错数据发送到 Sentry、DataDog 等监控服务。
</Callout>

## 错误事件结构

`onError` 处理器会接收到带有丰富上下文的详细错误事件：

```typescript
interface CopilotErrorEvent {
  type:
    | "error"
    | "request"
    | "response"
    | "agent_state"
    | "action"
    | "message"
    | "performance";
  timestamp: number;
  context: {
    source: "ui" | "runtime" | "agent";
    request?: {
      operation: string;
      method?: string;
      url?: string;
      startTime: number;
    };
    response?: {
      endTime: number;
      latency: number;
    };
    agent?: {
      name: string;
      nodeName?: string;
    };
    messages?: {
      input: any[];
      messageCount: number;
    };
    technical?: {
      environment: string;
      stackTrace?: string;
    };
  };
  error?: any; // Present for error events
}
```

## 常见错误可观测性模式

### 基础报错日志

```tsx
<CopilotKit
  publicApiKey="ck_pub_your_key"
  onError={(errorEvent) => {
    console.error("[CopilotKit Error]", {
      type: errorEvent.type,
      timestamp: new Date(errorEvent.timestamp).toISOString(),
      context: errorEvent.context,
      error: errorEvent.error,
    });
  }}
>
  {/* Your app */}
</CopilotKit>
```

### 与监控服务集成

```tsx
// Example with Sentry

<CopilotKit
  publicApiKey="ck_pub_your_key"
  onError={(errorEvent) => {
    if (errorEvent.type === "error") {
      Sentry.captureException(errorEvent.error, {
        tags: {
          source: errorEvent.context.source,
          operation: errorEvent.context.request?.operation,
        },
        extra: {
          context: errorEvent.context,
          timestamp: errorEvent.timestamp,
        },
      });
    }
  }}
>
  {/* Your app */}
</CopilotKit>
```

### 自定义错误分析

```tsx
<CopilotKit
  publicApiKey="ck_pub_your_key"
  onError={(errorEvent) => {
    // Track different error types
    analytics.track("copilotkit_event", {
      event_type: errorEvent.type,
      source: errorEvent.context.source,
      agent_name: errorEvent.context.agent?.name,
      latency: errorEvent.context.response?.latency,
      error_message: errorEvent.error?.message,
      timestamp: errorEvent.timestamp,
    });
  }}
>
  {/* Your app */}
</CopilotKit>
```

## 开发与生产环境配置

### 开发环境

```tsx
<CopilotKit
  runtimeUrl="http://localhost:3000/api/copilotkit"
  showDevConsole={true} // Show visual errors
  onError={(errorEvent) => {
    // Simple console logging for development
    console.log("CopilotKit Event:", errorEvent);
  }}
>
  {/* Your app */}
</CopilotKit>
```

### 生产环境

```tsx
<CopilotKit
  runtimeUrl="https://your-app.com/api/copilotkit"
  publicApiKey={process.env.NEXT_PUBLIC_COPILOTKIT_API_KEY}
  showDevConsole={false} // Hide from users
  onError={(errorEvent) => {
    // Production error observability
    if (errorEvent.type === "error") {
      // Log critical errors
      logger.error("CopilotKit Error", {
        error: errorEvent.error,
        context: errorEvent.context,
        timestamp: errorEvent.timestamp,
      });

      // Send to monitoring service
      monitoring.captureError(errorEvent.error, {
        extra: errorEvent.context,
      });
    }
  }}
>
  {/* Your app */}
</CopilotKit>
```

## 开始使用 Copilot Cloud

要使用错误可观测性 hook，你需要一个 Copilot Cloud 账号：

1. 在 [https://dashboard.operations.copilotkit.ai](https://dashboard.operations.copilotkit.ai) **免费注册**
2. 在控制台**获取你的 public API 密钥**
3. **将其添加到环境变量**：
   ```bash
   NEXT_PUBLIC_COPILOTKIT_API_KEY=ck_pub_your_key_here
   ```
4. **在你的 CopilotKit provider 中使用它**：
   ```tsx
   <CopilotKit publicApiKey={process.env.NEXT_PUBLIC_COPILOTKIT_API_KEY}>
     {/* Your app */}
   </CopilotKit>
   ```

## 最佳实践

### ✅ 推荐做法

- **开发时使用 `showDevConsole={true}`**，获得即时反馈
- **在生产环境设置 `showDevConsole={false}`**，对用户隐藏报错
- **实现完善的错误可观测性**，配合 `onError` hook 进行监控
- **监控报错模式**，主动发现并修复问题
- **使用结构化日志**，让报错分析更轻松

### ❌ 避免做法

- **不要在生产环境向最终用户暴露详细报错**
- **不要忽略错误事件**——它们提供了宝贵的调试信息
- **不要在错误可观测性 hook 中记录敏感数据**
- **不要用错误处理逻辑阻塞 UI**

## 故障排查

### 错误可观测性不生效

如果你的 `onError` hook 没有被调用：

1. **检查 publicApiKey**——错误可观测性需要有效的 API 密钥
2. **验证密钥格式**——应以 `ck_pub_` 开头
3. **确认已设置密钥**——检查你的环境变量
4. **用 dev console 测试**——使用 `showDevConsole={true}` 查看报错是否正在发生

### Dev Console 未显示

如果 dev console 没有显示报错：

1. **检查 showDevConsole 设置**——确保其值为 `true`
2. **查看控制台报错**——在浏览器开发者工具中检查 JavaScript 错误
3. **确认报错确实发生**——确保确实有错误产生
