## 选择正确的通道

一些 LangGraph 适配器会把浏览器提供的 `forwardedProps.config` 合并进
LangGraph 的 `RunnableConfig`。即使 LangGraph 的 config schema 接受这些值，它们仍然由浏览器控制、不可信。绝不要将它们用于凭据、租户身份、授权或服务器执行控制。请保持信任边界清晰，并根据值的类型选择对应的通道：

| 值 | 受支持的通道 |
| --- | --- |
| 模型需要看到的 UI 偏好 | 通过前端的 agent-context API 发布；参见 [Agent Config](/agent-config)。 |
| 身份验证与授权 | 发送 `Authorization` 请求头，并对每个请求进行校验；参见[身份验证](/auth)。 |
| Graph 执行设置 | 在调用或提供 graph 的可信后端中设置。 |

<Callout type="warning" title="不要把凭据作为运行属性发送">
  运行属性属于应用载荷，不是身份验证或 LangGraph 配置通道。请在服务器边界校验凭据，只把解析后的身份传给 graph。
</Callout>

## 模型可见的 UI 偏好

对于语气、专业水平、响应长度、所选记录等应当影响模型的非敏感值，请将其作为智能体上下文发布。[Agent Config 指南](/agent-config)展示了完整的模式，以及 CopilotKit middleware 如何在每一轮暴露最新值。

<FrontendOnly frontend="react">
  在 React 中，使用
  [`useAgentContext`](/reference/v2/hooks/useAgentContext) 发布这些值。
</FrontendOnly>

<FrontendOnly frontend="angular">
  在 Angular 中，使用
  [`connectAgentContext`](/reference/angular/functions/connectAgentContext) 发布这些值。
</FrontendOnly>

## 身份验证

身份验证应放在请求头中，而不是 graph 状态或运行时属性中。[身份验证指南](/auth)同时覆盖 LangGraph Platform 与自托管的 AG-UI 端点。两种情况下，都要在 graph 运行前校验当前请求，并只注入解析后的用户或租户标识符。

## 可信的 graph 执行设置

在影响 graph 配置的输入通过校验之后，再于后端代码中设置 graph 配置。不要整体接受浏览器提供的配置对象。

<Tabs groupId="language_langgraph_agent" items={['Python', 'TypeScript']} default="Python" persist>
  <Tab value="Python">
    对于自托管的 AG-UI 端点，使用由后端掌控的配置来构造一个请求级的 `LangGraphAGUIAgent`：

    ```python title="main.py"
    from copilotkit import LangGraphAGUIAgent

    def build_agent(tenant_id: str) -> LangGraphAGUIAgent:
        return LangGraphAGUIAgent(
            name="sample_agent",
            description="Tenant-scoped agent",
            graph=graph,
            config={
                "configurable": {"tenant_id": tenant_id},
                "recursion_limit": 50,
            },
        )
    ```

    然后，节点就可以从服务器提供的配置中读取经过校验的值：

    ```python
    from langchain_core.runnables import RunnableConfig

    async def agent_node(state: AgentState, config: RunnableConfig):
        tenant_id = config["configurable"]["tenant_id"]
        return state
    ```

    请在每个请求完成身份验证后再创建智能体，具体参见[自托管身份验证指南](/auth)。
  </Tab>

  <Tab value="TypeScript">
    在可信后端调用 graph 的地方设置运行时上下文与执行控制项。`recursionLimit` 是顶层的执行设置；你的应用值应放在 `context` 中：

    ```typescript title="agent.ts"
    const result = await graph.invoke(input, {
      context: { tenantId: verifiedTenantId },
      recursionLimit: 50,
    });
    ```

    通过节点的 LangGraph 运行时读取经过校验的上下文。匹配的 context schema 与节点签名请参见
    [LangGraph 运行时配置指南](https://docs.langchain.com/oss/javascript/langgraph/use-graph-api#add-runtime-configuration)。
  </Tab>
</Tabs>

## 不该做的事

- 不要把原始凭据放进模型可见的上下文或 graph 状态。
- 不要仅仅为了在后续轮次可用而持久化凭据。
- 不要仅因为某个适配器把值放进了 `RunnableConfig` 就信任它。
- 不要让浏览器决定递归上限、回调、元数据或其他服务器执行控制项。
- 不要在多次运行之间复用请求级身份。每个请求都要校验。
