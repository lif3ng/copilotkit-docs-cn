title: "第 4 步：智能体化聊天 UI"
---

到这一步，我们已经有了运行在 LangGraph Studio 中的 LangGraph 智能体，也有了一个简单的 copilot。现在，我们把两者结合起来，打造一个 copilot 智能体（CoAgent）！

<Steps>
<Step>
## 将智能体连接到 CopilotKit
我们需要让 CopilotKit 感知到正在运行的 LangGraph 智能体。为此，我们将设置一个远程端点，连接到本地运行的智能体。

由于我们使用的是 Copilot Cloud，只需在本地开发时运行以下命令即可。

```bash
npx copilotkit@latest dev --port 8000
```

```sh
✔ Select a project Local (ID: <project_id>)
✅ LangGraph Platform endpoint detected
⠹ Creating tunnel...

Tunnel Information:

• Tunnel URL:            https://<tunnel_id>.tunnels.devcopilotkit.com
• Endpoint Type:         LangGraph Platform
• Project:               projects/<project_id>

Press Ctrl+C to stop the tunnel

✔ 🚀 Local tunnel is live and linked to Copilot Cloud!
```

这样，Copilot Cloud 就知道在调用智能体时该把请求发送到哪里。

</Step>
<Step>
## 指定要使用的智能体

现在我们需要让 CopilotKit provider 知道要使用哪个智能体，可以通过指定 `agent` prop 来实现。

<Accordions>
<Accordion title="多智能体路由">
默认情况下，CopilotKit 会根据上下文智能地将请求路由到合适的智能体。这样你就可以拥有多个智能体和操作，而无需手动路由请求。

但在本例中，我们只有一个智能体，因此最好把所有请求都锁定到该智能体上。我们可以通过更新 `CopilotKit` provider 的 props 来实现。

</Accordion>
</Accordions>

我们的智能体名称是 `agent`，它在 `langgraph.json` 文件中指定。

```tsx title="frontend/src/app/layout.tsx"
// ...
<CopilotKit
  // ...
  agent="agent" // [!code ++]
>
  {...}
</CopilotKit>
```

</Step>
</Steps>

## 回顾

大功告成！以下是我们做过的事情：

- 我们将智能体连接到了 CopilotKit。
- 我们指定了要使用的智能体。
