## 从你的编码智能体开始

使用以下提示词将你的 LangGraph 智能体连接到 CopilotKit，并验证对话可以正常工作。你的编码智能体会按照本指南在你的项目中操作，你也可以按下面的手动步骤自行完成。

<PageAgentPrompt />

## 前置条件

开始之前，你需要准备以下内容：

- 一个 OpenAI API 密钥
- Node.js 20+
- 你顺手的包管理器
- （可选）一个 LangSmith API 密钥——仅在使用现有 LangGraph 智能体时需要

<Callout type="info" title="TypeScript 智能体的 Zod 版本">
在 TypeScript 智能体中添加 `@copilotkit/sdk-js` 时，请同时安装 Zod 3：

```bash
npm install @copilotkit/sdk-js zod@3
```

不带版本号的 `zod` 安装会选择 Zod 4，它不满足 SDK 对 `zod` 的 peer 依赖（`^3`）。使用 pnpm 或 Yarn 时同样请用 `zod@3`。如果你的智能体已经依赖 Zod 4，请在改动其依赖之前先确认 SDK 的兼容性；不要用 `--force` 或 `--legacy-peer-deps` 绕过冲突。

SDK 还对 `langchain` 有 peer 依赖。如果你的智能体将 `@langchain/core` 锁定到某个精确版本，npm 会安装最新的 `langchain`，而它可能要求更新版本的 `@langchain/core`，从而导致 `ERESOLVE` 失败。请安装一个 peer 范围能覆盖你的 `@langchain/core` 的 `langchain` 版本。要查看每个版本的 peer 范围，运行：

```bash
npm view langchain@1 peerDependencies
```

例如，`langchain@1.5.9` 要求 `@langchain/core ^1.2.8`，因此它是能与 `@langchain/core@1.2.8` 配合的最新版本。请精确锁定该版本。像 `^1.5.9` 这样的插入符范围会让后续安装选中 `langchain@1.5.19`，而后者要求 `@langchain/core ^1.2.20`：

```bash
npm install --save-exact @copilotkit/sdk-js zod@3 langchain@1.5.9
```
</Callout>

            ### 通过 AG-UI 暴露你的智能体

            如果你已经写好了一个 LangGraph 智能体，只需参考以下代码。本步骤中我们为了演示而创建一个简单的 LangGraph 智能体。

            <Tabs groupId="language_langgraph_agent" items={['Python', 'TypeScript']} default="Python" persist>
              <Tab value="TypeScript">
                TypeScript 智能体借助 `@langchain/langgraph-cli` 工具运行在 LangGraph API 服务器上。这就是 **LangSmith** 路线。**FastAPI** 路线仅支持 Python。

                在 `src/agent.ts` 中创建智能体：

                ```ts title="src/agent.ts" doctest="component"
                import { SystemMessage } from "@langchain/core/messages";
                import { ChatOpenAI } from "@langchain/openai";
                import {
                  END,
                  MessagesAnnotation,
                  START,
                  StateGraph,
                } from "@langchain/langgraph";

                async function mockLlm(state: typeof MessagesAnnotation.State) {
                  const model = new ChatOpenAI({ model: "gpt-4.1-mini" });
                  const response = await model.invoke([
                    new SystemMessage("You are a helpful assistant."),
                    ...state.messages,
                  ]);
                  return { messages: response };
                }

                // [!code highlight:5]
                export const graph = new StateGraph(MessagesAnnotation)
                  .addNode("mock_llm", mockLlm)
                  .addEdge(START, "mock_llm")
                  .addEdge("mock_llm", END)
                  .compile();
                ```

                不要向 `compile()` 传入 `checkpointer`。LangGraph API
                服务器会在运行时提供持久化。

                然后在智能体目录中添加一个 `langgraph.json`：

                ```json title="langgraph.json"
                {
                  "node_version": "20",
                  "dependencies": ["."],
                  "graphs": {
                    "sample_agent": "./src/agent.ts:graph"
                  },
                  "env": ".env"
                }
                ```

                `graphs` 条目的格式是 `<file>:<export>`。它必须指向导出的
                `graph` 常量，否则 CLI 会报
                “graph is nullish” 错误。键 `sample_agent` 就是下文
                runtime 路由要连接的 `graphId`。
              </Tab>
              <Tab value="Python">
              <Tabs groupId="deployment_method" items={['LangSmith', 'FastAPI']}>
                <Tab value="LangSmith">
                  首先，我们创建一个简单的 LangGraph 智能体：

                  ```python title="main.py"
                  from dotenv import load_dotenv
                  from langchain_core.messages import SystemMessage
                  from langchain_openai import ChatOpenAI
                  from langgraph.graph import END, START, MessagesState, StateGraph
                  load_dotenv()

                  async def mock_llm(state: MessagesState):
                    model = ChatOpenAI(model="gpt-4.1-mini")
                    system_message = SystemMessage(content="You are a helpful assistant.")
                    response = await model.ainvoke(
                      [
                        system_message,
                        *state["messages"],
                      ]
                    )
                    return {"messages": response}

                  graph = StateGraph(MessagesState)
                  graph.add_node(mock_llm)
                  graph.add_edge(START, "mock_llm")
                  graph.add_edge("mock_llm", END)
                  graph = graph.compile()
                  ```

                  <Callout type="warn" title="此路线下不要添加 checkpointer">
                    `compile()` 刻意没有传 `checkpointer=`。持久化由
                    LangGraph API 服务器负责，它会在运行时注入自己的
                    checkpointer。如果你在编译时内置了自定义 checkpointer，
                    `langgraph dev` 会拒绝加载该图
                    （`ValueError: ... includes a custom checkpointer ... persistence is
                    handled automatically by the platform`），部署后的图则会忽略它。
                    **FastAPI** Tab 正好相反——参见那里的说明。
                  </Callout>

                  接下来，要用 LangSmith 进行测试和部署，我们还需要一个 `langgraph.json`

                  ```sh
                  touch langgraph.json
                  ```

                  ```json title="langgraph.json"
                  {
                    "python_version": "3.12",
                    "dockerfile_lines": [],
                    "dependencies": ["."],
                    "package_manager": "uv",
                    "graphs": {
                      "sample_agent": "./main.py:graph"
                    },
                    "env": ".env"
                  }
                  ```
                </Tab>
                <Tab value="FastAPI">
                  首先，将 `ag-ui-langgraph` 包添加到你的项目：

                  ```bash
                  uv add ag-ui-langgraph fastapi uvicorn copilotkit
                  ```

                  然后创建一个简单的 LangGraph 智能体，添加一个 FastAPI 应用，并把我们的智能体挂载为 AG-UI 端点。

                  ```python title="main.py" doctest="server"
                  import os

                  # [!code highlight:2]
                  from dotenv import load_dotenv
                  from ag_ui_langgraph import add_langgraph_fastapi_endpoint
                  from copilotkit import LangGraphAGUIAgent
                  from fastapi import FastAPI
                  from langgraph.graph import END, START, MessagesState, StateGraph
                  from langchain_core.messages import SystemMessage
                  from langchain_openai import ChatOpenAI
                  from langgraph.checkpoint.memory import MemorySaver
                  import uvicorn
                  load_dotenv()

                  async def mock_llm(state: MessagesState):
                    model = ChatOpenAI(model="gpt-4.1-mini")
                    system_message = SystemMessage(content="You are a helpful assistant.")
                    response = await model.ainvoke(
                      [
                        system_message,
                        *state["messages"],
                      ]
                    )
                    return {"messages": response}


                  graph = StateGraph(MessagesState)
                  graph.add_node(mock_llm)
                  graph.add_edge(START, "mock_llm")
                  graph.add_edge("mock_llm", END)
                  graph = graph.compile(
                    checkpointer=MemorySaver()
                  )

                  app = FastAPI()

                  # [!code highlight:9]
                  add_langgraph_fastapi_endpoint(
                    app=app,
                    agent=LangGraphAGUIAgent(
                      name="sample_agent",
                      description="An example agent to use as a starting point for your own agent.",
                      graph=graph,
                    ),
                    path="/",
                  )

                  def main():
                    """Run the uvicorn server."""
                    uvicorn.run(
                      "main:app",
                      host="0.0.0.0",
                      port=8123,
                      reload=True,
                    )

                  if __name__ == "__main__":
                    main()
                  ```

                  <Callout type="info" title="为什么这个 Tab 编译时带 checkpointer">
                    这里由你自己运行图，因此没有任何东西提供持久化。`ag-ui-langgraph` 通过
                    `graph.aget_state(...)` 读取线程状态，如果图编译时没有
                    checkpointer，就会抛出
                    `ValueError: No checkpointer set`——所以要加 `MemorySaver()`。它只把状态保存在进程内存中；
                    生产环境请换成持久化的 saver（如 Postgres）。
                    **不要**把这段代码复制到 LangSmith Tab 的图中。
                  </Callout>

                  上文的 `main.py` 将 uvicorn 的端口设为了 `8123`，这正是
                  下文 runtime 路由所期望的端口。如果你换用其他端口，请
                  同时修改这两处。
                </Tab>

              ### 设置 Copilot Runtime

              创建一个 API 路由，将 CopilotKit 连接到你的 LangGraph 智能体：

              ```sh
              mkdir -p "app/api/copilotkit/[[...slug]]" && touch "app/api/copilotkit/[[...slug]]/route.ts"
              ```

              <Callout type="info" title="承载四种动词的 catch-all 路由">
                下例将 Runtime 挂载到一个 catch-all 路由
                （`app/api/copilotkit/[[...slug]]/route.ts`）上，同时服务 `GET`、`POST`、
                `PATCH` 和 `DELETE`。LangGraph 起步模板、
                [Intelligence 快速开始](/intelligence/quickstart)以及
                [runtime 端点页面](/backend/runtime-endpoints)都使用
                相同的挂载方式。

                如果你的应用已经用 `mode: "single-route"` 在单个 `POST` 路由上
                提供 Runtime，那就保留它。它同样承载 AG-UI 流、
                User Memory 和 Inspector 请求。请在 provider 上相应设置
                `useSingleEndpoint`。参见
                [Provider 与 handler 的配对](/backend/runtime-endpoints#provider-and-handler-pairs)。
              </Callout>

              如果你的智能体是 TypeScript 写的，请使用 **LangSmith** Tab。
              `LangGraphAgent` 会连接到由
              `@langchain/langgraph-cli` 启动的 LangGraph API 服务器。

              <Tabs groupId="deployment_method" items={['LangSmith', 'FastAPI']}>
                <Tab value="LangSmith">
                  ```tsx title="app/api/copilotkit/[[...slug]]/route.ts"
                  import {
                    CopilotKitIntelligence,
                    CopilotRuntime,
                    createCopilotRuntimeHandler,
                  } from "@copilotkit/runtime/v2";
                  // [!code highlight]
                  import { LangGraphAgent } from "@copilotkit/runtime/langgraph";

                  const runtime = new CopilotRuntime({
                    agents: {
                    // [!code highlight:5]
                      sample_agent: new LangGraphAgent({
                        deploymentUrl:  process.env.LANGGRAPH_DEPLOYMENT_URL || "http://localhost:8123",
                        graphId: "sample_agent",
                        langsmithApiKey: process.env.LANGSMITH_API_KEY || "",
                      }),
                    },
                    // [!code highlight:8]
                    intelligence: new CopilotKitIntelligence({
                      apiKey: process.env.CPK_INTELLIGENCE_API_KEY!,
                    }),
                    // Threads are per-user. Without this, every visitor shares one history.
                    identifyUser: (request) => ({
                      id: request.headers.get("x-user-id") ?? "anonymous",
                      name: request.headers.get("x-user-name") ?? "Anonymous",
                    }),
                  });

                  const handler = createCopilotRuntimeHandler({
                    runtime,
                    basePath: "/api/copilotkit",
                  });

                  export const GET = handler;
                  export const POST = handler;
                  export const PATCH = handler;
                  export const DELETE = handler;
                  ```
                </Tab>

          <Step>
              ### 配置 CopilotKit Provider

              用 CopilotKit provider 包裹你的应用：

              <Callout type="info" title="让 provider 与 handler 匹配">
                `useSingleEndpoint={false}` 将 provider 固定到上文的
                multi-route handler。参见
                [Provider 与 handler 的配对](/backend/runtime-endpoints#provider-and-handler-pairs)。
              </Callout>

              ```tsx title="app/providers.tsx"
              "use client";

              import { CopilotKitProvider } from "@copilotkit/react-core/v2";

              export function Providers({ children }: { children: React.ReactNode }) {
                return (
                  <CopilotKitProvider runtimeUrl="/api/copilotkit" agentId="sample_agent" useSingleEndpoint={false}>
                    {children}
                  </CopilotKitProvider>
                );
              }
              ```

              `app/layout.tsx` 是服务端组件，不能直接导入 provider，
              因此它改为渲染你的客户端文件：

              ```tsx title="app/layout.tsx"
              // [!code highlight:2]
              import { Providers } from "./providers";
              import "@copilotkit/react-core/v2/styles.css";
              import './globals.css';

              // ...

              export default function RootLayout({ children }: {children: React.ReactNode}) {
                return (
                  <html lang="en">
                    <body>
                      {/* [!code highlight:3] */}
                      <Providers>
                        {children}
                      </Providers>
                    </body>
                  </html>
                );
              }
              ```

              <Callout type="info" title="此相对 runtimeUrl 假设由 Next.js 提供 runtime 服务">
                `/api/copilotkit` 之所以能解析，是因为 Next.js 从同一源提供你的应用和
                runtime。纯客户端前端没有共享源，因此需要自己的独立
