## 从你的编码智能体开始

使用此提示词把你的 Mastra 智能体连接到 CopilotKit，并验证对话可以正常工作。你的编码智能体会在项目中按照本指南操作，你也可以按下面的手动步骤自己完成。

<PageAgentPrompt />

## 前置条件

开始之前，你需要准备以下内容：

- 一个 OpenAI API 密钥；如果智能体运行在 Claude 上，则需要一个 Anthropic API 密钥
- Node.js 20+
- 你顺手的包管理器

                ### 初始化你的 Mastra 项目

                如果你还没有搭好 Mastra 项目，先创建一个：

                ```bash
                npx create-mastra@latest my-agent
                cd my-agent
                ```
            </Step>
            <Step>
                ### 创建你的 Mastra 智能体

                在你的 Mastra 项目中创建一个新的智能体文件：

                ```ts title="src/mastra/agents/index.ts"
                import { openai } from "@ai-sdk/openai";
                import { Agent } from "@mastra/core/agent";

                export const myAgent = new Agent({
                  id: "my-agent",
                  name: "My Agent",
                  instructions: "You are a helpful assistant!",
                  model: openai("gpt-5.4"),
                });
                ```

                然后在你的 Mastra 实例中导出它：

                ```ts title="src/mastra/index.ts"
                import { Mastra } from "@mastra/core";
                import { myAgent } from "./agents";

                export const mastra = new Mastra({
                  agents: { myAgent },
                });
                ```

                <Callout type="warn" title="记录键是智能体的名称，而不是它的 `id`">
                  Mastra 以**你注册它时所用的键**来暴露每个智能体——在这里是 `myAgent`——
                  运行时映射以及 Provider 的 `agent` 属性都以这个键为索引。上面的 `name`
                  （`"My Agent"`）只是显示文本；即使你设置了 `id`，它同样不用于路由。
                  即便智能体声明了 `id: "my-agent"`，`listAgents()` 返回的仍是 `myAgent`。

                  同样的规则也适用于工具：`tools: { weatherTool }` 暴露的是
                  `weatherTool`，因此以该键注册的 `createTool({ id: "get-weather" })`
                  在网络上仍然叫 `weatherTool`。请让 `useFrontendTool` 的名称与记录键
                  保持一致，而不是与 `id` 一致。
                </Callout>

                <Callout type="info" title="改用 Anthropic 运行此智能体">
                  此示例使用的是 OpenAI 的 `gpt-5.4`。若要使用 Claude，请安装
                  `@ai-sdk/anthropic`，然后替换 import 与 `model` 配置：

                  ```ts title="src/mastra/agents/index.ts"
                  import { anthropic } from "@ai-sdk/anthropic";
                  // model: anthropic("claude-sonnet-4-6"),
                  ```

                  凭证变量随厂商而变——Anthropic 的提供方读取 `ANTHROPIC_API_KEY`，
                  因此在下一步中请导出它来替代 `OPENAI_API_KEY`。

                  <ApiKeyHint provider="anthropic" />
                </Callout>
            </Step>
            <Step>
                ### 配置环境

                将你的 OpenAI API 密钥设置为环境变量：

                ```bash
                export OPENAI_API_KEY=your_openai_api_key
                ```

                <ApiKeyHint provider="openai" />
            </Step>
            <Step>
                ### 启动你的智能体

                让 Mastra 服务器在它自己的终端中保持运行：

                ```bash
                npx mastra dev
                ```

                记下它打印的端口。端口空闲时 `mastra dev` 会使用 4111，被占用时则依次向后找到
                4131，接下来你构建的前端将通过该地址以 HTTP 访问这个智能体。

                在把前端接到它之前，先确认它正在服务你的智能体：

                ```bash
                curl http://127.0.0.1:4111/api/agents
                ```

                <Callout type="warn" title="裸的 `GET /` 不是存活检查">
                  Mastra 会在智能体端口上提供 Web 控制台，无论是否注册了智能体都会返回
                  `200`。请检查 `/api/agents`，并按名称查找你的智能体。
                </Callout>
            </Step>
            <Step>
                ### 创建你的前端

                CopilotKit 可与任何基于 React 的前端配合使用。本例中我们使用 Next.js。

                请把它创建在 Mastra 项目*旁边*，而不是项目内部：

                ```bash
                cd ..
                npx create-next-app@latest my-copilot-app
                cd my-copilot-app
                ```

                <Callout type="warn" title="不要把 `next dev` 指向你的 Mastra 项目根目录">
                  Next.js 首次运行时会改写它自己根目录下的 `tsconfig.json`：
                  强制启用 `esModuleInterop`、`isolatedModules`、`resolveJsonModule` 和
                  `jsx`，设置 `noEmit: true`，并替换 `include` 与 `exclude`。如果把
                  `next dev` 指向一个用 `tsc` 编译的 Mastra 项目，就会改写智能体构建
                  所依赖的配置。放在旁边的同级包则不会触碰它——这也是本指南通过 HTTP
                  访问智能体而不是直接导入它的原因。
                </Callout>
            </Step>
            <Step>
                ### 安装 CopilotKit 包

                ```npm
                npm install @copilotkit/react-ui @copilotkit/react-core @copilotkit/runtime @ag-ui/mastra @ag-ui/core@1.0.2 @ag-ui/client@1.0.2 @mastra/client-js
                ```
            </Step>
            <Step>
                ### 设置 Copilot Runtime

                创建一个 API 路由，把 CopilotKit 连接到你上面启动的 Mastra 服务器。
                `MastraAgent.getRemoteAgents` 会向该服务器查询它有哪些智能体，并通过
                HTTP 把每个智能体桥接过来，因此你的智能体仍作为独立进程运行：

                ```ts title="app/api/copilotkit/[[...slug]]/route.ts" doctest="component"
                import {
                  CopilotKitIntelligence,
                  CopilotRuntime,
                  createCopilotRuntimeHandler,
                } from "@copilotkit/runtime/v2";
                import { MastraAgent } from "@ag-ui/mastra";
                import { MastraClient } from "@mastra/client-js";

                const mastraClient = new MastraClient({
                  baseUrl: process.env.MASTRA_BASE_URL ?? "http://127.0.0.1:4111",
                });

                const runtime = new CopilotRuntime({
                  // A factory, so the agent list is fetched per request rather than at
                  // module load — the route survives an agent server that is not up yet.
                  agents: ({ request }) =>
                    MastraAgent.getRemoteAgents({
                      mastraClient,
                      // Scopes Mastra's own memory to the same user identified below.
                      resourceId: request.headers.get("x-user-id") ?? "anonymous",
                    }),
                  // [!code highlight:8]
                  intelligence: new CopilotKitIntelligence({
                    apiKey: process.env.CPK_INTELLIGENCE_API_KEY!,
                  }),
                  // Threads are per-user. Without this, every visitor shares one history.
                  identifyUser: (request) => ({
                    id: request.headers.get("x-user-id") ?? "anonymous",
                    name: request.headers.get("x-user-name") ?? "Anonymous",
                  }),
                });

                const handler = createCopilotRuntimeHandler({
                  runtime,
                  basePath: "/api/copilotkit",
                });

                export const GET = handler;
                export const POST = handler;
                export const PATCH = handler;
                export const DELETE = handler;
                ```

                在这个前端应用目录下，把运行时连接到一个 Intelligence 项目：

                ```bash title="Terminal"
                npx copilotkit@latest project select
                ```

                该命令会把服务端项目 API 密钥写入 `.env`。把智能体服务器的地址也加到
                同一个文件中；前端运行时是在这里读取这两个值的，而不是在 Mastra 项目中：

                ```plaintext title=".env"
                CPK_INTELLIGENCE_API_KEY=cpk-...
                MASTRA_BASE_URL=http://127.0.0.1:4111
                ```

                `MASTRA_BASE_URL` 默认值为 `http://127.0.0.1:4111`，因此只有当你的
                智能体服务器使用了其他端口，或者你指向的是已部署的 Mastra 服务时才需要设置它。

                <Callout type="info" title="改为内嵌 Mastra">
                  如果你的 Mastra 实例内嵌在这个 Next.js 应用中而不是独立进程里，请把
                  `getRemoteAgents` 换成
                  `MastraAgent.getLocalAgents({ mastra, resourceId })`，并去掉 client。
                  两种方式如何选择，请参阅
                  [本地与远程智能体](/mastra/copilot-runtime#local-vs-remote-agents)。
                </Callout>

                <Callout type="info" title="不使用 Intelligence 平台运行？">
                  去掉 `intelligence` 与 `identifyUser` 选项后，运行时会回退到带内存
                  运行器的 SSE 模式。聊天仍然可用，但 Threads 与 Inspector 会保持锁定，
                  密钥也永远不会被读取。完整的构造参数以及如何确认密钥已生效，请参阅
                  [将你的运行时连接到 Intelligence](/intelligence/quickstart)。
                </Callout>
            </Step>
            <Step>
                ### 配置 CopilotKit Provider

                `@copilotkit/react-core/v2` 导出的所有内容都是客户端组件，因此
                Provider 要放在你自己标记了 `"use client"` 的文件中：

                ```tsx title="app/providers.tsx"
                "use client";

                import { CopilotKit } from "@copilotkit/react-core/v2";

                export function Providers({ children }: { children: React.ReactNode }) {
                  return (
                    <CopilotKit runtimeUrl="/api/copilotkit" agent="myAgent" useSingleEndpoint={false}>
                      {children}
                    </CopilotKit>
                  );
                }
                ```

                然后用这个文件包裹你的应用：

                ```tsx title="app/layout.tsx"
                import { Providers } from "./providers"; // [!code highlight]
                import "@copilotkit/react-core/v2/styles.css";
                import './globals.css';

                // ...

                export default function RootLayout({ children }: {children: React.ReactNode}) {
                  return (
                    <html lang="en">
                      <body>
                        {/* [!code highlight:3] */}
                        <Providers>
                          {children}
                        </Providers>
                      </body>
                    </html>
                  );
                }
                ```

                <Callout type="warn" title="把 Provider 直接导入 layout 会破坏构建">
                  `app/layout.tsx` 是服务端组件。`@copilotkit/react-core/v2` 被标记为
                  `"use client"`，并通过 `export *` 重新导出 `@copilotkit/core` 与
                  `@ag-ui/client`，而 Next.js 无法跨这一边界进行枚举。在 Next.js 16
                  配合 webpack 时构建会失败，页面返回 500。在这两者之间放一个你自己的
                  客户端文件，就能让这个 import 留在客户端依赖图中。
                </Callout>

                <Callout type="info" title="这个相对 runtimeUrl 假设由 Next.js 服务运行时">
                  `/api/copilotkit` 之所以能解析，是因为 Next.js 从同一个源服务你的应用
                  和运行时。纯客户端前端没有共享源，因此它需要自己独立的运行时服务器，
                  以及形如 `http://localhost:8200/api/copilotkit` 的绝对 `runtimeUrl`。
                  `/react-spa`、`/vue`、`/angular` 和 `/react-native` 的各前端指南分别
                  展示了这种配置。
                </Callout>
            </Step>
