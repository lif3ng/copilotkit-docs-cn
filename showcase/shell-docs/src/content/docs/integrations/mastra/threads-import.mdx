## 在现有应用中添加 Intelligence

围绕你的 Mastra 智能体，为用户提供跨设备的重连、进度补看与消息送达。按照 [Intelligence 快速开始](/intelligence/quickstart)连接你现有的 CopilotKit 应用与 Runtime，然后验证新对话会被保存。这会为经由 CopilotKit 的运行启用 AG-UI 流，无需任何历史导入。

保持你的 Mastra 智能体及其持久化存储处于连接状态，这样在导入对话之后你可以继续这些对话。参见[流如何与框架存储协同工作](/intelligence/threads-explained#how-threads-work-with-framework-storage)。

## 纳入更早的对话（可选）

要让用户能重新打开接入 Intelligence 之前记录的对话，请使用下面的导入器复制受支持的历史内容。导入既不会启用实时送达，也不会建立持续的数据库复制，而且它无法恢复来源已不再暴露的历史。

Mastra 导入器从本地 LibSQL 数据库或 Mastra 服务器读取已保存的对话。它会带出已保存的消息、富工具结果、附件，以及（在可用的情况下）智能体状态。某些交互式内容（如 MCP 应用视图）可能没有保存在原始历史中。

下面的前置条件与命令仅适用于历史导入。可以使用 Threads Drawer 或[无头线程（Headless Threads）](/headless-threads)，通过同一个 UI 打开导入的对话与新对话。

## 前置条件

- 一个启用了 CopilotKit Intelligence 的 CopilotKit 应用。
- 保存在持久化存储中的 Mastra 对话。内存中的对话无法导入。
- 能访问 Mastra 数据库文件或服务器，以及要导入的对话所属的智能体 ID 和资源 ID。

## 确认目标项目

选择将接收这些历史的 Intelligence 项目。目的地由它的 app-api URL 和项目级运行时密钥决定。导入之前你需要先导出这两个值。

对于用 CLI 创建的应用，你可以选择一个云端托管的项目：

```bash title="Terminal"
npx copilotkit@latest project select
```

该命令会更新当前目录所选的项目，并把它的项目级运行时密钥写入应用生成的 `.env`。

## 配置来源

设置你要导入其对话的智能体与资源：

```bash title="Terminal"
export MASTRA_IMPORT_SOURCE_ID="my-mastra-app"
export MASTRA_IMPORT_AGENT_ID="support"
export MASTRA_IMPORT_RESOURCE_ID="customer-123"
export MASTRA_IMPORT_END_USER_ID="user-123"
```

使用你原生的 Mastra 智能体 ID，以及拥有这些对话的资源 ID。把 `MASTRA_IMPORT_END_USER_ID` 设置为你的 Runtime 从 `identifyUser` 返回的同一个应用用户 ID，这样该用户才能找到导入的对话。对每个资源和用户，用相应的值重复执行导入。

`MASTRA_IMPORT_SOURCE_ID` 是你为这个 Mastra 存储起的名字。再次导入时请保持不变，包括在数据库与服务器两种访问方式之间切换时。

选择读取已保存对话的方式：

    ```bash title="Terminal"

    export MASTRA_IMPORT_MEMORY_URL="file:/absolute/path/mastra.db"

    工作记忆默认按资源（resource）范围读取。如果你的智能体使用线程范围的工作记忆，请设置 `MASTRA_IMPORT_WORKING_MEMORY_SCOPE="thread"`。

    ```

    URL 中要包含你服务器的 API 前缀。如果你的服务器不需要 bearer token，则省略 `MASTRA_IMPORT_API_TOKEN`。

请在这些对话空闲时运行导入。

## 试运行（dry run）

在写入任何内容之前先预览导入。

```bash title="Terminal"
npx copilotkit@latest import --source mastra --dry-run
```

试运行会统计对话数量、报告无法导入的对话，并估算上传大小。它不需要 CopilotKit Intelligence 的 URL 或 API 密钥。

## 把 Mastra 智能体映射到 CopilotKit agent ID

把你在 `MASTRA_IMPORT_AGENT_ID` 中设置的 Mastra 智能体 ID，映射到你线上 CopilotKit 运行时所使用的 `agentId`。

```json title="agent-map.json"
{
  "support": "support-agent"
}
```

与线上流量使用相同的 `agentId`，可以让导入的历史与之后的对话归到一起。

## 准备 CopilotKit Intelligence 目的地

真正的导入需要目的地的 app-api URL 和项目级运行时密钥。CLI 创建的起步模板会把它们写入 `.env`，但导入器读取的是当前进程环境，不会自动加载 `.env` 或 `.copilotkit/project.json`。

导入之前，把生成的值复制到你的 shell 中：

```bash title="Terminal"
export INTELLIGENCE_API_URL="https://..."
export CPK_INTELLIGENCE_API_KEY="cpk-..."
```

你也可以改用 `--api-url` 和 `--api-key` 直接传入目的地。

## 导入对话

在试运行结果和智能体映射都确认无误后，运行导入。

```bash title="Terminal"
npx copilotkit@latest import \
  --source mastra \
  --agent-map ./agent-map.json
```

对于自托管的 CopilotKit Intelligence，请显式传入目标连接信息：

```bash title="Terminal"
npx copilotkit@latest import \
  --source mastra \
  --api-url "$INTELLIGENCE_API_URL" \
  --api-key "$CPK_INTELLIGENCE_API_KEY" \
  --agent-map ./agent-map.json \
  --yes
```

默认会跳过没有最终用户 ID 的对话。导入之前请设置 `MASTRA_IMPORT_END_USER_ID`。

## 验证导入的对话

打开 Threads Drawer，选择一个导入的 Mastra 对话，确认其历史记录显示在聊天中。

## 重新运行或替换

默认会跳过已导入过的对话。

使用 `--replace` 刷新它们；正在运行或已续写的对话保持不变：

```bash title="Terminal"
npx copilotkit@latest import \
  --source mastra \
  --agent-map ./agent-map.json \
  --replace
```

## 继续使用 Mastra 持久化

导入只是复制受支持的历史，并不会建立持续的数据库复制。Intelligence 的重命名、归档和删除操作只影响 Intelligence 记录，原生的 Mastra 记录保持不变。

你的应用会通过 CopilotKit 把之后的对话发送到 CopilotKit Intelligence。保持原始 Mastra 智能体及其持久化存储处于连接状态，并从 Threads Drawer 重新打开导入的对话，即可从上次中断的地方继续，包括受支持的待审批项与输入请求。

- **Threads Drawer**：CLI 创建的起步模板已内置。使用 [Threads Drawer 指南](/prebuilt-components/copilot-threads-drawer)自定义其现成的线程 UI。
- **无头线程**（Headless Threads）：只有需要自定义 UI 时才使用[无头线程指南](/headless-threads)。用 `useThreads` 选择一个线程，保存它的 `thread.id`，并把该值作为 `threadId` 传给你的聊天组件。

打开一个导入的对话并发送后续消息，即可继续它。
