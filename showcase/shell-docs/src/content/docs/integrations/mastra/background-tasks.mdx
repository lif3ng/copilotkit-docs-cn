## 这是什么？

Mastra 的[后台任务](https://mastra.ai/docs/agents/background-tasks)允许工具在智能体循环之外运行，而不是阻塞该循环。当一个工具被标记为 `background: { enabled: true }` 时，Mastra 会将它分派给自己的 `BackgroundTaskManager`，发出一个 `background-task-started` 生命周期 chunk，并返回一个占位结果，让对话继续流畅进行。

`MastraAgent`（AG-UI 适配器）会将该生命周期映射为 AG-UI **活动事件**（活动类型 `mastra-background-task`），并**抑制常规的工具 pill**——这样这项工作只会以实时“working”卡片的形式呈现，绝不会显示为孤立的工具调用。已注册的 CopilotKit 活动渲染器会在会话记录中内联绘制这张卡片。

## 什么时候应该使用它？

后台任务适合任何耗时过长、不该让对话干等的工作：

- **深度研究 / 长耗时查询**——启动一个多步骤的调查，让用户继续聊天
- **报告或产物生成**——在后台构建内容并展示进度
- **批量或扇出式工作**——同时分派多个任务，而不必让对话串行等待

<Callout type="info">
  完成结果是通过**带外**（out of band）方式送达的。在发起分派的那个回合中，Mastra 只会发出 `started` 生命周期外加一个占位结果，因此在该回合内卡片会一直处于“working”状态；完成的结果会在之后的回合送达（或从任务管理器中获取）。参见下文的[完成结果是带外送达的](#完成结果是带外送达的)。
</Callout>

<Step>
  ### 定义一个支持后台执行的工具

  用 `background: { enabled: true }` 标记该工具。Mastra 会将它分派给 `BackgroundTaskManager`，而不是内联执行。

  ```typescript title="src/mastra/tools/background-research.ts"
  import { createTool } from "@mastra/core/tools";
  import { z } from "zod";

  export const runDeepResearchTool = createTool({
    id: "run_deep_research",
    description:
      "Kick off a long-running deep-research task on a topic. This runs in " +
      "the background while the conversation continues.",
    inputSchema: z.object({
      topic: z.string().describe("The topic to research in depth."),
    }),
    background: { enabled: true }, // [!code highlight]
    execute: async ({ topic }) => {
      // Runs when the background worker executes the task.
      return JSON.stringify({
        topic,
        summary: `Deep research on "${topic}" completed.`,
      });
    },
  });
  ```
</Step>

<Step>
  ### 在 Mastra 实例上启用 BackgroundTaskManager

  只有在实例上启用了管理器时，支持后台执行的工具才会被分派。还需要配置 `storage`，以便追踪任务。

  ```typescript title="src/mastra/index.ts"
  import { Mastra } from "@mastra/core/mastra";
  import { LibSQLStore } from "@mastra/libsql";
  import { backgroundAgentsAgent } from "./agents";

  export const mastra = new Mastra({
    agents: { backgroundAgentsAgent },
    storage: new LibSQLStore({ id: "mastra-storage", url: ":memory:" }),
    backgroundTasks: { enabled: true }, // [!code highlight]
  });
  ```
</Step>

<Step>
  ### 将工具添加到你的智能体

  ```typescript title="src/mastra/agents/index.ts"
  import { Agent } from "@mastra/core/agent";
  import { openai } from "@ai-sdk/openai";
  import { runDeepResearchTool } from "@/mastra/tools/background-research"; // [!code highlight]

  export const backgroundAgentsAgent = new Agent({
    id: "background-agents",
    name: "Background Agents Agent",
    tools: { runDeepResearchTool }, // [!code highlight]
    model: openai("gpt-4.1"),
    instructions:
      "You are a research assistant that dispatches long-running work to the " +
      "background. When the user asks you to research a topic, call the " +
      "run_deep_research tool ONCE, then send a short message saying the work " +
      "is running in the background.",
  });
  ```
</Step>

<Step>
  ### 在前端渲染活动卡片

  为 `mastra-background-task` 活动类型编写一个活动渲染器。标准聊天界面会内联渲染已注册的活动消息，因此无需自定义消息列表。

  <FrontendOnly frontend="react">
  通过 `renderActivityMessages` 在 `<CopilotKit>` 上注册该渲染器。

  ```tsx title="ui/app/activity-card.tsx"
  import { z } from "zod";
  import type { ReactActivityMessageRenderer } from "@copilotkit/react-core/v2";

  const contentSchema = z
    .object({ status: z.string().optional(), args: z.record(z.unknown()).optional() })
    .passthrough();

  export const backgroundTaskActivityRenderer: ReactActivityMessageRenderer<
    z.infer<typeof contentSchema>
  > = {
    activityType: "mastra-background-task", // [!code highlight]
    content: contentSchema,
    render: ({ content }) => {
      const working = content.status !== "completed" && content.status !== "failed";
      const topic = (content.args?.topic as string | undefined) ?? "task";
      return (
        <div data-status={content.status ?? "running"}>
          <strong>Deep research</strong> — {topic}
          <span>{working ? "Working…" : content.status}</span>
        </div>
      );
    },
  };
  ```

  ```tsx title="ui/app/page.tsx"
  import { CopilotKit, CopilotChat } from "@copilotkit/react-core/v2";
  import { backgroundTaskActivityRenderer } from "./activity-card";

  export default function Page() {
    return (
      <CopilotKit
        runtimeUrl="/api/copilotkit"
        agent="backgroundAgentsAgent"
        renderActivityMessages={[backgroundTaskActivityRenderer]} // [!code highlight]
      >
        <CopilotChat />
      </CopilotKit>
    );
  }
  ```
  </FrontendOnly>

## 完成结果是带外送达的

按设计，发起分派的那次运行的流只会携带 `started` 生命周期外加一个占位结果——当流关闭时，工具的 `execute` 还没有执行完。因此在该回合内卡片会一直停留在“working”状态；完成的结果以带外方式送达。

Mastra 提供了 `untilIdle: true`（通过 `getLocalAgents`），用于保持运行不被关闭，并把管理器的 pubsub chunk（包括 `background-task-completed`）接入同一条流，从而让卡片能在同一回合内切换为“Completed”。这只有在**后台工作进程真正在空闲窗口关闭之前执行了被分派的任务**时才有效。在没有这类工作进程的单进程应用中，任务永远不会在该次运行内被执行，因此不会产生完成 chunk，`untilIdle` 只会让流保持打开，毫无收益。当你的部署拥有真正的后台工作进程时，启用 `untilIdle`，适配器的生命周期映射（`running` → `completed`/`failed`/`cancelled`）就会自动翻转卡片状态。否则，请通过任务管理器（`backgroundTaskManager.stream()` / `getTask(taskId)`）以带外方式获取结果。

## 以后台活动形式呈现 Observational Memory

如果你的智能体使用了 Mastra 的 [Observational Memory](https://mastra.ai/docs/memory/observational-memory)，你可以用同样的方式呈现其观察/缓冲/激活循环——以实时活动卡片的形式，而不是不可见的后台工作。这是可选项，默认关闭。

需要两个开关，二者缺一不可：

1. **智能体的 `Memory` 必须启用 Observational Memory**（Mastra 正是因此才会对 OM 生命周期进行流式传输）：

   ```typescript title="src/mastra/agents/index.ts"
   memory: new Memory({
     storage,
     options: {
       observationalMemory: {
         scope: "thread",
         observation: { messageTokens: 600, bufferTokens: 300 },
         model: openai("gpt-4.1"),
       },
     },
   }),
   ```

2. **必须告知适配器转发它**——向 `getLocalAgents` 传入 `observationalMemory: true`（或智能体 id 数组）：

   ```typescript title="app/api/copilotkit/route.ts"
   const localAgents = getLocalAgents({
     mastra,
     resourceId: "user-1",
     observationalMemory: true, // [!code highlight]
   });
   ```

两者都开启后，`MastraAgent` 会把 OM 生命周期映射为活动类型 `mastra-observational-memory` 下的 AG-UI 活动事件。渲染方式与后台任务卡片完全一致——为该活动类型注册一个渲染器：

<FrontendOnly frontend="react">
```tsx title="app/page.tsx"
const observationalMemoryActivityRenderer = {
  activityType: "mastra-observational-memory", // [!code highlight]
  render: ({ content }) => <OMActivityCard content={content} />,
};

<CopilotKit
  runtimeUrl="/api/copilotkit"
  renderActivityMessages={[observationalMemoryActivityRenderer]} // [!code highlight]
>
```
</FrontendOnly>

<FrontendOnly frontend="angular">
使用上文 Angular 源码区域中展示的 `observationalMemoryActivityRendererConfig` 及其注册方式。后台任务卡片与观察式记忆卡片使用相同的 `registerRenderActivityMessage` 生命周期。
</FrontendOnly>

活动内容携带该循环的信息（`cycleId`、`phase: "observation" | "buffering" | "activation"`、`status`、token 计数），并随着循环的推进原位更新，因此一张卡片即可追踪每个 OM 循环从开始到完成的全过程。

<Callout type="info">
  OM 循环依据**未观察的消息 token 数量**触发，而不是回合数——短对话可能永远触发不了。如果你正在测试卡片，请发送几条内容较多的消息。
</Callout>
