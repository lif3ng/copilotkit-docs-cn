CopilotKit 最常见的用例之一是使用 `useAgentContext` 注册应用状态与上下文。
这样，你就可以实时告知 CopilotKit 你的应用中正在发生什么。
例如：当前用户、当前页面等。

然后，此上下文可以与你的 Pydantic AI 智能体共享。

  如下所示，从 `run_input` 中读取条目并亲自交给智能体。
  参见 Pydantic AI 的 [AG-UI Context 指南](https://pydantic.dev/docs/ai/integrations/ui/ag-ui/#context)。

    ### 将数据添加到 Copilot

    [`useAgentContext` hook](/reference/v2/hooks/useAgentContext) 用于将数据作为上下文添加到 Copilot。

    ```tsx title="YourComponent.tsx"
    "use client" // only necessary if you are using Next.js with the App Router. // [!code highlight]
    import { useAgentContext } from "@copilotkit/react-core/v2"; // [!code highlight]
    import { useState } from 'react';

    export function YourComponent() {
      // Create colleagues state with some sample data
      const [colleagues, setColleagues] = useState([
        { id: 1, name: "John Doe", role: "Developer" },
        { id: 2, name: "Jane Smith", role: "Designer" },
        { id: 3, name: "Bob Wilson", role: "Product Manager" }
      ]);

      // Share context with the agent
      // [!code highlight:4]
      useAgentContext({
        description: "The current user's colleagues",
        value: colleagues,
      });
      return (
        // Your custom UI component
        <>...</>
      );
    }
    ```
  </Step>

  <Step>
    ### 在你的 Pydantic AI 智能体中使用数据

    条目通过 `RunAgentInput.context` 到达。分两步构建适配器，这样你就能
    访问 `run_input`、把条目传入 `deps`，并通过工具将它们
    暴露给模型。

    ```python title="agent.py"
    import json
    from dataclasses import dataclass

    from ag_ui.core import Context
    from pydantic_ai import Agent, RunContext
    from pydantic_ai.ui.ag_ui import AGUIAdapter
    from starlette.applications import Starlette
    from starlette.requests import Request
    from starlette.responses import Response
    from starlette.routing import Route


    @dataclass
    class AppContextDeps:
        """The entries the frontend shared on this run."""

        context: list[Context]


    agent = Agent(
        "openai:gpt-5.4-mini",
        instructions="You are a helpful assistant that can help emailing colleagues.",
        deps_type=AppContextDeps, # [!code highlight]
    )


    # [!code highlight:10]
    @agent.tool
    def colleagues(ctx: RunContext[AppContextDeps]) -> list[dict]:
        """The current user's colleagues, as the app shared them."""
        for entry in ctx.deps.context:
            if entry.description == "The current user's colleagues":
                # `useAgentContext` JSON-stringifies `value` before it leaves the
                # browser, and AG-UI types `Context.value` as a string, so parse it.
                return json.loads(entry.value)
        return []


    async def run_agent(request: Request) -> Response:
        # `dispatch_request` parses the request internally, so build the adapter in
        # two steps instead: `run_input` is what carries the frontend's entries.
        # [!code highlight:4]
        adapter = await AGUIAdapter.from_request(request, agent=agent)
        deps = AppContextDeps(context=adapter.run_input.context)
        return adapter.streaming_response(adapter.run_stream(deps=deps))


    app = Starlette(routes=[Route("/", run_agent, methods=["POST"])])

    if __name__ == "__main__":
        import uvicorn
        uvicorn.run(app, host="0.0.0.0", port=8000)
    ```

    有两个细节很容易错过：

    - **`value` 是字符串，而不是你的对象**。`useAgentContext` 会在运行离开浏览器之前对该值调用
      `JSON.stringify`，而 AG-UI 在两端都将 `Context.value` 类型定为字符串。因此必须使用
      `json.loads`，而像
      `isinstance(entry.value, list)` 这样的类型检查永远不会通过。
    - **用 `from_request`，而不是 `dispatch_request`**。这些文档其他地方用到的单行
      `AGUIAdapter.dispatch_request(request, agent=agent)` 会替你解析请求，
      这让你没有 `run_input` 可以用来构建 `deps`。
  </Step>

## 让条目保持为数据，而非指令

每一条目都是你的前端做出的一项声明，因此它描述的是一个请求——它永远不能确立
请求者的身份。请像上面的工具那样，以**数据**的形式把条目交给模型。
不要用它们来构造 [`instructions`](https://pydantic.dev/docs/ai/agents/#instructions)：指令承载着操作者权限，
如果用客户端提交的文本来拼装指令，提示词注入就会继承该权限。

由你的*服务端*确立的事实——经过身份验证的用户、工作区、租户——
才是应该放进指令的内容。要让某个客户端提供的事实改变智能体的行为，
应先对其进行身份验证，再查询你的服务端为它保存的策略，并据此撰写
指令。条目本身始终保持为数据。
