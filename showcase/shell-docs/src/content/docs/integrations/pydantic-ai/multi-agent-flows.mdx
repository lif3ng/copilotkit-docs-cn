## 什么是多智能体流？

在构建智能体化应用时，你常常需要编排一些需要多个智能体协同配合的复杂流。这在传统上称为多智能体编排（multi-agent orchestration）。

## 何时使用多智能体流？

当你需要编排多个智能体协同配合的复杂流时，多智能体流会很有用。随着智能体化应用的规模增长，将子任务委派给其他智能体，有助于扩展应用的关键部分。
- 将上下文切分为更小的块
- 将子任务委派给其他智能体
- 用单个智能体编排整个流

## CopilotKit 如何提供支持？

CopilotKit 有两种截然不同的使用模式：**路由模式**（Router Mode）或 **Agent Lock**。默认情况下，CopilotKit 使用路由模式，利用你配置的 LLM 在各智能体之间路由请求。

### 路由模式（默认）
使用 CoAgents 时，路由模式默认启用。要使用它，只需在 `CopilotKit` provider 组件中指定 runtime URL prop，并省略 `agent` prop，如下所示：
```tsx
<CopilotKit runtimeUrl="<copilot-runtime-url>">
  {/* Your application components */}
</CopilotKit>
```

在路由模式下，CopilotKit 充当中央枢纽，根据用户输入在不同智能体或操作之间动态选择并路由请求。这种模式适合以聊天为先的体验：LLM 聊天机器人是各类交互的入口，这些交互既可以留在聊天 UI 内，也可以扩展为原生 React UI 组件。

在这种模式下，CopilotKit 会根据上下文和用户输入，智能地将请求路由到最合适的智能体或操作。

<Callout type="warn">
    路由模式要求你先配置 LLM 适配器。具体方法参见文档中的[“配置 copilot runtime”](/quickstart?copilot-hosting=self-hosted#set-up-a-copilot-runtime-endpoint)一节。
</Callout>

### Agent Lock 模式
要使用 Agent Lock 模式，请在 `CopilotKit` 组件中通过 `agent` prop 指定智能体名称：
```tsx
// [!code word:agent]
<CopilotKit runtimeUrl="<copilot-runtime-url>" agent="<the-name-of-the-agent>">
  {/* Your application components */}
</CopilotKit>
```

在这种模式下，CopilotKit 被配置为只与某个特定智能体协作。当你想专注于特定任务或领域时，这种模式很有用。路由模式允许 LLM 和 CopilotKit 的路由器在多个智能体之间自由切换以处理用户请求，而 Agent Lock 模式下所有请求都停留在单个工作流图中，从而确保对工作流的精确控制。

选择最适合你应用体验的模式即可！另外请注意，虽然不能嵌套 `CopilotKit` provider，但你可以在应用的不同区域使用不同的智能体或模式——例如，你可以在一处使用能调用任意智能体或工具的路由模式聊天机器人，同时在另一处集成某个特定智能体，以实现更专注的工作流。
