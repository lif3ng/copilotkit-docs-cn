## 为现有应用接入 Intelligence

围绕你的 ADK 智能体，为用户提供跨设备的重连、追赶与消息送达能力。按照 [Intelligence 快速开始](/intelligence/quickstart) 连接你现有的 CopilotKit 应用与 Runtime，然后验证新对话能够被保存。这会为通过 CopilotKit 运行的会话启用 AG-UI 流；无需任何历史导入。

保持你的 ADK 智能体及其持久化存储处于连接状态，以便在导入对话之后能够继续这些对话。参见[流如何与框架存储协同工作](/intelligence/threads-explained#how-threads-work-with-framework-storage)。

## 纳入更早的对话（可选）

要让用户能够重新打开接入 Intelligence 之前记录的对话，请使用下方的导入器复制受支持的历史内容。导入不会启用实时送达，也不会建立持续的数据库复制，并且无法恢复源端已不再暴露的历史。

ADK 导入器从 ADK 数据库会话存储和 Vertex/Agent Engine 会话历史中读取持久化的会话。在可用的情况下，它会一并带来已保存的消息、富工具结果、附件以及智能体状态。某些交互式内容（例如 MCP 应用视图）可能没有保存在原始历史中。

以下前置条件与命令仅适用于该历史导入。使用 Threads Drawer 或 [Headless Threads](/headless-threads)，通过同一个 UI 打开已导入的对话和新对话。

## 前置条件

- 一个已接入 Intelligence 的现有 CopilotKit 应用。
- 已持久化的 ADK 会话。内存中的 ADK 会话无法导出。
- 环境变量中的 ADK 源凭据。
- 一份从 ADK `app_name` 值映射到你线上 CopilotKit `agentId` 的智能体映射。

<Callout type="warning" title="旧版 ADK pickle 存储">
  导入器不会解析旧版 ADK pickle 存储。请先使用 ADK 的会话迁移命令迁移这些会话，然后针对迁移后的存储重新运行导入。
</Callout>

## 确认目标项目

选择将接收这些历史的 Intelligence 项目。其 app-api URL 与项目级 runtime 密钥共同确定目的地。你需要在导入前导出这些值。

对于由 CLI 创建的应用，你可以选择一个云端托管的项目：

```bash title="Terminal"
npx copilotkit@latest project select
```

该命令会更新当前目录所选的项目，并把其项目级 runtime 密钥写入应用生成的 `.env`。

## 配置源

选择要读取的 ADK 后端。

<Tabs groupId="adk_import_backend" items={['Database', 'Vertex / Agent Engine']}>
  <Tab value="Database">
    ```bash title="Terminal"
    export ADK_SOURCE_BACKEND="database"
    export ADK_DATABASE_CONNECTION_STRING="postgres://..."
    export ADK_IMPORT_SCOPES="support:user-123"
    ```

    `ADK_IMPORT_SCOPES` 接受逗号分隔的选择器，例如 `app:user`、`app:*`、`*:user` 或 `*`。
  </Tab>
  <Tab value="Vertex / Agent Engine">
    ```bash title="Terminal"
    export ADK_SOURCE_BACKEND="vertex"
    export ADK_VERTEX_PROJECT_ID="my-gcp-project"
    export ADK_VERTEX_LOCATION="us-central1"
    export ADK_VERTEX_AGENT_ENGINE_ID="..."
    export ADK_IMPORT_SCOPES="support:*"
    ```

    导入器以与 ADK 相同的方式使用你的 Google 应用默认凭据或服务账号凭据。
  </Tab>
</Tabs>

你也可以通过 CLI 标志传递后端与作用域：

```bash title="Terminal"
npx copilotkit@latest import \
  --source adk \
  --adk-source-backend database \
  --adk-import-scopes "support:user-123" \
  --dry-run
```

## 进行试运行

在写入任何内容之前预览导入。

```bash title="Terminal"
npx copilotkit@latest import --source adk --dry-run
```

试运行会发现 ADK 应用名、统计会话数量、报告无法导入的会话，并估算上传大小。它不需要 CopilotKit Intelligence 的 URL 或 API 密钥。

## 将 ADK 应用名映射到 CopilotKit 智能体 ID

ADK 的源智能体键是 `app_name`。将发现的每个应用名映射到你线上 CopilotKit 运行时所使用的 `agentId`。

```json title="agent-map.json"
{
  "support": "support-agent",
  "research": "research-agent"
}
```

与线上流量使用相同的 `agentId`，可以让导入的会话与未来的对话归为一组。

## 准备 CopilotKit Intelligence 目的地

真正的导入需要目的地的 app-api URL 与项目级 runtime 密钥。由 CLI 创建的起步模板会把它们写入 `.env`，但导入器读取的是当前进程环境，不会自动加载 `.env` 或 `.copilotkit/project.json`。

导入前，请把生成的值复制到你的 shell 中：

```bash title="Terminal"
export INTELLIGENCE_API_URL="https://..."
export CPK_INTELLIGENCE_API_KEY="cpk-..."
```

你也可以改为用 `--api-url` 与 `--api-key` 直接传递目的地。

## 导入会话

在试运行结果与智能体映射确认无误后再运行导入。

```bash title="Terminal"
npx copilotkit@latest import \
  --source adk \
  --agent-map ./agent-map.json
```

对于自托管的 CopilotKit Intelligence，请显式传递目标连接信息：

```bash title="Terminal"
npx copilotkit@latest import \
  --source adk \
  --api-url "$INTELLIGENCE_API_URL" \
  --api-key "$CPK_INTELLIGENCE_API_KEY" \
  --agent-map ./agent-map.json \
  --yes
```

ADK 的用户归属默认取自 `session.user_id`。该值必须与你运行时的 `identifyUser` 返回的应用用户 ID 一致。默认情况下，无法恢复用户的会话会被跳过；只有当你有意把这些会话归入某个导入的兜底用户时，才使用 `--unrecoverable imported-unknown`。

## 验证已导入的会话

以你导入其 ID 的应用用户身份登录。从 Threads Drawer 打开该对话，确认更早的消息能够显示。发送一条消息，确认 ADK 更新的是同一个原生会话。

## 重新运行或替换

已导入的会话默认会被跳过。

使用 `--replace` 刷新它们；正在运行或已继续的会话保持不变：

```bash title="Terminal"
npx copilotkit@latest import \
  --source adk \
  --agent-map ./agent-map.json \
  --replace
```

## 继续使用 ADK 持久化

导入会复制受支持的历史，但不会建立持续的数据库复制。Intelligence 的重命名、归档与删除操作只影响 Intelligence 记录，原生 ADK 会话记录保持不变。

你的应用会通过 CopilotKit 把未来的对话发送到 CopilotKit Intelligence。保持原始 ADK 智能体及其持久化存储处于连接状态，并从 Threads Drawer 重新打开已导入的对话，即可从上次中断的地方继续，包括受支持的待审批事项与输入请求。

- **Threads Drawer**：由 CLI 创建的起步模板已内置。使用 [Threads Drawer 指南](/prebuilt-components/copilot-threads-drawer)自定义其现成的线程 UI。
- **Headless Threads**：仅在你需要自定义 UI 时使用 [Headless Threads 指南](/headless-threads)。用 `useThreads` 选择一个线程，保存其 `thread.id`，并把该值作为 `threadId` 传给你的聊天组件。

打开一个已导入的对话并发送后续消息，即可继续它。
