## 这是什么？

CopilotKit 最常见的用例之一，就是使用 `useAgentContext` 注册应用状态与上下文。
这样你就能让智能体实时了解你的应用中正在发生什么。

例如：当前用户、当前页面、当前屏幕上显示的表格行。

## 什么时候该用它？

当智能体的回答必须基于你的应用所持有的数据，而不是用户重新输入到聊天中的数据时，就使用它。队列、选区、购物车、筛选后的表格——页面里已经有了这些数据，而 `useAgentContext` 就是智能体获取它们的途径。

<Callout type="warn" title="ADK 需要在智能体侧补一行代码">
    与[内置智能体](/built-in-agent/agent-app-context)不同，ADK 智能体**不会**自动接收这些上下文。AG-UI 适配器只是把它存入 ADK 会话状态的 `CONTEXT_STATE_KEY`（即 `"_ag_ui_context"`）下，到此为止。没有任何环节会把它放进提示词。

    因此，用普通字符串 `instruction` 构建的 `LlmAgent` 永远看不到它。智能体依然会对着空无一物的输入流畅作答、格式正确——看起来像集成成功了，直到你拿答案与自己的数据核对才发现问题。下面的第 2 步就是把二者连接起来的关键一步。
</Callout>

    <Step>
        ### 与智能体共享数据

        [`useAgentContext` 钩子](/reference/v2/hooks/useAgentContext) 会把数据作为上下文添加给 Copilot。

        ```tsx title="YourComponent.tsx" showLineNumbers
        "use client" // only necessary if you are using Next.js with the App Router. // [!code highlight]
        import { useAgentContext } from "@copilotkit/react-core/v2"; // [!code highlight]
        import { useState } from 'react';

        export function YourComponent() {
            // Create colleagues state with some sample data
            const [colleagues, setColleagues] = useState([
                { id: 1, name: "John Doe", role: "Developer" },
                { id: 2, name: "Jane Smith", role: "Designer" },
                { id: 3, name: "Bob Wilson", role: "Product Manager" }
            ]);

            // Define agent context
            // [!code highlight:4]
            useAgentContext({
                description: "The current user's colleagues",
                value: colleagues,
            });
            return (
                // Your custom UI component
                <>...</>
            );
        }
        ```
    </Step>

    <Step>
        ### 在 ADK 智能体中读取上下文

        传入一个 [`InstructionProvider`](https://google.github.io/adk-docs/agents/llm-agents/#instructions) 而不是字符串。提供方会收到一个 `ReadonlyContext`，而适配器会把 CopilotKit 上下文留在 `ctx.state[CONTEXT_STATE_KEY]`。

        ```python title="agent.py"
        import json

        from ag_ui_adk import ADKAgent, CONTEXT_STATE_KEY, add_adk_fastapi_endpoint # [!code highlight]
        from google.adk.agents import LlmAgent
        from google.adk.agents.readonly_context import ReadonlyContext

        BASE_INSTRUCTION = """You are a helpful assistant that can help emailing colleagues.

        Answer only about the colleagues the page below sent you. If that list is empty, say the
        page sent no colleagues. If it holds colleagues but none of them match what the user asked
        about, say so and name the ones the page did send. Never invent a colleague."""


        def render_context(state) -> str:
            """Turn the entries the frontend sent into prompt text."""
            entries = state.get(CONTEXT_STATE_KEY) or [] # [!code highlight]
            if not entries:
                return "The page sent no context entries."

            blocks = []
            for entry in entries:
                description = entry.get("description", "(no description)")
                value = entry.get("value", "")
                # `value` arrives already JSON-encoded as a string. Anything else is encoded
                # here so a dict never reaches the prompt as a Python repr.
                if not isinstance(value, str):
                    value = json.dumps(value, ensure_ascii=False)
                blocks.append(f"### {description}\n{value}")
            return "\n\n".join(blocks)


        # An InstructionProvider, not a string. // [!code highlight]
        def build_instruction(ctx: ReadonlyContext) -> str:
            return f"{BASE_INSTRUCTION}\n\n## Context from the page\n\n{render_context(ctx.state)}\n"


        colleagues_agent = LlmAgent(
            name="colleagues_agent",
            model="gemini-3.8-flash",
            instruction=build_instruction, # [!code highlight]
        )

        adk_agent = ADKAgent(
            adk_agent=colleagues_agent,
            app_name="demo_app",
            user_id="demo_user",
            use_in_memory_services=True,
        )
        ```

        <Callout>
            `ctx.state` 是应当优先采用的形式，因为它在所有 `ag-ui-adk` 版本上都可用。在 `ag-ui-adk` 0.7.0 搭配 `google-adk` 1.22.0 及以上版本时，适配器还会把同样的条目复制到 `RunConfig.custom_metadata` 中，因此 `ctx.run_config.custom_metadata["ag_ui_context"]` 也能读到它们。但这两条路径本身都不会把它们放进提示词——那仍然是提供方的职责。
        </Callout>

        <Callout>
            就大括号而言，提供方也是更安全的形式。在字符串 instruction 下，ADK 会对文本运行 `inject_session_state`；其正则表达式会匹配任何 `{...}` 片段，但只有当内容是有效的状态名时才会替换。因此像 `{"id": 1}` 这样的 JSON 会被原样保留，而形如标识符的片段——例如某个上下文值里的 `{status}`——则会在会话状态中查找，找不到时就抛出 `KeyError`。提供方会在 `canonical_instruction` 中报告 `bypass_state_injection=True`（字符串则报告 `False`），因此渲染出的上下文完全不会被扫描。以上结论已对照 `ag-ui-adk` 0.7.0 所要求的 `google-adk` `>=1.28.1` 下限验证过。
        </Callout>
    </Step>

    <Step>
        ### 或在工具中读取

        同样的条目也会通过 `tool_context.state` 到达任何工具，当只有一个工具需要这些数据、而不必污染整个提示词时，这是更合适的方式。

        ```python title="tools.py"
        from ag_ui_adk import CONTEXT_STATE_KEY
        from google.adk.tools import ToolContext

        def find_colleague(tool_context: ToolContext, name: str) -> dict:
            """Look up one colleague among the ones the page sent."""
            entries = tool_context.state.get(CONTEXT_STATE_KEY) or [] # [!code highlight]
            # ... read the entry whose `description` matches the one you registered
            return {"found": False}
        ```
    </Step>

    <Step>
        ### 试试看！

        就上下文中的内容向你的智能体提问，它应该能够回答。

        然后把答案与你自己的数据核对，因为这是唯一一种会静默失败的集成。可靠的检验方法是做对照：用相同的请求分别发送一次带上下文、一次空上下文。如果两次答案描述的是同一条记录，就说明上下文没有起任何作用，智能体是在凭空编造作答。
    </Step>
</Steps>
