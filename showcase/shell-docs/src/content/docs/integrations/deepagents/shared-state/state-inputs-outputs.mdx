## 这是什么？

并非所有状态属性都需要在前端与后端之间共享。
本指南介绍如何确保只有恰当的状态部分会在前后端之间来回传递。

本指南基于 [LangGraph 的 Input/Output Schema 特性](https://docs.langchain.com/oss/python/langgraph/use-graph-api#define-input-and-output-schemas)

<Callout type="info">
此模式使用了 **LangGraph 的输入/输出 schema 拆分**，它适用于你自行构建自定义 LangGraph 图（graph）的场景。`createDeepAgent` 使用的是带单一状态 schema 的中间件，并不对外提供独立的输入/输出 schema。下方的 Python 示例展示的是 LangGraph 自定义图的做法。关于 Deep Agents TypeScript 中“智能体与前端共享状态”的等价实现，请参阅[共享状态指南](/deepagents/shared-state/in-app-agent-read)。
</Callout>

## 什么时候该用它？

取决于你的具体实现，有些属性仅供内部处理，而另一些则是 UI 用来传递用户输入的途径。
此外，某些状态属性包含大量信息，在智能体与 UI 之间来回同步它们可能代价高昂，却未必有实际收益。

## 实现方法

<Steps>
  <Step>
      ### 查看原有状态
      LangGraph 是有状态的。当你在节点之间流转时，状态会被更新并传递给下一个节点。在本例中，我们假设智能体应使用的状态可以这样描述：
      ```python title="agent.py"
      from copilotkit import CopilotKitState

      class AgentState(CopilotKitState):
          question: str
          answer: str
          resources: list[str]
      ```
  </Step>
  <Step>
    ### 将状态划分为 Input 和 Output
    我们的示例列出了若干状态属性，它们各有用途：
      - question 由用户提出，期望 LLM 作答
      - answer 是 LLM 返回的内容
      - resources 列表将由 LLM 用来回答问题，不应传递给用户，也不应由用户设置

      ```python title="agent.py"
      from copilotkit import CopilotKitState

      # Divide the state to 3 parts

      # Input schema for inputs you are willing to accept from the frontend
      class InputState(CopilotKitState):
        question: str

      # Output schema for output you are willing to pass to the frontend
      class OutputState(CopilotKitState):
        answer: str

      # The full schema, including the inputs, outputs and internal state ("resources" in our case)
      class OverallState(InputState, OutputState):
        resources: List[str]

      async def answer_node(state: OverallState, config: RunnableConfig):
        """
        Standard chat node, meant to answer general questions.
        """

        model = ChatOpenAI()

        # add the input question in the system prompt so it's passed to the LLM
        system_message = SystemMessage(
          content=f"You are a helpful assistant. Answer the question: {state.get('question')}"
        )

        response = await model.ainvoke([
          system_message,
          *state["messages"],
        ], config)

        # ...add the rest of the agent implementation

        # extract the answer, which will be assigned to the state soon
        answer = response.content

        return {
           "messages": response,
            # include the answer in the returned state
           "answer": answer
        }


      # finally, before compiling the graph, we define the 3 state components
      builder = StateGraph(OverallState, input=InputState, output=OutputState)

      # add all the different nodes and edges and compile the graph
      builder.add_node("answer_node", answer_node)
      builder.add_edge(START, "answer_node")
      builder.add_edge("answer_node", END)
      graph = builder.compile()
      ```
  </Step>
  <Step>
    ### 试一试！
    现在我们已经知道智能体会发出哪些状态属性，可以检查状态并预期会发生以下事情：
    - 我们能够提供 question，但不会从智能体那里收到它。如果要在 UI 中使用它，需要记住 UI 才是它的唯一事实来源
    - answer 会在智能体返回后发生变化
    - UI 无法访问 resources。

    ```tsx
    import { useAgent } from "@copilotkit/react-core/v2"; // [!code highlight]

    const { agent } = useAgent({
      agentId: "sample_agent",
    });

    const answer = agent.state.answer as string;

    console.log(answer) // You can expect seeing "answer" change, while the others are not returned from the agent
    ```
  </Step>
</Steps>
