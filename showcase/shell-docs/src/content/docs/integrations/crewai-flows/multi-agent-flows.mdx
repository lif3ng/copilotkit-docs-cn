## 什么是多智能体流？

在构建智能体化应用时，你经常需要编排需要多个智能体协同配合的复杂流程。这在传统上称为多智能体编排（multi-agent orchestration）。

## 什么时候该用它？

当你想编排需要多个智能体协同配合的复杂流程时，多智能体流会非常有用。随着智能体化应用不断增长，把子任务委托给其他智能体可以帮助你扩展应用的关键部分。

- 将上下文切分成更小的块
- 将子任务委托给其他智能体
- 使用单个智能体来编排整个流程

## CopilotKit 如何支持它？

CopilotKit 可以在两种不同的模式下使用：**路由模式**（Router Mode）**或**智能体锁定（Agent Lock）。默认情况下，CopilotKit 会使用路由模式，利用你配置的 LLM 在各智能体之间路由请求。

### 路由模式（默认）

使用 CoAgents 时，路由模式默认启用。要使用它，只需在 `CopilotKit` provider 组件中指定 runtime URL 属性，并省略 `agent` 属性，如下所示：

```tsx
<CopilotKit runtimeUrl="<copilot-runtime-url>">
  {/* Your application components */}
</CopilotKit>
```

在路由模式下，CopilotKit 充当中央枢纽，根据用户输入在不同智能体或操作之间动态选择并_路由_请求。这种模式适合以聊天为先的体验：LLM 聊天机器人是各类交互的入口，这些交互既可以留在聊天 UI 中，也可以扩展为原生 React UI 组件。

在这种模式下，CopilotKit 会根据上下文和用户输入，智能地将请求路由到最合适的智能体或操作。

<Callout type="warn">
  路由模式要求你配置 LLM 适配器。具体方法请参阅文档中[“配置 Copilot
  Runtime”](/quickstart?copilot-hosting=self-hosted#set-up-a-copilot-runtime-endpoint)一节。
</Callout>

### 智能体锁定模式

要使用智能体锁定模式，请通过 `agent` 属性在 `CopilotKit` 组件中指定智能体名称：

```tsx
// [!code word:agent]
<CopilotKit runtimeUrl="<copilot-runtime-url>" agent="<the-name-of-the-agent>">
  {/* Your application components */}
</CopilotKit>
```

在这种模式下，CopilotKit 被配置为只与特定的智能体协作。当你想专注于某个特定任务或领域时，这种模式非常有用。路由模式下，LLM 和 CopilotKit 的路由器可以在各智能体之间自由切换以处理用户请求；而智能体锁定模式下，所有请求都会留在同一个工作流图内，从而确保对工作流的精确控制。

哪种模式最适合你的应用体验，就用哪种！另外请注意：虽然 `CopilotKit` provider 不能嵌套，但你可以在应用的不同区域使用不同的智能体或模式——例如，你可以让聊天机器人以路由模式运行、能够调用任意智能体或工具，同时在其他位置集成某个特定智能体，以实现更聚焦的工作流。
