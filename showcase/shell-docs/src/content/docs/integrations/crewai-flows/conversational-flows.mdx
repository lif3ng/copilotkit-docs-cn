CrewAI 对话式 Flow 是 CrewAI Flows 的一种执行模式，而不是一个独立的 CopilotKit 集成。请先完成 [CrewAI 快速开始](/crewai-flows/quickstart)，然后将你现有的 Flow 及其 AG-UI 端点选择加入对话式执行。

CopilotKit 的每一轮对话都会传递给 CrewAI 的 `stream_turn` API。该集成将 CopilotKit 的 `threadId` 映射为 CrewAI 的 `session_id`，因此每个浏览器线程都拥有隔离的多轮对话。

<Callout type="info" title="完整的 CopilotKit 支持">
  对话式 Flow 支持与常规 CrewAI Flow 相同的 CopilotKit 特性，包括聊天组件、无头聊天、前端工具、工具渲染、生成式 UI、共享状态、推理、人机协同（human-in-the-loop）、子智能体、语音和多模态输入。升级 Flow 时，你的 CopilotKit 前端代码无需更改。
</Callout>

## 前置条件

- 完成 [CrewAI 快速开始](/crewai-flows/quickstart)，拥有一个可正常工作的 Flow 和 AG-UI 端点。
- 安装 CrewAI 1.15.11 或更高版本。更早的版本不提供此集成所需的 `stream_turn` 行为。
- 使用最新版本的 `ag-ui-crewai`。

```bash title="Terminal"
pip install -U "crewai>=1.15.11,<2" ag-ui-crewai
```

## 升级你的 Flow

<Steps>
  <Step>
    ### 在 Flow 上启用对话式执行

    在快速开始中创建的 Flow 类上添加 `conversational = True`。你不需要第二个智能体，也不需要单独部署。

    ```python title="flow.py"
    class SupportFlow(Flow[AppState]):
        conversational = True  # [!code highlight]

        # Keep your Flow methods, tools, and state here.
    ```
  </Step>

  <Step>
    ### 在端点上启用对话式执行

    用 FastAPI 注册 Flow 时传入同样的选择加入参数：

    ```python title="server.py"
    from fastapi import FastAPI
    from ag_ui_crewai import add_crewai_flow_fastapi_endpoint

    from flow import SupportFlow

    app = FastAPI()

    add_crewai_flow_fastapi_endpoint(
        app,
        SupportFlow(),
        "/",
        conversational=True,  # [!code highlight]
    )
    ```

    此时端点会调用 `stream_turn(message, session_id=thread_id)`，而不是通过常规的 `kickoff` 或 `astream` 路径启动 Flow。
  </Step>

  <Step>
    ### 保持 CopilotKit 前端不变

    继续使用快速开始和特性指南中相同的 `<CopilotKit>`、聊天组件、hook、工具和生成式 UI 组件。执行模式的更改完全位于 CrewAI 后端。
  </Step>
</Steps>

## 特性相关注意事项

大多数 CopilotKit 特性无需额外的对话式 Flow 配置。以下是需要注意的例外情况：

| 当你使用 | 该怎么做 |
| --- | --- |
| 自定义 Pydantic 状态 | 继承 `ag_ui_crewai.CopilotKitState`。除 CopilotKit 消息、工具和共享状态外，它还包含 CrewAI 所需的会话字段。 |
| CrewAI 对话式路由 | 使用 `route_turn()` 和 `@listen(...)` 对每一轮进行路由。返回公开回复或调用一次 `append_assistant_message()`；CrewAI 已经会追加当前用户消息。 |
| 配合 `useInterrupt` 的原生中断 | 像常规 CrewAI Flow 一样，使用 `emit_interrupt_outcome=True` 和 `enable_legacy_on_interrupt_event=False` 注册端点。 |
| CrewAI 持久化 | 继续使用 CrewAI 的 `@persist` 支持。CopilotKit 提供稳定的 `threadId`，该集成将其用作 CrewAI 的 `session_id`。 |

对于启用了中断的端点，注册方式如下：

```python title="server.py"
add_crewai_flow_fastapi_endpoint(
    app,
    SupportFlow(),
    "/",
    conversational=True,
    emit_interrupt_outcome=True,
    enable_legacy_on_interrupt_event=False,
)
```

## 现有 Flow 的路由

启用对话式模式会为你的 Flow 添加 CrewAI 的轮次路由器。如果你现有的 Flow 已经通过 `@start` 图产生一条公开响应，请确保对话式路由器不会再发送内置的 `converse` 响应。对于基于意图的对话，请将每轮的入口点移到 `route_turn()` 和 `@listen(...)` 处理器之后。

```python title="flow.py"
from crewai.flow import listen

class SupportFlow(Flow[AppState]):
    conversational = True

    def route_turn(self, _context):
        return "support"

    @listen("support")
    def answer(self):
        return self.run_existing_support_logic()
```

## 运行时约定

两处选择加入都是必需的。如果端点请求了对话式执行，但 Flow 既未声明 `conversational = True` 也未暴露 `stream_turn`，该集成会返回一个对应的 `RUN_ERROR`，而不是静默回退到常规 Flow 执行。
