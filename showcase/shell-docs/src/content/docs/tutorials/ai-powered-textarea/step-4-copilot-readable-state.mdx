---
title: "第 3 步：Copilot 可读状态"
---

到这里，我们已经配置好了 CopilotKit provider 和 `<CopilotTextarea />`，也享受到了一位出色 AI 助手带来的便利。不过还剩最后一个问题 —— copilot 助手并不了解这封邮件的往来内容。来解决这个问题吧。

## 应用的状态

我们快速回顾一下应用的状态是如何运作的。打开 [`lib/hooks/use-emails.tsx`](https://github.com/CopilotKit/CopilotKit/tree/main/examples/starters/textarea/start/lib/hooks/use-emails.tsx) 文件。

一眼望去就能看到，该文件暴露了一个持有 `emails` 的 provider（`EmailsProvider`）。要让 copilot 提供 AI 自动补全，就需要把这些上下文提供给它。

## `useAgentContext` hook

我们的目标是让 copilot 感知到这份状态，从而给出更准确、更有帮助的响应。借助 [`useAgentContext`](/reference/hooks/useAgentContext) hook 就能轻松实现。

```tsx title="libs/hooks/use-emails.tsx"
// ... the rest of the file

export const EmailsProvider = ({ children }: { children: ReactNode }) => {
  const [emails, setEmails] = useState<Email[]>(emailHistory);

  // [!code highlight:4]
  useAgentContext({
    description: "The history of this email thread",
    value: emails,
  });

  // ... the rest of the file
};
```

在本例中，我们用 `useAgentContext` hook 把邮件往来的状态提供给 copilot。

- `description` 属性：提供一段简明描述，告诉 copilot 这份可读数据的含义。
- `value` 属性：把整个状态以 JSON 字符串的形式传入。

在下一步中，我们将配置 AI 文本框，它会利用这份可读状态给出准确而有帮助的响应。

## 试试看吧！

现在回到应用，输入一些与邮件往来相关的内容。可以试试：

- `"Thanks Jo..."`（助手会补全出 John 的名字）
- `"I'm glad Spac..."`（助手会把公司名补全为 SpaceY）
- `"I'm glad they liked my..."`（助手会补充相关上下文）

现在，你的文本框已经完全了解这封邮件的往来内容，因此能给出有帮助且切题的自动补全。🚀
