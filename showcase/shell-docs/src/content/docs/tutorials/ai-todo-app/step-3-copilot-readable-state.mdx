---
title: "第 3 步：Copilot 可读状态"
---

到这里，应用中已经有了聊天弹窗，我们可以直接与 copilot 对话。这很棒，但 copilot 对我们的应用还一无所知。本步骤中，我们将把待办事项的状态提供给 copilot。

本步骤你将学到如何向 copilot 提供知识。就本例而言，我们想让 copilot 了解应用中的任务。

## 应用的状态

我们快速回顾一下应用的状态是如何运作的。打开 [`lib/hooks/use-tasks.tsx`](https://github.com/CopilotKit/CopilotKit/tree/main/examples/starters/todos-app/start/lib/hooks/use-tasks.tsx) 文件。

一眼望去就能看到，该文件暴露了一个 provider（`TasksProvider`），它定义了这些实用的内容：

- 任务状态（`tasks`）
- 添加任务的函数（`addTask`）
- 更新任务的函数（`updateTask`）
- 删除任务的函数（`deleteTask`）

这些内容都可以通过 `useTasks` hook 消费，应用的其余部分正是这样使用它的（欢迎查看 `TasksList`、`AddTask` 和 `Task` 组件）。

这与大多数 React 应用类似：无论是某个特性还是整个应用的前端状态，都由 context 或状态管理库来管理。

## `useAgentContext` hook

我们的目标是让 copilot 感知到这份状态，从而给出更准确、更有帮助的响应。借助 [`useAgentContext`](/reference/hooks/useAgentContext) hook 就能轻松实现。

```tsx title="lib/hooks/use-tasks.tsx" {3,8-11}
// ... the rest of the file

export const TasksProvider = ({ children }: { children: ReactNode }) => {
  const [tasks, setTasks] = useState<Task[]>(defaultTasks);

  // [!code highlight:4]
  useAgentContext({
    description: "The state of the todo list",
    value: JSON.stringify(tasks),
  });

  // ... the rest of the file
};
```

在本例中，我们用 `useAgentContext` hook 把任务状态提供给 copilot。

- `description` 属性：提供一段简明描述，告诉 copilot 这份可读数据的含义。
- `value` 属性：把整个状态以 JSON 字符串的形式传入。
