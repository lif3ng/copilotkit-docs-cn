Copilot Runtime 的 `agents` 映射接受 AG-UI `AbstractAgent` 实例。各框架适配器和 `HttpAgent` 都是它的子类，你也可以编写自己的子类。当你的智能体逻辑与运行时处于同一进程，且并非构建在 CopilotKit 已集成的框架之上时，就用这个方式。

如果你只想用自己的代码调用一个模型，[`BuiltInAgent` 工厂
模式](/backend/custom-agent)更省事：它会替你发出运行生命周期事件。如果你的智能体是一个已经通过 HTTP 说 AG-UI 的独立服务，请改用 [`HttpAgent`](#远程智能体使用-httpagent)。

## 安装

```bash
npm install @copilotkit/runtime @ag-ui/client@1.0.2 rxjs
```

你的 `@ag-ui/client` 必须是 `@copilotkit/runtime` 依赖的版本，这样应用里只有一份拷贝。运行 `npm ls @ag-ui/client`：它应该只显示一个去重后的版本。如果显示两个，请按 `@copilotkit/runtime` 下列出的版本重装 `@ag-ui/client`。

## 一个最小智能体

子类要实现 `run`。它接收 AG-UI 的 `RunAgentInput`（消息、工具、上下文、状态、`threadId`、`runId`），并返回一个由 AG-UI 事件组成的 RxJS `Observable`。以 `RUN_STARTED` 开始，以 `RUN_FINISHED` 结束，中间流式输出回复：

```ts title="lib/echo-agent.ts"
import {
  AbstractAgent,
  EventType,
  type BaseEvent,
  type RunAgentInput,
} from "@ag-ui/client";
import { Observable } from "rxjs";

export class EchoAgent extends AbstractAgent {
  run(input: RunAgentInput): Observable<BaseEvent> {
    return new Observable<BaseEvent>((subscriber) => {
      const { threadId, runId } = input;
      const last = input.messages.at(-1);
      const text = typeof last?.content === "string" ? last.content : "";
      const messageId = crypto.randomUUID();

      subscriber.next({ type: EventType.RUN_STARTED, threadId, runId });
      subscriber.next({ type: EventType.TEXT_MESSAGE_START, messageId, role: "assistant" });
      subscriber.next({ type: EventType.TEXT_MESSAGE_CONTENT, messageId, delta: `You said: ${text}` });
      subscriber.next({ type: EventType.TEXT_MESSAGE_END, messageId });
      subscriber.next({ type: EventType.RUN_FINISHED, threadId, runId });
      subscriber.complete();
    });
  }
}
```

工具调用、状态更新和推理是同一流上的更多事件。见
[AG-UI 事件参考](https://docs.ag-ui.com/concepts/events)。

## 在运行时中注册它

在 `agents` 映射中传入一个实例。键就是前端使用的智能体 ID。
不指定智能体名称时，聊天组件使用 `default`。

```ts title="app/api/copilotkit/[[...slug]]/route.ts"
import {
  CopilotRuntime,
  createCopilotRuntimeHandler,
  InMemoryAgentRunner,
} from "@copilotkit/runtime/v2";
import { EchoAgent } from "@/lib/echo-agent";

const runtime = new CopilotRuntime({
  agents: { default: new EchoAgent() },
  runner: new InMemoryAgentRunner(),
});

const handler = createCopilotRuntimeHandler({
  runtime,
  basePath: "/api/copilotkit",
});

export const GET = handler;
export const POST = handler;
export const PATCH = handler;
export const DELETE = handler;
```

智能体运行在路由处理器的进程内。没有单独的智能体服务器，也没有需要配置的 URL。前端配置与
[快速开始](/quickstart)相同。

## 智能体有自身字段时覆写 `clone`

运行时不会运行你注册的那个实例。对每个请求，它调用
`agent.clone()` 并运行副本，因此按请求的改动绝不会触及原始实例。

基类的 `AbstractAgent.clone()` 只复制 `AbstractAgent` 自身定义的字段，比如智能体 ID、线程 ID、消息、状态、订阅者和中间件。它不会调用你的构造函数。你的子类在构造函数中设置的字段，如 API 客户端、URL 或配置对象，在副本上是
`undefined`。

上面的 `EchoAgent` 没有自己的字段，因此基类 `clone` 就够了。在构造函数中接收客户端的智能体则需要自己复制它：

```ts title="lib/support-agent.ts"
import {
  AbstractAgent,
  EventType,
  type BaseEvent,
  type RunAgentInput,
} from "@ag-ui/client";
import { Observable } from "rxjs";

export interface SupportClient {
  answer(question: string, signal: AbortSignal): Promise<string>;
}

export class SupportAgent extends AbstractAgent {
  constructor(private client: SupportClient) {
    super();
  }

  override clone(): SupportAgent {
    const copy = super.clone() as SupportAgent;
    copy.client = this.client;
    return copy;
  }

  run(input: RunAgentInput): Observable<BaseEvent> {
    return new Observable<BaseEvent>((subscriber) => {
      const controller = new AbortController();
      const { threadId, runId } = input;
      const last = input.messages.at(-1);
      const question = typeof last?.content === "string" ? last.content : "";

      subscriber.next({ type: EventType.RUN_STARTED, threadId, runId });
      this.client
        .answer(question, controller.signal)
        .then((answer) => {
          const messageId = crypto.randomUUID();
          subscriber.next({ type: EventType.TEXT_MESSAGE_START, messageId, role: "assistant" });
          subscriber.next({ type: EventType.TEXT_MESSAGE_CONTENT, messageId, delta: answer });
          subscriber.next({ type: EventType.TEXT_MESSAGE_END, messageId });
          subscriber.next({ type: EventType.RUN_FINISHED, threadId, runId });
          subscriber.complete();
        })
        .catch((error) => subscriber.error(error));

      return () => controller.abort();
    });
  }
}
```

从 `super.clone()` 出发，再把你的字段加上去，就像 `HttpAgent` 复制它的 `url` 和 `headers` 那样。不要返回 `new SupportAgent(this.client)`：新实例初始不带任何中间件，你在启动时用 `agent.use(...)` 挂上去的一切都会悄然停止运行。

你只需要复制承载配置的字段。`run` 在每次运行开始时都会重置的字段保存的是按运行的临时状态，副本上丢失它没有任何影响。

`Observable` 内部返回的函数是它的 teardown。它在运行完成、失败或被取消订阅时执行，因此是取消在途工作的合适位置。

### 缺少 `clone` 时的症状

注册成功，`/info` 也列出了该智能体，但只要 `run` 一触及缺失的字段，每次运行都会失败。服务器日志：

```text
Agent execution failed: TypeError: Cannot read properties of undefined (reading 'answer')
```

使用 `InMemoryAgentRunner` 时，运行的事件流会以一个 `RUN_ERROR`
事件结束，它携带同样的消息和代码 `INCOMPLETE_STREAM`。如果错误点名列出的正是你自己的某个构造函数字段，就补一个复制该字段的 `clone` 覆写。

## 远程智能体：使用 `HttpAgent`

如果智能体作为独立服务运行并通过 HTTP 提供 AG-UI，就不要编写子类。注册一个指向该服务的 `HttpAgent`：

```ts title="app/api/copilotkit/[[...slug]]/route.ts"
import { HttpAgent } from "@ag-ui/client";
import { CopilotRuntime, InMemoryAgentRunner } from "@copilotkit/runtime/v2";

const runtime = new CopilotRuntime({
  agents: { default: new HttpAgent({ url: process.env.AGENT_URL! }) },
  runner: new InMemoryAgentRunner(),
});
```

`HttpAgent` 已经覆写了 `clone`。这里的 URL 是智能体服务自己的端点，不是运行时的。见 [Copilot Runtime](/backend/copilot-runtime#agents)。
