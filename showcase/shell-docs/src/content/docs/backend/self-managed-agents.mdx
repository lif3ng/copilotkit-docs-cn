前端 provider 通常通过
[运行时](/backend/copilot-runtime)与你的智能体通信：前端请求 `runtimeUrl`，运行时从 `/info` 发现智能体，代理在服务器端转发每次运行。但你也可以把 **AG-UI 智能体实例直接交给** provider，对这些智能体跳过运行时。生产环境与本地开发各有单独的选项，选对很重要。

## 生产环境：自管理智能体

`selfManagedAgents` 是连接你自己管理的智能体的受支持配置选项，比如一个指向你拥有且已加固的 AG-UI 兼容后端的 [`HttpAgent`](/backend/ag-ui)：

<Callout type="info" title="CopilotKit Intelligence 的一部分">
  `selfManagedAgents` 属于 CopilotKit 的 [Enterprise
  Intelligence 层级](/intelligence/intelligence-platform)。生产使用的授权事宜请[与工程师洽谈](https://copilotkit.ai/talk-to-an-engineer)。
</Callout>

<FrontendOnly frontend="react">
```tsx
import { HttpAgent } from "@ag-ui/client";
import { CopilotKit } from "@copilotkit/react-core/v2";

const supportAgent = new HttpAgent({
  url: "https://agents.example.com/support",
});

<CopilotKit
  selfManagedAgents={{ "support-agent": supportAgent }}
>
  <YourApp />
</CopilotKit>;
```
</FrontendOnly>

<FrontendOnly frontend="angular">
```ts title="src/app/app.config.ts"
import { ApplicationConfig } from "@angular/core";
import { HttpAgent } from "@ag-ui/client";
import { provideCopilotKit } from "@copilotkit/angular";

const supportAgent = new HttpAgent({
  url: "https://agents.example.com/support",
});

export const appConfig: ApplicationConfig = {
  providers: [
    provideCopilotKit({
      selfManagedAgents: { "support-agent": supportAgent },
    }),
  ],
};
```
</FrontendOnly>

每个键就是聊天组件与前端智能体 API 用来寻址该智能体的 `agentId`。自管理智能体使用你的传输方式和你的安全模型。由于请求不经过 CopilotKit 运行时，运行时的服务器端认证、中间件与路由都不适用。你的智能体端点必须对每个请求做认证与授权。

<Callout type="info">
你可以把 `selfManagedAgents` 与 `runtimeUrl` 组合使用。运行时发现的智能体与自管理智能体可以共存；用各自的 `agentId` 寻址。
</Callout>

## 开发环境：本地智能体

<FrontendOnly frontend="react">
`agents__unsafe_dev_only` 接受相同的结构：一个 `agentId` 到
`AbstractAgent` 的映射。这个名字故意起得很刺眼。只把它用于本地开发与原型。

```tsx
import { HttpAgent } from "@ag-ui/client";
import { CopilotKit } from "@copilotkit/react-core/v2";

const myAgent = new HttpAgent({ url: "http://localhost:8000" });

<CopilotKit agents__unsafe_dev_only={{ "my-agent": myAgent }}>
  <YourApp />
</CopilotKit>;
```

当你在本地接智能体、还不想搭一个运行时时，就用它。不要带上生产环境。如果你打算自己管理并加固连接，请切换到 `selfManagedAgents`，或者把智能体挪到
[运行时](/backend/copilot-runtime)后面。
</FrontendOnly>

<FrontendOnly frontend="angular">
Angular provider 的 `agents` 选项接受相同的结构，用于本地、浏览器内的开发：

```ts title="src/app/app.config.ts"
import { HttpAgent } from "@ag-ui/client";
import { provideCopilotKit } from "@copilotkit/angular";

const localAgent = new HttpAgent({ url: "http://localhost:8000" });

provideCopilotKit({
  agents: { "my-agent": localAgent },
})
```

`agents` 只用于本地开发与原型。生产环境请在加固端点后切换到 `selfManagedAgents`，或把智能体挪到[运行时](/backend/copilot-runtime)后面。
</FrontendOnly>

## 两者的关系

两个来源都注入同一个客户端智能体注册表。两者都提供时会合并，且**键冲突时 `selfManagedAgents` 胜出**：

<FrontendOnly frontend="react">
```ts
// effective agents ≈ { ...agents__unsafe_dev_only, ...selfManagedAgents }
```
</FrontendOnly>

<FrontendOnly frontend="angular">
```ts
// effective agents ≈ { ...agents, ...selfManagedAgents }
```
</FrontendOnly>

通过任一 provider 选项提供智能体，也能在至少注册了一个本地智能体时满足前端配置检查。

<FrontendOnly frontend="react">
你不会看到
`Missing required prop: 'runtimeUrl' or 'publicApiKey' or 'publicLicenseKey'`
报错；见[错误参考](/troubleshooting/error-reference)。
</FrontendOnly>

| | `selfManagedAgents` | 本地智能体 |
|---|---|---|
| **用途** | 生产环境、你自己管理的智能体 | 本地开发 / 原型 |
| **认证** | 由你负责 | 由你负责 |
| **运行时中间件 / 路由** | 不适用 | 不适用 |
| **键冲突时的优先级** | 胜出 | 被 `selfManagedAgents` 覆盖 |
