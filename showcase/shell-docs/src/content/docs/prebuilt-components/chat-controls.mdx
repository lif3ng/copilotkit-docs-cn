预构建聊天有两个常见的控制需求：从你自己的 UI 打开它，以及捕获助手消息上的点赞/点踩反馈。

## 从你自己的 UI 控制打开状态

将 `open` 与 `onOpenChange` 传给 `<CopilotSidebar>` 或 `<CopilotPopup>`，即可自己掌握打开状态。这就是受控模式：界面完全按照 `open` 的值来渲染，而每一个打开或关闭的请求（切换按钮、点击弹窗外部）都会通过 `onOpenChange` 送达，而不是直接改变界面状态。

```tsx
import { useState } from "react";
import { CopilotSidebar } from "@copilotkit/react-core/v2";

function Layout() {
  const [chatOpen, setChatOpen] = useState(false);

  return (
    <>
      <nav>
        <button onClick={() => setChatOpen(true)}>Ask the assistant</button>
      </nav>

      <CopilotSidebar open={chatOpen} onOpenChange={setChatOpen} />
    </>
  );
}
```

按钮位于侧边栏之外，这正是关键所在：无需在聊天子树内渲染任何东西就能打开或关闭它。由于 `open` 是唯一的事实来源，你还可以让聊天与路由、键盘快捷键或你已有的任何其他状态保持同步。

<Callout type="info">
`onOpenChange` 报告的是一个请求，而不是一次变更。如果你不把新值回写到 `open`，界面就会保持原样。正因如此，你可以为打开聊天设置门槛，例如要求先通过登录检查。你也可以只传 `onOpenChange` 而不传 `open`：界面继续自行管理，而它每次打开或关闭时你都会收到通知。
</Callout>

## 以编程方式打开或关闭聊天

如果你不想把状态提升到自己的组件里，`<CopilotPopup>` 和 `<CopilotSidebar>` 的打开状态也保存在 **聊天配置上下文** 中。通过 `useCopilotChatConfiguration()` 读取它，并在 provider 内的任意位置调用 `setModalOpen(true | false)`：

```tsx
import { useCopilotChatConfiguration } from "@copilotkit/react-core/v2";

function OpenChatButton() {
  const config = useCopilotChatConfiguration();

  // setModalOpen is only present when a provider in the tree owns modal state
  // (the prebuilt CopilotPopup / CopilotSidebar create it for you).
  if (!config?.setModalOpen) return null;

  return (
    <button onClick={() => config.setModalOpen(true)}>
      Ask the assistant
    </button>
  );
}
```

若要切换，读取 `config.isModalOpen` 并取反即可：

```tsx
<button onClick={() => config.setModalOpen(!config.isModalOpen)}>
  {config.isModalOpen ? "Close chat" : "Open chat"}
</button>
```

<Callout type="info">
`setModalOpen` / `isModalOpen` 只有在组件树中有 provider 持有模态状态时才有定义。预构建的 `<CopilotPopup>` 和 `<CopilotSidebar>` 会自动创建它。如果你自行组装聊天，请将相关子树包裹在 `<CopilotChatConfigurationProvider isModalDefaultOpen={false}>` 中，以确保模态状态存在。参见 [`useCopilotChatConfiguration` 参考](/reference/hooks/useCopilotChatConfiguration#modal-state-management)。
</Callout>

你还可以用声明式方式设置 **初始** 打开状态，然后让界面自行管理。预构建界面接受一个 `defaultOpen` prop：

```tsx
<CopilotSidebar defaultOpen={false} />
```

`defaultOpen` 与 `open` 就是非受控/受控这对常见搭配：用 `defaultOpen` 指定起始状态，用 `open` 让你自己的状态做决定。两者同时传入时，`open` 优先。

## 捕获消息反馈（点赞/点踩）

助手消息工具栏可以显示点赞和点踩按钮。在 v2 中，通过向 **助手消息插槽** 传入 `onThumbsUp` / `onThumbsDown` 来启用该功能。在没有开启 Automatic Learning 采集的情况下，只有提供了处理器或自定义点赞插槽时，这些按钮才会渲染：

```tsx
import { CopilotChat } from "@copilotkit/react-core/v2";

<CopilotChat
  messageView={{
    assistantMessage: {
      onThumbsUp: (message) => {
        analytics.track("feedback", { messageId: message.id, value: "up" });
      },
      onThumbsDown: (message) => {
        analytics.track("feedback", { messageId: message.id, value: "down" });
      },
    },
  }}
/>;
```

每个处理器都会收到助手 `message`，因此你可以把反馈关联到具体的那条响应（`message.id`）。由于 `<CopilotPopup>` 和 `<CopilotSidebar>` 都是对 `<CopilotChat>` 的封装，同样的 `messageView` 插槽在这两者上同样可用。

当插槽通过 `CopilotChatMessageView` 渲染时，由直接的 AG-UI `TEXT_MESSAGE_START` 创建的实时助手消息还可以携带该事件的不透明 `rawEvent` 值。拼接发生在点赞回调运行时；规范化消息和未来的运行输入保持不变。chunk、snapshot、持久化、旧版以及直接使用 `CopilotChatAssistantMessage` 的路径不提供这一回调元数据。

按钮文案来自聊天标签（`assistantMessageToolbarThumbsUpLabel` 默认为 `"Good response"`，`assistantMessageToolbarThumbsDownLabel` 默认为 `"Bad response"`）；可以通过[聊天标签](/reference/hooks/useCopilotChatConfiguration#copilotchatlabels)覆盖它们。

开启 [Automatic Learning 采集](/intelligence/capture-interactions#collect-reply-ratings)并启动一个 Trajectory 后，在任何像 `CopilotChat`、`CopilotPopup`、`CopilotSidebar` 那样在 `CopilotChatConfigurationProvider` 内使用 `CopilotChatMessageView` 渲染消息的聊天中，这些按钮无需处理器就会出现。此时评分还会发送到当前活跃的 Trajectory，用户可以添加评论，再次点击已选择的按钮则会移除评分。你的处理器只在给出评分时运行，移除评分时不会运行。

<Callout type="info">
想构建完全自定义的消息组件而不使用插槽？底层的 [`CopilotChatAssistantMessage`](/reference/components/CopilotChatAssistantMessage) 直接暴露了同样的 `onThumbsUp` / `onThumbsDown` props，但回调元数据的丰富由 `CopilotChatMessageView` 负责。
</Callout>
