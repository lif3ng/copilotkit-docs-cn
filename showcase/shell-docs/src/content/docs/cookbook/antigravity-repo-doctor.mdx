[Google Antigravity](https://github.com/google-antigravity/antigravity-sdk-python) 是 Google 的 agent SDK。它的 harness 调用 Gemini 并给 agent 提供真实的工具：在你选择的文件夹中读取和编辑文件、运行 shell 命令。[Antigravity AG-UI SDK（`ag-ui-antigravity`）](https://github.com/ag-ui-protocol/ag-ui/tree/main/integrations/antigravity/python)通过 [AG-UI](https://docs.ag-ui.com/) 对外服务该 agent，让 [CopilotKit](https://www.copilotkit.ai/) 应用可以与它对话。

<Callout type="info" title="OpenBot 中的 Antigravity">
[OpenBot](https://github.com/CopilotKit/OpenBot) 把 Google Antigravity 作为它的 Bot 之一提供，构建在同一个 Antigravity AG-UI SDK 之上。如果你想要一个开箱即跑、可自托管的应用中的 Antigravity，从 [`agent-antigravity`](https://github.com/CopilotKit/OpenBot/tree/main/agent-antigravity) 开始。
</Callout>

本篇示例带你走一遍 **Repo Doctor**：一个修复 GitHub 仓库损坏 CI 的应用。它读取 CI 结果、运行测试、复现失败，然后修复代码、以 diff 形式展示改动，并在推送前证明修复有效。你可以批准或拒绝每个有风险的步骤，或交给自动批准处理，最后下载整次运行的报告。

## 你将构建什么

一个带仓库从 CI 失败走到推送修复的聊天：

- 你说出一个公开的 GitHub 仓库，或点击开始屏幕上的一张卡片。
- agent 读取 CI 并告诉你哪里在失败。每个有风险的步骤（安装、检查、文件编辑、推送）都会以一张带 **Approve**（批准）与 **Deny**（拒绝）的卡片出现。
- 你看着聊天中的测试结果从红变绿，改动以 diff 形式展示。
- 最后你会得到一个已推送的修复分支和一份可下载的报告。

侧边面板记录仓库、检查、每次测试运行和你做出的每个决定。

## 开始之前

你需要 Node.js 22 或更新版本、[pnpm](https://pnpm.io/)、Python 3.13、[uv](https://docs.astral.sh/uv/)、`git`，以及为带原生扩展的项目准备的 C 编译器（macOS 上是 Xcode 命令行工具）。从 [Google AI Studio](https://aistudio.google.com/apikey) 获取 Gemini API 密钥。

agent 会在你的机器上安装并运行被克隆仓库的代码，请只在你信任的仓库上尝试。

## 快速开始

成品示例位于 CopilotKit 仓库中：

```bash
git clone --depth 1 https://github.com/CopilotKit/CopilotKit.git
cd CopilotKit/examples/showcases/antigravity-repo-doctor
pnpm install && pnpm dev
```

第一次 `pnpm dev` 会创建 `.env`、用 uv 安装 Python agent，然后停下等你添加 Gemini 密钥。添加后再次运行 `pnpm dev`。打开 [http://localhost:3000](http://localhost:3000)，在导航栏输入你的名字，点击 **google-gemini/genai-processors** 卡片。

下面的步骤一次一块地构建同一个应用。每个片段都来自该示例，每个标题就是它所在的文件，方便你对照页面打开完整文件。`# ...` 或 `// ...` 行表示省略的代码。

### 创建 Web 应用

Repo Doctor 是两个进程：一个带聊天和 CopilotKit 运行时的 Next.js 应用，以及旁边 `agent/` 里的 Python agent。先建 Next.js 应用并安装 CopilotKit 包，使用示例所用的版本：

```bash
pnpm create next-app@16.4.1 repo-doctor --yes
cd repo-doctor
pnpm add @copilotkit/react-core@1.79.0 @copilotkit/runtime@1.79.0 @copilotkit/a2ui-renderer@1.79.0 @ag-ui/client@1.0.2 zod@3.25.76
```

`@copilotkit/a2ui-renderer` 负责绘制测试结果卡片，`@ag-ui/client` 把运行时连接到 Python agent。A2UI catalog 需要 zod 3，所以 `zod` 固定在 3.25.76。

provider 包裹整个应用。它指向运行时路由、为测试结果卡片注册 A2UI catalog（你会在后面的步骤中构建它），并在开发环境打开 CopilotKit Inspector：

```tsx title="src/components/shell/app-shell.tsx"
"use client";

import {
  CopilotChatConfigurationProvider,
  CopilotKit,

import { catalog } from "@/a2ui/catalog";
// ...

const A2UI = { catalog }; // [!code highlight]

// ...

export function AppShell(props: ShellProps) {
  return (
    <CopilotKit
      runtimeUrl="/api/copilotkit"
      useSingleEndpoint={false}
      a2ui={A2UI} // [!code highlight]
      enableInspector={process.env.NODE_ENV === "development"} // [!code highlight]
    >
      <CopilotChatConfigurationProvider agentId={AGENT_ID}>
        {/* ... */}
      </CopilotChatConfigurationProvider>
    </CopilotKit>
  );
}
```

`src/app/page.tsx` 渲染 `AppShell`，它把聊天排在中间、侧边面板排在右侧。聊天是 `CopilotChat`，指向该 agent：

```tsx title="src/components/chat/chat-panel.tsx"
<CopilotChat
  // ...
  agentId={AGENT_ID} // [!code highlight]
  className="h-full"
  welcomeScreen={Welcome}
  // ...
/>
```

`welcomeScreen` 用开始屏幕及其仓库卡片替换空聊天。完整布局在 [`app-shell.tsx`](https://github.com/CopilotKit/CopilotKit/tree/main/examples/showcases/antigravity-repo-doctor/src/components/shell/app-shell.tsx) 和 [`chat-panel.tsx`](https://github.com/CopilotKit/CopilotKit/tree/main/examples/showcases/antigravity-repo-doctor/src/components/chat/chat-panel.tsx)。

### 创建智能体

agent 是 `agent/` 里的一个 uv 项目。创建它并一次性加入 Antigravity SDK 与其 AG-UI 适配器：

```bash
uv init --package --name repo-doctor agent
cd agent
uv add ag-ui-antigravity==0.2.1 google-antigravity==0.1.22 ag-ui-protocol==1.0.0 fastapi==0.143.2 "uvicorn[standard]==0.54.0" pydantic==2.14.1 pydantic-settings==2.16.0
```

`google-antigravity` 是带 harness 的 SDK，[`ag-ui-antigravity`](https://github.com/ag-ui-protocol/ag-ui/tree/main/integrations/antigravity/python) 通过 AG-UI 对外服务它。

从[示例的 agent 文件夹](https://github.com/CopilotKit/CopilotKit/tree/main/examples/showcases/antigravity-repo-doctor/agent/src/repo_doctor)复制这些辅助文件：

- [`config.py`](https://github.com/CopilotKit/CopilotKit/tree/main/examples/showcases/antigravity-repo-doctor/agent/src/repo_doctor/config.py) 读取 `.env` 并设置 agent 工作的文件夹。
- `shell.py` 运行命令，`workspace.py` 管理会话文件夹，`project.py` 推导安装与测试命令。

agent 是 Antigravity AG-UI SDK 的 `AntigravityAgent`，这里通过一个小子类使用。配置选定模型与提示、列出 agent 可用的内置工具、把 harness 指向一个工作区文件夹，并打开审批：

```python title="agent/src/repo_doctor/agent.py"
# ...
def create_agent(settings: Settings) -> ThreadScopedAntigravityAgent:
    # ...
    return ThreadScopedAntigravityAgent(
        settings=settings,
        # ...
        model=settings.gemini_model,
        api_key=settings.gemini_api_key.get_secret_value(),
        # ...
        system_instructions=SYSTEM_INSTRUCTIONS,
        capabilities=CapabilitiesConfig(enabled_tools=ENABLED_BUILTINS, enable_subagents=False),
        # Replaced per thread by ThreadScopedAntigravityAgent._build_agent.
        workspaces=[str(settings.workspace_root)],
        # ...
        tool_approval=True,  # [!code highlight]
        auto_approve_tools=list(AUTO_APPROVED),  # [!code highlight]
        # ...
    )
```

`tool_approval=True` 会暂停所有不在 `auto_approve_tools` 中的工具调用：

- **自行运行**：只读的内置工具（列出、搜索、查找和查看文件），以及 `clone_repo`、`ci_status`、`run_tests` 和 `show_diff`。
- **等你批准**：安装、检查、文件编辑、shell 命令和推送。

`ENABLED_BUILTINS` 打开文件与 shell 工具，外加 `finish`——harness 结束一轮所必需。

[`prompts.py`](https://github.com/CopilotKit/CopilotKit/tree/main/examples/showcases/antigravity-repo-doctor/agent/src/repo_doctor/prompts.py) 中的提示告诉模型何时用哪个工具，以及只有当检查从失败变为通过时，修复才算已验证。

一次调用就把 agent 变成 AG-UI 端点。`create_antigravity_app` 返回一个在 `POST /` 服务该 agent 的 FastAPI 应用：

```python title="agent/src/repo_doctor/server.py"
from ag_ui_antigravity import create_antigravity_app

# ...

def create_app() -> FastAPI:
    settings = get_settings()
    # ...
    agent = create_agent(settings)
    app: FastAPI = create_antigravity_app(agent, path="/")  # [!code highlight]
    # ...
    return app


def main() -> None:
    settings = get_settings()
    # ...
    uvicorn.run(create_app(), host=settings.agent_host, port=settings.agent_port)
```

两个进程读取项目根目录的同一个 `.env`。把 Gemini 密钥放进去，如果有的话再放一个 GitHub token（只读 token 能把 CI 查询限额从每小时 60 次提高到 5,000 次）。`AGENT_URL` 告诉 Web 应用 agent 监听在哪里：

```plaintext title=".env"
GEMINI_API_KEY=
GITHUB_TOKEN=
AGENT_URL=http://127.0.0.1:8000/
```

在 `agent/` 目录用 `uv run python -m repo_doctor.server` 启动 agent。它监听 127.0.0.1:8000。

### 连接运行时

运行时路由通过 AG-UI 把聊天连接到 Python agent。`HttpAgent` 把每次运行发送到 agent 的 URL，`a2ui` 选项打开 A2UI 中间件，把 agent 的测试结果卡片传递给聊天：

```ts title="src/app/api/copilotkit/[[...slug]]/route.ts"
import { HttpAgent } from "@ag-ui/client";
import {
  CopilotRuntime,
  createCopilotRuntimeHandler,
} from "@copilotkit/runtime/v2";
// ...

const agent = new HttpAgent({ url: env.AGENT_URL }); // [!code highlight]

const runtime = new CopilotRuntime({
  agents: { [AGENT_ID]: agent },
  a2ui: { injectA2UITool: false }, // [!code highlight]
  // ...
});

const handler = createCopilotRuntimeHandler({
  runtime,
  basePath: "/api/copilotkit",
});

export const GET = handler;
export const POST = handler;
export const PATCH = handler;
export const DELETE = handler;
```

harness 调用 Gemini，运行时自身从不调用模型。`injectA2UITool: false` 告诉运行时 agent 自己编写 A2UI 界面，因此不会给模型额外的渲染工具。省略的行会在你添加密钥后连接 CopilotKit Intelligence，见 CopilotKit Intelligence 一节。

在一个终端运行 `pnpm dev`，另一个终端运行 agent。打开 [http://localhost:3000](http://localhost:3000) 打个招呼。agent 会在聊天中回应。

</Step>

### 给智能体配置 CI 工具

agent 自有的工具位于 [`tools.py`](https://github.com/CopilotKit/CopilotKit/tree/main/examples/showcases/antigravity-repo-doctor/agent/src/repo_doctor/tools.py)：

- `clone_repo` 做浅克隆。
- `ci_status` 读取最新的 GitHub Actions 结果，指出失败的 job 和步骤。
- `install_dependencies` 安装项目。
- `run_tests` 运行测试套件。
- `run_check` 运行一条复现失败的命令。
- `show_diff` 返回真实的 `git diff`。
- `git_push` 在新分支上提交修复并推送到本地仓库，绝不推送到 GitHub。

每个都是带 docstring 的普通 async 函数。SDK 读取函数签名与 docstring，把该函数连同 Antigravity 内置文件工具一起提供给模型。

工具把发生的事情记录在共享状态里，侧边面板稍后读取它。`experimental_set_state` 会整体替换该状态并立即流式传到浏览器，因此这个辅助函数把每次变更合并进当前状态：

```python title="agent/src/repo_doctor/tools.py"
from ag_ui_antigravity import experimental_get_state, experimental_set_state

# ...

def _update_state(**changes: Any) -> None:
    experimental_set_state({**_state(), **changes})  # [!code highlight]
```

`clone_repo` 是 agent 调用的第一个工具。它克隆仓库，然后把了解到的东西存到共享状态的 `repo` 下：

```python title="agent/src/repo_doctor/tools.py"
async def clone_repo(repo_ref: str) -> dict[str, Any]:
    """Clones a public GitHub repository into this conversation's workspace."""
    try:
        slug = parse_repo_ref(repo_ref)
    except ValueError as exc:
        return _error(str(exc))
    # ...
    cloned = await shell.run(
        [
            "git",
            "clone",
            "--depth",
            "1",
            "--no-tags",
            f"https://github.com/{slug}.git",
            ".",
        ],
        cwd=repo,
        timeout=timeout,
    )
    if not cloned.ok:
        return _error(f"git clone failed: {cloned.output.strip()[-800:]}")
    await ensure_local_push_remote()  # [!code highlight]
    # ...
    info: dict[str, Any] = {
        "slug": slug,
        "path": str(repo),
        "url": f"https://github.com/{slug}",
        "branch": branch,
        # ...
    }
    # ...
    _update_state(repo=info)  # [!code highlight]
    # ...
```

有几点值得注意：

- 错误以 `{"ok": False, "error": ...}` 形式返回而不是抛出，让模型读到它们并决定下一步。
- `ensure_local_push_remote` 把 GitHub remote 重命名为 `upstream`、关闭其推送 URL，并把一个本地裸仓库添加为 `origin`。`git_push` 随后按路径推送到该裸仓库而不是 `origin`，关闭 git hooks，并在仓库配置重写 URL 时拒绝执行。即使 shell 命令改动了 `origin`，推送也永远到不了 GitHub。
- 接着运行 `ci_status`。它列出每个 workflow 的失败步骤，这通常足以让模型在 workflow 文件中找到对应的命令（[`ci.py`](https://github.com/CopilotKit/CopilotKit/tree/main/examples/showcases/antigravity-repo-doctor/agent/src/repo_doctor/ci.py)）。

`build_tools(workspace, settings)` 返回绑定到同一文件夹的七个工具。`ThreadScopedAntigravityAgent` 在 `_build_agent` 中为每条会话调用它（[`agent.py`](https://github.com/CopilotKit/CopilotKit/tree/main/examples/showcases/antigravity-repo-doctor/agent/src/repo_doctor/agent.py)），因此两条会话绝不会共享一个检出。

### 证明修复有效

仅凭测试通过并不能证明修复解决了 CI 看到的失败。这是 `run_check` 的职责。agent 把失败的 CI 步骤变成一条短命令并运行两次：修复前必须失败，修复后必须通过：

```python title="agent/src/repo_doctor/tools.py"
async def run_check(command: str, label: str) -> dict[str, Any]:
    """Runs one shell command that reproduces a failing CI step, and records it."""
    # ...
    result = await shell.run(
        [shell_bin, "-c", command], cwd=repo, timeout=CHECK_TIMEOUT_SECONDS, env=_check_env()
    )
    # ...
    exit_code = result.exit_code
    status = "passed" if exit_code == 0 else "failed"  # [!code highlight]
    # ...
    checks: list[dict[str, Any]] = list(_state().get("checks", []))
    number = len(checks) + 1
    record = {
        "run": number,
        "label": label,
        "command": command,
        "status": status,
        # ...
    }
    checks.append(record)
    _update_state(checks=checks)  # [!code highlight]
    return {
        "ok": True,
        **record,
        "output_tail": _ANSI.sub("", result.output)[-_CHECK_TAIL_CHARS:],
    }
```

- 退出码决定通过或失败。运行超过两分钟的检查按失败计。
- 每次检查都会加入共享状态的 `checks`，侧边面板因此能把失败的运行与通过的运行并列列出。

### 批准或拒绝每个有风险的步骤

当模型调用需要审批的工具时，适配器让该调用保持等待，并以一个中断结束运行。中断的 reason 是 `tool_approval`，元数据携带工具名与参数。[`useInterrupt`](/reference/hooks/useInterrupt) 为它渲染一张卡片，`resolve` 把你的答复连同中断 id 送回，从而继续那个等待中的调用：

```tsx title="src/components/chat/tool-renderers.tsx"
useInterrupt({
  agentId: AGENT_ID,
  enabled: (event) =>
    (event.value as { reason?: string } | undefined)?.reason === // [!code highlight]
    "tool_approval", // [!code highlight]
  render: ({ interrupt, resolve }) => {
    const { tool_name, args, ...meta } = (interrupt?.metadata ?? {}) as {
      tool_name?: string;
      args?: Record<string, unknown>;
    } & Record<string, unknown>;
    const tool = tool_name ?? "tool";
    return (
      <ApprovalCard
        key={interrupt?.id}
        request={{ tool, args: args ?? {}, meta }}
        repoPath={repoPath}
        autoApprove={autoApprove && !ALWAYS_ASK.has(tool)}
        onAnswer={(answer: ApprovalAnswer) => resolve(answer, interrupt?.id)} // [!code highlight]
      />
    );
  },
});
```

卡片发送 `{ approved: true }` 或 `{ approved: false, message }`，这正是适配器读取的形状。被拒绝的调用会被阻止，你的消息会回到模型那里，让它知道你为什么拒绝。

### 用 A2UI 绘制测试结果

测试结果卡片是一个 [A2UI](/generative-ui/a2ui) 界面：agent 以组件与数据描述卡片，CopilotKit 用应用自己的组件绘制它。`run_tests` 运行测试套件，把输出变成 `TestReport`，并在模型可读的结果旁返回 `a2ui_operations`：

```python title="agent/src/repo_doctor/tools.py"
async def run_tests(target: str = "") -> dict[str, Any]:
    """Runs the test suite and shows a live report card to the user."""
    # ...
    return {
        # Painted by CopilotKit's A2UI middleware; the model can ignore it.
        "a2ui_operations": report_surface_operations(report, run=number),  # [!code highlight]
        "status": report.status,
        "summary": report.headline(),
        # ...
    }
```

`a2ui.py` 构建三个操作：创建 surface、设置它唯一的 `TestReport` 组件、填充它的数据：

```python title="agent/src/repo_doctor/a2ui.py"
# Must match CATALOG_ID in src/a2ui/catalog.tsx (the Next.js app).
CATALOG_ID = "https://repo-doctor.dev/a2ui/catalog/v1"  # [!code highlight]

# ...

COMPONENTS: list[dict[str, Any]] = [
    {
        "id": "root",
        "component": "TestReport",
        **{name: {"path": f"/{name}"} for name in _BINDINGS},
    }
]

# ...

def report_surface_operations(report: TestReport, *, run: int) -> list[dict[str, Any]]:
    sid = surface_id(run)
    return [
        {"version": "v0.9", "createSurface": {"surfaceId": sid, "catalogId": CATALOG_ID}},
        {"version": "v0.9", "updateComponents": {"surfaceId": sid, "components": COMPONENTS}},
        {
            "version": "v0.9",
            "updateDataModel": {
                "surfaceId": sid,
                "path": "/",
                "value": report_data(report, run=run),  # [!code highlight]
            },
        },
    ]
```

组件树从不变化。每个 prop 都是指向数据模型的 `{ path }` 绑定，每次运行只填充数据。每次运行还有自己的 surface id（`test-run-1`、`test-run-2` 等），因此新一轮运行会新增一张卡片，而不是替换上一张。

在 Web 侧，definitions 是 agent 与卡片之间的契约：agent 可以点名的组件，以及每个组件 props 的 zod schema。每个 prop 可以是一个值，也可以是一个 `{ path }` 绑定：

```ts title="src/a2ui/definitions.ts"
const binding = z.object({ path: z.string() });
const dyn = <T extends z.ZodTypeAny>(schema: T) => z.union([schema, binding]); // [!code highlight]

// ...

export const definitions = {
  TestReport: {
    description:
      "The result of one test run: status, counts, per-file results and failures.",
    props: z.object({
      run: dyn(z.number()),
      status: dyn(z.enum(["passed", "failed", "error"])),
      headline: dyn(z.string()),
      // ...
      files: dyn(z.array(FileResult)),
      failures: dyn(z.array(FailedTest)),
      // ...
    }),
  },
} satisfies CatalogDefinitions;
```

`createCatalog` 把 definitions 与一个渲染器组合起来，渲染器把 props 映射到应用自己的 `TestReport` React 组件上，并使用与 agent 相同的 catalog id。这就是第一步中 provider 注册的 `catalog`：

```tsx title="src/a2ui/catalog.tsx"
"use client";

import { createCatalog } from "@copilotkit/a2ui-renderer";
import type { CatalogRenderers } from "@copilotkit/a2ui-renderer";
import { definitions } from "./definitions";
// ...
import { TestReport, list, num, str } from "./test-report";

/** Must match CATALOG_ID in agent/src/repo_doctor/a2ui.py. */
export const CATALOG_ID = "https://repo-doctor.dev/a2ui/catalog/v1"; // [!code highlight]

const renderers: CatalogRenderers<Definitions> = {
  TestReport: ({ props }) => {
    const status = str(props.status);
    return (
      <TestReport
        run={num(props.run)}
        status={status === "passed" || status === "error" ? status : "failed"}
        headline={str(props.headline)}
        // ...
        files={list<FileResultData>(props.files)}
        failures={list<FailedTestData>(props.failures)}
        summary={str(props.summary)}
      />
    );
  },
};

export const catalog = createCatalog(definitions, renderers, { // [!code highlight]
  catalogId: CATALOG_ID,
  includeBasicCatalog: false,
});
```

`includeBasicCatalog: false` 不包含 A2UI 的基础组件，因此 `TestReport` 是这个 catalog 唯一能绘制的组件。每次测试运行都有自己的 surface，所以每一轮都留在聊天里，从第一轮红色到最后一轮绿色：

### 构建侧边面板

每个工具都把自己那部分记录写进了共享状态。它在 Web 侧的形状如下：

```ts title="src/lib/agent-state.ts"
const AgentState = z.object({
  repo: Repo.optional().catch(undefined),
  install: Install.optional().catch(undefined),
  testRuns: z.array(TestRun).catch([]),
  // ...
  checks: z.array(Check).catch([]),
  approvals: z.array(Approval).catch([]),
  push: Push.optional().catch(undefined),
});
```

每个字段各有一个来源：

- `repo` 来自 `clone_repo`，`install` 来自 `install_dependencies`
- `testRuns` 从每次 `run_tests` 获得一行，`checks` 从每次 `run_check` 获得一条
- `approvals` 收下你的每个决定
- `push` 来自 `git_push`

[`useAgent`](/reference/hooks/useAgent) 把该状态交给浏览器。一个 provider 读取一次，并与卡片和面板共享：

```tsx title="src/lib/use-workspace.tsx"
export function WorkspaceProvider({ children }: { children: ReactNode }) {
  const { agent } = useAgent({ agentId: AGENT_ID }); // [!code highlight]
  const state = useMemo(() => parseAgentState(agent.state), [agent.state]); // [!code highlight]
  // ...
}
```

状态经由网络传输，所以 `parseAgentState` 先用 zod 校验它。[`workspace-panel.tsx`](https://github.com/CopilotKit/CopilotKit/tree/main/examples/showcases/antigravity-repo-doctor/src/components/shell/workspace-panel.tsx) 中的面板随后读取 `state.checks`、`state.approvals` 这类普通字段。

由于审批存放在共享状态里，重新打开一条会话时它们会回来。底部的 **Download report** 用同样的状态与消息在浏览器里生成一份 Markdown 报告。

## 完整示例还包含什么

上面的步骤覆盖了应用的核心。示例还有这些内容，各自位于独立文件中：

- **每条会话一个文件夹**。`ThreadScopedAntigravityAgent` 给每条会话自己的工作区与工具，并在删除会话时清理干净（[`agent.py`](https://github.com/CopilotKit/CopilotKit/tree/main/examples/showcases/antigravity-repo-doctor/agent/src/repo_doctor/agent.py)）。
- **保存的会话**。每次克隆、推送和运行之后，仓库、已推送的分支和 harness 的会话都会保存到 Cloud Storage，并在重启后恢复（[`snapshot.py`](https://github.com/CopilotKit/CopilotKit/tree/main/examples/showcases/antigravity-repo-doctor/agent/src/repo_doctor/snapshot.py)）。
- **安装防护**。通过 `run_command` 进行的包安装会在执行前被拒绝，因此所有安装都走 `install_dependencies`，PyTorch 始终安装为 CPU wheel（[`guards.py`](https://github.com/CopilotKit/CopilotKit/tree/main/examples/showcases/antigravity-repo-doctor/agent/src/repo_doctor/guards.py)）。
- **磁盘限额**。会话关闭时删除该会话的 Python venv（[`venvs.py`](https://github.com/CopilotKit/CopilotKit/tree/main/examples/showcases/antigravity-repo-doctor/agent/src/repo_doctor/venvs.py)）。agent 自己的 uv 缓存在启动时修剪，超过上限时清空（[`uvcache.py`](https://github.com/CopilotKit/CopilotKit/tree/main/examples/showcases/antigravity-repo-doctor/agent/src/repo_doctor/uvcache.py)）。
- **不止 Python**。安装与测试命令会依据仓库自身的文件推导，支持 Python、Node、Go 和 Rust 项目。工具链未安装的项目会被报告为不支持，而不是中途失败；Cloud Run 镜像包含 Python 与 Node（npm、pnpm 和 Yarn）（[`project.py`](https://github.com/CopilotKit/CopilotKit/tree/main/examples/showcases/antigravity-repo-doctor/agent/src/repo_doctor/project.py)）。
- **仅限本地的推送与干净的环境**。shell 命令与被克隆代码继承的环境里移除了 API 密钥与 GitHub token，任何指向 GitHub URL 的推送都会被送往一个不存在的主机（[`safety.py`](https://github.com/CopilotKit/CopilotKit/tree/main/examples/showcases/antigravity-repo-doctor/agent/src/repo_doctor/safety.py)）。
- **可下载的报告**。一份会话的 Markdown 总结，在浏览器中由消息与共享状态构建，不调用模型（[`report.ts`](https://github.com/CopilotKit/CopilotKit/tree/main/examples/showcases/antigravity-repo-doctor/src/lib/report.ts)）。

[CopilotKit Intelligence](/intelligence/quickstart) 把每条会话保存在其发起人名下，并把运行转化为 Product Analytics。

你可以让编码智能体使用 [CopilotKit CLI](/cli) 把一个 CopilotKit Intelligence 项目连接到本应用。它会运行 `npx copilotkit@latest login` 和 `npx copilotkit@latest project select --create repo-doctor --env-name .env`，把 `CPK_INTELLIGENCE_API_KEY` 写入 `.env`。重启 `pnpm dev` 后，左侧会出现会话列表。

```ts title="src/app/api/copilotkit/[[...slug]]/route.ts"
const runtime = new CopilotRuntime({

          apiKey: env.CPK_INTELLIGENCE_API_KEY,
          ...(env.INTELLIGENCE_API_URL
            ? { apiUrl: env.INTELLIGENCE_API_URL }
            : {}),
          ...(env.INTELLIGENCE_GATEWAY_WS_URL
            ? { wsUrl: env.INTELLIGENCE_GATEWAY_WS_URL }
            : {}),
        }),
        // Off: the runtime would name each new thread by running this agent a
        // second time (a new thread id, so a second Antigravity session,
        // workspace and Gemini turn). The thread list names threads from their
        // first message instead (src/components/shell/thread-list.tsx).
        generateThreadNames: false,
        // The person who typed their name in the navbar (a cookie), so threads
        // and Product Analytics are per person. Not authentication: replace it
        // with your own server-verified session before going public.
        identifyUser: (request: Request) => // [!code highlight]
          userFromCookieHeader(request.headers.get("cookie")) ?? {
            id: env.DEMO_USER_ID,
            name: "Demo user",

      }
    : { runner: new InMemoryAgentRunner() }),

```

## 部署到 Google Cloud

整个应用作为一个 Cloud Run 服务运行：UI、CopilotKit 运行时和 agent 由同一个镜像构建。密钥存放在 Secret Manager，每条会话保存到一个 Cloud Storage bucket。`gcloud auth login` 之后，在 `examples/showcases/antigravity-repo-doctor` 目录用 [gcloud CLI](https://cloud.google.com/sdk/docs/install) 运行以下命令。

构建镜像：

```bash
PROJECT=your-project
REGION=us-central1
IMAGE=$REGION-docker.pkg.dev/$PROJECT/repo-doctor/app
gcloud config set project $PROJECT

gcloud services enable run.googleapis.com artifactregistry.googleapis.com \
  cloudbuild.googleapis.com secretmanager.googleapis.com
gcloud artifacts repositories create repo-doctor --repository-format=docker --location=$REGION
gcloud builds submit --tag $IMAGE
```

把密钥放进 Secret Manager。下面的命令从你的 `.env` 读取它们，但不会打印：

```bash
secret() { grep "^$1=" .env | cut -d= -f2- | tr -d '\n"' | gcloud secrets create "$2" --data-file=-; }
secret GEMINI_API_KEY gemini-api-key
secret CPK_INTELLIGENCE_API_KEY cpk-intelligence-api-key
secret GITHUB_TOKEN github-token
```

创建一个只能读取那些密钥与 bucket 的服务账号，以及 bucket 本身：

```bash
gcloud iam service-accounts create repo-doctor --display-name="Repo Doctor"
SA=repo-doctor@$PROJECT.iam.gserviceaccount.com
# A new service account takes a few seconds to appear, so each binding retries.
for s in gemini-api-key cpk-intelligence-api-key github-token; do
  for try in 1 2 3 4 5 6; do
    gcloud secrets add-iam-policy-binding $s --member=serviceAccount:$SA \
      --role=roles/secretmanager.secretAccessor && break
    sleep 10
  done
done

BUCKET=$PROJECT-repo-doctor-ws
gcloud storage buckets create gs://$BUCKET --location=$REGION --uniform-bucket-level-access
gcloud storage buckets add-iam-policy-binding gs://$BUCKET \
  --member=serviceAccount:$SA --role=roles/storage.objectUser
```

把它部署为私有服务：

```bash
gcloud run deploy repo-doctor \
  --image $IMAGE --region $REGION --service-account $SA \
  --min-instances 1 --max-instances 1 \
  --cpu 4 --memory 16Gi --no-cpu-throttling \
  --timeout 3600 --execution-environment gen2 \
  --set-secrets GEMINI_API_KEY=gemini-api-key:latest,CPK_INTELLIGENCE_API_KEY=cpk-intelligence-api-key:latest,GITHUB_TOKEN=github-token:latest \
  --set-env-vars GEMINI_MODEL=gemini-3.5-flash,DEMO_USER_ID=repo-doctor-demo,WORKSPACE_BUCKET=gs://$BUCKET \
  --no-allow-unauthenticated

APP_URL=$(gcloud run services describe repo-doctor --region $REGION --format='value(status.url)')
gcloud run services update repo-doctor --region $REGION --update-env-vars APP_URL=$APP_URL
```

然后在你自己的机器上通过认证代理打开它，地址是 [http://localhost:8080](http://localhost:8080)：

```bash
gcloud run services proxy repo-doctor --region $REGION --port 8080
```

该服务恰好运行一个永不缩容到零的实例，因为一条会话的存活状态和它等待的审批卡片都保存在内存里。`--no-cpu-throttling` 让 agent 在等你时保持工作。

每次运行之后，agent 会把会话保存到 bucket 中它自己的文件夹：带编辑的仓库、已推送的修复分支和 agent 的会话。如果服务重启，该会话中的下一条消息会把它们带回来，agent 从上次中断处继续。已安装的包不会被保存；agent 会重新安装。

<Callout type="warning" title="公开之前先保护服务">
  被克隆仓库的代码会在容器内带网络访问运行，每条消息都消耗你的 Gemini 额度。请保持服务私有，并通过 `gcloud run services proxy` 打开，或放到 [IAP](https://cloud.google.com/run/docs/securing/identity-aware-proxy-cloud-run) 之后。生产部署需要真实的身份验证和每条会话独立的沙箱。把出站流量限制到 GitHub、Gemini 和包仓库在这里没有配置；
  [架构说明](https://github.com/CopilotKit/CopilotKit/blob/main/examples/showcases/antigravity-repo-doctor/docs/architecture.md#locking-down-network-access)描述了怎么做。
</Callout>
