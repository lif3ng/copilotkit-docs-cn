本篇示例用三块拼出一个生产级智能体化应用：用 [`@copilotkit/angular`](/angular) 构建的 **Angular** 前端、通过开放 [AG-UI](https://docs.ag-ui.com/) 协议对外服务的 **Google ADK** 智能体，以及一个可选的 [CopilotKit Intelligence](/intelligence/overview) 层，用于持久化线程与跨会话记忆。

先完成这两个快速开始：

- [Angular 前端](/angular)：让你得到一个可运行的 Angular 应用，带有由本地 Copilot Runtime 支撑的聊天 UI。
- [ADK 快速开始](/integrations/adk/quickstart)：通过 AG-UI 对外提供一个 ADK 智能体。

本篇示例覆盖两个快速开始接通之后出现的生产问题：共享聊天状态、请求身份、模型选择、服务端策略、线程与记忆。

## 各部分如何配合

该应用有三个进程：

1. **Angular 客户端**渲染聊天与生成式 UI，并运行 agent。
2. **运行时 / 后端即前端**（BFF）接好 Copilot Runtime、解析每请求用户、执行工具策略、代理记忆，并把每次运行转发给你的 agent。这一层负责身份、策略与记忆访问。
3. **Google ADK 智能体**负责推理并发出生成式 UI。一个可选的确定性专项 agent 处理固定负载。

<Callout type="info" title="在 BFF 中校验身份与策略">
  把来自浏览器的数据当作不可信。在服务端解析已认证用户、执行工具策略，并为记忆请求划定范围。
</Callout>

## 在聊天界面间共享智能体状态

调用 `injectAgentStore("default")` 会解析到同一个底层 agent。使用相同 agent id 的组件会观察到相同的消息与运行状态。

```ts title="chat.component.ts"
import { Component } from "@angular/core";
import { CopilotChat, injectAgentStore } from "@copilotkit/angular";

@Component({
  selector: "app-chat",
  imports: [CopilotChat],
  template: `<copilot-chat agentId="default" />`,
  // Give the surface a bounded height to keep the composer visible on long threads.
  styles: [`:host { display: block; height: 100%; min-height: 0; }`],
})
export class ChatComponent {
  readonly agentStore = injectAgentStore("default");
}
```

<Callout type="info" title="自定义提交逻辑只设一个属主">
  第二个输入框可以注入同一个 agent id，并观察到同一个 agent。为了让校验、附件和消息提交保持一致，请把同一个提交函数或服务传给每个自定义输入框。
</Callout>

<Callout type="warn" title="不要为全新线程拉取历史">
  **症状**：开始新对话时，第一条消息尚未发出就抛错。
  **原因**：全新的 thread id 没有任何消息，历史请求因此报错。
  **修复**：只为已存在、由用户选中的线程拉取历史。新对话用全新 id 运行，只在绑定的 thread id 变化时才重新加载已存储的消息。
</Callout>

<Callout type="warn" title="在两次运行之间修改运行时配置">
  运行时 URL 和请求头会参与 agent 解析。请在运行开始之前应用配置变更。每次请求都会变化且非机密的值请放进 run body。
</Callout>

## 每次运行都发送变化的上下文

<Callout type="warn" title="不要把浏览器上下文当授权">
  浏览器发来的 user id 不可信。请在服务端解析已认证用户。运行上下文只用于向 agent 提供当前、非机密的应用状态；任何身份值在用于划定数据范围之前，都必须对照服务端会话进行校验。
</Callout>

使用 [`connectAgentContext`](/reference/angular/functions/connectAgentContext) 在每次运行时发送当前、非机密的应用状态：

```ts title="chat.component.ts"
import { Component, signal } from "@angular/core";
import { connectAgentContext } from "@copilotkit/angular";

@Component({ /* ... */ })
export class ChatComponent {
  readonly userId = signal(currentUserId);

  constructor() {
    // Re-registers reactively when the signal changes (e.g. an in-session user switch).
    connectAgentContext(() => ({ description: "userId", value: this.userId() }));
  }
}
```

不要把这个浏览器值当作身份证明。BFF 必须将其与已认证会话比对，或用服务端身份替换它。如果某个 ADK 工具需要经过校验的 user id，请在 BFF 或 agent 适配器中把该值映射进 ADK 会话状态。工具随后就能读取应用定义的状态键：

```python title="agent/main.py"
def _user_id(tool_context) -> str | None:
    return tool_context.state.get("user_id")

def recall_for_user(tool_context) -> dict:
    user_id = _user_id(tool_context)
    # ...scope every read and write to user_id
    return {"ok": True}
```

具体映射属于你的服务端桥接层。保持显式，并用你实际部署的 ADK 适配器版本来测试它。

## 选择一个够用的模型

ADK 默认使用 Google 的 Gemini，也支持其他模型。配置请见 [ADK 快速开始](/integrations/adk/quickstart)。

- 优先选择指令遵循与工具使用可靠的新式模型。
- 用完整的工具与策略流程测试较旧或较小的模型。它们可能漏掉多段指令中的步骤。
- 任务需要时使用推理模型，并把其额外的延迟与成本算进去。

<Callout type="tip" title="向你的提供方确认模型可用性">
  接入之前，先确认该 model id 在你的账户下确实存在。以 Gemini 为例：
  ```bash
  curl "https://generativelanguage.googleapis.com/v1beta/models?key=$GOOGLE_API_KEY" | grep '"name"'
  ```
</Callout>

再补两个 agent 侧的习惯：

- **MCP 与工具超时保持短促**。过长的超时会让缓慢的外部工具服务器拖住第一条回复。较短的超时能更早报告失败。
- **用代码发出固定的生成式 UI 负载**。即使要求模型原样返回 JSON，它也可能改动。

## 在服务端执行治理

<Callout type="warn" title="客户端的工具防护只影响展示">
  **症状**：你在 UI 里“隐藏”的工具仍会被 agent 调用。
  **原因**：浏览器不可信，在 UI 中隐藏工具对 agent 的工具列表毫无影响。
  **修复**：在 BFF 上从入站 run body 中剔除不允许的工具，让模型无法调用它们，并过滤出站的生成式 UI 流。输出一条统一的治理回执，而不是静默丢弃输出。
</Callout>

- **把每请求的允许清单放进 run body**。能力变更即会在下一次运行生效。
- **在入站与出站检查中都归一化能力名大小写**（例如 `pieChart` 与 `PieChart`）。大小写不一致可能绕过策略检查。
- **让生成式 UI 卡片重排，而不是截断**。过长的动态标签会溢出固定尺寸的卡片。让布局随之增长，而不是裁剪内容。

## 添加持久化线程与记忆（可选）

[CopilotKit Intelligence](/intelligence/overview) 增加持久化的[线程](/AG-UI-Streams)与持久的跨会话记忆。要妥善处理平台缺失或不可达的情况，而不是让每个请求都失败：

- **自动探测**：启动时用短超时探测平台健康端点。如果不可达或无许可，就回退到内存型 runner。
- **端点可配置**：运行时、agent 的记忆客户端与健康探测共用一个 base URL 环境变量。重启之后再次检查该端点。

记忆工具调用平台的流式 JSON-RPC `/mcp` 端点，按用户划定范围：

```http
POST {INTELLIGENCE_API_URL}/mcp
Authorization: Bearer <key>
X-Cpki-User-Id: <user_id>
Accept: application/json, text/event-stream

{"jsonrpc":"2.0","id":1,"method":"tools/call",
 "params":{"name":"recall_memory","arguments":{}}}
```

响应是 server-sent 事件流。从第一个 `data:` 行读取 JSON-RPC 主体并拼接文本内容。写入可能包含嵌入（embedding）步骤、耗时数秒，因此请异步执行并设置合适的超时。

<Callout type="warn" title="逐一查询每个受支持的记忆范围">
  **症状**：agent 明明记得某些内容，自定义记忆面板却从不显示。
  **原因**：召回通常默认 *user* 范围并限制在很小的 top-N，硬编码 user 范围的面板会隐藏项目或团队范围的记忆。
  **修复**：如果你要构建记忆浏览器，请同时查询 user 与 project 范围，去重后合并。
</Callout>

<Callout type="info" title="自托管平台">
  自行运行 CopilotKit Intelligence 有单独的配置注意事项（许可验证与嵌入服务）。参见[自托管](/intelligence/self-hosting)。
</Callout>

## 生产清单

1. 聊天界面全程使用一个 agent id。自定义输入框之间共享同一个提交函数或服务。
2. 在服务端解析身份。每次运行都发送变化的、非机密的应用上下文。
3. 在两次运行之间应用运行时 URL 与请求头变更。
4. 在服务端执行工具策略。从入站运行中剔除不允许的工具，并过滤出站的生成式 UI。
5. 用完整的工具与策略流程测试当前主流的智能体模型，并确认你的提供方提供该模型。

## 深入一步

- **本地开发**：只有前端开发服务器会热重载。`tsx`/`node` BFF 与 Python agent 都不会，所以编辑后要重启它们。给每个服务分配一个稳定、互不冲突的端口并记录下来。
- **自定义聊天 UI**：在你的应用中构建欢迎与空状态，通过 `messageViewComponent` 自定义消息渲染，需要在中间穿插生成式 UI 时迭代完整消息列表。参见 [Angular 指南](/angular)。
- **线程详解**：参见[线程详解](/intelligence/threads-explained)。

## 用编码智能体上手

当 Angular 与 ADK 快速开始跑起来之后，把下面这段粘贴给你的编码智能体（Cursor、Claude Code 等）：

```text
Update my Angular + Google ADK + CopilotKit app for multi-user production:

1. Use one agent id across the chat surface. Calls to `injectAgentStore("default")` resolve the
   same agent. Route custom composers through one shared submit function or service.
2. Resolve the authenticated user on the BFF. If ADK tools need that id, map the server-validated
   value into an application-defined ADK session-state key. Do not trust browser context alone.
3. Apply runtime config changes (runtimeUrl/headers) between runs. Carry changing, non-secret
   application context in the run body.
4. Enforce tool policy on the server: strip disallowed tools from the inbound run body and filter the
   outbound generative-UI stream. Include the allow-list in the run body, and normalize tool-name casing.
5. Give the chat surface a bounded height, and only fetch thread history for an existing thread id.

Keep my existing Angular and ADK setup otherwise unchanged.
```
