CopilotKit 是一个三层栈——**前端、运行时、智能体**——由开放的 **[AG-UI](/agentic-protocols/ag-ui)** 事件协议连接。运行时位于你自己的应用服务器中，因此在你的 UI 与 agent 之间只隔着一种可审查的线上格式。

## 30 秒版

- **前端**。框架原生的 SDK 与预构建聊天组件，把你的 UI 连接到运行中的 agent。
- **运行时**。挂载在你应用服务器中的请求处理器（Next.js、Express、Hono、Bun、Deno、Workers）。负责中介身份验证、工具调用和 AG-UI 流。
- **智能体**。任何兼容 AG-UI 的后端——内置智能体、LangGraph、Mastra、CrewAI、Pydantic AI、MAF，或你自己的实现。
- **AG-UI** 是线上格式：16 种事件类型，传输无关、框架无关。可以替换任意一层而无需重写其他层。

### 1. 前端

用户直接交互的应用。CopilotKit 提供框架原生的状态与工具 API，以及 `CopilotChat`、`CopilotSidebar`、`CopilotPopup` 等预构建组件。可以使用预构建的聊天界面、用无头（headless）API 构建完全自定义的 UI，或两者混用。

### 2. 运行时

挂载在你应用服务器内的请求处理器（Next.js App Router、Express、Hono、Bun、Deno、Cloudflare Workers）。运行时接收来自前端的请求，中介身份验证与工具调用，并通过 AG-UI 把工作转发给你的 agent。走框架无关路径时，你可以在进程内实例化一个 `BuiltInAgent`，完全跳过外部 agent 进程。

### 3. 智能体

你选择的 agent 后端：LangGraph、Mastra、CrewAI、Pydantic AI、Microsoft Agent Framework、内置智能体（Built-in Agent），或任何自定义的兼容 AG-UI 实现。agent 运行你的提示、调用工具、发出状态，并把事件流式传回运行时。

## AG-UI：协议桥梁

CopilotKit 不会把你锁死在某个 agent 框架上。运行时通过 **[AG-UI](/agentic-protocols/ag-ui)** 与你的 agent 通信——这是一个开放的、事件驱动的协议，用于标准化 agent 与应用之间的通信方式：

- **事件驱动**——16 种标准化事件类型（文本增量、工具调用、状态快照与增量、运行生命周期）从 agent 经运行时流向前端。
- **双向**——用户发送输入，agent 作出响应，agent 暂停以等待人机协同（human-in-the-loop）输入，前端暴露 agent 可调用的前端工具。
- **传输无关**——SSE、WebSockets、webhook，任凭你的技术栈选择。
- **框架无关**——每个受支持的集成都附带一个轻量 AG-UI 适配器。改一行运行时配置即可切换后端。

> *“智能体的未来不属于某一家公司或某一个平台——而是一个由协议连接起来的智能体化生态。”*

由于这份契约是一个协议——而非 SDK 锁定——你可以在不重写前端的情况下更换 agent 层、并行运行多个 agent 后端，并与任何兼容 AG-UI 的东西集成：MCP 服务器、A2UI 组件、Oracle / Google / AWS 的 agent 平台。

## 请求流程一览

1. 用户在你的前端应用中发送一条消息。
2. 前端 agent API 向你的运行时端点发起请求。
3. 运行时与所配置的 agent 建立 AG-UI 会话。
4. agent 以 AG-UI 事件的形式发出文本、工具调用和状态更新。
5. 运行时将这些事件流式传回；前端实时渲染它们。
6. 如果 agent 调用了某个前端工具，运行时会转发该请求，你的浏览器端 handler 随之运行，结果再流回 agent。
7. 线程（Threads）、持久化与实时同步（在配置后）由 [CopilotKit Intelligence](/intelligence/overview) 中介——它是位于运行时旁边的平台后端。
