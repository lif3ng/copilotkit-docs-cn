# 调试模式

当智能体的表现不符合预期时——事件缺失、状态不更新或工具调用没有执行——你需要看清事件管线内部发生了什么。运行时调试模式提供结构化的服务端日志；前端则可以用浏览器网络工具或 AG-UI Event Inspector 检查产出的事件流。

启用后可以看到：
- 智能体发出了哪些事件，以及它们是否到达了客户端
- 事件在管线的哪个环节被丢弃或未通过校验
- 一个请求从开始到结束的完整生命周期

<Callout type="info">
  本地开发时的可视化错误展示（错误横幅、开发者控制台）请参见[错误调试](/troubleshooting/error-debugging)。调试模式聚焦于事件管线日志，而非 UI 层面的错误展示。
</Callout>

## 启用调试模式

### 服务端（运行时）

向 `CopilotRuntime` 构造函数传入 `debug: true`：

```ts title="app/api/copilotkit/route.ts"
const runtime = new CopilotRuntime({
  agents: {
    // your agents
  },
  debug: true, // [!code highlight]
});
```

这会生成结构化的 Pino 日志（由 `pino-pretty` 格式化），并带有 `copilotkit-debug` 组件标签：

```
[14:32:01.123] DEBUG (copilotkit-debug): Agent run started
    agentName: "default"
    threadId: "abc-123"
[14:32:01.130] DEBUG (copilotkit-debug): SSE stream opened
[14:32:01.145] DEBUG (copilotkit-debug): Event emitted
    type: "TEXT_MESSAGE_START"
    messageId: "msg-1"
    role: "assistant"
[14:32:01.200] DEBUG (copilotkit-debug): Event emitted
    type: "TEXT_MESSAGE_CONTENT"
    deltaLength: 42
[14:32:01.250] DEBUG (copilotkit-debug): Event emitted
    type: "TEXT_MESSAGE_END"
[14:32:01.260] DEBUG (copilotkit-debug): Event emitted
    type: "RUN_FINISHED"
[14:32:01.261] DEBUG (copilotkit-debug): SSE stream completed
    eventCount: 4
    loggedEventCount: 4
```

<FrontendOnly frontend="react">
### 客户端

向 `<CopilotKit>` 提供方传入 `debug={true}`：

```tsx
<CopilotKit
  runtimeUrl="/api/copilotkit"
  debug={true} // [!code highlight]
>
  <YourApp />
</CopilotKit>
```

这会把调试配置转发给 AG-UI 客户端传输层（`transformChunks`），视 AG-UI 库版本不同，可能产生传输层级别的调试输出。请注意，最丰富的调试日志来自**服务端**的 `CopilotRuntime`——请在该处启用 `debug: true`，以获得每个 AG-UI 事件的完整结构化 Pino 日志。

<Callout type="info">
  服务端与客户端的调试开关相互独立。在客户端启用调试不会影响服务端，反之亦然。
</Callout>
</FrontendOnly>

<FrontendOnly frontend="angular">
### 客户端排查

`@copilotkit/angular` 没有暴露单独的客户端调试开关。可以在 `CopilotRuntime` 上启用调试、用浏览器开发者工具检查 SSE 请求，或将 [AG-UI Event Inspector](/troubleshooting/event-inspector) 连接到开发环境运行时。
</FrontendOnly>

## 细粒度配置

在 `CopilotRuntime` 上，可以传入一个对象而不是 `true`，对记录内容进行细粒度控制：

```ts
debug: {
  events: true,     // Log every event emitted/received
  lifecycle: true,  // Log request/run lifecycle (start, finish, error)
  verbose: false,   // Log full payloads instead of summaries
}
```

### 默认值

| 输入 | `events` | `lifecycle` | `verbose` |
|-------|----------|-------------|-----------|
| `debug: true` | `true` | `true` | `false` |
| `debug: {}` | `true` | `true` | `false` |
| `debug: { events: false }` | `false` | `true` | `false` |

当 `debug` 是布尔值（`true`）时，事件与生命周期日志会启用，但详细（verbose）模式默认**关闭**（避免在日志中泄露 PII）。要获得完整的事件载荷，请显式使用 `debug: { verbose: true }` 开启。

### 示例

只记录生命周期事件（不记录逐事件日志）：

```ts
debug: { events: false, lifecycle: true }
```

记录带完整载荷的事件，但跳过生命周期日志：

```ts
debug: { events: true, lifecycle: false, verbose: true }
```

## 用调试模式排查问题

### 事件未到达客户端

在服务端启用调试以获得最详细的可视信息：
1. 在服务器日志中查找 `Event emitted`——预期的事件是否正在发送？
2. 确认 `SSE stream completed` 显示的 `eventCount` 符合预期。
3. 用浏览器的 Network 面板确认 SSE 事件确实在网络上到达。

### 工具调用未执行

启用服务端调试，然后检查：
1. 服务端是否发出了 `TOOL_CALL_START` 事件
2. `TOOL_CALL_ARGS` 和 `TOOL_CALL_END` 事件是否正确跟随
3. 通过浏览器 Network 面板确认这些事件出现在 SSE 流中

### 状态未更新

在服务器日志中查找 `STATE_SNAPSHOT` 或 `STATE_DELTA` 事件。如果它们出现在服务端却没出现在浏览器的 SSE 流中，则可能存在连接问题。

## 会记录哪些内容

### 服务端日志

| 类别 | 日志消息 | 说明 |
|----------|-------------|-------------|
| 生命周期 | `Agent run started` | 一个智能体运行已启动，包含智能体名称与线程 ID |
| 生命周期 | `SSE stream opened` | SSE 响应流已创建 |
| 生命周期 | `SSE stream completed` | 流已结束，包含事件总数 |
| 生命周期 | `SSE stream errored` | 流遇到错误 |
| 事件 | `Event emitted` | 每个 AG-UI 事件写入流时都会记录 |

在**摘要模式**（verbose 关闭）下，事件日志包含 `messageId`、`toolCallId`、`toolCallName`、`role` 等关键标识以及内容长度，而不是完整载荷。

<FrontendOnly frontend="react">
### 客户端

在客户端，`debug` 配置会透传给 AG-UI 传输层。产生什么调试输出（如果有的话）由 AG-UI 客户端库决定。CopilotKit 本身不会发出 `console.debug` 调用——调试标志配置的是底层 AG-UI 事件管线。
</FrontendOnly>

<FrontendOnly frontend="angular">
### 客户端

客户端侧的可视化请使用浏览器的 Network 面板或 AG-UI Event Inspector。Angular 包不会增加第二条控制台调试输出流。
</FrontendOnly>

<Callout type="warn">
  调试模式可能产生大量日志输出，在详细（verbose）模式下尤其如此。请在开发和调试时使用，不要在生产环境中使用。
</Callout>
