你有一个调用了 `useCopilotAction`、`useRenderTool`、`useCoAgentStateRender` 或其他任何具备渲染能力的 CopilotKit 钩子的文件，想在不跑完整聊天循环的情况下迭代 `render` prop——调整布局、测试不同状态、喂入不同参数。钩子浏览器是 [VS Code 扩展](/vs-code-extension)内的一个侧边栏加内联 CodeLens 界面，做的正是这件事。

阅读完本页后，你将拥有：

- 一个侧边栏，列出工作区中的每一个 CopilotKit 钩子调用。
- 任意渲染钩子的实时预览面板，表单控件由钩子声明的参数自动生成。
- 编辑器中每个钩子调用上方一个一键 `▶️ Preview Component` CodeLens。

## 前置条件

- 已安装 [CopilotKit VS Code 扩展](/vs-code-extension)。
- 工作区中某处导入了 `@copilotkit/react-core` 或 `@copilotkit/react-core/v2`。

<Callout type="info">
  钩子浏览器完全针对你的源文件运行——无需运行时、无需 API 密钥、无需运行智能体。
</Callout>

## 浏览与预览

<Steps>

<Step>
### 打开钩子浏览器

点击活动栏（Activity Bar）中的 CopilotKit 图标，展开 **CopilotKit Hooks** 侧边栏（三个视图中的第一个）。你会看到工作区中的每一个 CopilotKit 钩子调用，按钩子名称分组。每行显示 action/工具名称（或 `line:N`，适用于 `useLangGraphInterrupt` 这类无名钩子），以及文件路径和行号。
</Step>

<Step>
### 预览渲染钩子

点击渲染钩子（`useCopilotAction`、`useRenderTool` 等）下的任意行，在编辑器窗格中打开预览面板。第一次为某个文件打开面板时，扩展会通过 Rolldown 打包该文件，并对 `@copilotkit/react-core` 使用仅用于捕获的桩（stub）——你的组件挂载进 webview，钩子配置被捕获，`render` prop 由左侧（窄宽度时在顶部）的控件驱动：

- **状态**——`inProgress` / `executing` / `complete`。
- **Args / 参数**——表单由钩子的 `parameters` 数组（V1）或 Zod / Standard Schema（V2）构建。缺失字段、枚举选项、嵌套对象和数组均支持。
- **结果**——状态为 `complete` 后即可编辑。
- **钩子专属附加项**——`useCoAgentStateRender` 的 `nodeName`、`useRenderTool` 的 `toolCallId`，以及用于中断的事件值编辑器。

渲染输出位于右侧（或下方）一个带标签的边框内，让人一目了然：“这就是你的 `render` 返回的组件”。你使用的 Tailwind 类和文件中的任何 `.css` 导入都会被打包进去，并在每次加载时注入。
</Step>

<Step>
### 跳转到源码

每个侧边栏行在悬停时都有一个 `</>` 按钮，点击可在钩子调用的确切行打开文件。对于数据钩子（不可预览），点击行本身即可打开源码——即使没有预览，它们仍可作为导航索引使用。
</Step>

<Step>
### 使用内联 CodeLens

打开任何调用了渲染钩子的 `.ts` 或 `.tsx` 文件。你会看到每个钩子调用正上方有一个 `▶️ Preview Component` CodeLens——点击它会打开同一个预览面板。当你已经在源文件中、不想经由侧边栏来回切换时，这一功能非常方便。
</Step>

<Step>
### 编辑并重新渲染

保存文件。扩展会重新扫描该文件、重新打包预览并重新捕获。只要字段名和类型仍与新 schema 匹配，你的表单值就会被保留。
</Step>

</Steps>

## 钩子覆盖范围

每个具备渲染能力的 CopilotKit 钩子都可被发现和预览：

| 钩子 | 来源 | 预览形态 |
|---|---|---|
| `useCopilotAction` | `@copilotkit/react-core` | action (`args`, `status`, `result`) |
| `useCopilotAuthenticatedAction_c` | `@copilotkit/react-core` | action |
| `useCoAgentStateRender` | `@copilotkit/react-core` | coagent-state (`state`, `status`, `nodeName`) |
| `useLangGraphInterrupt` | `@copilotkit/react-core` | interrupt (`event`, `resolve`) |
| `useRenderTool` | `@copilotkit/react-core/v2` | render-tool (`parameters`, `status`, `toolCallId`) |
| `useRenderToolCall` | `@copilotkit/react-core/v2` | render-tool |
| `useDefaultRenderTool` | `@copilotkit/react-core/v2` | render-tool |
| `useLazyToolRenderer` | `@copilotkit/react-core/v2` | render-tool |
| `useFrontendTool` | `@copilotkit/react-core/v2` | render-tool |
| `useComponent` | `@copilotkit/react-core/v2` | render-tool |
| `useDefaultTool` | `@copilotkit/react-core/v2` | action |
| `useHumanInTheLoop` | `@copilotkit/react-core/v2` | action |
| `useInterrupt` | `@copilotkit/react-core/v2` | interrupt |
| `useRenderCustomMessages` | `@copilotkit/react-core/v2` | custom-messages (`message`) |
| `useRenderActivityMessage` | `@copilotkit/react-core/v2` | activity-message (`message`) |

数据钩子（`useCopilotReadable`、`useCoAgent`、`useAgent`、`useCopilotChat` 等）会出现在侧边栏中供导航，但没有预览——点击行即可打开源码。

导入的渲染组件同样可用：如果你的 `render` prop 是对同级文件中定义的组件的引用（而非内联箭头函数），Rolldown 会沿导入链查找，预览会绑定到实际组件。

## 行为说明

- **自动恢复**：如果某个 render prop 抛出异常，预览界面会显示一个可读的错误屏幕——在侧边栏中选择另一个钩子会自动重置错误边界。你绝不会卡在崩溃的预览上。
- **控件状态保留**：你上次使用的参数、状态和结果会按钩子存储在 VS Code 工作区状态中，下次打开同一个预览时会恢复。
- **样式生效**：`render` prop 中的 Tailwind 类通过加载到预览面板中的 Tailwind browser CDN 生效。本地 `.css` 导入由打包器收集，并在每次加载时作为 `<style>` 标签注入。

## 局限性

- **不解析桶文件（barrel file）再导出**——请直接从 `@copilotkit/react-core` 或 `@copilotkit/react-core/v2` 导入钩子。如果你通过自己的 index 文件再导出，扫描器将无法识别调用点。
- **非 CopilotKit provider**：如果你的组件需要 `<ThemeProvider>`、Redux、Auth 或其他自定义 provider 才能渲染，挂载时会抛出异常。请将钩子隔离到一个无 provider 的组件中以供预览，或在仅预览路径中桩掉该 provider。
- **智能体状态类型**：`useCoAgentStateRender` 的 state 没有运行时 schema（类型仅存在于 TypeScript 中），因此状态控件会退化为原始 JSON 编辑器。
- **动态 action 名称**：如果 `useCopilotAction({ name: someVariable })` 使用了非字面量名称，侧边栏会将该条目标注为 `(dynamic) · file:line`，直到运行时捕获解析出实际名称。

<Callout type="info">
  需要在智能体实际运行时查看实时 AG-UI 事件流？钩子浏览器是离线的、渲染优先的工具——[AG-UI 事件检查器](/troubleshooting/event-inspector)则是面向运行时的、事件优先的补充。
</Callout>
