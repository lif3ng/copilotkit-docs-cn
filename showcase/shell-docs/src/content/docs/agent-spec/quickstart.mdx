## 从你的编码智能体开始

使用这段提示词把你的 Agent Spec 智能体接入 CopilotKit，并验证对话可以正常工作。你的编码智能体会在你的项目中遵循本指南，你也可以按下面的手动步骤操作。

- Node.js 20+
- Python 3.10–3.13

          ### 安装 Agent Spec AG-UI 适配器（后端）

          Agent Spec 的 AG-UI 集成位于 `ag-ui/integrations/agent-spec/python`。你需要用它来激活起步模板中的智能体环境。安装方法如下：

          ```bash
          # 克隆适配器并进入 Python 包
          git clone --depth 1 --filter=blob:none --sparse https://github.com/ag-ui-protocol/ag-ui.git
          cd ag-ui
          git sparse-checkout set integrations/agent-spec/python
          cd integrations/agent-spec/python
          ```

          这一步会安装 AG-UI 集成，起步模板仓库将用它来安装起步模板中的智能体。这只是智能体环境的配置。
          由于该集成包使用 `uv` 作为包管理器，你可以轻松地这样安装：

          ```bash
          uv sync
          ```

          Agent Spec 是一种声明智能体与工作流结构的规范语言。Agent Spec 智能体可以运行在各种智能体框架上。目前我们支持 LangGraph 与 WayFlow（Oracle 的参考智能体框架，原生支持 Agent Spec）。
          根据你想用哪个智能体框架来执行你的 Agent Spec 智能体，可选的安装方式如下：

          ```bash
          uv sync --extra langgraph                         # 用于 LangGraph
          uv sync --extra wayflow                           # 用于 WayFlow
          uv sync --extra langgraph --extra wayflow         # 两者都装
          ```

          你也可以使用 `pip`：

          ```bash
          pip install -e .[wayflow]
          pip install -e .[langgraph]
          pip install -e .[wayflow,langgraph]
          ```

          注意：这些命令会从源码（即各自的 GitHub 仓库）安装 [`pyagentspec`](https://github.com/oracle/agent-spec) 与 [`wayflowcore`](https://github.com/oracle/wayflow) 包。
          你也可以改为从 PyPI 单独安装这些包：

          ```bash
          pip install pyagentspec[langgraph]
          pip install wayflowcore
          ```

          或者你也可以使用 uv（如果 pip 安装遇到问题）

          ```bash
          uv add pyagentspec[langgraph]
          uv add wayflowcore
          ```

          ### 设置你的智能体

          进入 ag_ui_agentspec 目录

          ```bash
          cd ag_ui_agentspec
          ```

          在 ag_ui_agentspec 目录中创建一个 main.py 文件


          ```bash
          #file path: ag-ui/integrations/agent-spec/python/ag_ui_agentspec/main.py
          from pyagentspec.agent import Agent
          from pyagentspec.llms import OpenAiCompatibleConfig
          from pyagentspec.serialization import AgentSpecSerializer
          from fastapi import FastAPI
          from ag_ui_agentspec.agent import AgentSpecAgent
          from ag_ui_agentspec.endpoint import add_agentspec_fastapi_endpoint
          import uvicorn

          agentspec_agent = Agent(
              name="AgentSpecAgent",
              description="A starter Agent that can call tools.",
              system_prompt="You are a helpful assistant, named Specky, that speaks a lot.",
              llm_config=OpenAiCompatibleConfig(
                  name="my-llm",
                  model_id="gpt-5.4",
                  url="https://api.openai.com/v1",
              ),
          )

          agent_spec_config = AgentSpecSerializer().to_json(agentspec_agent)


          #OR you can specify your own agent_spec_config like below
          #agent_spec_config = <loaded json/yaml string of your Agent Spec agent>

          runtime = "langgraph"  # or "wayflow"

          app = FastAPI()
          agent = AgentSpecAgent(agent_spec_config=agent_spec_config, runtime=runtime)
          add_agentspec_fastapi_endpoint(app, agentspec_agent=agent, path="/")

          if __name__ == "__main__":
              uvicorn.run("main:app", host="0.0.0.0", port=8000, reload=True)
          ```

          ### 设置 Copilot Runtime

          创建一个 API 路由，把 CopilotKit 连接到你的 Pydantic AI 智能体：

          ```tsx title="app/api/copilotkit/[[...slug]]/route.ts" doctest="component"
          import {
            CopilotKitIntelligence,
            CopilotRuntime,
            createCopilotRuntimeHandler,
          } from "@copilotkit/runtime/v2";
          import { HttpAgent } from "@ag-ui/client";

          const runtime = new CopilotRuntime({
            agents: {
              my_agent: new HttpAgent({ url: "http://localhost:8000/" }),
            },
            // [!code highlight:8]
            intelligence: new CopilotKitIntelligence({
              apiKey: process.env.CPK_INTELLIGENCE_API_KEY!,
            }),
            // Threads are per-user. Without this, every visitor shares one history.
            identifyUser: (request) => ({
              id: request.headers.get("x-user-id") ?? "anonymous",
              name: request.headers.get("x-user-name") ?? "Anonymous",
            }),
          });

          const handler = createCopilotRuntimeHandler({
            runtime,
            basePath: "/api/copilotkit",
          });

          export const GET = handler;
          export const POST = handler;
          ```

          在这个前端应用目录下，把运行时连接到一个 Intelligence 项目：

          ```bash title="终端"
          npx copilotkit@latest project select
          ```

          该命令会把服务端项目 API 密钥写入 `.env`。运行时在这里读取它：

          ```plaintext title=".env"
          CPK_INTELLIGENCE_API_KEY=cpk-...
          ```

          <Callout type="info" title="没有使用 Intelligence 平台？">
            去掉 `intelligence` 与 `identifyUser` 选项，运行时就会回退到使用内存运行器的
            SSE 模式。聊天仍然可用，但 Threads 与 Inspector 将保持锁定，密钥也不会被读取。
            完整的构造函数以及如何确认密钥正在使用，请参阅
            [将你的运行时连接到 Intelligence](/intelligence/quickstart)。
          </Callout>

          ### 配置 CopilotKit Provider

          用 CopilotKit provider 包裹你的应用：

          ```tsx title="app/providers.tsx"
          "use client";

          import { CopilotKit } from "@copilotkit/react-core/v2";

          export function Providers({ children }: { children: React.ReactNode }) {
            return (
              <CopilotKit runtimeUrl="/api/copilotkit" agent="my_agent" useSingleEndpoint={false}>
                {children}
              </CopilotKit>
            );
          }
          ```

          `app/layout.tsx` 是服务端组件，无法直接导入 provider，
          因此它改为渲染你的客户端文件：

          ```tsx title="app/layout.tsx"
          import { Providers } from "./providers"; // [!code highlight]
          import "@copilotkit/react-core/v2/styles.css";
          import './globals.css';

          // ...

          export default function RootLayout({ children }: {children: React.ReactNode}) {
            return (
              <html lang="en">
                <body>
                  {/* [!code highlight:3] */}
                  <Providers>
                    {children}
                  </Providers>
                </body>
              </html>
            );
          }
          ```

          <Callout type="info" title="此相对 runtimeUrl 假定由 Next.js 托管运行时">
            `/api/copilotkit` 之所以能解析，是因为 Next.js 从同一源提供你的应用与运行时。
            纯客户端前端没有共享源，因此需要自己单独的运行时服务器，
            以及一个绝对 `runtimeUrl`，例如 `http://localhost:8200/api/copilotkit`。
            `/react-spa`、`/vue`、`/angular` 与 `/react-native` 的各前端指南分别展示了这种配置。
          </Callout>

## 工具与工具注册表

如果你的 Agent Spec 包含与智能体在同一环境中执行的服务端工具，请在加载 `AgentSpecAgent` 时，通过一个 `tool_registry` 字典把这些工具按名称映射到 Python 可调用对象。

```python title="按名称绑定后端工具"
from __future__ import annotations
from fastapi import FastAPI
from ag_ui_agentspec.agent import AgentSpecAgent
from ag_ui_agentspec.endpoint import add_agentspec_fastapi_endpoint

def get_weather(city: str) -> Dict[str, Any]:
    return {"city": city, "temp_c": 22}

tool_registry = {"get_weather": get_weather}

app = FastAPI()
agent = AgentSpecAgent(
    agent_spec_config=<json/yaml string of your Agent Spec Agent>,
    runtime="langgraph",  # or "wayflow"
    tool_registry=tool_registry,
)
add_agentspec_fastapi_endpoint(app, agentspec_agent=agent, path="/")
```

前端工具（对应 Agent Spec 的 `ClientTool`）在浏览器中运行，不需要加入工具注册表——详情参见[生成式 UI 前端工具](/frontend-tools)。

## 幕后发生了什么

Agent Spec 与 `pyagentspec` SDK 帮助你在一个易读、可移植的配置对象/JSON 文件中定义智能体与工作流。
不同的适配器（LangGraph 与 WayFlow）会把你的 Agent Spec 配置加载为框架特定的对象并执行它们。换句话说，Agent Spec 是“编译器”，而框架则是“运行时”。
在这一转换过程中，适配器会配置已加载的对象，使其发出 Agent Spec Tracing 事件。这些事件在各运行时之间是标准化的。
最后，AG-UI Agent Spec 集成会监听 Agent Spec Tracing 事件，并将其导出为 AG-UI 事件，其中包括智能体执行、工具调用、智能体发出的消息等。
也就是说，如果智能体在执行期间发出一个事件（这取决于运行时），就会创建一个对应的 AG-UI 事件。
在前端，CopilotKit 将 AG-UI 事件转换并渲染为 UI。
