## 概览

本页面描述处于抢先体验阶段的 Trajectory 捕获会向 CopilotKit Intelligence 发送哪些内容。要开启捕获，参见[捕获交互](/intelligence/capture-interactions)。

捕获默认记录浏览器可见的数据。你的应用可以在投递前排除或修改事件。

## 默认捕获的内容

- URL（包括查询字符串和哈希部分），以及页面标题和 referrer，均受下文脱敏规则约束。
- 被点击元素的文本和属性，以及控件的实时值，均受下文脱敏规则约束。
- `target.label` 中每个被点击控件的简短、经过清理的名称。参见[点击标签](#点击标签)。
- `input` 与 `change` 事件中的输入框、下拉框、文本域及可编辑元素的值。
- 浏览器可见的请求与响应头，以及有大小上限的 body 快照。
- 回复评分及其评论，以及被评分回复的前 500 个字符。参见下文 [`message.feedback`](#事件)。

## 凭据脱敏

在以下捕获字段中，浏览器会将可识别的密码和凭据值替换为 `[redacted]`。这些规则无法检测到所有机密信息。[脱敏局限](#脱敏局限)描述了不支持的格式和取值。

- 密码字段的值。满足以下任一条件的字段会被视为密码字段：`type="password"`；在会话期间的任意时刻曾是密码类型（例如在“显示密码”切换之前）；其 `name` 是一个凭据键；或 `autocomplete` 设置为 `current-password`、`new-password` 或 `one-time-code`。
- 在密码字段中输入的任何值，无论它出现在 body 快照、URL 还是被点击元素的属性中。即使 `capture.inputs` 处于关闭状态，捕获也会在内存中保留最近 20 个长度不小于 4 个字符的此类值，并在停止时将其遗忘。纯数字值（例如一次性验证码）只按完整数字整体匹配。
- JSON、URL 编码和 `FormData` body 中凭据键的值；`key: value` 形式的文本（如 GraphQL 或 `Authorization: Bearer …`）；URL 查询字符串和哈希部分；以及被点击元素的属性（如 `href`）。嵌套在字符串值内部的 JSON、表单和 URL 也会被脱敏，最深可至四层。键名会保留。布尔值和 `null` 会保留，因此 `"password": null` 仍能表明没有设置密码。
- 被点击元素的属性，去掉 `data-` 前缀后其名称是一个凭据键，例如 `data-api-key` 或 `data-token`。
- 名称是凭据键的请求头的值，以及 `x-amz-security-token`、`private-token` 和 `x-token`。请求头名称会保留。

按单词拆分并忽略大小写后，一个凭据键包含 `password`、`passwd`、`passphrase`、`passcode`、`credential`、`apikey`、`apitoken`、`privatekey`、`subscriptionkey`、`accesstoken`、`refreshtoken`、`authtoken`、`sessiontoken` 或 `clientsecret`；含有单词 `secret` 或 `id token`；以单词 `authorization`、`cookie` 或 `cookies`、`jwt`、`bearer token`、`csrf token` 或 `xsrf token` 结尾；或者恰好是 `pwd`、`pass`、`token` 或 `otp`。请求头名称遵循相同规则，因此 `x-api-key`、`x-csrftoken`、`set-cookie` 和 `ocp-apim-subscription-key` 会被脱敏。描述凭据属性的键——以 `id`、`at`、`in`、`expires`、`length`、`count`、`enabled`、`required`、`policy`、`hint` 或 `type` 等单词结尾——不属于凭据键。例如，`accessToken` 和 `client_secret` 是凭据键，而 `tokenCount`、`secretary`、`invalidToken` 和 `passwordExpiresAt` 不是。

URL 中的用户名和密码（`https://user:pass@host`，任意 scheme）会被移除，body 文本和属性内也不例外。脱敏会对每个 body 的前 16 KiB 执行，然后才应用 4 KiB 的快照上限。超过 16 KiB 的 body 文本永远不会被捕获。无法脱敏的 body 会报告为 `unavailable`。不是有效 UTF-8 的文本 body 会以替换字符解码后再脱敏。其他被捕获的值保持不变。

## 脱敏局限

- 二进制 body（例如图片或 `application/octet-stream`）会以 base64 捕获，不会被检查。这包括不是有效 UTF-8 的未声明类型 body。
- 只有以 `FormData` 对象发送时，multipart body 才会按字段脱敏。手工拼接的 multipart 文本、XML 或 HTML、单引号的 JavaScript 对象，以及在查询或表单值中百分号编码的 JSON 或 URL，都不会被解析。
- 在 JSON 字符串之外，凭据键的值遇到空白符、`&`、`,`、`;`、`)`、`}` 或 `]` 即结束，因此在自由文本中只会脱敏 `password:` 之后的第一个单词。
- 长度不足 4 个字符的密码不会被记住。每个字段只记住最新的值，因此输入过程中较早发出的更短前缀之后不会再被匹配。
- URL 路径中的 OAuth 授权码（`code=`）和 token 不会被脱敏。
- 被点击元素的文本、页面标题和普通控件值不会经过通用的凭据扫描。
- 开发者事件的负载和显式操作名（`target.action`）不会经过自动凭据脱敏。

对于这些规则未覆盖的应用数据，可以使用 `beforeSend`、捕获开关和 `data-copilotkit-ignore` 来排除。这些控制手段见[控制手段](#控制手段)一节。

被点击元素的文本会在 1,000 个字符处截断。路径保持不变。捕获会跳过发往所配置 Runtime 端点的请求。

## 事件

每个事件都是一个 AG-UI `CUSTOM` 事件：`{ type: "CUSTOM", name, value, timestamp }`。每个投递的 `value` 都带有一个序列号 `seq`。序列号在 Core 实例的整个生命周期内递增，包括跨越停止/启动周期。

序列号以 Core 实例的创建时间（微秒）为起点。这并不能保证共享同一个 Trajectory ID 的多个 Core 实例之间序号唯一。除非你的应用需要续用现有的 Trajectory，否则请为每次页面加载使用新的 Trajectory UUID。

| `name` | 主要 `value` 字段 | 来源 |
| --- | --- | --- |
| `page` | `route`, `url`, `title`, `referrer` | 浏览器，启动时 |
| `navigation` | `from`, `to`, `navigationType` | 浏览器 |
| `click` | `target` (`tag`, `role`, `action`, `text`, `label`, `attributes`, control values, `input`), `route`, `url` | 浏览器 |
| `input` | `eventType`, `target` (element details and control values), `route`, `url` | 浏览器 |
| `network` | `transport`, `method`, `url`, `origin`, `route`, `status`, `durationMs`, `outcome`, `request`, `response` | 浏览器 |
| `thread.linked` | `threadId` | Core |
| `message.feedback` | `feedbackId`, `threadId`, `messageId`, `agentId`, `runId`, `rating`, `comment`, `response` | Chat，当用户对回复评分、修改评论或移除评分时 |

当 Runtime 在某个 Thread 中启动一次运行时，Core 会为该 Thread 发出一次 `thread.linked`。点击事件不携带 Thread、消息或工具字段。一个 Trajectory 可以包含不关联任何 Thread 的交互。

`message.feedback` 事件记录一次[回复评分](/intelligence/capture-interactions#collect-reply-ratings)。`rating` 为 `"up"` 或 `"down"`；用户移除评分时为 `null`。`comment` 会去除首尾空白、在 1,000 个字符处截断，为空时省略。`response` 保存被评分回复的前 500 个字符。当聊天不知道该回复所属的运行时，`runId` 会被省略。`feedbackId` 为 `threadId:messageId`；同一个 `feedbackId` 的最新事件即当前评分。

控件值包括 `value`、复选框和单选按钮的 `checked`、下拉框的 `selectedValues`，以及文件输入的文件元数据。

网络事件的 `request` 和 `response` 字段包含 `headers` 和 `body` 快照。每个序列化后的 body 快照上限为 4 KiB。快照会报告 `status`：`complete`、`empty`、`truncated`、`unavailable`、`interrupted` 或 `timeout`。它还可以包含 `text`、`encoding`（`utf-8` 或 `base64`）、`truncated` 和 `reason`。

Fetch body 捕获读取的是克隆出来的流，不会改变应用的响应。它会在达到大小上限或 1 秒后停止。浏览器限制和不可读取的 body 会产生明确的状态值。

Fetch 的时长在响应头到达时结束；XHR 的时长在 `loadend` 时结束。

通过 `emitTrajectoryEvent()` 发送的自有事件使用你自己的名称。捕获接受任何 JSON 值。对于非对象值以及已带有 `seq` 的对象，它会包装为 `{ data: value, seq }`。

## 点击标签

点击事件包含 `target.label`，即被点击控件的简短名称，例如 `Approve` 或 `Switch to dark mode`。自动学习（Automatic Learning）会把该名称提供给模型。捕获按顺序使用以下来源中第一个能给出名称的：

1. `aria-labelledby` 所引用元素的文本，除非它们位于可编辑内容、`textbox`、`searchbox`、`combobox` 或建议列表（见下文）内部。
2. `aria-label`。
3. 提交、按钮或重置类型 input 的显示文字，或图片 input 的 `alt` 文本。原生复选框或单选按钮的 `<label>` 文本不会被使用，因为它往往是待办事项之类的用户内容。请改为给这些控件设置 `aria-label` 或 `data-copilotkit-action`。
4. `title`，仅适用于控件：按钮、带 `href` 的链接、`summary`、具有控件角色（见下文）的元素，以及按钮样式的 input。绝不用于承载值的字段。
5. 以自身内容命名的控件的文本：按钮、带 `href` 的链接、`summary`，以及角色为 `button`、`link`、`tab`、`menuitem`、`menuitemcheckbox`、`menuitemradio`、`option`、`checkbox`、`switch`、`radio` 和 `treeitem` 的元素。显式设置的 `role` 会覆盖标签名。控件内部的图片按其 `alt` 计入，`svg` 或 `role="img"` 元素按其 `aria-label` 或普通 `<title>` 计入；捕获不会进一步深入图片内部。`b`、`em`、`mark`、`span` 等行内格式化元素会把词语连接在一起，其他元素则起分隔作用。

被点击的图片、`svg` 或角色为 `img`、`presentation`、`none` 的元素，会使用其自身的 `aria-labelledby`、`aria-label`、`alt` 或 `<title>`。如果没有，则取其外围最近的控件的名称。

文本绝不会来自列表项、行、单元格、对话框、region、`main`、label 等容器，也不会来自不带 `href` 的链接。当文本看起来像若干独立字段时（卡片正是如此），控件不会从其文本获得名称：

- 文本超过 80 个字符。
- 控件包含标题、列表、表格、`article`、`section`、`blockquote`、字段或多于一个段落。允许一个段落；`summary` 内部的标题也允许。
- 两个或更多 `div` 元素直接或通过行内元素持有文本，或者三个或更多同级元素各自带有文本。
- 遍历超过 1,000 个节点或 320 个字符。

可编辑内容永远不会贡献文本。script、style、template、`hidden` 以及 `aria-hidden="true"` 的内容会被跳过。分配给 web component 内部 `<slot>` 的文本不会被读取，因此这类控件需要 `aria-label`。`aria-label` 对以上所有情况依然生效。

自动补全建议不会从任何来源获得标签，因为它们的名称通常只是重复用户输入的内容。这里指的是由 combobox 或自动补全字段控制或拥有的弹窗中的 option 和 tree item、`combobox` 内部的 option，以及 `datalist` 的选项。它们的 `aria-labelledby`、`aria-label`、`title` 和文本都会被忽略，在其中点击的任何内容也不例外。位于其他控件上、指向这类列表的 `aria-labelledby` 同样给不出名称。要为建议命名，请设置 `data-copilotkit-action`，它会作为 `target.action` 发送。

捕获只能识别使用 ARIA 标注的建议列表。对于没有这些角色的自定义建议列表，请添加 `data-copilotkit-ignore`，或在 `beforeSend` 中移除标签。

捕获按以下顺序清理选定的名称：

1. 移除不可见字符：Unicode 默认可忽略码点，包括 bidi 控制符、零宽字符和软连字符。
2. 应用上文的密码与凭据脱敏。
3. 折叠空白符。
4. 再次替换已记住的密码，即使它们只差空白符或不可见字符也会被替换。
5. 将 URL（`scheme://…` 和 `www.…`）替换为 `[url]`。
6. 将电子邮箱替换为 `[email]`。
7. 将 JWT（`eyJ…`）替换为 `[redacted]`；同样处理由三个点分段组成、每段均不少于 16 个字符，或每段均不少于 8 个字符且各含一个数字的字符串。`settings.notifications.preferences` 这类点分名称会保留。
8. 将由字母、数字和 `_-+/=` 组成、长度不少于 24 个字符且含数字的连续串替换为 `[redacted]`。
9. 超过 80 个字符（按 Unicode 码点计）的名称会被截断并以 `…` 结尾。

只替换匹配的部分。如果清理后没有剩余名称，则省略 `label`。这一标签清理不会改变 `text`、`attributes` 或控件值。属性和控件值仍适用各自独立的凭据脱敏规则。标签干净并不意味着事件其余部分不含敏感数据。

`data-copilotkit-action` 会在 `target.action` 中为控件赋予显式名称。要排除某个控件，请添加 `data-copilotkit-ignore`。要发送不带标签的点击事件，请在 `beforeSend` 中移除该字段：

```ts
import type { TrajectoryEvent } from "@copilotkit/learning";

function withoutClickLabel(event: TrajectoryEvent): TrajectoryEvent {
  const value = event.value;
  if (event.name !== "click" || !value || typeof value !== "object" || Array.isArray(value)) {
    return event;
  }
  const target = value.target;
  if (target && typeof target === "object" && !Array.isArray(target)) {
    delete target.label;
  }
  return event;
}
```

在 React provider 上以 `learning={{ beforeSend: withoutClickLabel }}` 的形式传入该函数。

## 表单编辑的记录时机

文本编辑按字段合并。300 ms 内没有新的编辑时，捕获会把最新值记录一次。字段提交、焦点变化、非输入法组词状态下的回车、点击、提交表单、页面导航、开发者事件或显式停止，都会让待记录的编辑提前落盘，先于随后的动作。同一次编辑配对的 `input` 与 `change` 通知只会产生一条记录。用户后续的编辑可以再次记录相同的值，包括在应用清空字段之后。

事件的 `timestamp` 标记的是捕获记录这次编辑的时刻（在防抖之后或更早的强制落盘时），而不是最后一次按键的时间。

复选框、单选按钮、下拉框、滑块和颜色控件的变更会立即记录。在输入法组词期间，捕获会保留最新观察到的编辑，但不会在停顿时记录。组词完成会启动 300 ms 计时器；显式停止或其他触发落盘的动作即使组词仍在进行也会记录待处理的编辑。用于选择输入法候选词的回车不会触发落盘。网络响应不会结束一次连续输入。

这改变的是编辑被记录的频率，而不是捕获哪些字段或值。上文的脱敏与排除规则仍然适用。被记录的编辑走正常的投递队列。停止捕获会尝试发送最后一批数据，但不等待回执，也不保证持久化成功。当捕获失去网关连接时，它会清空待处理的编辑，使它们不会出现在之后的捕获会话中。

## 批次

Core 通过经过身份验证的连接向 Intelligence 发送 `{ events, dropped }`。该连接标识了 Trajectory。

- Core 在两秒后、达到 50 个事件时、或在批次超过 64 KiB 之前发送一个批次。
- 每个事件序列化为 UTF-8 JSON 后必须在 16 KiB 以内（含序列元数据）。
- 连接中断期间捕获暂停。恢复期间发出的开发者事件计入丢弃，其内容不会被缓冲。
- Core 不会重发失败的批次。缺少回执时报告 `PERSISTENCE_UNKNOWN`，因为 Intelligence 可能仍已接受该批次。
- 只有在没有更早的回执仍待确认时，停止才会尝试发送最后一批。它不会等待回执，也不保证事件已保存。

回执确认事件已进入队列。已保存的 Trajectory 记录异步更新。要确认持久化结果，请在 Intelligence 中重新打开该 Trajectory 并查找事件。

## 控制手段

在代码中（类型与默认值见 [API 参考](/intelligence/trajectories-reference#learning-prop-on-copilotkitprovider)）：

| 选项 | 作用 |
| --- | --- |
| `ignoreUrls` | 网络捕获会跳过的 URL 前缀或模式。 |
| `capture` | 关闭 `clicks`、`inputs`、`navigation` 或 `network`。四者默认均开启。 |
| `beforeSend` | 最后在浏览器中执行。返回事件、修改后的副本，或返回 `null` 以丢弃。 |

在标记中：

- `data-copilotkit-action="deal.approve"` 为控件显式命名，该名称进入 `target.action`。
- `data-copilotkit-ignore` 排除该元素内部的点击与输入事件。

示例：将发往某个服务的网络请求排除在捕获之外。

```tsx
<CopilotKitProvider
  runtimeUrl="/api/copilotkit"
  learning={{ ignoreUrls: ["https://payments.example.com/"] }}
>
  {children}
</CopilotKitProvider>
```

要开启捕获，参见[捕获交互](/intelligence/capture-interactions)。
