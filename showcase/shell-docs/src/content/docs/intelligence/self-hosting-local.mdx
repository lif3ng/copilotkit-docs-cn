## 概览

CopilotKit CLI 可以在你自己的机器上用 Docker 运行 CopilotKit Intelligence。你把一个应用连接到它、登录本地仪表盘，用自己的数据和模型试用 Intelligence。你不需要 Kubernetes 经验、云账户或 Team Self-hosted 计划。

<Callout type="warn" title="预览：支持 macOS">
  本地评估是一个预览特性，支持 macOS 搭配 Docker Desktop。CLI 也接受使用 rootful Docker Engine 的 Linux，但 Linux 运行时评估未经验证，不在受支持的预览范围内。请将其用于在单台机器上试用 Intelligence，它不是生产安装。要为你的团队运行 Intelligence，请使用 [Kubernetes 指南](/intelligence/self-hosting)或 [AWS ECS 指南](/intelligence/self-hosting-ecs)。
</Callout>

## 你的机器上会运行什么

CLI 会为每个应用文件夹创建一个本地堆栈。每个堆栈都有自己的数据、端口和仪表盘登录。

| 包含 | 不包含 |
| --- | --- |
| Intelligence 的 AG-UI 流（已保存的线程） | 用户记忆 |
| 自动学习 | 产品分析 |
| 渠道（Slack 和 Microsoft Teams） | 模型或模型凭据 |
| Intelligence 仪表盘和本地登录 | |

安装之后，只要许可证有效，堆栈就可以在无互联网访问的情况下运行。以下任务仍需联网：

- 首次安装及后续更新
- 获取或续期评估许可证
- 调用在线模型提供方
- Slack 和 Microsoft Teams 消息

## 开始之前

- **操作系统**：Apple silicon 或 Intel 的 macOS，并安装 Docker Desktop。CLI 在 macOS 上会拒绝其他 Docker 引擎，例如 Colima、OrbStack 和 Rancher Desktop，并且不支持 Windows。
- **Docker 资源**：每个堆栈至少 4 个 CPU、12 GiB 内存和 40 GiB 可用存储。CLI 会检查 Docker 在扣除你其他容器之后的剩余资源，不足时即停止。
- **Node.js**：本地登录建议使用 22 或更新版本。CLI 声明的最低版本为 20.9.0。
- **CopilotKit 账户**：CLI 用它获取你的评估许可证。Developer 计划即可。
- **模型访问（可选）**：用于自动学习的 OpenAI 或 Anthropic API 密钥，或 OpenAI 兼容端点。

Docker 由你自己安装。CLI 绝不会安装或更新 Docker。它会自行下载管理堆栈所需的工具副本。

## 搭建本地堆栈

请在你的应用文件夹中执行以下步骤。如果你还没有应用，先用 `npx copilotkit@latest init` 创建一个。

<Steps>
  <Step>
    ### 登录

    ```bash title="终端"
    npx copilotkit@latest login
    ```

    本地堆栈会使用你在此处选择的组织。安装过程不会复制云托管的项目或数据。
  </Step>

  <Step>
    ### 安装堆栈

    ```bash title="终端"
    npx copilotkit@latest local setup
    ```

    CLI 会先检查 Docker，然后询问自动学习模型（可以之后再添加）以及是否添加示例对话。对于新堆栈，随后它会选取最新发行版本、获取你的许可证并安装堆栈。

    运行过程中，CLI 会显示每个步骤及其耗时。镜像下载会显示已完成多少个镜像、目前的大小和速度。安装完成后，它会打开仪表盘并帮你登录。
  </Step>

  <Step>
    ### 连接你的应用

    ```bash title="终端"
    npx copilotkit@latest local connect
    ```

    该命令只展示连接变更而不实际执行。要应用变更，请运行：

    ```bash title="终端"
    npx copilotkit@latest local connect --approve-connection
    ```

    CLI 会将这些值写入应用的 `.env`：

    ```bash title=".env"
    INTELLIGENCE_API_URL=http://localhost:<port>
    INTELLIGENCE_GATEWAY_WS_URL=ws://localhost:<port>
    CPK_INTELLIGENCE_API_KEY=cpk-...
    SL_ENABLED=true
    ```
  </Step>

  <Step>
    ### 运行应用

    ```bash title="终端"
    npm run dev
    ```

    从你的应用发送一条消息。对话会出现在本地仪表盘中。
  </Step>
</Steps>

在做任何更改之前，CLI 会保存你之前的设置。如果 `.env` 被 Git 跟踪，CLI 会拒绝写入密钥。本地项目从空开始。你的云托管数据保持原样。

要恢复之前的设置，请运行：

```bash title="终端"
npx copilotkit@latest local cancel
```

`local cancel` 会恢复每一条仍与安装时写入内容一致的设置；对你后来修改过的设置则予以保留并指出名称。堆栈及其数据保持原位。

对于脚本，把每个回答都写成标志：

```bash title="终端"
npx copilotkit@latest local setup --defer-model --no-samples --json
npx copilotkit@latest local connect --approve-connection --json
```

## 登录本地仪表盘

本地仪表盘不使用你的 CopilotKit 账户。CLI 会在后台运行一个小型登录服务，每次登录都由你的终端批准。

```bash title="终端"
npx copilotkit@latest local login
```

请在应用文件夹中运行它。它会打开仪表盘并帮你登录，无需输入代码或点击。它使用的链接只能使用一次，两分钟后过期。在应用文件夹之外运行时，请加上 `--stack <id>`。

如果你自己在仪表盘中打开并选择 **Sign In**，请在终端批准该请求：

1. 运行 `npx copilotkit@latest local auth pending --stack <id>`。
2. 确认终端中的代码与浏览器中的代码一致。
3. 批准它。浏览器页面会显示完整的批准命令和一个 **Copy command** 按钮。将该命令粘贴到你的应用文件夹中运行，或运行 `npx copilotkit@latest local auth approve CODE --stack <id>`。使用 `deny CODE` 可以拒绝请求。

<Callout type="warn" title="只批准你自己的请求">
  任何能读取你 CLI 文件的进程都可以批准登录，包括编码智能体。只批准你自己发起的请求。
</Callout>

`local credentials` 会打印仪表盘 URL 和两个登录命令。它不会打印密码。

## 配置自动学习

堆栈不包含模型。你需要为每个堆栈提供模型访问，共享该堆栈的每个应用都会使用它。

要通过交互提示配置，请在应用文件夹中运行：

```bash title="终端"
npx copilotkit@latest local setup
```

选择 OpenAI、Anthropic 或 OpenAI 兼容端点。输入 API 密钥，然后从列表中选择一个模型。CLI 只会把密钥发送给该提供方的模型列表。它只显示自动学习支持的模型。

对于脚本，请把设置放在源码控制之外的 JSON 文件中：

```json title="model.json"
{
  "model": "openai/your-model",
  "provider": "openai",
  "apiKey": "your-model-key"
}
```

```bash title="终端"
npx copilotkit@latest local setup --model-config /path/to/model.json
```

要使用你自己机器上的模型，请将 `baseUrl` 指向一个 OpenAI 兼容服务器。API 密钥可选：

```json title="model.json"
{
  "model": "local/your-model",
  "provider": "compatible",
  "baseUrl": "http://localhost:11434/v1"
}
```

CLI 会将回环模型 URL（包括 `localhost`）改写为 `host.k3d.internal`，以便堆栈能通过 Docker 访问你的机器。安装过程不会测试模型端点是否可达。仅绑定回环地址的模型服务器尚未在 macOS 的 Docker Desktop 上验证；在依赖该配置之前，请通过一次真实的自动学习运行来验证访问。

在健康运行中的堆栈上，从一个模型切换到另一个只会重启自动学习服务。添加首个模型或用 `local setup --defer-model` 移除模型时，还会重启 app-api，从而启用或禁用自动学习运行。用相同的模型选择再次运行 `local setup` 不会产生任何变化。保存配置并不能证明模型可用，真正的自动学习运行才能证明。

在连接模型之前，学习运行处于关闭状态。线程、Learning Spaces 和已保存的结果仍然可用。仪表盘会显示 **No AI model connected** 以及修复它的命令。

### 添加示例对话

安装过程提供 16 个包含重复出现错误与纠正的示例对话，供自动学习去发现。只要堆栈中还没有它们，每次交互式 `local setup` 都会询问。它们会进入一个名为 **Sample conversations** 的独立 Learning Space，因此绝不会与你的应用线程混在一起。你也可以用 `npx copilotkit@latest local samples` 添加它们。

## 连接 Slack 或 Microsoft Teams

[渠道](/intelligence/channels)在本地堆栈上的配置方式相同。Slack 和 Microsoft Teams 必须能通过公共 HTTPS 地址访问你的机器，例如你的网络允许的隧道。该地址由你自行安排；CLI 不会安装或管理隧道。没有它，堆栈的其余部分仍可正常工作。

## 管理堆栈

请在应用文件夹中运行这些命令，或在其他位置运行时加上 `--stack <id>`。`local list` 会显示每个堆栈及其 ID。

| 命令 | 作用 |
| --- | --- |
| `local status` | 显示服务健康状况、URL 以及任何失败的安装步骤。 |
| `local start` | 以保存的发行版本、许可证和设置启动堆栈。无需互联网访问。 |
| `local stop` | 停止堆栈并保留其数据。 |
| `local list` | 列出你的所有堆栈，包括应用文件夹已删除的堆栈。 |
| `local login` | 打开仪表盘并帮你登录。 |
| `local credentials` | 打印仪表盘 URL 和登录命令。 |
| `local setup` | 更改模型设置，或恢复被中断的安装。 |
| `local samples` | 添加示例对话。 |
| `local update` | 将堆栈更新到最新发行版本并保留其数据。 |
| `local renew` | 获取新许可证并应用。 |
| `local cancel` | 恢复应用之前的连接设置。 |
| `local delete` | 先询问，然后删除堆栈及其全部数据。 |

每条命令都要加 `npx copilotkit@latest` 前缀。加上 `--json` 可以获得脚本和编码智能体可读取的带版本结果。`local setup`、`start`、`stop`、`delete`、`update`、`status` 和 `renew` 会在继续之前检查 Docker。`local connect`、`cancel` 和 `credentials` 不检查 Docker。CLI 不会替你启动 Docker。

退出 CLI 登录不会移除堆栈。如果安装失败，它会保留堆栈并指出是哪一步停止了。再次运行 `local setup` 即可用已保存的输入继续。

在 `local setup` 中加上 `--share-stack`，应用文件夹的副本就可以共享原堆栈。`local delete` 会列出使用该堆栈的每个应用文件夹，并在删除任何内容之前先询问；**No, keep it** 是默认选项。脚本用 `local delete --stack <id> --confirm-delete <id>` 进行确认。它绝不会删除你应用的源文件。

### 更新到新版本

```bash title="终端"
npx copilotkit@latest local update
```

`local update` 会找到最新发行版本并把堆栈迁移过去，保留你的线程、学习结果、项目和凭据。它会像安装过程一样显示进度。如果堆栈已经运行最新发行版本，它会如实说明且不做任何更改。如果某个发行版本无法就地更新堆栈的数据库，CLI 会如实说明并保持你的数据不变。

## 许可证与续期

你的评估许可证遵循你组织当前的计划：

- **除 Enterprise 外的所有计划**：许可证有效期为 30 天。免费的 Developer 计划即可。
- **Enterprise**：许可证有效期至你的付费期限结束；若没有记录截止日期，则为 30 天。
- **状态异常的付费计划**不会获得许可证。

要续期，请运行 `npx copilotkit@latest local renew`。续期需要互联网访问和 CopilotKit 登录，并执行同样的计划检查。它会保留你的数据，且不会重启已接受的学习任务。如果堆栈处于停止状态，`local start` 会应用保存的续期。

许可证过期后，新的学习运行会停止。已保存的线程和学习结果仍可读取，仪表盘会说明如何续期。

许可证与你在登录时选择的组织绑定。续期无法把堆栈转移到另一个组织。
