## 概览

你想在已有的应用上获得 AG-UI Streams、用户记忆、自动学习、渠道和产品分析。Intelligence 负责加上这一层。你的前端和智能体都保持原位。

你现有的线程存储和原生持久化保持配置不变。当对话经过所连接的运行时流动时，Intelligence 会自动记录一份自己受支持的 AG-UI 交互历史副本。参见 [Intelligence 记录了什么](/intelligence/bring-your-own-thread-system#how-recording-works)以及[保留现有 LangGraph 应用的示例](/intelligence/bring-your-own-thread-system#example-keep-an-existing-langgraph-conversation)。

当 Inspector 显示 Intelligence 已连接并展示你第一条已保存的线程时，配置就完成了。React Native 应用没有 Inspector，请改为在云托管项目中确认线程。

TypeScript 是默认且功能最完整的运行时，可以在有或没有 Intelligence 的情况下运行。Python、Go、Ruby 和 C#/.NET 运行时则需要 Intelligence（云托管或自托管）。请在下方选择你的**运行时服务器**所用的语言；你的智能体框架和前端保持不变。

## 手动配置

开始之前，请准备好一个可正常工作的 CopilotKit 前端和智能体。TypeScript 标签页连接你现有的运行时；其他标签页则在一个已通过 HTTP 提供 AG-UI 的智能体前面挂载一个原生运行时。请使用你智能体的 AG-UI URL，而不是 CopilotKit 运行时 URL。

<Steps>
  <Step>
    ### 选择 Intelligence 项目

    在你的应用目录中登录，然后选择将存储你的线程的项目。

    ```bash title="终端"
    npx copilotkit@latest login
    npx copilotkit@latest project select
    ```

    `project select` 会创建一个项目 API 密钥，并将其作为 `CPK_INTELLIGENCE_API_KEY` 写入 `.env`。请将该密钥放入运行 CopilotKit 运行时的进程环境中。命令输出不会打印该密钥，请从 `.env` 中读取。

    ```bash title=".env"
    CPK_INTELLIGENCE_API_KEY=cpk-...
    ```

    CLI 会在你运行命令的目录写入 `.env`。如果你的运行时进程加载的是另一个文件，请把该密钥复制进去。宿主环境已设置的值保持原样。

    请把密钥保存在服务器端。不要把它放进前端构建会发送到浏览器的变量中。
  </Step>

  <Step>
    ### 连接你的运行时

    选择你的运行时语言。该选择同样适用于下方的自托管设置。这些示例在每种语言中都使用多路由 HTTP 端点。

    <Tabs groupId="runtime_language" persist default="TypeScript" items={["TypeScript", "Python", "Go", "Ruby", "C#/.NET"]}>
    <Tab value="TypeScript">

    保留你现有的 TypeScript 运行时和智能体注册。如果尚未安装，请安装当前包：

    ```bash
    npm install @copilotkit/runtime
    ```

    添加一个 Intelligence 客户端。该客户端对所有智能体框架都相同。

    ```ts title="Your CopilotKit runtime"
    import {
      CopilotKitIntelligence,
      CopilotRuntime,
    } from "@copilotkit/runtime/v2";

    // Create the Intelligence client with your project API key. Keep this key on the server.
    const intelligence = new CopilotKitIntelligence({
      apiKey: process.env.CPK_INTELLIGENCE_API_KEY!,
    });

    const runtime = new CopilotRuntime({
      agents,
      // Pass the Intelligence client to the runtime
      intelligence,
      // Identify the user from a verified session or token
      identifyUser: async (request) => {
        const user = await authenticateApplicationUser(request);
        if (!user) throw new Error("Unauthorized");
        return { id: user.id, name: user.name };
      },
    });
    ```

    <Callout type="info" title="使用你现有的身份验证">
      `authenticateApplicationUser` 代表你的服务端身份验证函数。它必须从经过验证的会话或令牌中返回用户。Runtime 需要 `identifyUser` 来将网页线程与该用户关联。
    </Callout>

    如果不存在可信的用户身份，请在继续之前先添加身份验证。固定身份只适用于本地的单用户演示。

    <Callout type="warn" title="生产环境前保护好每条 Runtime 路由">
      `identifyUser` 标识调用者，但它不是身份验证闸门。请使用处理器的 `onRequest` 钩子拒绝未经身份验证的请求。你还必须对 `threads/events`、`threads/state` 和 `agent/stop` 强制执行线程所有权。完整模式请遵循[线程授权指南](/auth#thread-authorization)。
    </Callout>

    网页运行时需要 `identifyUser`。仅 Channels 的运行时没有网页界面，请改为传入非空的 `channels` 数组。

    运行时会从你传入的客户端读取密钥，它不会自行从环境中读取。`apiKey` 是唯一必填字段。你不需要传入组织 id 或项目 id。

    #### 已有 runner 的现有运行时

    开源运行时常会传入 `runner`。该选项决定运行记录存储在哪里。Intelligence 会自行存储运行记录。添加 `intelligence` 时请移除 `runner`。

    ```ts
    const runtime = new CopilotRuntime({
      agents,
      runner: new InMemoryAgentRunner(), // [!code --]
      intelligence, // [!code ++]
      identifyUser,
    });
    ```

    TypeScript 不允许同时使用这两个选项。JavaScript 运行时会抛出以下错误：

    ```text
    Intelligence Runtime auto-wires its own `runner`; passing `runner` alongside
    `intelligence` is not supported.
    ```

    你也可以保留 `runner` 并省略 `intelligence`。此时运行时保持在 SSE 模式，Inspector 中的线程仍处于锁定状态。参见 [AgentRunner 与持久化](/backend/agent-runner)。

    保留你已传入的其他运行时选项，例如 `mcpApps`、`a2ui` 和 `openGenerativeUI`。它们作用于每次运行中的智能体，与 `intelligence` 一起使用时方式相同。使用 MCP Apps 的应用请参见 [MCP Apps 与 Intelligence](/generative-ui/mcp-apps#mcp-apps-with-intelligence)。

    #### 挂载 TypeScript 处理器

    创建一个处理器，并在你已使用的服务器中为所有运行时子路径和 HTTP 方法挂载它。对于 Next.js，请使用 catch-all 路由：

    ```ts title="app/api/copilotkit/[[...slug]]/route.ts"
    import { createCopilotRuntimeHandler } from "@copilotkit/runtime/v2";

    const handler = createCopilotRuntimeHandler({
      runtime,
      basePath: "/api/copilotkit",
    });

    export const GET = handler;
    export const POST = handler;
    export const PATCH = handler;
    export const DELETE = handler;
    ```

    请在与上文配置好的 `runtime` 相同的模块中使用该处理器。它接受 Web `Request` 并返回 Web `Response`。对于 Express、Hono 及其他宿主，请使用 [TypeScript 服务器适配器指南](/runtime-server-adapter)。

    TypeScript 还支持 `mode: "single-route"`。如果你现有的应用使用该模式，请保留其单一 POST 路由和匹配的前端传输方式。该选项不适用于其他运行时语言。

  <Step>
    ### 连接你的前端

    将前端 provider 指向运行时的基础路径。如果你的前端把该路径代理到运行时，请使用 `/api/copilotkit`。对于独立的本地服务器，请使用 `http://localhost:8200/api/copilotkit`，并在运行时的 CORS 配置中允许你前端的精确来源（origin）。

    保留你现有的应用身份验证请求头或会话。下面的示例连接的是 TypeScript 运行时。对于上方标签页中的 Python、Go、Ruby 或 C#/.NET 运行时，请使用 `http://localhost:8200/api/copilotkit` 并取消注释 `headers` 行。那些原生示例使用本地应用令牌：`Authorization: Bearer <APP_AUTH_TOKEN>`。这是你自己设置的开发令牌，**不是** `CPK_INTELLIGENCE_API_KEY`。请将 `<APP_AUTH_TOKEN>` 替换为你在服务器上配置的同一本地令牌，并在部署前把本地方案替换为你应用的身份验证。

    <FrontendOnly frontend="react">
      对于上述多路由服务器，请设置 `useSingleEndpoint={false}`。如果你保留的是现有的 TypeScript 单路由服务器，则改为保持 `useSingleEndpoint={true}`。

      ```tsx title="Your CopilotKit provider"
      import { CopilotKitProvider } from "@copilotkit/react-core/v2";

      export function App() {
        return (
          <CopilotKitProvider
            runtimeUrl="/api/copilotkit"
            useSingleEndpoint={false}
            // Native runtime: runtimeUrl="http://localhost:8200/api/copilotkit" and
            // headers={{ Authorization: "Bearer <APP_AUTH_TOKEN>" }}
          >
            <YourApp />
          </CopilotKitProvider>
        );
      }
      ```
    </FrontendOnly>

    <FrontendOnly frontend="angular">
      将 `provideCopilotKit` 指向运行时的基础路径。

      ```ts title="src/app/app.config.ts"
      import { ApplicationConfig } from "@angular/core";
      import { provideCopilotKit } from "@copilotkit/angular";

      export const appConfig: ApplicationConfig = {
        providers: [
          provideCopilotKit({
            runtimeUrl: "http://localhost:8200/api/copilotkit",
            // Native runtime: headers: { Authorization: "Bearer <APP_AUTH_TOKEN>" },
          }),
        ],
      };
      ```
    </FrontendOnly>

    <FrontendOnly frontend="vue">
      将 `CopilotKitProvider` 指向运行时的基础路径，并包裹你现有的应用。

      ```vue title="src/App.vue"
      <script setup lang="ts">
      import { CopilotKitProvider } from "@copilotkit/vue/v2";
      import YourApp from "./YourApp.vue";
      </script>

      <template>
        <!-- Native runtime: add :headers="{ Authorization: 'Bearer <APP_AUTH_TOKEN>' }" -->
        <CopilotKitProvider runtime-url="http://localhost:8200/api/copilotkit">
          <YourApp />
        </CopilotKitProvider>
      </template>
      ```
    </FrontendOnly>

    <FrontendOnly frontend="react-native">
      将 `CopilotKitProvider` 指向模拟器或设备可以访问的运行时 URL。

      ```tsx title="App.tsx"
      import { CopilotKitProvider } from "@copilotkit/react-native/headless";
      import { Platform } from "react-native";
      import { AppContent } from "./src/AppContent";

      const runtimeUrl =
        Platform.OS === "android"
          ? "http://10.0.2.2:8200/api/copilotkit"
          : "http://localhost:8200/api/copilotkit";

      export default function App() {
        return (
          <CopilotKitProvider
            runtimeUrl={runtimeUrl}
            // Native runtime: headers={{ Authorization: "Bearer <APP_AUTH_TOKEN>" }}
          >
            <AppContent />
          </CopilotKitProvider>
        );
      }
      ```

      原生服务器示例为了本地开发绑定在回环地址上。对于无法访问该监听地址的 Android 模拟器或物理设备，请将运行时服务器也绑定到你开发机的局域网接口（或 `0.0.0.0`）。在物理设备上，请将前端 URL 的主机替换为开发机的局域网 IP 地址。保持身份验证开启，并将访问限制在你的开发网络内。
    </FrontendOnly>
  </Step>

  <Step>
    ### 确认连接

    启动运行时，并在 `{runtimeUrl}/info` 检查发现信息。对于运行在 3000 端口的 Next.js TypeScript 处理器：

    ```bash
    curl --fail http://localhost:3000/api/copilotkit/info
    ```

    对于原生示例，请使用 `http://localhost:8200/api/copilotkit/info`。

    响应应报告 `mode: "intelligence"` 以及你注册的智能体。仅凭发现信息不能证明持久化已生效；接下来请创建并检查一个线程。

    <FrontendOnly frontend="react">
      启动你的应用并在 localhost 上打开它。点击应用角落的 Inspector 按钮（Kite 图标）。

      1. 打开 **Home**，确认 **What's going on** 旁边显示 **Intelligence connected**。
      2. 回到你的应用，发送一条消息以创建线程。
      3. 在 Inspector 中打开 **Rich Threads**，你的新线程必须出现在列表中。
      4. 打开该线程，确认 **Messages** 中包含你发送的消息。

      如果 **Home** 未显示 **Intelligence connected**，或线程处于锁定状态，说明配置未完成。请按 Inspector 中显示的操作执行，或查阅 [Inspector 配置状态](/inspector#project-context-and-usage)。
    </FrontendOnly>

对话有回复并不能证明密钥正在被使用。SSE 运行时会在未读取密钥的情况下照常回复。请使用上方的 Inspector 检查，或在[云托管项目](/intelligence/managed-intelligence-platform)中打开该线程。

## 自托管部署

所有运行时默认使用云托管 Intelligence。若要自托管，请在所选运行时的配置中替换端点设置。保留上文配置中的项目密钥和身份验证。使用你的运行时和浏览器都能访问的公共地址。

<Tabs groupId="runtime_language" persist default="TypeScript" items={["TypeScript", "Python", "Go", "Ruby", "C#/.NET"]}>
<Tab value="TypeScript">

在 `CopilotKitIntelligence` 上同时设置 `apiUrl` 和 `wsUrl`。传入裸的 WebSocket 基础地址即可；客户端会自动追加 `/runner` 和 `/client`。

```ts
const intelligence = new CopilotKitIntelligence({
  apiUrl: "https://api.intelligence.internal",
  wsUrl: "wss://realtime.intelligence.internal",
  apiKey: process.env.CPK_INTELLIGENCE_API_KEY!,
});
```

</Tab>
<Tab value="Python">

在 `RuntimeConfig` 上设置全部三个 URL。runner 与浏览器 URL 包含不同的后缀：

```python
config = RuntimeConfig(
    api_key=os.environ["CPK_INTELLIGENCE_API_KEY"],
    api_url="https://api.intelligence.internal",
    runner_url="wss://realtime.intelligence.internal/runner",
    client_url="wss://realtime.intelligence.internal/client",
    base_path="/api/copilotkit",
    allowed_origins=("http://localhost:3000",),
)
```

将 `config` 传给 `IntelligenceRuntime`，以替代云托管配置。

</Tab>
<Tab value="Go">

在现有的 `copilotkit.Config` 中添加这些字段：

```go
APIURL:    "https://api.intelligence.internal",
RunnerURL: "wss://realtime.intelligence.internal/runner",
ClientURL: "wss://realtime.intelligence.internal/client",
```

</Tab>
<Tab value="Ruby">

在 `CopilotKit::Runtime.new` 中添加这些关键字参数：

```ruby
api_url: 'https://api.intelligence.internal',
runner_url: 'wss://realtime.intelligence.internal/runner',
client_url: 'wss://realtime.intelligence.internal/client',
```

</Tab>
<Tab value="C#/.NET">

在现有的 `RuntimeOptions` 中添加这些属性：

```csharp
ApiUrl = new Uri("https://api.intelligence.internal"),
RunnerUrl = new Uri("wss://realtime.intelligence.internal/runner"),
ClientUrl = new Uri("wss://realtime.intelligence.internal/client"),
```

</Tab>
</Tabs>

不要在 API 主机后追加 `/api`，也不要在任一 WebSocket URL 后追加 `/websocket`。客户端会自行添加这些路径段。只设置部分端点可能导致请求在你的部署与云托管 Intelligence 之间被拆分。

安装步骤参见[在 Kubernetes 上自托管](/intelligence/self-hosting)和[在 ECS 上自托管](/intelligence/self-hosting-ecs)。

## 故障排查

<Accordions>
  <Accordion title="对话正常，但项目中没有线程">
    在 TypeScript 中，检查 `intelligence` 是否已传给 `CopilotRuntime`；否则它会停留在 SSE 模式。其他运行时没有仅 SSE 的回退。请检查它们的服务端诊断信息和 Intelligence 端点设置。
  </Accordion>
  <Accordion title="首个请求出现身份验证错误">
    `CPK_INTELLIGENCE_API_KEY` 为空，或属于另一个项目。
  </Accordion>
  <Accordion title="套接字一直处于 connecting，然后报告未能在时限内就绪">
    检查上方自托管设置中的每个端点。实时（realtime）主机与 API 主机不同。原生运行时需要单独的 `/runner` 和 `/client` URL；TypeScript 则使用裸的 `wsUrl`。
  </Accordion>
  <Accordion title="请求日志中出现 /api/api/...">
    `apiUrl` 中包含了 `/api` 后缀。
  </Accordion>
  <Accordion title="出现类型错误或提及 runner 的抛错">
    这是 TypeScript 配置错误：同时设置了 `runner` 和 `intelligence`。Intelligence 会自行接线自己的 runner。
  </Accordion>
</Accordions>
