## 概览

技能分发让智能体无需再次执行 CLI 下载或重启进程，即可使用来自一个或多个 Learning 容器的已发布技能。框架适配器会添加一份按字母排序的目录和两个工具。

由模型决定何时加载并遵循某个技能。

开发者的指令始终具有最高优先级。技能无法覆盖智能体的角色、安全规则、工具限制或应用策略。

<Callout type="info">
  从[自动学习](/learning)开始，收集线程、配置每日运行并审核技能。连接适配器之前，请检查容器的 **Skills** 标签页中是否已启用 **Skill delivery**。如需引导式配置，请在该处选择 **Set up skill delivery**，并将提示复制到你的编码智能体中。
</Callout>

## 开始之前

Intelligence SDK 适配器会自动将已发布的技能加载到你的智能体中。它们会添加一份目录以及一些在运行期间读取技能指令的工具。

在运行示例之前，请完成以下步骤：

1. 在你的 Intelligence 项目中创建一个 Learning 容器。
2. 发布一个技能，并在容器的 **Skills** 标签页中启用 **Skill delivery**。
3. 使用项目密钥和 Learning 容器 ID 配置智能体。

对于单个容器，你可以**在代码中或通过环境变量**设置容器与修订版。下面的示例展示的是代码参数。若想改用环境变量，请从代码中省略相应参数。两种方式可以混用：代码中的显式取值会覆盖对应的环境变量。

例如，下面这份环境配置提供了项目密钥和容器：

```bash title="智能体服务器环境"
export CPK_INTELLIGENCE_API_KEY="your-project-key"
export CPK_INTELLIGENCE_LEARNING_CONTAINER_ID="support-learning"
# 自托管 Intelligence 还需设置 INTELLIGENCE_API_URL。
```

模型提供方的凭据需单独设置。将模型占位符替换为你已配置的模型，并在框架要求时安装相应的提供方包。

若要跟随最新发布的技能，请在代码中省略 revision 参数，并保持 `CPK_INTELLIGENCE_SKILLS_REVISION` 未设置。精确修订版锁定请参见[容器配置](#配置单个容器)。

技能分发不会把原生智能体运行发送到自动学习。若要收集新证据，还请[将你的 Runtime 线程分配给某个容器](/learning#assign-threads-from-your-runtime)。

## 选择适配器

| 框架 | 包 | 原生扩展 |
| --- | --- | --- |
| [BuiltInAgent](#builtinagent) | `@copilotkit/runtime/v2` | `learnedSkills` 配置 |
| [LangGraph Python](#langgraph-python) | `copilotkit-intelligence-langgraph` | `create_skill_registry_middleware` |
| [LangGraph TypeScript](#langgraph-typescript) | `@copilotkit/intelligence-langgraph` | `createSkillRegistryMiddleware` |
| [Mastra](#mastra) | `@copilotkit/intelligence-mastra` | `createSkillRegistryProcessor` |

| [Microsoft Agent Framework](#microsoft-agent-framework) | `CopilotKit.Intelligence.AgentFramework` | `SkillRegistryContextProvider` 与 `AddCopilotKitIntelligenceSkills` |

将适配器挂载到需要技能的智能体上。适配器不会检查或重建任意的图结构或智能体层级。子智能体的行为遵循所选框架。

TypeScript 使用来自 `@copilotkit/runtime/v2` 的规范客户端。Python 使用 `copilotkit-intelligence-runtime`。这些依赖包含技能分发之外的 Runtime 功能。.NET 适配器面向 `net9.0`，并使用 `CopilotKit.Intelligence`。

## 原生设置

这些适配器需要下述版本的服务端与规范客户端。

每个示例都展示了可选的修订版锁定。请将 `"exact-revision-id"` 替换为已发布的修订版 ID，或者移除该参数以使用环境变量回退。如果代码和环境都未指定修订版，适配器将跟随最新发布的技能。SDK 不支持将 `"auto"` 作为特殊取值。

### BuiltInAgent

直接在 `BuiltInAgent` 上配置 `learnedSkills`。无需包装器或单独的适配器包。

在下方代码中设置容器与修订版，**或者**省略这些参数并使用[环境变量](#配置单个容器)。代码取值优先。

```typescript
import { BuiltInAgent } from "@copilotkit/runtime/v2";

const agent = new BuiltInAgent({
  model: "openai/gpt-4o",
  prompt: "Follow the application's support policy.",
  learnedSkills: {
    // Set these here, or omit them to use environment variables (linked above).
    containerId: "support-learning",
    revision: "exact-revision-id", // Optional: pin a published revision.
  },
});
```

`CPK_INTELLIGENCE_API_KEY` 用于技能分发，模型提供方的密钥需单独设置。该配置还支持将现有的 `CopilotKitIntelligence` 实例作为 `client` 传入，或者显式提供 `apiKey` 与 `apiUrl`。这些凭据作用于 Intelligence，而非模型提供方。下述的环境变量回退与刷新设置同样适用。

经典模式会在模型调用之前添加目录和两个可执行的技能工具。当有技能可用时，默认步骤上限为 10，以便模型加载并使用这些指导。显式设置的 `maxSteps` 优先。在没有可用技能时，既有的默认步骤上限保持不变。

#### 工厂模式

BuiltInAgent 会在调用你的工厂函数之前获取快照。请将目录和工具接入你的模型调用：

在下方代码中设置容器与修订版，**或者**省略这些参数并使用[环境变量](#配置单个容器)。代码取值优先。

```typescript
import {
  BuiltInAgent,
  convertMessagesToVercelAISDKMessages,
} from "@copilotkit/runtime/v2";
import { openai } from "@ai-sdk/openai";
import { stepCountIs, streamText } from "ai";

const agent = new BuiltInAgent({
  type: "aisdk",
  learnedSkills: {
    // Set these here, or omit them to use environment variables (linked above).
    containerId: "support-learning",
    revision: "exact-revision-id", // Optional: pin a published revision.
  },
  factory: ({ input, abortSignal, learnedSkills }) =>
    streamText({
      model: openai("gpt-4o"),
      system: [
        "Follow the application's support policy.",
        learnedSkills.catalog,
      ].filter(Boolean).join("\n\n"),
      messages: convertMessagesToVercelAISDKMessages(input.messages),
      tools: { ...learnedSkills.tools },
      stopWhen: stepCountIs(10),
      abortSignal,
    }),
});
```

从 `@copilotkit/runtime/v2` 导入 `BuiltInAgentFactoryContext` 可为工厂上下文添加类型标注。每个工厂都会收到一个 `learnedSkills` 对象。当分发未配置或经验证的快照中不含技能时，其 `catalog` 为 `""`、`tools` 为 `{}`。省略该配置会禁用所有技能请求，即使分发相关的环境变量存在也一样。配置之后，后续运行会按新鲜度窗口检查新发布的技能。

这些工具使用 AI SDK 的 schema 和执行器。TanStack 与自定义工厂收到的是同一个对象，必须将这些工具适配到各自的模型库；它们并不是 TanStack 原生的工具定义。工厂代码负责模型调用及其步骤上限。请在该次调用中一并使用所提供的目录和工具。工具映射是只读的；请将其展开到新对象中以添加应用工具。

每次运行（包括恢复运行）都会在工厂或模型工作开始前获取一份快照。智能体克隆共享刷新缓存；每次调用保留各自的快照。取消操作只会终止该次调用的分发等待，不会取消其他克隆共享的刷新。快照不会进入应用状态。已缓存的技能可以应对瞬时故障，但一旦确认分发被拒，就会阻止新的执行。

请将 `copilotkit_load_skill` 和 `copilotkit_read_skill_file` 保留给分发使用。经典模式会拒绝与之冲突的客户端、配置或 MCP 工具名称。工厂代码在合并工具映射时必须避免覆盖这些名称。

### LangGraph Python

使用 Python 3.11 或更高版本，并配合来自 `langchain.agents.create_agent` 的原生异步智能体。

```bash
pip install copilotkit-intelligence-langgraph
```

在下方代码中设置容器与修订版，**或者**省略这些参数并使用[环境变量](#配置单个容器)。代码取值优先。

```python
import asyncio

from copilotkit_intelligence_langgraph import create_skill_registry_middleware
from langchain.agents import create_agent


async def main():
    skills = create_skill_registry_middleware(
        # Set these here, or omit them to use environment variables (linked above).
        container_id="support-learning",
        revision="exact-revision-id",  # Optional: pin a published revision.
    )  # Uses the environment above for the project key.
    try:
        await skills.initialize()
        agent = create_agent(
            "your-provider:your-model",
            system_prompt="Follow the application's support policy.",
            middleware=[skills],
        )
        result = await agent.ainvoke(
            {"messages": [{"role": "user", "content": "Help with a refund"}]}
        )
        print(result["messages"][-1].content)
    finally:
        await skills.aclose()


asyncio.run(main())
```

请使用 `ainvoke` 或 `astream`；不支持同步执行。该适配器支持 LangChain `>=1.2.16,<2` 与 LangGraph `>=1.1.10,<2`。请将中间件显式挂载到每个需要技能的智能体上。任意的已编译图不在本集成范围内。

### LangGraph TypeScript

使用 Node.js 20.19 或更高版本，并配合原生 LangChain 智能体。

```bash title="终端"
npm install @copilotkit/intelligence-langgraph langchain @langchain/core @langchain/langgraph zod
npm install --save-dev tsx
```

将此示例保存为 `agent.mts`，然后用 `npx tsx agent.mts` 运行：

在下方代码中设置容器与修订版，**或者**省略这些参数并使用[环境变量](#配置单个容器)。代码取值优先。

```typescript
import { createAgent } from "langchain";
import {
  SkillRegistry,
  createSkillRegistryMiddleware,
} from "@copilotkit/intelligence-langgraph";

const registry = new SkillRegistry({
  // Set these here, or omit them to use environment variables (linked above).
  containerId: "support-learning",
  revision: "exact-revision-id", // Optional: pin a published revision.
}); // Uses the environment above for the project key.
await registry.initialize(); // Catch this error in your application's startup code.
const skills = createSkillRegistryMiddleware({ registry });
const agent = skills.wrapAgent(
  createAgent({
    model: "your-provider:your-model",
    systemPrompt: "Follow the application's support policy.",
    middleware: [skills],
  }),
);
const result = await agent.invoke({
  messages: [{ role: "user", content: "Help with a refund" }],
});
console.log(result.messages.at(-1)?.content);
```

目前必须使用包装器，因为受影响的 LangChain/LangGraph 版本无法正确保存私有的瞬态中间件状态。请在 `invoke`、`stream` 和 `streamEvents` 中使用包装后的智能体，包括原生的 `Command` 恢复。`withConfig` 会保留包装器。可在包装之后通过 `agent.withConfig` 应用默认取消信号，或将信号传入每次调用。流对象、读取器和原生取消机制仍然可用。在没有包装器的情况下调用中间件会返回 `INVALID_CONFIG`。

待原生框架修复通过相同的生命周期测试后，仅中间件的配置方式将成为默认。包装器将变为可选，已包装的现有智能体仍可继续工作。

请将该中间件及其包装器挂载到每个选定的智能体上。多个智能体可以共享一个注册表，但每次包装后的调用都会捕获各自的快照。技能不会自动传播到任意的子智能体。对于访问 `.graph` 的集成，包装器支持原生智能体的图执行入口；图批处理以及任意已编译图的适配不在本集成范围内。

支持的依赖版本范围为 LangChain `>=1.5.11,<2`、LangGraph `>=1.4.14,<2` 和 LangChain core `>=1.2.10,<2`。注册表持有内存中的快照，不执行任何文件系统写入。注入的规范客户端仍由你的应用持有。

### Mastra

使用 Node.js 22.13 或更高版本，并配合 `@mastra/core>=1.0.0,<2`。

```bash title="终端"
npm install @copilotkit/intelligence-mastra @mastra/core zod
npm install --save-dev tsx
```

将此示例保存为 `agent.mts`，然后用 `npx tsx agent.mts` 运行。在原生 `Agent` 上注册该处理器及其工具：

在下方代码中设置容器与修订版，**或者**省略这些参数并使用[环境变量](#配置单个容器)。代码取值优先。

```typescript
import { Agent } from "@mastra/core/agent";
import {
  SkillRegistry,
  createSkillRegistryProcessor,
} from "@copilotkit/intelligence-mastra";

const registry = new SkillRegistry({
  // Set these here, or omit them to use environment variables (linked above).
  containerId: "support-learning",
  revision: "exact-revision-id", // Optional: pin a published revision.
}); // Uses the environment above for the project key.
await registry.initialize(); // Catch this error in your application's startup code.
const skills = createSkillRegistryProcessor({ registry });
const agent = skills.wrapAgent(
  new Agent({
    id: "support",
    name: "Support",
    model: "openai/gpt-4.1",
    instructions: "Follow the application's support policy.",
    inputProcessors: [skills],
    tools: { ...skills.tools },
  }),
);
const result = await agent.generate("Help with a refund.");
```

其他处理器和工具保留在原来的数组和映射中即可。请将 `copilotkit_load_skill` 和 `copilotkit_read_skill_file` 这两个名称保留给该适配器。

请通过包装后的智能体调用 `generate`、`stream`、`resumeGenerate` 和 `resumeStream`。包装器会在原生执行之前检查分发，并保留 Mastra 的流式结果。当你安装的 Mastra 版本提供了原生工具批准与拒绝方法时，包装器也会一并覆盖：`approveToolCall`、`declineToolCall`、`approveToolCallGenerate` 和 `declineToolCallGenerate`。恢复操作会开启一次新调用并捕获当前经过验证的快照，包括在下次模型调用之前有工具运行的情况。

注册处理器和工具，并包装每个选定的智能体。多个智能体可以共享一个注册表；每次调用保留各自的快照。子智能体遵循 Mastra 的原生传播规则。网络（networks）、旧版方法、后台工作进程以及独立的持久化工作进程分发不在本集成范围内。

在调用选项中传入 `abortSignal` 即可同时取消分发等待和原生执行。仅在智能体的 `defaultOptions` 中设置信号时，该信号作用于原生执行，但无法取消先于其运行的分发等待。取消某一次调用并不会取消与其他调用方共享的注册表刷新。

### Google ADK

使用 Python 3.11 或更高版本，并将 `SkillToolset` 添加到标准的 ADK `LlmAgent` 中。

```bash
pip install copilotkit-intelligence-adk
```

在下方代码中设置容器与修订版，**或者**省略这些参数并使用[环境变量](#配置单个容器)。代码取值优先。

```python
import asyncio

from copilotkit_intelligence_adk import SkillRegistry, SkillToolset
from google.adk.agents import LlmAgent
from google.adk.runners import Runner
from google.adk.sessions import InMemorySessionService
from google.genai import types


async def main():
    registry = SkillRegistry(
        # Set these here, or omit them to use environment variables (linked above).
        container_id="support-learning",
        revision="exact-revision-id",  # Optional: pin a published revision.
    )
    try:
        await registry.initialize()
        agent = LlmAgent(
            name="support",
            model="your-model",
            instruction="Follow the application's support policy.",
            tools=[SkillToolset(registry)],
        )
        sessions = InMemorySessionService()
        session = await sessions.create_session(app_name="support", user_id="demo")
        runner = Runner(agent=agent, app_name="support", session_service=sessions)
        message = types.Content(
            role="user", parts=[types.Part(text="Help with a refund.")]
        )
        async for event in runner.run_async(
            user_id="demo", session_id=session.id, new_message=message
        ):
            if event.is_final_response() and event.content:
                for part in event.content.parts or []:
                    if part.text:
                        print(part.text)
    finally:
        await registry.aclose()


asyncio.run(main())
```

该适配器支持 `google-adk>=1.17,<2`。多个选定的智能体可以共享一个注册表。关闭某个工具集并不会关闭共享的注册表。原生恢复的运行会获得新的调用标识；会话状态中不包含快照或锁。

### Microsoft Agent Framework

使用该提供方的原生智能体工厂，并配合你应用的 `IChatClient`：

在下方代码中设置容器与修订版，**或者**省略这些参数并使用[环境变量](#配置单个容器)。代码取值优先。

```csharp
using CopilotKit.Intelligence.AgentFramework;
using Microsoft.Agents.AI;

using var skills = new SkillRegistryContextProvider(new SkillRegistryOptions
{
    // Set these here, or omit them to use environment variables (linked above).
    ContainerId = "support-learning",
    Revision = "exact-revision-id", // Optional: pin a published revision.
});
await skills.InitializeAsync();
var agent = skills.CreateAgent(chatClient, new ChatClientAgentOptions
{
    Name = "support",
    ChatOptions = new() { Instructions = "Follow the application's support policy." }
});

```

该适配器面向 .NET 9 和 Agent Framework `>=1.0.0,<2.0.0`。`AddCopilotKitIntelligenceSkills` 还会通过依赖注入注册一个键控提供方和原生智能体。若要获得完整的调用检查，请使用此扩展方法或 `CreateAgent`。后台响应和继续令牌不受支持，因为框架在执行这些调用时会绕过上下文提供方。

## 配置多个容器

使用 `containers` 可以在同一项目中组合来自多个 Learning 容器的技能。
每个条目包含一个 `id` 和一个可选的 `revision` 锁定。
未指定修订版的条目将跟随该容器最新发布的技能。

BuiltInAgent 在 `learnedSkills` 中接受这份列表：

```typescript
const agent = new BuiltInAgent({
  model: "openai/gpt-4o",
  learnedSkills: {
    containers: [
      { id: "support", revision: "revision-123" },
      { id: "company-wide" },
    ],
  },
});
```

Mastra 与 LangGraph TypeScript 在 `SkillRegistry` 中接受同样的列表：

```typescript
const registry = new SkillRegistry({
  containers: [
    { id: "support", revision: "revision-123" },
    { id: "company-wide" },
  ],
});
await registry.initialize();
```

LangGraph Python 在其中间件工厂中接受这份列表：

```python
skills = create_skill_registry_middleware(
    containers=[
        {"id": "support", "revision": "revision-123"},
        {"id": "company-wide"},
    ],
)
```

Google ADK 在 `SkillRegistry(containers=[...])` 中接受同样的 Python 列表。
对于 Microsoft Agent Framework，请使用带类型的容器条目：

```csharp
var options = new SkillRegistryOptions
{
    Containers = new[]
    {
        new SkillContainerSource { Id = "support", Revision = "revision-123" },
        new SkillContainerSource { Id = "company-wide" },
    },
};
```

列表必须包含 1–50 个条目，且 ID 唯一、非空。
凭据、超时和新鲜度窗口适用于每个条目。
所有选定的容器都必须属于客户端密钥所标识的项目。

不要将 `containers` 与旧的 `containerId` 或顶层 `revision` 字段组合使用。
SDK 会拒绝这种组合，包括对应的 Python 和 .NET 字段。
TypeScript 还会在编译期拒绝这种组合。

显式的 `containers` 列表会忽略 `CPK_INTELLIGENCE_LEARNING_CONTAINER_ID` 和 `CPK_INTELLIGENCE_SKILLS_REVISION`。
连接类的环境变量仍然生效。
[单容器接口](#配置单个容器)及其环境变量默认值保持不变，继续受支持。

### 多容器单次请求

对于所有需要刷新的容器，SDK 会发送一个批量请求。
每个条目包含其容器 ID、可选的修订版锁定和缓存的 ETag。
响应会为每个容器携带一个快照、一个未变更结果或一个错误。
缓存仍然新鲜的容器无需请求。
即使显式的 `containers` 列表只含一个条目，也会使用该端点。

新接口要求 Intelligence 服务端支持 `POST /api/v1/learning/skills/batch`。
对于自托管的 Intelligence，请先更新服务端再启用 `containers`。
在较旧的服务端上，SDK 不会回退为分开的单独请求。
原有的单容器接口继续沿用其现有端点。

### 技能名称与失败

新接口会为每个技能名称加上其容器 ID 前缀，即使列表中只有一个条目也不例外。
例如，`support/refund-policy` 和 `company-wide/refund-policy` 仍是两个独立的技能。
SDK 会对该前缀中的容器 ID 进行 URI 编码。
工具调用使用目录中的确切名称。
旧接口则保留原始的不带前缀名称。

每个容器维护各自的修订版、缓存和刷新状态。
调用会在模型工作开始前捕获完整的合并目录。
即使之后发生刷新，该调用在其所有工具调用中仍使用这些技能。

如果任何一个容器无法加载其首个快照，调用就会失败。
已预热的容器在瞬时故障后可以继续使用其缓存的技能。
确认的访问拒绝或已被撤销的修订版会阻止整个调用。
SDK 绝不会悄悄地只提供所选目录的一部分。

对于新接口，`status.containers` 中的每个条目都会报告其容器的修订版和刷新状态。
.NET 通过 `MultiSkillRegistryStatus.Containers` 暴露这些条目。
聚合状态没有可锁定的服务端修订版。
只有当每个容器都有修订版锁定时，其模式才为 `pinned`。

## 配置单个容器

原有接口选择一个 Learning 容器。如上所示，在 TypeScript 中设置 `containerId`，在 Python 中设置 `container_id`，或在 .NET 中设置 `ContainerId`。BuiltInAgent 使用 `learnedSkills.containerId`。

单数字段只接受一个稳定的容器 ID。若要组合多个容器，请使用上文单独的 `containers` 接口。多个智能体可以共享一个注册表。

注入的规范 Intelligence 客户端会提供其现有的项目密钥、端点和 HTTP 生命周期。该客户端仍由你的应用持有。适配器不会构建第二个经过身份验证的传输层。

基于环境变量的配置使用以下变量。`npx copilotkit@latest project select` 会写入项目密钥。如果 CLI 尚无会话，请先运行 `npx copilotkit@latest login`。如果智能体服务器位于其他目录，请将该密钥复制到对应环境中。

```bash
CPK_INTELLIGENCE_API_KEY=cpk-...
CPK_INTELLIGENCE_LEARNING_CONTAINER_ID=expense-review
# 仅限自托管部署：
INTELLIGENCE_API_URL=https://intelligence.example.com
# 可选的精确修订版；省略则跟随最新：
CPK_INTELLIGENCE_SKILLS_REVISION=42
```

显式配置会覆盖环境变量的取值。注入的客户端会覆盖连接类的环境变量。新鲜度和请求超时默认均为 5 秒；调试日志默认关闭。这些行为选项请在代码中配置。

初始化可以在应用启动期间进行。有效但为空的容器也能成功完成初始化。初始化失败可被捕获并重试；适配器绝不会终止进程。在存在经过验证的快照之前，模型工作无法开始。

### 复用 Intelligence SDK 客户端

如果你的服务端已经创建了 Intelligence 客户端，请将该客户端传给注册表，从而复用其项目密钥和端点。

在下方代码中设置容器与修订版，**或者**省略这些参数并使用[环境变量](#配置单个容器)。代码取值优先。

```typescript
import { CopilotKitIntelligence } from "@copilotkit/runtime/v2";
import { SkillRegistry } from "@copilotkit/intelligence-mastra";

const intelligence = new CopilotKitIntelligence({
  apiKey: process.env.CPK_INTELLIGENCE_API_KEY!,
  apiUrl: process.env.INTELLIGENCE_API_URL,
});
const registry = new SkillRegistry({
  client: intelligence,
  // Set these here, or omit them to use environment variables (linked above).
  containerId: "support-learning",
  revision: "exact-revision-id", // Optional: pin a published revision.
});
await registry.initialize();
```

对于 LangGraph TypeScript，请从 `@copilotkit/intelligence-langgraph` 导入 `SkillRegistry` 并使用相同的配置。然后将该注册表传给上文展示的框架适配器。

## 确认分发正常工作

对于框架适配器，此项检查要求自动更新。请从示例中移除 `revision`（.NET 中为 `Revision`），并取消设置 `CPK_INTELLIGENCE_SKILLS_REVISION`。已锁定修订版的适配器在你发布更新的修订版后，仍会继续使用其选定的修订版。

1. 在容器中存在已发布技能的情况下初始化适配器。从适配器的状态中记录已加载的修订版。
2. 用与该技能相关的请求开启一次新调用。
3. 检查模型的工具调用中是否出现 `copilotkit_load_skill`，必要时还有 `copilotkit_read_skill_file`。
4. 发布一个新修订版，等待超过新鲜度窗口，然后再开启一次调用。
5. 确认适配器状态中已加载的修订版已变更为新发布的修订版。

对于原有的单容器接口，可在 TypeScript 中读取 `registry.status.revision`，LangGraph Python 读取 `skills.status.revision`，ADK 读取 `registry.status.revision`，.NET 读取 `skills.Status.Revision`。BuiltInAgent 不暴露公开的注册表状态；请在工具结果中检查已加载技能的内容，确认其中包含你发布的更改。有效但为空的容器也能成功初始化，因此仅有初始化成功并不能证明技能存在。

是否调用技能工具由模型决定。一次没有调用技能工具的运行并不能证明分发失败。也请检查目录和注册表状态。

## 刷新与调用行为

在每次调用之前，注册表会为每个选定的容器评估新鲜度窗口。当检查到期时，该调用会等待检查完成。使用 `containers` 时，并发调用会为到期需要刷新的容器共享一个批量请求，内部不做重试。未变更的响应会重置新鲜度窗口，且不会再次传输 ZIP。

每次调用都会为它的模型调用和工具调用保留一份完整快照。之后的刷新只影响之后的调用。修订版标识符是不透明的：请原样传递该字符串，不要解析、递增或按数值比较。

| 模式 | 行为 |
| --- | --- |
| `latest` | 检查成功后采用最新的完整已发布快照。 |
| 精确修订版 | 在持续进行授权与撤销检查的同时，保留所选的完整技能集。 |

已发布的修订版不会自动过期。适配器一旦收到撤销通知，新的调用就无法再使用该被撤销的修订版。正在进行中的调用会用其捕获的快照完成执行。

## 读取工具

框架适配器即使在快照为空时也会保持这两个工具处于注册状态。BuiltInAgent 在快照为空时会省略这两个工具；其工厂收到 `tools: {}`。当有可用技能时，这两个工具为：

- `copilotkit_load_skill(skill_name)` 返回 `SKILL.md` 及其配套文件列表。
- `copilotkit_read_skill_file(skill_name, path)` 返回一个配套的 UTF-8 文本文件。

查找会与该调用的清单进行匹配。未知名称、未知路径和不受支持的内容会按框架的工具错误行为处理。适配器绝不会执行脚本或将技能文件写入磁盘。

## 失败与状态

冷启动的注册表在无法加载有效快照时会返回带类型的错误。加载成功后，网络故障、超时、服务端不可用或替换内容不可读都会保留上一个快照并将其标记为陈旧。

陈旧状态没有最长时限。网络隔离的进程可以保留其最后一个经过验证的快照，直到连接恢复。重启会清除该内存快照。经确认的身份验证、授权、权益、分发被禁用或修订版被撤销都会阻止新的调用，而不会回退到陈旧内容。

只读状态包含 `initialized`、`revision`、`mode`、`lastCheckedAt`、`stale` 和 `lastError`。错误会暴露稳定的 `code`、安全的 `message`、`retryable` 和 `cause`。调试模式使用对应语言的常规日志器，且不会包含凭据、提示、技能正文和文件内容。

## 从下载技能迁移

为同一容器启用适配器时，请移除旧的手动 Learning 目录接线。不相关的静态技能或手工编写的技能可按需保留。适配器不会扫描、修改或删除已下载的文件。

`copilotkit skills download` 仍受支持，可用于检查、离线使用以及没有适配器的框架。
传入多个容器 ID 即可一起下载：

```bash
copilotkit skills download support company-wide --output ./skills
```

该命令会将每个容器写入各自的目录下，例如 `./skills/support/refund-policy/SKILL.md`。
只有在所有包都通过校验之后，才会创建目标位置。
目标位置不能已存在。
单个容器保持原有的扁平输出结构，例如 `./skills/refund-policy/SKILL.md`。
手动工作流请参见[自动学习指南](/learning)。

## 部署要求

云托管与自托管的 Intelligence 使用相同的分发契约。适配器依赖的服务端迁移和 v1 分发端点必须先行部署。每个适配器还要求已发布的规范客户端版本中包含习得快照操作。

暂停新的学习运行并不会停止分发。权益、显式禁用分发和修订版撤销分别控制对已发布快照的访问。
