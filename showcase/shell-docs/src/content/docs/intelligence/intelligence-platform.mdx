## Runtime 与平台的角色

一个 CopilotKit 应用包含三层：

- **前端。** 你的应用使用 CopilotKit 前端 SDK 来渲染聊天、生成式 UI、工具和线程控件。
- **Runtime。** 你的应用服务器承载 CopilotKit runtime，并通过 AG-UI 连接到你的智能体框架。
- **CopilotKit Intelligence。** 存储线程、提供项目 API 并支撑 Web 应用的平台服务。

runtime 是桥梁。它接收来自应用的请求，与你的智能体之间双向流式传输 AG-UI 事件，并在某项能力需要持久化的平台状态时使用 CopilotKit Intelligence。

## 项目边界

平台通过三个概念来划分数据范围：

- **组织（Organization）。** 计费与工作区的边界。
- **项目（Project）。** 组织内的一个应用或环境，例如生产、预发（staging）或演示。
- **用户（User）。** 来自你应用的已登录人员。

项目 API 密钥按项目签发。线程、事件和仪表盘历史只在拥有它们的项目内可见，因此生产与预发环境可以共享同一个平台部署，而互不共享会话数据。

## 线程

线程是某个用户在某个项目中保存下来的对话。产品介绍请阅读 [AG-UI Streams](/AG-UI-Streams)。回放与同步机制请阅读[线程是如何保存的](/intelligence/threads-explained)。

## 实时同步

实时同步让线程元数据和活动会话状态在各客户端之间保持一致。启用后，客户端会订阅由平台支持的更新，因此重命名、归档、活动运行状态等变化无需刷新页面即可呈现。

重要的应用层约定很简单：你的应用使用相同的前端 API，而 runtime 指向所选部署形态对应的平台端点。

## 检查

在[云托管项目](/intelligence/managed-intelligence-platform#get-started)中打开一条已存储的线程。API 密钥与套餐信息见 [Cloud-hosted](/intelligence/managed-intelligence-platform) 和 [套餐](/intelligence/plans)。

## 托管模式

云托管与自托管的 CopilotKit Intelligence 共享相同的应用契约：

| 部署形态 | 有何变化 | 保持不变的部分 |
|---|---|---|
| 云托管 | CopilotKit 运行平台、数据库、Web 应用、项目 API 密钥和套餐管理。 | 你的前端 API、runtime API、AG-UI 智能体连接和线程 API。 |
| 自托管 | 你在自己的 Kubernetes 集群中运行平台，并拥有其基础设施依赖。 | 你的前端 API、runtime API、AG-UI 智能体连接和线程 API。 |

自托管改变的只是平台的运营方，前端集成保持不变。从云托管切换到自托管需要 Team Self-hosted 套餐或 Enterprise 套餐。参见[套餐](/intelligence/plans)。

## 错误处理模型

由平台支撑的特性就是依赖网络的特性。如果平台端点不可用或凭据无效，线程操作会以运行时错误的形式暴露出来，而不是静默回退到仅本地的状态。

常见的排查要点：

- 确认 runtime 使用的平台 URL 与所选部署形态相匹配。
- 确认 runtime API 密钥或许可证对该项目或自托管环境有效。
- 确认你从应用传递的用户与项目上下文，与你期望看到的线程历史相匹配。
- 如果你期望跨标签页或跨设备的更新，确认实时同步已配置。
