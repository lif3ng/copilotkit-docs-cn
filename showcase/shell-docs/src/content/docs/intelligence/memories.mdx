## 什么是记忆？

记忆是关于某个用户或项目的简短而持久的一条陈述，存储在任何单个线程之外。“偏好简洁的状态更新”是一条记忆。揭示这一偏好的四十条消息则是一个线程。

这一区分很重要，因为两者的生命周期不同。对话结束，线程也就结束了；而记忆则被设计为比线程更长久，并被召回到尚未发生的对话中。

记忆以文本加向量嵌入的形式存储，因此召回是语义层面的，而不是关键词匹配。查询“这位用户喜欢怎样的更新”可以召回“偏好简洁的状态更新”，两者可以没有一个共同词。

## 核心概念

### 三种类型

每条记忆都属于三种类型之一。类型由保存者提供，绝不会被推断。

| 类型 | 内容 |
|------|------|
| `topical` | 关于主题的持久事实，与它被习得的时间无关。 |
| `episodic` | 发生过的某件事，锚定于某个场合。 |
| `operational` | 关于如何表现的偏好或工作指令。 |

类型不只是装饰。去重和取代都是同类型操作，因此文本完全相同的一条 `topical` 事实和一条 `operational` 偏好是两条记忆，而不是一条。

### 用户与项目范围

记忆可以限定于单个用户，也可以在整个项目内共享。

- **`user`** 是平台默认值。省略 `scope` 即为该值。这是目前唯一通过实时通道分发的范围。
- **`project`** 是共享的，必须显式请求。

范围在每个请求中都会根据调用方的授权强制执行，因此只拥有项目范围只读权限的客户端无法对其进行写入。

### 保存近似重复项会被吸收

如果你保存的内容与同一租户、同一范围、同一类型下某条活跃记忆高度相近，平台不会创建第二行，而是把新内容吸收进现有记忆、合并来源线程，并刷新新近度。

保存操作仍然成功，且结果会告诉你发生了哪种情况，因此 UI 或智能体可以明确表示“已吸收进现有记忆”，而不是暗示写入了新内容。

### 更新是整体替换，而非补丁

更新记忆会取代它：旧记忆被退役，并创建一条带新 `id` 的新记忆。你提交的变更集就是新记忆的完整定义。

<Callout type="warn">
在更新时省略 `sourceThreadIds` 并不会保留原值，而是会把新记忆的来源线程重置为空。请重新提交 `content`、`kind` 以及所有你想保留的 `sourceThreadIds`。
</Callout>

### 移除是退役，而非删除

移除记忆会让它退役，而不是彻底抹除。已退役的记忆不会出现在召回结果和默认列表中，但可以通过显式请求已失效的行来再次查看。

## 激活记忆

<Callout type="info">
记忆不是一个功能开关。不存在 `MEMORY_ENABLED` 环境变量，也不存在 `memory.enabled` Helm 配置值。访问由权益授予，嵌入器则在启动时单独配置。
</Callout>

在调用方能够使用记忆之前，必须同时满足两个相互独立的条件：

1. 该部署或组织拥有记忆的**权益**。
2. app-api 具有有效的**嵌入器配置**。

权益解析采用默认拒绝策略。未能解析的权益、处于非激活状态的权益或依赖服务故障，都会拒绝记忆访问，而不是放行。

### 自托管

已签名的部署许可证是唯一依据。当许可证包含 `memory` 特性时记忆才可用，该特性目前随 enterprise 计划提供。如果你的许可证不包含它，再多配置也无法挂载这些界面，正确的下一步是与我们沟通许可证问题，而不是继续修改 values 文件。

嵌入器通过以下变量配置，chart 会为你在模板中生成它们：

| 变量 | 用途 |
|------|------|
| `MEMORY_EMBEDDINGS_URL` | OpenAI 兼容嵌入端点的基础 URL。必填。 |
| `MEMORY_EMBEDDING_MODEL` | 发送给该端点的嵌入模型 id。必填。 |
| `MEMORY_EMBEDDINGS_API_KEY` | 可选的 Bearer 令牌。使用内置集群内嵌入器时请留空。 |
| `MEMORY_EMBEDDINGS_DIMENSIONS` | 可选。必须为 `1024`，因为存储的是 1024 维半精度向量。 |

部署之前值得了解的两个后果：

- 如果必需变量缺失或无效，**app-api 会拒绝启动**。
  这是有意为之。权益可能在进程运行期间发生变化，因此绝不能出现记忆路由存在而背后却没有嵌入器的情况。
- **数据库服务器上必须安装 pgvector**。创建记忆表的迁移同时会创建该扩展，缺少它时迁移任务会失败。

默认情况下，chart 会部署一个集群内的 text-embeddings-inference 工作负载，并让 app-api 指向它。若要改用托管提供方，请设置外部的嵌入 URL 和模型，此时集群内工作负载将不再被渲染：

```yaml title="values.yaml"
embeddings:
  external:
    url: https://api.openai.com
    model: text-embedding-3-small
    dimensions: 1024
    apiKey:
      existingSecret: openai-embeddings
      secretKey: api-key
```

<Callout type="warn">
更改嵌入模型或提供方会改变向量空间。现有记忆是在旧空间中嵌入的，在新空间中无法比较，因此在重新嵌入之前召回质量会下降。请把模型变更当作一次迁移，而不是调整配置。
</Callout>

### 云托管

在云托管 Intelligence 上，记忆按组织解析，依据是该组织的有效权益，即其计划特性与任何企业级覆盖的组合。你这边无需任何配置。

## 按请求限制访问

本节的运行时配置使用 TypeScript API。Python、Go、Ruby 和 C#/.NET 有不同的策略回调；参见[其他运行时语言中的记忆策略](#其他运行时语言中的记忆策略)。

权益决定一个部署是否拥有记忆，`memory.access` 决定单个请求可以用它做什么。它是 Intelligence 运行时上的单一策略，同时约束**两个**记忆界面：智能体在运行期间获得的工具，以及 `useMemories()` 背后的浏览器路由。

<Callout type="warn">
省略 `memory` 选项并不会关闭记忆——而是移除了限制。仅省略该选项时两个界面都处于关闭状态，但任何一个仍可以在没有策略的情况下被开启，届时对每个已通过身份验证的请求，它都会以两个范围均为 `read-write` 的方式运行：

- 启用 `enableEnterpriseLearning` 后，智能体运行会获得全部三个记忆工具，仅受你所在组织权益的限制。
- 已弃用的 `exposeMemoryRoutes: true` 标志会挂载浏览器路由，且背后没有任何策略。

这与 Channels 正好相反：在 Channels 中，运行若不主动请求就没有记忆。只要任一界面开启，就请配置 `memory.access`。
</Callout>

```ts title="runtime.ts"
const runtime = new CopilotRuntime({
  intelligence,
  identifyUser: async (request) => resolveUser(request),
  memory: {
    access: ({ user, consumer }) => {
      // Tenants on the free plan get recall, but record nothing new.
      if (isFreePlan(user)) return { user: "read", project: "none" };

      // The browser inspector is read-only; the agent may write.
      return consumer === "client"
        ? { user: "read", project: "read" }
        : { user: "read-write", project: "read-write" };
    },
  },
});
```

该回调在每个请求中运行一次，在 `identifyUser` 解析完成之后执行，并接收：

| 字段 | 含义 |
|------|------|
| `request` | 传入的 `Request`，当决策需要请求头、Cookie 或路径时使用。 |
| `user` | `identifyUser` 返回的应用用户。 |
| `consumer` | 智能体运行为 `"agent"`，浏览器记忆路由为 `"client"`。 |

返回一个同时指定两个范围的授权（grant），或返回 `null`。每个范围可取 `"none"`、`"read"` 或 `"read-write"`。该策略可以是异步的。

### 每种结果的行为

`null` 与所有范围均为 `"none"` 的授权是同一种结果，而非两种——都表示“此请求无法使用记忆”。代价取决于调用方请求的是什么：

| 策略返回 | 智能体运行 | 浏览器 `/memories/*` |
|----------|-----------|----------------------|
| 任一范围高于 `"none"` 的授权 | 挂载记忆工具，按授权范围过滤 | 请求正常进行 |
| `null`，或所有范围均为 `"none"` | **运行继续进行，但没有记忆工具** | **403** |
| 无返回（`undefined`），或访问级别不在三者之内 | 500 | 500 |
| 抛出错误 | 500 | 500 |

这种不对称是有意为之。对话请求的是记忆之外的东西，因此关闭记忆不能让用户失去助手。浏览器路由的存在只是为了提供记忆，因此“你不能访问记忆”直接回答了实际提出的问题——而返回空列表会错误地暗示记忆不存在。

缺少返回值会被视为策略损坏，而不是限制性策略，因此忘记 `return` 的分支会大声报错，而不是悄悄关闭记忆。

只允许一个范围而不允许另一个范围的授权会被严格执行：`{ user: "read", project: "none" }` 的授权只注册 `recall_memory`（限定于用户记忆），而不注册 `save_memory` 和 `forget_memory`，这样智能体永远不会看到自己无权调用的工具。

<Callout type="info">
`memory.access` 是记忆策略，不是针对请求的授权闸门。要直接拒绝请求，请使用 `beforeRequestMiddleware`，它可以在这一切运行之前就予以拒绝。
</Callout>

### 它同时会挂载浏览器路由

配置 `memory` 会开启 `/memories`、`/memories/recall`、`/memories/subscribe` 和 `/memories/:id`。不配置时，这些路由会返回 404，就像不存在一样，因此未选择启用的部署即使配置了 Intelligence，也不会暴露任何记忆相关信息。

较早的 `exposeMemoryRoutes: true` 标志只做挂载而不带策略，现已被弃用。`memory.access` 取代了它：一个选项既暴露界面，又约束它们能做什么。

### Channels 改为按运行授予记忆

Channel 运行会在 `runAgent` 上携带自己的授权，使用同样的三个访问级别，而不查询 `memory.access`。该路径请参见[身份与记忆](/channels/identity-and-memory)，其中包括如何在群聊对话中选择记忆主体。

### 其他运行时语言中的记忆策略

在[连接你的运行时](/intelligence/quickstart#connect-your-runtime)之后，基于可信的应用策略配置其回调：

| 运行时 | 配置 | 回调入参 |
| ------ | ---- | -------- |
| Python | `IntelligenceRuntime(memory_policy=...)` | 用户，然后是 Starlette 请求 |
| Go | `Config.MemoryAccess` | HTTP 请求，然后是用户 |
| Ruby | `Runtime.new(memory_access: ...)` | 用户，然后是 Rack 环境 |
| C#/.NET | `RuntimeOptions.MemoryGrant` | HTTP 上下文、用户、取消令牌 |

这些回调约束原生运行时的记忆路由。它们并不实现上文描述的 TypeScript `consumer` 回调或其自动的智能体工具注册。每个授权都指定 `user` 和 `project`，取值为 `none`、`read` 或 `read-write`。没有回调时，原生运行时会委托给 Intelligence 的记忆策略；省略它并不会禁用访问。

## 读取与写入记忆

<FrontendOnly frontend="react">
### React

`useMemories()` 返回当前经运行时身份验证用户的、以服务器为准的列表。它先从 REST 快照填充，然后通过实时增量保持最新。

```tsx title="components/memory-list.tsx"
import { useMemories } from "@copilotkit/react-core/v2";

export function MemoryList() {
  const { memories, isLoading, isAvailable, removeMemory } = useMemories();

  if (!isAvailable) return <p>Memory is not available for this runtime.</p>;
  if (isLoading) return <p>Loading memories…</p>;

  return (
    <ul>
      {memories.map((memory) => (
        <li key={memory.id}>
          {memory.content}
          <button type="button" onClick={() => void removeMemory(memory.id)}>
            Forget
          </button>
        </li>
      ))}
    </ul>
  );
}
```

在渲染记忆控件之前请检查 `isAvailable`。当运行时未暴露记忆路由时它会变为 `false`，这正是无权益部署在客户端看起来的样子。

`realtimeStatus` 与 `isAvailable` 相互独立，报告实时连接的健康状况：套接字加入时为 `connecting`，增量开始流动后为 `connected`，彻底放弃后为 `unavailable`。在最后这种状态下，列表是一份冻结的快照，因此应据此决定是否显示实时指示器，而不是在陈旧数据上显示实时标识。
</FrontendOnly>

### REST

记忆路由对任何持有运行时凭据的后端或脚本开放。身份验证使用运行时二元组：作为 Bearer 令牌的项目 API 密钥，加上请求头中的应用用户 id。

| 路由 | 用途 |
|------|------|
| `GET /api/memories` | 列出调用方的记忆。传入 `includeInvalidated=true` 可包含已退役的。 |
| `POST /api/memories` | 保存一条记忆。 |
| `POST /api/memories/recall` | 针对查询进行语义召回。 |
| `PATCH /api/memories/:id` | 用整体替换的方式取代一条记忆。 |
| `DELETE /api/memories/:id` | 退役一条记忆。 |
| `POST /api/memories/subscribe` | 为记忆元数据创建实时订阅。 |

保存时需要提供内容、类型、可选的范围和可选的来源信息：

```bash
curl -X POST https://your-deployment/api/memories \
  -H "Authorization: Bearer cpk-<project>_<short>_<long>" \
  -H "X-Cpki-User-Id: <app-user-id>" \
  -H "Content-Type: application/json" \
  -d '{
    "content": "Prefers concise status updates.",
    "kind": "operational",
    "sourceThreadIds": ["<thread-id>"]
  }'
```

`content` 上限为 8192 个字符，`sourceThreadIds` 上限为 100 条。未知字段会被拒绝而不是忽略，因此键名拼写错误会得到一个错误，而不是静默的空操作。

召回接受一个查询和一个可选的结果上限，默认为 5，最大为 20：

```bash
curl -X POST https://your-deployment/api/memories/recall \
  -H "Authorization: Bearer cpk-<project>_<short>_<long>" \
  -H "X-Cpki-User-Id: <app-user-id>" \
  -H "Content-Type: application/json" \
  -d '{ "query": "how does this user like updates", "limit": 5 }'
```

每个路由返回的记忆结构相同：`id`、`kind`、`scope`、`content` 和 `sourceThreadIds`。召回结果还额外携带 `score`；当请求已退役的行时，列表路由会携带 `invalidatedAt`。

### 基于 MCP 的智能体工具

三个工具让智能体管理自己的记忆：`save_memory`、`recall_memory` 和 `forget_memory`。

只有在 MCP 服务端挂载后它们才会注册，这是 MCP 的通用前提条件，而非记忆设置。注册仍会在每个请求中对照调用方组织的记忆权益进行检查，因此挂载 MCP 并不会授予记忆。

注册还会按该运行的授权进一步收窄，因此智能体只会被提供它真正可调用的工具：可读的范围注册 `recall_memory`，可写的范围额外注册 `save_memory` 和 `forget_memory`，而无任何授权则一个也不注册。该授权来自哪里，请参见[按请求限制访问](#按请求限制访问)。

## 召回的工作原理

召回是混合式的。查询会被嵌入并与存储的向量比较，结果再与其他信号融合为单一分数，即召回结果中的 `score` 字段所报告的值。已退役和已被取代的记忆会被排除。

这正是嵌入空间如此重要的原因。可比性是空间的属性，而不是文本的属性，因此在一个模型下写入的记忆，无法与在另一个模型下嵌入的查询进行有意义的排序。
