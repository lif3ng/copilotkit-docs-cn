## 概览

Trajectory（轨迹）将浏览器交互捕获为 CopilotKit Intelligence 中的 AG-UI `CUSTOM` 事件。该特性目前处于抢先体验阶段。

本指南将一个现有的 React 应用连接到 Intelligence。若要搭建本地环境，请使用 [Trajectories 快速开始](/intelligence/trajectories-quickstart)。

捕获的内容包括 URL、页面标题、referrer、元素文本、属性、表单值、浏览器可见的请求头，以及有大小上限的 body 快照。可识别的凭据字段会在浏览器中脱敏。脱敏存在局限。开启捕获之前，请先阅读[捕获的数据](/intelligence/captured-data)。

## 开启捕获

<Steps>
  <Step>
    ### 将 Runtime 连接到 Intelligence

    完成 [Trajectories 快速开始](/intelligence/trajectories-quickstart)或 [Intelligence 快速开始](/intelligence/quickstart)。

    TypeScript Runtime 需要 `intelligence` 和 `identifyUser`，并且其项目已启用 Trajectories。`identifyUser` 必须从你经过验证的应用会话中返回用户。项目 API 密钥请保存在服务端。

    在抢先体验期间，我们的工程团队会为你的项目启用 Trajectories。如果你不确定访问权限是否已就绪，请先[预约我们的工程师](https://www.copilotkit.ai/talk-to-an-engineer)再继续。

  </Step>
  <Step>
    ### 向 provider 传递 `learning`

    在你现有的 provider 中添加 `learning`：

    ```tsx title="app/providers.tsx"
    "use client";

    import { CopilotKitProvider } from "@copilotkit/react-core/v2";

    export function Providers({ children }: { children: React.ReactNode }) {
      return (
        <CopilotKitProvider runtimeUrl="/api/copilotkit" learning>
          {children}
        </CopilotKitProvider>
      );
    }
    ```

    保留你现有的 Runtime URL 和应用身份验证配置。provider 挂载后捕获即开始，无需打开聊天。

  </Step>
  <Step>
    ### 打开已保存的 Trajectory

    在你的应用中点击一个控件，然后等待至少两秒，让下一批数据发出。

    在同一个 Intelligence 项目中打开 **Trajectories**，打开最新的那条 Trajectory。在其 **Timeline** 中展开 **Product trajectory**，找到那次点击。刷新页面，确认事件仍然存在。

    若要关联 Thread，请在捕获处于活动状态时发起一次智能体对话。

  </Step>
</Steps>

捕获已开启。本指南的其余部分为可选内容。

## 收集回复评分

只要 Trajectory 在聊天打开期间启动，`CopilotChat`、`CopilotPopup` 和 `CopilotSidebar` 中每条带文本的已完成回复都会出现 **Good response** 和 **Bad response** 按钮。你无需传入 `onThumbsUp` 或 `onThumbsDown`。在捕获重连或停止期间，这些按钮依然保留。自定义聊天只要在 `CopilotChatConfigurationProvider` 内用 `CopilotChatMessageView` 渲染消息，也会获得这些按钮。如果想把点赞/点踩交给你自己的处理器，请向 message view 传入 `messageFeedback: false`，例如 `<CopilotChat messageView={{ messageFeedback: false }} />`。

- 点击拇指即为回复评分，旁边会打开一个可选的评论输入框。按回车或让输入框失焦即可保存评论。按 Esc 或点击任一拇指会丢弃未保存的修改。切换到另一个拇指则会开始新的评分，且不带评论。
- 再次指向或用键盘聚焦已选中的拇指，会打开它的评论，用户之后可以添加或修改评论。在触摸屏上，点按已选中的拇指则会移除评分。
- 再次点击已选中的拇指会移除评分。
- 页面保持打开期间，已选中的拇指及其评论会一直保留。刷新后拇指恢复为未评分状态；新的评分会在 Intelligence 中替换先前的那次。

每次变更都会向当前活动的 Trajectory 发送一个 `message.feedback` 事件。同一个 `feedbackId` 的最新事件即当前评分，`rating: null` 表示用户已移除评分：

```json
{
  "type": "CUSTOM",
  "name": "message.feedback",
  "timestamp": 1790841239012,
  "value": {
    "seq": 12,
    "feedbackId": "5f0c6b1e-0b8f-4f6e-9a57-2f3d1c9a4e21:msg-42",
    "threadId": "5f0c6b1e-0b8f-4f6e-9a57-2f3d1c9a4e21",
    "messageId": "msg-42",
    "agentId": "default",
    "runId": "run-9",
    "rating": "down",
    "comment": "Picked the wrong deal",
    "response": "I approved deal 41 for you."
  }
}
```

与任何 Trajectory 事件一样，在捕获重连或停止期间给出的评分不会被发送，发送失败也不会重试，但聊天界面仍会显示它。评分归属于其所在的 Thread，因此后续的 Trajectory 可以携带对它的变更。Intelligence 会在 Trajectory 中把评分显示在回复旁边，自动学习（Automatic Learning）会在读取会话时一并读取它。

当用户给出评分时，你自己的 `onThumbsUp` 和 `onThumbsDown` 处理器仍会执行，但用户移除评分时不会。要修改拇指的工具提示、评论占位文案或发送按钮的标签，请设置[聊天标签](/reference/hooks/useCopilotChatConfiguration#copilotchatlabels)。要重新设计或替换评论输入框，请使用助手消息的 `feedbackComment` 插槽。评论弹层带有 `data-copilotkit-ignore` 标记，因此捕获记录的是保存后的评论，而不是每一次按键。点击拇指仍会作为 `click` 事件被捕获。

## 以编程方式控制捕获

下面的几节用于控制捕获何时运行以及记录哪些内容。所有选项和方法参见 [API 参考](/intelligence/trajectories-reference)。

### 获得同意后才捕获

传入一个布尔值，把捕获与你应用的同意控制绑定：

```tsx
<CopilotKitProvider runtimeUrl="/api/copilotkit" learning={hasConsent}>
  {children}
</CopilotKitProvider>
```

provider 会生成一个 Trajectory UUID。只要捕获处于开启状态，它在重渲染和重连期间保持不变。当 `hasConsent` 变为 `false` 时，捕获停止。重新开启捕获会生成新的 ID。卸载 provider 也会停止捕获。可以通过 `copilotkit.trajectoryId` 读取当前活动的 ID。

### 自行启动和停止 Trajectory

设置 `autoStart: false`。此后 provider 会等待你的应用来启动捕获：

```tsx
<CopilotKitProvider
  runtimeUrl="/api/copilotkit"
  learning={{ autoStart: false }}
>
  {children}
</CopilotKitProvider>
```

当你的应用判定会话开始时，调用 Core：

```tsx
import { useCopilotKit } from "@copilotkit/react-core/v2";

function StartCaptureButton() {
  const { copilotkit } = useCopilotKit();

  async function startCapture() {
    const result = await copilotkit.startTrajectory();
    if (result.status === "error") {
      console.warn("Trajectory capture:", result.code);
    }
  }

  return (
    <button onClick={startCapture}>Start capture</button>
  );
}
```

同一时刻只有一个 Trajectory 在运行。`copilotkit.stopTrajectory()` 会结束它并尝试发送最后一批数据，但不会等待投递完成，也不保证最后的事件一定被保存。

### 记录业务结果

点击记录的是用户做了什么，并不能说明操作是否成功。在你的应用操作成功后，发出结果事件：

```tsx
import { useCopilotKit } from "@copilotkit/react-core/v2";

function ApproveButton({
  dealId,
  approveDeal,
}: {
  dealId: string;
  approveDeal: (id: string) => Promise<void>;
}) {
  const { copilotkit } = useCopilotKit();

  async function approve() {
    await approveDeal(dealId);
    copilotkit.emitTrajectoryEvent("deal.approved", { dealId });
  }

  return (
    <button onClick={approve}>
      Approve
    </button>
  );
}
```

事件归属于当前活动的 Trajectory。`click` 等内置名称是保留名。事件负载由你的应用控制。自动凭据脱敏不会检查开发者发出的事件。

### 为关键操作命名

点击事件会在 `target.label` 中包含一个简短的控件名称，例如 `Approve`。来源与脱敏规则参见[点击标签](/intelligence/captured-data#click-labels)。

添加 `data-copilotkit-action` 可以获得一个稳定、明确的操作名称：

```tsx
<button data-copilotkit-action="deal.approve" onClick={approve}>
  Approve
</button>
```

### 处理捕获错误

默认情况下，Core 会记录配置错误，附上错误码和配置提示。传入 `onError` 可以在你的应用中自行处理：

```tsx
<CopilotKitProvider
  runtimeUrl="/api/copilotkit"
  learning={{
    onError: ({ code }) => console.warn("Trajectory capture:", code),
  }}
>
  {children}
</CopilotKitProvider>
```

连接中断期间捕获会暂停，并使用新的凭据重新连接。恢复期间它不会缓冲开发者事件，也不会重发失败的批次。投递限制参见[批次](/intelligence/captured-data#batches)，各错误码参见[错误码](/intelligence/trajectories-reference#error-codes)。
