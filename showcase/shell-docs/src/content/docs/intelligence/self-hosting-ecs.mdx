## 概览

使用版本化的 ECS/Fargate 部署包及其 `cpki-ecs` 命令，在你自己的 AWS 账户中部署 CopilotKit Intelligence。你从自己的网络、数据库、机密和 OIDC 提供方开始，最终得到 HTTPS 之后的 Intelligence 仪表盘、经过身份验证的会话，以及连接到你部署的运行时。

<Callout type="info" title="选择你的部署路径">
  本页介绍 ECS/Fargate。若要在 Kubernetes 上部署，请使用 [Helm 指南](/intelligence/self-hosting)。如果想在准备好生产资源之前先评估 ECS，请使用[参考环境](#使用参考环境进行评估)。
</Callout>

## 部署包会部署什么

部署包使用与 Helm chart 相同的已发布 Intelligence 服务镜像。它将每个第一方任务镜像固定到 `release-manifest.json` 中的摘要（digest）。

| 堆栈 | 资源 |
| --- | --- |
| `<deploymentName>-foundation` | ECS 集群、HTTPS Application Load Balancer、安全组、私有 Cloud Map 服务发现、KMS 加密的 CloudWatch 日志组、IAM 角色，以及调度器死信队列。 |
| `<deploymentName>-release` | app API、前端、实时网关、嵌入、迁移、引导（bootstrap）和线程清理的任务定义。 |
| `<deploymentName>-services` | 四个运行中的服务、ALB 路由、CPU 自动伸缩，以及一个已禁用的线程清理计划任务。 |

| 服务 | 容器端口 | 公开路由 |
| --- | --- | --- |
| `app-api` | 4201 | UI 主机上的 `/api`、`/api/*`、`/auth` 和 `/auth/*`。 |
| `app-frontend` | 8080 | UI 主机上的其余路径，包括 `/healthz`。 |
| `realtime-gateway` | 4401 | 实时主机上的所有路径，包括 WebSocket 路由和 `/health`。 |
| `embeddings` | 8080 | 私有 Cloud Map 端点；无公开路由。 |

全部四个服务都运行在禁用公网 IP 分配的私有子网中。即使部署没有记忆（Memory）权益，embeddings 服务也会运行；app API 在启动时则需要其提供方配置。在此部署包中，组合镜像不是一个 ECS 任务。

这三个堆栈不会创建你的 VPC、PostgreSQL、Redis、OIDC 提供方、证书、KMS 密钥、机密值或应用 DNS 记录。

## 开始之前

### 发行包访问权限与工具

从**同一个发行版本**获取 `copilot-intelligence-ecs-<version>.tar.gz` 和 `release-manifest.json`。[Intelligence GitHub releases](https://github.com/CopilotKit/Intelligence/releases) 需要仓库访问权限。如果你没有访问权限，请联系 [CopilotKit 客户团队](https://copilotkit.ai/talk-to-an-engineer)获取发行包。

在部署机器上安装 AWS CLI v2、Bash、`jq`、`curl`、`tar` 和 Python 3。使用的 AWS 凭据需要能够创建 CloudFormation 堆栈及其 IAM 角色、传递生成的任务角色，并向数据库和 Redis 安全组添加入站规则。配置校验使用只读的 AWS API；部署则需要写入权限。

### AWS 资源

| 资源 | 所需配置 |
| --- | --- |
| 网络 | 一个 VPC，其中至少包含两个公有子网和两个私有子网。每组子网必须跨越至少两个可用区。公有子网需要一条指向互联网网关的有效 `0.0.0.0/0` 路由；私有子网需要一条指向 NAT 网关的有效 `0.0.0.0/0` 路由。配置器会拒绝仅使用端点的私有网络。 |
| 数据库 | 带有 pgvector 的 PostgreSQL，可在 5432 端口访问；Redis 可在 6379 端口访问。请提供它们的安全组 ID 以及 PostgreSQL 服务器的实际连接数上限。foundation 堆栈会添加来自其运行时安全组的入站规则。 |
| HTTPS 与 DNS | 一张已签发、同时覆盖 `uiHostName` 和 `realtimeHostName` 的 ACM 证书。部署完成后，将这两个域名指向 foundation ALB。 |
| 身份 | 一个 HTTPS OIDC 签发方和客户端。将 `https://<uiHostName>/auth/callback/<authProviderId>` 注册为回调地址。默认提供方 ID 为 `enterprise-sso`。 |
| 加密 | 部署账户和区域中两个不同且已启用的客户托管对称 KMS 密钥：`kmsKeyArn` 用于日志，`secretKmsKeyArn` 用于机密。请提供完整的密钥 ARN，而不是别名。 |

日志密钥策略必须允许区域级 CloudWatch Logs 服务（`logs.<region>.amazonaws.com`）使用 `kms:Encrypt`、`kms:Decrypt`、`kms:ReEncrypt*`、`kms:GenerateDataKey*` 和 `kms:Describe*`，并限定在 `/ecs/<deploymentName>/*` 的加密上下文内。机密密钥策略必须允许账户级 IAM 权限，使任务执行角色的 `kms:Decrypt` 授权生效。[参考环境](#使用参考环境进行评估)的 `substrate.yaml` 中包含这两个策略。

配置器会调用 `sts:GetCallerIdentity`、针对所提供 VPC、子网、路由和安全组的 EC2 describe API、`acm:DescribeCertificate`、`kms:DescribeKey` 和 `secretsmanager:DescribeSecret`。如果你配置了对象存储，它还需要 `s3:GetBucketLocation`。它会通过 HTTPS 检查 OIDC 发现文档。它不会读取机密值，也不会测试数据库凭据。

### 机密

为下方的每个必填字段创建一个单独的 Secrets Manager 机密。使用你将提供给配置器的确切 `secretKmsKeyArn` 加密每个机密。配置文件中只包含 ARN；任务在启动时才会接收机密值。

| 配置字段 | 机密值 |
| --- | --- |
| `databaseUrlSecretArn` | PostgreSQL 连接 URL（`DATABASE_URL`）。 |
| `redisUrlSecretArn` | Redis 连接 URL（`REDIS_URL`）。 |
| `authSecretArn` | 会话机密（`AUTH_SECRET`），至少 32 个字符。 |
| `authClientIdSecretArn` | OIDC 客户端 ID（`AUTH_CLIENT_ID`）。 |
| `authClientSecretSecretArn` | OIDC 客户端机密（`AUTH_CLIENT_SECRET`）。 |
| `runnerAuthSecretArn` | 实时 runner 身份验证机密（`RUNNER_AUTH_SECRET`）。 |
| `secretKeyBaseSecretArn` | Phoenix 机密密钥基（`SECRET_KEY_BASE`）。 |
| `releaseCookieSecretArn` | 共享的实时集群 cookie（`RELEASE_COOKIE`）。 |
| `providerCredentialEncryptionKeySecretArn` | 64 位十六进制字符的 AES-256 密钥（`APP_HOSTED_BOTS_CREDENTIAL_ENCRYPTION_KEY`）。 |

对于 RDS，服务镜像在 `/etc/cpki/rds-ca/global-bundle.pem` 中包含 CA 证书包。部署包 README 记录了使用该 CA 路径的 `sslmode=verify-full`。Redis URL 的 TLS 设置需与你的 Redis 服务相匹配。

| 可选字段 | 何时提供 |
| --- | --- |
| `licenseTokenSecretArn` | 用于授权能力的已签名部署许可证（`COPILOTKIT_LICENSE_TOKEN`）。项目 API 密钥是另一个运行时凭据。 |
| `bootstrapConfigSecretArn` | Base64 编码的引导 JSON（`BOOTSTRAP_CONFIG_B64`）。首次安装时提供此项以创建组织访问映射。现有部署可以保留其映射。 |
| `timescaleUrlSecretArn` | 用于分析的受限权限运行时 TimescaleDB URL。 |
| `timescaleMigratorUrlSecretArn` | 用于分析迁移的 schema 所有者 TimescaleDB URL。 |

分析功能默认禁用。要启用它，请将 `analyticsEnabled` 设为 `true`，并提供**两个** Timescale 机密 ARN。迁移任务会接收所有者 URL 和运行时 URL；app API 和实时服务只接收运行时 URL。两个运行时服务和迁移任务都必须能够访问 TimescaleDB。

### 首次安装的组织访问

OIDC 登录本身不会授予组织访问权限。请使用部署包中的 `config/bootstrap.example.json` 准备一个引导文件。下面的示例创建一个组织，并向 OIDC `groups` 声明中包含精确且区分大小写值 `intelligence-users` 的用户授予成员资格：

```json title="bootstrap.json"
{
  "organizations": [
    {
      "slug": "my-organization",
      "name": "My Organization",
      "mappings": [
        {
          "role": "org_member",
          "claimName": "groups",
          "claimValue": "intelligence-users"
        }
      ]
    }
  ],
  "platformAdminMappings": [],
  "emergencyPlatformAdminGrants": []
}
```

将组织和声明值替换为你自己的。你的 IdP 必须发出匹配的声明。支持的声明名称为 `groups`、`roles`、`department` 和 `entitlements`；电子邮件域名不会授予成员资格。如果你还需要向特定的 IdP 组授予平台管理权限，请使用示例文件中 `platformAdminMappings` 的结构。

对你的文件进行 Base64 编码，并将得到的文本存储为使用同一机密 KMS 密钥的 Secrets Manager 机密：

```bash title="终端"
base64 < bootstrap.json | tr -d '\n' > bootstrap.b64
```

将该机密的 ARN 作为 `bootstrapConfigSecretArn` 提供。部署会在迁移之后运行引导。如果不存在任何组织或访问映射，UI 会报告该部署尚未完成引导。如果登录用户不匹配任何映射，UI 会报告该用户未被分配到组织。

## 部署与验证

请在 Bash 中运行以下命令。保持同一个 shell 打开，以便第一步中设置的路径保持可用。

<Steps>
  <Step>
    ### 解压发行包

    将两个发行资产放入一个空的工作目录。将 `CPKI_VERSION` 设置为你获取到的版本；`0.12.9` 是一个已发布版本的示例。

    ```bash title="终端"
    export CPKI_VERSION=0.12.9
    export CPKI_DEPLOY_DIR="$PWD"

    tar -xzf "copilot-intelligence-ecs-${CPKI_VERSION}.tar.gz"
    cd "copilot-intelligence-ecs-${CPKI_VERSION}"
    export CPKI_CONFIG="$CPKI_DEPLOY_DIR/parameters.json"
    export CPKI_MANIFEST="$CPKI_DEPLOY_DIR/release-manifest.json"

    cmp ./release-manifest.json "$CPKI_MANIFEST"
    ./bin/cpki-ecs validate --offline
    ```

    `cmp` 必须报告内置清单与下载的清单之间没有差异。离线校验会检查部署包所需的文件以及清单契约。它不会连接 AWS，也不会校验你的账户资源。
  </Step>

  <Step>
    ### 生成你的配置

    使用上文准备好的 ID、ARN、主机名和签发方运行引导式配置器：

    ```bash title="终端"
    ./bin/cpki-ecs configure --interactive --output "$CPKI_CONFIG"
    ```

    该命令一次只问一个问题，检查本地约束和 AWS 元数据，并且只有在校验通过后才写入文件。它不会创建任何 AWS 资源。除非传入 `--force`，否则不会覆盖已有的输出文件。

    如果你使用命名的 AWS profile，请在配置或部署之前用 `AWS_PROFILE` 为整个 shell 选中它。配置器的 `--profile` 选项只作用于该次调用，不会保存进文件。

    对于预置的 JSON 文件，请把随附的示例复制到部署包之外，替换其中的占位符并进行校验：

    ```bash title="备选：预置 JSON"
    cp ./config/example.parameters.json "$CPKI_DEPLOY_DIR/draft.parameters.json"
    # 用你的资源 ID、ARN 和设置编辑 draft.parameters.json。
    ./bin/cpki-ecs configure \
      --from-json "$CPKI_DEPLOY_DIR/draft.parameters.json" \
      --output "$CPKI_CONFIG"
    ```

    引导式或 JSON 两种方式任选其一。对于自动化场景，`./bin/cpki-ecs configure --help` 列出了 `--non-interactive` 模式的所有标志。

    部署之前，请检查以下设置：

    | 设置 | 契约 |
    | --- | --- |
    | App API 与前端数量 | 期望、最小和最大数量必须至少为 2。realtime 的期望/最小值可以为 1；其最大值必须至少为 2。 |
    | 数据库连接池 | 配置器按 200% 滚动更新容量为 API 和 realtime 的最大数量做预算。两者连接池的总和必须不超过 `databaseMaxConnections` 的 70%。 |
    | 嵌入 | 除非你已选择其他兼容的提供方镜像与模型，否则请保留随附的按摘要固定的 `embeddingsImage` 和 `embeddingsModel`。 |
    | 可选 S3 | 为频道文件和实时归档设置 `objectStorageBucket` 及其对应的 `objectStorageRegion`。模板会授予作用域受限的任务角色访问权限。 |
    | 线程清理 | 保持 `threadCullerState` 为 `DISABLED`。该任务会删除数据。 |

    以示例中 API 和 realtime 最大数量为 10、连接池大小为 10 计算，滚动更新预算为 `20 × 10 + 20 × 10 = 400` 个连接。请将 `databaseMaxConnections` 设置为你服务器的上限；如果 400 超过该上限的 70%，请调整数量和连接池。
  </Step>

  <Step>
    ### 部署堆栈与迁移

    ```bash title="终端"
    ./bin/cpki-ecs deploy \
      --config "$CPKI_CONFIG" \
      --manifest "$CPKI_MANIFEST"
    ```

    该命令会应用 foundation 和 release 堆栈，运行产品迁移，在启用时运行分析迁移，并在已配置时运行引导。每个一次性任务都必须以退出码 0 结束，服务才会更新。随后命令会对照请求的发行版本验证已部署的服务。

    迁移或引导失败会在服务更新之前停止部署。重试之前，请阅读任务诊断信息和对应组件的 CloudWatch 日志。
  </Step>

  <Step>
    ### 设置 DNS 并检查健康状态

    读取 foundation 堆栈的输出：

    ```bash title="终端"
    export AWS_REGION="$(jq -r '.region' "$CPKI_CONFIG")"
    export CPKI_DEPLOYMENT_NAME="$(jq -r '.deploymentName' "$CPKI_CONFIG")"
    export CPKI_UI_HOST="$(jq -r '.uiHostName' "$CPKI_CONFIG")"
    export CPKI_REALTIME_HOST="$(jq -r '.realtimeHostName' "$CPKI_CONFIG")"

    aws cloudformation describe-stacks \
      --region "$AWS_REGION" \
      --stack-name "${CPKI_DEPLOYMENT_NAME}-foundation" \
      --query 'Stacks[0].Outputs' --output table
    ```

    使用 `LoadBalancerDnsName`（对于 Route53 别名还有 `LoadBalancerCanonicalHostedZoneId`）为两个主机创建 DNS 记录。源码发行版中的 `deploy/ecs/examples/reference-environment/app-dns.yaml` 提供了一个 Route53 示例；参见[如何获取参考模板](#使用参考环境进行评估)。

    两个域名都解析到 ALB 后，验证发行版本和健康路由：

    ```bash title="终端"
    ./bin/cpki-ecs verify \
      --config "$CPKI_CONFIG" \
      --manifest "$CPKI_MANIFEST"

    curl --fail "https://${CPKI_UI_HOST}/healthz"
    curl --fail "https://${CPKI_UI_HOST}/api/health"
    curl --fail "https://${CPKI_REALTIME_HOST}/health"
    ```

    `verify` 会检查堆栈状态、稳定的服务数量、已完成的滚动更新，以及所请求的任务定义和镜像摘要。它不会执行 OIDC 登录，也不能证明浏览器可以打开 WebSocket。
  </Step>

  <Step>
    ### 登录并连接你的运行时

    在浏览器中打开 UI 主机，使用符合你引导访问映射的用户通过 OIDC 提供方登录。选择组织，选择或创建项目，并在该部署中创建一个项目 API 密钥。

    按照[连接你的运行时](/intelligence/quickstart#self-hosted-deployments)操作，并使用你部署的两个基础 URL：

    ```ts title="Intelligence client in your server-side runtime"
    import { CopilotKitIntelligence } from "@copilotkit/runtime/v2";

    const intelligence = new CopilotKitIntelligence({
      apiUrl: "https://intelligence.example.com",
      wsUrl: "wss://realtime.intelligence.example.com",
      apiKey: process.env.CPK_INTELLIGENCE_API_KEY!,
    });
    ```

    将主机替换为 `uiHostName` 和 `realtimeHostName`，并将服务端密钥设置为你刚创建的项目密钥。按照运行时指南所示，将 `intelligence` 传给你现有的 `CopilotRuntime`。不要在这些基础 URL 后追加 `/api`、`/runner` 或 `/client`；路径由客户端添加。

    <Callout type="info" title="检查你应用的浏览器来源">
      `0.12.9` 发行模板将实时服务的 `CHECK_ORIGIN` 设置为 `https://<uiHostName>`。配置器没有额外的浏览器来源字段。如果你的应用运行在另一个来源上，请在测试其浏览器连接之前与你的部署团队一起检查网关的来源配置；仅更改运行时的 URL 不会改变该设置。
    </Callout>

    从你的应用发送一条消息。确认实时连接升级为 WebSocket、响应以流式返回，并且线程出现在你的自托管项目中。重新加载应用并重新打开该线程以检查持久化。这些检查在三个 HTTP 健康探测之外覆盖了用户路径。
  </Step>
</Steps>

## 使用参考环境进行评估

Intelligence 源码仓库在 `deploy/ecs/examples/reference-environment/` 下提供了一个 AWS 评估环境。部署包根目录的 `README.md` 包含完整的**快速开始：参考环境**命令，包括输出到参数的衔接。

<Callout type="info" title="单独获取参考模板">
  已发布的 `0.12.9` ECS 归档中不包含 `examples/reference-environment/`，尽管其 README 提到了该目录。请先从对应的源码发行版或你的 CopilotKit 客户团队处获取它，再按快速开始操作。三个生产模板已经包含在 ECS 归档中。
</Callout>

完成上文的解压步骤后，你可以使用已登录具备 Intelligence 仓库访问权限账户的 GitHub CLI 获取源码：

```bash title="终端"
gh release download "v${CPKI_VERSION}" \
  --repo CopilotKit/Intelligence \
  --archive tar.gz \
  --output "$CPKI_DEPLOY_DIR/intelligence-source.tar.gz"

mkdir "$CPKI_DEPLOY_DIR/reference-source"
tar -xzf "$CPKI_DEPLOY_DIR/intelligence-source.tar.gz" \
  --strip-components=1 -C "$CPKI_DEPLOY_DIR/reference-source"

cd "$CPKI_DEPLOY_DIR/copilot-intelligence-ecs-${CPKI_VERSION}"
cp -R "$CPKI_DEPLOY_DIR/reference-source/deploy/ecs/examples" ./examples
```

然后从解压出的 ECS 部署包目录开始，按照 `README.md` 中的**快速开始：参考环境**操作。使用你下载的发行清单即可；无需从镜像标签构造清单。

| 顺序 | 模板或命令 | 用途 |
| --- | --- | --- |
| 1 | `substrate.yaml` | VPC、公有/私有子网、NAT、RDS PostgreSQL、ElastiCache Redis、KMS 密钥、ACM 证书，以及数据库密码机密。 |
| 2 | `secrets.yaml` | 由 substrate 输出派生的运行时机密和连接 URL。 |
| 3 | `keycloak.yaml` 与 `realm-cpki.json` | 评估用 OIDC 签发方、应用客户端和演示用户。 |
| 4 | `cpki-ecs configure`，然后 `cpki-ecs deploy` | 与生产环境相同的三个 Intelligence 堆栈。 |
| 5 | `app-dns.yaml`，然后健康/登录检查 | UI 与 realtime 的 Route53 别名，随后进行验证。 |

<Callout type="warn" title="使用你自己的域名和仅用于评估的凭据">
  请提供你自己的 Route53 托管区域和主机名。覆盖 substrate 的 `WildcardDomain` 参数：其默认值是一个 CopilotKit 域名。证书必须覆盖 UI、realtime 和 Keycloak 主机。导入的 realm 包含 `demo` / `Passw0rd!`；参考环境仅用于评估。生产环境请使用你自己的身份提供方和托管资源。
</Callout>

参考环境不会添加 TimescaleDB 实例。除非你自己提供实例和两个分析机密 ARN，否则请保持分析功能禁用。

参考 realm 也没有定义组织声明映射。其演示登录可以验证 OIDC，但项目访问仍需要来自 IdP 的受支持声明以及上文的[引导映射](#首次安装的组织访问)。

## 运维部署

### 升级或回滚

保留之前的部署包、清单和配置。升级前，按照你的恢复策略备份数据库并检查迁移兼容性。获取新的部署包和匹配的清单，在一个新目录中解压，然后用你的配置运行其 `deploy` 命令。重复上文的健康检查、登录检查和运行时检查。

要回滚应用任务，请从保留的先前部署包及其清单运行：

```bash title="终端"
./bin/cpki-ecs rollback \
  --config "$CPKI_CONFIG" \
  --manifest ./release-manifest.json
```

回滚会注册先前的任务定义、更新服务并验证其发行版本。**它不会回滚数据库迁移**。ECS 部署熔断器也会回滚失败的服务部署；它不会回滚迁移或 foundation 堆栈的变更。

### 轮换机密或更改容量

更改某个机密值后，需要为每个使用它的服务启动一次新部署。例如，轮换某个 app API 机密后：

```bash title="终端"
aws ecs update-service \
  --region "$AWS_REGION" \
  --cluster "$CPKI_DEPLOYMENT_NAME" \
  --service "${CPKI_DEPLOYMENT_NAME}-app-api" \
  --force-new-deployment
```

运行中的任务在重启之前不会收到新的环境机密值。要更改服务数量，请校验更新后的配置并使用同一清单运行 `deploy`。API、前端和 realtime 通过 `targetCpuUtilization` 使用 CPU 目标跟踪。

### 排查失败的发布

使用 ECS 服务事件、已停止任务的原因以及 `/ecs/<deploymentName>/...` CloudWatch 日志组。Container Insights 默认启用。将 `otlpEndpoint` 设置为你的 OTLP 收集器基础 URL 以接收追踪。部署包不安装可观测性后端。参见[使用 OpenTelemetry 监控](/intelligence/self-hosting-observability)。

| 故障 | 检查项 |
| --- | --- |
| 配置被拒绝 | 所指名的资源、账户/区域、NAT 路由、证书覆盖的主机、确切的机密 KMS 密钥，以及 OIDC 发现响应。 |
| 迁移或引导失败 | 已停止的任务及其组件日志组。每个必需任务以零退出之前，服务不会更新。 |
| ALB 健康检查失败 | 正确主机上的 `/api/health`、`/healthz` 或 `/health`；任务对 PostgreSQL 和 Redis 的访问。 |
| OIDC 重定向被拒绝 | 在你的 IdP 注册的精确 `https://<uiHostName>/auth/callback/<authProviderId>`。 |
| 实时服务发现失败 | Cloud Map 记录，以及运行时安全组中针对 EPMD 4369 和 BEAM distribution 9000–9010 的规则。 |

### 移除部署

先移除应用 DNS 记录。然后从部署包目录删除三个 Intelligence 堆栈：

```bash title="终端 —— 移除部署"
./bin/cpki-ecs teardown \
  --config "$CPKI_CONFIG" \
  --confirm "$CPKI_DEPLOYMENT_NAME"
```

确认值必须与 `deploymentName` 完全一致。该操作会禁用 ALB 删除保护，并按此顺序删除 services、release 和 foundation。CloudWatch 日志组会保留。客户托管的数据库、Redis、VPC、IdP、机密、证书和 KMS 密钥都会保留。

对于参考环境，请按照部署包 README 中的完整拆除顺序操作：应用 DNS、部署包堆栈、Keycloak、机密，然后是 substrate。仅运行 `cpki-ecs teardown` 不会移除那些额外的堆栈。
