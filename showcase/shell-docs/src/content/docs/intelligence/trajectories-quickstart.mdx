## 概览

本指南使用 CopilotKit CLI 在你的机器上运行 CopilotKit Intelligence，并连接一个已有的 React 应用。你将录制浏览器活动，并在 Intelligence 中找到已保存的轨迹。

<Callout type="info" title="与工程团队一起抢先体验">
  轨迹功能目前处于抢先体验阶段。本指南用于与我们的工程团队一起进行概念验证，并默认你的许可证与轨迹访问权限均已就绪。

  如果不确定，请在开始前[预约我们的工程师](https://www.copilotkit.ai/talk-to-an-engineer)。
</Callout>

CLI 会安装并管理本地技术栈。你无需安装其内部工具，也无需创建安装配置文件。此配置仅用于本地评估，并非生产部署。

## 开始之前

- macOS，且 Docker Desktop 正在运行。请预留至少 4 个 CPU、12 GiB 的 Docker 内存和 40 GiB 的可用存储。
- 一个已有的 React 应用，带 TypeScript CopilotKit Runtime，外加 Node.js 22 或更高版本。
- 你已有的 CopilotKit 登录账号，供 CLI 使用。

浏览器捕获不需要模型。下面的步骤会跳过模型配置与示例对话。

## 1. 用 CLI 安装 Intelligence

在既有应用的文件夹中运行所有 CLI 命令。用已有账号登录：

```bash
npx copilotkit@latest login
```

为这次概念验证选择组织。然后安装本地技术栈：

```bash
npx copilotkit@latest local setup --defer-model --no-samples
```

CLI 会检查 Docker、下载发布产物并安装 Intelligence。安装完成后，它会打开本地仪表盘并帮你登录。请等安装完成后再继续。

关于 CLI 安装的更多信息，请参阅[在本地评估 Intelligence](/intelligence/self-hosting-local)。

## 2. 连接你的应用

预览连接变更：

```bash
npx copilotkit@latest local connect
```

应用这些变更：

```bash
npx copilotkit@latest local connect --approve-connection
```

CLI 会把本地 API URL、网关 URL 与项目密钥写入你应用的 `.env`，同时写入 `SL_ENABLED=true`。项目密钥请保存在服务端。

请确保你的 Runtime 服务器加载了这个 `.env` 文件。本地端口由 CLI 选择，因此请保留它写入的 URL。

CLI 在修改之前会保存原有配置。如果 `.env` 被 Git 跟踪，它会拒绝写入密钥。

## 3. 配置你的 Runtime

安装示例所需的软件包：

```bash
npm install @copilotkit/react-core@1.79.1 @copilotkit/runtime@1.79.1
```

使用 `.env` 中的值，在既有 Runtime 中配置 Intelligence 客户端：

```ts title="你的 CopilotKit Runtime"
import {
  CopilotKitIntelligence,
  CopilotRuntime,
} from "@copilotkit/runtime/v2";

const intelligence = new CopilotKitIntelligence({
  apiKey: process.env.CPK_INTELLIGENCE_API_KEY!,
  apiUrl: process.env.INTELLIGENCE_API_URL!,
  wsUrl: process.env.INTELLIGENCE_GATEWAY_WS_URL!,
});

const runtime = new CopilotRuntime({
  agents,
  intelligence,
  identifyUser,
});
```

保留你既有的 `agents`、handler 与应用身份验证。`identifyUser` 从你已验证的应用会话中返回用户。请移除显式的 `runner` 选项，因为 Intelligence 会提供 runner。

如果你的 Runtime 没有 `identifyUser`，请参考 [Runtime 连接示例](/intelligence/quickstart#connect-your-runtime)。

配置更改后，请重启你的 Runtime 和应用。

## 4. 录制一条轨迹

开启捕获之前，请先阅读[捕获的数据](/intelligence/captured-data)。

在既有 provider 中添加 `learning`：

```tsx title="你的 CopilotKit Provider"
<CopilotKitProvider runtimeUrl="/api/copilotkit" learning>
  {children}
</CopilotKitProvider>
```

保留你既有的 `runtimeUrl` 与身份验证 props。如果你的 Runtime 使用单一端点，也请保留 `useSingleEndpoint`。provider 挂载时捕获即开始。

1. 打开你的应用。
2. 点击几个控件，并编辑一个表单字段。
3. 向你的智能体发送一条消息以关联会话。没有会话时，浏览器捕获同样可用。
4. 等待至少两秒，让下一批数据发出。

如果捕获无法连接，浏览器控制台会显示带错误码的警告。参见[错误码](/intelligence/trajectories-reference#error-codes)。

## 5. 找到已保存的轨迹

在应用的文件夹中打开本地仪表盘：

```bash
npx copilotkit@latest local login
```

CLI 会打开仪表盘并帮你登录。

1. 打开与你的应用连接的项目。
2. 选择 **Trajectories**。
3. 刷新列表并打开最新的轨迹。
4. 在其 **Timeline** 上展开 **Product trajectory**，找到你的点击或表单编辑。
5. 重新加载页面，确认事件仍在。

该事件现在已是已保存轨迹的一部分。这项检查既不需要模型，也不需要实时查看。

## 停止与重启

在应用的文件夹中停止本地技术栈：

```bash
npx copilotkit@latest local stop
```

这会保留本地数据。稍后要继续时：

```bash
npx copilotkit@latest local start
```

## 故障排查

<Callout type="warn" title="许可证与访问错误需要我们的团队处理">
  如果看到 `TRAJECTORIES_NOT_ENABLED`、`TRAJECTORIES_UNAVAILABLE` 或 `MARKETPLACE_LICENSE_REQUIRED`，请在继续之前[预约我们的工程师](https://www.copilotkit.ai/talk-to-an-engineer)。我们的团队可以检查你的许可证、项目访问权限与部署支持。
</Callout>

| 问题 | 处理方式 |
| --- | --- |
| Docker 没有响应 | 启动 Docker Desktop。检查 Docker 是否具备**开始之前**中列出的资源。 |
| 安装中途停止 | 阅读 CLI 报错。运行 `npx copilotkit@latest local status` 检查技术栈状态。解决错误后，重新运行安装命令即可继续。 |
| 仪表盘要求重新登录 | 在应用的文件夹中运行 `npx copilotkit@latest local login`。 |
| 浏览器控制台显示捕获错误 | 检查 Runtime 是否加载了 `local connect` 写入的 `.env` 值。配置更改后请重启 Runtime。各错误码参见[错误码](/intelligence/trajectories-reference#error-codes)。 |
| 轨迹中没有可见事件 | 等待已保存的数据更新后刷新。检查浏览器控制台与所选项目。 |
| 轨迹没有关联会话 | 在捕获激活期间发起一次智能体对话。更早的对话不会自动关联。 |

更多 CLI 命令与恢复步骤，请参阅[管理技术栈](/intelligence/self-hosting-local#manage-the-stack)。
