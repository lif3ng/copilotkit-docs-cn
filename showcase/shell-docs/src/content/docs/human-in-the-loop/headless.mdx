## 这是什么？

`useInterrupt` 的 `render` 回调是那条 80% 的常规路径：它让 UI
贴着 `<CopilotChat>` 的会话记录走，并替你处理“何时显示选择器”的
逻辑。本页讲的是另一条出路：一个**无渲染**（render-less）的中断
解析器，由 `useInterrupt` 内部使用的同一批原语组装而成——这种模式
可以放在 React 树的任何位置，可以呈现你喜欢的任何形态（按钮组、
表单、弹窗、快捷键），并且完全不挂载聊天也能解析中断。

<WhenFrameworkHas flag="interrupt_pattern" equals="native">

底层原语就是框架自己的中断调用。它如何到达客户端取决于桥接层，
对应两种无头形态：

- 桥接层把暂停作为 `on_interrupt` 自定义事件暴露出来
  （LangGraph）：订阅该事件，然后带上匹配的 `resume`
  载荷调用 `copilotkit.runAgent({...})` 来恢复运行。
- 桥接层以标准的 AG-UI 中断结局结束运行（AWS
  Strands）：运行最终的 `RUN_FINISHED` 事件带有
  `outcome: { type: "interrupt", interrupts: [...] }`。调用
  `useInterrupt` 时传入 `renderInChat: false`，把它返回的元素放到
  任何你喜欢的地方；`resolve(...)` 会恢复运行。

无论哪种方式，都不需要聊天界面。

</WhenFrameworkHas>

<WhenFrameworkHas flag="interrupt_pattern" equals="promise-based">

对于基于 Promise 的集成，没有原生中断原语可用，因此无头变体使用
带 Promise 处理器的 `useFrontendTool`。处理器通过 React
状态暴露其待处理载荷——这样一个独立的“应用界面”就能在聊天之外
渲染选择器——并在用户交互后兑现该 Promise。同样的 UX，
不同的机制。

</WhenFrameworkHas>

<WhenFrameworkHas flag="interrupt_pattern" absent>

> **此框架不可用**。无头中断建立在 `useInterrupt` /
> `useFrontendTool` 模式之上，要求运行时暴露原生 `interrupt(...)`
> 原语（LangGraph）或可兑现 Promise 的前端工具路径。对于其他所有
> 集成，请改用
> [`useHumanInTheLoop`](../human-in-the-loop)——它是基于工具调用的
> 暂停/恢复流程的标准 hook，可用于所有支持工具调用的框架。

</WhenFrameworkHas>

## 何时使用无头中断？

- **测试 / Playwright 夹具**（fixture） ——
  确定性的、不带聊天的按钮组比聊天界面更容易驱动——后者里选择器
  要等一次 LLM 调用之后才出现。
- **非聊天 UI** —— 仪表盘、侧边面板、Inspector
  界面，或任何你想要智能体中断而不要聊天记录的地方。
- **自定义流程控制** ——
  当你需要确切知道中断何时到达（例如为其他 UI
  加闸门）、何时被解析时。
- **研究 / 调试** ——
  当你想绕开抽象层直接观察原始 AG-UI 自定义事件时。

如果你只想要“聊天里的选择器”，直接用
[`useInterrupt`](./useInterrupt) 就好。

## 底层原语

<FrameworkSetup concept="programmatic-control-setup" />

最简单的无头模式是配合 `renderInChat: false` 使用
`useInterrupt`。hook 不再把元素发布进 `<CopilotChat>`，而是直接
返回中断元素，你可以把它放到树里的任何位置：

```tsx
function ApprovalPanel() {
  const element = useInterrupt({
    renderInChat: false,
    render: ({ interrupt, resolve, cancel }) => (
      <div className="p-3 border rounded">
        <p>{interrupt?.message ?? "Approve this action?"}</p>
        <div className="mt-2 flex gap-2">
          <button onClick={() => resolve({ approved: true })}>Approve</button>
          <button onClick={() => cancel()}>Cancel</button>
        </div>
      </div>
    ),
  });

  // `element` is null while no interrupt is active; render it wherever you like.
  return <div className="approval-panel">{element}</div>;
}
```

`interrupt` 携带主要的 AG-UI `Interrupt` 对象
（`{ id, reason, message?, responseSchema?, expiresAt?, ... }`）。
`resolve(payload)` 提交用户的响应并恢复智能体。`cancel()`
取消中断并恢复运行。两者都返回 `Promise<RunAgentResult | void>`——
当有多个中断同时打开时，等待后续中断期间返回 void。

在底层，`useInterrupt` 组合了两个公开 API：

1. **`agent.subscribe({ onCustomEvent, onRunStartedEvent, onRunFinishedEvent, onRunFinalized, onRunFailed })`**
   —— 每个 `AbstractAgent` 都暴露一个 AG-UI
   事件订阅。标准中断随 `onRunFinishedEvent` 到达，形如
   `{ outcome: { type: "interrupt", interrupts: [...] } }`；旧版
   LangGraph 中断则以名为 `on_interrupt` 的自定义事件到达。
2. **`copilotkit.runAgent({ agent, resume })`**（标准）或
   **`copilotkit.runAgent({ agent, forwardedProps: { command: { resume, interruptEvent } } })`**（旧版）
   —— 与 `useInterrupt` 的 `resolve()` / `cancel()`
   恢复暂停运行时所用的是同一个调用。

该区域展示的内容取决于框架。框架以旧版自定义事件暂停时，它是一个
手写的、直接订阅原始事件的 hook；框架以标准 AG-UI 中断暂停时，
只需同样的 `useInterrupt` 调用加 `renderInChat: false`，代码片段
展示的就是后者。无论哪种，当你想要完全掌控时（测试夹具、自定义
累积逻辑），原始原语始终可用：

<Snippet region="headless-useinterrupt-primitives" title="frontend/src/app/page.tsx — useHeadlessInterrupt" />

手写变体小心处理了几件事：

- 它把到来的事件先暂存在本地 ref 里，直到 `onRunFinalized`
  才提交进 React 状态，与 `useInterrupt` 一致——后者在运行真正暂停
  之前不会暴露中断（而不是事件在流中途触发时就暴露）。
- `onRunStartedEvent` 会清掉残留的待处理状态，因此开启新一轮总是从
  干净状态开始。
- `onRunFailed` 会丢弃暂存的事件，这样一次传输抖动不会让 UI
  卡在选择器上，去等一个从未暂停过的运行。

</WhenFrameworkHas>

## 底层原语

render 回调有意返回 `null`——选择器 UI 位于应用界面里，而不是聊天
记录中。处理器的待处理状态决定选择器是否显示：

<Snippet region="headless-promise-primitives" title="frontend/src/app/page.tsx — useFrontendTool (headless Promise-based)" />

这个模式小心处理了几件事：

- 处理器把它的 `resolve` 回调暂存在以工具调用 id 为键的 ref
  里，因此并发的工具调用不会互相踩掉对方的解析器。
- `setPending` 从处理器内部调用，因此智能体一调用工具，应用界面
  就会重新渲染选择器；用户交互之后再以 `null`
  调用一次，选择器随之消失。
- `render: () => null` 让聊天记录保持干净——无头变体有意绕开内联
  渲染。

</WhenFrameworkHas>

## 从普通 UI 驱动

首选做法是配合 `renderInChat: false` 使用 `useInterrupt`——不用
手写订阅，不用 `<CopilotChat>`，不用 render prop：

```tsx
function HeadlessInterruptPanel() {
  const { copilotkit } = useCopilotKit();
  const { agent } = useAgent({ agentId: "interrupt-headless" });

  const kickOff = (prompt: string) => {
    agent.addMessage({ id: crypto.randomUUID(), role: "user", content: prompt });
    void copilotkit.runAgent({ agent });
  };

  const interruptElement = useInterrupt({
    renderInChat: false,
    render: ({ interrupt, resolve, cancel }) => (
      <div>
        <p>Pick a slot for {interrupt?.message ?? "a call"}:</p>
        {SLOTS.map((s) => (
          <button key={s.iso} onClick={() => resolve({ chosen_time: s.iso, chosen_label: s.label })}>
            {s.label}
          </button>
        ))}
        <button onClick={() => cancel()}>Cancel</button>
      </div>
    ),
  });

  if (interruptElement) {
    return interruptElement;
  }

  return <button onClick={() => kickOff("Book a call with sales.")}>Book call</button>;
}
```

如果你需要对订阅的完全掌控（例如用于 Playwright 测试中的自定义
`useHeadlessInterrupt` 夹具），仍然可以使用上面定义的
`useHeadlessInterrupt` 里的原始原语：

```tsx
function HeadlessInterruptPanelRaw() {
  const { copilotkit } = useCopilotKit();
  const { agent } = useAgent({ agentId: "interrupt-headless" });
  const { pending, resolve } = useHeadlessInterrupt("interrupt-headless");

  const kickOff = (prompt: string) => {
    agent.addMessage({ id: crypto.randomUUID(), role: "user", content: prompt });
    void copilotkit.runAgent({ agent });
  };

  if (pending) {
    return (
      <div>
        <p>Pick a slot for {pending.value.topic ?? "a call"}:</p>
        {SLOTS.map((s) => (
          <button key={s.iso} onClick={() => resolve({ chosen_time: s.iso, chosen_label: s.label })}>
            {s.label}
          </button>
        ))}
        <button onClick={() => resolve({ cancelled: true })}>Cancel</button>
      </div>
    );
  }

  return <button onClick={() => kickOff("Book a call with sales.")}>Book call</button>;
}
```
