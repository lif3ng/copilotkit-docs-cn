## 这是什么？

人机协同（human-in-the-loop，HITL）让智能体在运行中途暂停，向用户
收集输入、确认或选择，然后把答案并回推理继续运行。正是它把自主式
工作流变成协作式工作流：智能体保留自己的上下文，用户握住方向盘。

## 何时使用人机协同？

以下情况适合使用人机协同：

- **质量控制** —— 在高风险决策点上设一道人工闸门
- **边缘情况** —— 智能体置信度不高时给出优雅的回退
- **专家输入** —— 借助用户补足模型缺乏的领域知识
- **可靠性** —— 为真实生产流量构建更稳健的循环

## CopilotKit 中人机协同的两种模式

<FrameworkSetup concept="human-in-the-loop-setup" />

CopilotKit 提供两种互补的方式来暂停智能体回合并向人提问。从外面看
它们很相似（聊天暂停、出现一个自定义组件、用户作答、运行恢复），
但它们在后端的接线不同，各有各的适用面。

| 模式 | 由谁决定暂停？ | 后端形态 |
| --- | --- | --- |
| `useHumanInTheLoop` | **LLM**，通过调用一个已注册的客户端工具 | 仅前端的工具描述（Zod schema + `render`） |
| `useInterrupt` | **图**，通过在节点中调用 `interrupt(...)` | LangGraph 智能体里的服务端 `interrupt()` 调用 |

**选 `useHumanInTheLoop`**，当暂停是一次_由智能体发起_的决策——
模型自己选择向用户提问——并且你想把选择器 UI
内联进常规的工具调用流程。

**选 `useInterrupt`**，当暂停是一个_由图强制_的检查点——代码路径
确定性地需要人给出答案——并且你想以 `langgraph.interrupt()`
作为服务端契约。

## 模式 1 —— `useHumanInTheLoop`（基于工具）

智能体在客户端用 `useHumanInTheLoop` 注册一个人机协同工具。当 LLM
调用该工具时，CopilotKit 把这次调用路由进你的 `render`
函数，后者显示一个自定义组件，并带着用户的答案调用 `respond`。
智能体把答案当作工具结果看到，并从这里继续。

## 模式 2 —— `useInterrupt`（由图暂停）

用 LangGraph 的 `interrupt()` 时，暂停由图本身强制执行：节点调用
`interrupt({...})`，运行挂起，客户端收到载荷、渲染一个 UI，并带着
用户的答案恢复运行。CopilotKit 的 `useInterrupt` hook
就是这份渲染契约。

完整走一遍（包括后端工具与 render-prop 接线）请看
[`useInterrupt` 深度解析](/human-in-the-loop/useInterrupt)。

## 走向无头

上面两种模式都带 `render` prop——CopilotKit
替你处理“何时显示选择器”的逻辑。如果你想从一个位于树中任意位置的
自定义 UI（不一定在聊天里）来驱动中断的解析，请看
[无头中断指南](/human-in-the-loop/headless)——它展示了如何组合
`useAgent`、`agent.subscribe` 与 `copilotkit.runAgent`，
构建你自己的 `useInterrupt` 等价物。
