你已经有了一个可用的 CopilotChat，希望用户能随消息一起附加文件——图像、PDF、音频、视频——让 AI 能够看到并作出回应。读完本指南后，你的聊天将支持拖放文件附件，并带有预览、灯箱查看和多模态 AI 响应。

## 快速开始

在你的 `CopilotChat` 组件上添加 `attachments`：

```tsx title="page.tsx"
import { CopilotChat } from "@copilotkit/react-core/v2";

<CopilotChat
  agentId="my-agent"
  attachments={{ enabled: true }} // [!code highlight]
/>
```

就这么简单。用户现在可以点击附件按钮，或将文件拖放到聊天中。这些文件会作为消息内容的一部分发送给你的智能体。

## 配置

`attachments` prop 接受一个 `AttachmentsConfig` 对象：

```tsx
<CopilotChat
  attachments={{
    enabled: true,
    // Omit `accept` to allow all file types (default: "*/*").
    // Restrict with a MIME filter if needed:
    accept: "image/*,audio/*,video/*,application/pdf",
    maxSize: 10 * 1024 * 1024,      // 10MB limit (default: 20MB)
  }}
/>
```

| 选项 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `enabled` | `boolean` | — | 在聊天输入框中启用文件附件。 |
| `accept` | `string` | `"*/*"` | MIME 类型过滤。支持 `"image/*"`、`".pdf,.docx"` 等模式，或逗号分隔的列表。 |
| `maxSize` | `number` | `20 * 1024 * 1024` | 文件大小上限（单位为字节）。 |
| `maxConcurrentUploads` | `number` | `1` | 同时上传的文件数量。参见[上传并发](#上传并发)。 |
| `onUpload` | `(file: File) => AttachmentUploadResult \| Promise<...>` | — | 自定义上传处理器。参见[自定义上传处理器](#自定义上传处理器)。 |
| `onUploadFailed` | `(error: AttachmentUploadError) => void` | — | 在文件未通过校验或上传失败时调用。参见[处理上传错误](#处理上传错误)。 |

## 支持的文件类型

附件会根据其 MIME 类型按模态分类：

| 模态 | MIME 类型 | 预览 | AI 支持 |
| --- | --- | --- | --- |
| **图像** | `image/*` | 缩略图 + 灯箱查看 | 大多数具备视觉能力的模型均支持（GPT-4o、Claude 等） |
| **音频** | `audio/*` | 音频播放器 | 取决于模型 |
| **视频** | `video/*` | 带播放按钮的缩略图 + 灯箱 | 取决于模型 |
| **文档** | 其余所有类型 | 文件图标 + 名称；PDF 与文本支持灯箱预览 | 以文件内容形式发送——模型支持程度不一 |

<Callout type="info">
  并非所有模型都支持所有模态。例如，OpenAI 的 GPT-4o 支持图像，但不支持音频文件部分。如果模型不支持某种文件类型，你会收到 `RUN_ERROR` 事件。请使用 `onError` 回调来优雅地处理这种情况。
</Callout>

## 自定义上传处理器

默认情况下，文件会以 base64 读取并内联发送。对于大文件或生产环境应用，你应该上传到自己的存储，然后改为传入 URL。

`onUpload` 返回一个 `AttachmentUploadResult`——一个包含两种变体的可辨识联合类型：

<Tabs items={["Base64（内联）", "URL（托管）"]}>
  <Tab value="Base64（内联）">
    ```tsx
    <CopilotChat
      attachments={{
        enabled: true,
        onUpload: async (file) => {
          const buffer = await file.arrayBuffer();
          const base64 = btoa(String.fromCharCode(...new Uint8Array(buffer)));
          return {
            type: "data",
            value: base64,
            mimeType: file.type,
          };
        },
      }}
    />
    ```
  </Tab>
  <Tab value="URL（托管）">
    ```tsx
    <CopilotChat
      attachments={{
        enabled: true,
        onUpload: async (file) => {
          const formData = new FormData();
          formData.append("file", file);
          const res = await fetch("/api/upload", { method: "POST", body: formData });
          const { url } = await res.json();
          return {
            type: "url",
            value: url,
            mimeType: file.type,
          };
        },
      }}
    />
    ```
  </Tab>
</Tabs>

### 添加元数据

你可以为任意上传附加自定义元数据。它会包含在发送给智能体的 `InputContent` 部分中，并可通过内容部分上的 `metadata` 访问。

```tsx
onUpload: async (file) => {
  const url = await uploadToStorage(file);
  return {
    type: "url",
    value: url,
    mimeType: file.type,
    metadata: {
      uploadedBy: currentUser.id,
      category: "support-ticket",
    },
  };
},
```

文件名会自动包含在元数据中——你无需自己添加。

## 上传并发

当用户一次附加多个文件时，默认会逐个上传。每个选中的文件都会立即出现在附件队列中，无论其上传是否已开始。

设置 `maxConcurrentUploads` 可以同时上传多个文件——当你的上传端点能处理并行请求时，值得调高该值：

```tsx
<CopilotChat
  attachments={{
    enabled: true,
    maxConcurrentUploads: 3, // three files at a time
    onUpload: async (file) => uploadToStorage(file),
  }}
/>
```

该限制针对的是所有进行中的上传，而不是每一批：如果在一批拖放的文件仍在上传时又粘贴了新文件，两者会共享同一组并发名额。设为 `Infinity` 可完全解除限制。

当该值大于 `1` 时，你的 `onUpload` 处理器可能被并发调用，因此它不能依赖前一个文件已完成上传。

## 处理上传错误

使用 `onUploadFailed` 来响应文件被拒绝或上传失败的情况——例如显示一个 toast 提示：

```tsx
<CopilotChat
  attachments={{
    enabled: true,
    accept: "image/*",
    maxSize: 5 * 1024 * 1024, // 5MB
    onUploadFailed: (error) => {
      // error.reason: "file-too-large" | "invalid-type" | "upload-failed"
      // error.file: the original File object
      // error.message: human-readable description
      toast.error(error.message);
    },
  }}
/>
```

| 原因 | 触发时机 |
| --- | --- |
| `invalid-type` | 文件不符合 `accept` 过滤条件。 |
| `file-too-large` | 文件超过 `maxSize`。 |
| `upload-failed` | `onUpload` 处理器抛出异常，或默认的 base64 读取器失败。 |

对于消息发送_之后_才发生的错误（例如模型不支持该文件类型），请使用 `CopilotChat` 上的 `onError` 回调：

```tsx
<CopilotChat
  attachments={{ enabled: true }}
  onError={(event) => {
    console.error(`[${event.code}]`, event.error.message);
  }}
/>
```

## 工作原理

当用户附加文件并发送消息时，CopilotKit 会：

1. 读取每个文件（通过默认的 base64 读取器或你的 `onUpload` 处理器）
2. 构建一个 `InputContent` 部分数组——文本 + 每个附件一个部分
3. 使用 `content: [{ type: "text", ... }, { type: "image", source: ... }, ...]` 将消息添加给智能体
4. 智能体通过 AG-UI 协议接收多模态内容，并将其转发给模型

附件属于标准 AG-UI `InputContent` schema 的一部分，因此任何兼容 AG-UI 的智能体（BuiltInAgent、LangGraph、自定义）都能接收它们。
