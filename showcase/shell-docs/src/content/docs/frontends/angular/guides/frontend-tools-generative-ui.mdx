前端工具让智能体可以调用用户浏览器中的代码。当工具需要在聊天中展示进度或结果时，在同一次注册中附加一个渲染器。

## 让智能体展示你的组件

这是最简单的生成式 UI，也是唯一一种在智能体侧无需任何配置的类型。`registerComponent` 把一个独立组件注册为工具，智能体可以调用它来展示该组件。何时调用由智能体决定，props 也由它填充。

```ts title="src/app/incident-card.component.ts"
import { Component, input } from "@angular/core";
import { AngularToolCall, ToolRenderer } from "@copilotkit/angular";

type IncidentArgs = { id: string; severity: string };

@Component({
  selector: "app-incident-card",
  standalone: true,
  template: `
    @let call = toolCall();
    @if (call.status === "in-progress") {
      <p>Loading incident…</p>
    } @else {
      <article>
        <strong>{{ call.args.id }}</strong>
        <span>{{ call.args.severity }}</span>
      </article>
    }
  `,
})
export class IncidentCardComponent implements ToolRenderer<IncidentArgs> {
  readonly toolCall = input.required<AngularToolCall<IncidentArgs>>();
}
```

```ts
registerComponent({
  name: "show_incident",
  description: "Show one incident from the incident table.",
  parameters: z.object({
    id: z.string().describe("The incident id, such as INC-4711"),
    severity: z.string().describe("One of sev1, sev2, sev3"),
  }),
  component: IncidentCardComponent,
});
```

这里没有 `handler`，智能体侧也不需要任何改动。该工具由前端声明并通过 AG-UI 转发，因此无论背后是 Python 智能体还是 TypeScript 智能体，行为都一致。

<Callout type="warn" title="组件格式正确不代表内容正确">
  模型会根据它所知道的内容填充这些 props。一张基于你的应用并不持有的记录渲染出来的卡片，在浏览器、截图和视频里看起来与正确的卡片毫无差别。使用 [`CopilotKitAgentContext`](/reference/angular/directives/CopilotKitAgentContext) 把页面数据共享给智能体，然后对照你持有的记录核对渲染出的字段。
</Callout>

## 注册浏览器工具

在 Angular 注入上下文中调用 `registerFrontendTool`。线上 Showcase 示例围绕一个可写 signal 构建了类型化的工具配置：

<AngularSnippet region="frontend-tool-registration" />

在组件或服务中通过 `registerFrontendTool(createBackgroundTool(background))` 注册该配置。当该注入器被销毁时，注册会随之移除。

schema 声明了输入的形状并提供 TypeScript 推断。运行时参数以解析后的 JSON 传入；当操作需要严格的信任边界时，请在 handler 内部进行校验。handler 的第二个参数会收到调用方智能体、原始工具调用以及一个可选的中止信号。

## 渲染工具结果

渲染器是一个带有必需 `toolCall` signal 输入的独立组件。其状态依次经历 `"in-progress"`、`"executing"` 和 `"complete"`。

```ts title="src/app/weather-card.component.ts"
import { Component, input } from "@angular/core";
import {
  type AngularToolCall,
  type ToolRenderer,
} from "@copilotkit/angular";

type WeatherArgs = { city: string };

@Component({
  selector: "app-weather-card",
  template: `
    @let call = toolCall();
    @if (call.status === "complete") {
      <article>
        <strong>{{ call.args.city }}</strong>
        <p>{{ call.result }}</p>
      </article>
    } @else {
      <p>Loading weather for {{ call.args.city ?? "…" }}</p>
    }
  `,
})
export class WeatherCardComponent implements ToolRenderer<WeatherArgs> {
  readonly toolCall = input.required<AngularToolCall<WeatherArgs>>();
}
```

当工具在浏览器中运行时，把该类作为 `component` 传入：

```ts
registerFrontendTool({
  name: "getWeather",
  description: "Get the current weather for a city",
  parameters: z.object({ city: z.string() }),
  component: WeatherCardComponent,
  handler: async ({ city }, { signal }) => {
    const response = await fetch(`/api/weather?city=${encodeURIComponent(city)}`, {
      signal,
    });
    return response.text();
  },
});
```

当工具在服务端运行、浏览器只负责渲染其调用时，改用 `registerRenderToolCall`：

```ts
registerRenderToolCall({
  name: "getWeather",
  args: z.object({ city: z.string() }),
  component: WeatherCardComponent,
});
```

## 选择生成式 UI 路径

| 路径 | 最适合的场景 | Angular 配置 |
| --- | --- | --- |
| 你的组件，仅展示 | 智能体只需展示一个组件，不运行其他逻辑 | `registerComponent` |
| 你的组件 | 数据形状已知且有应用操作 | `registerFrontendTool` 或 `registerRenderToolCall` 并附组件 |
| A2UI | 服务端发出 A2UI 操作或快照 | 在 `provideCopilotKit` 中设置 `a2ui.catalog` 以启用内置渲染器；没有目录时 A2UI 保持关闭 |
| Open Generative UI | 智能体生成流式 HTML、CSS 和脚本表达式 | 在 `provideCopilotKit` 中设置 `openGenerativeUI` |
| MCP Apps | MCP 服务器返回交互式应用资源 | 添加来自 `@copilotkit/angular/mcp-apps` 的 `provideMCPApps()` |

### Open Generative UI

`openGenerativeUI` 对象让前端接入内置的沙箱化渲染器。当生成的 UI 需要请求应用执行操作时，应暴露收窄范围的主机函数。

```ts title="src/app/app.config.ts"
import { ApplicationConfig } from "@angular/core";
import {
  provideCopilotKit,
  type SandboxFunction,
} from "@copilotkit/angular";
import { z } from "zod";

const setDashboardFilter: SandboxFunction<{ filter: string }> = {
  name: "setDashboardFilter",
  description: "Set the active dashboard filter",
  parameters: z.object({ filter: z.string() }),
  handler: async ({ filter }) => {
    sessionStorage.setItem("dashboard-filter", filter);
    return { applied: filter };
  },
};

export const appConfig: ApplicationConfig = {
  providers: [
    provideCopilotKit({
      runtimeUrl: "/api/copilotkit",
      openGenerativeUI: {
        sandboxFunctions: [setDashboardFilter],
      },
    }),
  ],
};
```

生成的代码运行在没有同源访问权限的沙箱 iframe 中。它只能调用你在 `sandboxFunctions` 中列出的主机函数。

### MCP Apps

```ts title="src/app/app.config.ts"
import { ApplicationConfig } from "@angular/core";
import { provideCopilotKit } from "@copilotkit/angular";
import { provideMCPApps } from "@copilotkit/angular/mcp-apps";

export const appConfig: ApplicationConfig = {
  providers: [
    provideCopilotKit({ runtimeUrl: "/api/copilotkit" }),
    provideMCPApps(),
  ],
};
```

MCP 资源与工具请求经由所选的 AG-UI 智能体传输。浏览器 provider 不接收服务器 URL。
