`@copilotkit/angular` 会自动挂载 Inspector。它直接依赖 `@copilotkit/web-inspector`，因此无需安装任何东西，也无需锁定版本——`CopilotKit` 服务会创建 `cpk-web-inspector` 元素，传入你应用的核心实例，并在首次浏览器渲染后将其追加到 `document.body`。

**[Inspector](/inspector)** 一页介绍了各个面板展示的内容，以及 `enableInspector` 如何控制可见性。Angular 通过 `provideCopilotKit` 设置它：

```ts title="src/app/app.config.ts"
provideCopilotKit({
  runtimeUrl: "http://localhost:8200/api/copilotkit",
  enableInspector: false, // hide it during development
});
```

<Callout type="warn" title="升级前移除手动挂载">
  **0.4.0** 之前，`@copilotkit/angular` 并不会挂载 Inspector，本页此前介绍的是手动创建元素的 `WebInspector` 组件。如果你的应用仍保留该组件，请将其删除——连同 `<app-web-inspector />` 的使用处，以及 `package.json` 中对 `@copilotkit/web-inspector` 的直接依赖。

  保留它不只是冗余，还会带来更糟的后果。框架会复用已存在的 `cpk-web-inspector`，而不是再创建一个，但手写组件的 `DestroyRef.onDestroy` 会无条件移除该元素——因此，一旦路由变更销毁了该组件，框架正在驱动的 Inspector 也会被一并拆除，且只有整页刷新才能恢复。
</Callout>

## 生产环境与服务器渲染

两者都无需任何操作。

`@copilotkit/web-inspector` 的导入是服务内部的一个动态 `import()`，打包器会将其拆分为独立的 chunk，生产构建永远不会请求它。挂载逻辑运行在 `afterNextRender` 中，并受 `isPlatformBrowser` 检查保护，因此服务器渲染期间绝不会创建该元素。这两点都很重要，因为该 Web 组件要向 `customElements` 注册自身，而服务器上并不存在 `customElements`。

## 调整启动器位置

启动器默认位于右上角，元素通过内联 transform 定位。两者都可以在全局样式表中覆盖。放在左下角可以让启动器避开聊天面板或侧边栏的关闭按钮：

```css title="src/styles.css"
cpk-web-inspector {
  /* The panel is draggable and sets an inline transform. Neutralize it before
     choosing a corner. */
  transform: none !important;
  top: auto !important;
  bottom: 1rem !important;
  left: 1rem !important;
  right: auto !important;
}
```
