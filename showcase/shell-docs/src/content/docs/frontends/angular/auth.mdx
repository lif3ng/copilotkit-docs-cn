## 身份验证保护什么

CopilotKit 的身份验证覆盖两个边界：

1. 你的 Angular 应用把当前的会话令牌发送给 Copilot Runtime。
2. Copilot Runtime 在运行开始前验证该令牌，并只把获批准的
   身份或租户上下文转发给所选的智能体。

模型凭证与服务间（service-to-service）智能体令牌要保存在服务器上。
浏览器请求头只能证明最终用户的会话，并不是存放
后端机密的安全之处。

## 发送当前会话

在 `provideCopilotKit` 中设置初始请求头：

```ts title="src/app/app.config.ts"
import { ApplicationConfig } from "@angular/core";
import { provideCopilotKit } from "@copilotkit/angular";

export const appConfig: ApplicationConfig = {
  providers: [
    provideCopilotKit({
      runtimeUrl: "/api/copilotkit",
      headers: {
        Authorization: `Bearer ${readSessionToken()}`,
      },
    }),
  ],
};
```

当登录状态在应用启动后发生变化时，通过 `CopilotKit` 服务更新运行时连接：

```ts
import { inject } from "@angular/core";
import { CopilotKit } from "@copilotkit/angular";

const copilotKit = inject(CopilotKit);

copilotKit.updateRuntime({
  headers: sessionToken
    ? { Authorization: `Bearer ${sessionToken}` }
    : {},
});
```

## 向跨域运行时发送 cookies

要启用 HTTP-only cookie 身份验证，请设置 `credentials: "include"`，
并在你的运行时端点上配置 CORS：

```ts title="src/app/app.config.ts"
import { ApplicationConfig } from "@angular/core";
import { provideCopilotKit } from "@copilotkit/angular";

export const appConfig: ApplicationConfig = {
  providers: [
    provideCopilotKit({
      runtimeUrl: "https://runtime.example.com/api/copilotkit",
      credentials: "include",
    }),
  ],
};
```

在运行时上配置 `credentials: true` 以及 Angular 应用的确切
源。带凭证的 CORS 请求不能使用 `*` 作为允许的源。

## 校验每一个运行时请求

使用运行时适配器的请求钩子，在 CopilotKit 发现或运行智能体之前，拒绝缺失、过期或
未授权的会话：

```ts title="server.ts"
const handler = createCopilotExpressHandler({
  runtime,
  basePath: "/api/copilotkit",
  hooks: {
    onRequest: async ({ request }) => {
      const token = request.headers
        .get("authorization")
        ?.replace(/^Bearer\s+/i, "");
      const session = token ? await verifySession(token) : null;

      if (!session) {
        throw new Response("Unauthorized", { status: 401 });
      }
    },
  },
});
```

在身份验证之外还要应用授权。一个有效的用户令牌并不意味着
自动获得对所有智能体、租户或线程的访问权。

## 有选择地转发身份

Copilot Runtime 会把 `authorization` 与符合条件的 `x-*` 请求头转发给
自托管智能体，并受其拒绝名单约束。如果你的智能体只需要特定上下文，
建议使用一个小型允许名单：

```ts
const runtime = new CopilotRuntime({
  agents: { default: myAgent },
  forwardHeaders: {
    allow: ["authorization", "x-tenant-id"],
  },
});
```

服务器配置的智能体请求头优先于转发的浏览器请求头。请利用这种
分离来存放服务凭证，绝不要允许浏览器提供的请求头
覆盖后端令牌。

## 生产环境检查清单

- 对 `/info`、run、connect、stop、thread 与 memory 请求都做校验——而不只是
  聊天发送。
- 从已验证的会话派生用户与租户标识，而不是轻信任意的浏览器值。
- 把线程操作限定在已验证的用户与项目范围内。
- 登出时用 `updateRuntime({ headers: {} })` 清空前端请求头。
- 为部署后的 Angular 源配置 CORS。
- 记录授权失败，但不要记录 bearer 令牌。
