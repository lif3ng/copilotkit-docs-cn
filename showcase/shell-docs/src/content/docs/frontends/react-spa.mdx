本文档站的其余部分就是 React 文档。[前端工具](/frontend-tools)、[生成式 UI](/generative-ui)、[人机协同](/human-in-the-loop)、[无头 UI](/headless)、[预构建组件](/prebuilt-components)以及 [React 参考](/reference/v2)在 Vite 或 Create React App 项目中原样可用。

只有一条说明不能照搬：**Copilot Runtime 部署在哪里**。各快速开始假定 Next.js 从同一源（origin）同时提供应用和运行时，因此使用相对的 `runtimeUrl`（`/api/copilotkit`）。单页应用没有服务器，也没有共享源，这个路径解析不出任何东西。本页只讲这一处差异，其余内容请回到上面的页面。

## 从编码智能体开始

使用下面的提示词把 React 单页应用连接到单独托管的 Copilot Runtime，并验证对话确实可用。也可以按下面的手动步骤操作。

## 前置条件

- 一个 OpenAI API 密钥（或[模型选择](/model-selection)支持的其他模型提供方）
- React 18+
- Node.js 20.6+（用于 `--env-file`）

## 开始使用

<Steps>
    <Step>
        ### 创建你的 React 应用

        如果还没有：

        ```bash
        npm create vite@latest my-copilot-app -- --template react-ts
        cd my-copilot-app
        npm install
        ```

        已有的 Create React App 项目同样适用——只有最后一步的 dev server 命令不同。
    </Step>
    <Step>
        ### 安装 CopilotKit

        安装 React 前端包，以及用于本地 Copilot Runtime 服务器的 `@copilotkit/runtime`：

        <Tabs groupId="package-manager" items={['npm', 'pnpm', 'yarn']}>
            <Tab value="npm">
                ```bash
                npm install @copilotkit/react-core @copilotkit/runtime
                npm install -D tsx typescript @types/node
                ```
            </Tab>
            <Tab value="pnpm">
                ```bash
                pnpm add @copilotkit/react-core @copilotkit/runtime
                pnpm add -D tsx typescript @types/node
                ```
            </Tab>
            <Tab value="yarn">
                ```bash
                yarn add @copilotkit/react-core @copilotkit/runtime
                yarn add -D tsx typescript @types/node
                ```
            </Tab>
        </Tabs>
    </Step>
    <Step>
        ### 创建 Copilot Runtime

        你的 SPA 没有服务器，因此运行时需要自带一个。添加一个小的 Node 服务器，在它自己的端口上通过 `/api/copilotkit` 承载 Copilot Runtime，并注册一个 `default` 内置智能体：

        ```ts title="server.ts"
        import { createServer } from "node:http";
        import { BuiltInAgent, CopilotRuntime } from "@copilotkit/runtime/v2";
        import { createCopilotNodeListener } from "@copilotkit/runtime/v2/node";

        const runtime = new CopilotRuntime({
          agents: {
            default: new BuiltInAgent({
              model: "openai:gpt-5-mini",
              prompt: "You are a helpful assistant for a React app.",
            }),
          },
        });

        const port = 8200;

        createServer(
          createCopilotNodeListener({
            runtime,
            basePath: "/api/copilotkit",
            cors: true, // [!code highlight]
          }),
        ).listen(port, () => {
          console.log(
            `Copilot Runtime listening at http://localhost:${port}/api/copilotkit`,
          );
        });
        ```

        <Callout type="warn" title="这里必须设 `cors: true`，且它并非默认值">
          你的应用与运行时位于不同的源，因此运行时必须显式启用 CORS。`createCopilotNodeListener` 与 `createCopilotRuntimeHandler` **默认关闭 CORS**——省略 `cors` 时，每个浏览器请求都会在预检阶段失败。这一点与 Express 和 Hono 适配器不同，它们默认放行 CORS。部署前请参见[运行时端点](/backend/runtime-endpoints)了解按源配置与携带凭据的配置方式。
        </Callout>
    </Step>
    <Step>
        ### 导入样式

        在应用入口导入一次包的样式表。它是自包含的，聊天无需任何其他 CSS 即可渲染。

        ```tsx title="src/main.tsx"
        import React from "react";
        import ReactDOM from "react-dom/client";
        import App from "./App";
        import "@copilotkit/react-core/v2/styles.css"; // [!code highlight]

        ReactDOM.createRoot(document.getElementById("root")!).render(
          <React.StrictMode>
            <App />
          </React.StrictMode>,
        );
        ```
    </Step>
    <Step>
        ### 连接 Copilot Runtime

        把 `CopilotKitProvider` 指向运行时端点，并放入 `CopilotChat`。由于运行时注册了名为 `default` 的智能体，聊天会自动选用它。

        ```tsx title="src/App.tsx"
        import { CopilotKitProvider, CopilotChat } from "@copilotkit/react-core/v2";

        export default function App() {
          return (
            /* [!code highlight:5] */
            <CopilotKitProvider runtimeUrl="http://localhost:8200/api/copilotkit">
              <div style={{ height: "100vh" }}>
                <CopilotChat />
              </div>
            </CopilotKitProvider>
          );
        }
        ```

        <Callout type="warn" title="`runtimeUrl` 必须是绝对地址">
          各框架快速开始都使用相对的 `runtimeUrl="/api/copilotkit"`。它之所以**能**用，只是因为 Next.js 从同一源提供应用和运行时。在单页应用中，运行时是独立端口上的独立进程，因此 URL 必须写全——包括主机和端口。请从环境变量读取它（Vite 中为 `import.meta.env.VITE_COPILOT_RUNTIME_URL`），以便生产环境指向已部署的运行时。
        </Callout>

        要使用某个集成快速开始中的命名智能体，把 `agentId` 设为运行时 `agents` 映射中注册的键：

        ```tsx
        <CopilotKitProvider
          runtimeUrl="http://localhost:8200/api/copilotkit"
          agentId="sample_agent"
        >
          <CopilotChat />
        </CopilotKitProvider>
        ```

        `CopilotKitProvider` 使用的是 `agentId`；旧版 `<CopilotKit>` 示例中出现的 `agent` prop 不是 provider 的 prop。使用上面的 `default` 智能体时，省略 `agentId` 即可。

        <Callout type="info" title="选择你的聊天布局">
          `CopilotChat` 是全高的聊天。要换布局，可以换成 `CopilotSidebar`（可折叠侧边栏）或 `CopilotPopup`（浮动挂件）。它们接受相同的 props。
        </Callout>
    </Step>
    <Step>
        ### 启动运行时与应用

        你要运行两个开发服务器，因此它们需要两个不同的端口。在创建服务器凭据文件之前，先在项目的 `.gitignore` 中加入这一项：

        ```gitignore title=".gitignore"
        .env
        ```

        在 `server.ts` 旁创建 `.env`：

        ```dotenv title=".env"
        OPENAI_API_KEY=sk-...
        ```

        在一个终端中，从该目录启动 Copilot Runtime：

        ```bash
        npx tsx --env-file=.env server.ts
        ```

        独立的 Node 进程不会自动加载 `.env`。这个 flag 会在运行时导入执行之前加载它——连接 [Intelligence](/intelligence/quickstart) 时也包括 `CPK_INTELLIGENCE_API_KEY`。如果 CLI 把 `.env` 写在了上级目录，就把 `--env-file` 指向那个文件。服务器凭据不要放进 `VITE_*` 变量，它们会暴露给浏览器。

        `--env-file` flag 会保留 shell 中已设置的变量。
        如果本地开发时项目的 `.env` 应覆盖这些值，请安装 `dotenv`，
        并在 `server.ts` 中构造智能体之前加入以下代码：

        <Tabs groupId="package-manager" items={['npm', 'pnpm', 'yarn']}>
            <Tab value="npm">
                ```bash
                npm install dotenv
                ```
            </Tab>
            <Tab value="pnpm">
                ```bash
                pnpm add dotenv
                ```
            </Tab>
            <Tab value="yarn">
                ```bash
                yarn add dotenv
                ```
            </Tab>
        </Tabs>

        ```ts title="server.ts —— 加载项目环境变量"
        import { config } from "dotenv";

        config({
          path: new URL("./.env", import.meta.url),
          override: true,
        });
        ```

        这个路径选中的是 `server.ts` 旁边的 `.env`。只有当该文件应优先于继承的 shell 环境时，才使用 `override: true`。不加它时，导出的 `OPENAI_API_KEY` 会胜出，即使 `.env` 中是另一个密钥——这可能把请求发到错误的项目，或导致模型认证错误。密钥要留在服务端；不要加 `VITE_` 前缀，也不要放进前端代码。

        在另一个终端中启动 React 应用：

        ```bash
        npm run dev
        ```

        Vite 服务于 `http://localhost:5173`，运行时在 `8200`，默认值互不冲突。如果需要给应用换端口，传 `--port`——**Vite 会忽略 `PORT` 环境变量**，这与 Create React App 不同：

        ```bash
        npm run dev -- --port 3000
        ```

        在打开应用之前，先确认运行时就绪：

        ```bash
        curl --fail --silent --show-error http://localhost:8200/api/copilotkit/info
        ```

        等这条命令成功、且 JSON 包含上面注册的 `default` 智能体后再继续。

        如果某个 dev 脚本同时启动两个进程，打开浏览器前也要等待同样的运行时就绪检查。Vite 服务器开始监听并不意味着独立的运行时已就绪。打开过早会让应用的初始运行时连接停留在错误状态；如果已经发生，等 `/info` 成功后刷新页面即可。

        打开 dev server 的 URL，发送一条消息，你会看到它经由 Copilot Runtime 流式返回。

        <Accordions className="mb-4">
            <Accordion title="故障排查">
                - **CORS 错误，或请求在预检阶段失败**：在 `createCopilotNodeListener` 中保留 `cors: true`。它默认是关闭的，这也是“聊天渲染出来却始终不响应”最常见的原因。
                - **`/api/copilotkit` 返回 404**：你的 `runtimeUrl` 是相对路径。SPA 需要绝对的 `http://localhost:8200/api/copilotkit`。
                - **智能体无响应**：确认运行时服务器正在运行，且 `http://localhost:8200/api/copilotkit/info` 返回智能体信息。
                - **聊天没有样式**：确保在应用入口导入了 `@copilotkit/react-core/v2/styles.css`。
                - **模型认证错误或 Intelligence 未配置**：确认运行时以 `npx tsx --env-file=.env server.ts` 启动，且所选 env 文件包含必需的服务器凭据。Vite 加载自己的 env 文件并不会配置运行时进程。
            </Accordion>
        </Accordions>
    </Step>
    <Step>
        <OpenInspectorStep components={props.components} />
    </Step>
</Steps>

## 使用 Intelligence 连接远程智能体

大多数集成快速开始把智能体作为独立服务器运行，并把运行时展示为 Next.js 路由处理器。对单页应用，把同样的运行时放进 `server.ts` 即可。本例用 `HttpAgent` 注册位于 `http://localhost:8000/` 的智能体服务器，并把运行时连接到 [Intelligence](/intelligence/quickstart)。

按照 `@copilotkit/runtime` 所依赖的版本安装 AG-UI 客户端：

```bash
npm install @ag-ui/client@1.0.2
```

```ts title="server.ts"
import { createServer } from "node:http";
import { HttpAgent } from "@ag-ui/client";
import {
  CopilotKitIntelligence,
  CopilotRuntime,
} from "@copilotkit/runtime/v2";
import { createCopilotNodeListener } from "@copilotkit/runtime/v2/node";

const runtime = new CopilotRuntime({
  agents: {
    my_agent: new HttpAgent({ url: "http://localhost:8000/" }),
  },
  intelligence: new CopilotKitIntelligence({
    apiKey: process.env.CPK_INTELLIGENCE_API_KEY!,
  }),
  // Local development only. See the warning below.
  identifyUser: (request) => ({
    id: request.headers.get("x-user-id") ?? "anonymous",
    name: request.headers.get("x-user-name") ?? "Anonymous",
  }),
});

const port = 8200;

createServer(
  createCopilotNodeListener({
    runtime,
    basePath: "/api/copilotkit",
    cors: true,
  }),
).listen(port, () => {
  console.log(
    `Copilot Runtime listening at http://localhost:${port}/api/copilotkit`,
  );
});
```

<Callout type="warn" title="部署前替换基于 header 的身份标识">
  这里的 `identifyUser` 信任 `x-user-id` header，任何调用者都能冒充任意用户，不带该 header 的请求则会共享 `anonymous` 线程。请从经过验证的会话或令牌返回用户，并拒绝没有凭据的请求。`identifyUser` 不会对 `threads/events` 与 `threads/state` 路由做范围限定，请为它们自行添加归属校验。参见[线程授权](/auth#thread-authorization)。
</Callout>

在 `server.ts` 旁运行 `npx copilotkit@latest project select`，把 `CPK_INTELLIGENCE_API_KEY` 写入 `.env`。然后按上面步骤中的方式，用 `npx tsx --env-file=.env server.ts` 启动运行时。

在前端，把 `agentId` 设为 `agents` 映射中的键：

```tsx
<CopilotKitProvider
  runtimeUrl="http://localhost:8200/api/copilotkit"
  agentId="my_agent"
>
  <CopilotChat />
</CopilotKitProvider>
```

使用 Intelligence 时，run 路由不会把事件流式推给浏览器，provider 会通过 websocket 从 Intelligence 读取它们。参见[使用 Intelligence 运行与连接](/backend/runtime-endpoints#run-and-connect-with-intelligence)。
