## 这是什么？

`#interrupt` 插槽是覆盖 80% 场景的路径：它让 UI 保持在 `<CopilotChat>` 会话记录之中，并处理何时显示选择器。本页介绍的是一条“逃生通道”：设置 `renderInChat: false`，在 Vue 树的任意位置渲染响应式的中断状态。UI 可以是任何形态——按钮网格、表单、模态框、键盘快捷键——而且完全不需要挂载聊天组件。

<WhenFrameworkHas flag="interrupt_pattern" equals="native">

在原生中断运行时上，后端会暂停运行并将中断发送到客户端。Vue composable 通过 `slotProps` 将其暴露出来，随后 `resolve(...)` 或 `cancel(...)` 会按照当前的 AG-UI 标准流程恢复运行。同时也支持旧版 `on_interrupt` 事件，其传输层差异见下文。

</WhenFrameworkHas>

<WhenFrameworkHas flag="interrupt_pattern" equals="promise-based">

对于基于 Promise 的集成，没有原生的中断原语。可以用 `useHumanInTheLoop` 构建相同的无头体验：它的前端工具处理器让一个 Promise 保持挂起，应用状态在聊天之外渲染选择器，而用户的回答会解决该工具调用。

</WhenFrameworkHas>

<WhenFrameworkHas flag="interrupt_pattern" absent>

> **此框架不支持该功能**。无头运行时中断需要原生的中断传输通道。对于其他集成，请使用 [`useHumanInTheLoop`](../human-in-the-loop) 实现基于工具调用的暂停/恢复流程。

</WhenFrameworkHas>

## 何时应该使用它？

- **测试 / Playwright fixture** —— 一个确定性的、无聊天界面的按钮网格，比 LLM 调用后才出现的选择器更容易驱动。
- **非聊天 UI** —— 仪表盘、侧边面板、检查器界面，或任何你想要智能体中断但不要会话记录的地方。
- **自定义流程控制** —— 当你需要确切知道中断何时到达、何时被解决时。
- **研究 / 调试** —— 当你想在脱离聊天抽象的情况下观察原始中断状态时。

如果你只想要聊天中的选择器，请使用 [`useInterrupt`](./useInterrupt) 的默认 `renderInChat: true` 配合 `#interrupt` 插槽。

## 基础原语

<FrameworkSetup concept="programmatic-control-setup" />

最简单的无头模式使用 `useInterrupt({ renderInChat: false })`。这个 composable 不会把状态发布到 `<CopilotChat>`，而是返回响应式 ref，由你放置在任意位置：

```vue title="src/components/ApprovalPanel.vue"
<script setup lang="ts">
import { useInterrupt } from "@copilotkit/vue/v2";

const { slotProps } = useInterrupt({
  agentId: "interrupt-headless",
  renderInChat: false,
});
</script>

<template>
  <section v-if="slotProps" class="approval-panel">
    <p>{{ slotProps.interrupt?.message ?? "Approve this action?" }}</p>
    <button @click="slotProps.resolve({ approved: true })">Approve</button>
    <button @click="slotProps.cancel()">Cancel</button>
  </section>
</template>
```

`interrupt` 携带主要的 AG-UI `Interrupt` 对象（`{ id, reason, message?, responseSchema?, expiresAt?, ... }`）。`resolve(payload)` 提交用户的响应；`cancel()` 提交一个已取消的响应。两者都返回 `Promise<RunAgentResult | void>` —— 当有多个中断同时打开时，在等待后续中断期间为 `void`。

在内部，`useInterrupt` 组合了两个公开 API：

1. **`agent.subscribe({ onCustomEvent, onRunStartedEvent, onRunFinishedEvent, onRunFinalized, onRunFailed })`** —— 标准中断通过 `onRunFinishedEvent` 到达，形如 `{ outcome: "interrupt", interrupts: [...] }`；旧版中断则作为名为 `on_interrupt` 的自定义事件到达。
2. 标准传输通道使用 **`copilotkit.runAgent({ agent, resume })`**，旧版传输通道使用 **`copilotkit.runAgent({ agent, forwardedProps: { command: { resume, interruptEvent } } })`** —— 这正是 `resolve()` 与 `cancel()` 内部所做的调用。

这个 composable 会谨慎地做到：

- 只有在运行结束后才呈现标准中断，避免运行仍在流式传输时选择器闪现。
- 在新运行开始时清除过期的挂起状态。
- 在运行失败后丢弃暂存状态，避免传输错误让 UI 卡死。

</WhenFrameworkHas>

<WhenFrameworkHas flag="interrupt_pattern" equals="promise-based">

## 基础原语

注册一个 `useHumanInTheLoop` 工具，并用一个 Vue 渲染组件把挂起的请求反映到应用状态中。在该组件调用 `respond(...)` 之前，工具的处理器一直保持挂起；整个过程不涉及运行时中断或聊天插槽。

用工具调用 id 区分并发调用，在用户响应后清除挂起状态；如果真正的选择器位于应用的其他位置，就让渲染组件在视觉上保持空白。

</WhenFrameworkHas>

## 从普通 UI 驱动

当同一个页面既要启动运行、又要解决其暂停时，可以组合使用 `useAgent`、`useCopilotKit` 与无头中断状态：

```vue title="src/components/HeadlessInterruptPanel.vue"
<script setup lang="ts">
import { toRaw } from "vue";
import { useAgent, useCopilotKit, useInterrupt } from "@copilotkit/vue/v2";

const { agent } = useAgent({ agentId: "interrupt-headless" });
const { copilotkit } = useCopilotKit();
const { slotProps } = useInterrupt({
  agentId: "interrupt-headless",
  renderInChat: false,
});

async function kickOff(prompt: string) {
  const current = agent.value;
  if (!current || current.isRunning) return;

  current.addMessage({
    id: crypto.randomUUID(),
    role: "user",
    content: prompt,
  });
  await copilotkit.value.runAgent({ agent: toRaw(current) });
}
</script>

<template>
  <section v-if="slotProps">
    <p>{{ slotProps.interrupt?.message ?? "Pick an option" }}</p>
    <button @click="slotProps.resolve({ choice: 'approve' })">Approve</button>
    <button @click="slotProps.cancel()">Cancel</button>
  </section>
  <button v-else @click="kickOff('Prepare the governed action.')">
    Start
  </button>
</template>
```

如果你需要自定义的累积逻辑或确定性的测试 fixture，可以直接订阅该智能体。对于普通的产品 UI，公开的 `useInterrupt` composable 已经处理了标准与旧版传输通道、多个中断、清理以及恢复提交。

</WhenFrameworkHas>

## Provider 配置

调用这些 composable 的组件必须位于 `CopilotKitProvider` 之下：

```vue title="src/App.vue"
<script setup lang="ts">
import { CopilotKitProvider } from "@copilotkit/vue/v2";
import HeadlessInterruptPanel from "./components/HeadlessInterruptPanel.vue";
</script>

<template>
  <CopilotKitProvider runtime-url="/api/copilotkit">
    <HeadlessInterruptPanel />
  </CopilotKitProvider>
</template>
```
