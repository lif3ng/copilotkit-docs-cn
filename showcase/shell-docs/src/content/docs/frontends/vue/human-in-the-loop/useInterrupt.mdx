## 这是什么？

`useInterrupt` 让你的智能体在运行中途暂停，通过自定义 Vue UI 把控制权交给用户，并带着用户返回的内容恢复运行。这一暂停如何实现取决于框架的运行时。

<WhenFrameworkHas flag="interrupt_pattern" equals="native">

LangGraph 提供一等公民的 [`interrupt()`](https://docs.langchain.com/oss/python/langgraph/interrupts) 原语，让正在运行的节点挂起自身并把控制权交给客户端。运行在服务端被冻结，直到客户端带着载荷解决该中断；此时节点恢复执行，就好像 `interrupt()` 只是返回了那个载荷。

CopilotKit 的 `useInterrupt` 是这一契约的前端部分：它订阅被暂停的运行，暴露响应式的中断状态，并带着用户的答案恢复智能体。

</WhenFrameworkHas>

<WhenFrameworkHas flag="interrupt_pattern" equals="promise-based">

一些运行时无法像 LangGraph 的 `interrupt()` 那样在工具执行中途暂停运行。此时请改用 `useHumanInTheLoop` 走基于 Promise 的前端工具路径：智能体调用工具，客户端让请求保持打开，用户作答后 Promise 得到解决。UX 相同——智能体暂停、用户作答、智能体恢复——底层机制不同。

</WhenFrameworkHas>

<WhenFrameworkHas flag="interrupt_pattern" absent>

> **此框架不支持该功能。**`useInterrupt` 只有在底层运行时暴露原生中断原语时才有意义。对于其他集成，请改用 [`useHumanInTheLoop`](../human-in-the-loop) —— 它是基于工具调用的暂停/恢复流程的标准钩子，可用于所有支持前端工具的框架。

</WhenFrameworkHas>

## 何时应该使用它？

当暂停是一个**由图强制执行的检查点**——代码路径*必须*停下来等待人工，而不是由 LLM 发起的工具调用——时，使用 `useInterrupt`。典型情况：

- 敏感操作（支付、不可逆写入）必须经过批准
- 某项必需的状态未知，只能从用户处收集
- 智能体在较长的工作流中明确到达一个审批节点
- 你希望服务端契约是 `interrupt(...)` 并带着载荷恢复

对于由 LLM 发起、模型临时决定询问用户的暂停，请优先使用 [`useHumanInTheLoop`](../human-in-the-loop)。

## 后端：工具内的 `interrupt()`

<FrameworkSetup concept="human-in-the-loop-setup" />

智能体可以暴露一个 `schedule_meeting` 工具，它携带会议上下文发出中断。运行会冻结，直到客户端解决该中断；解决内容成为 `interrupt()` 的返回值，工具随后为模型解读它。

有两点需要注意：

- 载荷（例如 `{ "topic": topic, "attendee": attendee }`）就是 Vue 前端收到的 `event.value`。请保持它是一个简单的可序列化对象，包含 UI 所需的暂停时刻上下文。
- 返回侧的契约（例如 `{ chosen_label, chosen_time }` 或 `{ cancelled: true }`）完全由你定义。客户端可以发送任何可序列化的解决载荷；由工具赋予其含义，并且必须在产生副作用之前对其进行校验。

## 前端：`useInterrupt` 与聊天插槽

在后代组件中注册 `useInterrupt`。使用默认的 `renderInChat: true` 时，composable 会把待处理的中断发布到 `CopilotChat`；通过 `#interrupt` 作用域插槽渲染它，并调用 `resolve(...)` 恢复运行：

```vue title="src/components/MeetingChat.vue"
<script setup lang="ts">
import { CopilotChat, useInterrupt } from "@copilotkit/vue/v2";

useInterrupt<{ topic: string; attendee: string }>({
  agentId: "gen-ui-interrupt",
});
</script>

<template>
  <CopilotChat agent-id="gen-ui-interrupt">
    <template #interrupt="{ event, resolve }">
      <section>
        <p>Pick a time for {{ (event.value as { topic: string }).topic }}</p>
        <button
          @click="resolve({ chosen_label: 'Tomorrow', chosen_time: '2026-09-01T09:00:00Z' })"
        >
          Tomorrow at 09:00
        </button>
        <button @click="resolve({ cancelled: true })">Cancel</button>
      </section>
    </template>
  </CopilotChat>
</template>
```

你传给 `resolve` 的任何内容都会原样往返，作为对应中断的返回值回到智能体。

</WhenFrameworkHas>

## 前端：使用带 Promise 解决处理器的 `useHumanInTheLoop`

`useHumanInTheLoop` 注册一个前端工具，其处理器保持挂起，直到被渲染的 Vue 组件调用 `respond(...)`。这是 `useInterrupt` 的 `event` / `resolve` 组合在前端工具层面的对应物。

## 后端：指示智能体调用前端工具

智能体没有这个审批工具的本地实现。后端指示模型在需要输入时调用它；AG-UI 把工具调用路由到客户端，由返回 Promise 的处理器接管。

</WhenFrameworkHas>

### 关键 props

- **`agentId`** —— 必须与运行时注册的智能体匹配。若省略，composable 会假定使用默认智能体。不匹配意味着中断永远不会出现。
- **`renderInChat`** —— 为 `true` 时，`slotProps` 会发布到聊天的 `#interrupt` 插槽。当你的组件要在别处渲染返回的 ref 时，请将其设为 `false`。
- **`handler`** —— 可选地对中断进行预处理，可以提前解决它，并将其返回值作为 `result` 暴露。
- **`enabled`** —— 在中断呈现之前对其形态进行过滤。

Vue 的 `#interrupt` 插槽收到 `{ event, result, resolve }`。要获得完整的标准中断接口——包括 `interrupt`、`interrupts` 与 `cancel`——请在 `renderInChat: false` 下使用 composable 返回的 `slotProps`。

## 多个中断？用 `type` 标记并用 `enabled` 门控

如果你的图会发出不止一种中断，就用 `type` 字段标记每个载荷，并为每种形态安装一个 `useInterrupt`，各自用 `enabled` 门控：

```ts
useInterrupt({
  agentId: "gen-ui-interrupt",
  enabled: (event) => (event.value as { type?: string }).type === "ask",
});

useInterrupt({
  agentId: "gen-ui-interrupt",
  enabled: (event) => (event.value as { type?: string }).type === "approval",
});
```

## 用 `handler` 预处理

当中断有时可以*无需*用户输入就被解决时，传入一个在 UI 渲染之前运行的 `handler`。该处理器可以自行调用 `resolve(...)` 提前恢复智能体，或返回一个作为 `result` 暴露的值：

```ts
const { slotProps } = useInterrupt({
  agentId: "gen-ui-interrupt",
  renderInChat: false,
  handler: async ({ event, resolve }) => {
    const department = await lookupUserDepartment();
    const required = (event.value as { accessDepartment: string })
      .accessDepartment;

    if (required === department || department === "admin") {
      await resolve({ code: "AUTH_BY_DEPARTMENT" });
      return;
    }

    return { department };
  },
});
```

</WhenFrameworkHas>

## AG-UI 标准中断流程与旧版流程

`useInterrupt` 支持两种中断传输通道。了解你的智能体使用哪一种，有助于你编写正确的 UI。

### 标准流程（`RUN_FINISHED` 且 `outcome.type === "interrupt"`）

当智能体后端遵循 AG-UI 协议时，它通过发出一个 `RUN_FINISHED` 事件来标记中断，其 outcome 携带中断数组：

```text
outcome.type === "interrupt"
outcome.interrupts  // Interrupt[]
```

composable 在 `onRunFinishedEvent` 上检测到这一点，并在 `onRunFinalized` 触发后暴露这些中断。`slotProps.value` 包含：

- **`interrupt`** —— 主 `Interrupt`（`interrupts[0]`），形态为 `{ id, reason, message?, toolCallId?, responseSchema?, expiresAt?, metadata? }`。
- **`interrupts`** —— 全部打开的中断集合。
- **`resolve(payload?, interruptId?)`** —— 为目标中断记录一条已解决的响应。一旦每个打开的中断都有响应，运行即恢复。
- **`cancel(interruptId?)`** —— 为目标中断记录一条已取消的响应。同样适用先累积后提交的逻辑。

### 旧版流程（`on_interrupt` 自定义事件）

较旧的智能体可能发出自定义的 `on_interrupt` 事件。composable 在 `event.value` 中暴露其载荷，同时 `interrupt` 为 `null`、`interrupts` 为 `[]`。调用 `resolve(payload)` 会通过旧版机制 `forwardedProps.command` 恢复运行。`cancel()` 只会关闭中断而不恢复运行，因为旧版传输通道没有取消响应。

### 优先级

如果两种信号出现在同一次运行中，以标准流程为准。

### 批准 / 取消示例

```vue title="src/components/ApprovalPanel.vue"
<script setup lang="ts">
import { useInterrupt } from "@copilotkit/vue/v2";

const { slotProps } = useInterrupt({ renderInChat: false });
</script>

<template>
  <section v-if="slotProps">
    <p>{{ slotProps.interrupt?.message ?? "Approve this action?" }}</p>
    <button @click="slotProps.resolve({ approved: true })">Approve</button>
    <button @click="slotProps.cancel()">Cancel</button>
  </section>
</template>
```

两种方法都会在运行重启后返回 `RunAgentResult`，或在等待其他打开中断的响应期间返回 `void`。

### 多中断行为

一些智能体会在单次运行中发出多个中断。每个中断都有自己的 `id`；请逐一处理：

```vue
<template>
  <ul v-if="slotProps">
    <li v-for="item in slotProps.interrupts" :key="item.id">
      {{ item.message }}
      <button @click="slotProps.resolve({ ok: true }, item.id)">Approve</button>
      <button @click="slotProps.cancel(item.id)">Cancel</button>
    </li>
  </ul>
</template>
```

只有在**每一个**打开的中断都被处理之后，智能体运行才会恢复。如果省略 `interruptId`，则目标为主中断；当有多个中断打开时 Vue 会发出警告。

### `responseSchema` —— 仅用于展示，不做客户端校验

`Interrupt` 类型暴露一个 `responseSchema` JSON Schema，智能体可以用它描述期望的载荷。`useInterrupt` 会在 `interrupt.responseSchema` 上展示它供你的 UI 读取，但它**不会**据此校验 `resolve` 载荷。校验是智能体在恢复时的责任。

## Provider 配置

调用 `useInterrupt` 的组件必须是 `CopilotKitProvider` 的后代：

```vue title="src/App.vue"
<script setup lang="ts">
import { CopilotKitProvider } from "@copilotkit/vue/v2";
import MeetingChat from "./components/MeetingChat.vue";
</script>

<template>
  <CopilotKitProvider runtime-url="/api/copilotkit">
    <MeetingChat />
  </CopilotKitProvider>
</template>
```
