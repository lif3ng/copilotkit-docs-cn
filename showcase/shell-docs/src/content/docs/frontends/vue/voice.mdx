description: 为 Vue 聊天输入框添加由运行时支持的语音转文字。

---

你可以为 `CopilotChat` 添加语音输入，而无需另接一个麦克风按钮。只有当运行时声明了 `audioFileTranscriptionEnabled` 且浏览器支持 `MediaRecorder` 时，该组件才会渲染转录控件。

## 何时使用

- 语音输入适用于免提、无障碍、移动端、自助终端（kiosk）以及长篇提示等场景。
- 当用户发送的是音频文件而非现场说话时，请使用[多模态附件](/vue/multimodal-attachments)。

## 前端配置

```vue title="App.vue"
<script setup lang="ts">
import { CopilotChat, CopilotKitProvider } from "@copilotkit/vue/v2";
import "@copilotkit/vue/styles.css";
</script>

<template>
  <CopilotKitProvider runtime-url="/api/copilotkit">
    <CopilotChat />
  </CopilotKitProvider>
</template>
```

当用户开始录音时，浏览器会请求麦克风权限。录音结束后，Vue 组件把音频发送给运行时，将返回的转录文本放入输入框，并保持其可编辑状态。用户像提交其他消息一样提交它；Vue 不会自动发送转录文本。生产环境页面应通过 HTTPS 提供，浏览器才会授予麦克风访问权限。

默认的 REST 传输会把 multipart 表单数据 POST 到 `{runtimeUrl}/transcribe`，附带一个 `audio` 字段。启用 `use-single-endpoint` 后，Vue 客户端会向 `runtimeUrl` 发送一个 JSON 信封，其中包含 base64 音频、`mimeType` 和 `filename`。

当你的运行时只暴露单一端点时，设置该 provider 属性：

```vue
<CopilotKitProvider
  runtime-url="/api/copilotkit"
  :use-single-endpoint="true"
>
  <CopilotChat />
</CopilotKitProvider>
```

## 自定义音频处理

当你的应用想接收录制的 `Blob` 并自行处理转录时，传入 `on-finish-transcribe-with-audio`。这个回调会取代默认的运行时请求，因此它必须把产生的文本放入你自己的 UI：

```vue
<script setup lang="ts">
async function handleAudio(audio: Blob) {
  const transcript = await myTranscriptionService(audio);
  console.log(transcript);
}
</script>

<template>
  <CopilotChat :on-finish-transcribe-with-audio="handleAudio" />
</template>
```

Vue 包不提供 React 演示中的 `onTranscribed` 预录音频回调，也没有可运行的语音 Showcase 路由。要做确定性的演示与测试，请用录制好的 `Blob` 调用你自己的处理器，而不要给一个并不存在的 Vue 属性写文档。

## 配置运行时

只有当运行时拥有 `TranscriptionService` 时，麦克风才会出现。在你的 V2 运行时中配置该服务，并挂载常规的运行时处理器。该服务需实现：

```ts
import {
  CopilotRuntime,
  TranscriptionService,
} from "@copilotkit/runtime/v2";

class MyTranscriptionService extends TranscriptionService {
  async transcribeFile({ audioFile }: { audioFile: File }): Promise<string> {
    return transcribeWithYourProvider(audioFile);
  }
}

const runtime = new CopilotRuntime({
  agents,
  transcriptionService: new MyTranscriptionService(),
});
```

配置好该服务后，`GET /info` 会报告 `audioFileTranscriptionEnabled: true`，`POST /transcribe` 会分派到 `transcribeFile`。没有它，即使浏览器有麦克风，运行时也无法产出转录文本。

路由挂载、请求结构与服务器端错误处理请参阅[运行时 HTTP 端点](/backend/runtime-endpoints)。V2 运行时会把服务错误映射为 `rate_limited`、`auth_failed`、`audio_too_long`、`provider_error` 等转录错误码；Vue 输入框会展示一条可重试或可操作的消息，并在短暂延迟后清除。
