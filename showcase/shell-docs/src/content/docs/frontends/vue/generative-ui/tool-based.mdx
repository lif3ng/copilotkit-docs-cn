## 这是什么？

基于工具的生成式 UI 是生成式 UI 中最简单的形式：你用 `useComponent` 注册一个 Vue 组件，CopilotKit 便会将它作为工具暴露给智能体。当智能体调用该工具时，CopilotKit 会在聊天中内联渲染你的组件，并把工具参数直接作为带有类型的 props 传入。

[工具渲染](/vue/generative-ui/tool-rendering)是用自定义 UI 包装一个真实的后端工具；与之不同，基于工具的生成式 UI 本身就是那个组件。没有 handler，没有用户交互，也没有服务端执行。由智能体决定何时展示它并填入数据，而由 CopilotKit 将其绘制出来。

## 何时应该使用它？

在以下场景中使用 `useComponent`：

- 在聊天中内联展示丰富的 UI（卡片、图表、表格、仪表盘）
- 展示智能体从推理中得出的结构化数据
- 渲染预览、状态指示器或可视化摘要
- 让智能体以纯文本之外的方式呈现信息

对于需要用户交互的组件，请参阅[人机协同（human-in-the-loop）](/vue/human-in-the-loop)。要围绕真实的后端工具获得操作透明度，请参阅[工具渲染](/vue/generative-ui/tool-rendering)。

## 代码中的工作原理

`useComponent` 接受一个名称、一个描述 props 的 Zod schema，以及要渲染的组件。运行时在注册这个前端工具时会公布该 schema，TypeScript 则据此推断组件的 props。运行时传入的参数会经过 JSON 解析，但不会依据 schema 进行校验。

```vue title="src/components/WeatherCard.vue"
<script setup lang="ts">
defineProps<{ city: string; temperature: number; condition: string }>();
</script>

<template>
  <article>
    <strong>{{ city }}</strong>
    <p>{{ temperature }}° · {{ condition }}</p>
  </article>
</template>
```

Vue 的 composable 在组件 setup 阶段执行，因此调用 `useComponent` 的组件必须是 `CopilotKitProvider` 的后代。

```vue title="src/components/AgentExperience.vue"
<script setup lang="ts">
import { z } from "zod";
import { CopilotChat, useComponent } from "@copilotkit/vue/v2";
import WeatherCard from "./WeatherCard.vue";

useComponent({
  name: "show_weather",
  description: "Display the weather for one city.",
  parameters: z.object({
    city: z.string(),
    temperature: z.number(),
    condition: z.string(),
  }),
  render: WeatherCard,
});
</script>

<template><CopilotChat /></template>
```

```vue title="src/App.vue"
<script setup lang="ts">
import { CopilotKitProvider } from "@copilotkit/vue/v2";
import AgentExperience from "./components/AgentExperience.vue";
</script>

<template>
  <CopilotKitProvider runtime-url="/api/copilotkit">
    <AgentExperience />
  </CopilotKitProvider>
</template>
```

组件本身就是一个普通的 Vue 组件：它只读取自己的 props，并可以在智能体填充数据的过程中流式呈现。它对 CopilotKit 一无所知。

<Callout type="info">
  你传给 `useComponent` 的 `name` 就是智能体看到的工具名称。请用动词形式命名，例如 `render_bar_chart` 或 `show_weather`，这样当用户请求相应可视化时，LLM 才能可靠地选中它。
</Callout>

props 由模型提供，因此请结合应用状态对关键数据进行校验，而不要把一张格式完好的卡片当作这些值已获授权或仍然有效的证明。
