## 这是什么？

MCP Apps 是一类暴露了带关联 UI 资源工具的 MCP 服务器。当智能体调用其中一个工具时，CopilotKit 会自动获取该资源并在聊天中渲染对应的 UI 组件，无需编写任何额外的前端代码。

<Callout type="info">
  **免费课程**：在 [Build Interactive Agents with Generative UI](https://www.deeplearning.ai/short-courses/build-interactive-agents-with-generative-ui/) 中查看此模式的端到端构建——这是一门由 CopilotKit CEO 讲授的 DeepLearning.AI 免费短课程，涵盖生成式 UI 的完整谱系（受控式、声明式与开放式）。
</Callout>

核心优势：

- **零前端代码** —— UI 组件由 MCP 服务器提供
- **完全可交互** —— 组件可以使用 HTML、CSS 和 JavaScript
- **安全沙箱** —— 内容运行在隔离的 iframe 中
- **线程持久化** —— MCP Apps 会存入会话历史，并在重连时恢复

## 将运行时接入你的 MCP 服务器

只需在运行时上添加一个 `mcpApps.servers` 条目即可。运行时会自动将 MCP Apps 中间件应用到每个已注册的智能体：每当智能体调用一个由 MCP UI 资源支撑的工具时，中间件就会获取该资源并发出一个 `activity` 事件，由 Vue 内置的 `MCPAppsActivityRenderer` 以沙箱化 iframe 的形式在聊天中内联渲染。

```ts title="server.ts"
import { CopilotRuntime } from "@copilotkit/runtime/v2";

const runtime = new CopilotRuntime({
  agents: { default: agent },
  mcpApps: {
    servers: [
      {
        type: "http",
        url: "https://mcp.example.com/mcp",
        serverId: "support-tools",
      },
    ],
  },
});
```

<Callout type="info" title="始终固定 serverId">
  在生产环境中，请始终提供一个稳定的 `serverId`。否则 CopilotKit 会对服务器 URL 做哈希，URL 一旦变化（例如在不同环境之间），先前会话线程中持久化的 MCP Apps 将无法恢复，且不会有任何报错。
</Callout>

## 无需前端渲染器

与自定义活动类型不同，MCP Apps 渲染器已由 `CopilotKitProvider` 开箱即用地注册。一个普通的 `<CopilotChat />` 就够了，无需手动接线渲染器。

```vue title="src/App.vue"
<script setup lang="ts">
import { CopilotChat, CopilotKitProvider } from "@copilotkit/vue/v2";
</script>

<template>
  <CopilotKitProvider runtime-url="/api/copilotkit">
    <main style="height: 100dvh"><CopilotChat /></main>
  </CopilotKitProvider>
</template>
```

## 沙箱与小组件存储

每个 MCP App 都运行在一个具有不透明 origin 的沙箱化 iframe 中。小组件（widget）无法读取你页面的 cookie、存储或 DOM；也无法读取你的 API 的响应，除非某个 API 允许跨源请求（例如设置了 `Access-Control-Allow-Origin: *`）。它仍然可以发送请求，因此请像对待其他站点一样，为会改变状态的端点做好跨站请求伪造防护。代价是小组件自己也无法使用 `localStorage`、`sessionStorage`、`IndexedDB` 或 cookie。

小组件发出的需要 CORS 的请求（例如 `<script type="module">` 和 `fetch`）会以 `Origin: null` 发送。公开的小组件资源请以 `Access-Control-Allow-Origin: *` 提供。经典的 `<script src>` 标签不需要 CORS。若想彻底避开 CORS，可以把小组件打包成单个 HTML 文件，就像 [ext-apps 示例](https://github.com/modelcontextprotocol/ext-apps/tree/main/examples)使用 `vite-plugin-singlefile` 那样。

MCP Apps 规范将 `allow-same-origin` 与由独立 origin 提供的沙箱搭配使用。CopilotKit 是内联加载沙箱的，因此它选择不开启 `allow-same-origin`，而不是把页面的 origin 交给小组件。

如果小组件是你自己编写的且需要存储，可以恢复 `allow-same-origin`：

```vue title="受信任的小组件配置"
<script setup lang="ts">
import { CopilotChat, CopilotKitProvider } from "@copilotkit/vue/v2";
</script>

<template>
  <CopilotKitProvider
    runtime-url="/api/copilotkit"
    :mcp-apps="{ allowSameOriginFallback: true }"
  >
    <CopilotChat />
  </CopilotKitProvider>
</template>
```

<Callout type="warn" title="仅用于你信任的小组件">
  启用 `allowSameOriginFallback` 后，每个 MCP App 都会以你页面的 origin 运行。任何已连接 MCP 服务器的小组件都能读取你的 cookie 和存储，并以已登录用户的身份执行操作。如果连接了第三方 MCP 服务器，请不要启用。
</Callout>

## 传输类型

中间件支持两种传输类型：

### HTTP

使用这种格式连接接受标准 HTTP 请求的 MCP 服务器：

```typescript
{
  type: "http",
  url: "http://localhost:3101/mcp",
  serverId: "my-http-server"
}
```

### SSE

使用这种格式连接通过持久连接流式传输事件的 MCP 服务器：

```typescript
{
  type: "sse",
  url: "https://mcp.example.com/sse",
  headers: {
    "Authorization": "Bearer token"
  },
  serverId: "my-sse-server"
}
```

凭据请保存在运行时侧；不要在 Vue 代码中暴露私有的 MCP token。
