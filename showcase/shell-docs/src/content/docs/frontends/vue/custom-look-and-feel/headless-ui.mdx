## 这是什么？

无头 UI 让你完全掌控体验。组件、布局与样式都由你自己提供，而 CopilotKit 负责智能体通信、响应式消息状态、工具注册和流式传输。不需要 `CopilotChat` 外壳：由你的 Vue 组件来组合这些底层原语。

## 什么时候应该用它？

在以下情况使用无头 UI：

- [插槽系统](/vue/custom-look-and-feel/slots)满足不了你需要的布局。
- 你要把聊天嵌入一个已有自身设计模式的现有界面。
- 你在构建仪表盘、画布或检查器等非聊天界面，但仍需要与智能体通信。
- 你需要直接控制出现哪些消息角色和已注册渲染器。

采用无头方式也意味着，输入框、无障碍访问、滚动行为、附件、推理、中断以及每种消息角色的处理职责都会转移到你的应用，除非你有意组合公开的 Vue 聊天叶子组件。

## 核心组合式函数

这些组合式函数提供了与预构建聊天相同的智能体与运行时状态：

- `useAgent({ agentId })` 暴露响应式会话（`messages`、`isRunning`、状态以及智能体方法）。
- `useCopilotKit()` 暴露运行时 ref，用于调用 `copilotkit.value.runAgent({ agent })`。
- `useRenderActivityMessage()` 为当前智能体作用域解析已注册的 MCP Apps 及其他自定义活动渲染器。
- `useRenderCustomMessages()` 为生效的 `CopilotChatConfigurationProvider` 解析已注册的前置/后置消息渲染器。

组合式函数必须在 `CopilotKitProvider` 之下的组件中执行；在 provider 之上调用时没有可注入的运行时上下文。

<Callout type="info" title="Vue 没有 useRenderToolCall 组合式函数">
  当前的 Vue 公开 API 可以通过 `useRenderTool` 和 `useDefaultRenderTool` 注册渲染器，但没有暴露 React 那种解析器风格的 `useRenderToolCall`。当自定义外层布局仍需要已注册的工具渲染管线时，请使用 `CopilotChatMessageView`；或者通过 Vue 插槽显式接管工具调用分发。
</Callout>

## 最小示例

先用 `useAgent` 和 `useCopilotKit` 搭一个纯文本的消息列表和输入框：

```vue title="HeadlessChat.vue"
<script setup lang="ts">
import { computed, ref } from "vue";
import { useAgent, useCopilotKit } from "@copilotkit/vue/v2";

const { agent } = useAgent({ agentId: "my-agent" });
const { copilotkit } = useCopilotKit();
const input = ref("");
const messages = computed(() => agent.value?.messages ?? []);
const isRunning = computed(() => agent.value?.isRunning ?? false);

async function submit() {
  const current = agent.value;
  const content = input.value.trim();
  if (!current || !content || isRunning.value) return;

  current.addMessage({
    id: crypto.randomUUID(),
    role: "user",
    content,
  });
  input.value = "";
  await copilotkit.value.runAgent({ agent: current });
}
</script>

<template>
  <section aria-live="polite">
    <article v-for="message in messages" :key="message.id" :data-role="message.role">
      {{ message.content }}
    </article>
    <p v-if="isRunning">Thinking…</p>
    <form @submit.prevent="submit">
      <input v-model="input" aria-label="Message" />
      <button type="submit" :disabled="isRunning">Send</button>
    </form>
  </section>
</template>
```

将它渲染在运行时 provider 和聊天配置 provider 之下，以便智能体作用域的自定义渲染器能够一致地解析：

```vue
<CopilotKitProvider runtime-url="/api/copilotkit">
  <CopilotChatConfigurationProvider agent-id="my-agent">
    <HeadlessChat />
  </CopilotChatConfigurationProvider>
</CopilotKitProvider>
```

这个取舍是有意为之：这个最小示例只渲染文本。工具调用、推理消息、活动消息、中断、附件以及自定义的前置/后置内容，都需要你自己接入后才会出现。

## 完整示例

如果自定义外层布局需要保留 CopilotKit 完整的消息组合能力，请使用公开的 Vue 叶子组件，而不是重建它们的状态机。`CopilotChatMessageView` 已经能分发助手、用户、推理、工具、活动、中断以及自定义前置/后置内容：

```vue title="RenderedMessages.vue"
<script setup lang="ts">
import { computed } from "vue";
import {
  CopilotChatAssistantMessage,
  CopilotChatMessageView,
  CopilotChatUserMessage,
  useAgent,
} from "@copilotkit/vue/v2";

const { agent } = useAgent({ agentId: "my-agent" });
const messages = computed(() => agent.value?.messages ?? []);
const isRunning = computed(() => agent.value?.isRunning ?? false);
</script>

<template>
  <CopilotChatMessageView :messages="messages" :is-running="isRunning">
    <template #assistant-message="assistantProps">
      <article class="assistant-bubble">
        <CopilotChatAssistantMessage v-bind="assistantProps" />
      </article>
    </template>
    <template #user-message="userProps">
      <article class="user-bubble">
        <CopilotChatUserMessage v-bind="userProps" />
      </article>
    </template>
  </CopilotChatMessageView>
</template>
```

### Vue 中的等价组合方式

React 的完整示例通过 `useRenderToolCall`、`useRenderActivityMessage` 和 `useRenderCustomMessages` 手动组装出 `useRenderedMessages()`。Vue 暴露了后两个解析器，但没有 `useRenderToolCall`，因此无法做到完全一一对应的手动复刻。当你需要全部已注册的工具渲染器时，`CopilotChatMessageView` 就是官方支持的公开组合边界。

### 按角色分发

如果你选择完全手动的渲染器，需要覆盖每一种 AG-UI 消息角色：

- 助手消息包含流式文本和可选的工具调用。
- 用户消息可以包含文本或多模态内容片段。
- 推理消息可以使用 `CopilotChatReasoningMessage`。
- 活动消息可以使用 `useRenderActivityMessage()`。
- 在 `CopilotChatConfigurationProvider` 内部，前置/后置内容可以使用 `useRenderCustomMessages()`。
- 中断需要自己的待处理状态 UI 和恢复/取消操作。

漏掉某个角色，对应的内容就会从你的自定义界面中无声消失。

### 工具调用的组合

预构建消息视图按以下顺序解析工具调用：具名的 `tool-call-<name>` 插槽、`tool-call` 兜底插槽，然后是通过 `useRenderTool` / `useDefaultRenderTool` 注册的渲染器。保留公开的消息视图即可保留这一行为。完全手动的 Vue 界面必须自行实现工具调用渲染，因为目前没有任何公开的解析器组合式函数把已注册的渲染器以可调用函数的形式暴露出来。

### 气泡外观

把气泡组件做成纯粹的外观包装，套在已渲染好的公开叶子组件外面。这样你的设计系统只需掌控间距、颜色和布局，而无需复制消息解析、工具栏、Markdown、工具调用或推理逻辑。
