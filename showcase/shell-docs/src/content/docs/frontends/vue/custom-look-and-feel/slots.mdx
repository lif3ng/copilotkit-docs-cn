## 这是什么？

每个 CopilotKit Vue 聊天组件都由具名插槽组合而成。借助插槽，你可以只替换某个可见部分，同时保留运行时连接、响应式消息状态、流式行为以及预构建界面的其余部分。

Vue 提供三个实用的插槽自定义层次：

1. **在公开叶子组件上添加类和属性** —— 组合诸如 `CopilotChatMessageView` 这样的叶子组件，并向它传递 `class` 或其他属性。
2. **作用域插槽组合** —— 消费插槽的数据与操作，同时只替换模板中的那一部分。
3. **自定义组件** —— 在插槽内渲染你自己的 Vue 组件。

插槽是递归的：根级 `message-view` 插槽可以渲染公开的消息视图，后者的 `assistant-message` 插槽可以渲染公开的助手叶子组件，再后者的 `copy-button` 插槽可以替换工具栏上的一个控件。这是 React 插槽对象层级在 Vue 中的原生等价物；React 风格的 component 或 props 覆盖对象并不是 Vue 的 API。

## 代码中的样子

下面的示例替换与根指南相同的三个部分：欢迎页、助手消息卡片和输入免责声明。

### 欢迎页插槽

`welcome-screen` 插槽替换首条消息出现之前的空状态。它的作用域 props 包含输入与建议操作，因此自定义页面仍然可以通过现有聊天提交消息：

```vue title="SupportChat.vue"
<script setup lang="ts">
import { CopilotChat } from "@copilotkit/vue/v2";
</script>

<template>
  <CopilotChat>
    <template #welcome-screen="{ onSubmitMessage }">
      <section class="welcome-card">
        <h2>How can we help?</h2>
        <button type="button" @click="onSubmitMessage('Show my open tickets')">
          Show my open tickets
        </button>
      </section>
    </template>
  </CopilotChat>
</template>
```

### 助手消息插槽

使用 `message-view` 插槽组合公开的消息叶子组件，再自定义它们各自的插槽或事件。这样可以保持组件层级和 provider 祖先链完整：

```vue title="SupportChat.vue"
<script setup lang="ts">
import {
  CopilotChat,
  CopilotChatAssistantMessage,
  CopilotChatMessageView,
} from "@copilotkit/vue/v2";
</script>

<template>
  <CopilotChat>
    <template #message-view="{ messages, isRunning }">
      <CopilotChatMessageView :messages="messages" :is-running="isRunning">
        <template #assistant-message="{ message, messages: allMessages, isRunning: running }">
          <CopilotChatAssistantMessage
            :message="message"
            :messages="allMessages"
            :is-running="running"
          >
            <template #toolbar-items>
              <span class="reviewed-badge">Reviewed</span>
            </template>
          </CopilotChatAssistantMessage>
        </template>
      </CopilotChatMessageView>
    </template>
  </CopilotChat>
</template>
```

这些消息组件还暴露了更多具名插槽，覆盖用户消息、助手工具栏与按钮、工具调用、推理消息和活动消息。在活动渲染方面，`CopilotChatMessageView` 会先查找 `activity-<activityType>`，再查找 `activity-message`。

### 免责声明插槽

输入框的 `disclaimer` 插槽替换输入区下方的文字，而不动文本域、发送按钮、附件和语音转写控件：

```vue
<CopilotChat>
  <template #input="inputProps">
    <CopilotChatInput v-bind="inputProps">
      <template #disclaimer>
        <p class="support-disclaimer">Responses may be inaccurate.</p>
      </template>
    </CopilotChatInput>
  </template>
</CopilotChat>
```

## Tailwind 类

Vue 不接受用 Tailwind 字符串代替插槽。请给作用域插槽内组合的公开叶子组件添加 `class`，或给你自己的标记添加类：

```vue
<CopilotChat>
  <template #message-view="{ messages, isRunning }">
    <CopilotChatMessageView
      class="rounded-xl bg-gray-50 p-4 dark:bg-gray-900"
      :messages="messages"
      :is-running="isRunning"
    />
  </template>
</CopilotChat>
```

## Props 覆盖

React 的插槽对象 props 覆盖在 Vue 中没有直接等价物。请把 props、监听器和属性绑定到插槽内渲染的公开 Vue 叶子组件上：

```vue
<CopilotChat>
  <template #message-view="slotProps">
    <CopilotChatMessageView
      v-bind="slotProps"
      class="my-custom-messages"
      data-testid="message-view"
    />
  </template>
</CopilotChat>
```

## 自定义组件

若要完全掌控，就渲染你自己的组件。它会收到你选择透传的作用域数据：

```vue
<CopilotChat>
  <template #message-view="{ messages, isRunning }">
    <CustomMessageView :messages="messages" :is-running="isRunning" />
  </template>
</CopilotChat>
```

一旦替换了完整的插槽，该部分的渲染就完全由你的组件负责。想保留 CopilotKit 的默认行为时，请组合公开叶子组件。

## 嵌套插槽（逐层深入）

具名插槽通过公开 Vue 叶子组件实现嵌套，而不是嵌套的配置对象。

### 两层嵌套

在保留默认消息渲染器的同时覆盖助手工具栏：

```vue
<CopilotChat>
  <template #message-view="{ messages, isRunning }">
    <CopilotChatMessageView :messages="messages" :is-running="isRunning">
      <template #assistant-message="assistantProps">
        <CopilotChatAssistantMessage v-bind="assistantProps">
          <template #toolbar-items>
            <CustomToolbarAction />
          </template>
        </CopilotChatAssistantMessage>
      </template>
    </CopilotChatMessageView>
  </template>
</CopilotChat>
```

### 三层嵌套

替换某个具体的工具栏按钮，同时保留其命令式操作：

```vue
<CopilotChatAssistantMessage v-bind="assistantProps">
  <template #copy-button="{ onCopy }">
    <button type="button" @click="onCopy">Copy response</button>
  </template>
</CopilotChatAssistantMessage>
```

## 文案标签

只改文字时，使用预构建界面上的 `labels` prop：

```vue
<CopilotChat
  :labels="{
    chatInputPlaceholder: 'Ask your agent anything…',
    welcomeMessageText: 'How can I help you today?',
    chatDisclaimerText: 'AI responses may be inaccurate.',
  }"
/>
```

结构与行为用插槽，既有的面向用户文案用 labels。

## 可用插槽

### `CopilotChat` / `CopilotSidebar` / `CopilotPopup`

聊天界面暴露这些根级插槽。大多数插槽的作用域都带有维持默认行为所需的状态和操作：

| 插槽 | 说明 |
| --- | --- |
| `chat-view` | 完整聊天视图，包含消息、输入、建议、附件与语音转写状态。 |
| `message-view` | 消息列表组合；接收 `messages` 与 `isRunning`。 |
| `scroll-view` | 滚动容器、滚动操作、建议与底部按钮状态。 |
| `input` | 输入区状态，以及提交、停止、附件与语音转写操作。 |
| `suggestion-view` | 建议集合、加载索引与选择操作。 |
| `welcome-screen` | 初始空状态，带输入与建议数据。 |
| `welcome-message` | 仅默认欢迎文案区域。 |
| `interrupt` | 一个待处理中断及其解决器。 |

`CopilotSidebar` 与 `CopilotPopup` 还额外暴露：

| 插槽 | 说明 |
| --- | --- |
| `header` | 弹层头部，带打开状态与关闭操作。 |
| `toggle-button` | 启动按钮，带 `isOpen`、`toggle`、`open` 与 `close`。 |

### `CopilotChatMessageView`

| 插槽 | 说明 |
| --- | --- |
| `assistant-message` | 助手消息，附完整消息列表与运行状态。 |
| `user-message` | 用户消息。 |
| `reasoning-message` | 推理消息，附消息列表与运行状态。 |
| `tool-call-<name>` | 单个具名工具调用渲染器。 |
| `tool-call` | 兜底工具调用渲染器。 |
| `activity-<type>` | 单个具名活动消息渲染器。 |
| `activity-message` | 兜底活动消息渲染器。 |
| `message-before` / `message-after` | 每条消息前后可感知元数据的内容。 |
| `cursor` | 流式光标。 |

### 公开的消息与输入叶子组件

- `CopilotChatAssistantMessage` 暴露 `layout`、`message-renderer`、`tool-calls-view`、`toolbar`、`toolbar-items`，以及复制、反馈、朗读和重新生成按钮各自的插槽。
- `CopilotChatUserMessage` 暴露 `layout`、`message-renderer`、`toolbar`、`toolbar-items`、复制/编辑按钮和分支导航。
- `CopilotChatInput` 暴露 `layout`、`text-area`、`disclaimer`、`add-menu-button`、`audio-recorder` 以及发送/语音转写控件。

选用能表达该改动的最小粒度插槽。这样可以保留更多内置行为，并减少你需要自行维护的状态和无障碍接线。
