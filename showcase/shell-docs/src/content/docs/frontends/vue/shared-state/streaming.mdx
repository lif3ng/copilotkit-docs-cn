## 这是什么？

默认情况下，智能体状态只会在后端检查点*之间*更新，因此长时间运行的工具调用（例如撰写完整文档或起草电子邮件）在 UI 看来就是最后一次性大量涌现。对智能体原生应用而言，这种体验像是坏掉了：用户期望亲眼看着输出逐渐成形。

**状态流式传输**会在某个工具参数*生成的过程中*，把它的值直接转发进某个智能体状态键。通过 `useAgent` 订阅的 UI 会对每个 token 重新渲染。

## 何时应该使用它？

只要工具的输出是长篇文本或不断增长的结构化值，并且你希望用户实时看到它组装成形，就使用状态流式传输。常见形态：

- 输出文档的协作写作智能体
- 不断积累发现列表的研究智能体
- 逐步构建分步计划的规划智能体

没有流式传输时，用户只能盯着加载转圈。有了流式传输，他们能看到答案逐 token 生长。

## 后端：一条流式状态映射

<FrameworkSetup concept="state-streaming-setup" />

后端模式始终如一：把一个流式工具参数映射到一个共享状态键。基于中间件的框架通常以声明式映射的形式暴露这一能力。直接使用 SDK 的适配器则在它们的流式循环里完成同样的工作——解析部分工具参数，并在被映射的值每次变化时发出 `STATE_SNAPSHOT`。当 LLM 以流式生成该参数时，CopilotKit 会在工具执行结束前把每个部分值写入共享状态。

<Snippet region="state-streaming-middleware" title="后端——流式状态映射" />

有几点需要注意：

- 状态键必须存在于你的智能体状态中（本示例中为 `document`）。
- 工具名与参数名必须与你想转发的那个面向 LLM 的工具调用完全一致。
- 工具调用完成后，其最终返回值会写入同一个键，因此流式传输的部分值最终会成为权威的最终值。

## 前端：useAgent + OnStateChanged

UI 侧与其他任何共享状态订阅完全一样：带 `OnStateChanged` 的 `useAgent` 为你提供响应式的 `agent.value.state`。如果想要进行中/已完成指示器，再加上 `OnRunStatusChanged`。

```vue title="src/components/StreamingDocument.vue"
<script setup lang="ts">
import { computed } from "vue";
import { useAgent, UseAgentUpdate } from "@copilotkit/vue/v2";

type DocumentState = { document?: string };

const { agent } = useAgent({
  agentId: "writer",
  updates: [
    UseAgentUpdate.OnStateChanged,
    UseAgentUpdate.OnRunStatusChanged,
  ],
});
const state = computed(
  () => (agent.value?.state ?? {}) as DocumentState,
);
</script>

<template>
  <article aria-live="polite">
    <span v-if="agent?.isRunning">LIVE</span>
    <p>{{ state.document ?? "Waiting for a draft…" }}</p>
  </article>
</template>
```

从这里开始，`state.document` 是一个随每个 token 增长的字符串，`agent.isRunning` 则告诉你是否该显示流式指示器。

```vue title="src/App.vue"
<script setup lang="ts">
import { CopilotChat, CopilotKitProvider } from "@copilotkit/vue/v2";
import StreamingDocument from "./components/StreamingDocument.vue";
</script>

<template>
  <CopilotKitProvider runtime-url="/api/copilotkit">
    <StreamingDocument />
    <CopilotChat agent-id="writer" />
  </CopilotKitProvider>
</template>
```

如果运行时不发出部分状态快照，UI 就只能看到最终状态。Vue 前端无法凭空造出后端从未发送的更新。
