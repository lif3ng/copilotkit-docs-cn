当智能体的状态直接呈现在你的应用 UI 中——例如仪表盘、文档画布、地图或表格——[共享状态](/vue/shared-state)的威力最为明显。由于 `agent.state` 是通过 Vue ref 暴露的普通数据，你可以从任何后代组件订阅，并以任意喜欢的方式渲染它。

## 模式

`useAgent` 可以在 `CopilotKitProvider` 下的任何组件中使用，它不必邻近聊天组件。在你的主视图组件中调用它，读取 `agent.value.state`，然后渲染：

```vue title="src/components/Canvas.vue"
<script setup lang="ts">
import { computed, watchEffect } from "vue";
import { useAgent, UseAgentUpdate } from "@copilotkit/vue/v2";

type CanvasState = {
  title: string;
  items: { id: string; label: string; done: boolean }[];
};

const initialState: CanvasState = {
  title: "Project launch",
  items: [
    { id: "research", label: "Research user needs", done: true },
    { id: "prototype", label: "Build a prototype", done: false },
  ],
};

const { agent } = useAgent({
  updates: [UseAgentUpdate.OnStateChanged],
});
const state = computed(
  () => (agent.value?.state ?? {}) as Partial<CanvasState>,
);

watchEffect(() => {
  const currentAgent = agent.value;
  if (!currentAgent) return;

  const current = (currentAgent.state ?? {}) as Partial<CanvasState>;
  const updates: Partial<CanvasState> = {};
  if (current.title === undefined) updates.title = initialState.title;
  if (current.items === undefined) updates.items = initialState.items;

  if (Object.keys(updates).length > 0) {
    currentAgent.setState({ ...current, ...updates });
  }
});
</script>

<template>
  <main class="canvas">
    <h1>{{ state.title ?? "Untitled" }}</h1>
    <ul>
      <li
        v-for="item in state.items ?? []"
        :key="item.id"
        :data-done="item.done"
      >
        {{ item.label }}
      </li>
    </ul>
  </main>
</template>
```

本示例中的 `initialState` 值是由 UI 持有的初始状态，它让画布在智能体写入状态之前就能显示出来。这段 effect 只设置值为 `undefined` 的字段，并保留所有其他状态。如果初始状态由后端持有，请在该框架的共享状态配置中定义它。

每当智能体修改其状态——无论是来自工具调用、节点切换还是[流式更新](/vue/shared-state/streaming)——`useAgent` 都会更新 ref，Vue 随即重新渲染该组件。聊天可以放在侧边栏、弹窗里，甚至完全不存在；你的画布都会以同样的方式更新。

## 放在布局中的任意位置

agent 挂载在 `CopilotKitProvider` 上，因此聊天界面和你的主视图组件是同一个 agent 的两个消费者。典型的布局把画布作为主要内容渲染，聊天则并列一旁：

```vue title="src/App.vue"
<script setup lang="ts">
import { CopilotChat, CopilotKitProvider } from "@copilotkit/vue/v2";
import Canvas from "./components/Canvas.vue";
</script>

<template>
  <CopilotKitProvider runtime-url="/api/copilotkit">
    <div class="app-shell">
      <Canvas />
      <CopilotChat />
    </div>
  </CopilotKitProvider>
</template>
```

<Callout type="info">
  `<Canvas>` 与 `<CopilotChat>` 解析到的是同一个默认 agent，因此它们共享同一个 agent 实例和同一个状态对象。读取 `agent.state` 没有任何聊天特有的成分；聊天只是另一个消费者。
</Callout>

## 从主视图写回

同一个 agent 还暴露了 `setState`，因此你的画布可以是交互式的，而不是一面只读的镜子。点击处理器可以推送一个新值，智能体会在它的下一轮读取：

```ts
function toggleItem(id: string) {
  const currentAgent = agent.value;
  if (!currentAgent) return;

  const current = (currentAgent.state ?? {}) as Partial<CanvasState>;
  currentAgent.setState({
    ...current,
    items: (current.items ?? []).map((item) =>
      item.id === id ? { ...item, done: !item.done } : item,
    ),
  });
}
```

这与[共享状态](/vue/shared-state)中描述的双向通道是同一条。唯一的区别在于读写发生在你应用的主界面，而不是聊天里。

## 提示

- 当你有多个 agent 时，**用 `useAgent({ agentId: "research-agent" })` 指定特定 agent**。默认值是名为 `"default"` 的 agent。
- 如果流式运行导致沉重的画布重渲染得过于频繁，**用 `useAgent({ throttleMs })` 对高频更新进行限流**。
- 在运行进行期间，**把 `agent.state` 视为可能不完整的**。用默认值做好防护，避免半流式的状态让你的渲染崩溃。
