## 这是什么？

有时你希望智能体*了解*当前 UI 的一些信息，例如登录用户、当前页面或最近的活动日志，但又不想让智能体能够修改它们。这正是 `useAgentContext` 的用途：一条面向只读上下文的单向 **UI → 智能体** 通道。

与完整共享状态（UI 与智能体双方都能修改同一份状态约定）不同，`useAgentContext` 的值是纯输入。智能体在每一轮都会通过运行时的上下文注入看到它们，但 context API 不暴露任何 setter 或修改工具。

## 何时应该使用它？

在以下情况下，请使用 `useAgentContext` 而非完整的共享状态：

- 该值**由 UI 持有**，对智能体而言除了用户当前正在查看的内容之外没有其他意义。
- 智能体应当只读不写，例如用户身份、特性开关、选中的记录或滚动位置。
- 你希望该值在组件卸载时自动注销。

可以把它理解为“面向智能体的 props。”

## 代码中的工作方式

对每个要发布的值调用一次 `useAgentContext({ description, value })`。每次调用都会向运行时注册一个响应式上下文条目，它会：

- 随所提供的 ref 或 getter 变化而刷新。
- 在组件卸载时自动移除。
- 在每一轮通过后端的 CopilotKit 中间件呈现给智能体。

```vue title="src/components/WorkspaceContext.vue"
<script setup lang="ts">
import { ref } from "vue";
import { useAgentContext } from "@copilotkit/vue/v2";

const workspaceId = ref("northstar");

useAgentContext({
  description: "Active workspace",
  value: workspaceId,
});
</script>

<template>
  <p>Workspace: {{ workspaceId }}</p>
</template>
```

`description` 很重要：它是智能体随值一起看到的人类可读标签，智能体由此知道该如何处理这个值。请把它当作参数的 docstring 来对待。不要把机密信息放进这条通道；此处发布的任何内容都是供智能体读取的。

## 接入你自己的状态

`useAgentContext` 并不关心值来自哪里：本地 ref、computed 值、路由 getter、Pinia 或其他领域存储都可以。传入 ref 或 getter，当值变化时 Vue 会重新注册序列化后的上下文。

```vue title="src/App.vue"
<script setup lang="ts">
import { CopilotChat, CopilotKitProvider } from "@copilotkit/vue/v2";
import WorkspaceContext from "./components/WorkspaceContext.vue";
</script>

<template>
  <CopilotKitProvider runtime-url="/api/copilotkit">
    <WorkspaceContext />
    <CopilotChat />
  </CopilotKitProvider>
</template>
```

## 设计上只读

由于智能体永远看不到这些值的 setter 或修改工具，上下文注册本身无法更新它们。因此，只要该值是一个输入、而非双方共同编辑的共享工作区，`useAgentContext` 就是合适的工具。

当你需要既能读*又能*写时，请使用完整的**[共享状态](/vue/shared-state)**：当运行时支持共享状态时，`useAgent()` 会暴露 `agent.state`，以及同一个 agent 的 `setState(...)` 修改路径。
