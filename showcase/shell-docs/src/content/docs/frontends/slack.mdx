在本指南中，你将把 AG-UI 智能体连接到托管 Slack 应用，启动一个长期运行的 Channels SDK 监听器，并用一条真实的工作区消息进行验证。CopilotKit Intelligence 保管 Slack 凭据；你的进程保管智能体与应用逻辑。

刚接触这个产品？先阅读 [Channels 概览](/channels)，了解 SDK、Runtime、Intelligence 与提供方连接如何协同工作。

继续之前，先[在 Intelligence 中配置 Channel](/channels/intelligence)。你应当已拿到 `CHANNEL_CODE` 与 `CPK_INTELLIGENCE_API_KEY`。

## 从编码智能体开始

使用下面的提示词把智能体连接到 Slack、启动 Channels SDK 监听器，并用真实的工作区消息进行验证。也可以按下面的手动步骤操作。

<PageAgentPrompt />

## 开始之前

- Node.js 22 或更高版本；托管启动器依赖 Node.js 22+ 才有的全局 `WebSocket`
- 一个长期运行的 Node 宿主或容器；serverless 请求处理器无法持有持久的网关连接

  <Step>
    ### 连接你的智能体后端

    Channels 进程可以使用任何受支持的后端。选择器中的 **Agent backend** 决定下面的配置。它必须为每个 Slack 会话导出全新的 `makeAgent(threadId)` 结果；不要跨线程共享同一个有状态的智能体实例。

  <Step>
    ### 声明托管 Slack Channel

    创建下面的监听器。把 `support-slack` 替换为 Intelligence 中显示的准确 Code。

    在 Channel 上设置 `agent: makeAgent`，因为这里的 handler 调用了 `thread.runAgent()`。Channel 不会继承 `runtime.agents`。如果 Channel 的 handler 不经 `runAgent()` 而直接回复，则可以省略 `agent`。

    ```ts title="channel.ts"
    import { createServer } from "node:http";
    import { createChannel } from "@copilotkit/channels";
    import {
      CopilotKitIntelligence,
      CopilotRuntime,
    } from "@copilotkit/runtime/v2";
    import { createCopilotNodeListener } from "@copilotkit/runtime/v2/node";
    import { makeAgent } from "./agent.js";

    function required(name: string): string {
      const value = process.env[name];
      if (!value) throw new Error(`Missing required environment variable: ${name}`);
      return value;
    }

    const channel = createChannel({
      name: required("CHANNEL_CODE"),
      identifyUser: "platform",
      agent: makeAgent,
    });

    channel.onMessage(async ({ thread, message }) => {
      await thread.runAgent({
        // Combine text and attachments explicitly when both are present.
        prompt: message.contentParts?.length
          ? [
              ...(message.text
                ? [{ type: "text" as const, text: message.text }]
                : []),
              ...message.contentParts,
            ]
          : message.text,
        context: [
          { description: "Originating platform", value: message.platform },
        ],
      });
    });

    const intelligence = new CopilotKitIntelligence({
      apiKey: required("CPK_INTELLIGENCE_API_KEY"),
      // Cloud-hosted deployments use the default URLs. Override both URLs
      // together only for self-hosted or non-production Intelligence.
      apiUrl: process.env.INTELLIGENCE_API_URL,
      wsUrl: process.env.INTELLIGENCE_GATEWAY_WS_URL,
    });

    const runtime = new CopilotRuntime({
      agents: {},
      intelligence,
      channels: [channel],
    });

    // Wire teardown before the listener exists, because creating it is what
    // starts the Channel. A Ctrl-C during the connect window then still tears
    // the Channel down instead of hitting Node's default handler.
    let teardown: (() => Promise<void>) | undefined;
    const shutdown = async () => {
      await teardown?.();
    };
    process.once("SIGINT", shutdown);
    process.once("SIGTERM", shutdown);

    const listener = createCopilotNodeListener({
      runtime,
      basePath: "/api/copilotkit",
    });
    const channels = listener.channels;
    const server = createServer(listener);
    teardown = async () => {
      await channels.stop();
      if (server.listening) server.close();
    };

    // Optional: block startup until the activation above settles, so a broken
    // deploy fails loudly instead of serving as a bot that never answers.
    await channels.ready({ timeoutMs: 30_000 });
    const status = channels.status();
    if (status.overall !== "online") {
      throw new Error(`Slack Channel is not online: ${JSON.stringify(status)}`);
    }

    const port = Number(process.env.PORT ?? 3001);
    server.listen(port, () => {
      console.log(`Slack Channel online; lifecycle server listening on :${port}`);
    });
    ```

    创建 Node 监听器就会启动 Channel：它拥有自己的进程生命周期，声明的 Channel 因为被声明而自动连接。因此 `ready()` 是可选的、纯“等待并观察”——激活落定后 resolve，激活失败则 reject。由于它可能在仍需完成配置的情况下落定，请在宣布 Channel 上线前检查 `status()`。跳过 `ready()` 的话，激活失败只会出现在你的日志里。

  </Step>

  <Step>
    ### 配置密钥并启动

    ```dotenv title=".env"
    CPK_INTELLIGENCE_API_KEY=<project-api-key>
    CHANNEL_CODE=support-slack
    # Add the agent variables shown for your selected backend.
    PORT=3001

    # Optional paired overrides for self-hosted or non-production Intelligence:
    # INTELLIGENCE_API_URL=https://intelligence.example.com
    # INTELLIGENCE_GATEWAY_WS_URL=wss://realtime.intelligence.example.com
    ```

    生命周期服务器使用端口 `3001`，以便与端口 `3000` 上的 Web 应用并行运行。如果 `3001` 已被占用，把 `PORT` 设为另一个空闲端口。

    #### 这些值从哪里来

    这里有三个变量起作用，而你只需要提供一个：

    - `OPENAI_API_KEY`，或你的智能体所用模型提供方的密钥。
      这个由你自己创建并粘贴。
    - `CPK_INTELLIGENCE_API_KEY` 由 `copilotkit project select` 替你写入，它会创建项目及其密钥。
    - `CHANNEL_CODE` 由引导流程在声明 Channel 后替你写入；该流程知道自己刚创建的 Code。

    这样两个 Intelligence 值都会落入你的应用加载的环境文件中，你无需手工复制其中任何一个。自己手动设置也可以：参见[配置运行时交接](/channels/intelligence#configure-the-runtime-handoff)，了解每个值在 Intelligence 中的位置。

    云托管的 Intelligence 会提供两个默认 base URL。自托管或非生产部署则要同时覆盖两者。REST 与实时平面使用不同的主机，不要从 API URL 推导 WebSocket URL。两者都按裸 base URL 传入，不带 `/api`、`/socket`、`/runner` 或 `/client`。项目级运行时密钥请在 Intelligence 项目侧边栏的 **API Keys** 中创建。

    把 `.env` 排除在版本控制之外，启动所选的智能体后端，然后运行：

    ```bash title="Terminal"
    node --env-file=.env --import tsx channel.ts
    ```

    Intelligence 应从 **Waiting for runtime** 变为 **Online**。

    #### 了解健康状态

    启动进程正是连接 Channel 的动作，因此它应当自行变为 **Online**；本指南中的 `await channels.ready(...)` 只是等待这一过程落定。

    | 状态 | 检查什么 |
    | --- | --- |
    | **Disabled** | 先启用 Channel，再期待消息送达。 |
    | **Setup incomplete** | 启动运行时前，先完成所选提供方要求的配置字段。 |
    | **Setup failed** | 重新打开平台配置，修正被拒绝的凭据或配置。 |
    | **Waiting for runtime** | 启动进程——创建监听器即会连接 Channel——并使其 Code 与提供方和本 Channel 匹配。 |
    | **Conflict** | 对比每个副本的完整 Channel 声明集合。完全相同的副本应选出一个活跃主节点，其余为已连接的备节点；不同但有重叠的集合是不安全的。 |
    | **Offline** | 检查监听器进程、网络与 Intelligence 网关连接。 |
    | **Delivery failing** | 检查平台凭据、应用权限与提供方响应。 |
    | **Online** | 运行时已连接；发送一条真实的提供方消息来验证完整链路。 |

  </Step>

  <Step>
    ### 验证真实的 Slack 消息

    如有需要先邀请应用，然后在频道中 @ 它：

    ```text title="Slack"
    /invite @your-app
    @your-app summarize the decisions in this thread
    ```

    也请测试一条私信。真实工作区中的回复能端到端验证 Slack 令牌对、Intelligence 送达、网关监听器、AG-UI 智能体以及回复链路。

  </Step>
</Steps>

## 工具调用进度

托管 Slack 默认不在流式回复中包含工具调用进度，因此对话以干净的结果收尾。工具生命周期事件仍会保留在 Intelligence 历史中，并可在回放时查看。

当实时工具时间线有用时，可按 Channel 选择启用：

```ts title="channel.ts"
const channel = createChannel({
  name: required("CHANNEL_CODE"),
  identifyUser: "platform",
  agent: makeAgent,
  showToolStatus: true,
});
```

## 故障排查

<Accordions>
  <Accordion title="Channel 一直停留在 Waiting for runtime">
    确认 `CHANNEL_CODE` 与 Intelligence 的 Code 完全一致，且项目级 `CPK_INTELLIGENCE_API_KEY` 属于同一个项目。提供方路由来自 Intelligence 中绑定的 Slack 连接，而不是某个 `createChannel` 选项。
  </Accordion>
  <Accordion title="启动时报 setup_required">
    在 Intelligence 中重新打开该 Channel，完成 Slack 凭据步骤。`ready()` 落定本身并不代表提供方已在线。
  </Accordion>
  <Accordion title="应用显示 Online 但从未收到 @ 消息">
    把应用邀请进频道，然后核对 `xoxb-…` Bot User OAuth 令牌与 Signing Secret 是否来自同一个 Slack 应用。Intelligence 在配置阶段无法完全识别“有效但不匹配”的凭据。如果你更新过 manifest 或 scopes，请重新安装应用，并在 Intelligence 中保存当前的 bot 令牌后重试。
  </Accordion>
  <Accordion title="智能体混淆了不同会话">
    确保 `makeAgent` 为每个 `threadId` 创建新智能体，并在所选框架要求的地方赋上该 id。
  </Accordion>
</Accordions>
