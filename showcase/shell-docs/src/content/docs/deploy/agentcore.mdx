## CopilotKit + AWS AgentCore

[AWS Bedrock AgentCore](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/what-is-bedrock-agentcore.html)
提供一个安全、无服务器的运行时，用于大规模部署 AG-UI 智能体——身份验证、会话隔离和基础设施都由它处理。CopilotKit 则为这些智能体提供可用于生产环境的前端。

## 工作原理

两者通过 **CopilotKit Runtime** 连接——一个位于浏览器与 AgentCore 之间的轻量服务端层。它与你为任何 CopilotKit 驱动的智能体使用的 runtime 是同一个——只是 AgentCore 要求它必须跑在服务端（由于 SigV4/OAuth2 身份验证，浏览器无法直接调用 AgentCore）。

```
Browser → CopilotKit Runtime → AgentCore Runtime → your agent
```

## 你将获得

- **聊天 UI**——预构建的聊天界面，或用无头 API 打造你自己的
- **共享状态**——智能体状态与应用 UI 之间的双向同步
- **生成式 UI**——实时根据工具调用渲染自定义组件
- **人机协同**（human-in-the-loop）——让用户审查、批准或改写智能体的操作
- **AgentCore 记忆**——会话历史通过 AgentCore 的记忆层跨会话持久保存

        ### 设置 CopilotKit Runtime

        CopilotKit Runtime 是连接你的前端与 AgentCore 的服务端层。它负责通信协议和中间件，特别是针对 AgentCore 时，还负责浏览器无法直接完成的服务端身份验证。

        创建一个 API 路由：

        ```typescript title="app/api/copilotkit/[[...slug]]/route.ts"
        import {
          CopilotRuntime,
          createCopilotRuntimeHandler,
          InMemoryAgentRunner,
        } from "@copilotkit/runtime/v2";
        import { HttpAgent } from "@ag-ui/client";
        import { AgentCoreRunner } from "./agent-core-runner";

        const runtime = new CopilotRuntime({
          agents: {
            my_agent: new HttpAgent({
              url: process.env.AGENTCORE_ENDPOINT_URL!, // your /invocations URL
              headers: {
                Authorization: `Bearer ${process.env.AGENTCORE_ACCESS_TOKEN}`,
              },
            }),
          },
          runner: new AgentCoreRunner(),
        });

        const handler = createCopilotRuntimeHandler({
          runtime,
          basePath: "/api/copilotkit",
        });

        export const GET = handler;
        export const POST = handler;
        ```

        <Callout type="info" title="AGENTCORE_ENDPOINT_URL 是什么？">
          这是已部署 AgentCore Runtime 的调用 URL——你调用它即可触达你的智能体。其形式为：
          `https://bedrock-agentcore.{region}.amazonaws.com/runtimes/{encoded-arn}/invocations`
        </Callout>

        <Callout type="info" title="生产环境中的身份验证">

      <Step>
        ### 添加 AgentCoreRunner

        AgentCore 的记忆层在服务端存储会话历史。当 CopilotKit 重新连接到已有线程时（例如页面刷新后），会出现两个需要自定义 runner 才能解决的问题：

        1. **未知线程**——CopilotKit 可能在任何 `run()` 发生之前就调用 `connect()`。
           不处理这种情况，首次加载就会报错。
        2. **缺失的工具调用结果**——AgentCore 重放的历史包含带工具调用的助手消息，但省略了对应的结果。CopilotKit 需要这些结果来对齐其消息状态，因此 runner 会为每个历史工具调用合成空结果。

        在你的 API 路由旁边创建 runner 文件：

        ```typescript title="app/api/copilotkit/agent-core-runner.ts"
        import {
          EventType,
          type BaseEvent,
          type Message,
          type MessagesSnapshotEvent,
          type ToolCall,
          type ToolCallResultEvent,
        } from "@ag-ui/client";
        import { InMemoryAgentRunner } from "@copilotkit/runtime/v2";
        import { concatMap, of } from "rxjs";
        import { randomUUID } from "node:crypto";

        export class AgentCoreRunner extends InMemoryAgentRunner {
          private readonly knownThreadIds = new Set<string>();

          override run(request: Parameters<InMemoryAgentRunner["run"]>[0]) {
            if (request.threadId) this.knownThreadIds.add(request.threadId);
            return super.run(request);
          }

          override connect(request: Parameters<InMemoryAgentRunner["connect"]>[0]) {
            if (!request.threadId || !this.knownThreadIds.has(request.threadId)) {
              const threadId = request.threadId ?? randomUUID();
              const runId = randomUUID();
              return of<BaseEvent>(
                { type: EventType.RUN_STARTED, threadId, runId },
                { type: EventType.MESSAGES_SNAPSHOT, messages: [] },
                { type: EventType.RUN_FINISHED, threadId, runId },
              );
            }

            return super.connect(request).pipe(
              concatMap((event: BaseEvent) => {
                if (event.type !== EventType.MESSAGES_SNAPSHOT) return of(event);
                const snapshot = event as MessagesSnapshotEvent;
                const replayedResults: ToolCallResultEvent[] = snapshot.messages.flatMap(
                  (message: Message) => {
                    if (message.role !== "assistant" || !message.toolCalls?.length) return [];
                    return message.toolCalls.map<ToolCallResultEvent>((toolCall: ToolCall) => ({
                      type: EventType.TOOL_CALL_RESULT,
                      toolCallId: toolCall.id,
                      messageId: `${toolCall.id}-result`,
                      content: "",
                      role: "tool",
                    }));
                  },
                );
                return of<BaseEvent>(...replayedResults, snapshot);
              }),
            );
          }
        }
        ```
      </Step>

## 故障排查

### HTTP 401：`Missing Authentication Token`

```
Agent execution failed: Error: HTTP 401:
{"jsonrpc":"2.0","error":{"code":-32001,"message":"Missing Authentication Token"},"id":"null"}
```

`Missing Authentication Token` 是 AWS 自身的错误，不是 CopilotKit 或智能体的错误。当请求在没有任何凭证的情况下到达 AgentCore 或 API Gateway 端点，或请求路径匹配不到任何已部署路由时，AWS 就会返回它。请按顺序检查以下几点：

- **确认 runtime 确实在发送 token**。在 Copilot Runtime **服务器**（而非前端）的环境中设置 `AGENTCORE_ACCESS_TOKEN`。如果该变量未设置，`Authorization` 头会插值成 `Bearer undefined`，AWS 会像对待缺失请求头一样拒绝它。
- **确认 token 没有过期**。Cognito 访问 token 有效期很短。先签发一个新的并重试，再去排查其他任何问题。
- **`AGENTCORE_ENDPOINT_URL` 是完整的调用 URL**，以 `/invocations` 结尾，且智能体 ARN 经过 URL 编码：
  `https://bedrock-agentcore.{region}.amazonaws.com/runtimes/{encoded-arn}/invocations`。如果 URL 停在 `/invocations` 之前，就匹配不到任何路由，AWS 会把它报告为 `Missing Authentication Token` 而不是 404。
- **确认浏览器没有直接调用 AgentCore**。AgentCore 要求 SigV4 或 OAuth2 签名，浏览器无法完成。让前端指向你的 Copilot Runtime 端点，由 runtime 在服务端发起 AgentCore 调用。

<Callout type="warn" title="此错误不适用于本地快速开始">
  各框架快速开始在本地 `http://localhost:8000` 上运行智能体，本地智能体服务器永远不会返回 `Missing Authentication Token`。如果你看到这个错误，说明 runtime 指向了已部署的 AWS 端点。
</Callout>
