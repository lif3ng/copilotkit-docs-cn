## 什么是共享状态？

智能体化的 Copilot 会维护一个共享状态，把你的 UI 与智能体的执行无缝连接起来。这套共享状态系统让你可以：

- 展示智能体当前的进展与中间结果
- 通过 UI 交互更新智能体的状态
- 在整个应用中实时响应状态变化

## 什么时候该用它？

当你希望智能体和用户通过同一份应用状态协作时，就使用共享状态。智能体的输出会反映到 UI 中，用户在 UI 中的更新也会反映到智能体的执行里。

## 读取智能体状态

<FrameworkSetup concept="shared-state-setup" />

用 `useAgent` 把组件订阅到智能体的状态上。只要智能体修改自己的状态（例如通过一次工具调用），该 hook 就会触发，你的 UI 便会以新值重新渲染。

<Snippet region="use-agent-read" cell="shared-state-read-write" title="frontend/src/app/page.tsx：useAgent 订阅" />

返回的 `agent.state` 只是一个普通对象。像读取其他 React state 一样读取它，并渲染你关心的部分：智能体写入的笔记、结构化输出、进度指示器——智能体放进去的任何东西。

## 写入智能体状态

同一个 `agent` 对象还暴露了 `setState` 设置器。在 UI 事件处理器中调用它，会把新值推入共享状态，智能体会在它的下一轮读取回来。UI 的写入会实实在在地引导模型。

<Snippet region="use-agent-write" cell="shared-state-read-write" title="frontend/src/app/page.tsx：agent.setState" />

这正是这条通道双向的原因：UI 不仅能观察智能体，还能把新的输入（偏好、选择、半成品工作）直接交给智能体，而无需经过聊天线程。

## 在 UI 中渲染共享状态

由于 `agent.state` 就是普通的 React 数据，UI 层就是你平时构建的那些东西。本页的演示把智能体的输出接进一个小卡片组件，并通过 `setState` 把用户编辑回传。

<Snippet region="notes-card-render" cell="shared-state-read-write" title="frontend/src/app/page.tsx：NotesCard" />

这一切都不局限于聊天：`useAgent` 可以在 `<CopilotKit>` 下的任何组件中使用，因此你可以在主视图或画布中渲染 `agent.state`，而不只是聊天面板里。完整的主视图模式见 **[在应用中渲染智能体状态](/shared-state/rendering-in-app)**。

## 流式传输部分状态更新

默认情况下，智能体状态只在后端检查点*之间*更新，因此一次长时间运行的工具调用会到最后才一次性涌现出来。状态流式传输会在某个特定工具参数*生成的同时*把它直接转发到一个状态键，让 UI 能看着答案逐 token 组装起来。

<Snippet region="state-streaming-middleware" cell="shared-state-streaming" title="backend：流式状态更新" />

完整演练（包括前端对应的 `useAgent` 订阅）见 **[状态流式传输](/shared-state/streaming)**。

## 只读上下文

当某个值是 **UI 所有**的、智能体只应读取而绝不应回写时——比如当前用户、选中的记录或滚动位置——请使用 `useAgentContext` 而不是完整的共享状态。它把值发布为一条从 UI 到智能体的单向通道，并在组件卸载时自动注销。

完整模式见 **[智能体只读上下文](/shared-state/agent-readonly)**。
