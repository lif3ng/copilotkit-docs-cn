## 这是什么？

编程式控制适用于你想从代码而非聊天输入框来驱动智能体运行的情形：一个按钮、一个表单、一个定时任务、一个快捷键、一个图回调。CopilotKit 暴露了三个原语，覆盖所有触发模式：

- `agent.addMessage(...)` —— 向对话追加一条消息但不运行智能体。当你希望追加的消息开启一轮对话时，配合 `copilotkit.runAgent({ agent })` 使用。
- `copilotkit.runAgent({ agent })` —— `<CopilotChat />` 底层调用的同一入口。负责编排前端工具、后续运行和订阅者生命周期。
- `agent.subscribe(subscriber)` —— 底层 AG-UI 事件订阅（`onCustomEvent`、`onRunStartedEvent`、`onRunFinalized`、`onRunFailed` 等）。配合 `copilotkit.runAgent({ agent, resume })`（标准 AG-UI 中断）或 `copilotkit.runAgent({ agent, forwardedProps: { command: { resume, interruptEvent } } })`（旧版 `on_interrupt` 自定义事件）使用，可从任意 UI 驱动中断的解决。

下文的“发送并停止”示例刻意做到自包含。后面的订阅与中断示例则取自实际的 `interrupt-headless` 单元。

## 什么时候该用它？

在以下情况下使用编程式控制：

- 从按钮、表单或其他 UI 元素触发智能体运行
- 从 UI 交互直接执行特定工具（无需 LLM 回合）
- 在没有聊天窗口的情况下构建智能体特性
- 以编程方式访问智能体状态与结果
- 创建完全自定义的智能体驱动工作流

## 从代码发送消息

<FrameworkSetup concept="programmatic-control-setup" />

典型模式是用 `agent.addMessage` 追加一条用户消息，然后调用 `copilotkit.runAgent({ agent })`。使用 `copilotkit.stopAgent({ agent })` 可以取消进行中的运行。

```tsx title="frontend/src/app/agent-trigger.tsx"
"use client";

import { useAgent, useCopilotKit } from "@copilotkit/react-core/v2";

export function AgentTrigger({ agentId }: { agentId: string }) {
  const { agent } = useAgent({ agentId });
  const { copilotkit } = useCopilotKit();

  const run = async () => {
    if (agent.isRunning) return;

    agent.addMessage({
      id: crypto.randomUUID(),
      role: "user",
      content: "Summarize the latest sales data",
    });

    try {
      await copilotkit.runAgent({ agent });
    } catch (error) {
      console.error("CopilotKit runAgent failed:", error);
    }
  };

  return (
    <>
      <button onClick={run} disabled={agent.isRunning}>
        Run agent
      </button>
      <button
        onClick={() => copilotkit.stopAgent({ agent })}
        disabled={!agent.isRunning}
      >
        Stop
      </button>
    </>
  );
}
```

### `copilotkit.runAgent()` 与 `agent.runAgent()` 的区别

两个方法都会触发智能体，但它们工作在不同的层级：

- **`copilotkit.runAgent({ agent })`** —— 推荐的默认选择。编排完整生命周期：执行前端工具、处理后续运行，并通过订阅者系统路由错误。
- **`agent.runAgent(options)`** —— 智能体实例上的底层方法。它把请求发送给运行时，但**不会**执行前端工具，也不会串联后续运行。只在需要直接控制时使用它。（在中断恢复场景下，标准 AG-UI 中断请使用 `copilotkit.runAgent({ agent, resume })`，旧版 `on_interrupt` 自定义事件请使用 `copilotkit.runAgent({ agent, forwardedProps: { command: { resume, interruptEvent } } })`——下面的代码片段展示的正是旧版形式——这样订阅者生命周期仍会包住恢复后的运行。）

## 订阅智能体事件

`agent.subscribe(subscriber)` 返回 `{ unsubscribe }`。订阅者对象接受所有 AG-UI 生命周期回调：`onCustomEvent`、`onRunStartedEvent`、`onRunFinalized`、`onRunFailed`，以及各流式增量。可以用它驱动自定义进度 UI、把事件转发给分析系统，或捕获框架的暂停/恢复事件并用负载将其解决（即下文的模式）。

## 通过按钮解决 LangGraph 中断

`interrupt-headless` 单元展示了不借助 `useInterrupt` 或聊天界面的完整模式。一个普通 hook 订阅 `on_interrupt` 自定义事件，缓冲负载直到运行结束（避免 UI 在流式过程中闪烁），并暴露一个 `resolve(response)` 回调，该回调调用 `copilotkit.runAgent({ agent, forwardedProps: { command: { resume, interruptEvent } } })` 来解除图的阻塞：

## 通过按钮解决前端工具调用

对于基于 Promise 的集成，没有原生的中断原语——演示改用带 Promise 处理器的 `useFrontendTool`。处理器通过 React state 暂存它的 `resolve` 回调和待定负载，应用界面在聊天之外渲染选择器，用户的选择会 resolve 智能体工具调用正在等待的那个 Promise。相同的 UX，不同的机制——智能体永远不知道自己面对的是按钮网格而不是聊天选择器：

## 通过按钮解除暂停

> **此框架不支持中断式的暂停/恢复**。
> 上面展示的无头中断模式，要求底层运行时要么暴露原生 `interrupt(...)` 原语（LangGraph），要么提供基于 Promise 解析的前端工具路径。对于所有其他集成，请改用 [`useHumanInTheLoop`](./human-in-the-loop) 来驱动暂停——它是基于工具调用的暂停/恢复流程的标准 hook，适用于所有支持工具调用的框架。上文中的 `agent.addMessage`、`copilotkit.runAgent` 和 `agent.subscribe` 原语依然适用——只有中断解决路径因框架而异。

</WhenFrameworkHas>
