title: 文档贡献
---

我们迭代很快，文档有时会滞后于代码，因此非常欢迎对文档站的贡献。

文档站位于 [CopilotKit](https://github.com/CopilotKit/CopilotKit) monorepo 中的 `showcase/shell-docs`。它是一个 [Fumadocs](https://fumadocs.dev/) 站点；旧版 Nextra 的 `docs/` 目录正在逐步淘汰，不再是撰写新内容的正确位置。

## 前置条件

- [Node.js](https://nodejs.org/en/) 20.x 或更高版本
- 全局安装 [pnpm](https://pnpm.io/) v10.x（`npm i -g pnpm@^10`）
- [Nx](https://nx.dev/)——用于驱动 monorepo 中的所有任务。无需全局安装，仓库的 `pnpm install` 会提供一切。

## 如何贡献

<Steps>
  <Step>
  ### 复刻并克隆仓库

首先，复刻（fork）[CopilotKit GitHub 仓库](https://github.com/CopilotKit/CopilotKit)，然后克隆你的复刻：

```shell
git clone https://github.com/<your-username>/CopilotKit
cd CopilotKit
pnpm install
```

在仓库根目录运行 `pnpm install` 会安装 workspace 中的每个包，并配置好 lefthook pre-commit 钩子（lint、format、test）——首次提交之前必须运行一次。

  </Step>
  <Step>
  ### 在本地运行文档站

shell-docs 站点是一个 Nx 项目（`@copilotkit/showcase-shell-docs`）。在仓库根目录通过 Nx 运行它：

```shell
nx run shell-docs:dev
```

站点将在 [http://localhost:3003](http://localhost:3003) 上提供服务。如果你更愿意在包目录中运行，`cd showcase/shell-docs && pnpm dev` 也可以——两者走的是同一个脚本。

<Callout type="info">
请始终优先通过 Nx（`nx run`、`nx run-many`、`nx affected`）运行任务，而不是直接使用底层工具。这是整个 monorepo 的约定，可确保任务依赖得到遵守。
</Callout>

  </Step>
  <Step>
  ### 进行修改

文档页面位于：

```
showcase/shell-docs/src/content/docs/
```

需要记住的几条约定：

- 站点使用 **Fumadocs** 构建。内容以 MDX 编写。Frontmatter（`title`、`description`、`icon` 等）驱动侧边栏和元数据。
- 对于代码示例，优先使用 **`<Snippet>` region 模式**，而不是手工内联代码块。`<Snippet>` 使用 region 标记（如 `// region:my-region` … `// endregion:my-region`）从 `showcase/integrations/<framework>/...` 下的 showcase 集成中提取真实源码。这让每个代码示例都与可运行的演示代码绑定，让我们能够自动发现代码漂移。拿不准时，看看相邻页面是如何引用同一个集成的，并遵循该模式。
- hook、组件和 runtime API 的参考页面使用 `<PropertyReference>` 组件来渲染 prop/参数表。请与同一目录中现有参考页面的风格保持一致。

<Callout type="info">
打开 PR 之前，请检查自己的变更是否存在语法、拼写和格式问题，并确认链接、代码块和图片在本地开发服务器中正确渲染。
</Callout>

  </Step>
  <Step>

  ### 检查变更并提交 pull request

推送之前，lefthook pre-commit 钩子会通过 Nx 对受影响的项目运行 lint、format 和测试。如有任何失败，请修复问题后重新提交——不要绕过钩子。

对结果满意后，推送并向 [CopilotKit/CopilotKit](https://github.com/CopilotKit/CopilotKit/pulls) 仓库发起 PR。感谢你的贡献！

  </Step>
</Steps>
