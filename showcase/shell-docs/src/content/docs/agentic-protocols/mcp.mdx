## 简介

Model Context Protocol 是一项开放标准，让开发者能够在自己的数据源与 AI 驱动工具之间构建安全的双向连接。借助 MCP，你可以：

- 将 AI 应用连接到你的数据源
- 让 AI 工具安全地访问和利用你的数据
- 构建具备应用上下文的 AI 驱动特性

欲进一步了解，请访问 [Model Context Protocol](https://modelcontextprotocol.io/introduction) 网站。

## 什么时候需要（或不需要）MCP App

“MCP 服务器”涵盖了三种截然不同的东西，其中只有一种需要 [MCP App](/generative-ui/mcp-apps)。选错了，就意味着要么构建了并不需要的 UI，要么交付了一个谁都无从操作的工具。

先弄清你面对的是哪一类服务器：

| 你的服务器…… | 用户应该看到什么 | 应该构建什么 |
| --- | --- | --- |
| 读取数据并返回 | 什么都不用，或一行状态提示——答案应体现在智能体的回复里 | 普通 MCP 工具。无需渲染器。 |
| 改变某些东西（写入、发送、删除） | 即将发生的事情，并提供阻止它的方式 | 普通 MCP 工具 + 渲染器，对不可逆操作再加审批 |
| 拥有自己的界面（表单、选择器、可交互的图表） | 界面本身 | 带 UI 资源的 MCP App |

### 只读上下文服务器

这是最常见的情况，也是所需最少的情况。文档搜索、数据库查询、“查询这位客户”的工具——工具结果是*给模型的上下文*，而不是用户直接阅读的内容。智能体会把它融入自己的回答，而这个回答就是 UI。

连接服务器即可，到此为止。如果你希望工具调用可见而非隐形，通配渲染器可以为每次工具调用提供一张状态卡片，而无需为每个工具单独写一个渲染器：

```tsx
import { useDefaultRenderTool } from "@copilotkit/react-core/v2";

useDefaultRenderTool({
  render: ({ name, status, parameters, result }) => (
    <McpToolCall status={status} name={name} args={parameters} result={result} />
  ),
});
```

只有当*结果*本身真正可交互时——比如用户可以筛选的图表，而非只是阅读的表格——才需要考虑 MCP App。

### 操作与变更服务器

当工具要发送邮件、提交工单或删除一行记录时，用户需要看到它——而且通常需要授权。这仍然不是 MCP App：而是渲染器加人机协同（human-in-the-loop）。

渲染器展示发生了什么。审批步骤决定事情是否发生，凡是用户无法撤销的操作都应该有它。审批流程见[人机协同](/human-in-the-loop)，渲染器选项见[工具渲染](/generative-ui/tool-rendering)。

一个实用的判断标准：如果你考虑 MCP App 仅仅是为了渲染一个确认按钮，那你要的其实是人机协同。审批是 CopilotKit 的职责，而不是由服务器提供的 UI。

### 交互式 MCP App

当*服务器*拥有界面时，MCP App 才是正确答案——它暴露一个带有关联 UI 资源的工具，CopilotKit 会获取该资源并在沙箱化的 iframe 中渲染，而你无需编写任何前端代码。

当交互丰富到需要真正的 UI（座位选择器、配置表单、内嵌编辑器），并且应该由服务器作者——而非应用作者——来定义其外观时，这样做才值得。代价是服务器从此要发布 UI 并管理其版本，因此只读查询用不着它。

设置方法见 [MCP App](/generative-ui/mcp-apps)。

<Callout type="info">
  这几类并不互斥。同一个服务器可以同时暴露普通工具和由 App 支撑的工具；CopilotKit 会根据每次调用是否携带 UI 资源来决定如何渲染。
</Callout>

## 高级用法

### 实现 McpToolCall 组件

<details>
<summary>点击查看 McpToolCall 组件的实现</summary>

```tsx
"use client";

interface ToolCallProps {
  status: "complete" | "inProgress" | "executing";
  name?: string;
  args?: any;
  result?: any;
}

export default function MCPToolCall({
  status,
  name = "",
  args,
  result,
}: ToolCallProps) {
  const [isOpen, setIsOpen] = React.useState(false);

  // Format content for display
  const format = (content: any): string => {
    if (!content) return "";
    const text =
      typeof content === "object"
        ? JSON.stringify(content, null, 2)
        : String(content);
    return text
      .replace(/\\n/g, "\n")
      .replace(/\\t/g, "\t")
      .replace(/\\"/g, '"')
      .replace(/\\\\/g, "\\");
  };

  return (
    <div className="bg-[#1e2738] rounded-lg overflow-hidden w-full">
      <div
        className="p-3 flex items-center cursor-pointer"
        onClick={() => setIsOpen(!isOpen)}
      >
        <span className="text-white text-sm overflow-hidden text-ellipsis">
          {name || "MCP Tool Call"}
        </span>
        <div className="ml-auto">
          <div
            className={`w-2 h-2 rounded-full ${
              status === "complete"
                ? "bg-gray-300"
                : status === "inProgress" || status === "executing"
                  ? "bg-gray-500 animate-pulse"
                  : "bg-gray-700"
            }`}
          />
        </div>
      </div>

      {isOpen && (
        <div className="px-4 pb-4 text-gray-300 font-mono text-xs">
          {args && (
            <div className="mb-4">
              <div className="text-gray-400 mb-2">Parameters:</div>
              <pre className="whitespace-pre-wrap max-h-[200px] overflow-auto">
                {format(args)}
              </pre>
            </div>
          )}

          {status === "complete" && result && (
            <div>
              <div className="text-gray-400 mb-2">Result:</div>
              <pre className="whitespace-pre-wrap max-h-[200px] overflow-auto">
                {format(result)}
              </pre>
            </div>
          )}
        </div>
      )}
    </div>
  );
}
```

将 MCP 服务器挂载到智能体上。智能体会在一次运行开始时为每个服务器打开一个客户端，并在运行结束时关闭它，因此请求之间不会缓存任何内容：

```tsx title="app/api/copilotkit/route.ts"
import { BuiltInAgent } from "@copilotkit/runtime/v2";
import {
  CopilotRuntime,
  createCopilotRuntimeHandler,
} from "@copilotkit/runtime/v2";

const runtime = new CopilotRuntime({
  agents: {
    default: new BuiltInAgent({
      model: "openai/gpt-4o",
      mcpServers: [
        {
          type: "sse",
          url: "https://my-mcp-server.example.com/sse",
          headers: { Authorization: `Bearer ${process.env.MCP_API_KEY}` },
        },
      ],
    }),
  },
});

export const POST = createCopilotRuntimeHandler({
  runtime,
  basePath: "/api/copilotkit",
});
```

HTTP 传输、多服务器配置以及 `mcpClients` 的用法见 [MCP 服务器](/docs/integrations/built-in-agent/mcp-servers)——当你需要持久连接或按请求凭证时，`mcpClients` 可以让你自己掌控客户端生命周期。

<Callout type="warn" title="v1 运行时上的 `createMCPClient`">
  `@copilotkit/runtime` 中的 `new CopilotRuntime({ mcpServers, createMCPClient })` 是已弃用的 v1 API。它仍然可用，但它在运行时的整个生命周期内为每个端点保留一个客户端，而不是每次运行都打开再关闭。新项目请使用上面的智能体级配置。
</Callout>
