你已经有一个可用的智能体，希望用户能够调整它的行为方式：语气、专业水平、响应长度、语言、人设。学完本指南后，你的 UI 将持有一个类型化的配置对象，智能体在每次运行时都会读取它并据此重建系统提示。

## 何时使用

只要智能体的行为依赖于不适合作为聊天输入的用户可控设置，就适合使用智能体配置：

- **语气、语调、人设**：“俏皮”“正式”“随和”
- **专业水平**：“初学者”“中级”“专家”
- **响应形态**：短 / 中 / 长、结构化 / 散文式、语言
- **领域切换**：查询哪个知识库、启用哪部分工具子集

如果这些值是用户偶尔调整的*渠道*（设置面板、一排下拉选择器），那么智能体配置就是正确的形态。如果这些值是智能体应当写回的*内容*（笔记、文档、计划），请改用[共享状态](/shared-state)。

智能体配置如何从 UI 流入智能体的推理循环，取决于你的运行时架构。位于运行时之后的智能体在每次运行时从智能体状态中读取它，而进程内智能体则以转发属性（forwarded properties）的形式在提供方上接收同一个对象——用户体验相同，只是两侧的接线略有不同。

## 工作原理

<FrameworkSetup concept="agent-config-setup" />

智能体配置是一个由前端持有、并作为运行时上下文发布给智能体的类型化对象。后端读取该上下文条目并将其转换为系统提示。

<FrontendOnly frontend="react">
将类型化配置保存在 React state 中，然后通过 `useAgentContext` 把每次变更同步给智能体：

```tsx title="frontend/src/app/page.tsx — UI 发布类型化配置"
function ConfigContextRelay({ config }: { config: AgentConfig }) {
  useAgentContext({
    description: "Agent response preferences",
    value: {
      tone: config.tone,
      expertise: config.expertise,
      responseLength: config.responseLength,
    },
  });
  return null;
}
```
</FrontendOnly>

<FrontendOnly frontend="angular">
将配置保存在 Angular signal 中，并通过 `connectAgentContext` 发布计算得到的上下文。可运行的 Angular Showcase 正是使用了这个从 signal 到上下文的桥接：

</FrontendOnly>

上面的框架配置展示了所选智能体对应的确切后端桥接。在所有框架中，流程都是一样的：从当前运行中读取最新的有效上下文，并用它构建该轮次的系统提示。

```text title="后端流程"
config = latestValidConfig(currentRun.context)
systemPrompt = buildSystemPrompt(config)
model.invoke(systemPrompt, currentUserRequest)
```

智能体在每轮开始时读取最新的类型化配置，重建系统提示，然后执行该轮次。这与[共享状态的写入侧模式](/shared-state#writing-to-agent-state)是同一个形态；智能体配置只是该模式的一种具体用法，在其上叠加了一个由 UI 持有的类型化对象。

## 工作原理

运行时以进程内方式持有智能体，因此配置经由前端运行时属性而非智能体状态传递。不需要单独的后端服务来推送状态：类型化对象直接成为智能体工厂的输入。

<FrontendOnly frontend="react">
将类型化对象作为 `properties` 传给 `<CopilotKit>`：

```tsx title="frontend/src/app/page.tsx — 配置经由提供方传递"
<CopilotKit
  runtimeUrl="/api/copilotkit"
  properties={{ tone, expertise, responseLength }}
  useSingleEndpoint
>
  <Demo />
</CopilotKit>
```
</FrontendOnly>

<FrontendOnly frontend="angular">
每当 Angular signal 变化时更新运行时属性：

```ts title="src/app/agent-config.component.ts"
import { Component, effect, inject, signal } from "@angular/core";
import { CopilotKit } from "@copilotkit/angular";

@Component({
  selector: "app-agent-config",
  standalone: true,
  template: `
    <button type="button" (click)="tone.set('concise')">Concise</button>
    <button type="button" (click)="tone.set('detailed')">Detailed</button>
  `,
})
export class AgentConfigComponent {
  private readonly copilotKit = inject(CopilotKit);
  protected readonly tone = signal<"concise" | "detailed">("concise");

  constructor() {
    effect(() => {
      this.copilotKit.updateRuntime({
        properties: { tone: this.tone() },
      });
    });
  }
}
```
</FrontendOnly>

运行时在每次调用时都会把同一个对象作为 `input.forwardedProps` 交给智能体工厂。工厂在返回该轮次的智能体之前，会用这些字段构建系统提示：

```ts title="backend/agent factory — 每轮合成系统提示"
export const agentConfigFactory = async (input: AgentFactoryInput) => {
  const { tone, expertise, responseLength } = input.forwardedProps ?? {};
  const systemPrompt = buildSystemPrompt(tone, expertise, responseLength);
  return makeAgent({ systemPrompt /* ... */ });
};
```
