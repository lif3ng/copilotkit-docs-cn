托管的 Slack 和 Microsoft Teams 会把以斜杠开头的文本当作普通消息内容。表情回应处理器让智能体能够响应轻量级反馈，而无需把每个 emoji 都当作新的聊天消息。

## 托管命令不会被分发

生成的 Slack manifest 不会注册斜杠命令，托管的 Microsoft Teams 也不会解释 `/name` 前缀。因此，像 `/triage customer` 这样的消息会以普通文本的形式到达 `onMessage` 或 `onMention`。

`defineChannelCommand`、`commands` 和 `onCommand` 仍可用于会发出原生命令事件的直连适配器。它们不会让托管的 Slack 或 Microsoft Teams Channel 启用命令路由。

## 路由提及与普通消息

为来自提供方的普通消息注册 `onMessage`。当 `onMention` 已注册时，机器人被提及会选中 `onMention`；否则该提及会回退到 `onMessage`。非提及消息会选中 `onMessage`，且一条入站消息只会运行其中一条处理器路径。

<FrontendOnly frontend="slack">

当前生成的 manifest 除了订阅 `app_mention` 之外，还会订阅普通频道、私有频道、群组私聊（group DM）和私聊（DM）事件。由旧版 manifest 创建的 Slack 应用可能需要套用当前的事件订阅与机器人 scope，然后重新安装该应用。

</FrontendOnly>

<FrontendOnly frontend="teams">

在托管入口对活动进行规范化处理后，Microsoft Teams 消息会使用同样的 `onMessage` 与 `onMention` 选择逻辑。

</FrontendOnly>

## 处理收到的表情回应

已知的 Slack shortcode 和 Microsoft Teams 表情回应 token 会被规范化为可移植名称。可移植的出站集合为 `thumbs_up`、`thumbs_down`、`heart`、`fire`、`eyes`、`refresh`、`thinking` 和 `tada`。

```ts title="channel.ts"
channel.onReaction("eyes", async ({ added, thread, user }) => {
  await thread.post(
    added
      ? `${user?.name ?? "Someone"} marked this response for follow-up.`
      : `${user?.name ?? "Someone"} removed the follow-up marker.`,
  );
});
```

省略 emoji 参数即可接收所有新增与移除的表情回应：

```ts title="channel.ts"
channel.onReaction(async ({ emoji, rawEmoji, added, thread }) => {
  audit.record({ emoji, rawEmoji, added });
  await thread.post("Reaction recorded.");
});
```

当 SDK 能够识别时，`emoji` 是规范化后的值。`rawEmoji` 则保留提供方的原始 token，用于自定义或未映射的 emoji。

<Callout type="info" title="支持无输出的处理器">
  即使处理器没有发送任何消息，SDK 也会完结并确认一个托管回合。托管交付仍为至少一次（at-least-once），因此请让静默的审计或数据库写入保持幂等。
</Callout>

<FrontendOnly frontend="slack">

生成的 Slack manifest 会订阅 `reaction_added` 和 `reaction_removed`。托管入口会把机器人输出以及用户发出的根消息和回复上的表情回应，路由回其所在的既有托管对话；工作区中无关消息上的表情回应会被忽略。

</FrontendOnly>

<FrontendOnly frontend="teams">

Microsoft Teams 的 `messageReaction` 活动会经过同一个处理器规范化。像“赞”（Like）和“心”（Heart）这类经典表情回应，以及可识别的现代 emoji token，都会映射到 SDK 的可移植名称。

出站表情回应的新增/移除使用 Microsoft 的公开预览版表情回应 API。托管配置会针对租户验证该 API；当租户无法使用它时，配置将保持未就绪状态。

</FrontendOnly>

## 为单条消息附加表情回应处理器

当只有某一个已发送的组件需要对表情回应做出响应时，使用 `Message.onReaction`：

```tsx title="feedback-card.tsx"
import { Message, Section } from "@copilotkit/channels/ui";

export function FeedbackCard({ answerId }: { answerId: string }) {
  return (
    <Message
      onReaction={async (emoji, reaction) => {
        if (reaction.added && emoji === "thumbs_up") {
          await feedback.record(answerId, reaction.user?.id);
          await reaction.thread.post("Thanks for the feedback.");
          return;
        }
        await reaction.thread.post("Reaction update received.");
      }}
    >
      <Section>React with 👍 if this solved the problem.</Section>
    </Message>
  );
}
```

在 `createChannel({ components: [FeedbackCard] })` 中注册 `FeedbackCard`。要在进程重启后继续生效，还需要一个持久化的 `StateStore`，因为 SDK 必须重新加载拥有该回调的组件快照。

使用当前消息或会话记录中带投递作用域的引用，添加或移除机器人的表情回应：

```ts title="channel.ts"
channel.onMessage(async ({ message, thread }) => {
  await thread.react(message.ref, "eyes");
  await thread.unreact(message.ref, "eyes");
});
```

可移植集合适用于托管的 Slack 和 Microsoft Teams。当你的代码需要针对原生提供方分支处理时，允许使用提供方原生的字符串：在消息处理器中使用 `message.platform`，或在 `onReaction` 中使用 `reaction.thread.platform`。不支持的值会显式报错。

完整的处理器形态请参阅[命令参考](/reference/channels/functions/defineChannelCommand)和 [Message 参考](/reference/channels/components/Message)。
