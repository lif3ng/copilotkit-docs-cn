每条已投递的 Slack 或 Teams 会话都会成为一个 Channels SDK `Thread`。它是传递给 `onMessage`、工具、交互和中断回调的回复与工作流句柄。

<Callout type="info" title="Channels 线程不是 Intelligence 线程">
  Channels 的 `Thread` 是 SDK 内的一条平台会话。[Threads Drawer](/prebuilt-components/copilot-threads-drawer) 提供用于浏览和恢复智能体对话的应用 UI；可用 [`useThreads`](/reference/hooks/useThreads) 构建自定义 UI。两者共享同一个稳定的 thread id，但属于不同的 API。
</Callout>

## 会话身份

`thread.conversationKey` 是 Intelligence 为原生会话提供的不透明且稳定的键。不要解析它，也不要从其值推断 workspace、team、channel 或 thread 标识符。SDK 会把同一个值传给你的 `agent(threadId)` 工厂（或设置到克隆出的单例上），这正是每个快速开始都创建全新 agent 并赋予其 `threadId` 的原因。

```ts title="agent.ts"
export function makeAgent(threadId: string) {
  const agent = createAgentForYourFramework();
  agent.threadId = threadId;
  return agent;
}
```

推荐使用 agent **工厂**，让每一轮都获得显式的新实例。你也可以传入单例（`agent: shared`）；SDK 会在每次运行时于底层调用 `shared.clone()`，使并发轮次不会共享同一个可变对象。托管历史会在隔离之后加载到该次运行的 agent 上。

托管投递准入会让同一条规范会话保持独占，而不相关的会话并行运行。SDK 的 `store.concurrency` 设置仍管控其他适配器路径和共享工作流状态；它不会提高托管同 Thread 的投递上限。

原生提供方在 `message.platform` 和 `thread.platform` 上都可用。托管轮次会报告 `"slack"` 或 `"teams"`。

<Callout type="info" title="会话身份与用户身份要分开">
  一个 Thread 可以包含多个提供方参与者，且没有个人属主。在把应用用户数据或个人 Memory 附加到某一轮之前，请先参阅[身份与记忆](/channels/identity-and-memory)。
</Callout>

## 欢迎新安装或新会话

`onWelcome` 处理提供方安装或会话激活事件。它是一个生命周期事件，而非合成的用户消息，因此不会运行 `onMessage`，也不会向会话添加虚构的用户轮次。

```ts title="channel.ts"
channel.onWelcome(async ({ thread, user }) => {
  await thread.post(
    user ? `Welcome, ${user.name}.` : "Welcome. How can I help?",
  );
});
```

`user` 是 `identifyUser` 为该事件选出的可为空的应用用户。触发事件的提供方账户仍以 `actor` 的形式可用。

## Intelligence 恢复哪些内容

对于每个新轮次，托管传输层会为 agent 重建最近的会话历史。当前进行中的消息不在所拉取的历史里。省略 `prompt` 时，`runAgent()` 会自动注入它；当一轮可能同时包含文本与附件时，请传入显式合并的 prompt：

```ts title="channel.ts"
channel.onMessage(async ({ thread, message }) => {
  await thread.runAgent({
    prompt: message.contentParts?.length
      ? [
          ...(message.text
            ? [{ type: "text" as const, text: message.text }]
            : []),
          ...message.contentParts,
        ]
      : message.text,
  });
});
```

这段历史是用于给 agent 提供上下文种子的对话记录。它与应用工作流状态（例如审批步骤、所选环境或表单草稿）是分开的。

## 持久化工作流状态

对以 `conversationKey` 为键的 JSON 可序列化状态，请使用 `thread.state()` 和 `thread.setState()`。Standard Schema 让读取具有类型，并对写入进行校验：

```bash title="Terminal"
npm install zod
```

<FrontendOnly frontend="slack">

```ts title="channel.ts"
import { createChannel } from "@copilotkit/channels";
import { z } from "zod";
import { makeAgent } from "./agent.js";
import { durableStateStore } from "./state-store.js";

function required(name: string): string {
  const value = process.env[name];
  if (!value) throw new Error(`Missing ${name}`);
  return value;
}

const workflowState = z.object({
  incidentId: z.string(),
  stage: z.enum(["triage", "awaiting-approval", "resolved"]),
});

const channel = createChannel({
  name: required("CHANNEL_CODE"),
  identifyUser: "platform",
  agent: makeAgent,
  store: {
    state: workflowState,
    adapter: durableStateStore,
  },
});

channel.onMessage(async ({ thread, message }) => {
  const current = await thread.state();
  await thread.setState({
    incidentId: current?.incidentId ?? "INC-421",
    stage: "triage",
  });
  await thread.runAgent({ prompt: message.text });
});
```

</FrontendOnly>

`setState` 会整体替换存储值，不会合并局部补丁。

## 有意选择持久化边界

托管实时路径会恢复平台会话历史，但不会自动接好一个持久化的 SDK `StateStore`。没有 `store.adapter` 时，默认的 MemoryStore 只把这些内容保存在当前进程中：

- `thread.state()`
- 已注册的交互式操作快照
- SDK 锁、去重窗口和队列

对于必须跨部署存续的生产工作流，请为 [`StateStore` 契约](/reference/channels/classes/Channel#statestore-contract)提供一个持久化的应用侧实现。该契约包含键/值、列表、锁、去重和队列操作。值必须能经 JSON 往返无损。

<Callout type="warn" title="不要从 Online 状态推断持久性">
  **Online** 只确认托管连接健康、可以接收投递邀请。要测试投递，请发送一条真实的提供方消息。该状态并不能证明你的应用工作流状态能在进程重启后存续，因此在上线持久化工作流之前，请先在审批卡片待处理时测试一次重启。
</Callout>

## 运维清单

- 每个 `conversationKey` 使用一个全新的 agent。
- 把当前入站消息传给 `runAgent`。
- 对当前轮次按 `message.platform` 分支；当只有 Thread 可用时，`thread.platform` 携带相同的原生提供方。
- 只存储 JSON 可序列化的工作流数据。
- 传给 `setState` 的值采用整体替换，而非局部修补。
- 在承诺重启安全的审批之前，先配置好持久化的 `StateStore`。
- 在收到 `SIGINT` 和 `SIGTERM` 时停止监听器，让 Intelligence 干净地释放运行时。

方法请参阅 [Thread API](/reference/channels/classes/Thread)，托管恢复流程请参阅[交互式审批](/channels/interactive)。
