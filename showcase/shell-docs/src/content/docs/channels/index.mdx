## 从你的编程智能体开始

把这段提示复制到你的编程智能体中，让它帮你选择框架、配置智能体，并通过 CopilotKit Intelligence 把它连接到 Slack 或 Microsoft Teams。更愿意自己完成配置？请遵循下面的指南。

<ChannelsStartPrompt />

Channels 把你的智能体带入工作已经发生的对话之中。你的智能体依然运行在你自己的基础设施上。CopilotKit Intelligence 持有渠道连接（Slack、Teams、Discord 等），把每个回合投递给你的 Channels SDK 监听器，并把响应以原生渠道 UI 的形式发回去。

正如 [CopilotKit Intelligence 概览](/intelligence/overview)中所解释的，CopilotKit 开源版与 CopilotKit Intelligence 的分界线是持久化数据：不依赖它即可运行的功能属于开源版，而建立在持久化数据连接之上的功能——数据库及其中保存的状态——则属于 CopilotKit Intelligence。渠道运行器要在生产环境中正确运行就需要持久化数据：并发的参与者、竞态条件、重试与投递保证都依赖它。CopilotKit Intelligence 提供托管的渠道运行器，运行在其上的渠道还能获得 CopilotKit Intelligence 的其余能力，包括 Product Analytics、Automatic Learning 与治理。你当然可以在开源的 Channels SDK 上构建并运营自己的渠道运行器——只是持久化数据层要由你自己实现。

每条消息都经过同样的五个阶段：

1. 有人在 Slack 或 Teams 中给你的应用发消息。
2. CopilotKit Intelligence 使用为该 Channel 配置的凭据接收平台事件。
3. 一条常驻的 Intelligence 网关连接把该回合投递给你长驻的 Channels SDK 进程。
4. SDK 通过 [AG-UI](/agentic-protocols/ag-ui) 运行你的智能体，执行渠道工具，并渲染响应。
5. Intelligence 把结果以原生 Slack Block Kit 或 Teams Adaptive Card 内容的形式发回。

这种切分让平台凭据远离你的智能体进程，同时无需把你的智能体、工具或业务逻辑搬进 CopilotKit。

| 你自己运行                             | CopilotKit Intelligence 托管                  |
| -------------------------------------- | --------------------------------------------- |
| 智能体及其模型凭据                      | Slack 和 Teams 平台凭据                        |
| 长驻的 Channels SDK 监听器              | 平台入口与带凭据的投递                         |
| 工具与审批业务逻辑                      | 运行时注册、健康状态与重连                     |
| 部署、日志与应用侧身份验证              | 向监听器投递对话历史                           |

## 生产级自托管：在你自己的基础设施中运行 CopilotKit Intelligence

生产级自托管把你的 Channels 配置、提供方凭据、投递状态与平台运维都保留在你自己的网络内，让你的组织掌控数据驻留、安全与基础设施。你完全可以自托管 Channels SDK。上手指南即将推出；在此期间，如果你熟悉 Docker 和 Kubernetes，尽可以放手去做——我们也乐意提供帮助。
