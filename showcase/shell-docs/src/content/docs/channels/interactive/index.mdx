Channels JSX 把可移植组件渲染为原生渠道 UI。用它来做按钮、摘要和人机协同审批，而无需手工维护提供方 payload。

<FrontendOnly frontend="slack">

在 Slack 上，Channels JSX 渲染为 Block Kit。按钮点击会以 `block_actions` 事件的形式经由签名托管的 webhook 返回。

<Callout type="info" title="使用当前的 Slack manifest">
  新生成的 Slack manifest 会启用 **Interactivity** 并配置托管回调 URL。如果应用是由旧 manifest 创建的，请在测试按钮之前：在 Intelligence 中打开该 Channel，回到它的 Slack 配置说明，套用生成的 manifest，并重新安装应用。重新安装后，请在 Intelligence 中使用当前的 Bot User OAuth token，以防 Slack 重新签发过。参见[在 Intelligence 中配置 Channel](/channels/intelligence)。
</Callout>

</FrontendOnly>

<FrontendOnly frontend="teams">

在 Microsoft Teams 上，Channels JSX 渲染为 Adaptive Cards。按钮以 `Action.Submit` 渲染，点击会以消息活动的形式返回托管连接。Teams 的 `Action.Submit` 活动可能在没有来源消息 ref 的情况下到达；此时 `message.ref.id` 为空。

</FrontendOnly>

## 启用 Channels JSX

该 package 仅支持 ESM。在 `package.json` 中保留 `"type": "module"`，并添加：

```json title="tsconfig.json"
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "jsx": "react-jsx",
    "jsxImportSource": "@copilotkit/channels",
    "strict": true,
    "noEmit": true
  },
  "include": ["*.ts", "*.tsx"]
}
```

## 发送原生操作

定义一个具名组件，并在 Channel 上注册它：

```tsx title="approval-card.tsx"
import {
  Actions,
  Button,
  Header,
  Message,
  Section,
} from "@copilotkit/channels/ui";

export function ApprovalCard({ summary }: { summary: string }) {
  return (
    <Message>
      <Header>Approval required</Header>
      <Section>{summary}</Section>
      <Actions>
        <Button
          style="primary"
          value={{ approved: true }}
          onClick={async ({ thread, message, action }) => {
            const value = action.value;
            if (value === undefined) {
              await thread.post(
                "The approval value was missing. Please try again.",
              );
              return;
            }

            if (message.ref.id) {
              try {
                await thread.update(
                  message.ref,
                  <Message>
                    <Header>Approved</Header>
                    <Section>{summary}</Section>
                  </Message>,
                );
              } catch {
                // Updating the card is best-effort; always resume the agent.
              }
            }
            await thread.resume(value);
          }}
        >
          Approve
        </Button>
        <Button
          style="danger"
          value={{ approved: false }}
          onClick={async ({ thread, message, action }) => {
            const value = action.value;
            if (value === undefined) {
              await thread.post(
                "The approval value was missing. Please try again.",
              );
              return;
            }

            if (message.ref.id) {
              try {
                await thread.update(
                  message.ref,
                  <Message>
                    <Header>Rejected</Header>
                    <Section>{summary}</Section>
                  </Message>,
                );
              } catch {
                // Updating the card is best-effort; always resume the agent.
              }
            }
            await thread.resume(value);
          }}
        >
          Reject
        </Button>
      </Actions>
    </Message>
  );
}
```

```tsx title="channel.tsx"
import { createChannel } from "@copilotkit/channels";
import { ApprovalCard } from "./approval-card.js";
import { makeAgent } from "./agent.js";

function required(name: string): string {
  const value = process.env[name];
  if (!value) throw new Error(`Missing ${name}`);
  return value;
}

const channel = createChannel({
  name: required("CHANNEL_CODE"),
  identifyUser: "platform",
  agent: makeAgent,
  components: [ApprovalCard],
});

channel.onInterrupt<{ summary: string }>(
  "on_interrupt",
  async ({ payload, thread }) => {
    await thread.post(<ApprovalCard summary={payload.summary} />);
  },
);
```

</FrontendOnly>

注册让操作注册表能在后续点击到达时重建具名组件。请保持组件 props 可 JSON 序列化。

只有当 `message.ref.id` 非空时，才把交互消息当作可更新。本例中的卡片更新是尽力而为：ref 缺失或更新失败都不能阻止 `thread.resume(value)` 继续处理审批。

## 用发送-恢复模式处理托管审批

托管投递不能在 `thread.awaitChoice()` 里等待。点击会作为一条单独的被认领投递到达，因此阻塞第一条投递会让审批无法被处理。

对于会发出 SDK 所支持 `on_interrupt` 事件的智能体，安全的流程是：

1. 智能体发出 `on_interrupt` 事件。
2. `channel.onInterrupt` 发送已注册的组件后立即返回。
3. Intelligence 确认原始回合。
4. 随后的点击在可能时更新卡片，并调用 `thread.resume(value)`。
5. SDK 带着审批结果重新进入智能体。

所选智能体框架决定它如何发出与消费中断。智能体侧的中断请遵循其[人机协同指南](/human-in-the-loop)；Channel 处理器只保留可移植的展示与 `resume`。

<Callout type="info" title="框架的中断支持并非普遍具备">
  经过验证的托管路径是一个由 DeepAgent 工具驱动的审批：发出 `on_interrupt`、从投递中返回，然后从后续交互中恢复。对于其他所有后端，请遵循其人机协同指南，并运行一次真实提供方测试，确认中断到达 `onInterrupt`、处理器返回、后续点击调用了 `resume`、智能体消费了该值。不要假设原生 AG-UI 中断是可移植的。默认的 `sanitizeAgentEvents` 行为会修复一个已知的事件校验问题；它本身并不会增加框架中断支持。
</Callout>

<Callout type="warn" title="重启持久化需要 StateStore">
  托管的实时连接不会自动持久化 SDK 操作快照。默认的 MemoryStore 只把它们保存在当前进程里。注册组件让恢复成为可能，但对重启前卡片的点击仍需要一个持久化的 `createChannel({ store: { adapter } })` 后端。参见[线程与状态](/channels/threads-and-state)。
</Callout>

## 能力差异

文本与分节（section）是可移植的基线。交互行为还取决于所选提供方的应用配置：

<FrontendOnly frontend="slack">

- Slack 可以通过 Block Kit 投递按钮、下拉选择与输入框。当前生成的 manifest 已启用 Interactivity；对旧应用，请在 Intelligence 中打开该 Channel，从它的 Slack 配置说明中套用生成的 manifest，并重新安装。参见[在 Intelligence 中配置 Channel](/channels/intelligence)。

</FrontendOnly>

<FrontendOnly frontend="teams">

- Teams 可以把 Adaptive Cards 中的 `Action.Submit` 按钮作为消息活动投递。

</FrontendOnly>

其他提供方专属特性仍受能力门控：

- 收到的表情回应在 Intelligence 投递时即可处理，托管适配器支持添加或移除文档所列的可移植表情回应。
- 模态框的打开/提交回调是直连适配器的能力，不属于托管的 Slack 或 Teams 实时路径。
- 临时消息、会话标题和建议提示可能返回 `{ ok: false }`；当工作流依赖它们时，请检查返回结果。

处理器参数请参阅 [JSX 回调参考](/reference/channels/types/JSXCallbacks)，post、update 与 resume 的签名请参阅 [Thread API](/reference/channels/classes/Thread)。
