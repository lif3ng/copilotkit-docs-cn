托管 Channel 可以把提供方附件水合（hydrate）为 `message.contentParts`。SDK 以一种提供方中立的提示形态承载文本、图片、音频、视频和 PDF 文档。

## 把附件传给智能体

托管对话历史不包含当前入站回合。当省略 `prompt` 时，`runAgent()` 会自动选用入站文本或附件 part。当同一回合可能同时包含 `message.text` 和 `message.contentParts` 时，请构建组合提示：

```ts title="channel.ts"
channel.onMessage(async ({ thread, message }) => {
  const prompt = message.contentParts?.length
    ? [
        ...(message.text
          ? [{ type: "text" as const, text: message.text }]
          : []),
        ...message.contentParts,
      ]
    : message.text;

  await thread.runAgent({ prompt });
});
```

如果只传 `message.text`，模型将不会收到已水合的二进制附件。如果存在 `contentParts`，不要自行把它追加到托管历史；`runAgent` 会为该回合添加显式提示。

## 理解内容映射

| 提供方文件         | `AgentContentPart`                                             |
| ----------------- | -------------------------------------------------------------- |
| 图片 MIME 类型     | `{ type: "image", source: { type: "data", value, mimeType } }` |
| 音频 MIME 类型     | `{ type: "audio", source: ... }`                               |
| 视频 MIME 类型     | `{ type: "video", source: ... }`                               |
| PDF               | `{ type: "document", source: ... }`                            |
| `text/*`          | UTF-8 `{ type: "text", text }`                                 |
| 其他二进制类型     | 一条说明附件名称与 MIME 类型的文字提示                           |

二进制 `value` 为 base64。智能体是否真正理解某个媒体 part，取决于它所选的模型与框架。请选择多模态模型，并实测你接受的确切媒体类型。

文件获取是尽力而为的。提供方摄取失败可能在 SDK 收到文件句柄之前就丢失附件。如果 Intelligence 交付了句柄但 SDK 无法水合它，SDK 会插入一条简短的失败提示，而不是让整个回合失败。

<Callout type="info" title="托管文件大小上限">
  Intelligence 目前接受的单个入站与出站 Channel 文件最大为 25 MiB。提供方的限制可能更低。
</Callout>

## Slack 文件访问

<FrontendOnly frontend="slack">

Intelligence 使用托管的 Slack bot token 下载文件。应用必须在对话之中，且有读取该文件的权限。Slack 文档将 [`files:read`](https://api.slack.com/scopes/files%3Aread) 列为允许应用从其可访问的对话中下载文件的 scope。

当前由 Intelligence 生成的 manifest 会同时请求 `files:read` 和 `files:write`。如果你的应用早于该 manifest：

1. 在 Intelligence 中打开该 Channel，回到它的 Slack 配置说明，套用生成的 manifest，使两个 bot token scope 都存在。参见[在 Intelligence 中配置 Channel](/channels/intelligence)。
2. 重新安装应用，让工作区授予这些 scope。
3. 如果 Slack 重新签发了 Bot User OAuth token，请把当前值复制到 Intelligence。
4. 把应用邀请进来源对话。
5. 发送一个新文件，并验证模型收到了它。

如果附件缺失，或以获取失败提示的形式出现：

1. 确认重新安装后的 bot token 包含 `files:read`。
2. 确认应用是来源对话的成员。
3. 发送一个新文件，并检查真实的智能体回合。

</FrontendOnly>

## Microsoft Teams 文件访问

<FrontendOnly frontend="teams">

Microsoft Teams 在不同界面上暴露文件的方式不同：

- 个人 1:1 聊天中的上传可能以可下载的 `file.download.info` 附件形式到达。
- 带有 Bot Connector `contentUrl` 的内联媒体（图片、音频、视频和 PDF）可以通过 connector token 在聊天或频道中水合。该路径不需要 Graph 授权。
- 在团队频道中，SharePoint 引用上传与内联粘贴的图片使用 Microsoft Graph。Intelligence 会读取频道消息，然后解析其引用文件或托管内容。
- 其他群聊文件上传形态仍不受支持。请逐一实测你的工作流接受的每种附件形态。

生成的 Microsoft Teams package 已经声明了受支持的 `personal` 和 `team` bot scope，设置了 `supportsFiles: true`，并请求 `ChannelMessage.Read.Group` 资源特定授权。请原样上传该生成的 package。不要添加 `groupChat`；不支持托管群聊。团队所有者会在安装期间授予该资源特定权限。

对于由 Graph 支撑的团队频道消息：

- 应用 manifest 的 `ChannelMessage.Read.Group` 资源特定授权让 Intelligence 能读取频道消息和内联托管内容。团队所有者在安装期间授予它；不需要租户管理员的 Graph 授权。Microsoft 将其记载为[资源特定授权权限](https://learn.microsoft.com/en-us/microsoftteams/platform/graph-api/rsc/resource-specific-consent)。
- `Files.Read.All` 是一个**应用级**权限，且只覆盖一种情况：上传到团队频道的文件——它以 SharePoint 引用而非内容的形式到达。它需要租户管理员授权，因此 Microsoft Teams 配置流程会提供该选项并默认跳过。已同意更宽泛的 `Files.ReadWrite.All` 的租户无需再次授予即可满足此要求。

该权限是可选的，缺少它不会阻碍连接上报就绪。没有它时，文本回合仍会运行，消息仍会投递；只有被引用的文件会被省略，或以获取失败提示的形式呈现。在 1:1 聊天中分享的文件与粘贴到频道中的图片不经过 SharePoint，因此不受影响。请分别实测个人聊天、标准/私有团队频道、内联媒体、粘贴图片以及 SharePoint 引用上传。

</FrontendOnly>

## 发送文件

`thread.postFile()` 接收字节并返回结果，而不是在提供方能力不受支持时直接抛错：

```ts title="export-report.ts"
const csv = new TextEncoder().encode(
  ["id,status", "INC-421,investigating"].join("\n"),
);

const result = await thread.postFile({
  bytes: csv,
  filename: "incident-report.csv",
  title: "Incident report",
  altText: "CSV export of the incident report",
});

if (!result.ok) {
  await thread.post(`The report could not be attached: ${result.error}`);
}
```

在托管 Channel 上，`result.ok` 表示 Intelligence 已存储托管资产、提供方已确认文件或图片效果，且 SDK 已把该资产记录进规范的 Thread 历史。

<FrontendOnly frontend="slack">

托管 Slack 使用 Slack 的外部上传（external upload）流程，可以发送通用文件类型。生成的 manifest 包含 `files:write` bot scope。如果 Slack 应用早于当前 manifest，请套用当前 manifest 并重新安装。检查 `result.ok`，然后在提供方侧展示效果重要时再核对真实的 Slack 消息。

</FrontendOnly>

<FrontendOnly frontend="teams">

托管 Microsoft Teams 支持通用出站文件。在标准与私有团队频道中，Intelligence 会把原始字节上传到频道的 SharePoint 文件区，并发送一张可见的卡片或链接。在个人聊天中，同样的 `postFile()` 调用会在需要时启动 Microsoft 原生的同意卡片流程；接受即完成受信任上传，拒绝也只是一种正常的用户选择。图片可以使用内联 Bot Connector 路径。始终检查 `result.ok`，并在投递被拒绝时发送文本回退。

</FrontendOnly>

## 将附件视为不可信输入

- 在应用侧处理之前，校验声明的 MIME 类型与文件签名。
- 对解压、解析、页数与提取出的文本设置上限。
- 不要执行宏或上传的代码。
- 在文件能触发有实质影响的写入之前，先把提供方用户解析为经过身份验证的应用身份。
- 避免记录 base64 内容、签名下载 URL 或文档文本。

确切的公开形态请参阅 [`IncomingMessage` 参考](/reference/channels/types/IncomingMessage)与 [`AgentContentPart` 参考](/reference/channels/types/AgentContentPart)。
