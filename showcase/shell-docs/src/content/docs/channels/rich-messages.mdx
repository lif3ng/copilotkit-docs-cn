Channels JSX 让应用代码只需描述一次消息，再由所选的提供方渲染器将其转换为原生 UI。同一个组件既能产出 Slack Block Kit，也能产出 Microsoft Teams Adaptive Card。

## 启用 Channels JSX

Channels JSX 在运行时不使用 React。将 TypeScript 的 JSX transform 指向 `@copilotkit/channels`：

```json title="tsconfig.json"
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "jsx": "react-jsx",
    "jsxImportSource": "@copilotkit/channels",
    "strict": true,
    "noEmit": true
  },
  "include": ["*.ts", "*.tsx"]
}
```

在 `package.json` 中保留 `"type": "module"`，并在包含 JSX 的文件中使用 `.tsx`。

## 构建可移植的状态卡片

```tsx title="incident-card.tsx"
import {
  Context,
  Divider,
  Field,
  Fields,
  Header,
  Message,
  Section,
} from "@copilotkit/channels/ui";

export function IncidentCard(props: {
  id: string;
  summary: string;
  owner: string;
  status: string;
}) {
  return (
    <Message>
      <Header>{`${props.id} · ${props.status}`}</Header>
      <Section>{props.summary}</Section>
      <Divider />
      <Fields>
        <Field>{`Owner: ${props.owner}`}</Field>
        <Field>{`Status: ${props.status}`}</Field>
      </Fields>
      <Context>Updated from the incident service</Context>
    </Message>
  );
}
```

在消息处理器或工具中发布该组件：

```tsx title="channel.tsx"
channel.onMessage(async ({ thread }) => {
  await thread.post(
    <IncidentCard
      id="INC-421"
      summary="Checkout latency is above the SLO."
      owner="Payments"
      status="Investigating"
    />,
  );
});
```

当组件包含回调时，应使用带 JSON 可序列化 props 的具名组件，并在 `createChannel({ components: [...] })` 中注册它们。纯展示组件无需注册。

## 了解各提供方的渲染结果

| Channels 组件          | Slack                                                                          | Microsoft Teams                                                |
| ---------------------- | ------------------------------------------------------------------------------ | -------------------------------------------------------------- |
| `Message`              | 扁平化为 Block Kit；当前托管连接器不转发 `accent`                              | 扁平化为 Adaptive Card；`accent` 没有原生对应物                |
| `Header`               | 标头块                                                                         | 大号粗体文本块                                                 |
| `Section`、`Markdown`  | Slack `mrkdwn` 区块                                                            | 包装为 Adaptive Card 文本                                      |
| `Fields`、`Field`      | Section 内的字段；遵循 `Field.label`                                           | Fact 集合；从 `Label: value` 文本推导标签                      |
| `Context`              | Context 块                                                                     | 小号低调文本                                                   |
| `Actions`、`Button`    | Actions 块和按钮                                                               | 顶层 `Action.Submit` 或 `Action.OpenUrl`                       |
| `Select`、`Input`      | 原生 Block Kit 控件                                                            | Adaptive Card 输入项                                           |
| `Image`、`Divider`     | 原生图像与分隔线块                                                             | 图像和分隔线                                                   |
| `Table`、`Row`、`Cell` | 原生 Slack 表格块                                                              | Adaptive Card 1.5 表格                                         |
| `Chart`                | 被 Slack 渲染器忽略                                                            | 客户端支持时使用 Teams chart 扩展                              |

未知或不支持的节点会被忽略，而不是导致整条消息失败。这让可移植渲染更具韧性，但也意味着可选可视化周围的文本仍须承载关键结果。

要将你自己的 React 组件作为图像发布，请参阅[将 JSX 作为图像发布](/channels/posting-jsx-as-images)。要在一条消息中混用原生文本与 React 快照，请参阅[渲染与轮播](/channels/render-and-carousel)。

`Select` 和 `Input` 的交互行为因提供方而异。托管 Slack 直接分发这些控件。托管 Teams 则渲染 Adaptive Card 字段，并通过某个 `Button` 的 `Action.Submit` 提交它们；该 Button 回调会在 `ctx.values` 中接收其他具名字段。Teams 不会单独分发 `Select.onSelect` 或 `Input.onSubmit`。

<FrontendOnly frontend="slack">

Slack 文本会从 GitHub 风格的 Markdown 转换为 `mrkdwn`。集合与字符串会被限制在 Slack 的原生上限内。如果消息超出顶层块预算，渲染器会附加一条截断提示。

虽然直连的 Slack 渲染器可以返回附件 accent，但当前云端托管的 Intelligence 发布与更新路径只转发块。在托管 Slack 工作流中不要依赖 `Message.accent`。

不要把关键信息只放在 `Chart` 中：Slack 渲染器目前会跳过 chart 节点。请将图表与 `Section`、`Fields` 或 `Table` 搭配使用。

</FrontendOnly>

<FrontendOnly frontend="teams">

Teams 渲染 Adaptive Card 1.5 版。chart 节点使用 Teams chart 扩展；不支持这些扩展的客户端可能会省略图表。请为每个图表搭配一段文本摘要。

按钮样式会在可能时转换为正向或破坏性样式。具体的间距、颜色和排版仍由提供方决定。

</FrontendOnly>

## 安全地更新消息

`thread.post()` 会返回一个 `MessageRef`，可在当前托管投递期间对其进行更新：

```tsx title="update.tsx"
const ref = await thread.post(<IncidentCard {...incident} status="Loading" />);

await thread.update(ref, <IncidentCard {...incident} status="Investigating" />);
```

不要持久化该 ref 并假定它在后续投递中仍可更新。对于稍后的按钮点击，请使用交互中的 `message.ref`，检查 `message.ref.id` 非空，并将更新视为尽力而为。

<FrontendOnly frontend="slack">

托管 Slack 支持 post、update 和 delete 帧。

</FrontendOnly>

托管 Teams 支持 post、update 和 delete 帧。

## 将提供方专属负载留在边界

`{ raw: nativePayload, provider }` 这一逃生通道属于底层 renderable 类型的一部分，但它不具备可移植性。请为 Slack Block Kit 标注 `provider: "slack"`，为 Teams Adaptive Card 对象标注 `provider: "teams"`。提供方不匹配时，会在效果到达提供方之前显式失败。在共享的托管代码中请优先使用 Channels 组件。

要使用回调，请参阅[交互式消息与审批](/channels/interactive)；要查看组件 props，请浏览[Channels UI 参考](/reference/channels/components/Message)。
