Channels 暴露了两套不同的历史系统：

- Intelligence 托管的对话历史为智能体重建所选提供方的会话线程。
- SDK 会话记录（transcripts）创建由应用持有、以身份为键的记录，可以跨提供方与对话。

根据你需要的行为选择其一。二者不可互换。

## 使用托管对话历史

在每个被投递的回合上，Intelligence 会为该原生会话拉取近期消息，并以此初始化一个新的智能体实例。托管适配器中的默认历史上限是 20 条消息。

当前入站回合不在拉取到的历史之中。省略 `prompt` 时，`runAgent()` 会自动注入它。当你同时需要消息文本与已水合附件时，请构建显式提示：

```ts title="channel.ts"
channel.onMessage(async ({ thread, message }) => {
  await thread.runAgent({
    prompt: message.contentParts?.length
      ? [
          ...(message.text
            ? [{ type: "text" as const, text: message.text }]
            : []),
          ...message.contentParts,
        ]
      : message.text,
  });
});
```

为每个 `conversationKey` 创建全新的智能体实例；托管适配器会把重建出的消息分配给该实例。在多个线程之间共享同一个可变智能体可能导致历史泄露或被覆盖。

## 读取当前提供方线程

`thread.getMessages()` 返回近期历史的文本视图（尽力而为、由旧到新）：

```ts title="read-thread.ts"
const messages = await thread.getMessages();
const transcript = messages
  .map((message) => `${message.isBot ? "Agent" : "User"}: ${message.text}`)
  .join("\n");
```

在托管路径上，历史拉取失败会返回 `[]` 而不是让回合失败。该方法是面向文本的：二进制的图片、音频和视频内容可通过多模态历史提供给智能体，但不会以二进制数据的形式复现在 `ThreadMessage` 中。

## 增加跨平台 SDK 会话记录

当你的应用需要跨 Slack 和 Microsoft Teams 的以用户为中心的记录时，使用 SDK 会话记录。配置顶层的 `identifyUser` 与 `store.transcripts`。当身份解析为 `null` 时，会话记录桥会跳过个人读写。

<Callout type="info" title="先解析当前操作者">
  在把提供方 actor 当作应用用户使用之前，先阅读[身份与记忆](/channels/identity-and-memory)。共享的提供方对话没有个人属主，且每个事件都会独立解析自己的 actor。
</Callout>

<FrontendOnly frontend="slack">

```ts title="channel.ts"
import { createChannel } from "@copilotkit/channels";
import { durableStateStore } from "./state-store.js";

const channel = createChannel({
  name: required("CHANNEL_CODE"),
  identifyUser: async ({ provider, actor }) => {
    const account = await accounts.findByExternalIdentity({
      provider,
      externalUserId: actor.id,
    });
    return account ? { id: account.id, name: account.name } : null;
  },
  agent: makeAgent,
  store: {
    adapter: durableStateStore,
    transcripts: {
      retention: "30d",
      maxPerUser: 500,
    },
  },
});
```

</FrontendOnly>

提供方用户 id 不是跨平台身份。请把它们解析为稳定的应用用户 id、已验证邮箱，或你的应用控制的另一种身份。返回 `null` 会跳过该回合的会话记录存储。

如果该记录必须在重启后仍然存在，会话记录的列表 facet 必须是持久化的。默认的 `MemoryStore` 不够。

## 让 `runAgent` 只桥接一次会话记录

设置 `transcript: true` 即可注入既有的 SDK 会话记录条目、追加当前用户回合、运行智能体并捕获其回复：

```ts title="channel.ts"
channel.onMessage(async ({ thread, message }) => {
  await thread.runAgent({
    prompt: message.text,
    transcript: { limit: 20 },
  });
});
```

不要对同一组用户与助手回合再调用 `channel.transcripts.append()`。`runAgent({ transcript: ... })` 负责该桥接，手动追加会造成记录重复。

## 查询与删除应用记录

`channel.transcripts` 在 runner 启动 Channel 之后可用：

```ts title="transcripts.ts"
const recent = await channel.transcripts.list({
  userId: "usr_123",
  limit: 50,
});

const { deleted } = await channel.transcripts.delete({
  userId: "usr_123",
});
```

`list()` 按从旧到新的顺序返回条目。你可以按 platform、thread id 或 role 过滤。托管条目使用原生的 `"slack"` 或 `"teams"` 提供方。跨提供方身份请通过应用侧的 `userId` 解析；仅当你明确只想要某一个提供方的条目时才使用 platform 过滤。

`delete()` 会移除该用户名下由 SDK 持有的会话记录；提供方历史以及 Intelligence 另行的保留策略保持独立。

## 选对数据来源

| 需求                                                | 使用                                                                    |
| --------------------------------------------------- | ----------------------------------------------------------------------- |
| 继续当前的 Slack 或 Microsoft Teams 对话             | 托管对话历史                                                             |
| 查看某个提供方线程中的近期文本                       | `thread.getMessages()`                                                  |
| 在 Slack 与 Microsoft Teams 之间携带用户上下文       | 搭配稳定身份的 SDK 会话记录                                              |
| 存储工作流进度                                       | `thread.state()`                                                        |
| 满足应用的删除或保留要求                             | 持久化的 SDK 会话记录存储，外加你的提供方/Intelligence 策略               |

在生产环境启用这些能力之前，请参阅 [`Transcripts` 参考](/reference/channels/classes/Transcripts)与[持久化指南](/channels/persistence-and-scaling)。
