当智能体状态直接呈现在你的应用 UI 中时，[共享状态](/shared-state)的威力最为明显，比如仪表盘、文档画布、地图或表格。由于 `agent.state` 就是普通的 React 数据，你可以在组件树中的任意组件里订阅它，并按自己喜欢的方式渲染。

## 基本模式

`useAgent` 可以在 `<CopilotKit>` 下的任意组件中使用，不必靠近聊天组件。在你的主视图组件中调用它，读取 `agent.state` 并渲染即可：

```tsx title="components/Canvas.tsx"
import { useEffect } from "react";
import { useAgent } from "@copilotkit/react-core/v2";

type CanvasState = {
  title: string;
  items: { id: string; label: string; done: boolean }[];
};

const INITIAL_CANVAS_STATE: CanvasState = {
  title: "Project launch",
  items: [
    { id: "research", label: "Research user needs", done: true },
    { id: "prototype", label: "Build a prototype", done: false },
  ],
};

export function Canvas() {
  // No agentId means the "default" agent. Pass { agentId } to target another.
  const { agent, isReady } = useAgent();
  const state = (agent.state ?? {}) as Partial<CanvasState>;

  useEffect(() => {
    if (!isReady) return;

    const current = (agent.state ?? {}) as Partial<CanvasState>;
    const updates: Partial<CanvasState> = {};

    if (current.title === undefined) {
      updates.title = INITIAL_CANVAS_STATE.title;
    }
    if (current.items === undefined) {
      updates.items = INITIAL_CANVAS_STATE.items;
    }

    if (Object.keys(updates).length > 0) {
      agent.setState({ ...(agent.state ?? {}), ...updates });
    }
  }, [agent, isReady, state.title, state.items]);

  return (
    <main className="canvas">
      <h1>{state.title ?? "Untitled"}</h1>
      <ul>
        {(state.items ?? []).map((item) => (
          <li key={item.id} data-done={item.done}>
            {item.label}
          </li>
        ))}
      </ul>
    </main>
  );
}
```

本例中的 `INITIAL_CANVAS_STATE` 是由 UI 持有的初始状态，用于在智能体写入状态之前让画布可见。该 effect 只设置值为 `undefined` 的字段，并保留其他所有状态。如果初始状态由后端持有，请在对应框架的共享状态配置中定义它。

每当智能体修改其状态时——无论是通过工具调用、节点切换还是[流式更新](/shared-state/streaming)——`useAgent` 都会用新值重新渲染该组件。聊天可以放在侧边栏、弹窗中，甚至完全不出现；你的画布都会以同样的方式更新。

## 放在布局的任意位置

智能体依附于 `<CopilotKit>` 提供方，因此聊天界面和你的主视图组件只是同一个智能体的两个消费方。典型的布局会把画布作为主要内容渲染，把聊天作为停靠的侧边栏：

```tsx title="app/page.tsx"
import { CopilotKit, CopilotSidebar } from "@copilotkit/react-core/v2";
import { Canvas } from "../components/Canvas";

export default function Page() {
  return (
    <CopilotKit runtimeUrl="/api/copilotkit">
      <div className="app-shell">
        {/* Your app UI, driven by agent.state */}
        <Canvas />
        {/* Chat is just another consumer of the same agent */}
        <CopilotSidebar />
      </div>
    </CopilotKit>
  );
}
```

<Callout type="info">
`<Canvas>` 和 `<CopilotSidebar>` 都针对同一个 `agentId` 调用 `useAgent()`，因此它们共享同一个智能体实例和同一个状态对象。读取 `agent.state` 没有任何聊天专属之处，侧边栏也并不特殊。
</Callout>

## 从主视图写回

同一个 `agent` 还暴露了 `setState`，因此你的画布可以是可交互的，而不只是只读镜像。主视图中的点击处理函数可以推送新值，供智能体在下一轮读取：

```tsx
function toggleItem(id: string) {
  agent.setState({
    ...agent.state,
    items: (agent.state?.items ?? []).map((it) =>
      it.id === id ? { ...it, done: !it.done } : it,
    ),
  });
}
```

这就是 [共享状态](/shared-state) 中描述的同一条双向通道。唯一的区别在于，这里的读写发生在应用的主界面上，而不是聊天中。

## 实用技巧

- **定位特定智能体**：当你有多个智能体时，使用 `useAgent({ agentId: "research-agent" })`。默认是名为 `"default"` 的智能体。
- **节流高频更新**：如果流式运行导致较重的画布重新渲染得过于频繁，可使用 `useAgent({ throttleMs })`。
- **把 `agent.state` 视为可能不完整的状态**：运行进行期间，请像上面那样用默认值做防护，避免只流式传输了一半的状态导致渲染崩溃。
