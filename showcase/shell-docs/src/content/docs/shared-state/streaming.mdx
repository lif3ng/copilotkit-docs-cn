## 这是什么？

默认情况下，智能体状态只在后端检查点*之间*更新，因此一次长时间运行的工具调用（比如撰写完整文档、起草邮件）在 UI 看来就是最后一次性涌出的一大块。对智能体原生的应用来说，这种体验很糟糕：用户期望看着输出逐步成形。

**状态流式传输**会在*参数生成的过程中*，把特定工具参数的值直接转发到某个智能体状态键。通过 `useAgent` 订阅的 UI 会随每个 token 重新渲染。

## 什么时候应该使用它？

只要工具的输出是长篇文本或不断增长的结构化值，并且你希望用户实时看到它逐步组装起来，就可以使用状态流式传输。常见形态有：

- 输出文档的协作写作智能体
- 不断累积发现清单的研究智能体
- 逐步构建分步计划的规划智能体

没有流式传输时，用户只能盯着加载动画；有了流式传输，他们能看到答案逐 token 生长。

## 后端：一条流式状态映射

<FrameworkSetup concept="state-streaming-setup" />

后端模式始终相同：把一个流式工具参数映射到一个共享状态键。基于中间件的框架通常以声明式映射的形式暴露这一能力——例如 LangGraph Python 中带 `StateItem(...)` 条目的 `StateStreamingMiddleware`，或针对 LangGraph TypeScript 图使用带 `emitIntermediateState` 映射的 `copilotkitCustomizeConfig`。直接的 SDK 适配器则在各自的流式循环中完成同样的工作：解析不完整的工具参数，并在映射值变化时发出 `STATE_SNAPSHOT`。当 LLM 流式生成该参数时，CopilotKit 会在工具尚未执行完毕之前，把每个部分值写入共享状态。

<Snippet region="state-streaming-middleware" title="backend — 流式状态映射" />

有几点需要注意：

- 状态键必须已存在于你的智能体状态中（本演示中是 `document`）。
- 工具名和参数名必须与你要转发的那个面向 LLM 的工具调用完全一致（这里是 `write_document.document`）。
- 工具调用完成后，其最终返回值会写入同一个键，因此流式传输的部分值最终会变为权威的最终值。

## 前端：useAgent + OnStateChanged

UI 这边与任何其他共享状态订阅完全一致：`useAgent` 配合 `OnStateChanged` 即可得到响应式的 `agent.state`。如果你想要一个“实时”/“完成”指示器，再加上 `OnRunStatusChanged`。

<Snippet region="frontend-use-coagent-state" title="frontend/src/app/page.tsx — useAgent 订阅" />

从这里开始，`agent.state.document` 就是一个随每个 token 增长的字符串，`agent.isRunning` 则告诉你是否要显示流式指示器。
