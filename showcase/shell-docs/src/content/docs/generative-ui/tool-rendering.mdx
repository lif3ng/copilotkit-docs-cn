## 这是什么？

工具是 LLM 调用预定义（通常是确定性）函数的方式。工具渲染让你决定每个工具调用在聊天中的呈现方式。你不必展示原始 JSON，而是注册一个 React 组件，为调用绘制一张品牌化的卡片（参数、实时状态以及最终结果）。这就是 CopilotKit 称为**工具渲染**的**生成式 UI** 变体。

  **免费课程**：在 [Build Interactive Agents with Generative UI](https://www.deeplearning.ai/short-courses/build-interactive-agents-with-generative-ui/) 中查看此模式的端到端构建——这是由 CopilotKit CEO 讲授的 DeepLearning.AI 免费短课程，涵盖生成式 UI 的全部形态（受控式、声明式和开放式）。
</Callout>

## 什么时候应该使用？

当你想要以下效果时，就渲染工具调用：

- 让用户确切看到智能体正在调用哪些工具、传了哪些参数
- 在工具执行期间展示实时进度指示器
- 工具完成后渲染丰富、精致的结果
- 为重度依赖工具的智能体提供透明且符合品牌的聊天体验

## 默认工具渲染（零配置）

最简单的入口：不带参数调用 `useDefaultRenderTool()`。CopilotKit 会把内置的 `DefaultToolCallRenderer` 注册为 `*` 通配渲染器：每个工具调用都渲染成一张整洁的状态卡片（工具名、实时的 **Running → Done**（运行中 → 完成）徽标、可折叠的参数/结果），而你无需编写任何 UI。智能体连续发起的调用会归组到一张卡片中；参见[工具调用分组](#工具调用分组)。

没有这个钩子，运行时就没有 `*` 渲染器，工具调用便不可见；用户只能看到助手最终的文字总结。

## 工具调用分组

智能体常常连续调用多个工具。默认情况下，CopilotKit 会把由 `useDefaultRenderTool()` 内置卡片绘制的每一轮连续调用折叠成一张卡片，上面写着“Used 3 tools”（使用了 3 个工具）。当某个调用正在运行时，卡片会点名它（“Running read_file src/app.ts”），展开后每个调用各占一行。由你自己的渲染器绘制的调用始终独立显示，并会在它们周围把组切开，除非渲染器通过 `group: true` 主动加入分组：

```tsx title="page.tsx"
useDefaultRenderTool({ render: MyToolRow, group: true });
```

用消息视图上的 `toolCallDisplay` 选择调用的展示方式：

```tsx title="page.tsx"
// "grouped" (default) | "line" | "stacked" | "turn" | "separate"
<CopilotChat messageView={{ toolCallDisplay: "line" }} />
```

| 展示方式 | 用户看到的内容 |
| ------------ | ----------------------------------------------------------------------------------------- |
| `"grouped"` | 每轮连续调用一张卡片，折叠为“Used 3 tools”。展开后每个调用一行。 |
| `"line"` | 同样的分组，但只是一行安静的文字，例如“Thought for 4 seconds”。 |
| `"stacked"` | 最新调用叠在早前调用之上。展开后每个调用一张卡片。 |
| `"turn"` | 智能体公开工作，回复之前的所有内容折叠为“Worked for 9s”。 |
| `"separate"` | 每个调用一张独立卡片。 |

要并排比较各种展示方式，可在 React Storybook 中运行 [Tool call display stories](https://github.com/CopilotKit/CopilotKit/blob/main/examples/v2/react/storybook/stories/ToolCallDisplay.stories.tsx)。它们会通过真实的消息视图播放一段脚本化的运行过程，并提供一个切换 `toolCallDisplay` 的控件。

要重新设计组的样式或替换它，请使用工具调用视图的 `group` 插槽（适用于 grouped、line 和 stacked 三种展示方式）：

```tsx title="page.tsx"
// ToolTimeline: your component, given the group's `calls` and a `renderCall` function
<CopilotChat
  messageView={{
    assistantMessage: { toolCallsView: { group: ToolTimeline } },
  }}
/>
```

其 props 与替换示例参见 [`CopilotChatToolCallGroup`](/reference/components/CopilotChatToolCallGroup)。

## 按工具渲染器

最富表现力的方式是为每个工具名配一个渲染器。主 `tool-rendering` 演示单元格接了两个：`get_weather` 绘制品牌化的 `WeatherCard`，`search_flights` 绘制 `FlightListCard`。每个渲染器都会收到工具解析后的参数、实时的 `status`，以及（智能体返回后的）`result`：

### 工具输入与结果是分开的

在 `useRenderTool` 中，`parameters` 包含的是智能体发给工具的**输入**。当 `status` 变为 `"complete"` 时，它并不会变成工具的返回值。完成后的输出会单独作为 `result`（一个字符串）到达。对于返回 JSON 的工具，请先解析该字符串再读取其字段。

例如，`get_weather` 可能收到 `{ "location": "Paris" }` 并返回 `{ "temperature": 22 }`。用 `parameters.location` 读取请求的城市，用解析后的 `result.temperature` 读取温度。把 `temperature` 加进渲染器的 `parameters` schema 并不会把它从结果中复制过来。

如果卡片显示 **complete** 却仍在展示占位内容，请检查这些内容是否来自 `parameters` 而非解析后的 `result`。完成只表示工具已返回；它不会替你填充卡片的 props。
