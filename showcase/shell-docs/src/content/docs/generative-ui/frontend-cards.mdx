## 这是什么？

有时想在聊天中展示内容的是你的应用，而不是智能体。后台任务完成、WebSocket 推来一条告警，或者用户点击了一个按钮。你希望在会话记录里出现一张卡片，却没有可以挂靠的智能体回合，也不想往对话里塞一条假消息。

活动消息（activity message）解决了这个问题。活动消息是 `role: "activity"` 的消息。它像其他消息一样渲染在会话记录中，但每次运行发送给智能体的负载里都会被剔除。智能体和模型永远看不到它。

## 何时使用？

在以下情况下使用前端驱动的卡片：

- 卡片的来源是前端事件，而不是智能体。
- 卡片不能成为模型读取的对话的一部分。
- 仅限当前会话是可以接受的。卡片不会随线程持久化。

如果卡片由智能体决定展示，或者卡片必须在页面刷新后仍然存在，请改用[基于工具的生成式 UI](/generative-ui/tool-based)。

## 代码中的工作方式

### 1. 编写渲染器

渲染器把一个 `activityType` 与一个组件以及卡片内容的 schema 配成一对。

```tsx title="app/event-card.tsx"
import { z } from "zod";
import type { ReactActivityMessageRenderer } from "@copilotkit/react-core/v2";

const contentSchema = z.object({
  title: z.string(),
  detail: z.string().optional(),
});

export const eventCardRenderer: ReactActivityMessageRenderer<
  z.infer<typeof contentSchema>
> = {
  activityType: "app-event-card", // [!code highlight]
  content: contentSchema,
  render: ({ content }) => (
    <div className="rounded-lg border p-4">
      <strong>{content.title}</strong>
      {content.detail ? <p>{content.detail}</p> : null}
    </div>
  ),
};
```

### 2. 在 provider 上注册

```tsx title="app/page.tsx"
import { CopilotKit, CopilotChat } from "@copilotkit/react-core/v2";
import { eventCardRenderer } from "./event-card";

export default function Page() {
  return (
    <CopilotKit
      runtimeUrl="/api/copilotkit"
      renderActivityMessages={[eventCardRenderer]} // [!code highlight]
    >
      <CopilotChat />
    </CopilotKit>
  );
}
```

### 3. 从前端代码添加卡片

用 `useAgent()` 获取当前生效的 agent 实例，然后以 `role: "activity"` 调用 `addMessage`。

```tsx title="app/deployment-watcher.tsx"
import { useEffect } from "react";
import { useAgent } from "@copilotkit/react-core/v2";

export function DeploymentWatcher() {
  const { agent } = useAgent();

  useEffect(() => {
    const socket = new WebSocket("wss://example.com/deployments");
    socket.onmessage = (event) => {
      const deployment = JSON.parse(event.data);
      agent.addMessage({
        id: crypto.randomUUID(),
        role: "activity", // [!code highlight]
        activityType: "app-event-card",
        content: { title: "Deployment finished", detail: deployment.sha },
      });
    };
    return () => socket.close();
  }, [agent]);

  return null;
}
```

<Callout type="warn">
  请使用 `useAgent()` 返回的 agent。你自己构造并持有的 agent 实例并不是聊天渲染的那个实例，因此添加到它上面的消息永远不会出现。
</Callout>

同样的做法也适用于 `agent.subscribe` 处理器、按钮的 `onClick`，或其他任何能访问到 agent 的前端代码。

## 智能体收到什么

活动消息会保留在 `agent.messages` 中，因此会话记录可以渲染它们；而 `prepareRunAgentInput` 会在运行负载离开浏览器之前移除它们。

假设会话记录中有一条用户消息和一张卡片：

| 位置 | 存在的角色 |
| --- | --- |
| `agent.messages`（聊天渲染的内容） | `user`、`activity` |
| 运行负载（你的智能体收到的内容） | `user` |

来自后端的 `MESSAGES_SNAPSHOT` 也不会移除你的卡片。快照合并会保留活动消息，因此在浏览器中添加的卡片能在服务端历史回放后依然存在。

## 局限性

- **不会持久化**。卡片永远不会到达后端，因此页面刷新后就会消失。如果你需要卡片在刷新后恢复，可以改为由智能体以活动事件的形式发出。
- **每种活动类型一个渲染器**。注册一个 `activityType` 相匹配的渲染器，或使用 `"*"` 作为通配符。没有匹配渲染器的活动消息将不会渲染任何内容。
