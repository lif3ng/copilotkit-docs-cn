你已经有一个对话界面，想让智能体根据类型化的 JSON 规格绘制仪表盘。学完本指南后，智能体将输出一个 `{ root, elements }` 对象，而 [`@json-render/react`](https://www.npmjs.com/package/@json-render/react) 会通过你的 React 组件注册表将其渲染出来。

## 适用场景

- **需要带类型化契约的结构化 UI**，渲染器只接受已知的组件类型。
- **能容忍智能体输出中的说明性前言 + 代码围栏**（演示中的解析器会处理它们）。
- **你已在其他地方使用 json-render**，或更偏好用 Zod 描述的目录。

如果你想要流式的渐进渲染而非一次性的 JSON 渲染，请参阅姊妹页面 [Hashbrown](/generative-ui/hashbrown)，其中用 `@hashbrownai/react` 实现了相同场景。

## 前端

集成点是 `<CopilotChat>` 的 `messageView.assistantMessage` 插槽。演示的 **Code** 标签页包含完整的框架相关文件，本页的 Markdown 版本也收录了关键的前端源码文件。这些演示使用 `@json-render/react` 和 `@json-render/core` 的 `0.18.0` 版本，并配合 Zod 4 定义目录。若要了解更高版本的变更，请查看仓库中所选演示的 `package.json`。同时使用 Zod 3 的演示会通过 `zod4` 包别名导入 Zod 4。`page.tsx` 提供 `<CopilotKit>`，`chat.tsx` 将 `JsonRenderAssistantMessage` 安装到聊天插槽中，`json-render-renderer.tsx` 则负责解析助手消息内容。Code 标签页还展示了所选框架对应的运行时路由。

渲染器从 `registry.tsx` 导入 `registry`，把 `<Renderer spec={spec} registry={registry} />` 包在 `<JSONUIProvider registry={registry}>` 中，并在尚无法解析出规格时回退为普通助手消息。`catalog.ts` 用 `defineCatalog` 定义组件名和 Zod 属性 schema；`registry.tsx` 用 `defineRegistry(catalog, …)` 把这些名字绑定到 React 组件。请将这两个文件与渲染器一并复制。演示中的 `parseSpec` 会为组件类型设置白名单并检查基本的对象结构，但**不会**在运行时依据 Zod schema 校验输出的 props。如果你依赖这一层保证，请在渲染前自行校验 props。

## 后端

智能体输出一个 `{ root, elements }` JSON 对象作为助手消息内容。`root` 引用一个顶层元素的 id；`elements` 把每个 id 映射到与目录匹配的 `{ type, props, children }` 三元组。

```json title="智能体输出示例"
{
  "root": "revenue-card",
  "elements": {
    "revenue-card": {
      "type": "MetricCard",
      "props": { "label": "Total revenue", "value": "$184,302", "trend": "+12%" },
      "children": ["by-region"]
    },
    "by-region": {
      "type": "BarChart",
      "props": {
        "title": "Revenue by region",
        "description": null,
        "data": [
          { "label": "North America", "value": 112000 },
          { "label": "EMEA", "value": 72302 }
        ]
      }
    }
  }
}
```

示例使用一个 `MetricCard` 作为根元素，以及它注册在案的 `BarChart` 子元素。渲染器能容忍 JSON 前后的说明性前言或代码围栏，但智能体提示词要求输出纯 JSON。

## 两种模式对比

`byoc-json-render` 和 [`byoc-hashbrown`](/generative-ui/hashbrown) 用两个不同的渲染库解决同一个问题。智能体契约是相似的；差异在于 React 胶水代码、校验策略和渲染行为。
