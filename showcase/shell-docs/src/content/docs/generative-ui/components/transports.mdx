## 这是什么？

智能体必须以某种方式把 UI 发送到浏览器。有些智能体擅长工具调用，有些只会流式输出文本，还有些由你自己构建提示。**传输层**（transport）就是 UI 传递的途径：

- **工具**（默认）：智能体调用 `render_ui` 工具。
- **Markdown**：智能体在回复中用 `a2ui` 代码块书写 UI。

两种传输层使用相同的目录、界面载体和组件。改变的只是智能体与浏览器之间的通路。

## 如何选择

| | 工具 | Markdown |
| --- | --- | --- |
| 智能体如何书写 UI | 以 `render_ui` 工具调用的形式 | 在回复的 `a2ui` 代码块中 |
| 浏览器收到前是否校验 | 是，由运行时校验，浏览器中再次校验 | 在浏览器中校验 |
| UI 周围的文本 | 单独的消息 | 同一条回复中，UI 的前后 |
| 适用对象 | 会使用本次运行的工具与上下文的智能体 | 任何能流式输出文本的智能体 |

优先使用工具传输。如果你的智能体无法调用客户端工具，或者你希望 UI 出现在回复文本之中，请使用 Markdown。

## 工具传输

这是默认方式，因此 provider 只需要目录：

```tsx
<CopilotKitProvider runtimeUrl="/api/copilotkit" generativeUI={{ ui: standardUI }}>
```

当运行携带目录时，运行时会添加 `render_ui` 工具以及一段简短的调用指南。运行时会在流式传输过程中检查每个操作，浏览器则立即渲染其中有效的操作。

运行时选项 `generativeUI` 控制何时添加该工具：

- 省略：对每个携带工具传输目录的运行生效。
- `true`：对所有运行生效。
- `{ agents: ["shop"] }`：对这些智能体的所有运行生效。
- `false`：从不生效。

```ts title="app/api/copilotkit/route.ts"
const runtime = new CopilotRuntime({
  agents: { default: agent },
  generativeUI: true,
});
```

你的智能体必须使用本次运行的工具和上下文条目。内置智能体已经做到了这一点。对于 LangGraph Python 智能体，请添加 `CopilotKitMiddleware`。

## Markdown 传输

设置 `transport: "markdown"`：

```tsx
<CopilotKitProvider runtimeUrl="/api/copilotkit" generativeUI={{ ui: standardUI, transport: "markdown" }}>
```

provider 会把组件 schema 和一份写作指南作为上下文发送，智能体随后在回复中书写 UI。关于智能体写什么、如何流式输出以及如何构建自己的提示，请参阅 [Markdown 模式](/generative-ui/components/markdown-mode)。

## 仅部分智能体

默认情况下，每个智能体都能使用生成式 UI。若只想开放给其中一部分，请列出它们的 id：

```tsx
<CopilotKitProvider
  runtimeUrl="/api/copilotkit"
  generativeUI={{ ui: standardUI, agentIds: ["shop"] }}
>
```

其他智能体不会得到目录、指南，也没有 `render_ui` 工具。

## Token 开销

每次运行都会携带目录和一份指南。指南只包含你的目录所需规则，因此目录越小，指南越短。完整标准目录是其中最大的部分。要控制运行体积，请用 [`omit`](/generative-ui/components/standard-catalog#drop-components) 移除不需要的组件。

现在，你的智能体将以适合它的传输方式，获得所需的 UI 工具。
