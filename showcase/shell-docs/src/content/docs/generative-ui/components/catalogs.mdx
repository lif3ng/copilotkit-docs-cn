## 这是什么？

智能体无法渲染它不知道的组件。它还需要知道每个组件的 props，否则只能靠
猜，而猜出来的价格或错误的 prop 会把页面搞坏。

**组件目录**列出了智能体可以使用的组件。对每个组件，它保存 React 组件
本身、一段描述，以及 props 的 schema。智能体拿到描述和 schema，你的应用
拿到类型化的 props。

## 创建组件目录

用 `createGenerativeUI` 在模块级别声明一次组件目录：

```tsx title="app/catalog.tsx"
import { z } from "zod";
import {
  createGenerativeUI,
  type GenerativeUIComponentProps,
} from "@copilotkit/react-core/v2/generative-ui";

function ProductGrid({ title, children }: GenerativeUIComponentProps<typeof shopUI, "ProductGrid">) {
  return (
    <section>
      {title ? <h3>{title}</h3> : null}
      <div className="grid grid-cols-2 gap-4">{children}</div>
    </section>
  );
}

function ProductCard({ name, price, imageUrl }: GenerativeUIComponentProps<typeof shopUI, "ProductCard">) {
  return (
    <article>
      <img src={imageUrl} alt={name} />
      <h4>{name}</h4>
      <p>${price}</p>
    </article>
  );
}

export const shopUI = createGenerativeUI({
  id: "acme/shop@1",
  components: {
    ProductGrid: {
      component: ProductGrid,
      description: "A grid of products. Put the ids of ProductCard components in children.",
      props: z.object({ title: z.string().optional() }),
      slots: { children: "multiple" },
    },
    ProductCard: {
      component: ProductCard,
      description: "One product. Copy every value from a product of a tool result.",
      props: z.object({ name: z.string(), price: z.number(), imageUrl: z.string() }),
    },
  },
});
```

然后把它交给 provider：

```tsx
<CopilotKitProvider runtimeUrl="/api/copilotkit" generativeUI={{ ui: shopUI }}>
```

`id` 为组件目录命名。请使用带版本的 id，例如 `acme/shop@1`。

## 组件可以声明什么

- `component`：负责渲染的 React 组件。
- `description`：这个组件是什么、什么时候用。智能体会读它，所以请写具体。
- `props`：智能体设置的 props 的 schema。
- `slots`：承载子组件的 props。`"single"` 接收一个子组件，`"multiple"`
  接收一个列表。
- props schema 内的子组件引用：用来自
  `@copilotkit/react-core/v2/generative-ui` 的 `child()` 或 `childList()`
  标记某个 prop，位置可以在 schema 中的任何地方，例如
  `tabs: z.array(z.object({ title: z.string(), child: child() }))`。引擎会
  渲染被引用的组件，你的组件收到的将是 React 节点而非 id。A2UI 1.0 就是
  这样标记引用的（`ComponentId`、`ChildList`）；`slots` 保留给简单的顶层
  场景。
- `events`、`bind` 和 `writable`：操作、应用状态与输入。参见
  [连接应用状态与操作](/generative-ui/components/state-and-actions)。

除 `id` 和 `component` 之外，智能体写出的每个组件都可以携带 A2UI 1.0
信封：`catalogId`（必须是你 UI 的 id）、`metadata`
（`{ "extensions": { ... } }`，保留给你自己的工具链）以及 `accessibility`
（`label`、`description`、`live`、`hidden`；其中 `label`、`description` 和
`hidden` 可以是绑定或函数值）。引擎会解析 `accessibility`，并且这三者都
不会进入你的 props。`hidden` 和 `live` 适用于每个组件：引擎会把组件包进
一个带 `aria-hidden` 和 `aria-live` 的元素。`label` 或 `description` 需要
一个带 role 的元素，因此标准组件会把它们设置在自己的根元素或控件上。在
你自己的组件中，调用 `useGenerativeUIAccessibility()` 并把结果展开到根
元素上。不能被包装的组件（表格行或单元格）声明 `accessibility: "self"`
并自行应用这些属性。

## 为组件标注类型

`GenerativeUIComponentProps<typeof ui, "Name">` 让组件精确获得渲染器传入
的 props。类型读取自 schema，因此组件与组件目录不会渐行渐远：

```tsx
function ProductCard(props: GenerativeUIComponentProps<typeof shopUI, "ProductCard">) {
  props.price; // number
  props.color; // type error: not a prop of ProductCard
}
```

## 选择 schema 库

`props` 接受任何对象的
[Standard Schema](https://standardschema.dev)。智能体拿到的 props 是
JSON Schema 形式，因此 schema 必须能够给出一份：

<Tabs items={["zod", "Valibot"]}>
  <Tab value="zod">
    ```ts
    import { z } from "zod";

    props: z.object({ name: z.string(), price: z.number() }),
    ```
  </Tab>
  <Tab value="Valibot">
    ```ts
    import * as v from "valibot";
    import { toStandardJsonSchema } from "@valibot/to-json-schema";

    props: toStandardJsonSchema(v.object({ name: v.string(), price: v.number() })),
    ```
  </Tab>
</Tabs>

可用的有：zod 3、zod 4.2 及以上、ArkType，以及配合
`@valibot/to-json-schema` 使用的 Valibot。schema 必须支持同步校验，因为
props 是在界面渲染时检查的。

## 组合多个组件目录

`extends` 把其他组件目录合并进你的目录。结果的类型涵盖每个组件：

```ts
import { createGenerativeUI, standardUI } from "@copilotkit/react-core/v2/generative-ui";

export const appUI = createGenerativeUI({
  id: "acme/app@1",
  extends: [standardUI, cartUI],
  components: { Hero: { component: Hero, props: z.object({ title: z.string() }) } },
});
```

一个名称只能来自一个组件目录。两个名为 `Card` 的组件会在应用加载时抛错。
要替换标准组件，请使用
[overrides](/generative-ui/components/standard-catalog#replace-a-component)。

## 为其他 A2UI 工具导出组件目录

`exportA2UICatalog(ui)` 把你的 UI 写成 A2UI 1.0 组件目录定义（即
`catalog_definition.json` 的形态），供校验器、其他渲染器或提示词构建器
使用：

```ts
import { exportA2UICatalog } from "@copilotkit/react-core/v2/generative-ui";

const catalog = exportA2UICatalog(appUI, { title: "Acme app" });
fs.writeFileSync("acme-catalog.json", JSON.stringify(catalog, null, 2));
```

每个组件都是一个条目：`component` 作为 `const`，附带模型可设置的 props、
以 `Action` 引用表示的事件，以及以 `ComponentId` 或 `ChildList` 引用表示
的插槽。prop 可以取它的字面量 schema、`DataBinding` 或 `FunctionCall`，
因为渲染器会解析任何 prop 中的动态值。每个函数——无论内置还是自定义
声明——都要声明 `returnType` 和 `allowedCallers`；`calc` 和 `series` 与
其他函数一样列出，这样缺少它们的消费方就知道哪些是自己无法运行的。

## 位置参数顺序

A2UI Express 按组件目录 JSON Schema 中属性的顺序映射位置参数。其
[schema 驱动的键映射规范](https://a2ui.org/specification/proposals/express/a2ui_express/#schema-driven-key-mapping)
定义了该行为。哪些参数排在前面，由组件目录作者决定。

声明 `parameterOrder`，就能让组件的主要内容、子组件或操作排在最前，横跨
`props`、`slots` 和 `events`：

```tsx
const ui = createGenerativeUI({
  id: "acme/panel@1",
  components: {
    Panel: {
      component: Panel,
      props: z.object({ title: z.string(), color: z.string().optional() }),
      slots: { children: "multiple" },
      parameterOrder: ["title", "children"],
    },
  },
});
```

`exportA2UICatalog(ui)` 按 `component`、`title`、`children`、`color` 的
顺序输出 `Panel.properties`。Express 会忽略结构性的 `component` 判别
字段，因此第一个位置参数就是 title。`parameterOrder` 是 CopilotKit 的
编写/清单元数据，**不是 A2UI JSON Schema 的关键字**：可移植的导出会把它
落实到实际的 JSON 属性顺序上。

名称必须是唯一的、已声明的 prop、插槽或事件。声明了顺序的组件不能使用
规范的整数索引名（`"0"` 到 `"4294967294"`）：JavaScript 会把这些键按数值
排序并放在其他键之前，与请求的顺序无关。未列出的名称按其既有声明顺序排在
后面：先是 props，然后是插槽，最后是事件。绑定的 prop 和被匹配的事件不会
出现在面向模型的签名中。没有 `parameterOrder` 的组件目录保持其既有导出
顺序。`extends`、`omit` 和 React 组件 `overrides` 都会保留已声明的约定。

把位置顺序当作 API 契约对待。改动它可能改变现有 Express 程序的含义；
命名参数则保持含义不变。让短前缀保持稳定，可选的样式参数用命名参数传递。
为 Express 序列化或转换组件目录时，保持属性顺序不变。

## 智能体看到什么

智能体拿到每个组件时，会同时拿到它的描述和它可以设置的 props。它看不到：

- 来自应用状态的 props（`bind`）。
- 由你自己的代码处理的事件。

要查看这份清单，请打开 Inspector 中生成式 UI 面板的 **Catalog** 标签页。
它按声明组件的目录分组，方便你看到 `extends` 加进了什么。
