## 这是什么？

你希望智能体今天就能用表格、图表和表单来回答，而不是等你先建好一套组件
库。`standardUI` 是一个包含 69 个现成组件的目录，智能体已经知道怎么用
它们。A2UI 1.0 基础目录的 18 个组件都在其中，沿用 A2UI 的名称和 props
（`Image.url`、`CheckBox.value`、`Row.justify: "spaceBetween"`、
`weight` 对应 flex-grow）；其余组件则是对该目录的扩展。

直接照原样使用：

```tsx
import { standardUI } from "@copilotkit/react-core/v2/generative-ui";

<CopilotKitProvider runtimeUrl="/api/copilotkit" generativeUI={{ ui: standardUI }}>
```

几点需要知道：

- **所有输入都可校验**。`checks` 保存 A2UI 1.0 的 `Checkable` 规则：
  `[{ "condition": { "@call": "email", "args": { "value": { "@path": "/form/email" } } }, "message": "Enter a valid email" }]`。
  用户一旦碰过某个输入框，它就会显示第一条未通过的校验消息；带相同
  checks 的 `Button` 在有规则未通过时保持禁用。校验结果携带 A2UI 的
  `ValidationResult` 字段：内置校验器会设置 `code`（`required`、
  `pattern`、`tooShort`、`tooLong`、`notANumber`、`tooSmall`、`tooLarge`、
  `email`）；`severity` 为 `"warning"` 或 `"info"`（来自绑定结果或你自己的
  校验器）时，消息以其对应的颜色显示，但不会把输入标记为无效，也不会
  卡住 `Button`。
- **`Video` 接受任何 URL**。视频文件用原生播放器播放，`captions` 作为
  WebVTT 轨道加载；YouTube 链接在用户按下播放前显示封面图，之后加载
  增强隐私的嵌入播放器。其他视频网站（Vimeo、Loom、TikTok 等）的页面和
  加载失败的文件会显示为链接卡片，而不是一个播不了的播放器。YouTube 是
  唯一支持内嵌的平台；要内嵌其他平台，请[替换该组件](#替换组件)。
  `Tabs` 接受 `tabs: [{ "title", "child" }]`，并带每个面板的 id。
- **输入框保留用户输入**。智能体把输入框绑定到某个值后，用户键入的内容
  会保留下来，后续的智能体更新覆盖不了它。
- **`Button` 和 `Pressable` 可以在浏览器里直接行动**。`href` 打开一个
  URL，带 `copy` 的 `Button` 复制文本，都不会给智能体发消息。
- **`Map` 需要一个包**。如果你的智能体会画地图，请运行
  `npm install maplibre-gl`。没有它，地图会以列表形式展示这些地点。
- **`Chart` 开箱即用**。它使用 `recharts`，CopilotKit 已自带。

每个独立组件都有专属页面，包含现有的实时示例、可复制的界面操作和 API
参考。结构性部件记录在其父组件的页面上。预览使用本地示例数据，不需要
连接模型。

## Express 调用约定

标准组件目录在导出时，会把内容、子组件、标签/取值和常见操作排在展示
参数之前。例如，短前缀是 `Text(text?, children?)`、`Column(children?)`、
`Button(label?, onClick?)`、`TextField(label?, value?)` 和
`Chart(data?, xKey?, series?, chartType?)`。其他组件特有字段跟在后面，
然后是共享的布局与排版字段。可选样式用命名参数传最省事。

这是 CopilotKit 的组件目录设计，不是 A2UI 规定的签名清单。官方 Express
规范定义了 JSON 属性顺序如何变成参数顺序。标准组件目录通过
[`exportA2UICatalog`](/generative-ui/components/catalogs#positional-parameter-order)
应用这条规则，因此消费导出目录的智能体无论用什么框架，拿到的调用约定
都一样。

与最初实验性的样式优先目录相比，这改变了位置参数的含义。迁移到该目录时
请开启全新会话，并按其签名重新生成已保存的位置式 Express 源码。命名参数
和 JSON 属性值的含义保持不变。

## 添加你自己的组件

用 `extends` 把你的组件叠在标准组件之上：

```ts
import { createGenerativeUI, standardUI } from "@copilotkit/react-core/v2/generative-ui";

export const appUI = createGenerativeUI({
  id: "acme/app@1",
  extends: [standardUI],
  components: {
    ProductCard: { component: ProductCard, props: productSchema },
  },
});
```

如何声明组件，参见[组件目录](/generative-ui/components/catalogs)。

## 去掉组件

每个组件都会让提示词变长一点。如果你的应用永远用不到地图或视频，就把
它们去掉。`omit` 返回一份不含它们的目录副本，智能体从此看不到它们：

```ts
export const appUI = createGenerativeUI({
  id: "acme/app@1",
  extends: [standardUI.omit(["Map", "Video", "HtmlView"])],
  components: {},
});
```

名称是带类型的，拼错就是类型错误。`omit` 只调用一次，放在模块级别。

## 替换组件

你的应用有自己的卡片样式，带自己的阴影和间距。`overrides` 会替换标准
组件的 React 组件。智能体看到的组件与之前一样，props 也一样：

```tsx
import {
  createGenerativeUI,
  standardUI,
  type GenerativeUIComponentProps,
} from "@copilotkit/react-core/v2/generative-ui";

function MyCard({ children }: GenerativeUIComponentProps<typeof standardUI, "Card">) {
  return <div className="rounded-2xl border p-6 shadow-sm">{children}</div>;
}

export const appUI = createGenerativeUI({
  id: "acme/app@1",
  extends: [standardUI],
  overrides: { Card: { component: MyCard } },
  components: {},
});
```

- 你的组件会拿到被替换组件的 props。类型系统会检查这一点。
- 只有 `extends` 中各目录的组件才能被覆盖。未知的名称是类型错误。
- 两者可以组合使用：`extends: [standardUI.omit(["Map"])]` 搭配
  `overrides: { Card: ... }`。
