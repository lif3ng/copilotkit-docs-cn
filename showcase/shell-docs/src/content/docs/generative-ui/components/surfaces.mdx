## 这是什么？

聊天是放置答案的好地方，却不是放置商店商品网格的好地方。当用户询问“给我看看便宜的跑鞋”时，鞋子应该出现在页面的商品行里，而不是聊天气泡中。

一个**界面载体**（surface）就是一段生成的 UI。每个界面载体都渲染在一个**目标**（target）中，也就是生成式 UI 可以出现的位置：

- **聊天**。始终存在。智能体可以使用目录中的每一个组件。
- **页面目标**。页面上用 `GenerativeUISurface` 标记的一个区域。只有当它出现在屏幕上时，智能体才能看到它。

## 添加页面目标

用 `GenerativeUISurface` 包裹页面的某个区域，为它指定一个 id，并告诉智能体这个区域的用途：

```tsx title="app/page.tsx"
import { GenerativeUISurface } from "@copilotkit/react-core/v2/generative-ui";
import { shopUI } from "./catalog";

export function FeaturedProducts({ products }: { products: Product[] }) {
  return (
    <GenerativeUISurface
      id="featured"
      ui={shopUI}
      description="The Featured Products row of the home page. When the customer asks to see products here, show them as a ProductGrid with one ProductCard for each product. When they ask for the featured products again, delete this surface."
      components={["ProductGrid", "ProductCard"]}
      fallback={<ProductRow products={products} />}
    />
  );
}
```

各个 prop 的作用：

- `id`：目标的 id。智能体在这里渲染时会按名称指代它。
- `description`：这个区域是什么、里面适合放什么。智能体每次运行都会读取它，所以要像写指令一样来写。
- `fallback`：在智能体在此渲染之前显示；当智能体删除其界面载体后，会再次显示。
- `ui` 和 `components`：智能体在这里能使用的组件，仅限于此。参见[限制可用组件](#限制可用组件)。

现在，“给我看看便宜的跑鞋”会替换这一行，而“再看看精选商品”则会把你自己的商品行换回来。

## 限制可用组件

商品行只能放商品卡片，不能放轮播图或图表。`components` 列出了智能体在此目标中能使用的组件（包括根组件）：

```tsx
<GenerativeUISurface id="featured" ui={shopUI} components={["ProductGrid", "ProductCard"]} />
```

- 智能体会拿到这份列表，因此知道什么适合放进去。
- 使用其他组件的操作会被拒绝，并且智能体会收到拒绝原因。
- `ui` 为这些名称提供了类型，因此拼写错误会变成类型错误。请传入与 provider 中相同的目录。

省略 `components`（和 `ui`）即可允许使用目录中的所有组件。

## 滚动到界面载体

当智能体开始向某个目标渲染时，页面会滚动到该目标——除非它已经在屏幕上。为单个目标关闭此行为：

```tsx
<GenerativeUISurface id="sidebar-notes" autoScroll={false} />
```

如果页面有粘性页眉，请在 CSS 中为界面载体在顶部留出一些空间：

```css
[data-generative-ui-surface] {
  scroll-margin-top: 6rem;
}
```

## 每个条目一个目标

目标也可以更具体。商品页面可以为每个商品提供自己的目标，这样当用户在商品之间切换时，推荐内容也会随之切换：

```tsx
<GenerativeUISurface
  key={product.id}
  id={`recommendations-${product.id}`}
  description={`The "You might also like" row under ${product.name}. Show related products here. Never include ${product.name} itself.`}
/>
```

## 组件渲染失败时

每个组件都在自己的错误边界（error boundary）内渲染。某个组件出错时只会显示一个小型 fallback，界面载体的其余部分仍能正常工作。要上报错误，或绘制自定义 fallback：

```tsx
<CopilotKitProvider
  runtimeUrl="/api/copilotkit"
  generativeUI={{
    ui: shopUI,
    errorBoundary: {
      onError: (info) => console.warn(info.kind, info.surfaceId, info.error.message),
      fallback: ({ retry }) => <button onClick={retry}>Try again</button>,
    },
  }}
>
```

## 智能体了解的界面载体信息

每次运行时，智能体都会获得：

- 屏幕上的各个目标，包括它们的描述和组件限制。
- 已存在的界面载体，因此它可以就地更新某个载体，而不是新建一个。
- 用户在界面载体中输入的值。智能体不能覆盖这些值。
- 被浏览器拒绝的操作及其原因，以便智能体进行修正。

要查看同样的数据，请在 Inspector 中打开 Generative UI 面板的 **Surfaces** 标签页。如果某个界面载体始终为空，请参阅[内容未渲染时](/generative-ui/components#when-something-does-not-render)。
