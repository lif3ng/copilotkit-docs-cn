## 这是什么？

文本回答往往不是对的答案。“对比这三个套餐”想要的是一张表格。“给我看看
便宜的跑鞋”想要的是商品卡片，而且也许该出现在页面的商品栏里，而不是
聊天里。

借助组件与界面，智能体在回答的同时渲染真正的 React 组件：

- **在聊天中**：出现在它的回复里。
- **在页面各区域**：聊天之外。对聊天提问就能改变页面。

智能体能渲染什么由你决定。展示什么、填入什么值由智能体决定。用户可以在
UI 里输入、点它的按钮，并就它追问。

## 试试看

以下步骤为 Next.js 应用添加生成式 UI，通过 TanStack AI 使用 OpenAI 模型。

已经在跑 CopilotKit 了？只需做第 3 步。你的运行时无需改动：provider 传入
组件目录时，运行时会给该次运行一个 `render_ui` 工具和一份简短指南。你的
智能体必须把该次运行的工具和 context 传给它的模型，做法见第 2 步。
LangGraph Python 智能体则要加上 `CopilotKitMiddleware`。

<Steps>
  <Step>
  ### 安装依赖包

  ```bash
  npm install @copilotkit/react-core @copilotkit/runtime @tanstack/ai @tanstack/ai-openai
  ```

  把你的 OpenAI 密钥放进 `.env.local`：

  ```bash title=".env.local"
  OPENAI_API_KEY=sk-...
  ```
  </Step>
  <Step>
  ### 添加运行时和智能体

  该智能体是工厂模式的内置智能体：模型由你自己通过
  [TanStack AI](https://tanstack.com/ai) 调用。

  ```ts title="app/api/copilotkit/[[...slug]]/route.ts"
  import { chat } from "@tanstack/ai";
  import { openaiText } from "@tanstack/ai-openai";
  import {
    BuiltInAgent,
    convertInputToTanStackAI,
    CopilotRuntime,
    createCopilotRuntimeHandler,
    InMemoryAgentRunner,
  } from "@copilotkit/runtime/v2";

  const agent = new BuiltInAgent({
    type: "tanstack",
    factory: ({ input, abortController }) => {
      const { messages, systemPrompts, tools } = convertInputToTanStackAI(input);
      return chat({
        adapter: openaiText("gpt-5.5"),
        messages,
        systemPrompts: [
          "You are a helpful assistant. When a visual answer helps, render it with generative UI.",
          ...systemPrompts,
        ],
        tools,
        abortController,
      });
    },
  });

  const runtime = new CopilotRuntime({
    agents: { default: agent },
    runner: new InMemoryAgentRunner(),
  });

  const handler = createCopilotRuntimeHandler({ runtime, basePath: "/api/copilotkit" });

  export const GET = handler;
  export const POST = handler;
  ```

  把 `convertInputToTanStackAI` 返回的两个值都传下去：

  - `tools` 里有 `render_ui` 工具。没有它，模型无法渲染。
  - `systemPrompts` 里有那份指南：有哪些组件、各自的 props，以及如何调用
    `render_ui`。没有它，模型不知道该渲染什么。

  把你自己的工具和提示词加在它们旁边。不要替换它们。
  </Step>
  <Step>
  ### 开启生成式 UI

  把标准组件目录交给 provider。它自带 69 个现成组件：布局、文本、输入、
  表格、图表、地图等等。

  ```tsx title="app/providers.tsx"
  "use client";
  import { CopilotKitProvider } from "@copilotkit/react-core/v2";
  import { standardUI } from "@copilotkit/react-core/v2/generative-ui";
  import "@copilotkit/react-core/v2/styles.css";

  export function Providers({ children }: { children: React.ReactNode }) {
    return (
      <CopilotKitProvider runtimeUrl="/api/copilotkit" generativeUI={{ ui: standardUI }}>
        {children}
      </CopilotKitProvider>
    );
  }
  ```

  组件目录里是 React 组件，因此 provider 必须在客户端组件中创建。用它包住
  你的 layout，让每个页面共享同一个 provider，并在某个页面上放一个聊天：

  ```tsx title="app/layout.tsx"
  import { Providers } from "./providers";

  export default function RootLayout({ children }: { children: React.ReactNode }) {
    return (
      <html lang="en">
        <body>
          <Providers>{children}</Providers>
        </body>
      </html>
    );
  }
  ```

  ```tsx title="app/page.tsx"
  "use client";
  import { CopilotChat } from "@copilotkit/react-core/v2";

  export default function Page() {
    return <CopilotChat />;
  }
  ```
  </Step>
  <Step>
  ### 要点可视化的东西

  运行 `npm run dev`，打开页面，发送：

  ```text
  Compare the Starter, Team, and Enterprise plans in a table
  ```

  智能体写的时候表格就逐渐填上了。它是真正的组件，所以像“给客服加一列”
  这样的追问会原地修改它。
  </Step>
</Steps>

这就是一套能跑起来的配置。智能体现在可以在聊天里渲染标准组件了。

## 没渲染出来时怎么办

智能体回答了，但 UI 没出现，或者显示的内容不对。打开 Inspector，进入
**Generative UI**，按你看到的情况打开对应标签页：

| 你看到的 | 打开 | 要看什么 |
| --- | --- | --- |
| 面板显示 “No generative UI” | 无需打开 | provider 没有 `generativeUI` 配置。把 `generativeUI={{ ui }}` 传给 `CopilotKitProvider`。 |
| 界面一直为空，或显示了它的后备内容 | **Surfaces** | 找到该界面并打开它的卡片。**Rejected operations** 会给出每个被丢弃操作的原因，例如未知组件。 |
| 某个组件显示错误或缺失的值 | **Surfaces** | 组件树会显示每个已渲染组件以及智能体发送的 props。 |
| 智能体从不使用某个组件或函数 | **Catalog** | 按名字搜索。不在列表里的组件不会发送给模型。没有挂载处理器的函数会有警告。 |
| 想看模型收到了什么 | **Prompt** | 上一次运行以及下一次运行的信封和 `render_ui` 指南。 |

## 理解核心概念

三个概念支撑起整个特性：

- **[界面（Surfaces）](/generative-ui/components/surfaces)**：生成式 UI
  渲染的地方。聊天是一个，页面的任何区域也可以是。
- **[组件目录（Catalogs）](/generative-ui/components/catalogs)**：智能体
  可以使用的组件及其 props。可以直接用标准目录，或添加你自己的。
- **[传输方式（Transports）](/generative-ui/components/transports)**：UI
  如何到达浏览器。智能体可以调用工具，也可以在 Markdown 回复里直接写出
  UI。
