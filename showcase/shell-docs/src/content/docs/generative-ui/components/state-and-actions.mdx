## 这是什么？

你希望智能体渲染的商品卡片表现得像应用的其他部分一样。它要能显示该商品
在购物车里的数量，在用户点击时加入购物车，并保留用户在表单里键入的内容。

三个工具把生成的 UI 连到你的应用：

- **应用状态**：用应用中的实时取值填充 props。
- **函数**：组件触发事件时运行你的代码。
- **可写 props**：保留用户键入的内容。

## 展示实时应用状态

智能体不知道购物车里有多少件商品，也不许它猜。在组件目录里声明状态，
由库来填充 prop：

```tsx title="app/catalog.tsx"
const cartSchema = z.object({
  items: z.array(z.object({ productId: z.string(), quantity: z.number() })),
});

export const shopUI = createGenerativeUI({
  id: "acme/shop@1",
  state: { cart: cartSchema },
  components: {
    ProductCard: {
      component: ProductCard,
      props: z.object({ productId: z.string(), name: z.string(), inCart: z.number() }),
      bind: {
        inCart: (state, { productId }) =>
          state.cart.items.find((item) => item.productId === productId)?.quantity ?? 0,
      },
    },
  },
});
```

然后在你的应用里为状态赋值：

```tsx
import { useGenerativeUIState } from "@copilotkit/react-core/v2/generative-ui";

function CartState({ cart }: { cart: Cart }) {
  useGenerativeUIState(shopUI, "cart", { items: cart.items });
  return null;
}
```

props 如何拿到取值：

- prop 与状态键同名时读取该键。名为 `cart` 的 prop 拿到 `state.cart`。
- `bind` 为 prop 提供一个选择器。选择器能拿到状态和智能体设置的 props。
- 智能体永远不会设置绑定的 prop，也看不到它。

智能体同样看不到状态。要让它能回答“我的购物车里有什么？”，还要用
[`useAgentContext`](/reference/hooks/useAgentContext) 把数据给它。

## 在点击时运行你的代码

“加入购物车”就必须真的加入购物车，不给智能体发消息。声明一个函数，给
组件一个同名事件，再挂载一个处理器：

```tsx title="app/catalog.tsx"
export const shopUI = createGenerativeUI({
  id: "acme/shop@1",
  functions: {
    addToCart: {
      description: "Add a product to the cart",
      parameters: z.object({ productId: z.string(), quantity: z.number().default(1) }),
    },
  },
  components: {
    ProductCard: {
      component: ProductCard,
      props: z.object({ productId: z.string(), name: z.string() }),
      events: { onAddToCart: {} },
    },
  },
});
```

```tsx
import { useGenerativeUIFunction } from "@copilotkit/react-core/v2/generative-ui";

function CartActions({ cart }: { cart: Cart }) {
  useGenerativeUIFunction(shopUI, "addToCart", ({ productId, quantity }) => {
    cart.addItem(productId, quantity);
    return { added: productId };
  });
  return null;
}
```

在组件里，事件是一个带类型的 prop。它会返回结果，因此你可以展示进度和
错误：

```tsx
import { useState } from "react";
import type { GenerativeUIComponentProps } from "@copilotkit/react-core/v2/generative-ui";

function ProductCard({ productId, name, onAddToCart }: GenerativeUIComponentProps<typeof shopUI, "ProductCard">) {
  const [error, setError] = useState<string>();
  return (
    <article>
      <h4>{name}</h4>
      <button
        onClick={async () => {
          const result = await onAddToCart?.({ productId });
          if (result && !result.ok) setError(result.error.message);
        }}
      >
        Add to cart
      </button>
      {error ? <p role="alert">{error}</p> : null}
    </article>
  );
}
```

事件按名称匹配函数，或匹配去掉 `on` 的名称：`onAddToCart` 调用
`addToCart`。

### 谁可以调用函数

声明可以携带 A2UI 1.0 的接口字段。`allowedCallers` 取 `"rendererOnly"`
（事件绑定和 prop 取值）、`"agentOnly"`（`callRendererFunction`）或
`"rendererOrAgent"`。`requiresUserActivation: true` 把函数限制在用户手势
之内，`openUrl` 就是如此，因此它是 `rendererOnly`。`returnType` 说明处理
器返回什么，使用 A2UI 的名称（`"string"`、`"number"`、`"boolean"`、
`"array"`、`"object"`、`"validationResult"`、`"any"`、`"void"`）。

```ts
functions: {
  addToCart: { parameters: z.object({ productId: z.string() }), allowedCallers: "rendererOrAgent", returnType: "object" },
  track: { parameters: z.object({ event: z.string() }), returnType: "void" },
  reload: { parameters: z.object({}), allowedCallers: "agentOnly" },
},
```

省略时只有 UI 能调用该函数，与 A2UI 1.0 一致。manifest 和导出的组件目录
总会把这个值写出来，因此 1.0 的读取方看到的是同样的东西。事件不能匹配
`"agentOnly"` 函数，内置函数都是 UI 的取值函数。

在本版本中，无论 `allowedCallers` 怎么写，智能体都完全不能调用渲染器
函数：`callRendererFunction` 操作会被拒绝，也不会向模型提及，因为它的
结果要以 developer 消息的形式传回，而并非所有后端都会把这类消息保存在
模型能按序读到的地方。这些声明字段会保留在组件目录导出里，等该通路开启
后即可使用。

## 把点击发给智能体

有些点击需要智能体。例如“给我看 Team 套餐”需要一条新的回答。匹配不到
任何函数的事件就会这么做。给它 `parameters`：

```ts
events: {
  onChoose: {
    description: "The user picked a plan",
    parameters: z.object({ plan: z.string() }),
  },
},
```

用户点击时，这次点击会变成一条可见的用户消息，智能体会回答它。智能体
也可以自己选这条消息的文本（即它的 `userMessage`），例如“给我看 Team
套餐”。

这次点击启动的运行还会携带结构化的 A2UI 1.0 操作消息，位于
`forwardedProps.copilotkit.ui.metadata.extensions.copilotkit_action`：
`{ "version": "v1.0", "action": { "name": "choose", "surfaceId": "plans", "sourceComponentId": "team-button", "timestamp": "2026-10-20T10:00:00.000Z", "userMessage": "Show me the Team plan", "context": { "plan": "team" } } }`。
想要结构化事件的智能体从这里读取，而不是解析消息文本；来自
`@copilotkit/shared` 的 `envelopeToManifest` 会把它作为 `action` 还给你。

## 在浏览器中计算值

prop 除了字面量和绑定，还可以是函数值，且可以在任意深度：
`{ "@call": "formatCurrency", "args": { "value": { "@path": "/total" }, "currency": "EUR" } }`。
它读取的数据一变就重新计算，不需要与智能体往返。A2UI 1.0 基础目录的
函数都是内置的：`formatString`（支持 `${/path}` 和 `${fn(arg: value)}`
插值）、`formatNumber`、`formatCurrency`、`formatDate`、`pluralize`、
`and`、`or`、`not`，校验器 `required`、`regex`、`length`、`numeric` 和
`email`，模板中的 `@index`，以及只在事件的 `functionCall` 中运行的
`openUrl`。

A2UI 1.0 没有算术运算，所以 CopilotKit 加了两个组件目录函数。`calc`
基于命名参数求表达式的值：
`{ "@call": "calc", "args": { "expression": "seats * 29 * (annual ? 0.8 : 1)", "seats": { "@path": "/seats" }, "annual": { "@path": "/annual" } } }`，
支持 `+ - * / %`、比较运算、`&& || !`、`?:`、`min`、`max`、`round`、
`floor`、`ceil`、`abs` 和文本拼接。`series` 用一个条目模板配合对循环
变量的 `${...}` 表达式，构建包含 `count` 个条目的列表，用于图表数据。
两者对模型来说都是普通的组件目录函数；没有它们的渲染器会拒绝调用。这些
内置函数只在浏览器中运行：智能体无法用 `callRendererFunction` 调用它们。

## 保留用户输入

智能体填过的结账表单必须保留用户的修改。在 `writable` 里列出组件可以
修改的 props，每个都会得到一个 setter：

```tsx
CheckoutForm: {
  component: CheckoutForm,
  props: z.object({ email: z.string().optional() }),
  writable: ["email"],
},
```

```tsx
function CheckoutForm({ email, setEmail }: GenerativeUIComponentProps<typeof shopUI, "CheckoutForm">) {
  return <input value={email ?? ""} onChange={(event) => setEmail(event.target.value)} />;
}
```

智能体把 `email` 绑定到界面的某个值后，用户键入的内容就会写进那里。从
那时起，这个值就属于用户了：后续的智能体更新覆盖不了它。智能体在下一次
运行时仍然能看到这个值。

至此，卡片展示实时购物车数据，按钮运行你的代码，表单保留用户的输入。
