## 这是什么？

你的智能体流式输出文本没问题，但工具调用很麻烦：框架不透传客户端工具，
或者提示词得你自己拼。可你还是希望回复里有真正的 UI。

在 Markdown 模式下，智能体把 UI 写在回复里一个标记为 `a2ui` 的代码块中。
聊天把每个代码块渲染成一个可交互的界面，其周围的文本则按普通 Markdown
渲染：

````markdown
Here is an estimate you can play with:

```a2ui
{"version":"v1.0","createSurface":{"surfaceId":"plan-estimator","dataModel":{"seats":10,"price":"$290 / month"},"components":[{"id":"root","component":"Card","children":["seats","price"]}]}}
{"version":"v1.0","updateComponents":{"surfaceId":"plan-estimator","components":[{"id":"seats","component":"Slider","label":"Seats","min":1,"max":50,"value":{"@path":"/seats"}},{"id":"price","component":"Text","text":{"@path":"/price"}}]}}
```

Move the slider to change the seat count.
````

每一行就是一个 [A2UI v1.0](https://a2ui.org) 操作。UI 就是纯文本，所以
任何能流式输出文本的 AG-UI 智能体都能用。

## 开启方式

在 provider 上设置 Markdown 传输：

```tsx title="app/providers.tsx"
import { CopilotKitProvider } from "@copilotkit/react-core/v2";
import { standardUI } from "@copilotkit/react-core/v2/generative-ui";

<CopilotKitProvider runtimeUrl="/api/copilotkit" generativeUI={{ ui: standardUI, transport: "markdown" }}>
  {children}
</CopilotKitProvider>;
```

之后每次运行，provider 都会向智能体发送两条 context 条目：

- 一份精简的组件 schema：包含组件名、props、事件和插槽。
- 一份如何编写这些代码块的指南。只包含你的组件目录需要的规则。

运行时不会给这些运行添加 `render_ui` 工具。内置智能体会把 context 条目
放进自己的 system prompt。LangGraph Python 智能体请加
`CopilotKitMiddleware`。任何其他智能体只需要做一件事：把该次运行的
context 条目放进它的 system prompt。

## 流式渲染方式

回复还在流式输出时，UI 就已经开始绘制：

- 某一行的内容一到全，对应组件立刻渲染，因此界面是一个组件一个组件地
  补齐的。
- 尚未到达的子组件不占空间，没有占位符。
- 组件在出现时淡入一次。
- 如果流中途断了，界面会保留已经画出来的部分。

## UI 渲染在哪里

- **在回复里**：代码块在文本中的位置就地渲染。
- **更新同一个界面**：同一回复中靠后的代码块若 `surfaceId` 相同，会更新
  那个界面，而不是再添一个。
- **在页面上**：带 target 的代码块（```` ```a2ui target=featured ````）
  会渲染进 `<GenerativeUISurface id="featured">`。后续回复可以更新它。
  参见[界面](/generative-ui/components/surfaces)。

如果智能体漏了 `createSurface`，CopilotKit 会补一个。

## 代码块内的文本

智能体有时会把一个标题或一段说明放进代码块。这些文本会被提取出来，按
聊天 Markdown 渲染，因此最终进入界面的只有真正的 UI。界面会围绕文本
拆分成几个部分。这些部分共享取值，所以一个部分里的滑杆仍会更新另一个
部分里的值。

## 自行构建提示词

有些后端自己拼提示词。把 context 条目关掉，改为从运行中读取同样的数据：

```tsx
<CopilotKitProvider
  runtimeUrl="/api/copilotkit"
  generativeUI={{ ui: standardUI, transport: "markdown", sendContext: false }}
>
```

每次运行都会在 `forwardedProps.copilotkit.ui` 携带这些数据，形态是
A2UI v1.0 渲染器能力（renderer capabilities）：

```json
{
  "v1.0": {
    "supportedCatalogIds": ["copilotkit/standard@1"],
    "inlineCatalogs": [
      {
        "catalogId": "copilotkit/standard@1",
        "protocolVersion": "1.0",
        "components": { "Card": { "props": { "type": "object" } } },
        "functions": {},
        "instructions": "You can show interactive UI in your reply ..."
      }
    ]
  },
  "metadata": {
    "extensions": {
      "copilotkit_format": 3,
      "copilotkit_transport": "markdown",
      "copilotkit_targets": [{ "id": "chat", "kind": "chat" }],
      "copilotkit_surfaces": {},
      "copilotkit_contextSent": false
    }
  }
}
```

```python
ui = input.forwarded_props["copilotkit"]["ui"]
catalog = ui["v1.0"]["inlineCatalogs"][0]
system = f"{MY_PROMPT}\n\n{catalog['instructions']}\n\nComponents:\n{json.dumps(catalog['components'])}"
```

各部分的含义：

- `components`：每个组件的 JSON Schema，含事件和插槽。
- `instructions`：指南文本。
- `copilotkit_targets`：屏幕上的渲染目标。
- `copilotkit_surfaces`：该线程的各个界面，包括用户输入的值和浏览器拒绝
  的操作。被删除的界面带 `"status": "deleted"`，其 id 不能再使用。
  `createSurface` 被浏览器拒绝的界面带 `"status": "failed"`。
- `copilotkit_contextSent`：context 条目也已发送时为 `true`，后端因此
  绝不会重复添加 schema。

针对这类后端还有两个选项：

- `includeCatalog: false` 不发送 `components`，适用于已经有这些信息的
  后端。
- `agentIds: ["chat"]` 只向这些智能体发送 context 和这份数据。

## v1 聊天组件

`@copilotkit/react-ui` 中的 v1 聊天组件（`CopilotChat`、`CopilotSidebar`、
`CopilotPopup`）同样能渲染 `a2ui` 代码块。给 v1 的 `<CopilotKit>` provider
传同样的 `generativeUI` prop 即可。不传的话，代码块会按普通代码渲染。

## 限制

- 代码块必须顶行开头。缩进在列表项内的代码块会按普通代码渲染。
- 取值可以是字面量、绑定（`{"@path": "/seats"}`）或函数值
  （`{"@call": "calc", "args": { "expression": "seats * 29", "seats": {"@path": "/seats"} }}`）；
  参见[函数值](/generative-ui/components/state-and-actions#compute-values-in-the-browser)。
  `calc` 之外没有运算符，也没有能对列表做映射的函数。
- 一个 `surfaceId` 绝不重复使用，`deleteSurface` 之后也一样。

要跑起来，用内置智能体或 LangGraph Python 智能体启动
[`examples/v2/a2ui-markdown`](https://github.com/CopilotKit/CopilotKit/tree/main/examples/v2/a2ui-markdown)，
然后打开 `/?transport=markdown`。
