## 这是什么？

MCP Apps 是一类带有 UI 资源的 MCP 服务器，其工具与 UI 资源相关联。当智能体调用其中某个工具时，CopilotKit 会自动获取该资源并在聊天中渲染对应的 UI 组件；无需任何额外的前端代码。

<Callout type="info">
  **免费课程**：在 [Build Interactive Agents with Generative UI](https://www.deeplearning.ai/short-courses/build-interactive-agents-with-generative-ui/) 中查看此模式的端到端构建——这是由 CopilotKit CEO 讲授的 DeepLearning.AI 免费短课程，涵盖生成式 UI 的全部形态（受控式、声明式和开放式）。
</Callout>

主要优势：

- **零前端代码**——UI 组件由 MCP 服务器提供
- **完全可交互**——组件可以使用 HTML、CSS 和 JavaScript
- **安全沙箱**——内容运行在隔离的 iframe 中
- **线程持久化**——MCP Apps 会存入会话历史，并在重新连接时恢复

## 将运行时接入你的 MCP 服务器

只需在运行时上添加一条 `mcpApps.servers` 配置即可。运行时会自动为每个已注册的智能体应用 MCP Apps 中间件：每当智能体调用一个由 MCP UI 资源支撑的工具时，中间件就会获取该资源并发出一个 `activity` 事件，由内置的 `MCPAppsActivityRenderer` 以沙箱化 iframe 的形式在聊天中内联渲染。

<Snippet region="runtime-mcpapps-config" />

<Callout type="info" title="务必固定 serverId">
  在生产环境中，务必提供一个稳定的 `serverId`。否则 CopilotKit 会对服务器 URL 做哈希处理，URL 一旦变化（例如在不同环境之间切换），就会悄悄破坏此前会话线程中已持久化的 MCP Apps 的恢复。
</Callout>

## 结合 Intelligence 使用 MCP Apps

`mcpApps` 选项在连接了 [Intelligence](/intelligence/quickstart) 的运行时上以同样的方式工作。这两个选项各司其职：

- `mcpApps` 配置智能体一侧。每次运行时，运行时都会把 MCP Apps 中间件挂载到智能体上。
- `intelligence` 替换运行器。Intelligence 会存储线程和运行记录，因此线程被加载时，会话中的 MCP Apps 会随之恢复。

要把现有的 MCP Apps 运行时迁移到 Intelligence，保持 `mcpApps` 原样不动。移除 `runner`，然后添加 `intelligence` 和 `identifyUser`：

```typescript title="app/api/copilotkit/[[...slug]]/route.ts" doctest="component"
import {
  BuiltInAgent,
  CopilotKitIntelligence,
  CopilotRuntime,
  createCopilotRuntimeHandler,
} from "@copilotkit/runtime/v2";

const agent = new BuiltInAgent({
  model: "openai/gpt-5.4",
  prompt: "You are a helpful assistant.",
});

const runtime = new CopilotRuntime({
  agents: { default: agent },
  // Intelligence stores threads and runs. Do not pass `runner` as well.
  intelligence: new CopilotKitIntelligence({
    apiKey: process.env.CPK_INTELLIGENCE_API_KEY!,
  }),
  // Replace this fixed user with the user from your verified session.
  identifyUser: () => ({ id: "demo-user", name: "Demo User" }),
  // Unchanged from the in-memory setup.
  mcpApps: {
    servers: [
      {
        type: "http",
        url: "https://mcp.excalidraw.com/mcp",
        serverId: "excalidraw",
      },
    ],
  },
});

const handler = createCopilotRuntimeHandler({
  runtime,
  basePath: "/api/copilotkit",
});

export const GET = handler;
export const POST = handler;
export const PATCH = handler;
export const DELETE = handler;
```

迁移到 Intelligence 时，请保持相同的 `serverId` 值。线程中存储的 MCP Apps 正是通过该 ID 引用服务器的。

如果只想把某个服务器分配给单个智能体，请在 `mcpApps.servers` 的对应条目中添加 `agentId`。在 Intelligence 运行时上，相比自己把 `MCPAppsMiddleware` 挂载到智能体上，更推荐这种方式：此时运行时会对照该智能体的服务器逐一检查来自 MCP App 的每个请求。

关于 API 密钥、用户身份和路由保护，请遵循 [Intelligence 快速开始](/intelligence/quickstart)。

## 无需前端渲染器

与自定义 activity 类型不同，MCP Apps 渲染器已由 `CopilotKit` 开箱即用地注册好。一个普通的 `<CopilotChat />` 就足够了；不需要 `renderActivityMessages` prop，也无需手动接线 `useRenderActivityMessage`。

## 沙箱与小组件存储

每个 MCP App 都运行在一个具有不透明 origin 的沙箱化 iframe 中。小组件无法读取你页面的 cookie、存储或 DOM。它也无法读取你的 API 的响应，除非某个 API 允许跨源请求（例如设置了 `Access-Control-Allow-Origin: *`）。但它仍然可以发送请求，因此请像对待其他任何站点一样，防范跨站请求伪造攻击，保护好会更改状态的端点。相应的代价是，小组件自己也无法使用 `localStorage`、`sessionStorage`、`IndexedDB` 或 cookie。

小组件发出的需要 CORS 的请求（例如 `<script type="module">` 和 `fetch`）会以 `Origin: null` 发送。请为公开的小组件资源配置 `Access-Control-Allow-Origin: *`。经典的 `<script src>` 标签则不需要 CORS。要完全绕开 CORS，可以把小组件打包成单个 HTML 文件，就像 [ext-apps 示例](https://github.com/modelcontextprotocol/ext-apps/tree/main/examples)使用 `vite-plugin-singlefile` 那样。

MCP Apps 规范将 `allow-same-origin` 与从独立 origin 提供的沙箱搭配使用。CopilotKit 是内联加载沙箱的，因此它选择不启用 `allow-same-origin`，而不是把页面的 origin 交给小组件。

如果小组件是你自己编写的且需要存储，可以恢复 `allow-same-origin`：

```tsx
<CopilotKit runtimeUrl="/api/copilotkit" mcpApps={{ allowSameOriginFallback: true }}>
  {children}
</CopilotKit>
```

<Callout type="warn" title="仅用于你信任的小组件">
  启用 `allowSameOriginFallback` 后，每个 MCP App 都会以你页面的 origin 运行。此时任何已连接 MCP 服务器的小组件都能读取你的 cookie 和存储，并以已登录用户的身份执行操作。如果你连接了第三方 MCP 服务器，请不要启用它。
</Callout>

## 传输类型

中间件支持两种传输类型：

### HTTP

使用此格式连接接受标准 HTTP 请求的 MCP 服务器：

```typescript
{
  type: "http",
  url: "http://localhost:3101/mcp",
  serverId: "my-http-server"
}
```

### SSE

使用此格式连接通过持久连接流式传输事件的 MCP 服务器：

```typescript
{
  type: "sse",
  url: "https://mcp.example.com/sse",
  headers: {
    "Authorization": "Bearer token"
  },
  serverId: "my-sse-server"
}
```
