## 这是什么？

基于工具的生成式 UI（Tool-based Generative UI）是生成式 UI 最简单的形式：你用 `useComponent` 注册一个 React 组件，CopilotKit 就会把它作为一个工具暴露给智能体。当智能体调用该工具时，CopilotKit 会把你的组件内联渲染在聊天中，并把工具参数原封不动地作为类型化的 props 传入。

[工具渲染](/generative-ui/tool-rendering)是用自定义 UI 包装一个真实的后端工具；与之不同，基于工具的 GenUI 本身就是组件。没有处理函数，没有用户交互，也没有服务端执行。智能体决定何时展示它、填入数据，然后由 CopilotKit 把它画出来。

## 什么时候应该使用？

当你想要以下效果时，就使用 `useComponent`：

- 在聊天中内联展示富 UI（卡片、图表、表格、仪表盘）
- 展示智能体从推理中得出的结构化数据
- 渲染预览、状态指示器或可视化摘要
- 让智能体以超出纯文本的方式呈现信息

需要用户交互的组件，请参阅[人机协同（Human-in-the-loop）](/human-in-the-loop)。要围绕真实的后端工具获得操作透明度，请参阅[工具渲染](/generative-ui/tool-rendering)。

## 代码中的工作方式

<FrameworkSetup concept="frontend-tools-setup" />

在注册工具的组件中导入 React 钩子和 Zod。这也适用于内置智能体——它不需要后端工具注册步骤。

```tsx
import { useComponent } from "@copilotkit/react-core/v2";
import { z } from "zod";
```

`useComponent` 接受一个名称、一个描述其 props 的 Zod schema，以及要渲染的组件。运行时会把它注册为前端工具，让智能体能够发现它；该 schema 则成为这个工具的参数定义——正是它告诉模型应当发送哪些参数。

<Callout type="warn">
  `parameters` 是可选的，但省略它会让这个工具以空的参数 schema（`{ "type": "object", "properties": {} }`）对外暴露。模型于是没有任何可填的内容，就会不带参数调用工具，你的组件也就渲染不出任何 props。凡是需要数据的组件，都请传入 schema。
</Callout>

组件本身就是普通的 React：它只读取自己的 props，并且可以随着智能体填充载荷而流式传入。上面的示例用 [Recharts](https://recharts.org) 画柱状图；它对 CopilotKit 一无所知。

<Callout type="info">
  你传给 `useComponent` 的 `name` 就是智能体看到的工具名。请用动词形式命名，比如 `render_bar_chart` 或 `show_weather`，这样当用户要求相应的可视化时，LLM 才能可靠地选中它。
</Callout>

## 在无头聊天中渲染

CopilotKit 内置的聊天组件会替你把注册的组件画出来。无头（headless）或自定义聊天则自己渲染消息列表，因此除非你亲自渲染，否则工具调用不会被画出来——组件已注册、智能体也会调用它，但聊天界面依然空空如也。

用 `CopilotChatToolCallsView` 渲染每条助手消息上的工具调用：

```tsx
import { CopilotChatToolCallsView } from "@copilotkit/react-core/v2";

<CopilotChatToolCallsView message={assistantMessage} messages={allMessages} />;
```

它会为每个工具调用查找同级的 `tool` 角色消息，并把两者一起交给已注册的渲染器。若要更精细地控制位置，可以调用 `useRenderToolCall()` 自己绘制每个工具调用——参见[无头 UI](/custom-look-and-feel/headless-ui)。
