## 这是什么？

一些模型（OpenAI 的 `o1`、`o3` 和 `o4-mini`，以及 Anthropic 的 thinking 变体）会发出**推理标记**（reasoning tokens），即解释模型如何一步步得出答案的内部思维链轨迹。CopilotKit 将其呈现为一等公民消息：当 `REASONING_MESSAGE_*` 事件从智能体到达时，聊天会将其内联渲染，让用户能够跟随智能体的思考。

推理并不是接一根自定义渲染器的管线，而是聊天视图上一种专门的消息类型。你既可以接受内置的渲染，也可以用自己的组件覆盖 `reasoningMessage` 插槽。

## 什么时候应该使用？

当你想要以下效果时，就在 UI 中展示推理：

- 让用户实时了解智能体的思考过程
- 展示长问题或多步骤问题的进度
- 在开发过程中调试提示词行为
- 为推理卡片定制品牌样式，与产品的其他部分保持一致

## 默认推理渲染（零配置）

开箱即用，推理事件会渲染在 CopilotKit 内置的 `CopilotChatReasoningMessage` 卡片中：

- 模型推理期间，显示带脉动指示器的 **“Thinking…”**（思考中）标签。
- 内容自动展开，用户可以实时跟随思维链。
- 推理结束后折叠为 **“Thought for X seconds”**（思考了 X 秒），并带有可重新展开的箭头。
- 推理文本以 Markdown 渲染。

无需任何配置；只要你的模型发出推理标记，卡片就会自动出现：

## 自定义推理渲染

要完全掌控推理卡片，请向 `messageView` 上的 `reasoningMessage` 插槽传入一个组件。你的组件会收到 `ReasoningMessage` 对象（`.content` 保存流式文本）、完整的 `messages` 列表以及 `isRunning`，足以判断该块是否仍在流式输出、它是否是当前位于末尾的活动消息：

<Callout type="info">
  `messageView.reasoningMessage` 插槽既可以接受完整组件（如上所示），也可以接受形如 `{ header, contentView, toggle }` 的子插槽对象——如果你只想微调默认卡片的部分内容。子插槽 props 请参阅参考文档。
</Callout>
