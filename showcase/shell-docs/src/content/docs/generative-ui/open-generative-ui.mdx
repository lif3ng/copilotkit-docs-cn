## 这是什么？

开放式生成式 UI（Open Generative UI）让智能体即时生成完整的沙箱化 UI（HTML、CSS 和 JavaScript），并实时流式输出到聊天中。用户可以看到界面实时构建的过程：先应用样式，然后 HTML 逐步流入，最后 JavaScript 表达式逐一执行。

<Callout type="info">
  **免费课程**：在 [Build Interactive Agents with Generative UI](https://www.deeplearning.ai/short-courses/build-interactive-agents-with-generative-ui/) 中查看此模式的端到端构建——这是由 CopilotKit CEO 讲授的 DeepLearning.AI 免费短课程，涵盖生成式 UI 的全部形态（受控式、声明式和开放式）。
</Callout>

主要优势：

- **无需预定义组件**——智能体按需创建所需的任何 UI
- **实时流式传输**——HTML 在生成的同时流入预览
- **CDN 库**——生成的 UI 可以通过 `<script>` 标签加载 Chart.js、D3、Three.js 等
- **安全沙箱**——内容运行在隔离的 iframe 中，没有同源访问权限
- **沙箱函数**——可选择向生成的 UI 暴露宿主函数，实现双向通信

## 最小配置

启用开放式生成式 UI 只需在运行时加一个开关，再加上前端一个普通的 `<CopilotChat />`；内置的 activity 渲染器由 `CopilotKit` 自动注册，因此无需额外的前端接线。不过你的智能体仍须把本次运行的前端工具交给它的模型（参见下方警告）。

随后，`OpenGenerativeUIMiddleware` 会把智能体流式输出的 `generateSandboxedUi` 工具调用转换为 `open-generative-ui` activity 事件，由内置的 `OpenGenerativeUIActivityRenderer` 挂载到沙箱化 iframe 中。

<Callout type="warn" title="你的智能体必须把前端工具传给它的模型">
  `generateSandboxedUi` 作为运行输入中的前端工具到达智能体。只有当智能体把本次运行的前端工具交给它的模型时，它才会调用该工具。如果它只绑定自己的工具，模型就永远看不到 `generateSandboxedUi`，于是什么都渲染不出来，也不会报错。

  - 内置智能体已经会传递前端工具。
  - 用 `create_agent`（Python）或 `createAgent`（TypeScript）构建的 LangGraph 智能体，会在其 `middleware` 中添加 `CopilotKitMiddleware()`（Python，来自 `copilotkit`）或 `copilotkitMiddleware`（TypeScript，来自 `@copilotkit/sdk-js/langgraph`）。手工搭建的图则需要把前端工具与自己的工具绑定在一起：Python 中使用 `CopilotKitState` 并绑定 `state["copilotkit"]["actions"]`；TypeScript 中把 `CopilotKitStateAnnotation.spec` 展开进 state 并绑定 `state.copilotkit.actions`（用 `@copilotkit/sdk-js/langgraph` 的 `convertActionsToDynamicStructuredTools` 转换它们）。
  - 其他智能体则从运行输入转发前端工具。参见[前端工具](/frontend-tools)。
</Callout>

### 在 Provider 上注册沙箱函数

每个沙箱函数都是一座经过 Zod 校验的宿主侧桥接，智能体可以在生成的 iframe 内部通过 `Websandbox.connection.remote.<name>(args)` 调用它。处理函数运行在宿主页面中，其描述会附加到智能体的上下文里，因此智能体在生成 HTML/JS 时知道有哪些桥接可用。

<Callout type="info" title="沙箱如何回调你">
  在生成的 UI 内部，智能体会写出调用 `await Websandbox.connection.remote.notifyHost({ message: "hi" })` 的 JS 代码。该调用被代理回宿主页面，由你的 `handler` 携带经过校验的参数执行。

### 常见用例

- **主题切换**——生成的 UI 控制应用的外观
- **购物车 / 状态管理**——产品卡片把商品推入宿主状态
- **导航**——生成的 UI 触发宿主应用的路由变化
- **数据获取**——沙箱请求宿主获取 iframe 无法直接访问的数据

## 流式传输的工作原理

智能体按照针对用户体验优化的顺序生成工具调用的参数：

1. **`placeholderMessages`**——生成期间立即显示
2. **`css`**——先输出全部样式；CSS 完成后预览即启动
3. **`html`**——生成的同时实时流入预览
4. **`jsFunctions`**——在表达式之前注入的可复用辅助函数
5. **`jsExpressions`**——逐一执行；用户能看到每一条生效

中间件会增量解析工具调用参数，并在每个参数完成时发出 activity 事件，预览因此得以渐进更新。

## 使用 CDN 库

沙箱化 iframe 可以从 CDN 加载外部库；只需在生成的 HTML `<head>` 中包含 `<script>` 或 `<link>` 标签即可。Chart.js、D3、Three.js 以及任何其他托管在 CDN 上的库都开箱即用。

```html
<head>
  <script src="https://cdn.jsdelivr.net/npm/chart.js"></script>
</head>
<body>
  <canvas id="myChart"></canvas>
</body>
```
