在动态 schema 方案中，由辅助 LLM 根据会话上下文生成整个 UI（schema、数据与布局）。这是最灵活的 A2UI 形态；智能体可以针对任何请求渲染任何 UI，而无需预定义 schema。

## 工作原理

1. 智能体调用 A2UI 工具来绘制一个 surface；该工具在 `injectA2UITool: true` 时可用。
2. 运行时把你客户端的 catalog（组件名 + Zod 属性 schema）序列化进 agent 的 `copilotkit.context`，让 LLM 知道它可以发出哪些组件。
3. 工具调用以 `TOOL_CALL_ARGS` 事件的形式流经 LangGraph。
4. A2UI 中间件拦截该流，并随着数据项陆续到达逐步渲染卡片。

## 三文件拆分

规范的 Bring-Your-Own-Catalog（BYOC）布局把三个文件并排放在 `frontend/src/app/a2ui/` 下：

| 文件 | 存放内容 |
|---|---|
| `definitions.ts` | 每个自定义组件的 Zod 属性 schema + 人类可读的描述。与平台无关，因此运行时可将其序列化给 LLM。 |
| `renderers.tsx` | 以相同名称为键的 React 实现。TypeScript 保证每个定义都有对应的渲染器。 |
| `catalog.ts` | `createCatalog(definitions, renderers, { includeBasicCatalog: true })`：把你的自定义组件与 CopilotKit 的内置基础组件合并。 |

## 我关闭了自动注入，现在怎么办？

不传 catalog、不设置 `injectA2UITool`，或传了 catalog 但设置 `injectA2UITool: false`，你都算完全退出了自动注入。这意味着你需要自己接好两块东西：让智能体生成 A2UI surface 的 `generate_a2ui` 工具，以及让这些 surface 得以渲染的 `A2UIMiddleware`。

<Steps>
<Step>
### A2UIMiddleware

`A2UIMiddleware` 负责把 agent 的 `a2ui_operations` 变成渲染出来的 surface。没有它，agent 的输出永远变不成 UI，只会作为普通工具结果透传。它还能替你注入 `generate_a2ui` 工具（`injectA2UITool: true`），让你跳过下一步。把它附加到 AG-UI agent 上：

```typescript
import { A2UIMiddleware } from "@ag-ui/a2ui-middleware";

agent.use(new A2UIMiddleware({ injectA2UITool: false }));
```
</Step>

<Step>
### A2UI 智能体工具

`generate_a2ui` 工具会运行一个辅助 LLM（子智能体）来设计 surface，这正是你要给它指定模型的原因。用 AG-UI 工厂构建它，并加入 agent 的工具列表：

```python title="agent.py"
from ag_ui_langgraph import get_a2ui_tools
from langchain_openai import ChatOpenAI

generate_a2ui = get_a2ui_tools({
    "model": ChatOpenAI(model="gpt-4o"),
    "default_catalog_id": "copilotkit://app-dashboard-catalog",
})

tools = [my_other_tool, generate_a2ui]
```
</Step>
</Steps>

## 渐进式流式传输

辅助 LLM 的 `render_a2ui` 工具调用以 `TOOL_CALL_ARGS` 事件的形式流经 LangGraph。A2UI 中间件会：

1. 先等待完整的 `components` 数组，再发出任何内容；schema 必须完整后才能开始渲染。
2. 从部分 JSON 中提取 `surfaceId` 与 `root`。
3. schema 完整后即发出 `createSurface` 与 `updateComponents`。
4. 逐步提取完整的 `items` 对象，并为每个对象发出一次 `updateDataModel`，随着数据流入，卡片逐一显现。

在 schema 仍在生成时，会显示一个内置的进度指示器；一旦数据项开始到达，它就会自动隐藏。

## 何时应该使用动态 schema？

- 你事先不知道 UI 的形状；智能体根据用户的请求决定展示什么。
- 你想先为 A2UI 做原型，暂时不想敲定 schema 文件。
- 你正在构建一个对话式仪表盘，其布局逐轮变化。

如果 surface 是众所周知的（例如商品卡片、航班结果），请优先使用**[固定 schema](./fixed-schema)**；它更快、更省成本，且 UI 是确定性的。
