## 这是什么？

[A2UI](https://a2ui.org)（Agent-to-UI）是一份声明式生成式 UI 规范，由
Google 主导，CopilotKit 作为发布与设计合作伙伴。它让你的智能体通过基于
JSON 的 schema 渲染结构化 UI 组件，而不是纯文本：卡片、行、列、徽章、
价格标签，全部由你（或平台）定义的组件目录组合而成。

你可以使用
[A2UI Composer](https://a2ui-composer.ag-ui.com/)
以可视化方式设计和预览 A2UI schema。

<Callout type="info">
  **免费课程**：想看这个模式的端到端构建，请看
  [Build Interactive Agents with Generative UI](https://www.deeplearning.ai/short-courses/build-interactive-agents-with-generative-ui/)
  —— 这是一门免费的 DeepLearning.AI 短课程，由 CopilotKit 的 CEO 讲授，
  覆盖生成式 UI 的完整谱系（受控式、声明式与开放式）。
</Callout>

## 两种方式

CopilotKit 提供两种互补的 A2UI 方式：

- **[动态模式](./a2ui/dynamic-schema)**：辅助 LLM 同时生成 schema*和*
  数据。灵活性最大，智能体可以为任何提示生成任何 UI。

- **[固定模式](./a2ui/fixed-schema)**：组件树提前以 JSON 形式编写好。
  智能体在运行时只向数据模型流式传入*数据*。速度最快，没有 LLM schema
  生成。

两种方式共享同一套 A2UI 传输协议和同一个前端渲染器。差别在于 *schema 从
哪里来*以及*数据如何到达客户端*。

<Callout type="info">
  要让智能体在聊天中以及页面各区域里，用你自己的 React 组件渲染
  A2UI v1.0，请参见[组件与界面](/generative-ui/components)。
</Callout>

## 工作原理

每个 A2UI 界面都由智能体发出、前端渲染器消费的三种操作组装而成：

1. **`createSurface`** 用其组件目录初始化界面，必须是第一个操作。
2. **`updateComponents`** 为界面定义组件树（即 schema）。
3. **`updateDataModel`** 提供通过 JSON Pointer 路径填充组件的数据。

CopilotKit Python SDK 为每个操作都提供了辅助函数：

```python
from copilotkit import a2ui

a2ui.create_surface(surface_id, catalog_id=...)
a2ui.update_components(surface_id, components)
a2ui.update_data_model(surface_id, {"items": data})
a2ui.render(operations=[...])  # wraps in a2ui_operations and serializes
```

## 设置

启用 A2UI 有两种方式。大多数应用用第一种。

### 在 provider 上传入组件目录（推荐）

把 A2UI 组件目录传给 `<CopilotKit>` provider。目录告诉渲染器你的智能体能
画哪些组件，而且它会自动替你做两件事：启用 A2UI，并把 A2UI 工具注入你的
智能体。运行时上无需任何 `a2ui` 配置块。

```tsx title="app/page.tsx"
import { CopilotKit } from "@copilotkit/react-core/v2";

<CopilotKit runtimeUrl="/api/copilotkit" a2ui={{ catalog: myCatalog }}>
  {children}
</CopilotKit>;
```

### 不传组件目录时在运行时上启用

如果不传组件目录，则改为在运行时上启用 A2UI。`a2ui: true` 会应用中间件，
让智能体发出的界面得到渲染；再加上 `injectA2UITool: true`，还会注入渲染
工具，让智能体能够动态生成界面：

```typescript title="app/api/copilotkit/[[...slug]]/route.ts"
import { CopilotRuntime, InMemoryAgentRunner } from "@copilotkit/runtime/v2";

const runtime = new CopilotRuntime({
  agents: { default: myAgent },
  a2ui: { injectA2UITool: true },
  runner: new InMemoryAgentRunner(),
});
```

中间件自动处理传输协议，拦截包含 A2UI 操作的工具结果，并在聊天中把它们
渲染为丰富的界面。

<Callout type="warn">
  provider 上没有组件目录、运行时上也没有 `a2ui` 时，A2UI 界面不会渲染。
  这些操作会作为普通工具结果直接透传。
</Callout>

### 注入的是什么

开启注入后，运行时会向你的智能体添加一个名为 `generate_a2ui` 的工具。
调用它会运行一个辅助 LLM（一个子智能体），根据你的组件目录设计完整的
A2UI 界面（组件、布局和数据），然后流式输出到聊天中。这个工具不需要你
自己写。完整流程参见[动态模式](./a2ui/dynamic-schema)。

### 自定义或退出注入

如果不想依赖自动注入，可以自己掌控：设置 `injectA2UITool: false`，并用
AG-UI 工厂自行提供工具（Python 中是 `get_a2ui_tools()`，TypeScript 中是
`getA2UITools()`），由你设定模型、默认目录 id 等更多选项。显式的
`injectA2UITool: false` 总是生效，即使传了组件目录也一样。
[固定模式](./a2ui/fixed-schema)正是这样工作的：你的智能体持有一个只出
数据的工具，不注入任何子智能体。

## 颜色与深色模式

内置基础组件目录的颜色来自 CSS 变量。在深色模式下（聊天元素的某个祖先
带有 `.dark`），CopilotKit 的样式表会根据聊天主题设置这些变量，因此卡片、
标签和按钮保持可读。要使用自己的颜色，请在界面上设置这些变量：React 和
Vue 中是 `.a2ui-surface`，Angular 中是 `copilot-a2ui-surface`。

```css
.a2ui-surface {
  --a2ui-color-surface: #fafafa; /* card, modal, chip and button backgrounds */
  --a2ui-color-border: #e5e5e5; /* borders, tab rule, divider */
  --a2ui-color-muted: #737373; /* captions and secondary text */
  --a2ui-color-error: #dc2626; /* validation errors */
  --a2ui-primary-color: #2563eb; /* primary buttons, selected chips, active tab */
}
```

在界面上设置的颜色值同时适用于浅色和深色模式。若只想设置深色配色，请用
`.dark .a2ui-surface` 限定作用范围。
