在固定模式（fixed schema）下，你只需设计一次 UI schema（手写，或使用
[A2UI Composer](https://a2ui-composer.ag-ui.com/)），并将其保存在智能体一侧。
智能体工具只提供*数据*；工具一返回，界面立即出现，因为运行时不需要生成任何东西。

不同集成之间唯一的差异，在于 schema 是以何种方式*交付*给运行时的：

- **Schema-loading**（包括 Strands TypeScript）：schema 保存为智能体旁的
  一个 `.json` 文件，在启动时加载一次。
- **Schema-inline**（spring-ai、ms-agent-dotnet）：schema 在源码中以内联的
  类型化字面量声明。宿主语言没有提供 `load_schema` JSON 加载器，因此结构直接
  编译进去。
- **LLM-driven**（Mastra 和 Strands Python）：智能体运行一次辅助 LLM 调用，
  按请求生成操作容器。组件目录仍然是固定的；schema 按需生成。

询问一个航班，智能体就会用预定义的 schema 渲染出一张结构完整的卡片：

  下文全部以机票预订为例，让接线有具体的东西可渲染 —— `display_flight`、
  `flight-fixed-catalog` 以及机场/航空公司组件只是本页的示例，并非 API 的一部分。

  真正可迁移的是**结构**：一个固定组件目录、一个按目录返回数据的工具，以及一个
  包含 `createSurface` + `updateComponents` + `updateDataModel` 的操作容器。
  保留你自己应用的领域，替换成你自己的组件和工具即可 —— 讲解模式的页面并不是
  让你去构建一个机票预订应用的说明书。
</Callout>

## 工作原理

1. schema 会对智能体可用：视集成方式而定，或是在启动时从 JSON 文件加载，
   或是内联声明，或是按请求生成。
2. 智能体的 `display_flight` 工具从主 LLM 接收数据（出发地 / 目的地 /
   航空公司 / 价格）。
3. 该工具返回一个包含 `createSurface` + `updateComponents` +
   `updateDataModel` 操作的操作容器。
4. A2UI 中间件拦截工具结果，前端使用配套的 5 组件客户端目录渲染界面
   （Title、Airport、Arrow、AirlineBadge、PriceTag，外加内置组件）。

## 组合式 schema

下面的示例展示了一张以组合方式由小型子组件拼装而成的航班卡片，而不是一个
大一统的 `FlightCard`：

```
Card
 └─ Column
     ├─ Title        ("Flight Details")
     ├─ Row          (Airport → Arrow → Airport)
     ├─ Row          (AirlineBadge · PriceTag)
     └─ Button       (Book)
```

这棵树放在后端：视集成方式而定，可以是一个 JSON 文件、一个内联字面量，或
每次请求的 LLM 输出。没有数据绑定的组件（如 `Title` 或 `Arrow`）直接内联
携带取值；与 LLM 数据绑定的组件（如 `Airport`）则通过 JSON Pointer 路径
引用字段，例如 `{ "path": "/origin" }`。A2UI 绑定器会在 React 渲染器运行
*之前*解析这些路径，因此你的渲染器拿到的是解析后的值，根本看不到路径 ——
但*定义*仍然必须把该 prop 声明为“字面量或绑定”的联合类型，因为这个联合
类型是绑定器判断 prop 可绑定的唯一信号。参见[声明组件定义](#声明组件定义)。

## 由 5 个组件构成的自定义目录

前端组件目录只声明领域相关的原语（Title、Airport、Arrow、AirlineBadge、
PriceTag），并通过 `includeBasicCatalog: true` 合并 CopilotKit 的基础组件
目录（Card、Column、Row、Text、Button 等）。

<Step>
### 声明组件定义

每个组件都把 props 声明为一个 Zod schema。凡是 schema 会绑定到数据模型的
prop —— 也就是可能以 `{ "path": "/origin" }` 而非字面量形式到达的值 ——
**必须**声明为字面量类型与绑定对象的联合类型。这正是下面 `DynString`
辅助类型的用途，也是 `Airport` 的 `code` 使用它而不是普通 `z.string()`
的原因。

绑定器通过*检查 prop 的 Zod 类型*来决定是否解析它：包含 `{ path }` 成员的
联合类型会被视为动态，并针对数据模型进行解析；普通的字面量类型则被视为静态，
原样透传。因此，把绑定的 prop 声明为 `z.string()` 不只是损失类型精度 ——
它等于告诉绑定器不要解析这个 prop，原始的 `{ path: "/origin" }` 对象会
直接到达你的渲染器。

<Callout type="warn" title="绑定的 prop 用普通 `z.string()` 会导致渲染崩溃">
  由于未解析的对象会到达渲染器，第一个把它当文本渲染的地方就会抛出 React 的
  [error #31](https://react.dev/errors/31)：
  `Objects are not valid as a React child (found: object with keys {path})`。
  报错信息里没有任何指向 schema 的线索，所以看起来像是渲染器的 bug，而不是
  漏了联合类型。遇到时先检查 prop 的声明类型。

  从不绑定的 prop（`Arrow`，或 `variant` 枚举）用普通类型即可。这条规则
  只适用于 schema 会绑定的 prop。
</Callout>

一旦声明了联合类型，绑定器就会在你的渲染器运行前解析路径，因此渲染器拿到的
仍然是普通字符串 —— 联合类型描述的是 *schema* 可能发送什么，而不是渲染器
必须处理什么。如果你不想手写联合类型，`@copilotkit/a2ui-renderer` 重新导出了
A2UI 的标准 `DynamicStringSchema`（以及 `DynamicNumberSchema`、
`DynamicBooleanSchema` 和配套类型）：

```ts
import { DynamicStringSchema } from "@copilotkit/a2ui-renderer";
```

### 将工具接入现有的 `StateGraph`

上面的代码片段止步于工具本身。参考 cell 用
`langchain.agents.create_agent` 加 `CopilotKitMiddleware` 搭建智能体 ——
那些导入就是为此服务的 —— 但构建过程本身并没有展示。如果你是在已写好的
智能体上添加 A2UI，用的很可能是手写的 `StateGraph`。工具保持不变；把它放进
`ToolNode`，图的其余部分原样保留：

```python title="agent.py (LangGraph StateGraph form)"
from langchain_openai import ChatOpenAI
from langgraph.graph import START, MessagesState, StateGraph
from langgraph.prebuilt import ToolNode, tools_condition

# `display_flight` is the tool defined above — unchanged.
model = ChatOpenAI(model="gpt-4.1-mini").bind_tools([display_flight])


def call_model(state: MessagesState):
    return {"messages": [model.invoke(state["messages"])]}


builder = StateGraph(MessagesState)
builder.add_node("call_model", call_model)
builder.add_node("tools", ToolNode([display_flight]))
builder.add_edge(START, "call_model")
builder.add_conditional_edges("call_model", tools_condition)
builder.add_edge("tools", "call_model")

# No `checkpointer=` — the LangGraph API server owns persistence and
# rejects a custom one. See the LangGraph quickstart for the FastAPI case,
# where you host the graph yourself and do need a checkpointer.
graph = builder.compile()
```

智能体已有的 system prompt 保持不变。参考 cell 的提示词告诉模型只调用
`display_flight` 一次然后停下，因为工具结果*本身就是*渲染好的卡片。不加这句，
模型往往会再次调用工具，去寻找一个状态码。

`CopilotKitMiddleware` 是 `create_agent` 的中间件，在 `StateGraph` 中没有
对应物 —— 而且固定模式也用不着它：把工具结果变成界面的 A2UI 中间件运行在
TypeScript 运行时里（见下文[注册运行时](#注册运行时)），而不在图里。注意，
去掉它也会一并失去它的其他功能 —— 注入前端工具、把智能体状态暴露给模型 ——
所以如果你的智能体依赖这些，请继续使用 `create_agent`。

### 动态生成 schema

Mastra 和 Strands Python 走的是另一条路：智能体工具通过强制工具选择运行一次
*辅助* LLM 调用，按请求生成操作容器。前端组件目录依然是固定的（同样是
`Title`/`Airport`/`Arrow`/`AirlineBadge`/`PriceTag` 这些原语），但 schema
是即时构建的。schema 构建与渲染输出发生在同一次工具调用中。

这两个 SDK 在这里都没有提供 `a2ui.render(...)` 的等价物，因此工具要自己组装
`a2ui_operations` 信封 —— 下面的操作构建器也是你需要照搬的部分。注意这些
操作是*嵌套*的（`{ createSurface: {...} }`）：消费方按操作键分发，扁平的
`{ type: "create_surface" }` 形态会被忽略，界面永远不会绘制出来。

## 为什么组合式优于单体式

一个巨大的 `FlightCard` 组件写起来更快，但会把设计锁死。用 Card / Column /
Row / Title / Airport / Arrow / AirlineBadge / PriceTag 拼装卡片，你能得到：

- **可复用的原语**：同一个 `Airport` 渲染器可用于搜索结果、预订确认，以及
  未来的座位图。
- **schema 层面的设计迭代**：调整行的排布或更换徽章只需改一次 JSON；渲染器
  代码分毫不动。
- **与 A2UI Composer 兼容**：手写的与 Composer 构建的 schema 共享同一套
  原语词汇。

## 注册运行时

在固定模式下，工具由你的智能体自己持有，所以你不希望运行时再注入它自己的。
启用 A2UI，但关闭注入。

在 provider 上传入组件目录就足以启用 A2UI：

```tsx title="app/page.tsx"
<CopilotKit runtimeUrl="/api/copilotkit" a2ui={{ catalog: myCatalog }}>
  {children}
</CopilotKit>
```

由于组件目录默认会自动注入 A2UI 工具，请在运行时上设置
`injectA2UITool: false`，让智能体自己的工具成为唯一在场的工具。中间件仍会
自动检测工具返回的操作并渲染界面，全程无需子智能体参与：

```typescript title="app/api/copilotkit/route.ts"
const runtime = new CopilotRuntime({
  agents: { "a2ui-fixed-schema": agent },
  a2ui: { injectA2UITool: false, agents: ["a2ui-fixed-schema"] },
});
```

## 操作处理器（参考）

参考实现把固定模式与 `action_handlers={...}` 搭配，声明乐观 UI 切换（例如
用户点击“Book”时把航班 schema 替换为 `BOOKED_SCHEMA`）。Python SDK 的
`a2ui.render` 尚不支持 `action_handlers`，因此 cell 中省略了它们；
`booked_schema.json` 这个同名文件仍然保留，以便 SDK 一旦暴露 handler
kwarg 就能立即接线。

等该能力可用后，按钮会这样声明它的 action：

```json
{
  "Button": {
    "label": "Book",
    "action": {
      "name": "book_flight",
      "context": [
        { "key": "flightNumber", "value": { "path": "/flightNumber" } },
        { "key": "price", "value": { "path": "/price" } }
      ]
    }
  }
}
```

Python 工具则用一个以 action 名为键（外加一个 `"*"` 兜底）的处理器来匹配
它。在 SDK 支持之前，请改为在前端处理点击 —— `createA2UIMessageRenderer` /
`onAction` 模式参见
[进阶 —— 操作处理器](/integrations/langgraph/generative-ui/a2ui/advanced#action-handlers)。

## 什么时候应该使用固定模式？

- 界面形态已知：航班卡片、商品磁贴、订单摘要、仪表盘。
- 你想要确定性的、由设计师掌控的 UI。没有 LLM schema 漂移。
- 你想要尽可能快的首次绘制；没有辅助 LLM 调用。

如果 UI 必须随提示而变，请改用**[动态模式](./dynamic-schema)**。
