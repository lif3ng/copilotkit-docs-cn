Copilot Runtime 是连接你的前端应用与 AI 智能体的后端层。它会在[快速开始](/quickstart)过程中完成配置，也是使用 CopilotKit 的推荐方式。

## 设置运行时

运行时是一个轻量的服务器端点，将它添加到你的后端即可：

```npm
npm install @copilotkit/runtime
```

下面是一个使用 Next.js 的最小示例。`createCopilotRuntimeHandler` 返回一个普通的 fetch 处理器。它挂载在 **catch-all** 路径上，并导出 **GET、POST、PATCH 和 DELETE**，这样运行时就能提供它的各个子路由（`/info`、智能体运行、线程），而不是单个 URL：

```ts title="app/api/copilotkit/[[...slug]]/route.ts" doctest="component"
import {
  CopilotRuntime,
  createCopilotRuntimeHandler,
  InMemoryAgentRunner,
} from "@copilotkit/runtime/v2";

const runtime = new CopilotRuntime({
  agents: {
    // your agents go here
  },
  runner: new InMemoryAgentRunner(),
});

const handler = createCopilotRuntimeHandler({
  runtime,
  basePath: "/api/copilotkit",
});

export const GET = handler;
export const POST = handler;
export const PATCH = handler;
export const DELETE = handler;
```

路由就位后，`GET /api/copilotkit/info` 会返回一份 JSON 描述，内容是这个运行时以及它已注册的智能体。各类工具——以及前端的传输方式自动探测——正是通过这个路由来发现你的运行时的，因此这是确认端点已正确接线的最快方式。

然后将你的前端指向该端点：

<FrontendOnly frontend="react">
```tsx
<CopilotKit runtimeUrl="/api/copilotkit" useSingleEndpoint={false}>
  <YourApp />
</CopilotKit>
```

<Callout type="warn">
  `useSingleEndpoint={false}` 会选择 REST 传输方式，这正是 `createCopilotRuntimeHandler` 所提供的。请显式传入该属性：在已发布版本中，`<CopilotKit>` 会把该标志固定为 `true`——也就是单路由传输，它把所有请求都发送到裸的 `runtimeUrl`——而多路由运行时会以 404 回应这种请求，同时 `GET /info` 仍返回 200，于是应用看起来像是已连接。`<CopilotKitProvider>` 在省略该属性时已经会通过 `/info` 协商传输方式，`<CopilotKit>` 未来也会如此；届时这种写法依然正确，但不再必要。参见 [Provider and handler pairs](/backend/runtime-endpoints#provider-and-handler-pairs)。

  如果你想要的是单一的仅 POST URL，可以改为在普通的 `route.ts` 上用 `createCopilotEndpointSingleRoute` 挂载运行时，并省略该属性。
</Callout>
</FrontendOnly>

<FrontendOnly frontend="angular">
```ts title="src/app/app.config.ts"
import { provideCopilotKit } from "@copilotkit/angular";

provideCopilotKit({
  runtimeUrl: "/api/copilotkit",
})
```
</FrontendOnly>

有关其他后端框架（Express、NestJS、Node.js HTTP）的配置，请参见[快速开始](/quickstart)。

## 默认智能体

如果你注册了一个名为 `"default"` 的智能体，CopilotKit 的预构建 UI 组件会自动使用它，前端无需任何额外配置。当你只有一个主要智能体、不想在每处都指定 `agentId` 时，这会非常有用。

```ts title="app/api/copilotkit/[[...slug]]/route.ts"
const runtime = new CopilotRuntime({
  agents: {
    // Frontend APIs use this agent when no other agent id is selected.
    default: new HttpAgent({ url: "https://my-agent.example.com" }),
  },
});
```

注册多个智能体时，除非选中了某个特定智能体，聊天默认由 `"default"` 智能体驱动。其他智能体仍可通过前端智能体 API 访问。

## 运行时提供哪些能力

### 身份验证与安全

运行时运行在你自己的服务器上，这意味着智能体通信全程留在服务端。这为你提供了一个可信环境，可以在其中实施身份验证、校验请求并保护 API 密钥的安全。使用运行时后，安全默认项会自动生效，你的智能体端点不会暴露给未经身份验证的访问。

### AG-UI 中间件

[AG-UI 协议](/ag-ui-protocol)支持一个中间件层（`agent.use`），可用于日志记录、防护栏、请求转换等。由于运行时在服务端运行，这些中间件在一个可信环境中执行，不会被客户端篡改。

### 智能体路由

当你向运行时注册多个智能体后，它会自动处理发现与路由。你的前端无需了解每个智能体位于何处、如何访问等细节。

### CopilotKit Intelligence

[线程（threads）](/AG-UI-Streams)和 [inspector](/inspector) 等特性通过运行时与 CopilotKit Intelligence 提供。它们让你开箱即用地获得会话持久化与调试能力。

## 内置中间件

运行时支持两种一等中间件选项，可直接在 `CopilotRuntime` 上启用，无需对每个智能体手动调用 `.use()`。

### A2UI

传入 `a2ui: {}` 即可自动为所有已注册的智能体应用 `A2UIMiddleware`：

```ts title="app/api/copilotkit/[[...slug]]/route.ts"
const runtime = new CopilotRuntime({
  agents: { default: myAgent },
  a2ui: {}, // enables A2UI rendering for all agents
});
```

若只想对特定智能体生效，请传入一个 `agents` 列表：

```ts
a2ui: {
  agents: ["my-agent"];
}
```

在前端，A2UI 渲染器会自动激活。只有当你想覆盖它的默认值时，才需要配置 `a2ui`：

<FrontendOnly frontend="react">
```tsx
<CopilotKit
  runtimeUrl="/api/copilotkit"
  useSingleEndpoint={false}
  a2ui={{ theme: myCustomTheme }}
>
  {children}
</CopilotKit>
```
</FrontendOnly>

<FrontendOnly frontend="angular">
```ts title="src/app/app.config.ts"
provideCopilotKit({
  runtimeUrl: "/api/copilotkit",
  a2ui: { theme: myCustomTheme },
})
```
</FrontendOnly>

### mcpApps

传入 `mcpApps` 即可在一个地方为所有智能体配置 MCP 服务器：

```ts title="app/api/copilotkit/[[...slug]]/route.ts"
const runtime = new CopilotRuntime({
  agents: { default: myAgent },
  mcpApps: {
    servers: [
      { type: "http", url: "http://localhost:3108/mcp", serverId: "my-server" },
    ],
  },
});
```

每个服务器条目可选地接受一个 `agentId` 字段，把该服务器限定给单个智能体使用。若省略该字段，服务器对所有智能体可用。

## 想直接连接我的 AG-UI 智能体怎么办？

CopilotKit 构建于 [AG-UI 协议](/ag-ui-protocol)之上，这是一个开放标准。如果你想在没有运行时的情况下让前端直接连接兼容 AG-UI 的智能体，可以在前端配置中传入智能体实例：

<FrontendOnly frontend="react">
```tsx
import { HttpAgent } from "@ag-ui/client";

const myAgent = new HttpAgent({
  url: "https://my-agent.example.com",
});

<CopilotKit agents__unsafe_dev_only={{ "my-agent": myAgent }}>
  <YourApp />
</CopilotKit>;
```
</FrontendOnly>

<FrontendOnly frontend="angular">
```ts title="src/app/app.config.ts"
import { HttpAgent } from "@ag-ui/client";
import { provideCopilotKit } from "@copilotkit/angular";

provideCopilotKit({
  selfManagedAgents: {
    "my-agent": new HttpAgent({
      url: "https://my-agent.example.com",
    }),
  },
})
```
</FrontendOnly>

<Callout type="warn">
  直接连接智能体适用于开发和原型验证。除非你对自己的配置有足够把握，否则不建议在生产环境中采用这种方式，CopilotKit 也不提供官方支持。如果直接连接遇到问题，需要你自行排查。
</Callout>

在采用这条路之前，有几点重要事项需要了解：

1. **身份验证由你自己负责**。使用 Copilot Runtime 时，安全默认项会自动生效，你的智能体端点不会暴露给未经身份验证的访问。而直接连接时，保护智能体端点安全、管理身份验证就完全取决于你自己了。

2. **许多生态特性将无法使用。**AG-UI 协议支持一个设计为在后端运行的中间件层。CopilotKit 生态中的许多特性都依赖这个服务端中间件。没有运行时，这些特性——包括[线程（threads）](/AG-UI-Streams)和其他能力——都将无法使用。

### 对比

|                        | 使用运行时                  | 直接连接          |
| ---------------------- | --------------------------- | ----------------- |
| **身份验证**           | 提供安全默认项              | 由你自行管理      |
| **AG-UI 中间件**       | 在服务端运行                | 不可用            |
| **智能体路由**         | 自动                        | 手动              |
| **生态特性**           | 完整支持                    | 有限              |
| **CopilotKit 支持**    | 支持                        | 不支持            |
| **配置**               | 需要后端端点                | 仅前端            |
