## 概览

CopilotKit 1.10.X 引入了全新的无头（headless）UI 系统和简化的消息格式。大多数现有代码可以继续工作，但你可能需要更新自定义消息处理。

**你需要了解的内容**：

- 消息格式已从类改为普通对象
- 新增适用于高级用例的无头 UI 钩子
- 大多数特性保持向后兼容

## 关键改进与变更

### 增强的消息格式

消息现在使用普通对象而非类，以获得更好的性能和更简单的处理方式。

#### 之前

```tsx
const message = new TextMessage({
  role: MessageRole.Assistant,
  content: "Hello, how are you?",
});
```

#### 之后

```tsx
const message = {
  role: "assistant",
  content: "Hello, how are you?",
};
```

### 简化的消息类型检查

消息类型检查已精简，带来更好的开发者体验。不再使用之前的 `isTextMessage` 等方法，现在可以直接检查消息的 `role` 属性。

#### 之前

```tsx
if (message.isTextMessage()) {
  if (message.role === "assistant") {
    console.log(message.content);
  }
  if (message.role === "user") {
    console.log(message.content);
  }
}

if (message.isImageMessage()) {
  console.log(message.image);
}

if (message.isActionExecutionMessage()) {
  console.log(message.toolCalls);
}

// etc...
```

#### 之后

```tsx
if (message.role === "assistant") {
  console.log(message.content, message.toolCalls, message.image);
}

if (message.role === "user") {
  console.log(message.content, message.image);
}
```

### 自定义助手消息

此前，你必须使用 `subComponent` 属性来渲染自定义助手消息。现在可以改用 `generativeUI` 属性。

**重要**：两者都会继续可用。

#### 之前

```tsx
import { AssistantMessageProps } from "@copilotkit/react-ui";

export const AssistantMessage = (props: AssistantMessageProps) => {
  const { message, subComponent } = props;

  return <div style={{ marginBottom: "0.5rem" }}>{subComponent}</div>;
};
```

#### 之后

```tsx
import { AssistantMessageProps } from "@copilotkit/react-ui";

export const AssistantMessage = (props: AssistantMessageProps) => {
  const { message } = props;

  return <div style={{ marginBottom: "0.5rem" }}>{message.generativeUI}</div>;
};
```

#### 向后兼容性

- 自定义子组件仍然完全受支持
- `subComponent`（旧版）和 `generativeUI`（新）属性均可使用
- 现有的 `useCopilotChat` 代码仍可正常工作

## 新特性

### 高级无头 UI 钩子

新的 `useCopilotChatHeadless_c` 钩子提供对聊天 UI 的完全控制：

**特性**：

- 完全控制聊天 UI 的渲染
- 内置生成式 UI 支持
- 高级建议管理
- 面向人机协同（human-in-the-loop）工作流的中断处理

下面是一个使用新无头 UI 钩子的示例：

```tsx
const { messages, suggestions, interrupt } = useCopilotChatHeadless_c();

return (
  <div>
    {suggestions.map((suggestion) => (
      <div key={suggestion.id}>{suggestion.title}</div>
    ))}

    {interrupt}

    {messages.map((message) => {
      switch (message.role) {
        case "assistant":
          if (message.generativeUI) return message.generativeUI;
          return <div key={message.id}>{message.content}</div>;
        case "user":
          return <div key={message.id}>{message.content}</div>;
      }
    })}
  </div>
);
```

## 那 `useCopilotChat` 呢？

随着新无头 UI 钩子的推出，我们开始弃用 `useCopilotChat`。它仍会在维护模式下继续支持数月，但所有新的无头 UI 特性都将加入 `useCopilotChatHeadless_c`。

我们建议新项目迁移到新钩子。不过，在准备好迁移之前，请放心继续使用 `useCopilotChat`。

### 何时迁移

以下情况请**继续使用 `useCopilotChat`**：

- 你当前的实现运行良好
- 你不需要高级无头特性
- 你更倾向于渐进式迁移

以下情况请**迁移到 `useCopilotChatHeadless_c`**：

- 正在启动新项目
- 正在构建新的无头 UI 实现
- 需要生成式 UI 能力
- 想要使用高级建议与中断
- 正在构建完全自定义的聊天体验
