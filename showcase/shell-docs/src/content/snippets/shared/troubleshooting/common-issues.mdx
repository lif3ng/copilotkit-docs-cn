## 出现网络错误 / 找不到 API 的报错

如果你遇到网络或 API 错误，可以按以下方式排查：

<Accordions>
    <Accordion title="检查端点配置">
        检查 CopilotKit 配置中的端点设置：

        <FrontendOnly frontend="react">
        ```tsx
        <CopilotKit
          runtimeUrl="/api/copilotkit"
        >
          {/* Your app */}
        </CopilotKit>
        ```
        </FrontendOnly>

        <FrontendOnly frontend="react">
        或者，如果使用 Copilot Cloud
        ```tsx
        <CopilotKit
            publicApiKey="<your-copilot-cloud-public-api-key>"
        >
            {/* Your app */}
        </CopilotKit>
        ```
        </FrontendOnly>

        <FrontendOnly frontend="angular">
        ```ts title="src/app/app.config.ts"
        import { provideCopilotKit } from "@copilotkit/angular";

        provideCopilotKit({
          runtimeUrl: "/api/copilotkit",
          // Add this when using CopilotKit Intelligence.
          licenseKey: "<your-copilot-cloud-public-key>",
        })
        ```
        </FrontendOnly>

        常见问题：
        - 端点路径缺少开头的斜杠
        - 相对于应用 base URL 的路径不正确；如果使用绝对路径，则完整 URL 不正确
        - 端点路径有拼写错误
        <FrontendOnly frontend="react">
        - 如果使用 Copilot Cloud，请确保省略 `runtimeUrl` 属性并提供有效的 API 密钥
        </FrontendOnly>
    </Accordion>
    <Accordion title="localhost 与 127.0.0.1">
        如果你在本地运行并遇到连接错误，试试用 `127.0.0.1` 代替 `localhost`：

        ```bash
        # 如果这样不行：
        http://localhost:3000/api/copilotkit

        # 改成这样试试：
        http://127.0.0.1:3000/api/copilotkit
        ```

        这通常是由于 `/etc/hosts` 中的本地 DNS 解析问题或网络配置导致的。
    </Accordion>
    <Accordion title="确认后端正在运行">
        确保你的后端服务器：
        - 在预期的端口上运行
        - 可以被你的前端访问
        - 没有被 CORS 或防火墙拦截

        设置方法参见[快速开始](/quickstart)
    </Accordion>

</Accordions>

## 出现 “CopilotKit's Remote Endpoint” 未找到的报错

如果你看到 “CopilotKit's Remote Endpoint not found” 报错，通常意味着提供 `/info` 端点的服务不可访问。修复方法如下：

<Accordions>
    <Accordion title="检查 FastAPI 配置（如果使用 Python 的 FastAPI）">
        确保你的 FastAPI 应用已正确配置 CopilotKit SDK。<br/>
        如何配置参见 [Remote Python Endpoint](/guides/backend-actions/remote-backend-endpoint)
    </Accordion>
    <Accordion title="测试你的端点">
        `/info` 端点应返回智能体或操作信息。直接测试它：

        ```bash
        curl -v -d '{}' http://localhost:8000/copilotkit/info
        ```
        响应大致如下：
        ```bash

        * IPv6: ::1
        * IPv4: 127.0.0.1
        *   Trying [::1]:8000...
        * connect to ::1 port 8000 from ::1 port 55049 failed: Connection refused
        *   Trying 127.0.0.1:8000...
        * Connected to localhost (127.0.0.1) port 8000
        > POST /copilotkit/info HTTP/1.1
        > Host: localhost:8000
        > User-Agent: curl/8.7.1
        > Accept: */*
        > Content-Length: 2
        > Content-Type: application/x-www-form-urlencoded
        >
        * upload completely sent off: 2 bytes

        <
        * Connection #0 to host localhost left intact

        ```

        可以看到，这是一个 JSON 响应，包含你注册的智能体和操作，以及 `200 OK` 的 HTTP 状态。
        如果响应不同，请检查 FastAPI 日志中的错误。
    </Accordion>

## 隧道创建的连接问题

如果隧道创建过程一直在转圈，可能是你的路由器或 ISP 阻断了到 CopilotKit 隧道服务的连接。

<Accordions>
    <Accordion title="路由器或 ISP 阻断了隧道连接">
        要验证与隧道服务的连通性，试试这些命令：

        ```bash
        ping tunnels.devcopilotkit.com
        curl -I https://tunnels.devcopilotkit.com
        telnet tunnels.devcopilotkit.com 443
        ```

        如果这些命令失败，可能是路由器的安全功能或 ISP 阻断了连接。常见解决方案：
        - 检查路由器的安全设置
        - 联系 ISP 确认是否阻断了连接
        - 换个网络确认问题所在
    </Accordion>

</Accordions>
