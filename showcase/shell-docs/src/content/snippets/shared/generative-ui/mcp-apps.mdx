## 前置条件

开始之前，你需要准备以下内容：

- OpenAI API 密钥（或你偏好的 LLM 提供方的 API 密钥）
- Node.js 20+
- 你常用的包管理器
- 一个正在运行的 MCP 服务器（参见下文[示例 MCP 服务器](#示例-mcp-服务器)）

## MCP Apps 是什么？

MCP Apps 是一类 MCP 服务器，它们对外暴露的工具带有与之关联的 UI 资源。当智能体调用其中某个工具时，CopilotKit 会自动获取并在聊天中渲染对应的 UI 组件——无需额外的前端代码。

主要优势：

- **零前端代码** —— UI 组件由 MCP 服务器提供
- **完全可交互** —— 组件可以使用 HTML、CSS 和 JavaScript
- **安全沙箱** —— 内容运行在隔离的 iframe 中
- **直接的服务器通信** —— 中间件在渲染出的 UI 与 MCP 服务器之间安全地代理通信，实现实时交互
- **线程持久化** —— MCP Apps 会存入会话历史，并在重新连接时恢复

## 快速开始

想在一个新应用中体验 MCP Apps？我们提供了一个预构建的示例应用，可通过我们的 CLI 使用。

```bash
npx copilotkit create -f mcp-apps
```

## 开始使用

如果你想将 MCP App 添加到现有应用中，我们来逐步走一遍流程。

<Steps>
  <Step>
    ### （可选）创建新应用

    本示例将从零开始，如果你已有应用，可以跳过这一步。

    为便于示例，我们使用 Next.js，但该流程同样适用于任何前端 React 框架。

    ```bash
    npx create-next-app@latest
    ```

  </Step>
  <Step>
    ### 安装依赖

    ```npm
    npm install @copilotkit/react-core @copilotkit/runtime
    ```

    请使用 `@copilotkit/runtime` 1.76.0 或更高版本。运行时已内置 MCP Apps 中间件，因此下方的 `mcpApps` 选项无需其他包。只有当你自己通过 `.use()` 把中间件挂到某个智能体上时，才需要安装 `@ag-ui/mcp-apps-middleware`。其当前版本需要 `@ag-ui/client` 1.x，运行时 1.76.0 及以上版本使用的也是该版本。

  </Step>
  <Step>
    ### 配置智能体

    将你的智能体配置连同 MCP 服务器配置一起添加到 CopilotRuntime：

    <Callout>
      同样的流程适用于任何智能体配置。
    </Callout>

    ```bash
    touch app/api/copilotkit/route.ts
    ```

    ```typescript title="app/api/copilotkit/[[...slug]]/route.ts" doctest="component"
    import {
      CopilotRuntime,
      createCopilotRuntimeHandler,
      InMemoryAgentRunner,
    } from "@copilotkit/runtime/v2";
    import { BuiltInAgent } from "@copilotkit/runtime/v2";

    // 1. Create your agent
    const agent = new BuiltInAgent({
      model: "openai/gpt-5.4",
      prompt: "You are a helpful assistant.",
    });

    // 2. Create a service adapter, empty if not relevant

    // 3. Create the runtime with mcpApps configured
    const runtime = new CopilotRuntime({
      agents: {
        default: agent,
      },
      mcpApps: {
        servers: [
          {
            type: "http",
            url: "http://localhost:3108/mcp",
            serverId: "my-server", // Recommended: stable identifier
          },
        ],
      },
      runner: new InMemoryAgentRunner(),
    });

    // 4. Create the API route
    const handler = createCopilotRuntimeHandler({
      runtime,
      basePath: "/api/copilotkit",
    });

    export const GET = handler;
    export const POST = handler;
    ```

    <Callout type="info" title="服务器 ID">
      生产环境部署时务必提供 `serverId`。否则，CopilotKit 会基于服务器 URL 生成一个哈希值。如果你的 URL 发生变化（例如在不同环境之间），会话历史中先前存储的 MCP Apps 将无法正确加载。
    </Callout>

    或者，如果你想将 MCP Apps 限定于特定智能体，可以通过 `.use()` 直接在智能体上使用 `MCPAppsMiddleware`：

    ```typescript title="app/api/copilotkit/route.ts"
    import { MCPAppsMiddleware } from "@ag-ui/mcp-apps-middleware";

    const agent = new BuiltInAgent({
      model: "openai/gpt-5.4",
      prompt: "You are a helpful assistant.",
    }).use(
      new MCPAppsMiddleware({
        mcpServers: [
          {
            type: "http",
            url: "http://localhost:3108/mcp",
            serverId: "my-server",
          },
        ],
      }),
    );
    ```

    <Callout type="info" title="使用 Intelligence？">
      在连接到 Intelligence 的运行时上，保留 `mcpApps`，并将 `runner: new InMemoryAgentRunner()` 替换为 `intelligence` 和 `identifyUser`。参见 [MCP Apps with Intelligence](/generative-ui/mcp-apps#mcp-apps-with-intelligence)。
    </Callout>

  </Step>
  <Step>
    ### 配置环境

    在前端目录下创建 `.env.local` 文件，并添加你的 API 密钥：

    ```plaintext title=".env.local"
    OPENAI_API_KEY=your_openai_api_key
    ```

    <Callout type="info" title="其他模型怎么办？">
    示例默认配置为使用 OpenAI 的 GPT-4o，但你可以修改 BuiltInAgent，改用 CopilotKit 支持的任何语言模型。
    </Callout>

  </Step>
  <Step>
    ### 配置 CopilotKit Provider

    用 CopilotKit provider 包裹你的应用：

    ```tsx title="app/providers.tsx"
    "use client";

    import { CopilotKit } from "@copilotkit/react-core/v2";

    export function Providers({ children }: { children: React.ReactNode }) {
      return (
        <CopilotKit runtimeUrl="/api/copilotkit" useSingleEndpoint={false}>
          {children}
        </CopilotKit>
      );
    }
    ```

    `app/layout.tsx` 是服务端组件，无法直接导入 provider，因此它改为渲染你的客户端文件：

    ```tsx title="app/layout.tsx"
    // [!code highlight:2]
    import { Providers } from "./providers";
    import "@copilotkit/react-core/v2/styles.css";

    // ...

    export default function RootLayout({ children }: {children: React.ReactNode}) {
        return (
            <html lang="en">
                <body>
                    {/* [!code highlight:3] */}
                    <Providers>
                        {children}
                    </Providers>
                </body>
            </html>
        );
    }
    ```

  </Step>
  <Step>
    ### 添加聊天界面

    将 CopilotSidebar 组件添加到你的页面：

    ```tsx title="app/page.tsx"
    "use client";

    import { CopilotSidebar } from "@copilotkit/react-core/v2";

    export default function Page() {
        return (
            <main>
                <h1>Your App</h1>
                <CopilotSidebar />
            </main>
        );
    }
    ```

  </Step>
  <Step>
    ### 启动你的 UI

    启动开发服务器：

    <Tabs groupId="package-manager" items={['npm', 'pnpm', 'yarn', 'bun']}>
        <Tab value="npm">
            ```bash
            npm run dev
            ```
        </Tab>
        <Tab value="pnpm">
            ```bash
            pnpm dev
            ```
        </Tab>
        <Tab value="yarn">
            ```bash
            yarn dev
            ```
        </Tab>
        <Tab value="bun">
            ```bash
            bun dev
            ```
        </Tab>
    </Tabs>

    你的应用将在 `http://localhost:3000` 上可用。

  </Step>
</Steps>

大功告成！现在，当智能体使用了带有关联 UI 资源的工具时，MCP Apps 就会自动渲染。

## 传输类型

中间件支持两种传输类型：

### HTTP 传输

适用于基于 HTTP 通信的 MCP 服务器：

```typescript
{
  type: "http",
  url: "http://localhost:3101/mcp",
  serverId: "my-http-server"
}
```

### SSE 传输

适用于使用 Server-Sent Events 的 MCP 服务器：

```typescript
{
  type: "sse",
  url: "https://mcp.example.com/sse",
  headers: {
    "Authorization": "Bearer token"
  },
  serverId: "my-sse-server"
}
```

## 线程支持

MCP Apps 与 CopilotKit 的线程系统完全集成：

- **持久化** —— 保存线程时，MCP Apps 会作为会话历史的一部分存储
- **恢复** —— 加载线程时，所有 MCP Apps 都会连同其原始状态一起恢复
- **服务器 ID 稳定性** —— 使用一致的 `serverId` 可确保 MCP Apps 在各会话间正确加载
