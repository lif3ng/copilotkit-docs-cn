智能中枢的 AG-UI 流为这个自定义 UI 背后的历史记录与消息投递提供支撑。使用 `useThreads` 列出和管理会话，并把它们的 `threadId` 传给你的聊天组件。

## 这是什么？

`useThreads` 钩子可以列出、创建、重命名、归档和删除 CopilotKit Intelligence 线程，并通过 WebSocket 实现实时同步。线程适用于任何智能体框架——CopilotKit Intelligence 在服务端存储会话历史，因此用户可以关闭浏览器，之后再从上次中断的地方继续。除非你的后端显式桥接了这些系统，否则它不会列出或修改原生 LangGraph、ADK 或其他框架的存储。线程元数据更新（重命名、归档、新线程）无需轮询即可出现在已连接的客户端上。

## 什么时候应该使用它？

- 你的应用需要为每个用户保存多个会话（比如聊天历史侧边栏）
- 用户需要能够跨会话或跨设备恢复之前的对话
- 你需要实时同步，让在一个标签页创建的线程出现在另一个标签页上
- 你需要让用户通过重命名或归档来整理会话

## 前置条件

- 已连接 CopilotKit Intelligence 的 CopilotKit 应用
- `@copilotkit/react-core` v1.56 或更高版本
- 你的运行时所支持的模型提供方密钥

对于多用户应用，在暴露线程列表或生命周期操作之前，先把 Runtime 配置为
[将 AG-UI 流限定到已登录用户](/threads-lifecycle#scope-rich-threads-to-the-signed-in-user)。

<Steps>
      <Step>
        ### 为 Runtime 配置 CopilotKit Intelligence

        在线程 UI 能够列出和恢复会话之前，你的 `CopilotRuntime` 必须连接到 CopilotKit Intelligence。这个连接就是下文的 `intelligence` 选项——一个 `CopilotKitIntelligence` 实例。如果你的应用来自 CLI 起步模板，这段 Runtime 配置已经为你生成好了。否则，请按照[将运行时连接到智能中枢](/intelligence/quickstart)了解完整构造函数，然后回到这里添加无头 UI。线程名称由 LLM 在首条消息之后自动生成——你可以用 `generateThreadNames: false` 关闭这一行为。

        ```typescript title="server.ts"
        import {
          CopilotKitIntelligence,
          CopilotRuntime,
        } from "@copilotkit/runtime/v2";

        const runtime = new CopilotRuntime({
          agents: {
            default: agent,
          },
          // Without `intelligence` the runtime runs in SSE mode and the thread
          // UI has nothing to list — chat still works, so this fails quietly.
          intelligence: new CopilotKitIntelligence({
            apiKey: process.env.CPK_INTELLIGENCE_API_KEY!,
          }),
          // Required alongside `intelligence`: threads are scoped per user, so
          // without this every visitor shares one history. Resolve the real
          // signed-in user — see Thread & History Lifecycle.
          identifyUser: async (request) => {
            const session = await verifyAppSession(request);
            if (!session?.user) throw new Error("Unauthorized");
            return { id: session.user.id, name: session.user.name };
          },
          // Thread names are auto-generated by default.
          // Set to false to disable:
          // generateThreadNames: false,

          // Optional: tune thread lock behavior
          // lockTtlSeconds: 20,              // Lock TTL (default 20s, max 3600s)
          // lockHeartbeatIntervalSeconds: 15, // Heartbeat interval (default 15s, max 3000s)
          // lockKeyPrefix: "my-app",          // Custom Redis key prefix for the lock
        });
        ```

        CLI 的 `init` 及其 `create` 别名会把云托管平台 URL、`SL_ENABLED`、项目级 `CPK_INTELLIGENCE_API_KEY` 和可选的 `CPK_TELEMETRY_ID` 写入 `.env`。

        请把 `CPK_INTELLIGENCE_API_KEY` 保存在服务端。项目密钥负责把 Runtime 连接到智能中枢；遥测 ID 则是一个非机密的分析身份。

        云托管配置不会签发 `COPILOTKIT_LICENSE_TOKEN`。该令牌仅用于离线或自托管授权，不能替代云托管的项目 API 密钥。

        已启用智能中枢的现有应用应保持其当前的服务端 Runtime 配置。

        生产级自托管使用相同的 React API，并由 CopilotKit 工程团队协助通过[自托管 CopilotKit Intelligence](/intelligence/self-hosting) 进行部署。

        **线程锁选项**：智能体运行开始时，runtime 会对线程加锁以防止并发运行。你可以调整这一行为：

        | 选项 | 默认值 | 上限 | 说明 |
        |------|--------|------|------|
        | `lockTtlSeconds` | `20` | `3600`（1 小时） | 锁在自动过期前保持的时长。 |
        | `lockHeartbeatIntervalSeconds` | `15` | `3000`（50 分钟） | 运行期间 runtime 续期锁的频率。 |
        | `lockKeyPrefix` | — | — | 线程锁的自定义 Redis 键前缀。多个应用共用一个 Redis 实例时很有用。 |
      </Step>

      <Step>
        ### 用 useThreads 列出和管理线程

        使用 `useThreads` 钩子为特定智能体获取和管理线程。该钩子返回线程列表、加载状态和变更方法。

        ```tsx title="ThreadSidebar.tsx"
        import { useThreads } from "@copilotkit/react-core/v2"; // [!code highlight]

        function ThreadSidebar() {
          const { // [!code highlight:6]
            threads,
            isLoading,
            renameThread,
            archiveThread,
            deleteThread,
          } = useThreads({ agentId: "my-agent" });

          if (isLoading) return <div>Loading...</div>;

          return (
            <div>
              {threads.map((thread) => (
                <div key={thread.id}>
                  <span>{thread.name ?? "New conversation"}</span>
                  <button onClick={() => renameThread(thread.id, "Renamed")}>
                    Rename
                  </button>
                  <button onClick={() => archiveThread(thread.id)}>
                    Archive
                  </button>
                </div>
              ))}
            </div>
          );
        }
        ```

        `threads` 数组按最近更新时间倒序排列，并保持实时同步——来自其他标签页或设备的新线程会自动出现。

        **归档与删除的区别**：`archiveThread` 是软删除——线程仍保留在数据库中，但默认从列表中隐藏。传入 `includeArchived: true` 可以显示已归档的线程。`deleteThread` 是永久且不可逆的。两者都没有内置确认对话框——如有需要请自行添加。
      </Step>

      <Step>
        ### 在线程之间切换

        当用户选择一个线程时，把它的 `threadId` 传给你的聊天组件。聊天组件会清空当前消息、获取所选线程的历史并回放。如果智能体仍在该线程上运行，聊天会接上实时流。

        ```tsx title="App.tsx"
        import { CopilotChat } from "@copilotkit/react-core/v2"; // [!code highlight]
        import { useState } from "react";

        function App() {
          const [activeThreadId, setActiveThreadId] = useState<string | undefined>();

          return (
            <div className="flex">
              <ThreadSidebar onSelectThread={setActiveThreadId} />
              <CopilotChat threadId={activeThreadId} /> {/* [!code highlight] */}
            </div>
          );
        }
        ```

        当 `threadId` 变化时，聊天组件会自动加载所选线程的历史并重新连接到智能体的流。如果智能体仍在该线程上运行，聊天会接上实时流。

        <WhenFrameworkHas flag="thread_persistence_pattern" equals="langgraph">
          <Callout type="info" title="LangGraph 持久化">
            当你传入显式的 CopilotKit `threadId` 时，CopilotKit 会把它作为 AG-UI `threadId` 转发给后端。在你实现该映射的前提下，LangGraph 后端可以直接使用这个值，或把它映射为自己的 checkpoint/线程标识符。LangGraph Platform 的线程 ID 必须是 UUID。CopilotKit 的 `useThreads` 管理的是 CopilotKit Intelligence 线程记录；除非你的后端额外加了桥接，重命名、归档和删除操作不会更新 LangGraph 存储。
          </Callout>
        </WhenFrameworkHas>

        <WhenFrameworkHas flag="thread_persistence_pattern" equals="adk-session">
          <Callout type="info" title="ADK 会话">
            当你传入显式的 CopilotKit `threadId` 时，CopilotKit 会把它作为 AG-UI `threadId` 转发给后端。ADK 后端可以把这个值映射为 ADK 会话 ID，但当前示例使用的是内存版 ADK 服务，因此这些会话默认并不持久。持久的 ADK 会话持久化需要配置独立的 ADK session service。CopilotKit 的 `useThreads` 管理的是 CopilotKit Intelligence 线程记录，而不是 ADK 的原生会话存储。
          </Callout>
        </WhenFrameworkHas>
      </Step>

      <Step>
        ### 为大量线程列表添加分页

        对于会话较多的用户，可以使用 `limit` 参数启用基于游标的分页。

        ```tsx title="ThreadSidebar.tsx"
        const {
          threads,
          hasMoreThreads,
          isFetchingMoreThreads,
          fetchMoreThreads,
        } = useThreads({
          agentId: "my-agent",
          limit: 20, // [!code highlight]
        });

        // In your JSX:
        {hasMoreThreads && (
          <button
            onClick={fetchMoreThreads}
            disabled={isFetchingMoreThreads}
          >
            {isFetchingMoreThreads ? "Loading..." : "Load more"}
          </button>
        )}
        ```

## 每个线程驱动一个智能体

`useThreads` 负责列出和切换线程。要读取或运行**限定在特定线程**的智能体——比如每个线程开一个标签页——需要把 `agentId`、`runtimeAgentId` 和 `threadId` 三者全部传给 `useAgent`：

```tsx
const { agent } = useAgent({
  agentId: `chat-${threadId}`, // local id, unique per mounted thread
  runtimeAgentId: "default",   // the one runtime agent they all route to
  threadId,                    // the thread this instance is pinned to
});
```

这会为每个钩子注册一个私有的代理智能体，因此多个线程可以同时挂载到同一个 runtime 智能体上。`agent.runAgent()` 随即定位到对应线程。

<Callout type="warn">
  这三个属性是一组配套参数，缺少任何一个都无法通过编译。特别是 `useAgent({ agentId, threadId })` 会报类型错误：runtime 智能体是单例，若把线程直接钉在它上面，两个共享同一 `agentId` 的钩子就会互相覆盖对方的线程。完整规则参见 [`useAgent` 参考](/reference/hooks/useAgent)。
</Callout>
