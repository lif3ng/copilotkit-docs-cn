## 为现有线程添加 AG-UI 流

已经有 LangGraph、Google ADK、Mastra 或自定义后端中的线程，想让它们与 CopilotKit 协同工作？保留现有存储即可。你的框架管理智能体的会话、模型上下文与执行状态；智能中枢则补充恢复交互式会话所需的事件历史与投递能力。

通过[智能中枢快速开始](/intelligence/quickstart)接入你现有的 CopilotKit 应用，为后续运行添加 AG-UI 投递，同时由你的框架继续管理智能体上下文与持久化。如果也想纳入更早的会话，请按 <DocsTrackedLink href="/threads-import" surface="docs_threads_history_sync">为现有线程添加 AG-UI 流</DocsTrackedLink> 中的可选历史步骤操作，ADK、LangGraph 和 Mastra 均受支持。导入是一次性的接入步骤，不是数据库之间的持续复制。

CopilotKit 线程与原生框架的会话或 checkpoint 存储是分开的。当智能体框架还需要自己的会话标识符时，你的后端可以维护一个稳定的映射。

<WhenFrameworkHas flag="thread_persistence_pattern" equals="langgraph">
  <Callout type="info" title="LangGraph 线程 ID">
    CopilotKit 会通过 AG-UI 把当前活动的 `threadId` 传给你的 LangGraph 后端。你可以直接使用它，也可以持久化一个到 LangGraph 线程或 checkpoint 标识符的映射。LangGraph Platform 的线程 ID 必须是 UUID。
  </Callout>
</WhenFrameworkHas>

<WhenFrameworkHas flag="thread_persistence_pattern" equals="adk-session">
  <Callout type="info" title="ADK 会话">
    CopilotKit 会通过 AG-UI 把当前活动的 `threadId` 传给你的 ADK 后端。如果你同时使用持久的 ADK session service，请维护一个稳定的映射；CopilotKit 的线程生命周期操作不会修改原生 ADK 会话存储。
  </Callout>
</WhenFrameworkHas>

## 为什么要使用 CopilotKit AG-UI 流？

智能中枢的 AG-UI 流为现有的智能体与框架线程补充投递能力：

- **重连并补齐进度**：重新打开会话即可回放已记录的事件，并重新连接到仍在进行的运行。
- **后台继续运行**：浏览器断开后，只要 Runtime 和智能体仍在运行，智能体运行就可以继续。这不是服务器故障后的执行恢复。
- **跨设备投递**：用户可以在另一台设备上重新打开同一会话。智能中枢为已连接的客户端同步线程元数据；稳定用户身份由你的应用提供。
- **把用户历史与模型上下文分开**：智能中枢记录经由它交付的 AG-UI 事件。框架的模型上下文压缩与智能中枢的事件回放各有用途。
- **恢复交互式会话**：回放内容包括受支持的消息、生成式 UI、工具交互、状态和多模态输入。

这些是 CopilotKit Intelligence 的能力，而不是仅凭 AG-UI 协议就能提供的保证。重新打开或切回会话会触发回放与重连；参见[连接行为](/intelligence/threads-explained#websocket-disconnection)。

## 手动配置 AG-UI 流

创建一个连接到云托管 CopilotKit Intelligence 的新 CopilotKit 应用。你的应用与 CopilotKit Runtime 在本地运行，CopilotKit Intelligence 负责记录 AG-UI 事件并投递给已连接的客户端。如果你已经有在用的应用，请改为按照[智能中枢快速开始](/intelligence/quickstart#set-it-up-manually)接入它。

<Steps>
  <Step>

    运行交互式的起步模板命令：

    </DocsTrackedCopy>
  </Step>

  <Step>
    ### 连接 CopilotKit Intelligence

  <Step>
    ### 启动应用与 Runtime

    使用 CLI 打印出的命令启动生成的应用与 Runtime。标准 npm 配置下：

  <Step>

### 生产级自托管：在你自己的基础设施中运行 CopilotKit Intelligence

生产级自托管把 AG-UI 流、持久化事件历史、身份、存储与运维都留在你自己的网络之内，让组织掌控数据驻留、安全与基础设施。CopilotKit 工程团队会协助你的团队在 Kubernetes 环境中部署 CopilotKit Intelligence。欢迎<DocsTrackedLink href="https://copilotkit.ai/talk-to-an-engineer" surface="docs_threads_self_hosting_contact">预约 CopilotKit 工程师</DocsTrackedLink>开始上手。

## AG-UI 流的工作原理

两种 UI 路径都使用智能中枢的 AG-UI 流。一个稳定的 `threadId` 把可见会话与运行时及其持久化事件历史连接起来。

/>
<Image
  src="/images/threads/threads-diagram-dark.png"
  alt="用户在笔记本电脑上开始会话，离开或切换设备后，又在手机上回到同一会话。"

1. 你的 UI 使用一个稳定的 `threadId` 打开会话。
2. `CopilotRuntime` 运行你的智能体，并把会话事件发送到 CopilotKit Intelligence。
3. 用户回来时，CopilotKit Intelligence 会回放已存储的历史、重新连接仍在进行的运行，并同步线程元数据。

<Callout type="info" title="线程如何按用户隔离？">
  由你的应用对用户做身份验证，`CopilotRuntime` 在服务端通过 `identifyUser` 解析该已验证身份。CopilotKit Intelligence 使用稳定的用户 ID 来限定线程列表和生命周期操作。Runtime 契约与实现模式参见
  [将 AG-UI 流限定到已登录用户](/threads-lifecycle#scope-rich-threads-to-the-signed-in-user)。
</Callout>

### CopilotKit 负责什么

| CopilotKit 负责 | 由你掌控 |
|---|---|
| 持久化的事件存储与回放 | 你的智能体的行为与工具 |
| 从回放到实时流的重连 | 会话体验与布局 |
| 线程元数据的实时同步 | 用户可以访问哪些线程操作 |
| 命名、分页、归档与删除语义 | 应用层的授权与权限 |
| Runtime 到平台的事件管道与线程锁 | 需要时到原生框架会话的映射 |
| 云托管或自托管的平台基础设施 | 适合你组织的部署模式 |

<Callout type="info" title="无头意味着自定义 UI，而非自定义基础设施">
  Threads Drawer 与无头线程使用同一套持久化、回放、同步和加锁基础设施。选择无头线程的前提是你想自己构建界面，而不是想重写线程后端。
</Callout>
