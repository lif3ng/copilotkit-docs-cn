## 为现有应用添加智能中枢

为你智能体已在管理的会话添加重连、补齐进度与跨设备投递能力。按照[智能中枢快速开始](/intelligence/quickstart)接入你现有的 CopilotKit 应用与 Runtime，然后验证新会话能否保存。这套配置会为经由 CopilotKit 的运行启用 AG-UI 流；无需导入旧会话。

你的框架继续管理智能体上下文与执行状态。保持已配置的持久化 LangGraph checkpointer 或持久化 ADK session service，并让 CopilotKit `threadId` 值与原生框架会话标识符之间的映射保持稳定。各层的职责分工参见 [AG-UI 流与框架线程](/intelligence/threads-explained#how-threads-work-with-framework-storage)。

不导入历史的完整示例参见[保留现有 LangGraph 会话](/intelligence/bring-your-own-thread-system#example-keep-an-existing-langgraph-conversation)。

## 纳入更早的会话（可选）

如果你还想让用户重新打开接入智能中枢之前记录的历史，请使用下面的步骤把受支持的历史复制到智能中枢。本指南覆盖 Google ADK、LangGraph、Mastra 和 AWS Strands 存储。它只复制历史内容；不会启用实时投递、无法恢复过去的执行，也不会建立持续的数据库复制。

使用 Threads Drawer 或 `useThreads` 选择会话，并把它的 `threadId` 传给你的聊天组件。导入的会话和新会话随后共用同一套 UI。导入无法恢复来源已不再暴露的内容。

## 支持的来源

| 来源 | 导入指南 | 支持的历史 |
|---|---|---|
| Google ADK | [为 ADK 会话添加 AG-UI 流](/google-adk/threads-import) | 来自数据库 session service 或 Vertex/Agent Engine session service 的持久化 ADK 会话。 |
| LangGraph | [为 LangGraph 线程添加 AG-UI 流](/langgraph-python/threads-import) | 来自 LangGraph Server / LangSmith 部署或具备持久化存储的 Python FastAPI 应用的已保存会话。 |
| Mastra | [为 Mastra 会话添加 AG-UI 流](/mastra/threads-import) | 来自本地 LibSQL 数据库或 Mastra 服务器的已保存会话。 |
| AWS Strands | [Python](/strands/threads-import) · [TypeScript](/strands-typescript/threads-import) | 来自本地会话文件或 S3 的已保存单智能体会话；Python 还支持 AgentCore Memory 原生会话。 |

## 会导入哪些内容？

导入器会保留能在 CopilotKit 聊天 UI 中渲染、或对下游学习系统有帮助的会话内容：

- 用户、助手、工具、系统与开发者消息
- 工具调用与工具结果
- 来源有暴露时的推理轨迹
- 抽取期间可解析的媒体
- 来源支持时的已保存智能体状态
- 原始时间戳
- 导入来源信息与每个会话的导入结果

它不会导入框架的传输噪音、LangSmith 追踪或不受支持的来源存储。可导入的内容取决于你的来源保存了什么；细节请参见你框架的导入指南。

## 导入流程

<Steps>
  <Step>
    ### 确认目标项目

    选择接收历史记录的智能中枢项目。由它的 app-api URL 和项目级 runtime 密钥指定目的地。导入前你需要先导出这些值。

    对于 CLI 创建的应用，可以选择一个云托管项目：

    ```bash title="Terminal"
    npx copilotkit@latest project select
    ```

    该命令会更新当前目录所选的项目，并把其项目级 runtime 密钥写入应用生成的 `.env`。
  </Step>

  <Step>
    ### 先做一次试运行

    试运行（dry run）会读取来源、发现来源智能体键、统计会话数量、报告将跳过的条目，并估算上传体积，且不会开启导入批次。它不需要 CopilotKit Intelligence URL 或 API 密钥。

    <Tabs groupId="thread_import_source" items={['ADK', 'LangGraph', 'Mastra']}>
      <Tab value="ADK">
        [配置 ADK 来源](/google-adk/threads-import#configure-the-source)，然后运行：

        ```bash
        npx copilotkit@latest import --source adk --dry-run
        ```
      </Tab>
      <Tab value="LangGraph">
        [配置 LangGraph 来源](/langgraph-python/threads-import#configure-the-source)及其用户 ID，然后运行：

        ```bash
        npx copilotkit@latest import --source langgraph --user-source metadata.user_id --dry-run
        ```
      </Tab>
      <Tab value="Mastra">
        使用 [Mastra 导入指南](/mastra/threads-import#configure-the-source)配置你的来源，然后运行：

        ```bash
        npx copilotkit@latest import --source mastra --dry-run
        ```
      </Tab>
    </Tabs>
  </Step>

  <Step>
    ### 映射来源智能体

    导入器会把每个来源智能体键映射到你的线上 CopilotKit runtime 所使用的 `agentId`。导入与后续运行要使用同一个智能体 ID。导入的应用用户 ID 也必须与 runtime 的 `identifyUser` 返回的 ID 一致。

    对于脚本化导入，把映射放进一个 JSON 文件：

    ```json title="agent-map.json"
    {
      "support-agent": "support-agent",
      "sales-agent": "sales-agent"
    }
    ```
  </Step>

  <Step>
    ### 准备 CopilotKit Intelligence 目的地

    正式导入需要目的地的 app-api URL 和项目级 runtime 密钥。CLI 创建的起步模板会把它们写入 `.env`，但导入器读取的是当前进程环境，不会自动加载 `.env` 或 `.copilotkit/project.json`。

    导入前，把生成的值复制到你的 shell 中：

    ```bash title="Terminal"
    export INTELLIGENCE_API_URL="https://..."
    export CPK_INTELLIGENCE_API_KEY="cpk-..."
    ```

    密钥也接受 `COPILOTKIT_API_KEY`。你也可以改用 `--api-url` 和 `--api-key` 直接传入相同的值。
  </Step>

  <Step>
    ### 执行导入

    试运行结果无误后，按来源执行对应导入：

    - [为 ADK 会话添加 AG-UI 流](/google-adk/threads-import)
    - [为 LangGraph 线程添加 AG-UI 流](/langgraph-python/threads-import)
    - [为 Mastra 会话添加 AG-UI 流](/mastra/threads-import)

    已导入的线程默认会被跳过。使用 `--replace` 刷新它们；正在运行或已续跑的线程保持不变。
  </Step>

  <Step>
    ### 验证导入的会话

    以分配了该导入会话的应用用户身份登录。在 Threads Drawer 中打开它，确认历史记录正常显示。发送一条消息，确认原生框架延续了同一会话。
  </Step>

  <Step>
    ### 继续使用框架的持久化

    应用会把后续经由 CopilotKit 运行的会话发送到 CopilotKit Intelligence。保持已配置的持久化 LangGraph 或 ADK 存储，让这些运行继续同时使用两层持久化。重新打开会话时使用相同的 CopilotKit `threadId` 以及到其原生线程或会话的稳定映射，历史就能保持连续。

    导入只复制受支持的历史，不会建立持续的数据库复制。智能中枢的重命名、归档和删除操作只影响智能中枢自己的记录。

    - **Threads Drawer**：CLI 创建的起步模板已经内置。使用 [Threads Drawer 指南](/prebuilt-components/copilot-threads-drawer)自定义这套现成的线程 UI。
    - **无头线程**（Headless Threads）：仅当需要自定义 UI 时使用[无头线程指南](/headless-threads)。用 `useThreads` 选择线程，保存其 `thread.id`，并把该值作为 `threadId` 传给你的聊天组件。

    重新打开会话时，使用 Drawer 或 `useThreads` 返回的导入 `thread.id`。与原生 ID 的任何映射保持不变。

    底层持久化与回放模型参见 [AG-UI 流与框架线程](/intelligence/threads-explained)。
  </Step>
</Steps>

## 部署注意事项

- **云托管的 CopilotKit Intelligence**：导出 CLI 创建的应用在 `.env` 中生成的目的地值，或用 `--api-url` 和 `--api-key` 传入。`project select` 可以改写应用生成的值，但导入器仍只读取命令行参数或当前进程环境。参见[云托管的 CopilotKit Intelligence](/intelligence/managed-intelligence-platform)。
- **自托管的 CopilotKit Intelligence**：用 `--api-url` 传入部署的 app-api URL，用 `--api-key` 传入项目级 `cpk` runtime 密钥。参见[自托管 CopilotKit Intelligence](/intelligence/self-hosting)。
