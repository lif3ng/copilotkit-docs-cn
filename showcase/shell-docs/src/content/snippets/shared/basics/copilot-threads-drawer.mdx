## 这是什么？

`<CopilotThreadsDrawer>` 为你的应用提供一个现成的会话侧边栏。用户可以列出、切换、新建、归档和删除自己的线程，而你无需接线任何**活动线程状态**即可让它工作。把它放在聊天旁边，它就会自动连接。

如果你的项目由 CopilotKit CLI 起步模板创建，抽屉及其共享聊天配置已经内置。否则，请使用下面的设置步骤把它加入现有的 CopilotKit 应用。本指南还会介绍抽屉的自定义与组件选项。

<Frame description="CopilotThreadsDrawer 位于 CopilotChat 旁边。选择一个线程即可重放其会话，无需任何活动线程接线。">
  <img
    src="/images/threads/support-desk-threads.png"
    alt="一个客服台应用，Threads Drawer 列出客户会话，旁边是 CopilotChat 中 Northstar Analytics 的工单详情"
    className="w-full rounded-lg"
  />
</Frame>

在底层，它是自包含的 `copilotkit-threads-drawer` web component 的一层薄 React 包装器，数据来自 [`useThreads`](/reference/hooks/useThreads) 与你的聊天配置。

想构建自己的线程 UI？同样的数据与操作也可通过 `useThreads` hook 以无头（headless）方式使用（参见[无头线程（Headless Threads）](/headless-threads)）。线程**重命名**就是其中一种无头操作：预构建抽屉的行菜单只涵盖归档/取消归档与删除，如需重命名，请用 `useThreads` 配合你自己的 UI 来接线。

## 何时应该使用？

当你想要以下能力时，可以使用抽屉：

- 聊天旁一个常驻的线程切换器（会话历史侧边栏）
- 零接线的线程切换、新对话、归档与删除
- 一个自包含、可主题化、跟随应用明暗主题的 UI
- 一个移动端就绪、自带启动按钮的离屏（off-canvas）抽屉

它需要 CopilotKit Intelligence（线程在服务端存储和同步）。<SignupLink surface="docs_drawer">开始云端托管配置</SignupLink>以创建或选择一个项目。

对于多用户应用，请将 Runtime 配置为[将 AG-UI Streams 限定到已登录用户](/threads-lifecycle#scope-rich-threads-to-the-signed-in-user)。

## 设置线程抽屉

将 `<CopilotThreadsDrawer>` 放在 `<CopilotChat>` 旁边，并用一个共享的 `<CopilotChatConfigurationProvider>` 把**两者**包裹起来。如果你使用的是 CLI 创建的起步模板，这个结构已经就位。正是这份共享配置让抽屉能够驱动聊天：无需任何回调，选中一行就会把聊天连接到该线程并重放其历史；“New Conversation”行会把聊天重置为全新的欢迎界面。下面的示例展示了要加入现有应用、或在自定义起步模板时需要保留的核心结构。

<Callout type="warn">
  **抽屉仅随 `@copilotkit/react-core/v2` 提供**。v1 没有抽屉，所以请从这一个包中引入抽屉、聊天与 provider。注意 import 路径：`@copilotkit/react-ui` 是[已弃用的 v1 包](/migrate/v2)，它以同样的名字导出自己的 `CopilotChat` 与 `CopilotSidebar`。
</Callout>

```tsx title="app/page.tsx"
import {
  CopilotKitProvider,
  CopilotChatConfigurationProvider,
  CopilotChat,
  CopilotThreadsDrawer,
} from "@copilotkit/react-core/v2";
import "@copilotkit/react-core/v2/styles.css";

export default function Page() {
  return (
    <CopilotKitProvider runtimeUrl="/api/copilotkit">
      <CopilotChatConfigurationProvider>
        <div style={{ display: "flex", height: "100dvh" }}>
          <CopilotThreadsDrawer />
          <CopilotChat />
        </div>
      </CopilotChatConfigurationProvider>
    </CopilotKitProvider>
  );
}
```

这就是全部集成工作。如果手写侧边栏，你需要在自己的状态里跟踪活动的 `threadId`，并在列表与聊天之间传递选择/新建线程的处理器；而在这里，抽屉与 `CopilotChatConfigurationProvider` 共享该状态，因此完全无需编写这些接线。

## 在侧边栏聊天中使用抽屉

`<CopilotChat>` 并不是唯一的宿主。`<CopilotSidebar>` 的工作方式相同，因为它内部渲染的就是一个 `<CopilotChat>`，因此共享同一份聊天配置。让抽屉作为你内容的兄弟元素，并把侧边栏放在旁边：

```tsx title="app/page.tsx"
import {
  CopilotKitProvider,
  CopilotChatConfigurationProvider,
  CopilotSidebar,
  CopilotThreadsDrawer,
} from "@copilotkit/react-core/v2";
import "@copilotkit/react-core/v2/styles.css";

export default function Page() {
  return (
    <CopilotKitProvider runtimeUrl="/api/copilotkit">
      <CopilotChatConfigurationProvider>
        <div style={{ display: "flex", height: "100dvh" }}>
          <CopilotThreadsDrawer />
          <main style={{ flex: 1 }}>
            <YourMainContent />
            <CopilotSidebar defaultOpen={true} />
          </main>
        </div>
      </CopilotChatConfigurationProvider>
    </CopilotKitProvider>
  );
}
```

`<CopilotPopup>` 基于同样的原因、以同样的方式承载抽屉。

<Callout type="info">
  从聊天头部打开抽屉的启动按钮只在移动端视口出现。在桌面端，抽屉是一个常驻的、始终可见的内联面板，因此那里的启动按钮不会有任何作用。桌面端没有启动按钮是设计使然，不是接线出了问题。
</Callout>

## 添加你自己的“新建对话”按钮

抽屉有自己的“New Conversation”行。你的应用也可以保留自己的按钮，例如放在工具栏或页面头部。要让该按钮启动新对话，请调用 [`useCopilotChatConfiguration`](/reference/hooks/useCopilotChatConfiguration) 中的 `startNewThread()`。这与抽屉自己那行调用的函数相同。

```tsx title="app/page.tsx"
import {
  CopilotKitProvider,
  CopilotChatConfigurationProvider,
  CopilotChat,
  CopilotThreadsDrawer,
  useCopilotChatConfiguration,
} from "@copilotkit/react-core/v2";
import "@copilotkit/react-core/v2/styles.css";

function NewConversationButton() {
  const configuration = useCopilotChatConfiguration(); // [!code highlight]

  return (
    <button
      type="button"
      onClick={() => configuration?.startNewThread()} // [!code highlight]
    >
      New conversation
    </button>
  );
}

export default function Page() {
  return (
    <CopilotKitProvider runtimeUrl="/api/copilotkit">
      <CopilotChatConfigurationProvider>
        <div style={{ display: "flex", height: "100dvh" }}>
          <CopilotThreadsDrawer />
          <main style={{ flex: 1, display: "flex", flexDirection: "column" }}>
            <header>
              <NewConversationButton />
            </header>
            <CopilotChat />
          </main>
        </div>
      </CopilotChatConfigurationProvider>
    </CopilotKitProvider>
  );
}
```

工作方式如下：

- 把按钮放进与抽屉和聊天相同的 `<CopilotChatConfigurationProvider>` 内。在 provider 之外，`useCopilotChatConfiguration()` 返回 `null`，按钮将不起作用。
- `startNewThread()` 为聊天分配新的线程 id 并显示欢迎界面。抽屉从同一份配置读取活动线程，因此不会有任何行保持选中。
- 新线程会在首次运行后出现在抽屉列表中。空线程不会获得行。
- 如果你设置了 `<CopilotChatConfigurationProvider>` 的 `threadId` 属性，线程就由你的应用控制。此时 `startNewThread()` 与抽屉自身的行选择都不会起作用，并会记录一条警告。请把线程 id 保存在你自己的状态中，并向抽屉传入两个更新该状态的回调：选中行时用 `onThreadSelect`，其“New Conversation”行用 `onNewThread`。你的按钮执行的代码与 `onNewThread` 相同：

  ```tsx
  function ControlledChat() {
    const [threadId, setThreadId] = useState(() => crypto.randomUUID());
    const startNew = () => setThreadId(crypto.randomUUID());

    return (
      <CopilotChatConfigurationProvider threadId={threadId}>
        <CopilotThreadsDrawer
          onThreadSelect={(id) => setThreadId(id)}
          onNewThread={startNew}
        />
        <button type="button" onClick={startNew}>
          New conversation
        </button>
        <CopilotChat />
      </CopilotChatConfigurationProvider>
    );
  }
  ```

若只想显示你自己的按钮，可以用对应的 CSS part 隐藏抽屉自带的新建对话控件。`new-thread-button` 是展开抽屉中的那一行；`launcher-new-thread` 是收起或折叠启动器中的（+）按钮。

```css
copilotkit-threads-drawer::part(new-thread-button),
copilotkit-threads-drawer::part(launcher-new-thread) {
  display: none;
}
```

## 抽屉显示哪个智能体的线程

抽屉只列出**一个**智能体的线程。它按以下顺序取找到的第一个智能体 ID：

1. 抽屉自身的 `agentId` 属性。
2. 最近的 `<CopilotChatConfigurationProvider>` 的 `agentId`。`<CopilotKit>` 会用它的 `agent` 属性在应用外层渲染一个这样的 provider，因此在 `<CopilotKit agent="...">` 之下抽屉会到此为止。若没有 `agent`，它会解析为 `"default"`。
3. `<CopilotKitProvider>` 上的 `agentId`。
4. `"default"`。

大多数框架快速开始使用 `<CopilotKit agent="...">`。内置智能体与 LangGraph 快速开始使用 `<CopilotKitProvider agentId="...">`。无论哪种，抽屉都能找到智能体。

如果你的运行时注册了多个智能体，抽屉只显示它解析到的那个智能体的线程。要列出另一个智能体的线程，请传入该智能体的 ID：

```tsx
<CopilotThreadsDrawer agentId="research_agent" />
```

`<CopilotChat>` 按相同顺序解析其智能体。要把抽屉和聊天一起切换到另一个智能体，改为在共享的 `<CopilotChatConfigurationProvider>` 上设置一次 `agentId`。

## 配置抽屉

`<CopilotThreadsDrawer>` 无需任何属性即可工作。可选属性如下：

| 属性 | 描述 |
|------|-------------|
| `agentId` | 要列出其线程的智能体。默认取聊天配置中的智能体，其次是 `<CopilotKitProvider>` 上的 `agentId`，最后是 `"default"`。参见[抽屉显示哪个智能体的线程](#抽屉显示哪个智能体的线程)。 |
| `label` | 抽屉区域与线程列表框的无障碍名称。默认为 `"Threads"`。重新设计的头部没有可见标题。 |
| `recentLabel` | 显示在线程列表上方的小节标题。默认为 `"Recent Conversations"`。 |
| `onThreadSelect` | 用于自行接管线程选择的逃生出口。 |
| `onNewThread` | 用于自行处理“New Conversation”行的逃生出口。 |
| `renderRow` | 为每行渲染自定义内容（保留行本身的样式框架）。 |
| `limit` | 分页的每页数量。还有更多线程时显示“Load more”控件。省略则一次性加载全部。 |

完整的属性与类型列表参见 [Threads Drawer 参考](/reference/components/CopilotThreadsDrawer)。

## 自定义

抽屉渲染在 shadow root 中，样式自包含并继承主题，因此无需任何配置就能在任意应用（包括深色模式）中正确显示。有三个受限的定制出口可以穿越这层边界：

- **插槽（slots）**：用 `slot` 属性投影子元素（`header`、`empty`、`footer`、`memories`、`launcher-icon`）：

  ```tsx
  <CopilotThreadsDrawer>
    <span slot="header">My conversations</span>
  </CopilotThreadsDrawer>
  ```

- **每行内容**：`renderRow` 属性把自定义内容投影进每一行，同时元素保留选中态、归档样式以及每行的 kebab 菜单（Archive/Delete）。
- **CSS parts + 变量 token**：重构结构性 `::part()` 的样式，或覆盖 `--cpk-drawer-*` token。完整列表见[参考](/reference/components/CopilotThreadsDrawer#customization)。

## 访问 Intelligence

线程需要 CopilotKit Intelligence。抽屉通过 Runtime 解析其许可（entitlement），因此凭据是服务端配置，而不是 provider 上的属性。设置哪种凭据取决于你的部署方式。

**云端托管 Intelligence**：凭据是项目级的 `CPK_INTELLIGENCE_API_KEY`，Runtime 会从你组织的订阅中解析抽屉的许可。云端托管配置不会签发 `COPILOTKIT_LICENSE_TOKEN`；该 token 只用于离线或自托管授权，不能替代云端托管项目的 API 密钥。如果项目由 CLI 创建，密钥已在 `.env` 中，抽屉无需其他配置。

**自托管与开源**：为 Runtime 提供一个 license token，要么作为 `licenseToken` 选项，要么作为 `COPILOTKIT_LICENSE_TOKEN` 环境变量。两者都设置时选项优先。没有 token 时，抽屉会显示一个带 Upgrade 链接的锁定视图来替代列表，并且不会发起任何线程请求。

只要 Runtime 报告没有有效许可，就会出现锁定视图：可能是 license token 缺失或过期的自托管部署，也可能是订阅处于非活动状态的云端托管项目。
