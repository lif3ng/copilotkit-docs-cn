    ### 使用 Strands 原生中断暂停工具

    AWS Strands 提供了一流的[中断原语](https://strandsagents.com/docs/user-guide/concepts/interrupts/)（interrupt primitive）。通过 `@tool(context=True)` 声明的工具可以调用 `tool_context.interrupt(name, reason=...)`，该调用会暂停智能体循环，并把 `reason` 作为中断载荷交给客户端。AG-UI 适配器随后以携带 `outcome.type == "interrupt"` 的 `RUN_FINISHED` 结束本次运行。

    <DemoCode
      file="src/agents/interrupt_agent.py"
      region="backend-interrupt-tool"
      title="src/agents/interrupt_agent.py"
    />

    恢复载荷送达时是包装过的：答案形如 `{"response": ...}`，客户端取消形如 `{"cancelled": True}`。适配器之所以要做包装，是因为 Strands 的恢复闸门基于真值判断，裸的假值答案会导致同一个中断被永久反复触发。

  </Step>
  <Step>
    ### 暂停型工具不要占用客户端执行的名称

    `useHumanInTheLoop` 在前端（FRONTEND）注册其工具，因此前端用过的名称不能再同时用作暂停型后端工具。本演示站挂载了一个专用的中断智能体，并把中断演示的智能体名称指向它，从而让共享智能体上的 `schedule_meeting` 空出来，供前端工具流程使用。

  </Step>
  <Step>
    ### 在同一进程中恢复，或跨重启恢复

    在同一个运行中的进程里暂停和恢复无需额外接线。要让恢复操作在重启后依然有效，请通过 `StrandsAgentConfig.session_manager_provider` 为智能体提供一个 Strands `SessionManager`；适配器会把中断检查点持久化到该会话中。

  </Step>
</Steps>
