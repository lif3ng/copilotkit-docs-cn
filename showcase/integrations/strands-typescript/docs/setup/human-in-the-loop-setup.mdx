    ### 使用 Strands 原生中断暂停工具

    AWS Strands 提供了一流的[中断原语](https://strandsagents.com/docs/user-guide/concepts/interrupts/)（interrupt primitive）。工具的回调会收到一个上下文，调用其中的 `interrupt({ name, reason })` 即可暂停智能体循环，并把 `reason` 作为中断载荷交给客户端。AG-UI 适配器随后以携带 `outcome.type === "interrupt"` 的 `RUN_FINISHED` 结束本次运行。

    <DemoCode
      file="src/agent/interrupt-agent.ts"
      region="backend-interrupt-tool"
      title="src/agent/interrupt-agent.ts"
    />

    答案如何送达工具取决于适配器版本。锁定的 `@ag-ui/aws-strands` 0.2.3 会原样透传客户端载荷，并以 `{ status: "cancelled" }` 表示取消；Python 适配器则把答案包装为 `{ response: ... }`，取消时传 `{ cancelled: true }`。两种形态都要处理，否则用户选定的时段回到模型那里时，会像用户从未选择过一样。

  </Step>
  <Step>
    ### 暂停型工具不要占用客户端执行的名称

    `useHumanInTheLoop` 在前端（FRONTEND）注册其工具，因此前端用过的名称不能再同时用作暂停型后端工具。本演示站挂载了一个专用的中断智能体，并把中断演示的智能体名称指向它，从而让共享智能体上的 `schedule_meeting` 空出来，供前端工具流程使用。

  </Step>
  <Step>
    ### 在同一进程中恢复，或跨重启恢复

    在同一个运行中的进程里暂停和恢复无需额外接线。要让恢复操作在重启后依然有效，请通过 `StrandsAgentConfig.sessionManagerProvider` 为智能体提供一个 Strands `SessionManager`；适配器会把中断检查点持久化到该会话中。

  </Step>
</Steps>
