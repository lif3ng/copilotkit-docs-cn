### Mastra 子智能体设置

把下面这个完整的辅助文件保存为 `src/mastra/tools/working-memory.ts`，与 `subagents.ts` 放在一起。后者会从该文件导入 `writeDelegationsToWorkingMemory`。三张聊天卡片由子智能体的工具调用渲染而来；单独的委派日志则从工作记忆（working memory）中读取 `agent.state.delegations`。

示例的 `subagents.ts` 还导入了 `@/mastra/_header_forwarding`，用于向 OpenAI 传递诊断请求头和安全的消息 ID。该文件已随示例源码提供。请把它与示例一起复制；如果你的应用不需要示例的请求处理逻辑，也可以把 `subagents.ts` 中的 `openai` 导入替换为 `import { openai } from "@ai-sdk/openai";`。

监督智能体的 `Memory` 使用 `SubagentsAgentState` 模式启用了工作记忆。它的委派工具会调用 `writeDelegationsToWorkingMemory` 来更新日志。请保持工作记忆以 `scope: "thread"` 启用，这样每个对话都有各自的委派日志。聊天卡片来自工具调用，不依赖该日志。

如果你添加**新聊天**（New chat）控件，请在开始新线程前清空前端的委派状态。Mastra 适配器会在创建新的本地线程之前，把非空的前端状态发送到工作记忆，因此保留旧日志可能导致第一条消息报错 `Thread ... not found`。下面的两种部署方式都适用此规则：

```tsx title="新聊天控件"
import { useAgent, useCopilotChatConfiguration } from "@copilotkit/react-core/v2";

function NewSubagentsChat() {
  const { agent } = useAgent({ agentId: "subagentsSupervisorAgent" });
  const chat = useCopilotChatConfiguration();

  return (
    <button onClick={() => {
      agent.setState({});
      chat?.startNewThread();
    }}>
      New chat
    </button>
  );
}
```

在示例的本地运行时别名中，使用 `subagents` 作为智能体 ID。

当 Mastra 与你的前端运行在**同一进程**中时，像示例那样在 Copilot Runtime 路由中使用 `getLocalAgent`，并在该用户的每次运行中传入相同的 `resourceId`。为每个新对话分配新的线程 ID，并按上文所示清空前端的委派状态。当 Mastra 作为**独立服务器**运行时，请在该服务器上暴露一个 CopilotKit 路由。通用的 `MastraAgent.getRemoteAgents` 客户端会转发子智能体的工具调用，但不会转发日志所使用的工作记忆状态。在 Mastra 服务器上安装 `@ag-ui/mastra@1.1.1` 和 `@copilotkit/runtime`，然后把下面这段代码加到注册 `subagentsSupervisorAgent` 的 `Mastra` 实例中：

```ts title="src/mastra/index.ts"
import { Mastra } from "@mastra/core/mastra";
import { registerCopilotKit } from "@ag-ui/mastra/copilotkit";
import { subagentsSupervisorAgent } from "./agents";

export const mastra = new Mastra({
  agents: { subagentsSupervisorAgent },
  server: {
    apiRoutes: [
      registerCopilotKit({
        path: "/copilotkit",
        resourceId: "user-1",
        cors: { origin: "http://localhost:3000" },
      }),
    ],
  },
});
```

把前端的运行时 URL 指向 `http://127.0.0.1:4111/copilotkit`，并在前端选择或读取智能体状态的所有位置选中已注册的智能体键 `subagentsSupervisorAgent`。示例的本地运行时映射的是短别名 `subagents`，而独立 Mastra 服务器则直接暴露其注册的键。

把 CORS origin 设置为你前端的实际 origin。在多用户服务器中，请在 `registerCopilotKit` 选项中加入 `setContext`，并根据通过身份验证的用户来设置 `MASTRA_RESOURCE_ID_KEY`。例如，从 `@mastra/core/request-context` 导入 `MASTRA_RESOURCE_ID_KEY` 之后：

```ts
setContext: async (c, requestContext) => {
  const user = await requireAuthenticatedUser(c); // your server's auth layer
  requestContext.set(MASTRA_RESOURCE_ID_KEY, user.id);
},
```

上面静态的 `resourceId` 只是单用户场景的兜底方案。请确认三张工具卡片能正常完成、日志能收到状态。使用新聊天控件之后，新对话应当以空日志开始。
