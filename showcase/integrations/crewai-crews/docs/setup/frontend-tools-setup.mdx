    ### 从 Flow 的状态中取出被转发的工具

    Flow 拥有自己的模型调用，因此与聊天智能体不同，它必须亲自把被转发的工具交给模型。将 Flow 的泛型类型指定为 `CopilotKitState` 并读取 `state.copilotkit.actions` —— 经 `useComponent` 注册的组件就到达这里。

    ```python title="src/agents/chart_flow.py"
    from crewai.flow.flow import Flow, start
    from litellm import acompletion

    from ag_ui_crewai import CopilotKitState, copilotkit_stream


    class ChartFlow(Flow[CopilotKitState]):
        @start()
        async def chat(self) -> None:
            actions = self.state.copilotkit.actions or None
            response = await copilotkit_stream(
                await acompletion(
                    model="openai/gpt-5-mini",
                    messages=[
                        {"role": "system", "content": SYSTEM_PROMPT},
                        *self.state.messages,
                    ],
                    tools=actions,
                    parallel_tool_calls=False,
                    stream=True,
                )
            )
            self.state.messages.append(response.choices[0].message)
    ```

    用 `copilotkit_stream` 包裹这次调用，工具调用就能在流式传输过程中实时到达浏览器。如果 Flow 要等模型全部完成才返回，那么在整轮结束前不会渲染任何内容。

  </Step>
  <Step>
    ### 决定何时强制调用该组件

    Flow 可以控制 `tool_choice`，这是聊天智能体不具备的杠杆。在用户回合强制调用、之后保持 `auto`，既能立即渲染组件，又能让运行正常结束：一旦浏览器返回结果，后续回合就只是平实的文字叙述。

    ```python title="src/agents/chart_flow.py"
    on_user_turn = bool(
        self.state.messages and self.state.messages[-1].get("role") == "user"
    )
    tool_choice = "required" if actions and on_user_turn else "auto"
    ```

    如果每一回合都让 `tool_choice` 停留在 `auto`，Flow 往往只会用文字作答、组件永远不会出现——这是最常见的成因。

  </Step>
</Steps>
